---
title: "コマンド"
---

`.opencode/commands/review.md` を作成すると、プロンプトを `/review` コマンドにできます。

```md title=".opencode/commands/review.md"
Review $ARGUMENTS for bugs and missing tests.
```

TUI から、対象を指定して実行します。

```text
/review src/auth.ts
```

OpenCode は、`Review src/auth.ts for bugs and missing tests.` をユーザーのプロンプトとして送信します。

## Markdown

グローバルなコマンドは `~/.config/opencode/commands/` に、プロジェクトのコマンドは `.opencode/commands/` に置きます。

```text
~/.config/opencode/commands/review.md
.opencode/commands/review.md
```

検出されるのは `.md` ファイルだけです。ネストされたパスは、`/` で区切られたコマンド名になります。

```md title=".opencode/commands/team/review.md"
Review $ARGUMENTS using the team's checklist.
```

ネストされたコマンドは、`/team/review src/auth.ts` のように実行します。旧来の単数形のディレクトリ `command/` も検出されますが、新しいファイルには `commands/` を使用してください。

コマンドにメタデータが必要な場合は、YAML フロントマターを追加します。前後の空白を取り除いた Markdown の本文が、常にプロンプトのテンプレートになります。

```md title=".opencode/commands/review.md"
---
description: Review code for correctness
agent: plan
model: anthropic/claude-sonnet-4-5#high
---

Review $ARGUMENTS. Report bugs first.
```

## JSON

任意の OpenCode の JSON または JSONC の[設定ファイル](/config)で、`commands` の下にコマンドを定義します。各コマンドには `template` が必要です。

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "commands": {
    "review": {
      "description": "Review code for correctness",
      "template": "Review $ARGUMENTS. Report bugs first.",
    },
  },
}
```

## フィールド

Markdown のフロントマターと JSON のエントリでは、同じフィールドを使用できます。ただし、Markdown では `template` がファイルの本文から取得されます。

| フィールド | 必須 | 動作 |
| --- | --- | --- |
| `template` | JSON のみ | プロンプトのテンプレート。 |
| `description` | いいえ | コマンドの一覧や検出時に表示されるテキスト。 |
| `agent` | いいえ | コマンドの実行時に選択されるエージェント。 |
| `model` | いいえ | `provider/model` または `provider/model#variant` 形式で指定する、オーバーライド用のモデル。 |
| `subagent` | いいえ | `true` の場合はバックグラウンドの子セッションで実行し、`false` の場合は強制的に現在のセッションで実行します。 |
| `subtask` | いいえ | `subagent` の非推奨のエイリアス。 |

たとえば、次の JSON のコマンドでは、現在指定できる任意のフィールドをすべて設定しています。

```jsonc title="opencode.jsonc"
{
  "commands": {
    "audit": {
      "template": "Audit $ARGUMENTS.",
      "description": "Audit a package",
      "agent": "general",
      "model": "anthropic/claude-sonnet-4-5#high",
      "subagent": true,
    },
  },
}
```

`template` は本文から取得されるため、Markdown のフロントマターには記述しないでください。

## 引数

入力された引数の文字列全体をそのまま使うには、`$ARGUMENTS` を使用します。

```md title=".opencode/commands/component.md"
Create a typed React component named $ARGUMENTS.
```

`/component Account Settings` の場合、プレースホルダーは `Account Settings` になります。

## 位置引数

解析された位置引数を使うには、`$1`、`$2`、およびそれ以降の番号を使用します。単一引用符または二重引用符で囲んだ語は 1 つの引数にまとめられ、引用符は取り除かれます。

```md title=".opencode/commands/check.md"
Check $1. Focus on $2.
```

`/check src/auth.ts "error handling"` の場合、`$1` は `src/auth.ts` に、`$2` は `error handling` になります。

番号が最も大きいプレースホルダーには、対応する引数とそれ以降のすべての引数が入ります。指定されなかった位置引数は空文字列になります。

```md title=".opencode/commands/compare.md"
Compare $1 with $2.
```

`/compare api stable branch` の場合、OpenCode は `Compare api with stable branch.` を送信します。

## フォールバック

テンプレートに `$ARGUMENTS` も位置引数のプレースホルダーもない場合、OpenCode は空でない引数を、空行を挟んで末尾に追加します。

```md title=".opencode/commands/explain.md"
Explain this code clearly.
```

`/explain src/cache.ts` の場合、プロンプトは次のようになります。

```text
Explain this code clearly.

src/cache.ts
```

## シェル

シェルコマンドを `!` とバッククォートで囲むと、プロンプトの送信前にその出力が挿入されます。

```md title=".opencode/commands/review-diff.md"
Review this diff:

!`git diff --stat && git diff`
```

OpenCode は、設定されたシェルを使って、アクティブなプロジェクトの場所で各ブロックを実行し、まとめた出力を挿入します。引数のプレースホルダーは先に展開されます。

```md title=".opencode/commands/history.md"
Summarize these commits:

!`git log --oneline -$1`
```

`/history 5` の場合、シェルには `git log --oneline -5` が渡されます。信頼できない引数をシェルブロック内に置かないでください。

<Callout type="warning">
  シェルブロックは、OpenCode がコマンドを評価する時点で、エージェントのツール権限のフローを経由せずに実行されます。信頼できるソースのコマンドだけを使用してください。
</Callout>

## 添付ファイル

保存されたテンプレートでは `@path` は展開されず、通常のプロンプトのテキストのまま扱われます。

```md title=".opencode/commands/readme.md"
Review @README.md.
```

ファイルを添付するには、コマンドを呼び出す際に入力欄から追加します。OpenCode は、展開したプロンプトを送信するときに、入力欄で追加した添付ファイルを保持します。

## 実行

コマンドは、引数とシェルブロックを展開してから、永続的なユーザープロンプトとして送信されます。デフォルトでは、現在のセッションで実行されます。

```md title=".opencode/commands/plan.md"
---
agent: plan
---

Plan $ARGUMENTS.
```

`/plan migration` を実行すると、プロンプトの送信前に現在のセッションが `plan` に切り替わります。

モデルは、次のルールに従って選択されます。

1. コマンドの `model` は、ほかのすべてのモデルより優先されます。
2. それがない場合は、コマンドで選択したエージェントに設定されたモデルが、呼び出し時にアクティブなモデルより優先されます。
3. どちらもない場合は、現在のセッションのモデルがそのまま使われます。

たとえば、次のコマンドでは、エージェントと明示的なモデルの両方を選択しています。

```md title=".opencode/commands/design.md"
---
agent: plan
model: openai/gpt-5#high
---

Design $ARGUMENTS.
```

## バックグラウンド実行

コマンドをバックグラウンドの子セッションで実行するには、`subagent: true` を設定します。

```md title=".opencode/commands/audit.md"
---
description: Audit changes
agent: general
subagent: true
---

Audit $ARGUMENTS for bugs and missing tests.
```

親セッションは引き続き使用でき、エージェントとモデルも変わりません。子セッションが終了すると、OpenCode はその結果または失敗を親セッションに送ります。

| 値 | 動作 |
| --- | --- |
| `true` | 選択したエージェントが `mode: primary` の場合でも、常に子セッションを使用します。 |
| `false` | 選択したエージェントが `mode: subagent` の場合でも、常に現在のセッションを使用します。 |
| 省略 | 選択したエージェントが `mode: subagent` の場合にのみ、子セッションを使用します。 |

子セッションでは、コマンドのモデル、選択したエージェントのモデル、親セッションのモデルの順に使用されます。旧来の `subtask` も引き続き受け付けますが、両方のフィールドがある場合は `subagent` が優先されます。

```yaml
subagent: false
subtask: true
```

この例では、`subagent` が優先されるため、現在のセッションで実行されます。

## 読み込み

Markdown と JSON のコマンドは、1 つのレジストリを共有します。後から読み込まれたソースは、同じ名前の以前のコマンドを置き換えます。

```text
~/.config/opencode/commands/review.md   # Lower priority
.opencode/commands/review.md           # Replaces the global command
```

プロジェクトのソースはグローバルのソースより優先され、より近いプロジェクトのソースは祖先ディレクトリのソースより優先されます。カスタムの定義で、先に登録された組み込みコマンドを置き換えることもできます。OpenCode は、コマンドファイルと設定の変更を自動的に再読み込みします。

```md title=".opencode/commands/review.md"
Review only the staged changes: !`git diff --cached`
```

このファイルを保存すると、OpenCode を再起動せずに `/review` が更新されます。
