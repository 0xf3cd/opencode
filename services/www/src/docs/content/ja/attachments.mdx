## 添付の方法

ローカルファイルを添付し、プロンプトでそのファイルを使うよう OpenCode に指示します。デスクトップクライアントや Web クライアントでは、**Attach file** を選択するか、ファイルを貼り付けるか、プロンプトにドラッグします。

```text
Summarize the attached README.md and list the required setup steps.
```

デスクトップのファイル選択ダイアログでは、合計 20 MiB まで選択できます。ほかのインターフェイスでは、クライアント側でより低い上限が適用される場合があります。

<Callout type="warning">
  画像を添付する前に、画像入力に対応したモデルを選択してください。OpenCode は対応している画像をプロバイダーに渡せますが、形式、サイズ（寸法）、ファイル数、ファイルサイズの制限はプロバイダーとモデル側でも適用されます。テキスト専用のモデルでは、リクエストが拒否される場合があります。
</Callout>

## 構文

V2 のプロンプトとコマンドの入力では、添付ファイルを `uri` と、省略可能な `name` および `description` で記述します。

```json
{
  "uri": "file:///home/me/project/src/server.ts",
  "name": "server.ts",
  "description": "HTTP server entrypoint"
}
```

サーバーからアクセスできるファイルやディレクトリには、絶対パスの `file:` URL を使用します。テキストファイルでは、正の整数の `start` と `end` パラメーターで行範囲（1 始まり）を指定できます。

```text
file:///home/me/project/src/server.ts?start=20&end=60
```

内容をインラインで送信するには、`data:` URL を使用します。

```json
{
  "uri": "data:text/plain;base64,SGVsbG8sIE9wZW5Db2RlIQ==",
  "name": "greeting.txt"
}
```

HTTP および HTTPS の URL は添付ファイルとしてサポートされていません。プログラムからプロンプトを送信する方法については、自動生成された [API リファレンス](/api)を参照してください。

## 形式

現在の V2 のセッションでは、次の種類の添付ファイルがモデルに渡されます。

| 入力 | モデルが受け取る内容 | 例 |
| --- | --- | --- |
| UTF-8 テキストファイル | ファイル名とデコードされたテキスト | `README.md` |
| ディレクトリ | 直下のファイルとディレクトリの一覧（再帰なし） | `file:///home/me/` |
| PNG、JPEG、GIF、WebP | 画像メディア | `diagram.png` |

SVG はテキストとして扱われます。PDF、AVIF、BMP、音声、動画などのバイナリのプロンプト添付ファイルは、モデルへのリクエストに含まれません。サポートされていないバイナリは、先にテキストまたはサポートされている画像に変換してください。たとえば PDF のページは、`page-1.png` としてエクスポートしてから添付します。

OpenCode は、プロンプトを受け付ける前に各添付ファイルを読み込みます。無効な URL、読み取れないパス、ファイルやディレクトリ以外のパス、デコード後のサイズが 20 MiB を超える添付ファイルは拒否されます。メディアタイプはバイト列から判定されるため、ファイル名や `data:` URL のメディアタイプを変更しても、サポートされていないバイナリがモデルに渡されることはありません。

## 画像

画像の正規化は、`opencode.json` または `opencode.jsonc` で設定します。

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "media": {
    "image": {
      "auto_resize": true,
      "max_width": 2000,
      "max_height": 2000,
      "max_base64_bytes": 5242880,
    },
  },
}
```

すべてのフィールドは省略可能です。

| フィールド | デフォルト | 動作 |
| --- | --- | --- |
| `auto_resize` | `true` | 設定された上限を超える画像をリサイズします。`false` の場合は画像を拒否します。 |
| `max_width` | `2000` | 最大幅（ピクセル）。正の整数を指定する必要があります。 |
| `max_height` | `2000` | 最大の高さ（ピクセル）。正の整数を指定する必要があります。 |
| `max_base64_bytes` | `5242880` | Base64 エンコード後の画像の最大バイト数。正の整数を指定する必要があります。 |

たとえば次の設定では、幅が 1200 ピクセルを超える画像はリサイズされずに拒否されます。

```jsonc title="opencode.jsonc"
{
  "media": {
    "image": {
      "auto_resize": false,
      "max_width": 1200,
    },
  },
}
```

これらの設定は、プロンプトに添付された対応画像と、組み込みの `read` ツールが返す画像の両方に適用されます。

## 処理

`read` ツールは、PNG、JPEG、GIF、WebP を内容から判別し、元の画像データを最大 20 MiB まで読み込みます。幅、高さ、Base64 の長さは、設定された画像の上限と照合されます。

`auto_resize: true` の場合、OpenCode はアスペクト比を維持したまま、サイズの上限に収まるように縮小します。その後、Base64 の上限を満たすまで PNG と JPEG のエンコードを段階的に小さくして試すため、出力のメディアタイプが変わることがあります。

```text
Input:  4000 × 2000 WebP
Limits: 2000 × 2000
Output: 2000 × 1000 PNG or JPEG
```

どのエンコードでも収まらない場合、処理は失敗します。`auto_resize: false` の場合、いずれかの上限を超える画像は変更されずに失敗します。デコードできない画像も失敗します。

```text
Input:  2400 × 1600 JPEG
Limit:  max_width = 2000, auto_resize = false
Result: Image processing fails
```

画像のリサイズ機能が利用できない場合、OpenCode は元の画像を変更せずにそのまま渡します。したがって、画像の設定は処理上の上限であり、アップロードやセキュリティの境界ではありません。

## 制限事項

| 制限 | 値または動作 | 例 |
| --- | --- | --- |
| 直接の添付 | 1 項目あたりデコード後 20 MiB。クライアントによってはより低い上限が適用されます | 12 MiB のファイル 2 つは、項目ごとの上限内に収まります |
| デスクトップのファイル選択 | 合計 20 MiB | 12 MiB のファイル 2 つは、選択の上限を超えます |
| `max_base64_bytes` | `data:` URL 全体ではなく、Base64 エンコード部分のみが対象 | `SGVsbG8=` は 8 バイトとして数えられます |
| プロバイダーの画像の上限 | OpenCode による処理の後に適用されます | OpenCode が受け付けた画像でも、プロバイダーが拒否する場合があります |
| テキスト添付のモデル対応 | マルチモーダルモデルは不要です | `notes.txt` はプロンプトのテキストとして挿入されます |
| `read` のテキストの上限 | 別のページングと切り詰めの上限が使われます | 大きなログはページ単位で読み取ります |

クライアントがファイルを受け付けても、その内容がモデルに届くとは限りません。添付ファイルは、モデルに渡される形式であり、OpenCode とプロバイダーの両方の上限を満たしている必要があります。
