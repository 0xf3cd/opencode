---
title: "Effect"
---

`@opencode/plugin/effect` は、OpenCode プラグイン API の Effect ネイティブ版です。コンテキストの操作は Effect または Stream を返し、コールバックは Effect を返します。プラグインのライフタイムは `Scope` で表されます。

OpenCode は、プラグインとその `node_modules` の依存関係を読み込む際に、`effect`（エクスポートされた `effect/*` サブパスを含む）と `@opencode/plugin` を実行時に提供します。これらはプラグインにバンドルせず、ローカルでの型チェックやテスト用に peer/dev 依存関係としてインストールしてください。

```sh
bun add --peer @opencode/plugin effect
```

Effect プラグインを `.opencode/plugins/` からエクスポートすると、自動的に読み込まれます。

```ts title=".opencode/plugins/concise/index.ts"
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "example",
  effect: (ctx) =>
    Effect.gen(function* () {
      const storage = ctx.storage
      yield* storage.set("loaded", true)
    }),
})
```

公開パッケージや `.opencode/plugins/` 以外にあるプラグインディレクトリは、ほかのサーバープラグインと同じ `plugins` 設定を使用します。

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": [
    "opencode-acme-effect-plugin",
    "opencode-acme-effect-plugin@1.2.0",
    "@acme/opencode-effect-plugin",
    "./plugins/local-effect",
    {
      "package": "@acme/opencode-effect-plugin",
      "options": { "agent": "reviewer", "strict": true },
    },
  ],
}
```

有効化、パッケージの解決、設定の優先順位については、[プラグインの設定](/plugins)を参照してください。

```ts title="plugins/local-effect/index.ts"
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "local-effect",
  effect: (ctx) =>
    Effect.gen(function* () {
      yield* Effect.logInfo("Effect plugin loaded", { version: ctx.app.version })
    }),
})
```

## ライフサイクル

`effect` は、プラグインの読み込み時に実行されます。そのスコープはプラグインの再読み込みまたはアンロード時に閉じられるため、登録、スコープ付きのファイバー、ファイナライザーはまとめて解放されます。

```ts
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "lifecycle",
  effect: (ctx) =>
    Effect.gen(function* () {
      yield* Effect.logInfo("loaded", { version: ctx.app.version })
      yield* Effect.addFinalizer(() => Effect.logInfo("unloaded"))
    }),
})
```

バックグラウンドの処理には、スコープ付きのファイバーを使用します。プラグインのスコープは、クリーンアップ時にそのファイバーを中断します。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const storage = ctx.storage
    yield* Effect.repeat(
      storage.set("heartbeat", { time: Date.now() }),
      { schedule: Schedule.spaced("1 minute") },
    ).pipe(Effect.forkScoped)
  }),
```

### コンテキスト

コンテキストは、接続先の OpenCode サーバー用の Effect クライアントに加えて、プラグイン専用の変換、フック、ストレージ、再読み込み、オプションを公開します。OpenCode の内部の Core サービスは公開しません。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const plugins = ctx.plugin
    const active = yield* plugins.list().pipe(Effect.orDie)
    yield* Effect.logInfo("active plugins", { count: active.data.length })
  }),
```

プラグインの定義とコンテキスト全体は、次のように宣言されています。

```ts

    readonly terminal: Pick<ExperimentalApi<unknown>["persistentPty"], "read">
  }
  readonly integration: IntegrationDomain

  readonly reference: ReferenceDomain
  readonly rpc: RpcDomain

  readonly storage: StorageDomain

interface Plugin<R = Scope.Scope> {
  readonly id: string
  readonly effect: (context: Context) => Effect.Effect<void, never, R>
}
```

### オプション

オプションは、`opencode.json(c)` でオブジェクト形式を使って渡します。

```jsonc title="opencode.jsonc"
{
  "plugins": [
    {
      "package": "./plugins/company-effect",
      "options": { "strict": true },
    },
  ],
}
```

オプションは `ctx.options` から読み取ります。型が不明な値は、使用前に絞り込んでください。

```ts title="plugins/company-effect/index.ts"
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "company",
  effect: (ctx) =>
    Effect.gen(function* () {
      const strict = ctx.options.strict === true
      yield* Effect.logInfo("company plugin configured", { strict })
    }),
})
```

## 変換

変換は、エディターを通じて状態を同期的に編集します。OpenCode は、ドメインごとに登録順で変換を適用します。まずソースがプロバイダーと不変のモデル定義を提供し、その後、モデルの変換がアクティブなプロバイダーの候補を編集します。登録を yield すると、その登録はプラグインのスコープ内で保持されます。

```ts title="plugins/models-effect/index.ts"
import { Model, Plugin, Provider } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "company.models",
  effect: (ctx) =>
    Effect.gen(function* () {
      const providerID = Provider.ID.make("acme")
      const models = [{ ...Model.Info.default(providerID, Model.ID.make("reasoner")), name: "Acme Reasoner" }]
      yield* ctx.provider.transform((editor) => {
        editor.add({
          info: {
            ...Provider.Info.empty(providerID),
            name: "Acme",
            activation: "enabled",
            package: "@opencode/ai/providers/openai-compatible",
            settings: { baseURL: "http://127.0.0.1:8000/v1" },
          },
          models,
        })
      })
    }),
})
```

モデルの変換を使うと、アクティブなプロバイダーの候補コレクション全体にポリシーを適用できます。

```ts title="plugins/model-budget-effect/index.ts"
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.model.transform((editor) => {
      editor
        .list()
        .filter((model) => model.cost.some((tier) => tier.output > 20))
        .forEach((model) => {
          editor.remove(model.providerID, model.id)
        })
    })
  }),
```

変換が使用する外部の状態が変わったときは、`reload` を呼び出します。この例では、`loadFromSource()` は `{ info: Provider.Info, models: readonly Model.Info[] }` のエントリを返します。プロバイダーを再読み込みすると、モデルの結果全体も無効化されます。

```ts title="plugins/models-effect/index.ts"
effect: (ctx) =>
  Effect.gen(function* () {
    const provider = ctx.provider
    const source = { providers: yield* loadFromSource() }

    yield* provider.transform((editor) => {
      source.providers.forEach((provider) => editor.add(provider))
    })

    yield* Effect.repeat(
      Effect.gen(function* () {
        source.providers = yield* loadFromSource()
        yield* provider.reload()
      }),
      { schedule: Schedule.spaced("1 minute") },
    ).pipe(Effect.forkScoped)
  }),
```

## API

### エージェント

すべてのエージェントを読み取るか、ID を指定して 1 つを取得します。クライアントのレスポンスには、解決済みのロケーションとスキーマデータが含まれます。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const agent = ctx.agent
    const agents = yield* agent.list().pipe(Effect.orDie)
    const build = yield* agent.get({ agentID: Agent.ID.make("build") }).pipe(Effect.orDie)
    yield* Effect.logInfo("agents", { count: agents.data.length, build: build.data.name })
  }),
```

エージェントを変換または再読み込みします。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const agent = ctx.agent
    yield* agent.transform((editor) => {
      editor.default("build")
      editor.update("build", (item) => (item.description = "Builds features and fixes bugs"))
      editor.remove("legacy")
    })
    yield* agent.reload()
  }),
```

スキーマ：[`Agent.Info`](/api#schema-Agent.Info)

```ts
interface AgentEditor {
  list(): readonly Types.DeepMutable<Agent.Info>[]
  get(id: string): Types.DeepMutable<Agent.Info> | undefined
  default(id: string | undefined): void
  update(id: string, update: (agent: Types.DeepMutable<Agent.Info>) => void): void
  remove(id: string): void
}

interface AgentDomain extends AgentApi<unknown> {
  readonly transform: Transform<AgentEditor>
  readonly reload: () => Effect.Effect<void>
}
```

### プロバイダー

利用可能なプロバイダーを読み取るか、ID を指定して 1 つのプロバイダーのメタデータを確認します。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const provider = ctx.provider
    const providers = yield* provider.list().pipe(Effect.orDie)
    const anthropic = yield* provider.get({ providerID: Provider.ID.make("anthropic") }).pipe(Effect.orDie)
    yield* Effect.logInfo("providers", {
      providers: providers.data.length,
      anthropic: anthropic.data.name,
    })
  }),
```

プロバイダーの変換は、プロバイダーの設定とソースの定義を編集します。エディターでの読み取りには非アクティブなプロバイダーも含まれ、不変の定義が公開されます。`models.update` は、ソースモデルの所有コピーを編集します。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.provider.transform((editor) => {
      editor.update("anthropic", (provider) => {
        provider.headers = { ...provider.headers, "x-company": "engineering" }
      })
      editor.models.update("anthropic", "claude-sonnet-4-5", (model) => (model.name = "Team Sonnet"))
      editor.models.remove("anthropic", "legacy-model")
      editor.remove("legacy-provider")
    })
  }),
```

`models.set` でソースのインベントリを置き換え、取り込んだ定義が変わったら再読み込みします。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const provider = ctx.provider
    const source = { models: yield* loadModels() }
    yield* provider.transform((editor) => editor.models.set("acme", source.models))
    source.models = yield* loadModels()
    yield* provider.reload()
  }),
```

アカウントごとに検出を行う場合は、インベントリの読み込みに使った接続を `sourceConnection` として渡します。別の接続が選択されている間、プラグインが更新後のインベントリを公開するまで、OpenCode はそのプロバイダーを除外します。

```ts
const connection = yield * ctx.integration.connection.active("acme")
if (!connection) return
const inventory = yield * loadInventory(connection)
yield *
  ctx.provider.transform((editor) => {
    editor.add({ info: inventory.provider, models: inventory.models, sourceConnection: connection })
  })
```

スキーマ：[`Provider.Info`](/api#schema-Provider.Info)、[`Model.Info`](/api#schema-Model.Info)

```ts

  readonly provider: Provider.Info
  readonly models: ReadonlyMap<string, Model.Info>

}

interface ProviderEditor {
  list(): readonly ProviderRecord[]

  remove(providerID: string): void
  readonly models: {
    set(providerID: string, models: readonly Model.Info[]): void

  }

  readonly transform: Transform<ProviderEditor>

```

### モデル

利用可能なモデルとデフォルトの選択を読み取ります。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const model = ctx.model
    const models = yield* model.list().pipe(Effect.orDie)
    const selected = yield* model.default().pipe(Effect.orDie)
    yield* Effect.logInfo("models", { count: models.data.length, selected: selected.data?.name })
  }),
```

モデルの変換は、アクティブなプロバイダーの候補コレクション全体を編集します。無効化された候補も、すべての変換が終わるまでは編集できます。`update` でモデルを追加できるのは、利用可能なプロバイダーの下だけです。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.model.transform((editor) => {
      editor.list("anthropic").forEach((model) => {
        editor.update(model.providerID, model.id, (draft) => {
          draft.enabled = draft.capabilities.tools
        })
      })
      editor.default.set("anthropic", "claude-sonnet-4-5")
      editor.remove("anthropic", "legacy-model")
    })
  }),
```

コールバックは、モデルの生のオーバーライドを編集します。プロバイダーのデフォルトは、OpenCode が結果を確定するときに一度だけマージされ、変更がなければ読み取り時にその結果が再利用されます。`editor.provider` は、モデルの変換の出力ではなく、非アクティブなテンプレートを含む不変のソース定義を読み取ります。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const model = ctx.model
    yield* model.transform((editor) => {
      const source = editor.provider.get("anthropic")?.models.get("claude-sonnet-4-5")
      if (!source) return
      editor.update("anthropic", source.id, (draft) => {
        draft.limit.context = Math.min(draft.limit.context, source.limit.context)
      })
    })
    yield* model.reload()
  }),
```

スキーマ：[`Model.Info`](/api#schema-Model.Info)


### コマンド

現在のロケーションで利用できるコマンドを読み取ります。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const command = ctx.command
    const commands = yield* command.list().pipe(Effect.orDie)
    yield* Effect.logInfo("commands", { names: commands.data.map((item) => item.name) })
  }),
```

現在のコマンドの変換は追加のみに対応しています。実行関数は、セッション、プロンプトの添付ファイル、配信モードを受け取ります。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const command = ctx.command
    const session = ctx.session
    yield* command.transform((editor) => {
      editor.add({
        name: "security-review",
        description: "Review changes for security issues",
        execute: (input) =>
          session.prompt({
            ...input.prompt,
            sessionID: input.sessionID,
            text: `Review these changes for security issues.\n\n${input.prompt.text}`,
            delivery: input.delivery,
          }).pipe(Effect.asVoid),
      })
    })
    yield* command.reload()
  }),
```

スキーマ：[`Command.Info`](/api#schema-Command.Info)、[`Session.Inbox.Delivery`](/api#schema-Session.Inbox.Delivery)


### インテグレーション

インテグレーションを読み取り、アクティブな認証情報があれば解決します。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const integration = ctx.integration
    const integrations = yield* integration.list().pipe(Effect.orDie)
    const github = yield* integration.get({ integrationID: Integration.ID.make("github") }).pipe(Effect.orDie)
    const connection = yield* integration.connection.active("github")
    const credential = connection ? yield* integration.connection.resolve(connection).pipe(Effect.orDie) : undefined
    yield* Effect.logInfo("integration", {
      count: integrations.data.length,
      github: github.data.name,
      credential: credential?.type,
    })
  }),
```

接続済みの API を通じて、キーで接続するか、OAuth の認証試行を進めます。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const integration = ctx.integration
    const token = yield* Config.Redacted("GITHUB_TOKEN").pipe(Effect.orDie)
    yield* integration.connect
      .key({ integrationID: Integration.ID.make("github"), key: Redacted.value(token) })
      .pipe(Effect.orDie)

    const attempt = yield* integration.oauth
      .connect({
        integrationID: Integration.ID.make("acme"),
        methodID: Integration.MethodID.make("oauth"),
      })
      .pipe(Effect.orDie)
    const status = yield* integration.oauth
      .status({
        integrationID: Integration.ID.make("acme"),
        attemptID: attempt.data.attemptID,
      })
      .pipe(Effect.orDie)
    yield* Effect.logInfo("OAuth status", { status: status.data })
  }),
```

インテグレーションと認証方法を変換します。OAuth メソッドのコールバックは Effect であり、スコープ付きのリソースを取得できます。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const integration = ctx.integration
    yield* integration.transform((editor) => {
      editor.update("acme", (item) => (item.name = "Acme"))
      editor.method.update({
        integrationID: "acme",
        method: { id: "device", type: "oauth", label: "Sign in with Acme" },
        authorize: () =>
          Effect.succeed({
            mode: "code",
            url: "https://acme.example/device",
            instructions: "Enter the displayed code",
            callback: (code) => exchangeCode(code),
          }),
      })
    })
    yield* integration.reload()
  }),
```

### MCP

MCP サーバーとその現在の接続状態を一覧表示します。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const mcp = ctx.mcp
    const servers = yield* mcp.list().pipe(Effect.orDie)
    yield* Effect.logInfo("MCP servers", { count: servers.data.length })
  }),
```

プラグインは、変換を通じてのみ MCP サーバーを管理します。サーバーの追加または置き換えには `editor.set`、設定の変更には `editor.update`、削除には `editor.remove` を使用します。設定の確認には `editor.list` と `editor.get` を使用します。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const mcp = ctx.mcp
    yield* mcp.transform((editor) => {
      const servers = editor.list()
      const docs = editor.get("docs")
      editor.set("docs", { type: "remote", url: "https://mcp.example.com" })
      editor.update("docs", (server) => (server.disabled = false))
      editor.remove("legacy")
    })
  }),
```

変換で `disabled: true` を設定するとサーバーが無効化されて切断され、`disabled: false` を設定すると有効化されて OpenCode が接続できるようになります。OpenCode は、変換後の設定に基づいてサーバーのライフサイクルを調整します。

変換が使用する外部の状態が変わったら、`reload()` を呼び出して変換を再適用し、サーバーの状態を調整します。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const mcp = ctx.mcp
    yield* mcp.reload()
  }),
```

スキーマ：[`Mcp.Server`](/api#schema-Mcp.Server)、[`Mcp.LocalConfigEncoded`](/api#schema-Mcp.LocalConfigEncoded)、[`Mcp.RemoteConfigEncoded`](/api#schema-Mcp.RemoteConfigEncoded)

```ts
  set(name: string, config: Mcp.ServerConfig): void
  update(name: string, update: (config: Types.DeepMutable<Mcp.ServerConfig>) => void): void
  remove(name: string): void
}

interface MCPDomain extends Pick<McpApi<unknown>, "list"> {
  readonly transform: Transform<MCPEditor>
  readonly reload: () => Effect.Effect<void>
}
```

### プラグイン

### ツール

Effect の `Schema` を使って、型付きのツールを登録します。実行関数はデコード済みの入力を受け取り、型付きの出力、表示用コンテンツ、またはメタデータを含む Effect を返します。

エディターは `add`、`update`、`remove` に対応しています。変換のコールバックは同期的であり、Effect や Promise を返してはいけません。外部データは、登録または再読み込みの前に読み込んでください。OpenCode は、アクティブな変換を新しいエディター上で登録順に再実行します。実際のツール名が同じ場合は、後から登録された有効な定義が先の定義をオーバーライドします。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const tool = ctx.tool
    yield* tool.transform((editor) => {
      editor.namespace({
        name: "acme",
        description: "Customer account tools",
      })
      editor.add({
        name: "greeting",
        description: "Create a greeting",
        input: Schema.Struct({ name: Schema.String }),
        output: Schema.Struct({ greeting: Schema.String }),
        options: { namespace: "acme", codemode: true },
        execute: ({ name }, context) =>
          Effect.gen(function* () {
            yield* context.progress({ status: "greeting" })
            return { output: { greeting: `Hello ${name}!` } }
          }),
      })
    })
  }),
```

コールバックが取り込んだソースデータを変更したら、`yield* ctx.tool.reload()` を呼び出します。再読み込みでは、アクティブな変換が順序を変えずに再実行されます。プラグインの effect は再実行されません。

ツールには実際の名前を含む `id` があり、その ID が存在しない場合、`get()` は `undefined` を返します。`update` と `remove` には、名前空間を含む実際のツール名（上の例では `acme_greeting`）を指定します。名前空間内のドットと、ツール名でサポートされていない文字は `_` に置き換えられます。存在しない名前は無視されます。ツールを作成するには、完全な定義を指定して `add` を使用する必要があります。更新では名前と名前空間が維持されます。スキーマやオプションを置き換えるには、ネストした値を変更するのではなく、新しい値を代入してください。無効な更新はログに記録され、以前の定義がそのまま残ります。

```ts
yield *
  ctx.tool.transform((editor) => {
    editor.update("acme_greeting", (tool) => {
      tool.description = "Greet the user by name"
    })
    editor.remove("acme_obsolete")
  })
```

更新と削除は、MCP カタログの更新後も含め、追加と同じ順序で再実行されます。

`transform` はスコープ付きの登録を返します。`yield* registration.dispose` を実行するとその変換が削除され、残りの変換から再構築されるため、オーバーライドされていた以前の定義が再び有効になります。破棄は冪等であり、プラグインのスコープを閉じた場合もその登録は破棄されます。

モデルへの各リクエストは、ツールのスナップショットを取得します。再読み込みと破棄は今後のスナップショットに影響し、既存のリクエストがすでに取得した定義や実行関数には影響しません。変更可能なプラグインデータをクロージャーで参照している実行関数は、引き続きそのデータの変更を反映します。値を特定の定義に結び付けておく必要がある場合は、変換の中でその値を取り込んでください。

スキーマ：[`Tool.Content`](/api#schema-Tool.Content)、[`Tool.TextContent`](/api#schema-Tool.TextContent)、[`Tool.FileContent`](/api#schema-Tool.FileContent)

```ts
interface ToolEditor {
  list(): readonly (Tool.Info & { readonly id: string })[]
  get(id: string): (Tool.Info & { readonly id: string }) | undefined
  namespace(namespace: { name: string; description: string }): void
  add<Input extends Tool.ValueSchema<any>, Output extends Tool.ValueSchema<any> | undefined>(
    tool: Tool.Info<Input, Output>,
  ): void
  update(id: string, update: (tool: Types.Mutable<Tool.Info>) => void): void
  remove(id: string): void
}

  readonly list: () => Effect.Effect<readonly (Tool.Info & { readonly id: string })[]>
```

### VCS

リポジトリ情報、作業コピーの状態、ファイルの差分を読み取ります。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const vcs = ctx.vcs
    const info = yield* vcs.get().pipe(Effect.orDie)
    const branches = yield* vcs.branches({ search: "feature", limit: 10 }).pipe(Effect.orDie)
    const changes = yield* vcs.status().pipe(Effect.orDie)
    const diff = yield* vcs.diff({ mode: "working", context: 3 }).pipe(Effect.orDie)
    yield* Effect.logInfo("vcs", { branch: info.data.branch.current, files: changes.data.length })
  }),
```

スコープ付きの変換を通じて、ロケーション単位のプロバイダーを登録します。検出されたリポジトリの種類に一致するプロバイダーは自動的に選択されます。別のプロバイダーを選択するには、`editor.default.set` を使用します。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const vcs = ctx.vcs
    yield* vcs.transform((editor) => {
      editor.add({
        id: "custom",
        name: "Custom VCS",
        info: () => Effect.succeed({ branch: { current: "feature", default: "main" } }),
        branches: (input) => readBranches(input),
        status: (scope) => readStatus(scope.worktree),
        diff: (input) => readDiff(input),
      })
      editor.default.set("custom")
    })
  }),
```

プロバイダーのコールバックは、現在のロケーション、作業コピーのルート、正規のプロジェクトルート、省略可能なリポジトリストアを受け取ります。差分のコールバックは、さらに選択されたモード、要求されたコンテキスト、出力のバイト数の上限も受け取ります。リポジトリの検出には、引き続き OpenCode 組み込みの Git と Mercurial の検出機能が使われます。

プロバイダーは、`scope.worktree` にリポジトリを作成する `init(scope)` を任意で実装できます。初期化では、検出されたリポジトリの種類ではなく、ID によってプロバイダーが選択されます（デフォルトは Git）。ロケーションにまだリポジトリがない場合でも、`init` を持つプロバイダーを登録してください。OpenCode は、ディレクトリが存在し、リポジトリがないことを確認してから `init` を呼び出し、その後プロジェクトを再検出します。新しいリポジトリ形式には、このコールバックとは別に検出のサポートが必要です。

## フック

フックは、実行中の操作に介入します。複数のプラグインが同じフックを登録でき、OpenCode はプラグインの順序でそれらを実行するため、後のフックは前のフックによる変更を参照できます。登録はプラグインのスコープが続く間有効です。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook("context", () => Effect.void)
  }),
```

### セッション

モデルへの送信直前に、組み立て済みのシステム指示、メッセージ、ツールを変更します。`context` はエージェントループで実行され、`compaction`、`generate`、`title` はそれぞれの補助リクエストで実行されます。`compaction` と `title` は、モデルの呼び出しをスキップするための `result` を受け付けます。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook("context", (event) =>
      Effect.sync(() => {
        event.system.push({ type: "text", text: "Keep the review focused on correctness." })
        delete event.tools.write
      }),
    )
    yield* session.hook("compaction", (event) =>
      Effect.map(summarize(event.messages), (summary) => {
        event.result = { summary }
      }),
    )
  }),
```

モデルのリクエスト設定を変更します。フックの対象を 1 つのプロバイダーに限定することもできます。イベントには、後述の HTTP フックと同じ `kind` が含まれます。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook(
      "model.request",
      (event) => Effect.sync(() => (event.headers["x-plugin"] = "review")),
      { providerID: "anthropic" },
    )
  }),
```

プロバイダーのネイティブなリクエストまたはレスポンスを変更します。これらのボディは一度しか読み取れないストリームであるため、読み取る前にボディを複製するか置き換えてください。どちらのフックも、セッションが発行するすべてのリクエストで実行されます。`event.kind` は、リクエストを発行したフローに応じて `"primary"`、`"compaction"`、`"title"`、`"generate"` のいずれかになります。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook("http.request", (event) =>
      Effect.sync(() => {
        event.request.headers.set("x-session-id", event.sessionID)
        if (event.kind === "title") event.request.headers.set("x-priority", "background")
      }),
    )
    yield* session.hook("http.response", (event) =>
      Effect.sync(() => {
        event.response = new Response(event.response.body, {
          status: event.response.status,
          headers: { ...Object.fromEntries(event.response.headers), "x-plugin": "review" },
        })
      }),
    )
  }),
```

WebSocket でストリーミングするプロバイダーはセッションごとに 1 つの接続を再利用するため、その通信は HTTP フックには渡されません。実験的な `experimental.ws.handshake` フックは、接続が選択される前にモデル呼び出しごとに 1 回実行され、接続の `url` と `headers` を公開します。どちらかを変更するとソケットが開き直されます。WebSocket のルートが HTTP にフォールバックしたリクエストでは、HTTP フックが引き続き実行されます。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.session.hook(
      "experimental.ws.handshake",
      (event) =>
        Effect.gen(function* () {
          event.headers.authorization = `Bearer ${yield* mintToken(event.url)}`
          delete event.headers["api-key"]
        }),
      { providerID: "azure" },
    )
  }),
```

`experimental.ws.send` と `experimental.ws.receive` は、フレームそのものを公開します。`send` はプロバイダードライバーが送信フレームを組み立てた後に実行され、`receive` は受信フレームごとに、ドライバーがそれを処理する前に実行されます。フックから戻った時点の `frame` の内容が、そのまま送信されるか、ドライバーに渡されます。OpenCode はその内容を検証しません。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.session.hook(
      "experimental.ws.send",
      (event) =>
        Effect.sync(() => {
          const body = JSON.parse(event.frame)
          if (body.type === "response.create") body.metadata = { ...body.metadata, session: event.sessionID }
          event.frame = JSON.stringify(body)
        }),
      { providerID: "openai" },
    )
  }),
```

プロバイダーのエラーに対する再試行の判断をオーバーライドしたり、待機時間（ミリ秒）を置き換えたりします。このフックは、OpenCode がエラーを分類して再試行ポリシーを提案した後、再試行がスケジュールされる前に実行されます。OpenCode が次の試行を内部でどのように実行するかは公開されません。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.session.hook("retry", (event) =>
      Effect.sync(() => {
        if (event.error.status === 429) {
          event.decision = { retry: true, delay: 10_000 }
          return
        }
        if (event.error.type === "provider.invalid-request" && event.attempt === 2) {
          event.decision = { retry: true, delay: 0 }
          return
        }
        if (event.attempt >= 3) event.decision = { retry: false }
      }),
    )
  }),
```

最初の `decision` には OpenCode のポリシーが入っています。そのため、フックで通常は再試行されないプロバイダーのエラーを再試行可能にしたり、提案された再試行を取り消したりできます。複数のフックは登録順に実行され、後のフックは現在の判断を参照します。組み込みの最大試行回数は、超えられない上限として維持されます。`attempt` は提案されている実際の試行番号です。最初のリクエストが試行 `1` なので、最初の再試行は試行 `2` になります。無効な待機時間（`NaN`、無限大、負の値）は、計算された待機時間にフォールバックします。コンテキストオーバーフローからの復旧は、同じリクエストを再試行するのではなく会話を圧縮するため、この仕組みとは別に扱われます。

### ツール

before フックでは、入力を置き換えたり、`Tool.Error` で失敗させたりできます。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const tool = ctx.tool
    yield* tool.hook("execute.before", (event) =>
      event.tool === "write"
        ? Effect.fail(new Tool.Error({ message: "Writes are disabled" }))
        : Effect.logDebug("tool input", { tool: event.tool, input: event.input }),
    )
  }),
```

after フックでは、成功した結果や失敗を確認したり置き換えたりできます。

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const tool = ctx.tool
    yield* tool.hook("execute.after", (event) => {
      if (event.status === "error") return Effect.logWarning("tool failed", { message: event.error.message })
      return Effect.sync(() => {
        event.result = { ...event.result, metadata: { observed: true } }
      })
    })
  }),
```

共通の登録型を見ると、どの操作にプラグインのスコープが必要かがわかります。

```ts
interface Registration {
  readonly dispose: Effect.Effect<void>
}

type Hooks<Spec, Failures extends Record<keyof Spec, unknown> = Record<keyof Spec, never>> = <Name extends keyof Spec>(
  name: Name,
  callback: (input: Spec[Name]) => Effect.Effect<void, Failures[Name]>,
) => Effect.Effect<Registration, never, Scope.Scope>

type Transform<Input> = (callback: (input: Input) => void) => Effect.Effect<Registration, never, Scope.Scope>
```

## 公開

パッケージとして配布するプラグインは、ローカルの Effect プラグインと同じデフォルトエクスポートを使用します。メインのエントリポイントから Effect の実装をエクスポートし、`effect` を `peerDependency` として宣言します。

```json title="package.json"
{
  "name": "opencode-acme-effect-plugin",
  "version": "1.0.0",
  "type": "module",
  "exports": {
    ".": "./src/index.ts"
  },
  "dependencies": {
    "@opencode/plugin": "latest"
  },
  "peerDependencies": {
    "effect": "^4.0.0"
  }
}
```

OpenCode は、`effect`、エクスポートされた `effect/*` サブパス、`@opencode/plugin` のインポート（プラグインの `node_modules` 内の依存関係からのインポートを含む）を、ホストのランタイムインスタンスにリダイレクトします。これにより、ファイバー、ロガー、`Schema` パーサーが 1 つのランタイムを共有します。

- 公開するプラグインの成果物に `effect` をバンドルしないでください。バンドラーでビルドする場合は、`effect` と `effect/*` を external に指定します。
- プラグインとその `node_modules` の依存関係は、常にホストである OpenCode リリースの `effect` インスタンス上で実行されます。対象とする OpenCode リリースと互換性のある `effect` の API とモジュールパスを使用してください。別のメジャーバージョンの `effect`（Effect 3 など）でビルドされた依存関係にもホストの `effect` が渡されるため、サポートされません。
- 提供されるのは公開されている `effect` のサブパスだけです。Effect の非公開の `internal` モジュールをインポートするプラグインは、そのパスを示すエラーで読み込みに失敗します。
- コンパイル済みの OpenCode バイナリには、Effect の HTTP API ドキュメントページで使われる Scalar と Swagger UI のアセットが含まれていません。プラグインからこれらのページを配信すると、代わりに通知が表示されます。

パッケージのエントリポイントは、`effect` 関数を持つ `Plugin.define` をエクスポートします。

```ts title="src/index.ts"
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "acme.published",
  effect: (ctx) =>
    Effect.gen(function* () {
      const storage = ctx.storage
      yield* storage.set("installed", true)
    }),
})
```

対象とする OpenCode リリースと互換性のあるバージョンを使用し、ワークスペースにリンクしたコピーだけでなく、インストールしたパッケージでもテストしてください。

```sh
bun pm pack
bun add ./opencode-acme-effect-plugin-1.0.0.tgz
```
