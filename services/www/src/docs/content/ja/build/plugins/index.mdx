プラグインを使うと、OpenCode の動作を変更したり、新しい機能を追加したりできます。ターミナル UI を変更するには、[CLI プラグイン](/build/plugins/cli)を構築します。

既存の OpenCode 1 のプラグインを移行する場合は、[V1 プラグイン移行ガイド](/build/plugins/migrate-v1)に従ってください。

```ts title=".opencode/plugins/example/index.ts"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "example",
  async setup(ctx) {
    await ctx.storage.set("loaded", true)
  },
})
```

上記のローカルの例のように、`.opencode/plugins/` 以下のプラグインは自動的に読み込まれます。公開済みのパッケージや、ほかの場所にあるプラグインディレクトリを読み込むには、`opencode.json(c)` の `plugins` に追加します。

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": [
    "opencode-acme-plugin",
    "opencode-acme-plugin@1.2.0",
    "@acme/opencode-plugin",
    "./plugins/local",
    "../shared/plugin",
    "/absolute/path/plugin",
    "file:///home/me/plugins/local",
    {
      "package": "@acme/opencode-plugin",
      "options": {
        "agent": "reviewer",
        "strict": true,
      },
    },
  ],
}
```

読み込みと設定のその他のオプションについては、[プラグインの設定](/plugins)を参照してください。

## ライフサイクル

`setup` はプラグインの読み込み時に実行されます。プラグインのアンロード時に実行されるクリーンアップ関数を返すこともできます。

```ts
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "example",
  setup(ctx) {
    console.log(`loaded in OpenCode ${ctx.app.version}`)
    return () => console.log("unloaded")
  },
})
```

### コンテキスト

プラグインのコンテキストは、実質的に [OpenCode サーバークライアント](/build/client)です。読み取りメソッドとアクションメソッドは、クライアントと同じ入力とレスポンスを使用します。さらに、変換、ランタイムフック、再読み込み、登録、プラグインオプションのためのプラグイン専用メソッドが追加されています。

```ts
setup(ctx) {
  console.log(ctx.app.version)
}
```

`ctx.location` は、このプラグインインスタンスが読み込まれたロケーションを表します。`directory`、省略可能な `workspaceID`、`project` のメタデータ（`id`、`directory`、`canonical`）が含まれます。Promise プラグインと Effect プラグインのどちらでも利用できます。これはプラグインインスタンスのロケーションであり、プラグインがアクセスできるすべてのセッションや、受信するすべてのイベントのロケーションではありません。

```ts
setup(ctx) {
  console.log(ctx.location.directory)
  console.log(ctx.location.project.canonical)
}
```

### オプション

プラグインのオプションは、`opencode.json(c)` でオブジェクト形式を使って渡します。

```jsonc title="opencode.jsonc"
{
  "plugins": [
    {
      "package": "./plugins/company",
      "options": {
        "strict": true,
      },
    },
  ],
}
```

渡した値は、`setup` の中で `ctx.options` から読み取ります。

```ts title="plugins/company/index.ts"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "company",
  setup(ctx) {
    const strict = ctx.options.strict === true
  },
})
```

## 変換

変換（transform）は、OpenCode のドメイン状態に対する同期的な編集です。各変換は、同じドメインで先に登録された変換の結果の上に積み重なります。`ctx.model.list()` などのレジストリの読み取りには、プラグインのセットアップ中も含め、その時点までのすべての登録が反映されます。起動時のバッチ処理がまとめるのは更新通知だけで、読み取りの戻り値が遅れることはありません。一方、リソースのステータス API は、実行中のリソースの状態を返します。定義が登録されていても、その接続やほかのリソース処理が完了しているとは限りません。

ソースは、`ctx.provider.transform` を通じてプロバイダーと不変のモデル定義を提供します。

```ts title="plugins/models/index.ts"
import { Model, Plugin, Provider } from "@opencode/plugin"

export default Plugin.define({
  id: "company.models",
  async setup(ctx) {
    const providerID = Provider.ID.make("acme")
    const models = [{ ...Model.Info.default(providerID, Model.ID.make("reasoner")), name: "Acme Reasoner" }]
    await ctx.provider.transform((editor) => {
      editor.add({
        info: {
          ...Provider.Info.empty(providerID),
          name: "Acme",
          activation: "enabled",
          package: "@opencode/ai/providers/openai-compatible",
          settings: { baseURL: "http://127.0.0.1:8000/v1" },
        },
        models,
      })
    })

    const available = await ctx.model.list()
  },
})
```

登録、削除、`reload()` のいずれかが行われると、レジストリは変更済みとしてマークされます。次の読み取りでは、アクティブなすべての変換を登録順に新しい値へ再適用して、レジストリを再構築します。変換は軽量で、何度実行しても同じ結果になるようにしてください。すでに読み取った値が、後の再構築によって変更されることはありません。

プロバイダーの変換と利用可否が確定すると、OpenCode はアクティブなプロバイダーのモデルを具体化し、すべてのモデル変換を順に再適用します。モデルのポリシーでは、新しく更新されたソースを含め、候補のコレクション全体を確認できます。

```ts title="plugins/model-budget/index.ts"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "company.model-budget",
  async setup(ctx) {
    await ctx.model.transform((editor) => {
      editor
        .list()
        .filter((model) => model.cost.some((tier) => tier.output > 20))
        .forEach((model) => {
          editor.remove(model.providerID, model.id)
        })
    })
  },
})
```

コールバックが参照する入力は、自動的には監視されません。外部データは同期コールバックの前に読み込み、その入力が変わったら `reload()` を呼び出します。この例では、`loadFromSource()` は `{ info: Provider.Info, models: readonly Model.Info[] }` のエントリを返します。

```ts title="plugins/models/index.ts"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "company.models",
  async setup(ctx) {
    const source = { providers: await loadFromSource() }

    await ctx.provider.transform((editor) => {
      source.providers.forEach((provider) => editor.add(provider))
    })

    const refresh = async () => {
      source.providers = await loadFromSource()
      await ctx.provider.reload()
    }

    const timer = setInterval(() => void refresh().catch(console.error), 60_000)
    return () => clearInterval(timer)
  },
})
```

プロバイダーが変更されると、アクティブなモデルの結果全体が無効になります。そのため、出力価格によるポリシーは更新後のモデルにも引き続き適用されます。モデル変換が参照する入力だけが変わった場合は、`ctx.model.reload()` を使用します。

## API

### エージェント

すべてのエージェントを読み取るか、ID を指定して 1 つ取得します。

```ts
const agents = await ctx.agent.list()
const build = await ctx.agent.get({ agentID: "build" })
```

変換を登録すると、エージェントの確認、更新、削除や、デフォルトエージェントの選択ができます。

```ts
await ctx.agent.transform((editor) => {
  const agents = editor.list()
  const build = editor.get("build")

  editor.default("build")
  editor.update("build", (agent) => {
    agent.description = "Builds features and fixes bugs"
  })
  editor.remove("legacy")
})
```

変換が参照する外部の状態が変わったら、エージェントを再読み込みします。

```ts
await ctx.agent.reload()
```

### プロバイダー

利用可能なプロバイダーを読み取るか、ID を指定して 1 つのプロバイダーのメタデータを確認します。

```ts
const providers = await ctx.provider.list()
const provider = await ctx.provider.get({ providerID: "anthropic" })
```

プロバイダーの変換では、プロバイダーの設定とソース定義を編集します。エディターの読み取りには非アクティブなプロバイダーも含まれ、不変の定義が返されます。`models.update` は、ソースモデルの所有コピーを編集します。

```ts
await ctx.provider.transform((editor) => {
  editor.update("anthropic", (provider) => {
    provider.headers = { ...provider.headers, "x-company": "engineering" }
  })
  editor.models.update("anthropic", "claude-sonnet-4-5", (model) => {
    model.name = "Team Sonnet"
  })
  editor.models.remove("anthropic", "legacy-model")
  editor.remove("legacy-provider")
})
```

`models.set` でプロバイダーのソースインベントリを置き換え、参照している定義が変わったら再読み込みします。

```ts
const source = { models: await loadModels() }
await ctx.provider.transform((editor) => {
  editor.models.set("acme", source.models)
})

source.models = await loadModels()
await ctx.provider.reload()
```

アカウント固有の検出を行う場合は、インベントリの読み込みに使用した接続を `sourceConnection` として渡します。別の接続が選択されている間、OpenCode はそのプロバイダーを除外し、プラグインが更新後のインベントリを公開するまでその状態を維持します。

```ts
const connection = await ctx.integration.connection.active("acme")
if (!connection) return
const inventory = await loadInventory(connection)
await ctx.provider.transform((editor) => {
  editor.add({ info: inventory.provider, models: inventory.models, sourceConnection: connection })
})
```

### モデル

利用可能なモデルとデフォルトの選択を読み取ります。

```ts
const models = await ctx.model.list()
const selected = await ctx.model.default()
```

モデルの変換では、アクティブなプロバイダーの候補コレクション全体を編集します。無効化された候補も、すべての変換が完了するまでは編集できます。`update` でモデルを追加できるのは、利用可能なプロバイダーの下に限られます。

```ts
await ctx.model.transform((editor) => {
  editor.list("anthropic").forEach((model) => {
    editor.update(model.providerID, model.id, (draft) => {
      draft.enabled = draft.capabilities.tools
    })
  })
  editor.default.set("anthropic", "claude-sonnet-4-5")
  editor.remove("anthropic", "legacy-model")
})
```

コールバックが編集するのは、モデルの生のオーバーライドです。プロバイダーのデフォルトは、OpenCode が結果を確定する際に一度だけマージされ、変更がなければ以降の読み取りでその結果が再利用されます。`editor.provider` が公開するのは、モデル変換の出力ではなく、非アクティブなテンプレートを含む不変のソース定義です。

```ts
await ctx.model.transform((editor) => {
  const source = editor.provider.get("anthropic")?.models.get("claude-sonnet-4-5")
  if (!source) return
  editor.update("anthropic", source.id, (model) => {
    model.limit.context = Math.min(model.limit.context, source.limit.context)
  })
})

await ctx.model.reload()
```

### インテグレーション

インテグレーションを読み取り、アクティブな認証情報を確認します。

```ts
const integrations = await ctx.integration.list()
const github = await ctx.integration.get({ integrationID: "github" })
const connection = await ctx.integration.connection.active("github")
const credential = connection ? await ctx.integration.connection.resolve(connection) : undefined
```

API キーでインテグレーションを接続します。

```ts
await ctx.integration.connect.key({
  integrationID: "github",
  key: process.env.GITHUB_TOKEN!,
})
```

OAuth による接続の試行を開始、確認、完了、キャンセルします。

```ts
const attempt = await ctx.integration.oauth.connect({ integrationID: "github", methodID: "oauth" })
const status = await ctx.integration.oauth.status({ integrationID: "github", attemptID: attempt.data.attemptID })
await ctx.integration.oauth.complete({ integrationID: "github", attemptID: attempt.data.attemptID, code })
await ctx.integration.oauth.cancel({ integrationID: "github", attemptID: attempt.data.attemptID })
```

コマンドベースの接続でも、同じ開始、ステータス確認、キャンセルの流れを利用できます。

```ts
const attempt = await ctx.integration.command.connect({ integrationID: "acme", methodID: "cli" })
const status = await ctx.integration.command.status({ integrationID: "acme", attemptID: attempt.data.attemptID })
await ctx.integration.command.cancel({ integrationID: "acme", attemptID: attempt.data.attemptID })
```

変換を登録すると、インテグレーションを確認し、その認証方式を管理できます。

```ts
await ctx.integration.transform((editor) => {
  const integrations = editor.list()
  const acme = editor.get("acme")

  editor.update("acme", (integration) => {
    integration.name = "Acme"
  })
  editor.method.update({
    integrationID: "acme",
    method: { id: "cli", type: "command", label: "Sign in with Acme CLI", command: ["acme", "login"] },
  })

  const methods = editor.method.list("acme")
  const legacy = methods.find((method) => method.type === "command" && method.id === "legacy")
  if (legacy) editor.method.remove("acme", legacy)
  editor.remove("legacy")
})
```

変換が参照する外部の状態が変わったら、インテグレーションを再読み込みします。

```ts
await ctx.integration.reload()
```

### MCP

MCP サーバーとその現在の接続状態を一覧表示します。

```ts
const servers = await ctx.mcp.list()
```

プラグインは、変換を通じてのみ MCP サーバーを管理します。サーバーの追加または置き換えには `editor.set`、設定の変更には `editor.update`、削除には `editor.remove` を使用します。設定を確認するには `editor.list` と `editor.get` を使用します。

```ts
await ctx.mcp.transform((editor) => {
  const servers = editor.list()
  const docs = editor.get("docs")
  editor.set("docs", { type: "remote", url: "https://mcp.example.com" })
  editor.update("docs", (server) => {
    server.disabled = false
  })
  editor.remove("legacy")
})
```

変換で `disabled: true` を設定するとサーバーが無効になって切断され、`disabled: false` を設定するとサーバーが有効になり、OpenCode が接続できるようになります。OpenCode は、変換後の設定に基づいてサーバーのライフサイクルを調整します。

変換が参照する外部の状態が変わったら `reload()` を呼び出し、変換を再適用してサーバーの状態を調整します。

```ts
await ctx.mcp.reload()
```

### 参照ディレクトリ

ロケーションで利用可能な参照ディレクトリを読み取ります。

```ts
const references = await ctx.reference.list()
```

変換を登録すると、ローカルおよび Git の参照ディレクトリを確認、追加、削除できます。`get(name)` は、現在設定されているソースを返します。その名前が存在しない場合は `undefined` を返します。

```ts
await ctx.reference.transform((editor) => {
```

### ツール

変換のコールバックの外で、すべての変換が適用された後の、現在登録されているツールを読み取ります。各ツールには、実効名を含む `id` があります。

```ts
const tools = await ctx.tool.list()
const read = tools.find((tool) => tool.id === "read")
```

ツールの登録、更新、削除は、Promise プラグインであっても同期的な変換で行います。外部データは、登録または再読み込みの前に読み込んでください。後から行われた有効な登録は、同じ実効名のツールをオーバーライドします。

```ts
const registration = await ctx.tool.transform((editor) => {
  editor.namespace({
    name: "acme",
    description: "Customer account tools",
  })
  editor.add({
    name: "greeting",
    description: "Create a greeting",
    input: {
      type: "object",
      properties: { name: { type: "string" } },
      required: ["name"],
      additionalProperties: false,
    },
    options: { namespace: "acme", codemode: true },
    execute: async (input, context) => {
      await context.progress({ status: "greeting" })
      return { content: `Hello ${(input as { name: string }).name}!` }
    },
  })
})
```

Promise ツールの実行関数は `context.signal` を受け取ります。これを `fetch` などのキャンセル可能な処理に渡すと、セッションを停止したときに基盤となる操作も停止します。

```ts
execute: async ({ url }, context) => {
  const response = await fetch(url, { signal: context.signal })
  return { content: await response.text() }
}
```

コールバックが参照するソースデータを変更した後は、`reload()` を呼び出します。再読み込みでは、アクティブな変換を順序を変えずに再適用します。プラグインのセットアップは再実行されません。

```ts
await ctx.tool.reload()
```

エディター内の現在のツールを確認するには、`list()` と `get()` を使用します。ツールには実効名を含む `id` があり、その ID が存在しない場合、`get()` は `undefined` を返します。`update` と `remove` には、名前空間を含む実効ツール名（上の例では `acme_greeting`）を指定します。名前空間に含まれるドットと、ツール名に含まれる使用できない文字は `_` に置き換えられます。存在しない名前は無視されます。ツールを新規作成するには、完全な定義を指定して `add` を使用する必要があります。更新しても名前と名前空間は維持されます。スキーマやオプションを置き換えるには、ネストした値を変更するのではなく、新しい値を代入してください。無効な更新はログに記録され、以前の定義がそのまま維持されます。

```ts
await ctx.tool.transform((editor) => {
  editor.update("acme_greeting", (tool) => {
    tool.description = "Greet the user by name"
  })
  editor.remove("acme_obsolete")
})
```

更新と削除は、MCP カタログの更新後も含め、追加と一緒に順番どおり再適用されます。それらの登録を破棄すると変更は取り消され、残りの変換から再構築されます。

登録を破棄すると、その変換が削除されて残りの変換から再構築され、その変換がオーバーライドしていた以前の定義が再び有効になります。破棄はべき等で、プラグインをアンロードした場合もその登録は破棄されます。

```ts
await registration.dispose()
```

各モデルリクエストは、安定した実行可能なツールのスナップショットを取得します。後から行われる変換、再読み込み、破棄は将来のスナップショットに影響し、すでに取得された定義、Code Mode の名前空間の説明、実行関数には影響しません。ただし、変更可能なプラグインデータをクロージャーで参照している実行関数は、そのデータの変化を引き続き反映します。値をその定義に結び付けたままにする必要がある場合は、変換の中でその値を取得してください。

### Worktree

通常のプラグインのライフサイクルを使って、ローカルの worktree 戦略を登録します。この例の実装モジュールは、オプションの検証と、バックエンドの `create`、`remove`、`list` 操作を担当します。

```ts title="plugins/worktrees/index.ts"
import { Plugin } from "@opencode/plugin"
import { makeStrategy } from "./strategy"

export default Plugin.define({
  id: "company.worktrees",
  async setup(ctx) {
    const strategy = makeStrategy(ctx.options)
    await ctx.worktree.transform((editor) => {
      editor.add(strategy)
    })
  },
})
```

プラグインは `plugins` で読み込み、共通の作成先は別途設定します。

```jsonc title="opencode.jsonc"
{
  "worktree": { "directory": "../worktrees" },
  "plugins": [{ "package": "./plugins/worktrees", "options": {} }],
}
```

- 戦略を追加すると、自動的に選択されます。最後にアクティブになった登録が優先されるため、戦略を選択するための設定は不要です。
- 登録を破棄するかプラグインをアンロードすると、以前の実装に戻ります。最終的には、同梱の Git 戦略に戻ります。
- `reload()` は、参照している入力が変わった後に変換を再適用します。プラグインのセットアップは再実行されません。
- 作成に失敗しても、Git による再試行は行われません。既存の worktree は、デフォルトが変わっても記録されたオーナーを維持します。
- 戦略が管理するのはローカルディレクトリです。リモートワークスペースのプロビジョニングは、このインターフェイスの対象外です。

#### 操作

プラグインのコンテキストは、クライアントと同じプロジェクトベースの worktree 操作を公開しています。すべての操作に `projectID` が必要です。`list` は、同じプロジェクトの既知のチェックアウトを含め、保存済みのインベントリだけを読み取ります。設定の読み込み、プラグインの起動、ファイルシステムの変更の検出は行いません。

```ts
const projectID = ctx.location.project.id
const created = await ctx.worktree.create({ projectID, name: "task" })
const inventory = await ctx.worktree.list({ projectID })
await ctx.worktree.refresh({ projectID })
await ctx.worktree.remove({ projectID, directory: created.directory, force: false })
```

作成時には、プロジェクトに保存されている `canonical` ディレクトリから設定とプラグインを読み込み、そこで選択されている戦略を使用します。省略可能な引数として、親ディレクトリの `directory`、ソースの `from`、開始ブランチの `branch`、`name` を指定できます。ソースのデフォルトは正規のチェックアウトで、`from` で上書きする場合はそのプロジェクトに属している必要があります。ソースを選択しても、設定のルートは変わりません。開始 ref を指定する場合は、選択された戦略がそれをサポートしている必要があります。たとえば Rift のネイティブのスナップショット操作には、ref を選択するオプションがありません。

作成と更新では、正規のチェックアウトのプラグインがアクティブになるまで待機します。そのチェックアウトのプラグインのセットアップ中に行われた呼び出しは、その時点までの登録を参照し、自身のアクティブ化を待機しません。

削除時には、正規の設定を読み込んでそのプラグインをアクティブにし、現在選択されているデフォルトではなく、worktree に記録された戦略を使用します。記録されたオーナーが利用できない場合はエラーになります。worktree の作成先は別の場所でもかまいません。

```ts
await ctx.worktree.remove({
  directory: "/worktrees/task",
  projectID,
  force: false,
})
```

オーナーが見つからない場合、Git にフォールバックせずに削除が失敗します。戦略は、`@opencode/plugin` から `Worktree` をインポートして `new Worktree.OperationError({ message: "Uncommitted changes", forceRequired: true })` を throw すると、Core や Git のエラーに依存せずに強制削除の確認を要求できます。

更新時には、正規の設定を読み込み、利用可能なすべての戦略に、既知のチェックアウトのルート全体から worktree を探すよう要求します。結果を統合し、記録された所有関係を維持して、存在しなくなったディレクトリを削除します。検出に失敗したソースはログに記録され、ほかのソースの処理は続行されます。既存のディレクトリは、利用可能な戦略がどれも報告しなくても保存されたままになります。変更されたインベントリを読み取るには、`worktree.updated` を監視して、再度 `list` を呼び出します。

```ts
await ctx.worktree.refresh({ projectID })
```

#### リファレンス

実装は、名前付けと衝突の処理が済んだ後の、推奨される作成先を受け取ります。`create` からは実際のディレクトリを返します。バックエンドが独自のレイアウトを必要とする場合は、推奨された作成先と異なってもかまいません。OpenCode は返されたパスを解決し、インベントリ、起動時のコマンド、API の結果に使用します。返されたディレクトリは存在している必要があります。

別の作成先を選択する戦略は、その場所での名前の衝突を自身で処理します。その場合も、OpenCode は戦略を呼び出す前に推奨された親ディレクトリを作成します。`list` は、戦略が所有するディレクトリとリポジトリのルートだけを報告する必要があります。

```ts
interface WorktreeDefinition {
  readonly id: string
  create(
    input: { sourceDirectory: string; directory: string; branch?: string },
    context: { signal: AbortSignal },
  ): Promise<{ directory: string }>
  remove(input: { directory: string; force: boolean }, context: { signal: AbortSignal }): Promise<void>
  list(
    sourceDirectory: string,
    context: { signal: AbortSignal },
  ): Promise<readonly { directory: string; type: "root" | "worktree" }[]>
}

interface WorktreeEditor {
  add(definition: WorktreeDefinition): void
}

interface WorktreeDomain extends WorktreeApi {
  transform(callback: (editor: WorktreeEditor) => void): Promise<Registration>
  reload(): Promise<void>
}
```

Promise のコールバックは、`signal` によるキャンセルに対応する必要があります。Effect のコールバックは Effect を返し、代わりに Effect の割り込みを使用します。登録はプラグインのランタイムにスコープされたままで、プロジェクトの操作では正規のチェックアウトのレジストリが使われます。Core の設定アダプターは、ディレクトリの設定をそのレジストリに反映します。

### Web 検索

変換で、プロバイダーを登録してデフォルトのプロバイダーを選択します。

```ts
await ctx.websearch.transform((editor) => {
  editor.add({
    id: "internal",
    name: "Internal search",
    execute: async ({ query }, { signal }) => {
      const response = await fetch(`https://search.example.com?q=${encodeURIComponent(query)}`, { signal })
      const result = await response.json()
      return [{ url: result.url, title: result.title, content: result.content, time: {} }]
    },
  })
  editor.default.set("internal")
})
```

`false` を選択すると Web 検索が無効になります。外部の状態が変わった後は、プロバイダーを再読み込みします。

```ts
await ctx.websearch.transform((editor) => editor.default.set(false))
await ctx.websearch.reload()
```

## フック

フックは、実行中の操作に割り込みます。フックをそのドメインに登録し、不要になったら返された登録を破棄します。

```ts
const registration = await ctx.session.hook("context", () => {})
await registration.dispose()
```

複数のプラグインが同じフックを登録できます。OpenCode はプラグインの順にフックを実行するため、後のフックは前のフックによる変更を参照できます。

### セッション

セッションのフックは、プロンプトの受け付け、モデル呼び出し、ネイティブ HTTP、リトライに割り込みます。

#### プロンプトの受け付け

ユーザーから届いたプロンプトに、添付ファイルとスキルの解決、およびインボックスへの永続的な受け付けの前に割り込みます。

```ts
await ctx.session.hook("prompt", (event) => {
  event.prompt.text = event.prompt.text.replaceAll("company-secret", "[redacted]")
  event.prompt.files ??= []
  event.prompt.files.push({ uri: "file:///project/policy.md" })
  event.metadata = { ...event.metadata, source: "company-policy" }
  event.delivery = "queue"
})
```

フックは、フック専用の変更可能なドラフトを受け取ります。

- `prompt` には、`text`、`files`、`agents` 内のエージェントのメンション、選択された `skills` が含まれます。
- `metadata` には、アプリケーションが定義する受け付け時のメタデータが含まれます。
- `delivery` のデフォルトは `"steer"` で、`"queue"` に変更できます。
- セッション ID とメッセージ ID は読み取り専用で、フックで受け付け先を変更することはできません。

フックで追加したファイルとスキルは、通常の解決と検証の手順を経ます。テキストを書き換える場合は、一致しなくなった添付ファイルの `mention` のオフセットを更新または削除してください。エージェントのメンションによって、セッションのアクティブなエージェントが切り替わることはありません。

プロンプトフックは、次の条件で実行されます。

- フックは、セッションのロケーションのプラグインの準備が整った後に、登録順に実行されます。
- `session.prompt` を通じて送信するコマンドでは、フックが実行されます。
- 合成メッセージ、シェルメッセージ、コンテキスト圧縮の制御、移動の制御では実行されません。
- フックは受け付け時に 1 回だけ実行され、モデル呼び出しのたびに実行されるわけではありません。
- モデルの解決は受け付けの後に行われるため、プロバイダー単位のスコープは利用できません。

編集内容は、永続化される正規のユーザー入力になります。準備が失敗するか中断された場合、OpenCode はそのプロンプトを受け付けません。

プロンプトフックはリトライしても安全なようにしてください。フックは、副作用が厳密に 1 回だけ実行されることを保証する境界ではありません。

- すでに保留中または配信済みの ID でリトライすると、フックは再実行されず、元の受け付け結果が返されます。
- 同時に送信された場合はフックが複数回実行されることがありますが、最初に成功した受け付けだけが採用されます。
- プロンプトフックは入力を変換するためのもので、型付きの拒否 API はありません。

#### モデルリクエスト

モデルへの送信の直前に、組み立てられたシステム指示、メッセージ、ツール、リクエストオプションを変更します。セッションが発行するリクエストの種類ごとに専用のフックがあるため、プラグインはエージェントループと補助的なリクエストを区別して扱えます。

- `context` は、ツールによる継続を含むエージェントループで実行されます。
- `compaction` は、チェックポイントの要約で実行されます。`messages` は要約対象のトランスクリプトで、OpenCode はフックの実行後に要約用のプロンプトを追加します。`result` を設定すると、モデル呼び出しを省略してコンテキスト圧縮の結果を自分で記録できます。`result` には、完了した圧縮メッセージと同じフィールドを指定します。
- `generate` は、一時的な `ctx.session.generate` の呼び出しで実行されます。
- `title` は、タイトルの生成で実行されます。`agent` と `tools` はありません。`result` を設定すると、タイトルを自分で指定できます。

```ts
await ctx.session.hook("context", (event) => {
  event.system.push({ type: "text", text: "Keep the review focused on correctness." })
  delete event.tools.write
  event.options.temperature = 0.2
  event.options.maxTokens = 8_000
})

await ctx.session.hook("compaction", async (event) => {
  event.result = { summary: await summarize(event.messages) }
})
```

変更は送信されるモデル呼び出しにのみ影響し、永続化された履歴や設定には影響しません。すべてのリクエストに適用したいフックは、種類ごとに登録する必要があります。

リクエストのオーバーライドには、次のルールが適用されます。

- `options` はモデル呼び出しごとに空の状態から始まり、解決済みのモデル設定は含まれません。
- 型付きのキーは生成設定です。それ以外のキーは、プロバイダーオプションとして選択されたプロトコルに渡されます。
- フックは登録順に実行され、前のフックによるオーバーライドを参照できます。
- リクエストのオーバーライドはモデルのデフォルトより優先され、モデルのデフォルトはルートのデフォルトより優先されます。
- プロバイダーオプションのオブジェクトは再帰的にマージされます。配列とスカラー値は、前の値を置き換えます。
- オーバーライドを削除するか `undefined` に設定すると、設定済みのデフォルトにフォールバックします。デフォルト自体が削除されるわけではありません。
- 生の HTTP ボディのオーバーレイは、プロトコルへの変換後に適用され、変換結果のフィールドを上書きできます。

#### プロバイダーオプション

プロバイダーオプションには、生の HTTP ボディのフィールドではなく、選択されたプロトコルのセマンティックなオプション名を使用します。プロバイダー固有の設定は、対応するプロバイダーにスコープしてください。たとえば OpenAI Responses では `reasoningEffort` を使用します。

```ts
await ctx.session.hook(
  "context",
  (event) => {
    event.options.reasoningEffort = "high"
  },
  { providerID: "openai" },
)
```

生成オプションは、選択されたプロトコルとモデルによって異なります。

- `maxTokens` は、セマンティックな出力トークンの上限です。
- Gemini は `topK` をサポートしていますが、OpenAI Responses では公開されていません。

#### model.request フック

モデルリクエストの設定を変更します。必要に応じて、フックを 1 つのプロバイダーにスコープできます。イベントには、後述の HTTP フックと同じ `kind` が含まれます。

```ts
await ctx.session.hook(
  "model.request",
  (event) => {
    event.headers["x-plugin"] = "review"
  },
  { providerID: "anthropic" },
)
```

#### ネイティブ HTTP

プロバイダーへのネイティブなリクエストまたはレスポンスを変更します。ボディは 1 回しか読み取れないストリームなので、読み取る前にボディを複製するか置き換えてください。

どちらのフックも、セッションが発行するすべてのリクエストで実行されます。`event.kind` は、リクエストを発行したフローを示します。エージェントループでは `"primary"`、チェックポイントの要約では `"compaction"`、タイトルの生成では `"title"`、一時的な `ctx.session.generate` の呼び出しでは `"generate"` です。補助的なリクエストを区別するには、エージェント ID ではなくこの値を使用してください。

```ts
await ctx.session.hook("http.request", (event) => {
  event.request.headers.set("x-session-id", event.sessionID)
  if (event.kind === "title") event.request.headers.set("x-priority", "background")
})

await ctx.session.hook("http.response", (event) => {
  event.response = new Response(event.response.body, {
    status: event.response.status,
    headers: { ...Object.fromEntries(event.response.headers), "x-plugin": "review" },
  })
})
```

#### ネイティブ WebSocket（実験的）

WebSocket でストリーミングするプロバイダーは、セッションごとに 1 つの接続を開き、リクエスト間で再利用します。そのため、その通信は `http.request` と `http.response` からは見えません。`experimental.ws.handshake` フックは、接続が選択される前に、モデル呼び出しごとに 1 回実行されます。このフックには、HTTP フックと同じ `sessionID`、`agent`、`model`、`kind` に加えて、接続の `url` と `headers` が含まれます。`url` や `headers` を変更すると、リクエストが使用するソケットが変わるため、ローテーションされた Bearer トークンでは接続が開き直されます。

HTTP フックは、WebSocket ルートのフォールバック先となるリクエストを含め、すべての HTTP リクエストで引き続き実行されます。

```ts
await ctx.session.hook(
  "experimental.ws.handshake",
  async (event) => {
    event.headers.authorization = `Bearer ${await mintToken(event.url)}`
    delete event.headers["api-key"]
  },
  { providerID: "azure" },
)
```

`experimental.ws.send` と `experimental.ws.receive` は、フレームそのものを公開します。これは、HTTP のリクエストやレスポンスのボディを編集することに相当する WebSocket 版の機能です。`send` は、プロバイダーのドライバーが送信フレームを構築した後、書き込む前に実行されます。`receive` は、受信した各フレームに対して、ドライバーがそれを処理する前に実行されます。どちらもフレームを文字列として保持し、フックが戻った時点で `frame` に入っている内容を送信します。

OpenCode は書き換えられたフレームを検証しません。ドライバーはプロバイダーからの応答をもとに状態を追跡するため、プロトコル上の意味を変える書き換えは、HTTP ボディを書き換える場合と同様に、プラグインの責任となります。

```ts
await ctx.session.hook(
  "experimental.ws.send",
  (event) => {
    const body = JSON.parse(event.frame)
    if (body.type === "response.create") body.metadata = { ...body.metadata, session: event.sessionID }
    event.frame = JSON.stringify(body)
  },
  { providerID: "openai" },
)

await ctx.session.hook("experimental.ws.receive", (event) => {
  if (event.frame.includes('"type":"error"')) console.error(event.frame)
})
```

これらのフックは実験的なもので、名前や形式が変更される可能性があります。

#### リトライポリシー

プロバイダーでの失敗に対するリトライの判断をオーバーライドしたり、リトライまでの遅延（ミリ秒）を置き換えたりします。このフックは、OpenCode が失敗を分類してポリシーを提案した後、リトライがスケジュールされる前に実行されます。OpenCode が次の試行を内部でどのように実行するかは公開されません。

```ts
await ctx.session.hook("retry", (event) => {
  if (event.error.status === 429) {
    event.decision = { retry: true, delay: 10_000 }
    return
  }
  if (event.error.type === "provider.invalid-request" && event.attempt === 2) {
    event.decision = { retry: true, delay: 0 }
    return
  }
  if (event.attempt >= 3) event.decision = { retry: false }
})
```

リトライフックでは、終了扱いの失敗をリトライ可能にしたり、提案されたリトライを拒否したりして、OpenCode の初期の `decision` を変更できます。

リトライの判断には、次のルールが適用されます。

- 複数のフックは登録順に実行され、後のフックは現在の判断を参照できます。
- 組み込みの最大試行回数は、引き続き絶対的な上限です。
- `attempt` は、判断の対象となっている実際の試行の番号です。最初のリクエストが `1` なので、最初のリトライは `2` になります。
- `NaN`、無限大、負の値などの無効な遅延は、計算された遅延にフォールバックします。
- コンテキストのオーバーフローからの回復は別の仕組みです。同じリクエストをリトライするのではなく、会話を圧縮するためです。

### 権限

設定済みのルールが評価された後、アクションが実行されるか権限の確認が表示される前に、権限の判断を見直します。

```ts
await ctx.permission.hook("evaluate", async (event) => {
  if (event.action === "read") return

  const messages = await ctx.session.context({ sessionID: event.sessionID })
  const review = await ctx.generate.text({
    model: { providerID: "anthropic", id: "claude-sonnet-4-6" },
    prompt: buildSafetyPrompt({ messages, action: event.action, resources: event.resources }),
  })
  const decision = parseDecision(review.text)

  event.effect = decision.effect
  event.message = decision.reason
})
```

権限フックには、次のルールが適用されます。

- フックは、`allow` と `ask` の判断で実行されます。

- フックは `effect` を `allow`、`ask`、`deny` のいずれかに変更できます。
- `message` は、エスカレーションされた権限リクエストに表示されるか、拒否の理由になります。

## 公開

パッケージとして配布するプラグインも、ローカルプラグインと同じデフォルトエクスポートを使用します。最小限のマニフェストは次のとおりです。

```json title="package.json"
{
  "name": "opencode-acme-plugin",
  "version": "1.0.0",
  "type": "module",
  "exports": {
    ".": "./src/index.ts",
    "./rpc": "./src/rpc.ts"
  },
  "dependencies": {
    "@opencode/plugin": "latest"
  }
}
```

`./rpc` エクスポートは省略可能です。ほかのプラグインやクライアントが実装を読み込まずにインポートできる、共有の [RPC コントラクト](/build/plugins/rpc)を公開する場合に含めます。

対象とする OpenCode リリースと互換性のあるバージョンを使用し、ワークスペースでリンクしたコピーだけでなく、インストールしたパッケージもテストしてください。新しい API コントラクトを採用したら、互換性のあるプラグインのアップデートを公開してください。

## V1 のサポート

1 つのプラグインで、同じパッケージのエントリポイントから V1 と V2 の両方をサポートできます。V1 の `server()` 関数と V2 の `setup()` 関数を持つ 1 つのオブジェクトをデフォルトエクスポートします。

```ts title="src/index.ts"
import { Plugin } from "@opencode/plugin"

export default {
  ...Plugin.define({
    id: "example",
    async setup(ctx) {
      await ctx.tool.hook("execute.before", () => {
        console.log("A tool is about to run")
      })
    },
  }),
  async server() {
    return {
      "tool.execute.before": async () => {
        console.log("A tool is about to run")
      },
    }
  },
}
```

- V1 は `server()` を呼び出し、返されたフックを使用します。
- V2 は、デフォルトエクスポートの `id` と `setup()`（Effect プラグインの場合は `effect()`）を読み取り、`server()` は無視します。
- それぞれの実装は、それぞれの API で記述してください。エクスポートを共有しても、V1 のフックが V2 のフックに変換されるわけではありません。
- `Plugin.define(...)` をエクスポートするオブジェクトに展開すると、V2 の定義が `server()` とは別に型チェックされます。

V1 のオブジェクト形式は、OpenCode `1.18.29` でサポートされています。それより古い V1 リリースでは、関数のエクスポートが想定されている場合があります。サポートする予定の最も古い V1 リリースと V2 の両方で、インストールしたパッケージをテストしてください。
