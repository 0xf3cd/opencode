title: "Cloudflare"
---

Cloudflare Durable Object 内では `@opencode/sdk/workerd` を使用します。このプロファイルはオブジェクトの SQLite ストレージを使用し、退避（eviction）からの復旧に備えて永続イベントを保存します。また、利用できないローカルファイルシステムとプロセスのサービスを代替実装に置き換えます。

```sh
bun add @opencode/sdk
```

リクエストごとにホストを作成するのではなく、Durable Object インスタンスの存続期間中は 1 つのホストを保持します。

```ts
import { OpenCodeWorkerd } from "@opencode/sdk/workerd"
import myPlugin from "./my-plugin"

export class OpenCodeDO {
  private readonly opencode: Promise<OpenCodeWorkerd.Interface>

  constructor(state: DurableObjectState) {
    this.opencode = state.blockConcurrencyWhile(() =>
      OpenCodeWorkerd.create({
        storage: state.storage,
        config: { default_agent: "build" },
        plugins: [myPlugin],
      }),
    )
  }

  async fetch() {
    const opencode = await this.opencode
    return Response.json(await opencode.server.info())
  }
}
```

`blockConcurrencyWhile` は、ホストの準備が整うまで Durable Object のイベントをすべて受け付けず、初期化に失敗した場合はオブジェクトをリセットします。保持した Promise により、リクエストハンドラーは起動後に同じホストへ直接アクセスできます。

```ts
constructor(state: DurableObjectState) {
  this.opencode = state.blockConcurrencyWhile(() =>
    OpenCodeWorkerd.create({ storage: state.storage }),
  )
}
```

Wrangler は、`workerd` パッケージ条件によって OpenCode の Workerd 対応の実装を選択します。Cloudflare はクリーンアップを実行せずに Durable Object を退避させることがあるため、正しく動作するかどうかは `close()` の呼び出しに依存しません。

```jsonc title="wrangler.jsonc"
{
  "compatibility_flags": ["nodejs_compat"]
}
```

## カスタマイズ

Worker にバンドルしたプラグインを登録して、OpenCode インスタンスをカスタマイズできます。`OpenCodeWorkerd.create()` にプラグインを渡すと、エージェント、モデル、ツールなどの動作をカスタマイズできます。

```ts
import { Plugin } from "@opencode/plugin"
import { OpenCodeWorkerd } from "@opencode/sdk/workerd"

const plugin = Plugin.define({
  id: "customize-agent",
  async setup(ctx) {
    await ctx.agent.transform((agents) => {
      agents.update("build", (agent) => {
        agent.description = "Builds features and fixes bugs for our team"
      })
    })
  },
})

await OpenCodeWorkerd.create({
  storage: state.storage,
  config: { default_agent: "build" },
  plugins: [plugin],
})
```

プラグインのフック、変換、ツール、プラグインコンテキストの全体については、[プラグインのドキュメント](/build/plugins)を参照してください。
