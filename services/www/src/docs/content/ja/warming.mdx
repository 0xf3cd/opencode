---
title: "ウォームアップ"
---

セッションのウォームアップは、プロンプトの合間に作業を中断している間、定期的にモデルへリクエストを送信して、プロバイダー側のプロンプトキャッシュなどの短時間しか保持されない状態を維持する機能です。デフォルトでは無効です。

ウォームアップは、どの [OpenCode の設定ファイル](/config)でも有効にできます。

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "warming": true,
}
```

この設定では、最近アクティブだったセッションでモデルへのリクエストがないまま 4 分が経過すると、OpenCode がそのセッションをウォームアップします。その後は、ウォームアップ以外の最新のリクエストから 30 分が経過するまで、4 分ごとにウォームアップを続けます。

## オプション

ウォームアップのプロンプト、アイドル間隔、有効期間を変更するには、オブジェクト形式を使用します。

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "warming": {
    "prompt": "Do not perform any work. Reply with exactly: OK",
    "interval": "5 minutes",
    "duration": "1 hour",
  },
}
```

| フィールド | デフォルト | 用途 |
| --- | --- | --- |
| `prompt` | キープアライブ用の指示 | ウォームアップリクエストのたびに、一時的なユーザーメッセージとして追加されます。デフォルトでは、作業をせず、ツールを使わず、`OK` と返答するようモデルに指示します。 |
| `interval` | `"4 minutes"` | 次のウォームアップリクエストまでのアイドル時間です。 |
| `duration` | `"30 minutes"` | ウォームアップ以外の最新のモデルリクエストから数えた、ウォームアップの有効期間です。 |

オブジェクトで省略したフィールドはデフォルト値のままになります。たとえば、次の設定では間隔だけが変更されます。

```jsonc title="opencode.jsonc"
{
  "warming": {
    "interval": "2 minutes",
  },
}
```

## 期間の指定

`interval` と `duration` には期間を表す文字列を指定します。どちらも 0 より大きい有限の値として解釈できる必要があります。そうでない場合、OpenCode はウォームアップを行わず、警告をログに記録します。

```jsonc title="opencode.jsonc"
{
  "warming": {
    "interval": "30 seconds",
    "duration": "1 hour",
  },
}
```

## タイミング

ウォームアップは、ウォームアップ以外のモデルリクエストの後に始まります。ウォームアップリクエストが完了すると次のアイドル間隔が始まりますが、有効期間は延長されません。

```text
00:00  normal model request
00:04  warming request
00:08  warming request
00:30  warming stops
```

ウォームアップ以外の新しいモデルのアクティビティがあると、両方のタイマーがリセットされます。間隔が有効期間と同じかそれより長い場合は、ウォームアップリクエストが送信される前に有効期間が終了します。

```text
00:00  normal model request
00:20  normal model request; window restarts
00:24  warming request
00:50  warming stops
```

## リクエスト

ウォームアップリクエストでは、セッションの現在のモデル、エージェント、指示、会話のコンテキストが使われます。OpenCode は設定されたプロンプトを一時的に追加し、モデルを 1 回呼び出して、そのレスポンスを破棄します。

```text
[current session context]
[transient user message: keep-alive prompt]
→ one model response, discarded
```

このリクエストによって、入力が受け付けられたり、履歴にメッセージが追加されたり、永続的なセッションの状態が変更されたりすることはありません。OpenCode はローカルのツール呼び出しを実行せず、ツールのループも続行しません。デフォルトのプロンプトでも、ツールを使わないようモデルに指示しています。

## 失敗時の動作

ウォームアップの失敗はログに記録されますが、セッションが失敗したり変更されたりすることはありません。OpenCode は次の間隔まで待ってから再試行します。その間も、元の有効期間のカウントダウンは続きます。

```text
00:04  warming request fails; session is unchanged
00:08  next warming attempt
```

## コスト

ウォームアップリクエストは、実際のプロバイダーへのリクエストです。ほかのモデルリクエストと同様に、トークンを消費し、コストが発生し、レート制限の対象となり、失敗することもあります。

- 間隔を短くすると、リクエスト数が増えます。
- 有効期間を長くすると、より多くのウォームアップリクエストが送信される可能性があります。
- プロバイダー側で得られる効果が増加する使用量に見合う場合にのみ、ウォームアップを有効にしてください。

たとえばデフォルト設定では、中断のない 30 分間の有効期間中に、4、8、12、16、20、24、28 分の時点で最大 7 回のウォームアップが試行されます。

## 無効化

明示的に無効にするには、`warming` を `false` に設定します。このフィールドを省略した場合も、ウォームアップは無効のままです。

```jsonc title="opencode.jsonc"
{
  "warming": false,
}
```
