---
title: "コンテキスト圧縮"
---

コンテキスト圧縮は、長いセッションの古い会話を要約に置き換えて空きを作る機能です。これにより、モデルのコンテキスト上限を超えてもセッションを続けられます。

## 仕組み

セッションがモデルのコンテキスト上限に近づくと、OpenCode は直近の会話（デフォルトでは約 15,000 トークン）以外のすべてを要約します。要約ができると、その直近の会話の前に要約が配置され、そこからセッションが続行されます。

```text
before   [ system prompt ][ older conversation ............ ][ recent 15k ][ pending work ]
after    [ system prompt ][ summary ][ recent 15k ][ pending work ]
```

モデルからは、要約は過去の会話として見えます。2 回目以降の圧縮では、最初から作り直すのではなく、同じ要約が更新されます。

## 自動圧縮

自動圧縮はデフォルトで有効です。

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "compaction": {
    "auto": true,
    "keep": { "tokens": 15000 },
  },
}
```

圧縮では情報の一部が失われます。直近の詳細を正確に残したい場合は、`keep.tokens` を増やすか、自動圧縮が行われる前に自分で圧縮をリクエストしてください。

## 手動圧縮

履歴が短くても、圧縮はいつでもリクエストできます。

```sh
opencode api post /api/session/ses_example/compact --data '{}'
```

`api` コマンドは、バックグラウンドサービスを検出して認証します。そのレスポンスはリクエストが受け付けられたことを示すだけで、要約の完了は待ちません。完了を知るには `session.compaction.*` イベントを追跡します。操作の詳細については、[API リファレンス](/api)を参照してください。

| ルール | 動作 |
| --- | --- |
| タイミング | 次の安全なタイミングで、待機中のプロンプトより先に実行されます。 |
| 重複 | 保留中のリクエストがある間に行われたリクエストは、そのリクエストに統合されます。 |
| 自動圧縮との関係 | `compaction.auto` が `false` の場合も動作します。 |

`id` を渡すと、同一内容の再試行がべき等になります。同じ ID を別のリクエストに再利用すると、競合が返されます。

```sh
opencode api post /api/session/ses_example/compact --data '{"id":"msg_compact_once"}'
```

## 設定

`compaction` は、どの [OpenCode の設定ファイル](/config)にも追加できます。

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "compaction": {
    "auto": false,
    "keep": { "tokens": 24000 },
    "buffer": 16000,
  },
}
```

| フィールド | デフォルト | 動作 |
| --- | ---: | --- |
| `auto` | `true` | コンテキスト上限に近づくと自動的に圧縮し、プロバイダーがリクエストを長すぎるとして拒否した場合には 1 回だけ回復を試みます。手動圧縮は常に利用できます。 |
| `keep.tokens` | `15000` | 要約とともに残す直近の会話のおおよその量です。値を大きくすると詳細が多く残りますが、新しい作業に使える領域は少なくなります。 |
| `buffer` | 上限の 10% | モデルの上限に対して空けておくトークン数です。値を大きくすると、自動圧縮が早く始まります。 |

`keep.tokens` と `buffer` には 0 以上の整数を指定できます。

## プロバイダー

デフォルトでは、OpenCode がセッションのモデルを使って要約を作成します。一部のプロバイダーは、代わりにプロバイダー側で会話を圧縮できます。この機能は、`settings.compaction` でプロバイダーごとまたはモデルごとに有効にします。

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "settings": { "compaction": { "type": "native" } },
      "models": {
        "gpt-4.1": { "settings": { "compaction": { "type": "summary" } } },
      },
    },
  },
}
```

モデルの設定は、プロバイダーの設定よりも優先されます。`native` はプロバイダーの圧縮を、`summary` は OpenCode 独自の圧縮を使用します。

ネイティブ圧縮では、OpenCode は会話をプロバイダーの圧縮エンドポイントに送信します。プロバイダーは、古い会話の代わりとなる、中身を参照できない暗号化されたアイテムを返します。`keep.tokens` までの直近のメッセージと添付ファイルは、そのアイテムとともに保持されます。

```text
before   [ older conversation ........................ ][ recent user messages ]
after    [ encrypted checkpoint + recent user messages ]
```

| 項目 | 動作 |
| --- | --- |
| 対応状況 | OpenAI Responses のモデルが対象です。対応状況はデプロイやモデルによって異なります。 |
| しきい値 | 要約による圧縮と同じ `auto` と `buffer` の設定を使用します。手動のリクエストも利用できます。 |
| 移植性 | 暗号化されたチェックポイントは、同じプロバイダー、モデル、エンドポイントでのみ機能します。モデルを切り替えた場合、セッションは元の会話から続行されます。 |
| 長すぎる場合 | プロバイダーが圧縮を長すぎるとして拒否した場合、OpenCode はより小さなリクエストで再試行します。要約による圧縮には切り替わりません。 |

## 要約

要約は、別のエージェントがそこから作業を引き継げるように構造化されています。

```md
## Objective
Finish the authentication migration.

## Next Move
- Update the callback handler.
- Verify the login flow.
```

要約には、目的と要件、決定事項、完了した作業と進行中の作業、障害と次の手順、関連ファイルが含まれます。要約とともに残される直近の会話では、長いツール出力は短縮され、添付ファイルのデータは短い説明に置き換えられます。

圧縮後は、その時点の指示ファイルの内容がセッションの基準になります。詳しくは[指示](/instructions)を参照してください。

## 制限事項

| 制限 | 結果 |
| --- | --- |
| モデル | 圧縮にはセッションのモデルが使われます。圧縮専用のモデルはありません。 |
| 履歴 | 圧縮には、置き換えられる古い会話が必要です。リクエストの大部分が固定の指示とツールのスキーマで占められている場合、空きは作れません。 |
| サイズ | 圧縮対象の会話自体が長すぎる場合、OpenCode は短縮したテキスト版を送信し、最も古いやり取りを省くことがあります。 |
| 回復 | 長すぎるとして拒否されたリクエストは、圧縮されてから 1 回だけ再試行されます。2 回目も拒否された場合はエラーが返されます。 |
| 保存 | モデルに送信されなくなった以前のメッセージも、保存されたまま残ります。 |

たとえば、次のような場合は圧縮では解決できません。

```text
128k context = 120k fixed instructions and tools + 8k conversation
```

## 移行

V1 では末尾のターンを残す方式と刈り込み（pruning）を使っていました。V2 では要約と `compaction.keep.tokens` を使用します。

```jsonc
{
  "compaction": {
    "keep": { "tokens": 15000 }
  }
}
```

このページの設定と動作は V2 に適用されます。
