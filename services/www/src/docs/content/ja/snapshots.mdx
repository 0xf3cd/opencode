---
title: "スナップショット"
---

スナップショットを使うと、直近の会話とファイルの変更をまとめて元に戻せます。直近の作業をやり直すのに便利ですが、重要なものについては Git のコミットやバックアップを残してください。

## ワークフロー

やり直したい応答の後に `/undo` を実行します。OpenCode はロールバックをステージし、影響を受けたファイルを復元して、削除されたプロンプトを編集できるように入力欄に戻します。

```text
/undo

# Edit the restored prompt, then submit it again.
Add validation without changing the public API.
```

編集したプロンプトを送信すると、ステージされたロールバックが確定します。送信する前に `/redo` を実行すると、ロールバックを取り消し、`/undo` 前の会話とファイルを復元できます。

```text
/redo
```

ターミナルには、次のデフォルトのショートカットも用意されています。

| 操作 | コマンド | ショートカット |
| --- | --- | --- |
| 直前のメッセージのロールバックをステージ | `/undo` | `<leader>u` |
| ステージされたロールバックを取り消し | `/redo` | `<leader>r` |

それより前のメッセージを選択して **Revert** を選ぶと、その時点までのロールバックをステージすることもできます。

## 取得

OpenCode は、モデルのステップごとに、モデル呼び出しの直前と、ステップが成功または失敗として記録された時点でスナップショットの取得を試みます。アシスタントメッセージには、これら 2 つのスナップショットの間で変更されたパスが記録されます。

```text
before model step ── snapshot A
model edits src/api.ts
step finishes ────── snapshot B ── changed: src/api.ts
```

取得はベストエフォートで行われます。どちらかのスナップショットを取得できなかった場合も会話は続行されますが、そのステップでは復元できるファイルの変更がないことがあります。

## 対象範囲

スナップショットの対象は、Git worktree 内にあるセッションのアクティブディレクトリです。たとえば、`packages/app` で開いたセッションでは、`packages/app` 以下の対象ファイルが取得され、リポジトリ内のほかの場所の変更は取得されません。

| 内容 | 取得 | 例 |
| --- | --- | --- |
| アクティブディレクトリ内の追跡対象ファイル | される | `packages/app/src/app.tsx` |
| 無視されていない未追跡ファイル（1 ファイルあたり 2 MiB まで） | される | `packages/app/notes.txt` |
| Git で無視されているファイル | されない | `packages/app/dist/app.js` |
| 2 MiB を超える個々の未追跡ファイル | されない | `packages/app/debug.log` |
| アクティブディレクトリ外のファイル | されない | `packages/server/src/index.ts` |
| Git のメタデータとその他の副作用 | されない | コミット、ブランチ、データベース、プロセス |

ファイルシステムのスナップショットには Git リポジトリが必要です。リポジトリ外でも `/undo` で会話履歴をロールバックすることはできますが、ファイルは復元できません。

## 復元

ロールバックで復元されるのは、選択した会話の境界より後のアシスタントのステップに関連付けられたパスだけです。各パスは、最初に取り消されたステップより前の状態に戻ります。それらのステップで作成されたファイルは、その時点で存在していなかった場合は削除されます。

| タイムライン | `src/api.ts` | `src/new.ts` |
| --- | --- | --- |
| 選択した境界 | バージョン A | 存在しない |
| 以降のアシスタントのステップ | バージョン B | 作成 |
| ロールバック後 | バージョン A | 削除 |

それらのステップに関連付けられていないパスは変更されません。影響を受けるパスに対する現在の編集は上書きされる可能性があるため、作業を続ける前に復元の概要と `git diff` を確認してください。

```sh
git diff --stat
git diff
```

## 保存場所

OpenCode は、スナップショットをデータディレクトリ内にある独立した内部 Git オブジェクトデータベースにローカルで保存します。スナップショットの取得によって、コミットが作成されたり、ブランチが移動したり、リポジトリのインデックスが意図的に変更されたりすることはありません。

```sh
# Your repository remains an ordinary dirty worktree after capture.
git status --short
```

スナップショットのオブジェクトには、追跡対象ファイルと対象となる未追跡ファイルの内容がすべて含まれる場合があります。OpenCode のデータディレクトリは、機密性の高いローカルデータとして扱ってください。

## 設定

スナップショットはデフォルトで有効です。今後のファイルシステムの取得を停止するには、[設定](/config#snapshots)で `snapshots` を `false` に設定します。

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "snapshots": false,
}
```

スナップショットを無効にしても、保存済みのスナップショットは削除されません。会話のロールバックは引き続き利用できますが、ファイルシステムの状態が取得されていなければ、関連するファイルの変更は復元できません。

## 安全性

スナップショットは便利な機能ですが、トランザクションやバックアップではありません。

- シェルコマンドは、サービス、プロセス、ネットワークリソース、データベース、Git の状態、無視された出力、アクティブディレクトリ外のファイルを変更する可能性があります。スナップショットを復元しても、これらの影響は元に戻りません。
- 取得に失敗した場合や、使用できるスナップショットのペアがない場合、中断または失敗した作業による変更が残ることがあります。
- 影響を受けるパスを復元すると、その現在の内容は上書きされます。ステージされたロールバックを取り消した場合も、その後の編集が上書きされることがあります。
- OpenCode はセッションの実行中にはロールバック操作を拒否しますが、取得から復元までの間に外部のエディターやコマンドによって worktree が変更される可能性はあります。
- ロールバックを確定すると、アクティブな会話の表示からメッセージが削除されますが、永続的なセッション履歴や既存のスナップショットストレージからは削除されません。安全な消去ではありません。

未コミットの変更がある worktree で `/undo` を使う前に、重要な作業はコミットまたはバックアップしてください。
