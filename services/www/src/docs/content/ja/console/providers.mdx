---
title: "プロバイダー"
description: "自分のモデルプロバイダーのアカウントを OpenCode Console のワークスペースに接続し、メンバーが使えるモデルを選択します。"
---

Anthropic、OpenAI、AWS Bedrock など、すでに契約しているプロバイダーのアカウントを接続し、そのモデルをワークスペースの全員と共有できます。Console が認証情報を保管し、各プロバイダーをゲートウェイ経由で提供するため、メンバーはプロバイダーのキーを見ることなくモデルを利用できます。同じゲートウェイは、[プロバイダー API](/console/api/providers) を通じて独自のツールからも利用できます。

オーナーと管理者は **Providers** タブでプロバイダーを管理します。メンバーは `/connect` を実行すると、OpenCode で有効なモデルを使えるようになります。

## プロバイダーの接続

1. **Providers** を開き、**Connect Provider** をクリックします。
2. カタログからプロバイダーを選び、その API キーを入力します。
3. 必要に応じて **Test connection** をクリックし、**Save** をクリックします。

カタログには Anthropic、OpenAI、Google、xAI、DeepSeek、Mistral、Groq、OpenRouter をはじめ、多数のプロバイダーが含まれています。カタログのプロバイダーには、モデルがあらかじめ設定されています。

### クラウドプロバイダー

クラウドプロバイダーでは、追加の情報がいくつか必要です。

| プロバイダー | 必要な情報 |
| --------------------- | ------------------------------------- |
| Azure                 | リソース名と API キー |
| AWS Bedrock           | リージョンと API キー |
| Google Vertex AI      | リージョンとサービスアカウントの JSON |
| Cloudflare AI Gateway | アカウント ID、ゲートウェイ ID、API トークン |
| Databricks            | ワークスペース URL とトークン |

### カスタムプロバイダー

**Add Custom Provider** をクリックしてその他のエンドポイントを接続し、**Add Model** でモデルを追加します。

| フィールド | 説明 |
| ---------- | ------------------------------------------------------------------------------- |
| Base URL   | Console がリクエストを転送する先。たとえば `https://api.deepseek.com/v1`。 |
| Format     | Chat Completions、Responses API、Anthropic Compatible、Google Generative AI のいずれか。 |
| Auth mode  | Bearer、API key header、Custom header のいずれか。 |
| Credential | Console がプロバイダーに送信するキー。 |

## モデルの選択

プロバイダーを開くと、そのモデルが表示されます。メンバーが利用できるのは、有効にしたモデルだけです。

- **Enabled** トグルでモデルをオンまたはオフにします。
- **New models** をオンにすると、プロバイダーが今後追加するモデルも有効になります。

## モデルの編集

モデルをクリックすると編集できます。変更はパネルを閉じたときに保存されます。

| セクション | 変更できる内容 |
| ------------- | --------------------------------------------------------------- |
| General       | 表示名、API ID、ツール対応、入力と出力の種類 |
| Variants      | 独自のヘッダーやボディを持つバリアント |
| Configuration | デフォルトのバリアント、リクエストヘッダーとボディ、トークン上限 |
| Cost Tiers    | 100 万トークンあたりの入力、出力、キャッシュ読み取り、キャッシュ書き込みの料金 |

### カスタム料金

カタログのモデルには、最初はプロバイダーの定価が設定されています。OpenAI との契約で割引を受けているなど、個別の料金で契約している場合は、**Cost Tiers** で料金を上書きしてください。これにより、使用量レポートと[予算](/console/budgets)が実際の支払額と一致します。

| フィールド | 定価 | 契約料金 |
| ---------------- | ---------- | ---------- |
| 入力料金 | $2.50      | $2.00      |
| 出力料金 | $15.00     | $12.00     |
| キャッシュ読み取り料金 | $0.25      | $0.20      |

変更した料金は、プロバイダーのページで強調表示されます。定価に戻すには、フィールドの **Restore default value**、またはモデルの **⋯ › Restore...** を使用します。

一定のコンテキストサイズを超えると料金が上がるモデル（たとえば 200K トークンを超えるプロンプト）では、**Context** ティアを追加します。

### カスタムモデル

カタログにないモデルを追加するには、**Add Model** をクリックし、**Display name** と **Model ID** を入力します。既存のモデルの設定をもとに作成する場合は、そのモデルの **⋯ › Duplicate...** を使用します。

## OpenCode のモデル

**Models** タブでは、Console が提供する[モデル](/console/models)を管理します。これらのモデルの料金はワークスペースのクレジットから支払われます。操作はプロバイダーのページと同じです。

- モデルを個別にオンまたはオフにします。
- **Free models** をオフにすると、ワークスペースで無料モデルをブロックします。
- **New models** をオンにすると、Console の新しいモデルが自動的に有効になります。

自分のプロバイダーだけを使う場合は、**⋯ › Disable** でプロバイダー全体を無効にします。

## OpenCode での利用

メンバーは `/connect` を実行してワークスペースを選択します。有効な各プロバイダーは「ワークスペース名 / プロバイダー名」の形式で表示され、`/models` にはその有効なモデルが一覧表示されます。

```text
Acme Inc. / Anthropic
```

全員の OpenCode でワークスペースのプロバイダーだけを使うように制限するには、**Settings › General** で **Managed providers only** をオンにします。

## 無効化と削除

プロバイダーの **⋯** メニューを開きます。

- **Disable**：プロバイダーとそのモデルをメンバーから非表示にします。設定は保持されます。
- **Remove...**：プロバイダーとそのモデルを削除します。ダイアログには最近それを使用したユーザーが表示され、代わりに無効化する **Disable instead** も選択できます。

キーをローテーションするには、プロバイダーのページで認証情報をクリックし、新しいキーを入力します。

## 請求

トークンの料金はプロバイダーから請求され、Console はそれに対してクレジットを消費しません。ただし Console は、各リクエストとモデルの料金設定に基づくコストを記録するため、使用量レポートと[予算](/console/budgets)にはこれらも含まれます。

OpenCode ではなく独自のツールからプロバイダーを呼び出すには、[プロバイダー API](/console/api/providers) を使用します。
