---
title: "ディレクトリ同期"
description: "Okta、Microsoft Entra ID、または任意の SCIM 2.0 対応 ID プロバイダーから、ワークスペースのメンバーを自動的に追加・削除します。"
---

ディレクトリ同期（SCIM 2.0）は、ID プロバイダーでユーザーを割り当てるとワークスペースに追加し、割り当てを解除するとアクセスを削除します。ロールは引き続き Console で管理します。

```text
https://opencode.ai/console/scim/v2
```

## 事前準備

- ワークスペースに [SSO](/console/sso) を設定します。
- ユーザーがサインインに使うすべてのメールドメインを[検証](/console/sso#verify-email-domains)します。ディレクトリ同期で追加されるのは検証済みドメインのユーザーだけです。それ以外のユーザーは [Members](/console/members) から招待してください。

## トークンの作成

1. **Settings › Security** を開き、**Directory sync** の下にある **Set up** をクリックします。
2. **SCIM base URL** とトークンをコピーします。トークンは一度しか表示されないため、シークレットマネージャーに保管してください。

ID プロバイダーは、すべてのリクエストでこのトークンを送信します。

```text
Authorization: Bearer <token>
```

## ID プロバイダーの接続

### Okta

1. **SCIM 2.0 Test App (Header Auth)** アプリを追加します。
2. ベース URL を設定し、**API Token** に `Bearer ` に続けてトークンを入力します。
3. **Create Users**、**Update User Attributes**、**Deactivate Users** を有効にします。**Import Groups** とパスワード同期はオフのままにします。

### Microsoft Entra ID

1. エンタープライズアプリで **Provisioning** を開き、モードを **Automatic** に設定します。
2. ベース URL を **Tenant URL** に、トークンを **Secret Token** に入力します。
3. ユーザーとグループを割り当て、プロビジョニングを開始します。

### その他のプロバイダー

ヘッダートークン認証に対応した SCIM 2.0 アプリを使い、ベース URL を指定します。Console は `/Users` と `/Groups` エンドポイントに対応しています。

まずテスト用に 1 人を割り当てます。最初のリクエストの後、**Directory sync** に **Connected to your identity provider** と表示されます。

## 同期される内容

| ID プロバイダーでの操作 | Console での結果 |
| ------------------------- | --------------------------------------------------------------------------------- |
| ユーザーの割り当て | **Member** として追加されます。既存のメンバーはロールが維持されます。 |
| 名前の更新 | プロフィールが更新されます。 |
| 割り当て解除または無効化 | アクセスが停止され、**Deactivated** と表示されます。そのユーザーが作成した API キーは取り消されます。 |
| 再割り当て | アクセスが復元されます。取り消されたキーは取り消されたままです。 |
| 削除 | ワークスペースから削除されます。そのユーザーのアカウントやほかのワークスペースには影響しません。 |

- ロールとメールアドレスはディレクトリ同期では変更されません。
- 最後のオーナーは無効化も削除もできません。
- [Go](/console/go) のサブスクリプションがあるワークスペースでは、ディレクトリ同期でメンバーを追加できません。

## グループ

グループをプッシュすると、そのメンバーにタグを付けられます。たとえば Okta の **Push Groups** や Entra のグループ割り当てを使います。グループをプッシュする前に、ユーザーを割り当てておいてください。

```text
Platform Admins  →  platform-admins
```

各グループは、そのメンバーにグループ名に基づくタグを付けます。**Settings › Security › Group tags** では、タグの名前を変更したり、複数のグループを 1 つのタグにまとめたり、グループへのタグ付けを停止したりできます。グループから外れると、そのタグは削除されます。

## トークンのローテーション

1. **New token** をクリックし、新しいトークンを ID プロバイダーに設定します。
2. 新しいトークンに最終使用日時が表示されるまで待ちます。
3. 古いトークンを取り消します。

トークンを取り消すと以降の更新は停止しますが、既存のメンバーは変わりません。SSO 接続を削除すると、すべてのトークンが取り消されます。

## SSO とディレクトリ同期

ワークスペースでトークンを一度発行すると、SSO による[メンバーの自動追加](/console/sso#automatic-membership)は行われなくなります。後でトークンを取り消した場合でも、メンバーシップはディレクトリによって決まります。
