OpenCode Console では、OpenCode チームがテストして検証したモデルを提供しています。サインインしてクレジットを追加し、API キーを取得すると、OpenCode やほかのコーディングエージェントでこれらのモデルを使用できます。

Console は、OpenCode のほかのプロバイダーと同じように使えます。利用は**完全に任意**で、代わりにほかのプロバイダーを使うこともできます。一定の使用量が含まれるサブスクリプションについては、[OpenCode Go](/console/go) を参照してください。

## 利用方法

1. [Console](https://opencode.ai/console) にサインインし、請求情報とクレジットを追加して、API キーをコピーします。
2. TUI で `/connect` を実行し、OpenCode の従量課金プロバイダーを選択して、API キーを貼り付けます。

   ```text
   /connect
   ```

3. `/models` を実行して利用可能なモデルを確認し、1 つ選択します。

   ```text
   /models
   ```

料金はリクエストごとに発生し、アカウントにクレジットを追加して支払います。

### Jev

Jev は、高速で構造化された判断を行うための TypeSafe AI の System One モデルです。テキストを生成する代わりに、型付きの質問に照らして `state` を評価し、コードでそのまま使える値と確率を返します。はい/いいえ（`noul`）、多肢選択（`choice`）、ルーブリックに基づく評価（`score`）の質問に対応しています。

OpenCode Console の API キーを使い、`https://opencode.ai/inference/v1/systemone` エンドポイントを呼び出します。次の例では、サポートリクエストが緊急かどうかを判定します。

```bash
curl https://opencode.ai/inference/v1/systemone \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "jev-1.13",
    "state": "My payments have failed for three days and I am losing sales. Please help now.",
    "questions": {
      "is_urgent": {
        "type": "noul",
        "instructions": "Does this request require urgent attention?"
      }
    }
  }'
```

1 回のリクエストで複数の質問を送信できます。Jev はそれらを並列に評価し、それぞれの回答を対応する質問 ID の下に返します。

```bash
curl https://opencode.ai/inference/v1/systemone \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "jev-1.13",
    "state": "My order arrived late and the item is damaged. I want a refund.",
    "questions": {
      "department": {
        "type": "choice",
        "instructions": "Which team should handle this request?",
        "criteria": {
          "returns": "Refunds, exchanges, or damaged items",
          "shipping": "Delivery delays or lost packages",
          "billing": "Charges, invoices, or payment problems"
        }
      },
      "frustration": {
        "type": "score",
        "instructions": "How frustrated is the customer?",
        "criteria": ["Calm", "Frustrated", "Very angry"]
      }
    }
  }'
```

期間限定の無料モデルを使うには、`jev-1.13` の代わりに `jev-1.13-free` を指定します。質問の種類とレスポンスのフィールドの詳細については、[TypeSafe AI のドキュメント](https://docs.typesafe.ai/)を参照してください。

### 月間上限

ワークスペース全体と、チームの各メンバーに月間使用量の上限を設定できます。

たとえば月間使用量の上限を $20 に設定すると、Console が 1 か月に $20 を超えて使用することはありません。ただし、自動チャージを有効にしている場合は、残高がルールのしきい値を下回ったときに $20 を超えて請求されることがあります。

## 背景

利用できるモデルは数多くありますが、コーディングエージェントとしてうまく機能するものはわずかです。また、プロバイダーによって設定、パフォーマンス、品質が異なるため、OpenRouter などのゲートウェイ経由でアクセスしたモデルは異なる性能を示すことがあります。

<Callout type="tip">OpenCode と組み合わせてうまく機能するモデルとプロバイダーを厳選してテストしました。</Callout>

このカタログを作成するために、次のことを行いました。

1. 厳選したモデルをテストし、最適な実行方法について各モデルのチームと話し合いました。
2. プロバイダーと協力し、モデルが正しく提供されていることを確認しました。
3. モデルとプロバイダーの組み合わせごとにベンチマークを行い、自信を持っておすすめできる一覧を作成しました。

Console は、これらのモデルへのアクセスを提供する AI ゲートウェイです。

## 目標

Console を開発した目的は次のとおりです。

1. コーディングエージェントに最適なモデルとプロバイダーを**ベンチマーク**する。
2. パフォーマンスを落としたり安価なプロバイダーにルーティングしたりすることなく、**最高品質**の選択肢を提供する。
3. 原価で販売し、上乗せは処理手数料の分だけにすることで、**値下げ**をそのまま還元する。
4. **ロックインをなくす**。Console はどのコーディングエージェントでも使え、OpenCode ではほかのプロバイダーも使える。
