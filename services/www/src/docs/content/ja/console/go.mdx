OpenCode Go では、人気のオープンなコーディングモデルに安定してアクセスできます。月額プランは 2 種類です。

| プラン | 料金 | 含まれる使用量 |
| ----------- | ------------- | ------------------------------------------- |
| **Go**      | **月額 $10** | 以下のモデルを低コストで利用 |
| **Go Plus** | **月額 $40** | 以下のモデルをより高い使用量上限で利用 |

Go は、OpenCode のほかのプロバイダーと同じように使えます。OpenCode Go を購読し、API キーを取得します。利用は**完全に任意**で、OpenCode を使うために必須ではありません。

このサービスは主に世界各地のユーザー向けに設計されており、グローバルに安定したアクセスを提供します。

## 利用方法

1. [OpenCode Console](https://opencode.ai/console) にサインインして Go または Go Plus を購読し、請求情報を追加して、API キーをコピーします。
2. TUI で `/connect` を実行し、**OpenCode Go** を選択して、API キーを貼り付けます。

   ```text
   /connect
   ```

3. `/models` を実行し、Go で利用できるモデルを選択します。

   ```text
   /models
   ```

<Callout>
  Go と Go Plus は、サインアップ時に作成される **Personal** ワークスペースのように、メンバーが 1 人だけのワークスペース向けです。Go のサブスクリプションがあるワークスペースでは、メンバーを招待できません。
</Callout>

## 利用できる場所

OpenCode Go は、[OpenCode](https://opencode.ai) と、同様の種類のリクエストを送信するほかのコーディングエージェント向けに設計されています。ほかのユーザーの利用体験を損なう不正利用がないか、トラフィックは監視されています。

クライアントは次の条件を満たす必要があります。

1. 一般的なコーディングエージェントのトラフィックを送信する。
2. 汎用的な SDK や HTTP ライブラリの名前ではなく、`my-coding-agent/1.0` のような独自のユーザーエージェントで自身を識別する。
3. ルーティングとプロンプトキャッシュを最適化できるように、会話ごとに安定したセッション ID を `x-opencode-session` で送信する。

### 動作確認済みのクライアント

OpenCode のほかに、以下のクライアントが OpenCode Go で正しく動作することを確認しています。ただし、今後も動作し続けることを保証するものではありません。

| クライアント | セッション対応                                                                                                                                                                                                                             |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Hermes**        | [PR #101864](https://github.com/NousResearch/hermes-agent/pull/101864) を含むビルドでは、OpenCode へのメインと補助のリクエストでヘッダーを送信します。この修正は v0.21.0 の後にマージされたため、v0.21.0 自体には含まれていません。                 |
| **Claude Code**   | Go はこのクライアント独自のセッションヘッダーを認識します。カスタムヘッダーを付けるラッパーは不要です。                                                                                                                                                                |
| **Codex**         | Go はこのクライアント独自のセッションヘッダーを認識します。一部のバージョンやプロキシ構成ではヘッダーが省略されるため、リクエストを転送する際はセッションヘッダーを保持してください。                                                                                                |
| **ZCode**         | Go はこのクライアント独自のセッションヘッダーを認識します。[`x-opencode-session` への対応リクエスト](https://github.com/zai-org/feedback/issues/492)はオープンのままですが、このヘッダーを送信する必要はなくなりました。                                   |
| **Pi**            | 現在のビルドは OpenCode 向けにセッション情報を送信します。古いバージョンは更新してください。                                                                                                                                                           |
| **jcode**         | [セッションヘッダーの修正](https://github.com/1jehuang/jcode/issues/1167)を含む **v0.81.6 以降**に更新してください。                                                                                                                     |
| **Kilo Code CLI** | [PR #13752](https://github.com/Kilo-Org/kilocode/pull/13752) を含むビルドでは、OpenCode のセッションヘッダーが復元されます。この修正は CLI が対象で、VS Code 拡張機能は対象外です。[issue #13723](https://github.com/Kilo-Org/kilocode/issues/13723) を参照してください。 |

### 上限を超えた使用

Console の残高にクレジットもある場合は、Console で **Use balance** オプションを有効にできます。有効にすると、使用量の上限に達した後、Go はリクエストをブロックする代わりに[従量課金の残高](/console/models#pricing)にフォールバックします。

### 一部のモデルの使用量が少ない理由

Go に含まれる月間使用量は、モデルによって異なります。

ほとんどのモデルでは、大口割引と GPU 容量の確保によってこれを実現しています。そうして削減できたコストを、より多くの月間使用量として還元しています。

一部のモデルについては、モデルが新しい、または公開料金がすでに割り引かれているといった理由で、割引の交渉や低コストでのホスティングができていません。

こうしたモデルでも、モデルのプロバイダーに直接支払う場合よりは少し多く使えます。これらのモデルに含まれる月間使用量が少ないのは、このためです。

## 背景

オープンモデルは大きく進化し、コーディングタスクではプロプライエタリモデルに迫る性能を発揮するようになりました。多くのプロバイダーが競って提供できるため、通常ははるかに安価です。

しかし、安定した低レイテンシーのアクセスを確保するのは難しい場合があります。プロバイダーによって品質や可用性が異なるためです。

<Callout type="tip">OpenCode と組み合わせてうまく機能するモデルとプロバイダーを厳選してテストしました。</Callout>

この問題を解決するために、次のことを行いました。

1. 厳選したオープンモデルをテストし、最適な実行方法について各モデルのチームと話し合いました。
2. いくつかのプロバイダーと協力し、これらのモデルが正しく提供されていることを確認しました。
3. モデルとプロバイダーの組み合わせをベンチマークし、自信を持っておすすめできる一覧を作成しました。

Go と Go Plus のどちらでもこれらのモデルを利用できます。使用量に合ったプランを選んでください。

## 目標

OpenCode Go を作成した目的は次のとおりです。

1. 低価格のサブスクリプションで、より多くの人が AI コーディングを**利用しやすく**する。
2. 最高水準のオープンなコーディングモデルへの**安定した**アクセスを提供する。
3. コーディングエージェントでの利用に向けて**テストとベンチマーク**を行ったモデルを厳選する。
4. OpenCode でほかのプロバイダーも使えるようにし、**ロックインをなくす**。
