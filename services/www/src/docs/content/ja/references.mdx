---
title: "参照ディレクトリ"
---

参照ディレクトリを使うと、現在のプロジェクト外にあるディレクトリに、名前を付けて OpenCode からアクセスできるようになります。`opencode.json` または `opencode.jsonc` に追加し、必要なときにクライアントでそのエイリアスを添付します。

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "references": {
    "docs": {
      "path": "../product-docs",
      "description": "Use for product behavior and terminology",
    },
  },
}
```

`docs` を添付したら、関連するパスを調べるようエージェントに依頼します。

```text
Read the attached docs reference and summarize api/authentication.md.
```

参照ディレクトリは、ドキュメント、共有ライブラリ、サンプル、別のリポジトリのソースコードなどに使います。

## ローカル

ローカルディレクトリには `path` を使用します。

```jsonc
{
  "references": {
    "design-system": {
      "path": "../design-system",
      "description": "Use when working with components or design tokens",
    },
  },
}
```

パスは次のように扱われます。

- 相対パスは、設定ファイルがあるディレクトリを基準に解決されます。
- 絶対パスを使用できます。
- `~/docs` のようなホームディレクトリからの相対パスを使用できます。

ほかのフィールドが不要な場合は、文字列の短縮形を使用できます。

```jsonc
{
  "references": {
    "docs": "../docs",
    "shared": "~/work/shared",
  },
}
```

<Callout type="note">
  短縮形の文字列がローカルパスとして扱われるのは、`.`、`/`、`~` のいずれかで始まる場合だけです。`docs` ではなく `./docs` と指定してください。`docs` のような値は Git リポジトリとして解釈されます。
</Callout>

## Git

リモートの Git リポジトリには `repository` を使用します。

```jsonc
{
  "references": {
    "effect": {
      "repository": "Effect-TS/effect",
      "branch": "main",
    },
    "internal-sdk": {
      "repository": "git@gitlab.example.com:platform/sdk.git",
      "branch": "release/v2",
    },
  },
}
```

次の形式のリモートに対応しています。

- GitHub の `owner/repo` 短縮形
- Git URL
- ホスト/パス形式
- SCP 形式のリモート

ローカルの `file:` リポジトリには対応していません。

リモートのデフォルトブランチを追跡するには、文字列の短縮形を使用します。

```jsonc
{
  "references": {
    "effect": "Effect-TS/effect",
    "sdk": "gitlab.com/platform/sdk",
  },
}
```

`branch` を指定しない場合、OpenCode はリモートのデフォルトブランチをチェックアウトして更新します。ブランチ名には英字、数字、`/`、`_`、`.`、`-` を使用できますが、`-` で始めたり `..` を含めたりすることはできません。

```jsonc
{
  "references": {
    "sdk": {
      "repository": "example/sdk",
      "branch": "release/v2.1",
    },
  },
}
```

## 保存場所

OpenCode は各リモートを正規化し、グローバルデータディレクトリ内に、リモートとブランチの組み合わせごとに 1 つのチェックアウトを保存します。ブランチを明示的に指定しない場合、パスは次の形式になります。

```text
opencode/repos/<host>/<repository-path>
```

一般的な Linux 環境では、`Effect-TS/effect` は次の場所に保存されます。

```text
~/.local/share/opencode/repos/github.com/Effect-TS/effect
```

ブランチを明示的に指定すると、エンコードされた `@<branch>` サフィックスが付きます。

```text
~/.local/share/opencode/repos/github.com/Effect-TS/effect@main
```

## 更新

存在しないリポジトリは非同期でクローンされます。既存のチェックアウトは、参照ディレクトリの読み込み時や再読み込み時、およびその Location で新しいユーザープロンプトが受け付けられた後に、バックグラウンドで確認されます。

```text
Prompt admitted → refresh check starts in background → agent continues
```

チェックアウトが更新の対象になるのは、前回の更新の試行から 24 時間以上経過している場合か、試行の記録がない場合です。更新では、設定されたブランチまたはリモートのデフォルトブランチを取得し、その状態にリセットします。

```text
Last attempt: 25 hours ago → eligible
Last attempt: 2 hours ago  → skipped
```

更新は次のルールに従います。

- タイムスタンプは、サービスを再起動しても保持されます。
- 同じチェックアウトを使用する Location は、そのタイムスタンプを共有します。
- 失敗した試行はログに記録され、24 時間の制限の対象になります。
- Location が使われていない間は、定期的なポーリングは行われません。
- クローンや更新に失敗しても、ほかの参照ディレクトリの読み込みは止まりません。

プロンプトは、クローンや更新の完了を待ちません。そのため、後のツールによる読み取りでは更新後のチェックアウトが見えていても、添付ファイルには古い内容が含まれていることがあります。また、新しい参照ディレクトリは、チェックアウトの準備ができる前に表示される場合があります。

```text
Attachment created → cached content
Background refresh completes → later tool read sees newer content
```

<Callout type="warning">
  キャッシュされたチェックアウトは共有されており、エージェントが使用している間にも更新される可能性があります。更新によってリセットされるため、キャッシュされたチェックアウトは編集しないでください。
</Callout>

## エージェントへの案内

`description` は、どのような場合に参照ディレクトリが役立つかをエージェントに伝えます。説明のある参照ディレクトリは、エイリアスと解決済みのパスとともにエージェントへの指示に含まれます。

```jsonc
{
  "references": {
    "docs": {
      "path": "../docs",
      "description": "Use for product behavior and terminology",
    },
  },
}
```

説明のない参照ディレクトリは、クライアントからは引き続き利用できますが、エージェントには自動的には案内されません。

```jsonc
{
  "references": {
    "archive": {
      "path": "../archive",
    },
  },
}
```

## 表示

`hidden` を `true` に設定すると、インタラクティブなクライアントの選択画面から参照ディレクトリが非表示になります。

```jsonc
{
  "references": {
    "internal": {
      "path": "../internal",
      "description": "Use for internal service behavior",
      "hidden": true,
    },
  },
}
```

`hidden` が影響するのは、インタラクティブな画面での表示だけです。参照ディレクトリは参照 API には引き続き含まれ、説明がある場合はエージェントへの指示にも含まれます。

## 使い方

クライアントは、ルートのエイリアスで参照ディレクトリを添付します。添付ファイルには、ルート直下のファイルとディレクトリの一覧（再帰なし）が含まれます。

```text
Attached alias: docs
Ask: Inspect docs/guides/deployment.md and explain the deployment steps.
```

ルートより下の内容が必要な場合は、特定のパスを調べるようエージェントに依頼してください。

## 権限

参照ディレクトリによって、追加のツール権限が付与されることはありません。アクティブな Location の外へのアクセスには、引き続き通常のツールのルールと `external_directory` 権限が適用されます。編集するには、該当する編集権限も必要です。

```text
Read ../product-docs/api.md
```

このリクエストが成功するのは、有効な権限でその外部の読み取りが許可されている場合だけです。

## フィールド

| フィールド | ローカル | Git | 説明 |
| --- | --- | --- | --- |
| `path` | 必須 | 不可 | ローカルディレクトリのパス |
| `repository` | 不可 | 必須 | リモートの Git リポジトリ |
| `branch` | 不可 | 任意 | 取得してチェックアウトするブランチ |
| `description` | 任意 | 任意 | エージェントがいつ使うべきかを説明する案内 |
| `hidden` | 任意 | 任意 | インタラクティブなクライアントの選択画面で非表示にする |

完全な Git エントリでは、Git で使用できるすべてのフィールドを指定できます。

```jsonc
{
  "references": {
    "sdk": {
      "repository": "example/sdk",
      "branch": "main",
      "description": "Use for SDK implementation details",
      "hidden": false,
    },
  },
}
```

## エイリアス

エイリアスは空にできません。また、`/`、`\`、空白文字、バッククォート、カンマを含めることはできません。

```text
Valid:   docs
Invalid: product docs
Invalid: docs/api
```
