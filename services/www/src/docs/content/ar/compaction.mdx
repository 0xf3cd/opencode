---
title: "ضغط السياق"
---

يُفسح ضغط السياق المجال في الجلسات الطويلة عبر استبدال الأجزاء الأقدم من المحادثة بملخص، فتتمكن الجلسة من الاستمرار بعد
تجاوز حد سياق النموذج.

## آلية العمل

عندما تقترب الجلسة من حد سياق النموذج، يلخّص OpenCode كل شيء عدا الجزء الأحدث من المحادثة، وهو نحو 15,000 token افتراضيًا.
وبمجرد جاهزية الملخص، يوضع قبل تلك المحادثة الحديثة وتستمر الجلسة من هناك.

```text
before   [ system prompt ][ older conversation ............ ][ recent 15k ][ pending work ]
after    [ system prompt ][ summary ][ recent 15k ][ pending work ]
```

يرى النموذج الملخص على أنه محادثة سابقة. وتحدّث عمليات الضغط اللاحقة الملخص نفسه بدلًا من البدء من جديد.

## البدء

الضغط التلقائي مفعّل افتراضيًا:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "compaction": {
    "auto": true,
    "keep": { "tokens": 15000 },
  },
}
```

ضغط السياق يفقد بعض المعلومات. لذا زِد قيمة `keep.tokens` عندما تكون التفاصيل الحديثة الدقيقة مهمة، أو اطلب الضغط بنفسك
قبل أن يبدأ الضغط التلقائي.

## يدويًا

يمكنك طلب الضغط في أي وقت، حتى مع سجل قصير:

```sh
opencode api post /api/session/ses_example/compact --data '{}'
```

يكتشف الأمر `api` الخدمة الخلفية ويُصادِق معها. وتؤكد استجابته قبول الطلب فقط، ولا تنتظر اكتمال الملخص. تابع أحداث
`session.compaction.*` لمعرفة وقت انتهائه. وراجع [مرجع API](/api) للاطلاع على العملية كاملة.

| القاعدة | السلوك |
| --- | --- |
| التوقيت | يُنفَّذ عند النقطة الآمنة التالية، قبل الموجّهات التي لا تزال في الانتظار. |
| التكرار | تُدمج الطلبات المُرسلة أثناء وجود طلب معلّق في ذلك الطلب. |
| الأتمتة | يعمل حتى عندما تكون قيمة `compaction.auto` هي `false`. |

مرّر `id` لجعل إعادة المحاولة المطابقة تمامًا متساوية الأثر (idempotent). وتؤدي إعادة استخدام المعرّف نفسه لطلب مختلف إلى
إرجاع تعارض.

```sh
opencode api post /api/session/ses_example/compact --data '{"id":"msg_compact_once"}'
```

## الإعدادات

أضف `compaction` إلى أي [ملف من ملفات تهيئة OpenCode](/config):

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "compaction": {
    "auto": false,
    "keep": { "tokens": 24000 },
    "buffer": 16000,
  },
}
```

| الحقل | القيمة الافتراضية | السلوك |
| --- | ---: | --- |
| `auto` | `true` | يضغط السياق تلقائيًا قرب حد السياق، ويتعافى مرة واحدة عندما يرفض المزوّد طلبًا لطوله الزائد. ويعمل الضغط اليدوي دائمًا. |
| `keep.tokens` | `15000` | الحجم التقريبي للمحادثة الحديثة التي تُبقى بجانب الملخص. تحفظ القيم الأكبر تفاصيل أكثر لكنها تترك مساحة أقل للعمل الجديد. |
| `buffer` | 10% من الحد | عدد tokens التي تُترك فارغة دون حد النموذج. تبدأ القيم الأكبر الضغط التلقائي في وقت أبكر. |

يقبل `keep.tokens` و`buffer` أعدادًا صحيحة غير سالبة.

## المزوّدون

يكتب OpenCode الملخص بنفسه افتراضيًا باستخدام نموذج الجلسة. لكن بعض المزوّدين يستطيعون ضغط المحادثة من جهتهم بدلًا من ذلك.
فعّل ذلك لكل مزوّد أو نموذج عبر `settings.compaction`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "settings": { "compaction": { "type": "native" } },
      "models": {
        "gpt-4.1": { "settings": { "compaction": { "type": "summary" } } },
      },
    },
  },
}
```

يتجاوز إعداد النموذج إعداد المزوّد. تستخدم القيمة `native` ضغط المزوّد، بينما تستخدم `summary` ضغط OpenCode نفسه.

مع الضغط الأصلي، يرسل OpenCode المحادثة إلى نقطة نهاية الضغط لدى المزوّد. ويُرجع المزوّد عنصرًا مشفّرًا ومبهمًا يحل محل
المحادثة الأقدم. وتُبقى رسائلك ومرفقاتك الحديثة بجانبه، حتى حد `keep.tokens`:

```text
before   [ older conversation ........................ ][ recent user messages ]
after    [ encrypted checkpoint + recent user messages ]
```

| الموضوع | السلوك |
| --- | --- |
| الدعم | نماذج OpenAI Responses. ويختلف الدعم حسب النشر (deployment) والنموذج. |
| العتبة | الإعدادان `auto` و`buffer` نفساهما المستخدمان في الضغط بالملخص. وتعمل الطلبات اليدوية أيضًا. |
| قابلية النقل | لا تعمل نقطة الحفظ المشفّرة إلا مع المزوّد والنموذج ونقطة النهاية نفسها. وإذا بدّلت النموذج، تستمر الجلسة من المحادثة الأصلية بدلًا من نقطة الحفظ. |
| الطول الزائد | إذا رفض المزوّد عملية ضغط لطولها الزائد، يعيد OpenCode المحاولة بطلب أصغر، ولا يتحوّل إلى الملخص. |

## الملخصات

يُنظَّم الملخص بحيث يتمكن وكيل آخر من استئناف العمل انطلاقًا منه:

```md
## Objective
Finish the authentication migration.

## Next Move
- Update the callback handler.
- Verify the login flow.
```

يغطي الملخص الهدف والمتطلبات، والقرارات، والعمل المكتمل والجاري، والعوائق والخطوات التالية، والملفات ذات الصلة. وفي
المحادثة الحديثة التي تُبقى بجانبه، تُختصر مخرجات الأدوات الطويلة وتُستبدل بيانات المرفقات بوصف قصير.

بعد الضغط، تصبح الإصدارات الحالية من ملفات التعليمات هي الأساس المرجعي للجلسة؛ راجع [التعليمات](/instructions).

## الحدود

| الحد | النتيجة |
| --- | --- |
| النموذج | يستخدم الضغط نموذج الجلسة، ولا يوجد نموذج مستقل للضغط. |
| السجل | يحتاج الضغط إلى محادثة أقدم ليستبدلها. ولا يستطيع إفساح المجال عندما يتكوّن الطلب في معظمه من تعليمات ثابتة ومخططات أدوات. |
| الحجم | إذا كانت المحادثة المراد ضغطها طويلة جدًا بحد ذاتها، يرسل OpenCode نسخة نصية مختصرة وقد يُسقط أقدم التبادلات. |
| التعافي | يُضغط الطلب المرفوض لطوله الزائد ثم يُعاد مرة واحدة. ويُرجَع الرفض الثاني على شكل خطأ. |
| التخزين | تظل الرسائل السابقة مخزّنة حتى عندما لا تعود تُرسل إلى النموذج. |

مثلًا، لا يفيد الضغط في هذه الحالة:

```text
128k context = 120k fixed instructions and tools + 8k conversation
```

## الترحيل

استخدم V1 سلوك الأدوار الأخيرة (tail-turn) والتقليم (pruning). أما V2 فيستخدم الملخصات و`compaction.keep.tokens`:

```jsonc
{
  "compaction": {
    "keep": { "tokens": 15000 }
  }
}
```

تنطبق الإعدادات والسلوك الموضحة في هذه الصفحة على V2.
