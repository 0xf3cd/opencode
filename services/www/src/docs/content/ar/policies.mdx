تحدد السياسات ما إذا كان OpenCode مسموحًا له بتنفيذ إجراء على مورد مسمّى. تُكتب السياسات ضمن `policies`، ويمكن أيضًا أن
توفرها مساحة عمل متصلة في [OpenCode Console](/console).

السياسات منفصلة عن [الأذونات](/permissions). فالأذونات قواعد أدوات خاصة بكل وكيل، ويمكنها أن تُرجع `allow` أو `deny` أو
`ask`. أما السياسات فثنائية، ولا تطلب الموافقة أبدًا، ولا تفعل سوى تضييق ما كانت الأذونات والمزوّدون سيسمحون به لولاها.

## الإعداد

ارفض مزوّدًا واحدًا في كل مكان بإضافة عبارة إلى `opencode.jsonc`:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "policies": [{ "action": "provider.use", "resource": "openai", "effect": "deny" }],
}
```

يختفي المزوّد المرفوض من الكتالوج ومن اختيار النموذج حتى لو كانت لديه بيانات اعتماد صالحة.

كانت الإصدارات السابقة تقرأ السياسات من `experimental.policies`. ولا يزال هذا المفتاح يعمل، ويُدمج في `policies`:

```jsonc
{
  "experimental": {
    "policies": [{ "action": "provider.use", "resource": "openai", "effect": "deny" }],
  },
}
```

## العبارات

لكل عبارة ثلاثة حقول:

| الحقل      | القيم                                         | المعنى                                               |
| ---------- | --------------------------------------------- | ---------------------------------------------------- |
| `action`   | `provider.use`, `tool.use`, `integration.use` | العملية الخاضعة للتحكم                               |
| `resource` | سلسلة نصية أو نمط بأحرف بدل                   | ما تنطبق عليه العبارة؛ ويعتمد على الإجراء            |
| `effect`   | `allow`, `deny`                               | القرار عند تطابق هذه العبارة                         |

تُسقَط العبارات التي تفشل في التحقق مع تحذير في سجل الخادم، وتظل بقية القائمة سارية. راجع السجل بعد تعديل أي `deny`.

## المطابقة

تستخدم الموارد أحرف البدل نفسها التي تستخدمها الأذونات لمطابقة القيمة كاملة: يطابق `*` صفر محارف أو أكثر، ويطابق `?` محرفًا
واحدًا.

```jsonc
{
  "policies": [{ "action": "provider.use", "resource": "company-*", "effect": "deny" }],
}
```

ترفض هذه العبارة `company-us` و`company-eu`. ويطابق النمط المنتهي بـ ` *` القيمة أيضًا دون وسائط، لذا يغطي
`shell:git push *` الأمر `git push` وحده.

## الترتيب

عند تطابق عدة عبارات، تُطبَّق الأخيرة. لا توجد قاعدة للأكثر تحديدًا، لذا ضع العبارات العامة أولًا ثم الاستثناءات بعدها. وإذا
لم تتطابق أي عبارة، يُسمح بالإجراء.

```jsonc
{
  "policies": [
    { "action": "provider.use", "resource": "*", "effect": "deny" },
    { "action": "provider.use", "resource": "anthropic", "effect": "allow" },
  ],
}
```

يبقى Anthropic وحده متاحًا.

## المزوّدون

يتحكم `provider.use` فيما إذا كان المزوّد قابلًا للاستخدام أصلًا. والمورد هو معرّف المزوّد: `anthropic` أو `openai` أو
`opencode` أو معرّف مخصص من [`providers`](/providers).

```jsonc
{
  "providers": {
    "company-ai": {
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": { "baseURL": "https://ai.company.example/v1" },
    },
  },
  "policies": [
    { "action": "provider.use", "resource": "*", "effect": "deny" },
    { "action": "provider.use", "resource": "company-ai", "effect": "allow" },
  ],
}
```

يهيّئ الإدخال في `providers` نقطة النهاية، وتجعل العبارات منه المزوّد الوحيد الذي سيستخدمه OpenCode. وتنطبق السياسة أيًّا
كانت الطريقة التي عُرف بها المزوّد: بيانات الكتالوج، أو متغيرات البيئة، أو الحسابات المحفوظة، أو الإضافات المدمجة، أو
التهيئة.

استخدم `provider.use` بدلًا من قائمتي `enabled_providers` و`disabled_providers` في V1. ولا تزال ملفات V1 تُحمَّل؛ راجع
[الترحيل من V1](/migrate-v1#supported-fields-without-direct-native-equivalents).

## الأدوات

ترفض عبارات `tool.use` فحص [الإذن](/permissions) رفضًا قاطعًا. والمورد بالشكل `<action>:<value>`، ويُطابَق مع كل مورد تفحصه
الأداة.

```jsonc
{
  "policies": [
    { "action": "tool.use", "resource": "shell:git push *", "effect": "deny" },
    { "action": "tool.use", "resource": "edit:*.env", "effect": "deny" },
    { "action": "tool.use", "resource": "webfetch:*", "effect": "deny" },
  ],
}
```

يفشل الفحص المرفوض بالرسالة `Blocked by configuration policy` بدلًا من طلب الموافقة. ويُطبَّق بعد قواعد الوكيل والموافقات
المحفوظة، لذا يتجاوز `ask` وموافقة **Allow always** على حد سواء.

| النمط                        | ما يمنعه                                       |
| ---------------------------- | ---------------------------------------------- |
| `shell:*`                    | كل أوامر shell                                 |
| `read:*/.ssh/*`              | قراءة مواد SSH                                 |
| `external_directory:*`       | أي وصول خارج الموقع (Location) أو worktree     |
| `subagent:general`           | تشغيل وكيل فرعي واحد                           |
| `github_delete_repository:*` | أداة MCP واحدة                                 |
| `*`                          | كل ما لم يُرفض بعد                             |

لا تمنح عبارة `tool.use` ذات التأثير `allow` الوصول أبدًا. بل تقتصر على رفع `deny` أوسع يسبقها، وبعدها تتولى قواعد الوكيل نفسه
القرار.

```jsonc
{
  "policies": [
    { "action": "tool.use", "resource": "shell:*", "effect": "deny" },
    { "action": "tool.use", "resource": "shell:git status *", "effect": "allow" },
  ],
}
```

يخضع `git status` لقاعدة `shell` الخاصة بالوكيل، بينما يُمنع كل أمر آخر.

## التكاملات

يتحكم `integration.use` في تحميل خادم MCP أو مهارة أو إضافة. والمورد هو نوع التكامل ومعرّفه:

| المورد            | ينطبق على                                                          |
| ----------------- | ------------------------------------------------------------------ |
| `mcp:<server>`    | [خادم MCP](/mcp-servers) حسب اسمه المهيّأ                          |
| `skill:<id>`      | [مهارة](/skills) حسب معرّفها                                       |
| `plugin:<target>` | [إضافة](/plugins) حسب اسم الحزمة دون إصدار أو حسب المسار المطلق    |

```jsonc
{
  "policies": [
    { "action": "integration.use", "resource": "mcp:*", "effect": "deny" },
    { "action": "integration.use", "resource": "mcp:github", "effect": "allow" },
    { "action": "integration.use", "resource": "plugin:opencode-acme-cli", "effect": "deny" },
  ],
}
```

يُزال خادم MCP أو المهارة المرفوضة، ولا تُحمَّل الإضافة المرفوضة، أيًّا كانت طريقة تهيئتها.

## الأولوية

في الإعدادات العادية، تكون الغلبة للتهيئة الأقرب. أما السياسات فتعكس ذلك: إذ تُقيَّم العبارات القادمة من التهيئة الأوسع
لاحقًا، فتتجاوز العبارات الأضيق. وتكون الكلمة الأخيرة دائمًا للتهيئة المُدارة ولخدمة Console المتصلة.

| السلطة         | المصدر                                                                                                         |
| -------------- | -------------------------------------------------------------------------------------------------------------- |
| 1 (الأعلى)     | مساحة عمل OpenCode Console المتصلة                                                                             |
| 2              | التفضيلات المُدارة في macOS (`/Library/Managed Preferences/ai.opencode.managed.plist`)                          |
| 3              | ملف `opencode.json(c)` على مستوى النظام (`/Library/Application Support/opencode`, `/etc/opencode`, `%ProgramData%\opencode`) |
| 4              | الملف العام `~/.config/opencode/opencode.json(c)`                                                              |
| 5              | ملف `opencode.json(c)` المباشر؛ وتتغلب الأدلة الخارجية على الداخلية                                             |
| 6 (الأدنى)     | ملف `.opencode/opencode.json(c)`؛ وتتغلب الأدلة الخارجية على الداخلية                                           |

لا يستطيع المستودع إعادة تفعيل مزوّد رفضته على المستوى العام:

```jsonc title="~/.config/opencode/opencode.jsonc"
{
  "policies": [{ "action": "provider.use", "resource": "openai", "effect": "deny" }],
}
```

```jsonc title="project/opencode.jsonc"
{
  "policies": [{ "action": "provider.use", "resource": "openai", "effect": "allow" }],
}
```

يبقى `openai` مرفوضًا. وداخل الملف الواحد، تحتفظ العبارات بترتيب كتابتها.

## Console

تحوّل مساحة العمل في [OpenCode Console](/console) سياسات Providers وTools الخاصة بها إلى عبارات، وتُرجعها مع تهيئة مساحة
العمل. ويُلحقها OpenCode بعد كل العبارات المكتوبة، فتكون لها الكلمة الأخيرة: لا يمكن لقاعدة `allow` في المستودع أو لدى
المستخدم رفع `deny` صادر عن المؤسسة، بينما يرفع `allow` الصادر عن المؤسسة أي `deny` من سلطة أدنى.

تذكر حالات الرفض الناتجة عن هذه العبارات اسم مساحة العمل:

```text
Blocked by Acme's policy
```

تتبع العبارات الحساب المتصل.

| الحدث                         | النتيجة                                                   |
| ----------------------------- | --------------------------------------------------------- |
| تغيّر سياسة Console           | تُطبَّق عند الجلب التالي، نحو مرة كل دقيقة               |
| التبديل إلى مساحة عمل أخرى    | تُستبدل العبارات بعبارات تلك المساحة                      |
| قطع الاتصال                   | تُمسح العبارات                                            |
| تعذّر الوصول إلى Console      | تبقى آخر عبارات لذلك الاتصال سارية                        |

لا يمكن تعطيل إضافة Console وإضافة السياسات من `plugins`؛ راجع [التحكم في الإضافات](/plugins#control).

<Callout type="note">
  لا تهيّئ السياسات نقاط النهاية أو بيانات الاعتماد، ولا تستطيع جعل مزوّد غير قابل للاستخدام قابلًا له. كما أنها لا تعزل
  شيفرة الإضافات: فالمزوّد المرفوض يُمنع على المسار المعتاد للمزوّدين والنماذج.
</Callout>
