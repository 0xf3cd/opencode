اضبط متغيرات الخادم الوسيط (proxy) القياسية واستثنِ منها عناوين الاسترجاع (loopback). يتواصل CLI مع خدمته الخلفية عبر
اتصالات HTTP محلية، لذا يلزم استثناء عناوين الاسترجاع متى ضُبط خادم وسيط في بيئة CLI.

```bash
export HTTP_PROXY=http://proxy.example.com:8080
export HTTPS_PROXY=http://proxy.example.com:8080
export NO_PROXY=localhost,127.0.0.1,::1

opencode
```

يعالج المتغير `HTTP_PROXY` الوجهات التي تستخدم HTTP، ويعالج `HTTPS_PROXY` الوجهات التي تستخدم HTTPS. ويمكن أن يبدأ عنوان
URL للخادم الوسيط نفسه بـ `http://` في كلا المتغيرين. أما `NO_PROXY` فهو قائمة مفصولة بفواصل بالمضيفات والعناوين التي
يُتصل بها مباشرةً.

## الخدمة

لا تؤثر المتغيرات التي تُصدِّرها في shell على الخدمة الخلفية إلا إذا شُغِّلت الخدمة منه. لذا احفظ المتغيرات في تهيئة
الخدمة المُدارة لتستخدم مرات التشغيل اللاحقة للخدمة إعدادات الشبكة نفسها.

```bash
opencode service set env HTTP_PROXY http://proxy.example.com:8080
opencode service set env HTTPS_PROXY http://proxy.example.com:8080
opencode service set env NO_PROXY localhost,127.0.0.1,::1
opencode service start
```

يؤدي تغيير أي متغير بيئة مُدار إلى إيقاف الخدمة قيد التشغيل، ثم يعيد الأمر `service start` تشغيلها بالبيئة الجديدة.
وإذا كانت بيئة shell التي تشغّل منها CLI تضبط خادمًا وسيطًا، فأبقِ `NO_PROXY` مضبوطًا فيها أيضًا، لأن متغيرات الخدمة المُدارة تنطبق على
عملية الخادم لا على عملية CLI.

لإزالة متغير محفوظ، استخدم `service unset env`:

```bash
opencode service unset env HTTPS_PROXY
```

## المصادقة

إذا كان الخادم الوسيط يقبل بيانات الاعتماد ضمن عنوان URL، فضمّن اسم المستخدم وكلمة المرور في كل عنوان URL لخادم وسيط
يتطلب المصادقة. وطبّق الترميز بالنسبة المئوية (percent-encoding) على المحارف مثل `@` و`:` و`/` إذا وردت في اسم المستخدم
أو كلمة المرور.

```bash
export HTTPS_PROXY='http://user:p%40ssword@proxy.example.com:8080'
```

أما للخدمة الخلفية، فاحفظ عنوان URL كاملًا. تُخزَّن القيمة في تهيئة الخدمة الخاصة، ويعرضها الأمر
`opencode service get env`، لذا لا تشارك مخرجاته.

```bash
opencode service set env HTTPS_PROXY 'http://user:p%40ssword@proxy.example.com:8080'
```

## الشهادات

إذا كان الخادم الوسيط أو الوجهة يستخدم شهادة موقّعة من جهة إصدار شهادات خاصة، فاضبط `NODE_EXTRA_CA_CERTS` على ملف PEM.
تُضاف جهات الإصدار الإضافية هذه إلى مخزن الثقة في بيئة التشغيل عند بدء العملية.

```bash
export NODE_EXTRA_CA_CERTS=/etc/company/ca.pem
opencode --standalone
```

احفظ مسار الملف في تهيئة الخدمة الخلفية، ثم أعد تشغيلها:

```bash
opencode service set env NODE_EXTRA_CA_CERTS /etc/company/ca.pem
opencode service start
```

## الواجهة الأمامية

يستخدم كلٌّ من `--standalone` و`serve` بيئة العملية الخاصة به، ولا يهيّئ الأمر `opencode service set env` هاتين
العمليتين.

```bash
HTTP_PROXY=http://proxy.example.com:8080 \
HTTPS_PROXY=http://proxy.example.com:8080 \
NO_PROXY=localhost,127.0.0.1,::1 \
opencode --standalone
```

وطبّق النمط نفسه على خادم يعمل في الواجهة الأمامية:

```bash
HTTPS_PROXY=http://proxy.example.com:8080 \
NO_PROXY=localhost,127.0.0.1,::1 \
opencode serve
```

## التحقق

بعد تطبيق الإعدادات، تحقّق من أن CLI يستطيع الوصول إلى الخدمة الخلفية:

```bash
opencode api get /api/info
```

تؤكد الاستجابة الناجحة لفحص السلامة أن الاتصال المحلي بين العميل والخدمة يعمل. وللتحقق من الخادم الوسيط الصادر للخدمة
ومسار الشهادات، أرسل طلبًا عاديًا إلى أحد المزوّدين.
