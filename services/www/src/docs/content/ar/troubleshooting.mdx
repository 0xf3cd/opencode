<Callout type="tip">
  يمكنك أن تطلب من OpenCode تصحيح أخطائه بنفسه. صِف المشكلة واطلب منه استخدام صفحة استكشاف الأخطاء هذه؛ إذ يستطيع قراءة
  الخطوات أدناه وفحص خدمته وسجلاته والمساعدة في تحديد المشكلة.
</Callout>

يعتمد OpenCode بنية عميل وخادم. يملك خادم يعمل في الخلفية الجلسات والإضافات والأذونات وسائر حالة التطبيق. ابدأ بتحديد ما
إذا كانت المشكلة في أحد العملاء، أو في الخادم المشترك، أو في مشروع بعينه.

## التحقق من الخدمة الخلفية

اعرض معلومات الخادم الحالي:

```bash
opencode service status
```

تحقّق من أن واجهة API الخاصة به سليمة:

```bash
opencode api get /api/info
```

إذا علقت الخدمة أو لم تكن سليمة، فأعد تشغيلها:

```bash
opencode service restart
```

ويمكنك أيضًا إيقافها وتشغيلها صراحةً:

```bash
opencode service stop
opencode service start
```

<Callout type="note">
  عادةً ما يكتشف OpenCode الخدمة الخلفية المشتركة أو يشغّلها تلقائيًا. ولا تحتاج إلى أوامر الخدمة إلا عند تشخيص دورة
  حياتها.
</Callout>

## السماح بمصدر متصفح

إذا تعذّر على عميل متصفح من مصدر (origin) آخر الاتصال بسبب CORS، فأضف مصدر العميل إلى تهيئة الخدمة:

```bash
opencode service set cors http://192.168.1.10:3001
opencode service get cors
```

استخدم مصدر HTTP أو HTTPS مطابقًا تمامًا، مع المنفذ عند الحاجة، دون مسار أو شرطة مائلة في النهاية. وللسماح بعدة مصادر،
مرّر قائمة مفصولة بفواصل في وسيط واحد؛ وتُزال المسافات المحيطة بكل مصدر:

```bash
opencode service set cors "http://192.168.1.10:3001, https://app.example.com"
```

يطبع الأمر `service get cors` مصفوفة JSON. ولإزالة القائمة المهيّأة:

```bash
opencode service unset cors
```

يؤدي ضبط تهيئة الخدمة أو إلغاء ضبطها إلى إيقاف الخدمة الخلفية، وتعتمد التهيئة الجديدة عند تشغيلها التالي؛ استخدم
`opencode service start` لتشغيلها صراحةً.

أما للخادم الذي يعمل في الواجهة الأمامية، فكرّر `--cors` لكل مصدر إضافي مسموح به:

```bash
opencode serve --cors http://192.168.1.10:3001 --cors https://app.example.com
```

مع `serve --service`، تتجاوز خيارات `--cors` الممرَّرة القائمةَ المحفوظة لتلك العملية. ومن دون هذه الخيارات، يستخدم وضع
الخدمة القائمة المحفوظة. لا يغيّر CORS عنوان الاستماع ولا يتجاوز مصادقة الخادم.

## فحص واجهة API

يستخدم الأمر `api` آلية اكتشاف الخدمة المحلية والمصادقة نفسها. ويقبل إما طريقة HTTP ومسارًا، وإما معرّف عملية OpenAPI.

راجع [مرجع API](/api) للاطلاع على جميع نقاط النهاية ومعرّفات العمليات.

مرّر متن طلب بصيغة JSON باستخدام `--data` أو `-d`، وأضف الترويسات باستخدام `--header` أو `-H`.

<Callout type="warning">
  قد يؤدي تشغيل `opencode api` إلى بدء الخدمة الخلفية إذا لم تتوفر خدمة متوافقة وسليمة.
</Callout>

## قراءة السجلات

تكتب الإصدارات المثبّتة سجلاتها في:

```text
~/.local/share/opencode/log/opencode.log
```

تابع السجل أثناء إعادة إنتاج المشكلة:

```bash
tail -f ~/.local/share/opencode/log/opencode.log
```

يتضمن كل سطر معرّف العملية `run` والحقل `role`. استخدم `role=server` لتتبع نشاط الجلسات والمزوّدين والإضافات والأذونات
والأدوات.

```bash
grep 'role=server' ~/.local/share/opencode/log/opencode.log
grep 'run=8fc3b1d5' ~/.local/share/opencode/log/opencode.log
```

## التقاط ملفات تعريف المعالج والذاكرة

على macOS وLinux، يمكنك إرسال إشارة إلى عملية OpenCode قيد التشغيل لالتقاط بيانات تشخيصية. احصل على معرّف العملية (PID)
للخادم الخلفي من نقطة نهاية فحص السلامة:

```bash
opencode api get /api/info
```

استخدم قيمة `pid` الواردة في الاستجابة مع إحدى هاتين الإشارتين:

- تلتقط الإشارة `SIGPROF` ملف تعريف للمعالج (CPU profile) مدته عشر ثوانٍ:

  ```bash
  kill -SIGPROF <pid>
  ```

  تُكتب النتيجة في دليل السجلات باسم `cpu-<pid>-<timestamp>.cpuprofile`.

- تلتقط الإشارة `SIGUSR1` لقطة للذاكرة (heap snapshot):

  ```bash
  kill -SIGUSR1 <pid>
  ```

  تُكتب النتيجة في دليل السجلات باسم `heap-<pid>-<timestamp>.heapsnapshot`.

انتظر ظهور `CPU profile written` أو `heap snapshot written` في `opencode.log` قبل فتح الملف. يتضمن سطر السجل المقابل المسار
الكامل للملف. ويمكنك فحص كلا النوعين في Chrome DevTools.

<Callout type="note">
  لا تتوفر ملفات التعريف المُشغَّلة بالإشارات على Windows. وقد تؤدي كتابة لقطة الذاكرة إلى إيقاف العملية مؤقتًا وزيادة
  استهلاكها للذاكرة لفترة وجيزة.
</Callout>

## ملفات الخدمة

يسجّل الخادم المشترك نفسه في:

```text
~/.local/state/opencode/service.json
```

وتُخزَّن تهيئة الخدمة الخاصة به منفصلةً في:

```text
~/.config/opencode/service.json
```

وتوجد قاعدة البيانات عادةً في:

```text
~/.local/share/opencode/opencode.db
```

يمكن للمتغير `OPENCODE_DB` تجاوز موقع قاعدة البيانات.

<Callout type="warning">
  لا تحذف ملفات الخدمة أو قاعدة البيانات ولا تعدّلها أثناء استكشاف الأخطاء. استخدم أوامر الخدمة لإدارة العملية الخلفية
  (daemon)، وخذ نسخة احتياطية قبل فحص البيانات الدائمة بأدوات خارجية.
</Callout>

## الإبلاغ عن مشكلة

أرفق ما يلي عند الإبلاغ عن مشكلة يمكن إعادة إنتاجها:

- مخرجات `opencode --version`
- مخرجات `opencode service status`
- أقصر تسلسل من الخطوات يعيد إنتاج المشكلة
- ما إذا كانت المشكلة تؤثر في الخدمة المشتركة، أو في عميل بعينه، أو في مشروع واحد
- أسطر السجل ذات الصلة، بما فيها الحقلان `run` و`role`

أزِل مفاتيح API وترويسات التفويض والموجّهات ومحتويات الملفات وسائر البيانات الحساسة قبل مشاركة السجلات.

أبلغ عن المشكلات القابلة لإعادة الإنتاج في [GitHub Issues](https://github.com/anomalyco/opencode/issues).
