---
title: "التهيئة"
---

لتهيئة OpenCode، أنشئ الملف `opencode.jsonc` في مشروعك. أضف المخطط (schema) ليتحقق المحرر من صحة الملف، ثم اضبط الخيارات التي تحتاجها فقط.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "anthropic/claude-sonnet-4-5",
}
```

يمكنك أيضًا أن تطلب من OpenCode تحديث هذا الملف نيابةً عنك.

## الصيغة

يدعم OpenCode صيغتي JSON وJSONC. استخدم JSONC إذا أردت كتابة تعليقات أو فواصل زائدة في نهاية القوائم.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  // Use this model by default.
  "model": "anthropic/claude-sonnet-4-5",
}
```

## المواقع

ضع الإعدادات المُدارة التي تشمل الجهاز كله في دليل تهيئة النظام:

| المنصة | الدليل |
| -------- | --------------------------------------- |
| macOS    | `/Library/Application Support/opencode` |
| Linux    | `/etc/opencode`                         |
| Windows  | `%ProgramData%\opencode`                |

يعمل دليل النظام مثل الدليل العام. فإلى جانب `opencode.json(c)`، يحمّل الدلائل `agents/` و`commands/` و`skills/`
و`plugins/` لكل مستخدم على الجهاز:

```text
/etc/opencode/
├── opencode.json
├── agents/review.md
├── commands/release.md
└── skills/deploy/SKILL.md
```

على macOS، يقرأ OpenCode أيضًا التفضيلات المُدارة التي تنشرها أدوات MDM للنطاق `ai.opencode.managed`. ويحل الملف
الشخصي الخاص بالمستخدم محل الملف الذي يشمل الجهاز كله:

```text
/Library/Managed Preferences/<user>/ai.opencode.managed.plist
/Library/Managed Preferences/ai.opencode.managed.plist
```

للإعدادات المُدارة الأولوية القصوى، فلا يستطيع المستخدمون ولا المشاريع تجاوز القيم التي تضبطها، كما تتجاوز التفضيلات
المُدارة دليلَ النظام. غير أن الإعدادات وحدها لا تمنع المستخدمين من إضافة مزوّدين أو خوادم MCP أو وكلاء أو إضافات؛
لفرض القيود، استخدم [السياسات](/policies#precedence) في التهيئة المُدارة.

ضع إعدادات المستخدم التي تنطبق على كل المشاريع في التهيئة العامة:

```text
~/.config/opencode/opencode.json(c)
```

وضع إعدادات المشروع في أحد هذين الملفين:

```text
/home/user/projects/my-app/opencode.json(c)
/home/user/projects/my-app/.opencode/opencode.json(c)
```

يبحث OpenCode بدءًا من الدليل الحالي وصولًا إلى جذر نظام الملفات. يدمج أولًا ملفات `opencode.json(c)` المباشرة من
الدليل الأبعد إلى الأقرب، ثم يدمج الملفات الموجودة داخل دلائل `.opencode` بالترتيب نفسه. وهذا يعني أن كل تهيئة
`.opencode` مكتشَفة تتجاوز كل تهيئة مباشرة. لذا التزم بشكل واحد في شجرة الدلائل كلها ما لم تكن بحاجة إلى هذا السلوك.

مثلًا، لنفترض أنك شغّلت OpenCode من `/home/user/projects/acme/packages/web`:

```text
/etc/opencode/opencode.json
~/.config/opencode/opencode.json

/home/user/projects/acme/
├── opencode.json
└── packages/
    └── web/
        ├── opencode.json
        └── src/
```

يطبّق OpenCode هذه الملفات من الأدنى أولوية إلى الأعلى:

1. `~/.config/opencode/opencode.json`
2. `/home/user/projects/acme/opencode.json`
3. `/home/user/projects/acme/packages/web/opencode.json`
4. `/etc/opencode/opencode.json`

تتجاوز تهيئة الحزمة الإعدادات المطابقة في تهيئة المستودع، وتتجاوز تهيئة المستودع بدورها التهيئة العامة، أما تهيئة النظام
فتتجاوزها جميعًا. وتبقى الإعدادات غير المتعارضة كما هي. أما [السياسات](/policies#precedence) الواردة في الملفات العامة
وملفات المشروع فتُقيَّم بالترتيب المعاكس، وتتقدم سياسات النظام عليها جميعًا.

## المخطط

يتوفر مخطط تهيئة OpenCode الكامل على [opencode.ai/config.json](https://opencode.ai/config.json).

أضف الحقل `$schema` إلى ملف التهيئة لتفعيل التحقق من الصحة والإكمال التلقائي في المحررات التي تدعم JSON Schema:

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json"
}
```

اعتمد على المخطط مرجعًا موثوقًا للحقول المتاحة والقيم المقبولة وبنية التهيئة المتداخلة.

### Shell

اضبط shell الذي تستخدمه أداتا الطرفية وshell.

```jsonc
{
  "shell": "/bin/zsh",
}
```

### النموذج

اضبط النموذج الافتراضي بالصيغة `provider/model`. لا يحتفظ الإعداد الافتراضي في المستوى الجذري حاليًا بقيمة `#variant`،
لكن مراجع النماذج في الوكلاء والأوامر يمكنها اختيار متغير.

```jsonc
{
  "model": "anthropic/claude-sonnet-4-5",
}
```

راجع [دليل النماذج](/models) لمعرفة كيفية اختيار النماذج واستخدام النماذج المحلية.

### الوكيل

اختر الوكيل الأساسي الذي يُستخدم عندما لا تحدد الجلسة وكيلًا صراحةً.

```jsonc
{
  "default_agent": "build",
}
```

راجع [دليل الوكلاء](/agents) للتعرّف على الوكلاء المدمجين والمخصصين.

### التحديثات

تحكّم في التحقق من التحديثات من التهيئة العامة. اضبط `update` على `"disable"` لتخطيها، أو على `"notify"` لعرض
التحديثات المتاحة قبل تثبيتها، أو على `"auto"` لتثبيت التحديثات تلقائيًا. إذا لم تحدده، فقيمة `update` الافتراضية هي
`"notify"`.

لا يعيد التثبيت التلقائي تشغيل الخادم قيد التشغيل، لذا أعد تشغيله يدويًا لتفعيل التحديث المثبّت. وتُتجاهل القيم المضبوطة
على مستوى المشروع.

```jsonc
{
  "update": "notify",
}
```

### المشاركة

اضبط سياسة مشاركة الجلسات. يقبل OpenCode هذا الحقل، لكن مشاركة الجلسات غير مدعومة بعد.

```jsonc
{
  "share": "manual",
}
```

راجع [دليل المشاركة](/sharing) لمزيد من التفاصيل.

### اسم المستخدم

اضبط اسم مستخدم. يقبل OpenCode هذا الحقل لكنه لا يعرضه في المحادثات.

```jsonc
{
  "username": "alice",
}
```

### الأذونات

عرّف قواعد مرتبة تسمح للوكيل باستخدام أداة على مورد مطابق، أو تمنعه، أو تطلب موافقتك أولًا.

```jsonc
{
  "permissions": [
    {
      "action": "shell",
      "resource": "git push *",
      "effect": "ask",
    },
  ],
}
```

راجع [دليل الأذونات](/permissions) لمعرفة كيفية مطابقة القواعد والإجراءات المتاحة.

### السياسات

اسمح باستخدام مزوّد أو امنعه، أو امنع فحص إذن منعًا قاطعًا، أو احظر خادم MCP أو مهارة أو إضافة، وذلك بعبارات مرتبة
يمكن لتهيئة أوسع نطاقًا أن تتجاوزها.

```jsonc
{
  "policies": [
    { "action": "provider.use", "resource": "*", "effect": "deny" },
    { "action": "provider.use", "resource": "anthropic", "effect": "allow" },
    { "action": "tool.use", "resource": "shell:git push *", "effect": "deny" },
  ],
}
```

راجع [دليل السياسات](/policies) لمعرفة كيفية المطابقة والأولوية بين ملفات التهيئة والسياسات التي تديرها Console.

### الوكلاء

تجاوز الوكلاء المدمجين أو عرّف وكلاء متخصصين لكل منهم نموذجه وتعليماته ووضعه وأذوناته.

```jsonc
{
  "agents": {
    "reviewer": {
      "description": "Review changes without editing files",
      "mode": "subagent",
      "system": "Focus on correctness, security, and missing tests.",
      "permissions": [{ "action": "edit", "resource": "*", "effect": "deny" }],
    },
  },
}
```

راجع [دليل الوكلاء](/agents) للاطلاع على جميع خيارات الوكلاء والوكلاء المعرّفين في ملفات.

### اللقطات

فعّل لقطات نظام الملفات التي يستخدمها التراجع والاسترجاع أو عطّلها.

```jsonc
{
  "snapshots": false,
}
```

راجع [دليل اللقطات](/snapshots) لمعرفة سلوك التراجع والإعادة.

### المراقب

تجاهل الملفات والدلائل التي لا ينبغي أن تؤدي تغييراتها إلى تحديثات نظام الملفات.

```jsonc
{
  "watcher": {
    "ignore": ["dist/**", "coverage/**"],
  },
}
```

### المُنسِّق

نسّق الملفات بعد أن تغيّرها الأدوات `write` أو `edit` أو `patch`. اضبط `formatter` على `true` لتفعيل المُنسِّقات
المدمجة المتاحة.

```jsonc
{
  "formatter": true,
}
```

راجع [دليل المُنسِّقات](/formatters) للتعرّف على المُنسِّقات المدمجة والمخصصة.

### الوسائط

تحكّم في كيفية تغيير حجم الصور الكبيرة جدًا التي تحمّلها الأداة `read` أو رفضها قبل إرسالها إلى النموذج.

```jsonc
{
  "media": {
    "image": {
      "auto_resize": true,
      "max_width": 2000,
      "max_height": 2000,
      "max_base64_bytes": 5242880,
    },
  },
}
```

راجع [دليل المرفقات](/attachments) لمعرفة كيفية معالجة الصور وحدودها.

### المخرجات

اضبط الحد الأقصى لعدد الأسطر والبايتات التي يُحتفظ بها من نتيجة الأداة.

```jsonc
{
  "tool_output": {
    "max_lines": 2000,
    "max_bytes": 51200,
  },
}
```

### البحث

اختر طريقة بحث OpenCode على الويب. استخدم `"random"` لاختيار مزوّد متاح تلقائيًا.

```jsonc
{
  "websearch": {
    "provider": "random",
  },
}
```

راجع [دليل البحث على الويب](/websearch) للتعرّف على المزوّدين وبيانات الاعتماد وطريقة الاختيار وحدود المعدل وتعطيل البحث.

### MCP

هيّئ خوادم Model Context Protocol المحلية والبعيدة. ويمكن لكل خادم أن يتجاوز المهلات العامة.

```jsonc
{
  "mcp": {
    "servers": {
      "playwright": {
        "type": "local",
        "command": ["bunx", "@playwright/mcp"],
      },
    },
  },
}
```

راجع [دليل MCP](/mcp-servers) للتعرّف على الخوادم البعيدة وOAuth ومتغيرات البيئة والمهلات.

### ضغط السياق

تحكّم في ضغط السياق التلقائي وفي مقدار السياق الحديث الذي يحتفظ به.

```jsonc
{
  "compaction": {
    "auto": true,
    "keep": {
      "tokens": 15000,
    },
    "buffer": 20000,
  },
}
```

تظل الملخصات المحلية هي الخيار الافتراضي. لاستخدام ضغط السياق الأصلي لدى المزوّد في الطلبات التلقائية واليدوية معًا،
اضبط ذلك في سياسة المزوّد أو النموذج:

```jsonc
{
  "providers": {
    "openai": {
      "settings": { "compaction": { "type": "native" } },
      "models": {
        "gpt-4.1": { "settings": { "compaction": { "type": "summary" } } },
      },
    },
  },
}
```

يتجاوز إعداد النموذج إعداد المزوّد. ويستخدم ضغط السياق التلقائي ميزانية الإدخال القابلة للاستخدام في النموذج المحدد.
وتحتفظ نقاط الحفظ (checkpoints) لدى المزوّد برسائل المستخدم الحديثة ضمن ميزانية `compaction.keep.tokens` نفسها التي
تستخدمها الملخصات المحلية للجزء الأخير المحتفَظ به. ويؤدي ضبط `compaction.auto: false` في المستوى الأعلى إلى تعطيل ضغط
السياق التلقائي الجديد دون التخلص من نقاط الحفظ المثبّتة. راجع [دليل ضغط السياق](/compaction) لمعرفة كيفية حساب
الميزانية والتعافي من تجاوز الحد.

### التسخين المسبق

أبقِ جلسات النماذج النشطة مؤخرًا ساخنة عبر طلبات عابرة دورية. التسخين المسبق معطّل افتراضيًا؛ اضبطه على `true` لاستخدام
فاصل خمول مدته أربع دقائق ونافذة نشاط مدتها 30 دقيقة.

```jsonc
{
  "warming": {
    "prompt": "Do not perform any work. Reply with exactly: OK",
    "interval": "4 minutes",
    "duration": "30 minutes",
  },
}
```

راجع [دليل التسخين المسبق](/warming) لمعرفة سلوك الطلبات والتخصيص واعتبارات التكلفة.

### المهارات

أضف الدلائل أو عناوين URL التي ينبغي أن يبحث فيها OpenCode عن مهارات الوكلاء.

```jsonc
{
  "skills": ["./team-skills", "https://example.com/.well-known/skills/"],
}
```

راجع [دليل المهارات](/skills) لمعرفة بنية المهارة والاكتشاف التلقائي ضمن `.opencode/skills/`.

### الأوامر

عرّف أوامر شرطة مائلة (slash commands) قابلة لإعادة الاستخدام في صورة قوالب موجّهات مسمّاة.

```jsonc
{
  "commands": {
    "review": {
      "description": "Review the current changes",
      "template": "Review the current diff for correctness and missing tests.",
    },
  },
}
```

راجع [دليل الأوامر](/commands) للتعرّف على الوسائط والنماذج والوكلاء والأوامر المعرّفة في ملفات.

### التعليمات

صرّح بملفات تعليمات إضافية أو أنماط glob أو عناوين URL. يقبل OpenCode هذا الحقل لكنه لا يحمّل عناصره؛ استخدم
`AGENTS.md` للتعليمات.

```jsonc
{
  "instructions": ["CONTRIBUTING.md", "docs/guidelines/*.md"],
}
```

راجع [دليل التعليمات](/instructions) للتعرّف على تعليمات المشروع و`AGENTS.md`.

### المراجع

اجعل الدلائل المحلية أو مستودعات Git متاحة سياقًا داعمًا مسمّى.

```jsonc
{
  "references": {
    "docs": {
      "path": "../product-docs",
      "description": "Product behavior and terminology",
    },
    "effect": {
      "repository": "Effect-TS/effect",
      "branch": "main",
    },
  },
}
```

راجع [دليل المراجع](/references) للتعرّف على الصيغة المختصرة وإمكانية الظهور وتحليل المسارات.

### Worktrees

اضبط الدليل الأب لكل worktree محلي جديد. يُلحق OpenCode اسم worktree المطلوب أو المولَّد.

```jsonc
{
  "worktree": {
    "directory": "../worktrees",
  },
}
```

تُحلَّل المسارات النسبية بالنسبة إلى النسخة الأساسية المحفوظة من المشروع (canonical checkout). وينطبق ذلك على التهيئة
العامة وتهيئة المشروع على حد سواء؛ أما المسارات المطلقة فتُستخدم كما هي، ويُحلَّل `~/` بالنسبة إلى الدليل الرئيسي
للمستخدم.

مثلًا، تضع هذه التهيئة العامة كل worktree جديد داخل الدليل `.lane/trees/` الخاص بكل مشروع:

```jsonc
{
  "worktree": {
    "directory": ".lane/trees",
  },
}
```

من دون هذا الإعداد، يُنشأ worktree في دليل بيانات الخادم ضمن `worktree/<first-six-project-ID-characters>`. ويحمّل إنشاء
worktree وتحديثه التهيئةَ من النسخة الأساسية المحفوظة للمشروع، حتى عندما تشترك نسخ أخرى في معرّف المشروع نفسه. ولا يؤدي
تغيير هذا الإعداد إلى نقل أي worktree موجود.

الخيار الافتراضي المدمج هو Git. وأي [إضافة](/build/plugins#worktrees) تسجّل استراتيجية تصبح تلقائيًا الخيار الافتراضي
في بيئة تشغيل تلك الإضافة. وتستخدم عمليات المشروع بيئة تشغيل النسخة الأساسية. أما الخيارات الخاصة بكل استراتيجية فتتبع
تلك الإضافة، لا كائن التهيئة `worktree`.

### الإضافات

حمّل الإضافات من الحزم أو من دلائل إضافات محلية. استخدم صيغة الكائن عندما تقبل الإضافة خيارات.

```jsonc
{
  "plugins": [
    "opencode-example-plugin",
    {
      "package": "./plugins/local",
      "options": {
        "enabled": true,
      },
    },
  ],
}
```

راجع [دليل الإضافات](/plugins) لمعرفة كيفية تحميل الإضافات وتهيئتها.

### المزوّدون

هيّئ المزوّدين وأضف نماذجهم أو تجاوزها، وكذلك إعدادات الطلبات والترويسات ومتغيرات النماذج.

```jsonc
{
  "providers": {
    "openai": {
      "models": {
        "gpt-5.2-custom": {
          "modelID": "gpt-5.2",
          "name": "GPT-5.2 Custom",
          "limit": {
            "context": 200000,
            "output": 32000,
          },
        },
      },
    },
  },
}
```

يختار الإعداد `settings.transport: "websocket"` في المزوّد اتصال WebSocket الخاص بجلسته.

راجع [دليل المزوّدين](/providers) للتعرّف على بيانات الاعتماد ونقاط النهاية المخصصة وحزم المزوّدين ونقل WebSocket وتهيئة النماذج.
