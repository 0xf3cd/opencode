يمكن للإضافات تعديل سلوك OpenCode وإضافة ميزات جديدة. ولتغيير واجهة الطرفية، أنشئ [إضافة
CLI](/build/plugins/cli).

هل تُرحّل إضافة موجودة من OpenCode 1؟ اتبع [دليل ترحيل إضافات V1](/build/plugins/migrate-v1).

```ts title=".opencode/plugins/example/index.ts"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "example",
  async setup(ctx) {
    await ctx.storage.set("loaded", true)
  },
})
```

تُحمَّل الإضافات الموجودة في `.opencode/plugins/` تلقائيًا، مثل المثال المحلي أعلاه. ولتحميل حزم منشورة أو مجلدات
إضافات من مواقع أخرى، أضفها إلى `plugins` في `opencode.json(c)`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": [
    "opencode-acme-plugin",
    "opencode-acme-plugin@1.2.0",
    "@acme/opencode-plugin",
    "./plugins/local",
    "../shared/plugin",
    "/absolute/path/plugin",
    "file:///home/me/plugins/local",
    {
      "package": "@acme/opencode-plugin",
      "options": {
        "agent": "reviewer",
        "strict": true,
      },
    },
  ],
}
```

راجع [تهيئة الإضافات](/plugins) لمزيد من خيارات التحميل والتهيئة.

## دورة الحياة

تعمل `setup` عند تحميل الإضافة. ويمكنها إعادة دالة تنظيف تعمل عند إلغاء تحميل الإضافة.

```ts
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "example",
  setup(ctx) {
    console.log(`loaded in OpenCode ${ctx.app.version}`)
    return () => console.log("unloaded")
  },
})
```

### السياق

سياق الإضافة هو في جوهره [عميل لخادم OpenCode](/build/client). تستخدم توابع القراءة والإجراءات فيه المدخلات والاستجابات
نفسها التي يستخدمها العميل، ويضيف توابع خاصة بالإضافات للتحويلات وخطّافات (hooks) وقت التشغيل وإعادة التحميل والتسجيلات
وخيارات الإضافة.

```ts
setup(ctx) {
  console.log(ctx.app.version)
}
```

يصف `ctx.location` الموقع الذي حُمِّلت فيه نسخة الإضافة هذه. ويتضمن `directory` و`workspaceID` الاختياري وبيانات
`project` الوصفية (`id` و`directory` و`canonical`). وهو متاح في إضافات Promise وإضافات Effect على حد سواء. هذا موقع نسخة
الإضافة، وليس موقع كل جلسة يمكنها الوصول إليها أو كل حدث تتلقاه.

```ts
setup(ctx) {
  console.log(ctx.location.directory)
  console.log(ctx.location.project.canonical)
}
```

### الخيارات

مرّر خيارات الإضافة باستخدام صيغة الكائن في `opencode.json(c)`.

```jsonc title="opencode.jsonc"
{
  "plugins": [
    {
      "package": "./plugins/company",
      "options": {
        "strict": true,
      },
    },
  ],
}
```

اقرأ هذه القيم من `ctx.options` أثناء `setup`.

```ts title="plugins/company/index.ts"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "company",
  setup(ctx) {
    const strict = ctx.options.strict === true
  },
})
```

## التحويلات

التحويلات تعديلات متزامنة على حالة المجالات في OpenCode، ويبني كل تحويل على التسجيلات السابقة في مجاله. تعكس قراءات
السجل مثل `ctx.model.list()` كل التسجيلات حتى تلك اللحظة، بما في ذلك أثناء إعداد الإضافة؛ إذ يقتصر التجميع عند بدء
التشغيل على دمج إشعارات التحديث، ولا يؤخر أبدًا ما تعيده القراءة. أما واجهات API حالة الموارد فتظل تعرض حالة الموارد
قيد التشغيل: فتسجيل تعريف لا يعني أن اتصاله أو غير ذلك من أعمال الموارد قد اكتمل.

تضيف المصادر المزوّدين وتعريفات النماذج غير القابلة للتعديل عبر `ctx.provider.transform`.

```ts title="plugins/models/index.ts"
import { Model, Plugin, Provider } from "@opencode/plugin"

export default Plugin.define({
  id: "company.models",
  async setup(ctx) {
    const providerID = Provider.ID.make("acme")
    const models = [{ ...Model.Info.default(providerID, Model.ID.make("reasoner")), name: "Acme Reasoner" }]
    await ctx.provider.transform((editor) => {
      editor.add({
        info: {
          ...Provider.Info.empty(providerID),
          name: "Acme",
          activation: "enabled",
          package: "@opencode/ai/providers/openai-compatible",
          settings: { baseURL: "http://127.0.0.1:8000/v1" },
        },
        models,
      })
    })

    const available = await ctx.model.list()
  },
})
```

أي تسجيل أو إزالة أو استدعاء لـ `reload()` يجعل السجل متغيرًا، فتعيد القراءة التالية بناءه بإعادة تطبيق كل تحويل نشط
بترتيب التسجيل على قيمة جديدة. أبقِ التحويلات خفيفة وقابلة للتكرار. ولا تُعدِّل عمليات إعادة البناء اللاحقة أبدًا قيمةً
سبق أن قرأتها.

بعد حلّ تحويلات المزوّدين وتوافرهم، يُنشئ OpenCode نماذج المزوّدين النشطين ويعيد تطبيق كل تحويلات النماذج بالترتيب.
ويمكن لسياسة النماذج فحص مجموعة النماذج المرشحة كاملةً، بما فيها المصادر التي حُدِّثت للتو.

```ts title="plugins/model-budget/index.ts"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "company.model-budget",
  async setup(ctx) {
    await ctx.model.transform((editor) => {
      editor
        .list()
        .filter((model) => model.cost.some((tier) => tier.output > 20))
        .forEach((model) => {
          editor.remove(model.providerID, model.id)
        })
    })
  },
})
```

لا تُراقَب المدخلات المُلتقطة تلقائيًا. حمّل البيانات الخارجية قبل دالة رد النداء المتزامنة، ثم استدعِ `reload()` بعد
تغيّر تلك المدخلات. في هذا المثال، تعيد `loadFromSource()` عناصر بالشكل
`{ info: Provider.Info, models: readonly Model.Info[] }`.

```ts title="plugins/models/index.ts"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "company.models",
  async setup(ctx) {
    const source = { providers: await loadFromSource() }

    await ctx.provider.transform((editor) => {
      source.providers.forEach((provider) => editor.add(provider))
    })

    const refresh = async () => {
      source.providers = await loadFromSource()
      await ctx.provider.reload()
    }

    const timer = setInterval(() => void refresh().catch(console.error), 60_000)
    return () => clearInterval(timer)
  },
})
```

تُبطل تغييرات المزوّدين نتيجة النماذج النشطة بأكملها، لذا تظل سياسة سعر المخرجات تصفّي النماذج المُحدَّثة. استخدم
`ctx.model.reload()` عندما يتغير فقط مُدخل التقطه تحويل للنماذج.

## واجهة API

### الوكيل

اقرأ كل الوكلاء أو اجلب وكيلًا واحدًا بمعرّفه.

```ts
const agents = await ctx.agent.list()
const build = await ctx.agent.get({ agentID: "build" })
```

سجّل تحويلًا لفحص الوكلاء أو تحديثهم أو إزالتهم أو تحديد الوكيل الافتراضي.

```ts
await ctx.agent.transform((editor) => {
  const agents = editor.list()
  const build = editor.get("build")

  editor.default("build")
  editor.update("build", (agent) => {
    agent.description = "Builds features and fixes bugs"
  })
  editor.remove("legacy")
})
```

أعد تحميل الوكلاء بعد تغيّر حالة خارجية يستخدمها تحويل.

```ts
await ctx.agent.reload()
```

### المزوّدون

اقرأ المزوّدين المتاحين أو افحص البيانات الوصفية لمزوّد واحد بمعرّفه.

```ts
const providers = await ctx.provider.list()
const provider = await ctx.provider.get({ providerID: "anthropic" })
```

تعدّل تحويلات المزوّدين إعدادات المزوّد وتعريفات المصادر. تتضمن قراءات المحرر المزوّدين غير النشطين وتعرض تعريفات غير
قابلة للتعديل؛ أما `models.update` فيعدّل نسخة مملوكة من نموذج المصدر.

```ts
await ctx.provider.transform((editor) => {
  editor.update("anthropic", (provider) => {
    provider.headers = { ...provider.headers, "x-company": "engineering" }
  })
  editor.models.update("anthropic", "claude-sonnet-4-5", (model) => {
    model.name = "Team Sonnet"
  })
  editor.models.remove("anthropic", "legacy-model")
  editor.remove("legacy-provider")
})
```

استبدل مخزون نماذج مصدر المزوّد باستخدام `models.set`، ثم أعد التحميل بعد تغيّر التعريفات المُلتقطة.

```ts
const source = { models: await loadModels() }
await ctx.provider.transform((editor) => {
  editor.models.set("acme", source.models)
})

source.models = await loadModels()
await ctx.provider.reload()
```

للاكتشاف الخاص بكل حساب، مرّر الاتصال المستخدم لتحميل المخزون في `sourceConnection`. يستبعد OpenCode ذلك المزوّد ما دام
اتصال آخر محددًا، إلى أن تنشر إضافتك مخزونها المُحدَّث.

```ts
const connection = await ctx.integration.connection.active("acme")
if (!connection) return
const inventory = await loadInventory(connection)
await ctx.provider.transform((editor) => {
  editor.add({ info: inventory.provider, models: inventory.models, sourceConnection: connection })
})
```

### النماذج

اقرأ النماذج المتاحة والاختيار الافتراضي.

```ts
const models = await ctx.model.list()
const selected = await ctx.model.default()
```

تعدّل تحويلات النماذج مجموعة النماذج المرشحة من المزوّدين النشطين بأكملها. تظل النماذج المرشحة المعطّلة قابلة للتعديل حتى
تنتهي كل التحويلات؛ ولا يمكن لـ `update` إضافة نموذج إلا ضمن مزوّد متاح.

```ts
await ctx.model.transform((editor) => {
  editor.list("anthropic").forEach((model) => {
    editor.update(model.providerID, model.id, (draft) => {
      draft.enabled = draft.capabilities.tools
    })
  })
  editor.default.set("anthropic", "claude-sonnet-4-5")
  editor.remove("anthropic", "legacy-model")
})
```

تعدّل دوال رد النداء تجاوزات النماذج الخام. تُدمج القيم الافتراضية للمزوّد مرة واحدة عندما يعتمد OpenCode النتيجة،
وتعيد القراءات اللاحقة استخدام تلك النتيجة ما لم يتغير شيء. ويعرض `editor.provider` تعريفات المصادر غير القابلة للتعديل،
بما فيها القوالب غير النشطة، لا مخرجات تحويلات النماذج.

```ts
await ctx.model.transform((editor) => {
  const source = editor.provider.get("anthropic")?.models.get("claude-sonnet-4-5")
  if (!source) return
  editor.update("anthropic", source.id, (model) => {
    model.limit.context = Math.min(model.limit.context, source.limit.context)
  })
})

await ctx.model.reload()
```

اقرأ التكاملات وافحص بيانات الاعتماد النشطة.

```ts
const attempt = await ctx.integration.oauth.connect({ integrationID: "github", methodID: "oauth" })
const status = await ctx.integration.oauth.status({ integrationID: "github", attemptID: attempt.data.attemptID })
await ctx.integration.oauth.complete({ integrationID: "github", attemptID: attempt.data.attemptID, code })
```

توفّر الاتصالات القائمة على الأوامر تدفق البدء والحالة والإلغاء نفسه.

```ts
const attempt = await ctx.integration.command.connect({ integrationID: "acme", methodID: "cli" })

await ctx.integration.command.cancel({ integrationID: "acme", attemptID: attempt.data.attemptID })
```

سجّل تحويلًا لفحص التكاملات وإدارة طرق المصادقة الخاصة بها.

```ts
await ctx.integration.transform((editor) => {
  const integrations = editor.list()
  const acme = editor.get("acme")

  editor.update("acme", (integration) => {
    integration.name = "Acme"
  })
  editor.method.update({
    integrationID: "acme",
    method: { id: "cli", type: "command", label: "Sign in with Acme CLI", command: ["acme", "login"] },
  })

  const methods = editor.method.list("acme")
  const legacy = methods.find((method) => method.type === "command" && method.id === "legacy")
  if (legacy) editor.method.remove("acme", legacy)
  editor.remove("legacy")
})
```

أعد تحميل التكاملات بعد تغيّر حالة خارجية يستخدمها تحويل.

```ts
await ctx.integration.reload()
```

### MCP

اسرد خوادم MCP وحالة اتصالها الحالية.

```ts
const servers = await ctx.mcp.list()
```

لا تدير الإضافات خوادم MCP إلا عبر التحويلات. استخدم `editor.set` لإضافة خادم أو استبداله، و`editor.update` لتغيير
تهيئته، و`editor.remove` لإزالته. وافحص التهيئة باستخدام `editor.list` و`editor.get`.

```ts
await ctx.mcp.transform((editor) => {
  const servers = editor.list()
  const docs = editor.get("docs")
  editor.set("docs", { type: "remote", url: "https://mcp.example.com" })
  editor.update("docs", (server) => {
    server.disabled = false
  })
  editor.remove("legacy")
})
```

اضبط `disabled: true` في تحويل لتعطيل خادم وقطع اتصاله، أو `disabled: false` لتفعيله والسماح لـ OpenCode بالاتصال به.
يوفّق OpenCode دورة حياة الخوادم وفق التهيئة الناتجة عن التحويلات.

استدعِ `reload()` بعد تغيّر حالة خارجية يستخدمها تحويل، لإعادة تطبيق التحويلات وتوفيق حالة الخوادم.

```ts
await ctx.mcp.reload()
```

#### المرجع

المخططات: [`Mcp.Server`](/api#schema-Mcp.Server)، [`Mcp.LocalConfigEncoded`](/api#schema-Mcp.LocalConfigEncoded)،
[`Mcp.RemoteConfigEncoded`](/api#schema-Mcp.RemoteConfigEncoded)


### الأدوات

اقرأ الأدوات المسجّلة حاليًا، بعد تطبيق كل التحويلات، خارج دالة رد نداء التحويل. لكل أداة `id` يحتوي على اسمها الفعلي.

```ts
const tools = await ctx.tool.list()
const read = tools.find((tool) => tool.id === "read")
```

سجّل الأدوات وحدّثها وأزلها بتحويل متزامن، بما في ذلك في إضافات Promise. حمّل البيانات الخارجية قبل التسجيل أو إعادة
التحميل. ويتجاوز التسجيلُ الصالح اللاحق أيَّ أداة بالاسم الفعلي نفسه.

```ts
const registration = await ctx.tool.transform((editor) => {
  editor.namespace({
    name: "acme",
    description: "Customer account tools",
  })
  editor.add({
    name: "greeting",
    description: "Create a greeting",
    input: {
      type: "object",
      properties: { name: { type: "string" } },
      required: ["name"],
      additionalProperties: false,
    },
    options: { namespace: "acme", codemode: true },
    execute: async (input, context) => {
      await context.progress({ status: "greeting" })
      return { content: `Hello ${(input as { name: string }).name}!` }
    },
  })
})
```

يتلقى منفّذو أدوات Promise القيمة `context.signal`. مرّرها إلى الأعمال القابلة للإلغاء مثل `fetch`، كي يؤدي إيقاف الجلسة
إلى إيقاف العملية الأساسية أيضًا.

```ts
execute: async ({ url }, context) => {
  const response = await fetch(url, { signal: context.signal })
  return { content: await response.text() }
}
```

استدعِ `reload()` بعد تغيير بيانات المصدر التي التقطتها دالة رد النداء. تعيد إعادة التحميل تطبيق التحويلات النشطة دون
تغيير ترتيبها، ولا تعيد تشغيل إعداد الإضافة.

```ts
await ctx.tool.reload()
```

استخدم `list()` و`get()` لفحص الأدوات الموجودة حاليًا في المحرر. لكل أداة `id` يحتوي على اسمها الفعلي، وتعيد `get()`
القيمة `undefined` عندما لا يوجد ذلك المعرّف. استخدم `update` و`remove` مع اسم الأداة الفعلي، بما في ذلك مساحة أسمائها
(`acme_greeting` في المثال أعلاه). تتحول النقاط في مساحات الأسماء والمحارف غير المدعومة في أسماء الأدوات إلى `_`. تُتجاهل
الأسماء غير الموجودة؛ إذ يتطلب إنشاء أداة استخدام `add` مع تعريف كامل. تحافظ التحديثات على الاسم ومساحة الأسماء.
ولاستبدال المخططات أو الخيارات، أسند إليها قيمًا جديدة بدلًا من تعديل القيم المتداخلة. تُسجَّل التحديثات غير الصالحة في
السجلات، ويبقى التعريف السابق كما هو.

```ts
await ctx.tool.transform((editor) => {
  editor.update("acme_greeting", (tool) => {
    tool.description = "Greet the user by name"
  })
  editor.remove("acme_obsolete")
})
```

يُعاد تطبيق عمليات التحديث والإزالة بالترتيب مع عمليات الإضافة، بما في ذلك بعد تحديثات كتالوج MCP. ويؤدي التخلص من تسجيلها إلى
إزالة تلك التغييرات وإعادة البناء من التحويلات المتبقية.

تخلّص من التسجيل لإزالة تحويله وإعادة البناء من التحويلات المتبقية، فيظهر أي تعريف سابق كان قد تجاوزه. التخلص من التسجيل
عملية متساوية القوى (idempotent)، كما يؤدي إلغاء تحميل الإضافة إلى التخلص من تسجيلاتها.

```ts
await registration.dispose()
```

يلتقط كل طلب إلى النموذج لقطة ثابتة وقابلة للتنفيذ من الأدوات. تؤثر التحويلات وعمليات إعادة التحميل والتخلص اللاحقة في
اللقطات المستقبلية، لا في التعريفات أو أوصاف مساحات أسماء Code Mode أو المنفّذين الذين التُقطوا بالفعل. أما المنفّذون
الذين يلتقطون في closure بيانات قابلة للتعديل من الإضافة فيظلون يرون تلك البيانات؛ لذا التقط القيمة داخل التحويل عندما
يجب أن تبقى مرتبطة بذلك التعريف.

### Worktrees

سجّل استراتيجية worktree محلية باستخدام دورة حياة الإضافة المعتادة. تتولى وحدة التنفيذ في هذا المثال التحقق من الخيارات،
وعمليات `create` و`remove` و`list` الخاصة بالواجهة الخلفية.

```ts title="plugins/worktrees/index.ts"
import { Plugin } from "@opencode/plugin"
import { makeStrategy } from "./strategy"

export default Plugin.define({
  id: "company.worktrees",
  async setup(ctx) {
    const strategy = makeStrategy(ctx.options)
    await ctx.worktree.transform((editor) => {
      editor.add(strategy)
    })
  },
})
```

حمّل الإضافة عبر `plugins`، وهيّئ الوجهة المشتركة بشكل منفصل:

```jsonc title="opencode.jsonc"
{
  "worktree": { "directory": "../worktrees" },
  "plugins": [{ "package": "./plugins/worktrees", "options": {} }],
}
```

- تؤدي إضافة استراتيجية إلى تحديدها تلقائيًا. يسري آخر تسجيل نشط، ولا حاجة إلى تهيئة لاختيار الاستراتيجية.
- يؤدي التخلص من تسجيلها أو إلغاء تحميل الإضافة إلى استعادة التنفيذ السابق، وفي النهاية استراتيجية Git المضمّنة.
- تعيد `reload()` تطبيق التحويلات بعد تغيّر المدخلات المُلتقطة، ولا تعيد تشغيل إعداد الإضافة.
- لا تُعاد محاولة الإنشاء الفاشل عبر Git. وتحتفظ worktrees الموجودة بمالكها المسجّل حتى عند تغيّر الاستراتيجية الافتراضية.
- تدير الاستراتيجيات المجلدات المحلية. وتجهيز مساحات العمل البعيدة ليس جزءًا من هذه الواجهة.

#### العمليات

يوفّر سياق الإضافة عمليات worktree نفسها القائمة على المشروع التي يوفّرها العميل. تتطلب كل عملية `projectID`. لا تقرأ
`list` إلا المخزون المحفوظ، بما في ذلك النسخ المعروفة من المشروع نفسه؛ ولا تحمّل التهيئة، ولا تشغّل الإضافات، ولا تكتشف
تغييرات نظام الملفات.

```ts
const projectID = ctx.location.project.id
const created = await ctx.worktree.create({ projectID, name: "task" })
const inventory = await ctx.worktree.list({ projectID })
await ctx.worktree.refresh({ projectID })
await ctx.worktree.remove({ projectID, directory: created.directory, force: false })
```

تحمّل عملية الإنشاء التهيئة والإضافات من المجلد `canonical` المحفوظ للمشروع، وتستخدم الاستراتيجية التي اختارتها. وتقبل
اختياريًا مجلدًا أبًا `directory`، ومصدرًا `from`، وفرعًا للبدء `branch`، واسمًا `name`. يكون المصدر افتراضيًا النسخة
المعتمدة (canonical checkout)، ويجب أن ينتمي أي تجاوز عبر `from` إلى ذلك المشروع. ولا يغيّر اختيار المصدر جذر التهيئة.
يجب أن تدعم الاستراتيجية المحددة أي مرجع (ref) بداية يُمرَّر؛ فعملية اللقطة الأصلية في Rift مثلًا لا تملك خيارًا لتحديد
المرجع.

تنتظر عمليتا الإنشاء والتحديث تفعيل إضافات النسخة المعتمدة. أما الاستدعاءات التي تجري أثناء إعداد إضافات تلك النسخة،
فترى التسجيلات التي تمت حتى تلك اللحظة، ولا تنتظر تفعيلها هي.

تحمّل عملية الإزالة التهيئة المعتمدة وتفعّل إضافاتها، ثم تستخدم الاستراتيجية المسجّلة للـ worktree بدلًا من الاستراتيجية
الافتراضية المحددة حاليًا. ويؤدي عدم توفر المالك المسجّل إلى خطأ. ويمكن أن تكون وجهة الـ worktree في مكان آخر:

```ts
await ctx.worktree.remove({
  directory: "/worktrees/task",
  projectID,
  force: false,
})
```

يؤدي غياب المالك إلى فشل الإزالة بدلًا من الرجوع إلى Git. ويمكن للاستراتيجية رمي `new Worktree.OperationError({
message: "Uncommitted changes", forceRequired: true })`، مع استيراد `Worktree` من `@opencode/plugin`، لطلب تأكيد الإزالة
القسرية دون الاعتماد على أخطاء Core أو Git.

تحمّل عملية التحديث التهيئة المعتمدة، وتطلب من كل الاستراتيجيات المتاحة العثور على worktrees عبر جذور النسخ المعروفة.
وتدمج النتائج، وتحافظ على الملكية المسجّلة، وتحذف المجلدات المفقودة. يُسجَّل فشل أي مصدر اكتشاف في السجلات بينما تستمر
المصادر الأخرى. وتبقى المجلدات الموجودة محفوظة حتى إن لم تُبلغ عنها أي استراتيجية متاحة. راقب الحدث `worktree.updated`
واستدعِ `list` مجددًا لقراءة المخزون المتغيّر.

```ts
await ctx.worktree.refresh({ projectID })
```

#### المرجع

تتلقى التنفيذات وجهة مقترحة بعد معالجة التسمية والتعارضات. أعد المجلد الفعلي من `create`؛ فقد يختلف عندما تتطلب الواجهة
الخلفية تخطيطها الخاص. يحلّ OpenCode المسار المُعاد ويستخدمه للمخزون وأوامر بدء التشغيل ونتيجة API. ويجب أن يكون المجلد
المُعاد موجودًا.

تتولى الاستراتيجيات التي تختار وجهة أخرى معالجة تعارضات التسمية هناك. ومع ذلك يُنشئ OpenCode المجلد الأب المقترح قبل
استدعاء الاستراتيجية. ويجب ألا تُبلغ `list` إلا عن المجلدات التي تملكها الاستراتيجية، إضافةً إلى جذور المستودعات.

```ts
interface WorktreeDefinition {
  readonly id: string
  create(
    input: { sourceDirectory: string; directory: string; branch?: string },
    context: { signal: AbortSignal },
  ): Promise<{ directory: string }>
  remove(input: { directory: string; force: boolean }, context: { signal: AbortSignal }): Promise<void>
  list(
    sourceDirectory: string,
    context: { signal: AbortSignal },
  ): Promise<readonly { directory: string; type: "root" | "worktree" }[]>
}

interface WorktreeEditor {
  add(definition: WorktreeDefinition): void
}

interface WorktreeDomain extends WorktreeApi {
  transform(callback: (editor: WorktreeEditor) => void): Promise<Registration>
  reload(): Promise<void>
}
```

يجب أن تتعاون دوال رد النداء المبنية على Promise مع الإلغاء عبر `signal`. أما دوال رد النداء في Effect فتعيد Effects
وتستخدم آلية المقاطعة في Effect بدلًا من ذلك. تبقى التسجيلات ضمن نطاق بيئة تشغيل الإضافة، بينما تستخدم عمليات المشروع سجل
النسخة المعتمدة. وتغذّي محوّلات التهيئة في Core ذلك السجل بإعدادات المجلدات.

### البحث على الويب

اسرد مزوّدي البحث على الويب، أو نفّذ استعلامًا عبر المزوّد المحدد.

```ts
const providers = await ctx.websearch.providers()
const results = await ctx.websearch.query({ query: "OpenCode plugins", providerID: "internal" })
```

سجّل مزوّدًا وحدّد المزوّد الافتراضي باستخدام تحويل.

```ts
await ctx.websearch.transform((editor) => {
  editor.add({
    id: "internal",
    name: "Internal search",
    execute: async ({ query }, { signal }) => {
      const response = await fetch(`https://search.example.com?q=${encodeURIComponent(query)}`, { signal })
      const result = await response.json()
      return [{ url: result.url, title: result.title, content: result.content, time: {} }]
    },
  })
  editor.default.set("internal")
})
```

عطّل البحث على الويب باختيار `false`، أو أعد تحميل المزوّدين بعد تغيّر حالة خارجية.

```ts
await ctx.websearch.transform((editor) => editor.default.set(false))
await ctx.websearch.reload()
```

## الخطّافات

تعترض الخطّافات العمليات الجارية. سجّل الخطّاف على مجاله، وتخلّص من التسجيل المُعاد عندما لا تعود بحاجة إليه.

```ts
const registration = await ctx.session.hook("context", () => {})
await registration.dispose()
```

يمكن لعدة إضافات تسجيل الخطّاف نفسه. يشغّلها OpenCode بترتيب الإضافات، فترى الخطّافات اللاحقة التغييرات التي أجرتها
الخطّافات السابقة.

### الجلسات

تعترض خطّافات الجلسات قبول الموجّهات، واستدعاءات النماذج، وHTTP الأصلي، وإعادة المحاولات.

#### قبول الموجّه

اعترض موجّهات المستخدم الواردة قبل حلّ المرفقات والمهارات وقبل قبولها الدائم في صندوق الوارد:

```ts
await ctx.session.hook("prompt", (event) => {
  event.prompt.text = event.prompt.text.replaceAll("company-secret", "[redacted]")
  event.prompt.files ??= []
  event.prompt.files.push({ uri: "file:///project/policy.md" })
  event.metadata = { ...event.metadata, source: "company-policy" }
  event.delivery = "queue"
})
```

يتلقى الخطّاف مسودة مملوكة قابلة للتعديل:

- يحتوي `prompt` على `text` و`files` وإشارات الوكلاء في `agents` والمهارات المحددة في `skills`.
- يحتوي `metadata` على بيانات وصفية للقبول يحددها التطبيق.
- قيمة `delivery` هي `"steer"` افتراضيًا، ويمكن تغييرها إلى `"queue"`.
- معرّفات الجلسة والرسالة للقراءة فقط؛ ولا يمكن للخطّاف إعادة توجيه القبول.

تخضع الملفات والمهارات التي يضيفها الخطّاف لمسار الحل والتحقق المعتاد. وعند إعادة كتابة النص، حدّث إزاحات `mention` في
المرفقات التي لم تعد مطابقة أو أزلها. ولا تؤدي إشارات الوكلاء إلى تبديل الوكيل النشط في الجلسة.

تعمل خطّافات الموجّه وفق الشروط التالية:

- تعمل الخطّافات بترتيب التسجيل بعد جاهزية إضافات موقع الجلسة.
- تشغّل الأوامر التي ترسل عبر `session.prompt` الخطّاف.
- لا تشغّله الرسائل الاصطناعية ورسائل shell وعناصر التحكم في ضغط السياق وعناصر التحكم في النقل.
- يعمل الخطّاف مرة واحدة أثناء القبول، لا قبل كل استدعاء للنموذج.
- لا يتوفر تحديد النطاق بحسب المزوّد، لأن حلّ النموذج يحدث بعد القبول.

تصبح التعديلات هي مدخلات المستخدم المعتمدة المحفوظة. وإذا فشل التحضير أو قوطع، فلا يقبل OpenCode الموجّه.

اجعل خطّافات الموجّه آمنة عند إعادة المحاولة. فهي ليست حدًّا يضمن تنفيذ الآثار الجانبية مرة واحدة بالضبط:

- تؤدي إعادة المحاولة بمعرّف معلّق أو مُسلَّم بالفعل إلى إعادة القبول الأصلي دون إعادة تشغيل الخطّافات.
- قد تشغّل الإرسالات المتزامنة الخطّافات أكثر من مرة، لكن أول قبول ناجح فقط هو الذي يسري.
- تحوّل خطّافات الموجّه المدخلات، ولا توفّر واجهة API محددة النوع للرفض.

#### طلبات النموذج

عدّل تعليمات النظام المُجمَّعة أو الرسائل أو الأدوات أو خيارات الطلب مباشرةً قبل إرسالها إلى النموذج. لكل نوع من الطلبات
التي تصدرها الجلسة خطّافه الخاص، لذا يمكن للإضافة التعامل مع حلقة الوكيل والطلبات المساعدة بشكل مختلف:

- يعمل `context` لحلقة الوكيل، بما في ذلك المتابعات الناتجة عن الأدوات.
- يعمل `compaction` لملخصات نقاط الحفظ. يمثّل `messages` النص الكامل للمحادثة الذي يُلخَّص؛ ويُلحق OpenCode موجّه التلخيص
  الخاص به بعد تشغيل الخطّافات. اضبط `result` لتسجّل ضغط السياق بنفسك وتتخطى استدعاء النموذج؛ ويقبل الحقول نفسها التي
  تحتويها رسالة ضغط سياق مكتملة.
- يعمل `generate` لاستدعاءات `ctx.session.generate` العابرة.
- يعمل `title` لتوليد العناوين، ولا يحتوي على `agent` أو `tools`. اضبط `result` لتوفّر العنوان بنفسك.

```ts
await ctx.session.hook("context", (event) => {
  event.system.push({ type: "text", text: "Keep the review focused on correctness." })
  delete event.tools.write
  event.options.temperature = 0.2
  event.options.maxTokens = 8_000
})

await ctx.session.hook("compaction", async (event) => {
  event.result = { summary: await summarize(event.messages) }
})
```

لا تؤثر التغييرات إلا في استدعاء النموذج الصادر، لا في السجل المحفوظ أو التهيئة. والخطّاف الذي يجب أن ينطبق على كل طلب
يجب تسجيله لكل نوع.

تتبع تجاوزات الطلب القواعد التالية:

- يبدأ `options` فارغًا في كل استدعاء للنموذج؛ ولا يحتوي على إعدادات النموذج المحلولة.
- المفاتيح محددة النوع هي إعدادات التوليد؛ وأي مفتاح آخر يُمرَّر إلى البروتوكول المحدد بوصفه خيارًا للمزوّد.
- تعمل الخطّافات بترتيب التسجيل وترى التجاوزات التي أجرتها الخطّافات السابقة.
- لتجاوزات الطلب أولوية على القيم الافتراضية للنموذج، التي لها بدورها أولوية على القيم الافتراضية للمسار.
- تُدمج كائنات خيارات المزوّد تكراريًا؛ أما المصفوفات والقيم المفردة فتستبدل القيم السابقة.
- يؤدي حذف تجاوز أو ضبطه على `undefined` إلى الرجوع إلى القيم الافتراضية المهيّأة، لا إلى إزالتها.
- تُطبَّق تراكبات جسم HTTP الخام بعد التحويل إلى صيغة البروتوكول، ويمكنها تجاوز الحقول الناتجة.

#### خيارات المزوّد

تستخدم خيارات المزوّد أسماء الخيارات الدلالية للبروتوكول المحدد، لا حقول جسم HTTP الخام. حدّد نطاق الإعدادات الخاصة
بمزوّد معيّن بالمزوّد المطابق. فمثلًا، تستخدم OpenAI Responses الخيار `reasoningEffort`:

```ts
await ctx.session.hook(
  "context",
  (event) => {
    event.options.reasoningEffort = "high"
  },
  { providerID: "openai" },
)
```

تعتمد خيارات التوليد على البروتوكول والنموذج المحددين:

- يمثّل `maxTokens` الحد الدلالي لعدد tokens المخرجات.
- يدعم Gemini الخيار `topK`، بينما لا توفّره OpenAI Responses.

#### طلب النموذج

عدّل إعدادات طلب النموذج، واختياريًا حدّد نطاق الخطّاف بمزوّد واحد. يحمل الحدث قيمة `kind` نفسها التي تحملها خطّافات HTTP
أدناه.

```ts
await ctx.session.hook(
  "model.request",
  (event) => {
    event.headers["x-plugin"] = "review"
  },
  { providerID: "anthropic" },
)
```

#### HTTP الأصلي

عدّل طلبات المزوّد الأصلية أو استجاباته. أجسامها تدفقات تُقرأ مرة واحدة فقط؛ لذا انسخ الجسم أو استبدله قبل قراءته.

يعمل كلا الخطّافين لكل طلب تصدره الجلسة. وتوضح `event.kind` المسار الذي أصدر الطلب: `"primary"` لحلقة الوكيل،
و`"compaction"` لملخصات نقاط الحفظ، و`"title"` لتوليد العناوين، و`"generate"` لاستدعاءات `ctx.session.generate` العابرة.
استخدمها بدلًا من معرّف الوكيل للتمييز بين الطلبات المساعدة.

```ts
await ctx.session.hook("http.request", (event) => {
  event.request.headers.set("x-session-id", event.sessionID)
  if (event.kind === "title") event.request.headers.set("x-priority", "background")
})

await ctx.session.hook("http.response", (event) => {
  event.response = new Response(event.response.body, {
    status: event.response.status,
    headers: { ...Object.fromEntries(event.response.headers), "x-plugin": "review" },
  })
})
```

#### WebSocket الأصلي (تجريبي)

يفتح المزوّدون الذين يبثّون عبر WebSocket اتصالًا واحدًا لكل جلسة ويعيدون استخدامه عبر الطلبات، لذا لا يرى `http.request`
و`http.response` تلك الحركة أبدًا. يعمل الخطّاف `experimental.ws.handshake` مرة واحدة لكل استدعاء للنموذج قبل اختيار
الاتصال. ويحمل قيم `sessionID` و`agent` و`model` و`kind` نفسها التي تحملها خطّافات HTTP، إضافةً إلى `url` و`headers`
الخاصين بالاتصال. ويؤدي تغيير `url` أو `headers` إلى تغيير المقبس الذي يستخدمه الطلب، لذا فإن تدوير bearer token يعيد
فتح الاتصال.

تظل خطّافات HTTP تعمل لكل طلب HTTP، بما في ذلك الطلب الذي يرجع إليه مسار WebSocket عند الإخفاق.

```ts
await ctx.session.hook(
  "experimental.ws.handshake",
  async (event) => {
    event.headers.authorization = `Bearer ${await mintToken(event.url)}`
    delete event.headers["api-key"]
  },
  { providerID: "azure" },
)
```

يعرض `experimental.ws.send` و`experimental.ws.receive` الإطارات نفسها، وهما نظيرا تعديل جسم طلب HTTP أو استجابته في
WebSocket. يعمل `send` بعد أن يبني برنامج تشغيل المزوّد إطارًا صادرًا وقبل كتابته؛ ويعمل `receive` على كل إطار وارد قبل
أن يراه برنامج التشغيل. يحمل كلاهما الإطار نصًا، ويُرسل ما يحتويه `frame` عند انتهاء الخطّاف.

لا يتحقق OpenCode من صحة الإطارات المُعادة كتابتها. يتتبع برنامج التشغيل الحالة من ردود المزوّد، لذا فإن أي إعادة كتابة
تغيّر دلالة البروتوكول تقع مسؤوليتها على الإضافة، تمامًا كما في جسم HTTP المُعاد كتابته.

```ts
await ctx.session.hook(
  "experimental.ws.send",
  (event) => {
    const body = JSON.parse(event.frame)
    if (body.type === "response.create") body.metadata = { ...body.metadata, session: event.sessionID }
    event.frame = JSON.stringify(body)
  },
  { providerID: "openai" },
)

await ctx.session.hook("experimental.ws.receive", (event) => {
  if (event.frame.includes('"type":"error"')) console.error(event.frame)
})
```

هذه الخطّافات تجريبية، وقد تتغير أسماؤها أو بنيتها.

#### سياسة إعادة المحاولة

تجاوز قرار إعادة المحاولة عند فشل المزوّد، أو استبدل مدة الانتظار بالمللي ثانية. يعمل الخطّاف بعد أن يصنّف OpenCode
الفشل ويقترح سياسته، لكن قبل جدولة أي إعادة محاولة. ولا يكشف الكيفية التي ينفّذ بها OpenCode المحاولة التالية داخليًا.

```ts
await ctx.session.hook("retry", (event) => {
  if (event.error.status === 429) {
    event.decision = { retry: true, delay: 10_000 }
    return
  }
  if (event.error.type === "provider.invalid-request" && event.attempt === 2) {
    event.decision = { retry: true, delay: 0 }
    return
  }
  if (event.attempt >= 3) event.decision = { retry: false }
})
```

يمكن لخطّافات إعادة المحاولة تغيير القرار الأولي `decision` في OpenCode، بجعل فشل نهائي قابلًا لإعادة المحاولة، أو برفض
إعادة محاولة مقترحة.

تتبع قرارات إعادة المحاولة القواعد التالية:

- تعمل الخطّافات المتعددة بترتيب التسجيل، وترى الخطّافات اللاحقة القرار الحالي.
- يظل الحد الأقصى المدمج لعدد المحاولات حدًّا صارمًا.
- يمثّل `attempt` المحاولة الفعلية قيد النظر. الطلب الأولي هو `1`، لذا فإن أول إعادة محاولة هي `2`.
- ترجع مدد الانتظار غير الصالحة، مثل `NaN` أو اللانهاية أو القيم السالبة، إلى المدة المحسوبة.
- التعافي من تجاوز السياق منفصل، لأنه يضغط المحادثة بدلًا من إعادة محاولة الطلب نفسه.

```ts
  readonly agent: string
  readonly model: { providerID: string; id: string; variant?: string }
  readonly kind: "primary" | "compaction" | "title" | "generate"
  frame: string
}

type RetryDecision = { retry: false } | { retry: true; delay: number }

interface SessionRetryHook {
  readonly sessionID: string
  readonly agent: string
  readonly model: { providerID: string; id: string; variant?: string }
  readonly error: { type: string; message: string; status?: number }
  readonly attempt: number
  decision: RetryDecision
}

interface SessionRequestHook {
  readonly sessionID: string
  readonly model: { providerID: string; id: string; variant?: string }
  system: SystemPart[]
  messages: Message[]
  options: {
    maxTokens?: number
    temperature?: number
    topP?: number
    topK?: number
    frequencyPenalty?: number
    presencePenalty?: number
    seed?: number
    stop?: string[]
  } & Record<string, unknown>
}

interface SessionContextHook extends SessionRequestHook {
  readonly agent: string
  tools: Record<string, { description: string; input: JsonSchema }>
}

interface SessionCompactionResult {
  summary: string
  providerState?: Record<string, unknown>
  metadata?: Record<string, unknown>
  tokens?: TokenUsage
}

interface SessionHookContext {
  hook<Name extends keyof SessionHooks>(
    name: Name,
    callback: (event: SessionHooks[Name]) => Promise<void> | void,
    options?: Name extends "prompt" ? never : { providerID?: string },
  ): Promise<Registration>
}
```

### الأذونات

راجع قرارات الأذونات بعد تقييم القواعد المهيّأة، وقبل تنفيذ الإجراء أو نشر طلب إذن.

```ts
await ctx.permission.hook("evaluate", async (event) => {
  if (event.action === "read") return

  const messages = await ctx.session.context({ sessionID: event.sessionID })
  const review = await ctx.generate.text({
    model: { providerID: "anthropic", id: "claude-sonnet-4-6" },
    prompt: buildSafetyPrompt({ messages, action: event.action, resources: event.resources }),
  })
  const decision = parseDecision(review.text)

  event.effect = decision.effect
  event.message = decision.reason
})
```

تتبع خطّافات الأذونات القواعد التالية:

- تعمل الخطّافات لقرارات `allow` و`ask`.
- القرار `deny` المهيّأ صراحةً نهائي ولا يستدعي الخطّاف.
- يمكن للخطّاف تغيير `effect` إلى `allow` أو `ask` أو `deny`.
- يظهر `message` في طلب الإذن المُصعَّد، أو يصبح سبب الرفض.

#### المرجع

```ts
interface PermissionEvaluation {
  readonly sessionID: string
  readonly agent?: string
  readonly action: string
  readonly resources: readonly string[]
  readonly metadata?: Record<string, unknown>
  readonly source?: { type: "tool"; messageID: string; id: string }
  effect: "allow" | "ask" | "deny"
  message?: string
}
```

## النشر

تستخدم إضافة الحزمة التصدير الافتراضي نفسه الذي تستخدمه الإضافة المحلية. وهذا ملف تعريف (manifest) بالحد الأدنى:

```json title="package.json"
{
  "name": "opencode-acme-plugin",
  "version": "1.0.0",
  "type": "module",
  "exports": {
    ".": "./src/index.ts",
    "./rpc": "./src/rpc.ts"
  },
  "dependencies": {
    "@opencode/plugin": "latest"
  }
}
```

التصدير `./rpc` اختياري؛ أضفه عند نشر [عقد RPC](/build/plugins/rpc) مشترك لتستورده الإضافات والعملاء الآخرون دون تحميل
تنفيذك.

استخدم إصدارات متوافقة مع إصدار OpenCode الذي تستهدفه، واختبر الحزمة المثبّتة لا مجرد نسخة مرتبطة عبر مساحة العمل.
وانشر تحديثًا متوافقًا للإضافة عندما تعتمد عقد API أحدث.

## دعم V1

يمكن للإضافة دعم V1 وV2 من نقطة الدخول نفسها في الحزمة. صدّر افتراضيًا كائنًا واحدًا يحتوي على الدالة `server()` الخاصة
بـ V1 والدالة `setup()` الخاصة بـ V2:

```ts title="src/index.ts"
import { Plugin } from "@opencode/plugin"

export default {
  ...Plugin.define({
    id: "example",
    async setup(ctx) {
      await ctx.tool.hook("execute.before", () => {
        console.log("A tool is about to run")
      })
    },
  }),
  async server() {
    return {
      "tool.execute.before": async () => {
        console.log("A tool is about to run")
      },
    }
  },
}
```

- يستدعي V1 الدالة `server()` ويستخدم الخطّافات التي تعيدها.
- يقرأ V2 قيمتي `id` و`setup()` من التصدير الافتراضي (أو `effect()` لإضافات Effect)، ويتجاهل `server()`.
- أبقِ كل تنفيذ على واجهة API الخاصة به؛ فمشاركة التصدير لا تحوّل خطّافات V1 إلى خطّافات V2.
- انشر `Plugin.define(...)` بعامل النشر (spread) داخل الكائن المُصدَّر، كي يتحقق من أنواع تعريف V2 بمعزل عن `server()`.

صيغة الكائن في V1 مدعومة في OpenCode `1.18.29`. وقد تتوقع إصدارات V1 الأقدم تصدير دوال بدلًا من ذلك؛ لذا اختبر الحزمة
المثبّتة مع أقدم إصدار V1 تنوي دعمه ومع V2.
