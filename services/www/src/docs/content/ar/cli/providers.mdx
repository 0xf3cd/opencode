title: "المزوّدون"
description: "اربط حسابات المزوّدين وأدِر بيانات الاعتماد من CLI وواجهة TUI."
---

اربط مزوّدًا في واجهة TUI، ثم اختر أحد نماذجه:

```text
/connect
/models
```

يعرض الأمر `/connect` التكاملات المتاحة من الخادم والمشروع الحاليين. اختر مزوّدًا، ثم اختر طريقة المصادقة إن كان يوفّر
أكثر من طريقة، واتبع التعليمات التي تظهر.

## TUI

تدعم واجهة TUI مفاتيح API وOAuth وأوامر المصادقة التي يوفّرها المزوّد. تفتح طريقة OAuth عنوان URL للتفويض أو تعرض رمزًا
لإدخاله؛ اضغط `o` لفتح عنوان URL و`c` لنسخ تفاصيل التفويض.

```text
/connect
# Select OpenAI, then Codex device code (legacy).
```

شغّل `/connect` مجددًا لإضافة حساب آخر. يؤدي اختيار مزوّد متصل مسبقًا إلى فتح قائمة حساباته، حيث يمكنك تفعيل حساب محفوظ
أو إعادة تسميته أو حذفه.

## CLI

استخدم `auth login` للوصول إلى طرق المزوّد نفسها دون فتح واجهة TUI. إذا لم تحدد مزوّدًا، يفتح الأمر أداة اختيار تفاعلية
للمزوّدين.

```bash
opencode auth login
```

مرّر معرّف التكامل أو اسمه لتخطي أداة الاختيار الأولى. استخدم `--method key` لاختيار إدخال مفتاح API صراحةً.

```bash
opencode auth login anthropic --method key
```

تختلف معرّفات الطرق من مزوّد لآخر. شغّل الأمر دون `--method` لعرض الطرق المتاحة عندما يوفّر المزوّد أكثر من طريقة.

```bash
opencode auth login openai
```

يتطلب إدخال مفتاح API ونماذج الإدخال الخاصة بالمزوّد طرفية تفاعلية، وكذلك طرق OAuth التي تطلب منك لصق رمز تفويض.

## الطرق

يتلقى OpenCode بيانات اعتماد المزوّدين عبر أربع طرق تكامل:

| الطريقة | السلوك |
| --- | --- |
| مفتاح API | يطلب قيمة سرية ويحفظها حسابًا لدى المزوّد. |
| OAuth | يوفّر عنوان URL في المتصفح أو رمز جهاز أو طلبًا لإدخال رمز التفويض، ثم يحفظ tokens ويجددها عند دعم ذلك. |
| أمر | يشغّل أمر مصادقة يوفّره المزوّد ويحفظ مخرجاته القياسية مفتاحًا. |
| البيئة | يقرأ متغيرًا مدعومًا من عملية الخادم دون حفظه. |

يمكن للمزوّدين إضافة نماذج إدخال إلى طريقتي مفتاح API وOAuth لجمع تفاصيل مطلوبة، مثل اسم مورد Azure أو نطاق GitHub
Enterprise. ويعرض CLI وواجهة TUI هذه النماذج قبل بدء المصادقة.

## البيئة

اضبط متغير البيئة الذي يدعمه المزوّد على عملية الخادم التي تنفّذ طلبات النماذج. ولخادم خاص مؤقت، مرّره عند التشغيل في
الوضع المستقل.

```bash
ANTHROPIC_API_KEY=sk-ant-... opencode --standalone
```

أما للخادم الخلفي المشترك، فأضف المتغير إلى بيئته المُدارة. يؤدي ذلك إلى إيقاف الخدمة قيد التشغيل، ثم يشغّلها أمر OpenCode
التالي بالقيمة الجديدة.

```bash
opencode service set env ANTHROPIC_API_KEY sk-ant-...
opencode auth list
```

تظهر اتصالات البيئة في `auth list` بالنوع `environment`. وهي ليست حسابات: لا يستطيع `auth logout` إزالتها، لذا احذف
المتغير لقطع الاتصال. وللحساب المحفوظ الأولوية على اتصال البيئة للتكامل نفسه.

```bash
opencode auth list
opencode service unset env ANTHROPIC_API_KEY
```

يستخدم بعض مزوّدي الخدمات السحابية أيضًا سلسلة بيانات الاعتماد المحيطة الأصلية لديهم بدلًا من متغير لمفتاح API:

- يدعم Amazon Bedrock سلسلة بيانات الاعتماد الافتراضية في AWS، بما في ذلك الملفات الشخصية (profiles) ومتغيرات بيئة مفاتيح
  الوصول وهوية الويب وبيانات اعتماد الحاويات. ويدعم أيضًا `AWS_BEARER_TOKEN_BEDROCK`.
- يستخدم Google Vertex بيانات الاعتماد الافتراضية للتطبيق (Application Default Credentials) ومشروعًا يمكن تحديده. مثلًا،
  صادِق باستخدام `gcloud auth application-default login` واضبط `GOOGLE_CLOUD_PROJECT`.
- يوفّر Azure الطريقة **Microsoft Entra ID (Azure CLI)** للاتصال عندما يكون `az` مثبّتًا. شغّل `az login` أولًا، ثم
  اختر تلك الطريقة في `/connect` أو `auth login azure`.

```bash
gcloud auth application-default login
GOOGLE_CLOUD_PROJECT=my-project opencode
```

راجع [المزوّدون](/providers) لمعرفة الإعداد الخاص بكل مزوّد والإعداد على جانب الخادم.

## الحسابات

ينشئ كل تسجيل دخول ناجح عبر مفتاح API أو OAuth أو أمر حسابًا محفوظًا. يصبح أحدث حساب هو الحساب النشط؛ ويمكنك تبديل
الحساب النشط باستخدام تسميته أو معرّف بيانات اعتماده.

```bash
opencode auth list
opencode auth switch anthropic work
```

أزِل حسابًا محفوظًا باستخدام `auth logout`. يفتح كلا الأمرين أداة اختيار عند حذف وسائطهما.

```bash
opencode auth logout anthropic work
```

في واجهة TUI، يوفّر `/connect` عمليات الإضافة والتفعيل وإعادة التسمية والحذف نفسها للحسابات المحفوظة.

## التخزين

تُحفظ مفاتيح API وtokens الخاصة بـ OAuth في قاعدة بيانات SQLite التابعة للخادم. وللخادم المحلي، اطبع مسار قاعدة بياناته
باستخدام:

```bash
opencode debug paths db
```

المسار المعتاد للإصدار هو `~/.local/share/opencode/opencode.db`، ويمكن أن يغيّره كلٌّ من `XDG_DATA_HOME` وقناة الإصدار
و`OPENCODE_DB`. لا تعدّل قاعدة البيانات لإدارة بيانات الاعتماد؛ استخدم `/connect` أو أوامر `auth`.

يستورد V2 بيانات الاعتماد المدعومة من الملف القديم `auth.json` في دليل بيانات OpenCode أثناء ترحيل قاعدة البيانات. وتُخزَّن
بيانات الاعتماد الجديدة والمحدَّثة في SQLite بدلًا من كتابتها مرة أخرى في ذلك الملف.
