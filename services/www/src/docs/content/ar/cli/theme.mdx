---
title: "السمة"
---

يأتي OpenCode بالعديد من السمات المدمجة للوضعين الفاتح والداكن. اختر إحداها من الإعدادات، أو امزج ألوانك الخاصة.

## اختيار سمة

اضغط `Ctrl+P`، واختر **Open settings**، ثم افتح **Theme**. السمة الافتراضية هي `opencode`.

يمكنك أيضًا ضبطها في [إعدادات CLI](/cli/config) العامة:

```json title="~/.config/opencode/cli.json"
{
  "$schema": "https://opencode.ai/v2/cli.json",
  "theme": {
    "name": "tokyonight",
    "mode": "dark"
  }
}
```

شغّل `/themes` لتغيير السمة دون فتح الإعدادات.

## ألوان النظام

عندما يتمكن OpenCode من قراءة لوحة ألوان الطرفية، تتضمن أداة اختيار السمات السمة `system`. تستمد هذه السمة ألوانها من لون
النص الأمامي والخلفية ولوحة ألوان ANSI في طرفيتك.

يختار اسم السمة `system` الألوان المستمدة من الطرفية، بينما يتبع الوضع `system` مظهر الطرفية الفاتح أو الداكن.

## الوضع

استخدم `system` لاتباع مظهر الطرفية، أو ثبّت السمة على الوضع الفاتح أو الداكن:

| الوضع | السلوك |
| --- | --- |
| `system` | يتبع مظهر الطرفية المكتشَف، فاتحًا كان أو داكنًا. |
| `dark` | يستخدم دائمًا الألوان الداكنة للسمة. |
| `light` | يستخدم دائمًا الألوان الفاتحة للسمة. |

يقابل ذلك الحقل `mode` داخل `theme` في تهيئة CLI. وإذا وفّرت سمة مخصصة وضعًا واحدًا فقط، يستخدمه OpenCode عند طلب الوضع
الآخر.

## إضافة سمة

لإضافة سمة نزّلتها أو تلقيتها من شخص آخر، انسخ ملف JSON الخاص بها إلى دليل السمات العام:

```bash
cp theme.json ~/.config/opencode/themes/
```

يمكنك أيضًا وضع السمة في دليل `.opencode/themes` داخل مشروع لإتاحتها في ذلك المشروع وحده.

يصبح اسم الملف اسمًا للسمة؛ فمثلًا يظهر `my-theme.json` باسم `my-theme`. أعد تشغيل OpenCode بعد إضافة الملف، ثم شغّل
`/themes` لاختيارها.

يقرأ OpenCode ملفات `.json` فقط. وتحل السمة الأقرب إلى الدليل الحالي محل السمة العامة أو سمة الدليل الأب التي تحمل الاسم
نفسه.

## استخدام السمات في الإضافات

تقرأ [إضافات CLI](/build/plugins/cli) الألوان المحلولة عبر `context.theme`، والوضع النشط عبر `context.themeMode`. استخدم
الرموز الدلالية (semantic tokens) لتتبع إضافتك السمة المختارة:

```tsx title="Inside a CLI plugin component"
import { usePlugin } from "@opencode/plugin/tui"

function Status() {
  const context = usePlugin()
  return <text fg={context.theme.text.base}>Ready</text>
}
```

لا تسجّل واجهة API العامة لإضافات CLI أي سمات. أضف تعريفات السمات المخصصة عبر ملفات JSON في الأدلة المذكورة أعلاه.

## إنشاء سمة

استخدم [أداة السمات](https://opencode.ai/theme/) لإنشاء السمات أو تعديلها. تسهّل هذه الأداة فهم البنية وتغييرها وتعريف
ألوان مخصصة. والشرح أدناه للرجوع إليه.

تفصل السمة الرموز الدلالية المشتركة عن لوحات الألوان الخاصة بكل وضع:

| القسم | الغرض |
| --- | --- |
| `base` | شجرة الرموز الكاملة المشتركة بين جميع الأوضاع. |
| `light`, `dark` | لوحة كاملة من التدرّجات اللونية، مع تجاوزات اختيارية للرموز في ذلك الوضع. |

توفّر كل سمة قسم `base` كاملًا، وتعرّف أحد القسمين `light` أو `dark` على الأقل. ترث الأوضاع من `base` في الملف نفسه، ولا
ترث من سمة OpenCode المدمجة ولا من بعضها بعضًا.

تعرض الأمثلة أدناه الأقسام المتعلقة بكل مفهوم فقط. استخدم محرر السمات لإنشاء ملف كامل قبل تخصيصه.

### البنية

ضع الألوان التي يستخدمها الوضعان في `base`، ثم تجاوزها داخل `light` أو `dark` عند الحاجة:

```json title="theme.json (excerpt)"
{
  "$schema": "https://opencode.ai/theme.json",
  "base": {
    "text": {
      "base": "$hue.neutral.200",
      "muted": "$hue.neutral.400"
    }
  },
  "light": {
    "hue": {}
  },
  "dark": {
    "hue": {},
    "text": {
      "muted": "$hue.neutral.300"
    }
  }
}
```

يوفّر القسم `base` الكامل جميع الرموز الدلالية. ويوفّر كل وضع جميع التدرّجات اللونية المطلوبة، ويمكنه تجاوز أي جزء من
شجرة الرموز الأساسية.

### الألوان والمراجع

يمكن أن يكون اللون قيمة سداسية عشرية (hex)، أو `"transparent"`، أو مرجعًا إلى لون آخر في السمة:

```json title="Inside base or a mode"
{
  "text": {
    "base": "#eeeeee",
    "muted": "$hue.neutral.400"
  },
  "border": {
    "base": "$text.muted"
  }
}
```

### التدرّجات اللونية

التدرّجات اللونية (hues) سلالم ألوان من تسع درجات. يعرّف كل وضع التدرّجات الأساسية الثمانية وثلاثة أسماء بديلة:

| النوع | القيم |
| --- | --- |
| أساسي | `gray`, `red`, `orange`, `yellow`, `green`, `cyan`, `blue`, `purple` |
| اسم بديل | `accent`, `interactive`, `neutral` |
| درجة | `100`, `200`, `300`, `400`, `500`, `600`, `700`, `800`, `900` |

عرّف الدرجات التسع كلها لكل تدرّج أساسي، أو اجعل تدرّجًا اسمًا بديلًا لتدرّج آخر:

```json title="Inside light or dark"
{
  "hue": {
    "purple": {
      "100": "#b38ff4",
      "200": "#9d7cd8",
      "300": "#8869bd",
      "400": "#7357a2",
      "500": "#5f4688",
      "600": "#4b356f",
      "700": "#392557",
      "800": "#271640",
      "900": "#17072b"
    },
    "accent": "$hue.purple"
  }
}
```

تتبع درجات التدرّج اتجاه التباين في الوضع. ففي السمات الفاتحة تتدرج من الداكن عند `100` إلى الفاتح عند `900`، وفي
السمات الداكنة من الفاتح عند `100` إلى الداكن عند `900`.

تحدد المصفوفة `categorical` في `base` التدرّجات المرتبة المستخدمة للتمييز بين الوكلاء والعناصر المتكررة الأخرى:

```json title="Inside base"
{
  "categorical": ["accent", "purple", "green", "blue"]
}
```

### الرموز الدلالية

تُسند الرموز الدلالية الألوانَ إلى أدوار في الواجهة. وتستخدم المكوّنات هذه الأدوار بدلًا من اختيار الألوان مباشرةً.

| المجموعة | الغرض |
| --- | --- |
| `text` | النص الأساسي والخافت ونص الإجراءات وحقول النماذج والحالة والملاحظات. |
| `background` | الخلفية الأساسية والأسطح المرتفعة والإجراءات وحقول النماذج وتعبئة الملاحظات. |
| `border`, `scrollbar` | ألوان الحدود وشريط التمرير. |
| `diff` | ألوان الإضافات والحذف والسياق والتمييز وأرقام الأسطر. |
| `syntax` | تمييز صياغة الشيفرة المصدرية. |
| `markdown` | عناصر Markdown. |

مثلًا، يتحكم `text.muted` في النص الثانوي، بينما يعرّف `background.raised` أسطحًا متزايدة الارتفاع تدريجيًا:

```json title="Inside base"
{
  "text": {
    "base": "$hue.neutral.200",
    "muted": "$hue.neutral.400"
  },
  "background": {
    "base": "$hue.neutral.800",
    "raised": {
      "base": "$hue.neutral.700",
      "high": "$hue.neutral.600",
      "max": "$hue.neutral.500"
    }
  }
}
```

مفاتيح الصياغة هي `comment` و`keyword` و`function` و`variable` و`string` و`number` و`type` و`operator`
و`punctuation`.

مفاتيح Markdown هي `text` و`heading` و`link` و`linkText` و`code` و`blockQuote` و`emphasis` و`strong`
و`horizontalRule` و`listItem` و`listEnumeration` و`image` و`imageText` و`codeBlock`.

### الإجراءات والحالات

للإجراءات ثلاثة أنواع: `primary` و`secondary` و`destructive`. وتستخدم الإجراءات وحقول النماذج القيمة `base` إضافةً إلى
حالات تفاعل اختيارية:

```json title="Inside base or a mode"
{
  "text": {
    "action": {
      "primary": {
        "base": "$hue.interactive.400",
        "$hovered": "$hue.interactive.300",
        "$disabled": "$hue.neutral.600"
      }
    }
  }
}
```

مفاتيح الحالات هي `$hovered` و`$focused` و`$pressed` و`$selected` و`$disabled`. وتستخدم الحالة غير المحددة لون `base`
الخاص بذلك الإجراء أو حقل النموذج.

### سطح مربعات الحوار

تختار اللوحات ومربعات الحوار والقوائم والإشعارات المنبثقة (toasts) مستوى عمقها من `background.raised`. ويمكن لمربعات
الحوار أيضًا تجاوز الرموز الدلالية باستخدام `@dialog`:

```json title="Inside base or a mode"
{
  "@dialog": {
    "background": {
      "base": "$background.raised.base",
      "action": {
        "primary": {
          "$hovered": "$background.raised.high"
        }
      }
    }
  }
}
```

تحلّ واجهة TUI المراجع مجددًا بعد تطبيق `@dialog`، لذا تتبع الرموز التي تشير إلى `$background.base` خلفية مربع الحوار.
وتصبح قيمة `base` لإجراء سياقي البديل الاحتياطي لحالاته غير المحددة، بينما تظل التجاوزات الصريحة للحالات هي الغالبة.
