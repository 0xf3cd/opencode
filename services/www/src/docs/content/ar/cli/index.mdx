شغّل CLI داخل مشروع لفتح الواجهة الطرفية بملء الشاشة:

```bash
opencode
```

مرّر مسار دليل للعمل في مشروع آخر:

```bash
opencode ~/code/my-project
```

الطرفيات المقترحة:

- [Ghostty](https://ghostty.org)
- [WezTerm](https://wezterm.org)
- [Alacritty](https://alacritty.org)
- [Kitty](https://sw.kovidgoyal.net/kitty/)

يمنح دعم Truecolor السمات أدق ألوانها، أما الطرفيات التي لا تدعمه فتستخدم ألوانًا تقريبية من لوحة الألوان المتاحة.

## الأتمتة

استخدم `opencode run` لإرسال موجّه دون فتح الواجهة التفاعلية. صُمّم هذا الأمر للسكربتات ومهام CI وغيرها من سير العمل
التي تحتاج إلى مخرجات النموذج مباشرةً في الطرفية.

```bash
opencode run "Explain this repository"
```

## الواجهة المصغّرة

استخدم `opencode mini` لتشغيل واجهة OpenCode التفاعلية المصغّرة بدلًا من واجهة TUI بملء الشاشة.

```bash
opencode mini
```

شغّل `opencode mini --help` لعرض خياراته الخاصة بالجلسة والنموذج والوكيل والموجّه وإعادة التشغيل (replay).

## الخدمة الخلفية

يكتشف OpenCode افتراضيًا خادمًا خلفيًا مشتركًا واحدًا لحساب المستخدم لديك، أو يشغّله إن لم يكن موجودًا. ويتصل كل عميل
محلي من عملاء OpenCode بهذا الخادم، وهو الذي يملك الجلسات والتهيئة والتكاملات والأذونات وتنفيذ الأدوات.

استخدم `--standalone` للتشغيل بخادم خاص، أو `--server` للاتصال بعنوان URL لخادم محدد:

```bash
opencode --standalone
opencode --server http://localhost:4096
```

لجعل الخوادم الخاصة هي الخيار الافتراضي لأوامر CLI بدلًا من تشغيل الخدمة المشتركة، عطّل الخدمة:

```bash
opencode service set disabled true
opencode
```

يؤدي ذلك إلى إيقاف الخدمة الخلفية قيد التشغيل. ويظل `--server` يتصل بالخادم المحدد صراحةً، ويظل بإمكان الأمر
`opencode service start` تشغيل الخدمة المشتركة صراحةً. للعودة إلى استخدام الخدمة تلقائيًا، شغّل
`opencode service unset disabled`. يتطلب الاقتران (pairing) الخدمة المشتركة، ولا يتوفر ما دامت معطّلة.

راجع [استكشاف الأخطاء وإصلاحها](/troubleshooting) لتشخيص مشكلات الخدمة المشتركة، و[مرجع API](/api) لنقاط نهاية الخادم.

## المسارات

اطبع مسارًا محليًا محددًا لاستخدامه مع أدوات أخرى:

```bash
opencode debug paths db
sqlite3 "$(opencode debug paths db)"
```

يقبل المحدِّد الاختياري القيم `db` أو `home` أو `data` أو `config` أو `cache` أو `state` أو `tmp` أو `bin` أو `log`
أو `repos`، ويطبع المسار وحده متبوعًا بسطر جديد. يراعي مسار قاعدة البيانات قناة الإصدار والمتغير `OPENCODE_DB`؛ وتُحَلّ
المسارات النسبية المستخدمة لتجاوز قاعدة البيانات داخل دليل البيانات، وتُطبع القيمة `:memory:` كما هي. لا يشغّل هذا الأمر
خادمًا ولا يفتح قاعدة البيانات.

احذف المحدِّد لعرض جميع المسارات مع تسمياتها:

```bash
opencode debug paths
```

## إلغاء التثبيت

اعرض مسبقًا الملفات والتثبيت الذي ستجري إزالته:

```bash
opencode uninstall --dry-run
```

شغّل `opencode uninstall` لتأكيد الإزالة. يوقف OpenCode الخدمات الخلفية المسجّلة والطرفيات الدائمة قبل إزالة دليل
ذاكرة التخزين المؤقت العام، وهو دليل مشترك بين إصدارات OpenCode وقنواته. لا تُزال بيانات الجلسات ولا التهيئة ولا الحالة
أبدًا.

- يتخطى الخيار `--force` (`-f`) التأكيد؛ استخدمه للإزالة غير التفاعلية.
- تستخدم عمليات التثبيت عبر مدير الحزم مدير الحزم المكتشَف. أما عمليات التثبيت عبر curl فتطبع الأمر النهائي لإزالة
  الملف التنفيذي يدويًا.
