تضيف مزامنة الدليل (SCIM 2.0) الأشخاص إلى مساحة العمل عند تعيينهم في مزوّد الهوية، وتزيل وصولهم عند إلغاء تعيينهم. أما
الأدوار فتظل إدارتها في Console.

```text
https://opencode.ai/console/scim/v2
```

## قبل البدء

- أعدّ [SSO](/console/sso) لمساحة العمل.
- [وثّق](/console/sso#verify-email-domains) كل نطاق بريد إلكتروني يسجّل به أفرادك الدخول. لا تضيف مزامنة الدليل إلا
  الأشخاص الذين ينتمون إلى نطاق موثّق؛ أما غيرهم فادعُهم من [Members](/console/members).

## إنشاء token

1. افتح **Settings › Security** وانقر **Set up** تحت **Directory sync**.
2. انسخ **SCIM base URL** وقيمة token. لا تُعرض هذه القيمة إلا مرة واحدة، لذا خزّنها في مدير أسرار.

يرسل مزوّد الهوية قيمة token مع كل طلب.

```text
Authorization: Bearer <token>
```

## ربط مزوّد الهوية

### Okta

1. أضف التطبيق **SCIM 2.0 Test App (Header Auth)**.
2. اضبط عنوان URL الأساسي، وأدخل `Bearer ` متبوعًا بقيمة token في **API Token**.
3. فعّل **Create Users** و**Update User Attributes** و**Deactivate Users**. واترك **Import Groups** ومزامنة كلمات المرور
   معطّلة.

### Microsoft Entra ID

1. في تطبيق المؤسسة، افتح **Provisioning** واضبط الوضع على **Automatic**.
2. أدخل عنوان URL الأساسي في **Tenant URL** وقيمة token في **Secret Token**.
3. عيّن المستخدمين والمجموعات، ثم ابدأ التزويد (provisioning).

### مزوّدون آخرون

استخدم تطبيق SCIM 2.0 يدعم المصادقة عبر token في الترويسة، ووجّهه إلى عنوان URL الأساسي. تدعم Console نقطتي النهاية
`/Users` و`/Groups`.

عيّن شخصًا واحدًا للاختبار أولًا. يعرض **Directory sync** الرسالة **Connected to your identity provider** بعد أول طلب.

## ما تجري مزامنته

| في مزوّد الهوية | في Console |
| ------------------------- | --------------------------------------------------------------------------------- |
| تعيين شخص | يُضاف بدور **Member**. ويحتفظ الأعضاء الحاليون بأدوارهم. |
| تحديث الاسم | يُحدَّث الملف الشخصي. |
| إلغاء التعيين أو التعطيل | يُعلَّق الوصول ويظهر الشخص بحالة **Deactivated**. وتُلغى مفاتيح API التي أنشأها. |
| إعادة التعيين | يُستعاد الوصول. وتبقى المفاتيح الملغاة ملغاة. |
| الحذف | يُزال من مساحة العمل. ولا يتأثر حسابه ولا مساحات العمل الأخرى. |

- لا تغيّر مزامنة الدليل الأدوار ولا عناوين البريد الإلكتروني.
- لا يمكن تعطيل آخر مالك أو حذفه.
- لا يمكن لمساحات العمل المشتركة في [Go](/console/go) إضافة أعضاء عبر مزامنة الدليل.

## المجموعات

ادفع المجموعات لوسم أعضائها، مثلًا عبر **Push Groups** في Okta أو تعيين المجموعات في Entra. عيّن الأشخاص قبل دفع
مجموعاتهم.

```text
Platform Admins  →  platform-admins
```

تَسِم كل مجموعة أعضاءها بوسم يحمل اسمها. ومن **Settings › Security › Group tags** يمكنك إعادة تسمية وسم، أو توجيه عدة
مجموعات إلى وسم واحد، أو إيقاف وسم مجموعة ما. ويؤدي ترك المجموعة إلى إزالة وسمها.

## تدوير token

1. انقر **New token** وثبّته في مزوّد الهوية.
2. انتظر حتى يظهر تاريخ آخر استخدام بجانب token الجديد.
3. ألغِ token القديم.

يوقف إلغاء token التحديثات المستقبلية، لكنه لا يغيّر الأعضاء الحاليين. ويؤدي حذف اتصال SSO إلى إلغاء جميع tokens.

## SSO ومزامنة الدليل

بمجرد أن تُصدر مساحة العمل token، يتوقف SSO عن [إضافة الأعضاء تلقائيًا](/console/sso#automatic-membership). ويحدد الدليل
من ينتمي إلى مساحة العمل، حتى لو أُلغي token لاحقًا.
