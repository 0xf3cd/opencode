---
title: "الأذونات"
---

تتحكم الأذونات فيما إذا كان يُسمح للوكيل بتنفيذ إجراء على مورد ما.

## الإعداد

من الإعدادات الشائعة طلب الموافقة قبل تشغيل أوامر shell، والسماح بأوامر فحص Git الروتينية، ومنع عمليات الدفع (push)
دائمًا. أضف هذه القواعد المرتبة إلى `opencode.jsonc`:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "permissions": [
    { "action": "shell", "resource": "*", "effect": "ask" },
    { "action": "shell", "resource": "git status *", "effect": "allow" },
    { "action": "shell", "resource": "git diff *", "effect": "allow" },
    { "action": "shell", "resource": "git push *", "effect": "deny" },
  ],
}
```

تُطبَّق آخر قاعدة مطابقة، لذا تأتي الاستثناءات المحددة بعد القاعدة العامة.

<Callout type="warning">
  يستخدم V1 أسماء مختلفة للحقول والإجراءات. في V2، استخدم `permissions` و`shell` و`subagent` بدلًا من `permission`
  و`bash` و`task`.
</Callout>

## القواعد

تتطلب كل قاعدة ثلاثة حقول نصية:

| الحقل      | المعنى                                                                          |
| ---------- | ------------------------------------------------------------------------------- |
| `action`   | إجراء الإذن الخاص بالأداة                                                       |
| `resource` | القيمة المستخدمة، مثل مسار أو أمر أو عنوان URL أو استعلام أو معرّف مهارة أو معرّف وكيل |
| `effect`   | `allow` أو `deny` أو `ask`                                                       |

```jsonc
{
  "permissions": [
    { "action": "read", "resource": "*", "effect": "allow" },
    { "action": "read", "resource": "*.env", "effect": "deny" },
  ],
}
```

| التأثير  | النتيجة                              |
| -------- | ------------------------------------ |
| `allow`  | المتابعة دون طلب موافقة              |
| `deny`   | منع العملية                          |
| `ask`    | انتظار قرار من العميل                |

إذا لم تطابق أي قاعدة، يستخدم OpenCode القيمة `ask`.

## المطابقة

تستخدم الإجراءات والموارد أحرف بدل بسيطة تُطابق القيمة كاملة:

| النمط   | ما يطابقه                                  |
| ------- | ------------------------------------------ |
| `*`     | صفر محارف أو أكثر، بما فيها `/`            |
| `?`     | محرف واحد بالضبط                           |
| غير ذلك | المحرف نفسه حرفيًا                         |

```jsonc
{
  "permissions": [
    { "action": "edit", "resource": "packages/docs/*.mdx", "effect": "allow" },
  ],
}
```

يطابق هذا النمط المسار الموحّد بأكمله. وتُحوَّل الشرطات المائلة العكسية إلى شرطات مائلة، والمطابقة غير حساسة لحالة الأحرف
على Windows.

يطابق نمط shell المنتهي بـ ` *` الأمرَ أيضًا عند تشغيله دون وسائط:

```jsonc
{ "action": "shell", "resource": "git status *", "effect": "allow" }
```

يطابق هذا النمط كلًّا من `git status` و`git status --short`.

يجمع OpenCode القواعد بالترتيب ويستخدم آخر تطابق. تُحمَّل التهيئة ذات الأولوية الأدنى أولًا، ثم تُلحق القواعد العامة، ثم
تُلحق قواعد الوكيل أخيرًا.

```jsonc
{
  "permissions": [
    { "action": "read", "resource": "*", "effect": "allow" },
    { "action": "read", "resource": "secrets/*", "effect": "deny" },
  ],
}
```

قد تفحص العمليات عدة موارد، مثل رقعة تمس عدة ملفات. فإذا ظهر أي `deny` رُفضت العملية؛ وإلا فإن أي `ask` يؤدي إلى طلب
الموافقة؛ وإلا سُمح بالعملية.

## الإجراءات

أسماء الإجراءات في V2 سلاسل نصية، لذا يمكن للإضافات تعريف إجراءات أخرى. تستخدم الأدوات المدمجة حاليًا الإجراءات والموارد
التالية:

| الإجراء              | المورد                                                                          |
| -------------------- | ------------------------------------------------------------------------------- |
| `read`               | مسار داخلي نسبي إلى الموقع (Location)، أو مسار خارجي مطلق بصيغته القانونية     |
| `edit`               | المسار المستهدف في `edit` و`write` و`patch`                                     |
| `glob`               | نمط glob المطلوب                                                                |
| `grep`               | التعبير النمطي المطلوب، لا مسار البحث                                           |
| `shell`              | سلسلة الأمر التي يستخرجها المحلّل؛ وقد تنتج الأوامر المركّبة عدة سلاسل          |
| `subagent`           | معرّف الوكيل المستهدف                                                           |
| `skill`              | معرّف المهارة                                                                   |
| `question`           | `*`                                                                             |
| `webfetch`           | عنوان URL المطلوب                                                               |
| `websearch`          | استعلام البحث                                                                   |
| `external_directory` | حد الدليل الخارجي بصيغته القانونية، وينتهي عادةً بـ `/*`                         |
| `<server>_<tool>`    | `*` لأداة MCP؛ وتتحول المحارف غير المدعومة في الاسمين إلى `_`                   |
| `execute`            | `*`؛ يتحكم في إتاحة Code Mode، بينما تفرض الأدوات المتداخلة قواعدها الخاصة      |

مثلًا، اسمح بمهارة واحدة وارفض جميع المهارات الأخرى:

```jsonc
{
  "permissions": [
    { "action": "skill", "resource": "*", "effect": "deny" },
    { "action": "skill", "resource": "effect", "effect": "allow" },
  ],
}
```

ليس `doom_loop` و`lsp` من إجراءات الأذونات الحالية في V2 Core.

## الأدلة

يحتاج أي مسار يقع خارج الموقع النشط وخارج worktree المشروع غير الجذري معًا إلى موافقة `external_directory` قبل موافقة
`read` أو `edit` الخاصة به.

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "permissions": [
    { "action": "external_directory", "resource": "~/projects/reference/*", "effect": "allow" },
    { "action": "read", "resource": "~/projects/reference/*", "effect": "allow" },
    { "action": "edit", "resource": "~/projects/reference/*", "effect": "deny" },
  ],
}
```

ينطبق ذلك على المسارات الخارجية التي تستخدمها `read` و`edit` و`write` و`patch`. وتفحص أداة shell دليل العمل الخارجي
والأدلة التي يستنتجها المحلّل قبل فحص موارد `shell`.

في `external_directory` و`read` و`edit`، تُوسَّع البادئات `~` و`~/` و`$HOME` و`$HOME/` عند تحميل التهيئة:

```jsonc
{ "action": "read", "resource": "$HOME/reference/*", "effect": "allow" }
```

تبقى موارد shell نص أوامر خامًا، ولا يُوسَّع فيها مسار الدليل المنزلي.

<Callout type="warning">
  تعمل `shell` بصلاحيات مستخدم المضيف على نظام الملفات والعمليات والشبكة. واستنتاج الأدلة من نص الأمر غير مضمون، لذا فضّل
  قائمة سماح ضيقة لأوامر shell بدلًا من أنماط يُراد بها التعرّف على كل أمر خطير.
</Callout>

قد تخرج مسارات التعديل النسبية من الموقع النشط مع بقائها داخل worktree المشروع. وتُحوَّل المسارات الخارجية الصريحة إلى
صيغتها القانونية قبل المطابقة، لذا لا تأذن إلا بحدود أدلة موثوقة.

## المحلّل

فعّل محلّل shell المحمول التجريبي باستخدام:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "experimental": {
    "portable_shell_scanner": true,
  },
}
```

يحل المحلّل المحمول محل المحلّل الافتراضي المبني على tree-sitter؛ ولا يُستخدم tree-sitter بديلًا احتياطيًا ولا رأيًا ثانيًا.
وإذا تعذّر على المحلّل المحمول تحليل أمر ما، يُرجع خطأ من المحلّل، لا رفضًا للإذن.

لا يغيّر هذا الخيار إلا اختيار المحلّل. فقواعد الأذونات الحالية وأنماط الموافقات المحفوظة واستنتاج الأدلة غير المضمون تظل
سارية. ولا يوجد وضع موافقة إضافي ولا تقييد شامل للأدلة غير المعروفة.

## القيم الافتراضية

يبدأ كل وكيل، بما في ذلك الوكلاء المخصصون، بهذه السياسة الأساسية المرتبة:

```jsonc
[
  { "action": "*", "resource": "*", "effect": "allow" },
  { "action": "external_directory", "resource": "*", "effect": "ask" },
  { "action": "read", "resource": "*.env", "effect": "ask" },
  { "action": "read", "resource": "*.env.*", "effect": "ask" },
  { "action": "read", "resource": "*.env.example", "effect": "allow" },
]
```

يُلحق الوكلاء المضمّنون مع OpenCode السياسات التالية:

| الوكيل       | السياسة الإضافية                                                                 |
| ------------ | -------------------------------------------------------------------------------- |
| `build`      | يسمح بالأسئلة                                                                    |
| `plan`       | يسمح بالأسئلة؛ ويرفض التعديلات إلا على الملفات ضمن `~/.opencode/plan`             |
| `general`    | يرفض الأسئلة وتشغيل الوكلاء الفرعيين                                              |
| `explore`    | يرفض كل شيء عدا القراءة وglob وgrep وجلب صفحات الويب والبحث على الويب؛ ويطلب الموافقة للأدلة الخارجية ولقراءة ملفات `.env` |
| `title`      | يرفض جميع الإجراءات                                                              |
| `summary`    | يرفض جميع الإجراءات                                                              |
| `compaction` | يحتفظ بالسياسة الأساسية                                                          |

يسمح OpenCode أيضًا بالوصول الخارجي إلى أدلته المُدارة لمخرجات الأدوات ومخرجات shell والملفات المؤقتة والتهيئة العامة. ويظل
الإجراء الأساسي، مثل `read` أو `edit` أو غيرهما، خاضعًا لقواعده الخاصة. ويمكن للقواعد العامة وقواعد الوكيل اللاحقة تجاوز
هذه القيم الافتراضية.

## الوكلاء

ضع القواعد المشتركة في المستوى الأعلى، والقواعد الأضيق تحت `agents.<id>.permissions`:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "permissions": [
    { "action": "shell", "resource": "*", "effect": "ask" },
    { "action": "shell", "resource": "git status *", "effect": "allow" },
  ],
  "agents": {
    "reviewer": {
      "description": "Review code without changing it",
      "mode": "subagent",
      "permissions": [
        { "action": "edit", "resource": "*", "effect": "deny" },
      ],
    },
  },
}
```

تُلحق قواعد الوكيل بعد القواعد العامة، ولا تستبدل المصفوفة العامة. ويستخدم الوكيل الفرعي المخصص أذوناته الخاصة، لا مجموعة
فرعية من أذونات الوكيل الأب.

## الموافقات

عندما تؤول قاعدة إلى `ask`، يمكن للعملاء الرد بأحد الخيارات التالية:

| الخيار                         | الرد       | النتيجة                                                                  |
| ------------------------------ | ---------- | ------------------------------------------------------------------------ |
| Allow once (السماح مرة واحدة)  | `once`     | الموافقة على الطلب المعلّق فقط                                           |
| Allow always (السماح دائمًا)   | `always`   | الموافقة عليه وحفظ الأنماط التي تقترحها الأداة للمشروع                   |
| Reject (الرفض)                 | `reject`   | رفضه ورفض جميع طلبات الإذن المعلّقة الأخرى في تلك الجلسة                 |

مثلًا، قد يؤدي اختيار **Allow always** للأمر `git status --short` إلى حفظ بادئة shell تغطي أوامر `git status` اللاحقة:

```text
shell: git status * → allow
```

الموافقات المحفوظة قواعد `allow` دائمة على مستوى المشروع. ولا تتجاوز أبدًا قاعدة `deny` مهيّأة. وتختار الأدوات النمط المقترح
للحفظ: بعضها يقترح `*`، وتقترح shell بادئات الأوامر، وتقترح المهارات والوكلاء الفرعيون معرّفاتها. راجع الموافقات الواسعة
وأزل ما لم تعد بحاجة إليه.

يمكن للعملاء إرفاق ملاحظات عند الرفض. ويجب على العملاء غير التفاعليين أن يحددوا طريقة التعامل مع طلبات الموافقة؛ وتبقى قواعد
`deny` المهيّأة نافذة دائمًا.

## السياسات

يمكن أن ترفض [سياسةٌ](/policies) فحصَ الإذن رفضًا قاطعًا بعد تطبيق هذه القواعد والموافقات المحفوظة. فهي تحوّل `allow` أو
`ask` إلى `deny`، ولا تمنح الوصول أبدًا.

```jsonc
{
  "policies": [{ "action": "tool.use", "resource": "shell:sudo *", "effect": "deny" }],
}
```

تتجاوز السياسات العامة والسياسات التي تديرها Console تهيئة المشروع، وبهذه الطريقة تمنع المؤسسة أمرًا قد يسمح به المستودع.
