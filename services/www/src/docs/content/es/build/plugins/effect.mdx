---
title: "Effect"
---

`@opencode/plugin/effect` es la versión nativa de Effect de la API de plugins de OpenCode. Sus operaciones de
contexto devuelven Effects o Streams, los callbacks devuelven Effects y el ciclo de vida del plugin se representa con
`Scope`.

OpenCode proporciona `effect` (incluidas las subrutas exportadas `effect/*`) y `@opencode/plugin` en tiempo de
ejecución al cargar los plugins y sus dependencias de `node_modules`. Instálalos como dependencias peer o de desarrollo
para la comprobación de tipos y las pruebas locales, en lugar de empaquetarlos en tu plugin.

```sh
bun add --peer @opencode/plugin effect
```

Exporta un plugin de Effect desde `.opencode/plugins/` para que se cargue automáticamente.

```ts title=".opencode/plugins/concise/index.ts"
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "example",
  effect: (ctx) =>
    Effect.gen(function* () {
      const storage = ctx.storage
      yield* storage.set("loaded", true)
    }),
})
```

Los paquetes publicados y los directorios de plugins fuera de `.opencode/plugins/` usan la misma configuración
`plugins` que los demás plugins del servidor.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": [
    "opencode-acme-effect-plugin",
    "opencode-acme-effect-plugin@1.2.0",
    "@acme/opencode-effect-plugin",
    "./plugins/local-effect",
    {
      "package": "@acme/opencode-effect-plugin",
      "options": { "agent": "reviewer", "strict": true },
    },
  ],
}
```

Consulta [Configurar plugins](/plugins) para conocer la activación, la resolución de paquetes y la precedencia de
la configuración.

```ts title="plugins/local-effect/index.ts"
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "local-effect",
  effect: (ctx) =>
    Effect.gen(function* () {
      yield* Effect.logInfo("Effect plugin loaded", { version: ctx.app.version })
    }),
})
```

## Ciclo de vida

El `effect` se ejecuta cuando se carga el plugin. Su scope se cierra cuando el plugin se recarga o se descarga, de
modo que los registros, los fibers con ámbito y los finalizadores se liberan a la vez.

```ts
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "lifecycle",
  effect: (ctx) =>
    Effect.gen(function* () {
      yield* Effect.logInfo("loaded", { version: ctx.app.version })
      yield* Effect.addFinalizer(() => Effect.logInfo("unloaded"))
    }),
})
```

Usa fibers con ámbito para el trabajo en segundo plano. El scope del plugin interrumpe el fiber durante la limpieza.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const storage = ctx.storage
    yield* Effect.repeat(
      storage.set("heartbeat", { time: Date.now() }),
      { schedule: Schedule.spaced("1 minute") },
    ).pipe(Effect.forkScoped)
  }),
```

### Contexto

El contexto expone el cliente de Effect del servidor de OpenCode conectado, además de transformaciones, hooks,
almacenamiento, recargas y opciones exclusivos de los plugins. No expone los servicios privados de Core de
OpenCode.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const plugins = ctx.plugin
    const active = yield* plugins.list().pipe(Effect.orDie)
    yield* Effect.logInfo("active plugins", { count: active.data.length })
  }),
```

La definición del plugin y el contexto completo se declaran así.

```ts
interface Context {
  readonly app: App
  readonly location: Location.Info
  readonly options: PluginOptions
  readonly agent: AgentDomain
  readonly aisdk: AISDKDomain
  readonly command: CommandDomain
  readonly event: EventDomain
  readonly experimental: {
    readonly terminal: Pick<ExperimentalApi<unknown>["persistentPty"], "read">
  }
  readonly integration: IntegrationDomain
  readonly mcp: MCPDomain
  readonly model: ModelDomain
  readonly generate: GenerateApi<unknown>
  readonly permission: PermissionDomain
  readonly plugin: Pick<PluginApi<unknown>, "list">
  readonly provider: ProviderDomain
  readonly reference: ReferenceDomain
  readonly rpc: RpcDomain
  readonly session: SessionDomain
  readonly shell: ShellDomain
  readonly skill: SkillDomain
  readonly storage: StorageDomain
  readonly tool: ToolDomain
  readonly vcs: VcsDomain
  readonly websearch: WebSearchDomain
  readonly worktree: WorktreeDomain
}

interface Plugin<R = Scope.Scope> {
  readonly id: string
  readonly effect: (context: Context) => Effect.Effect<void, never, R>
}
```

### Opciones

Pasa las opciones con la forma de objeto en `opencode.json(c)`.

```jsonc title="opencode.jsonc"
{
  "plugins": [
    {
      "package": "./plugins/company-effect",
      "options": { "strict": true },
    },
  ],
}
```

Lee las opciones desde `ctx.options`. Acota los valores desconocidos antes de usarlos.

```ts title="plugins/company-effect/index.ts"
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "company",
  effect: (ctx) =>
    Effect.gen(function* () {
      const strict = ctx.options.strict === true
      yield* Effect.logInfo("company plugin configured", { strict })
    }),
})
```

## Transformaciones

Las transformaciones editan el estado de forma síncrona mediante un editor. OpenCode aplica las transformaciones en
orden de registro dentro de cada dominio. Primero, las fuentes aportan proveedores y definiciones inmutables de modelos;
después, las transformaciones de modelos editan los candidatos de los proveedores activos. Hacer `yield` del registro lo
mantiene en el scope del plugin.

```ts title="plugins/models-effect/index.ts"
import { Model, Plugin, Provider } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "company.models",
  effect: (ctx) =>
    Effect.gen(function* () {
      const providerID = Provider.ID.make("acme")
      const models = [{ ...Model.Info.default(providerID, Model.ID.make("reasoner")), name: "Acme Reasoner" }]
      yield* ctx.provider.transform((editor) => {
        editor.add({
          info: {
            ...Provider.Info.empty(providerID),
            name: "Acme",
            activation: "enabled",
            package: "@opencode/ai/providers/openai-compatible",
            settings: { baseURL: "http://127.0.0.1:8000/v1" },
          },
          models,
        })
      })
    }),
})
```

Una transformación de modelos puede aplicar una política sobre toda la colección de candidatos de los proveedores
activos.

```ts title="plugins/model-budget-effect/index.ts"
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.model.transform((editor) => {
      editor
        .list()
        .filter((model) => model.cost.some((tier) => tier.output > 20))
        .forEach((model) => {
          editor.remove(model.providerID, model.id)
        })
    })
  }),
```

Llama a `reload` cuando cambie el estado externo que usa una transformación. Aquí, `loadFromSource()` devuelve
entradas `{ info: Provider.Info, models: readonly Model.Info[] }`; las recargas de proveedores también invalidan todo el
resultado de modelos.

```ts title="plugins/models-effect/index.ts"
effect: (ctx) =>
  Effect.gen(function* () {
    const provider = ctx.provider
    const source = { providers: yield* loadFromSource() }

    yield* provider.transform((editor) => {
      source.providers.forEach((provider) => editor.add(provider))
    })

    yield* Effect.repeat(
      Effect.gen(function* () {
        source.providers = yield* loadFromSource()
        yield* provider.reload()
      }),
      { schedule: Schedule.spaced("1 minute") },
    ).pipe(Effect.forkScoped)
  }),
```

## API

### Agentes

Lee todos los agentes u obtén uno por su ID. Las respuestas del cliente incluyen la ubicación resuelta y los datos del
esquema.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const agent = ctx.agent
    const agents = yield* agent.list().pipe(Effect.orDie)
    const build = yield* agent.get({ agentID: Agent.ID.make("build") }).pipe(Effect.orDie)
    yield* Effect.logInfo("agents", { count: agents.data.length, build: build.data.name })
  }),
```

Transforma o recarga agentes.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const agent = ctx.agent
    yield* agent.transform((editor) => {
      editor.default("build")
      editor.update("build", (item) => (item.description = "Builds features and fixes bugs"))
      editor.remove("legacy")
    })
    yield* agent.reload()
  }),
```

Esquema: [`Agent.Info`](/api#schema-Agent.Info).

```ts
interface AgentEditor {
  list(): readonly Types.DeepMutable<Agent.Info>[]
  get(id: string): Types.DeepMutable<Agent.Info> | undefined
  default(id: string | undefined): void
  update(id: string, update: (agent: Types.DeepMutable<Agent.Info>) => void): void
  remove(id: string): void
}

interface AgentDomain extends AgentApi<unknown> {
  readonly transform: Transform<AgentEditor>
  readonly reload: () => Effect.Effect<void>
}
```

### Proveedores

Lee los proveedores disponibles o consulta los metadatos de un proveedor por su ID.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const provider = ctx.provider
    const providers = yield* provider.list().pipe(Effect.orDie)
    const anthropic = yield* provider.get({ providerID: Provider.ID.make("anthropic") }).pipe(Effect.orDie)
    yield* Effect.logInfo("providers", {
      providers: providers.data.length,
      anthropic: anthropic.data.name,
    })
  }),
```

Las transformaciones de proveedores editan los ajustes de los proveedores y las definiciones de las fuentes. Las
lecturas del editor incluyen los proveedores inactivos y exponen definiciones inmutables; `models.update` edita una copia
propia de un modelo de la fuente.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.provider.transform((editor) => {
      editor.update("anthropic", (provider) => {
        provider.headers = { ...provider.headers, "x-company": "engineering" }
      })
      editor.models.update("anthropic", "claude-sonnet-4-5", (model) => (model.name = "Team Sonnet"))
      editor.models.remove("anthropic", "legacy-model")
      editor.remove("legacy-provider")
    })
  }),
```

Reemplaza el inventario de una fuente con `models.set` y recarga después de que cambien las definiciones capturadas.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const provider = ctx.provider
    const source = { models: yield* loadModels() }
    yield* provider.transform((editor) => editor.models.set("acme", source.models))
    source.models = yield* loadModels()
    yield* provider.reload()
  }),
```

Para el descubrimiento específico de una cuenta, pasa como `sourceConnection` la conexión usada para cargar el
inventario. OpenCode excluye ese proveedor mientras haya otra conexión seleccionada, hasta que tu plugin publique su
inventario actualizado.

```ts
const connection = yield * ctx.integration.connection.active("acme")
if (!connection) return
const inventory = yield * loadInventory(connection)
yield *
  ctx.provider.transform((editor) => {
    editor.add({ info: inventory.provider, models: inventory.models, sourceConnection: connection })
  })
```

Esquemas: [`Provider.Info`](/api#schema-Provider.Info), [`Model.Info`](/api#schema-Model.Info).

```ts
interface ProviderRecord {
  readonly provider: Provider.Info
  readonly models: ReadonlyMap<string, Model.Info>
  readonly sourceConnection?: ConnectionInfo
}

interface ProviderEditor {
  list(): readonly ProviderRecord[]
  get(providerID: string): ProviderRecord | undefined
  add(input: { info: Provider.Info; models: readonly Model.Info[]; sourceConnection?: ConnectionInfo }): void
  update(providerID: string, update: (provider: Types.DeepMutable<Provider.Info>) => void): void
  remove(providerID: string): void
  readonly models: {
    set(providerID: string, models: readonly Model.Info[]): void
    update(providerID: string, modelID: string, update: (model: Types.DeepMutable<Model.Info>) => void): void
    remove(providerID: string, modelID: string): void
  }
}

interface ProviderDomain extends ProviderApi<unknown> {
  readonly transform: Transform<ProviderEditor>
  readonly reload: () => Effect.Effect<void>
}
```

### Modelos

Lee los modelos disponibles y la selección predeterminada.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const model = ctx.model
    const models = yield* model.list().pipe(Effect.orDie)
    const selected = yield* model.default().pipe(Effect.orDie)
    yield* Effect.logInfo("models", { count: models.data.length, selected: selected.data?.name })
  }),
```

Las transformaciones de modelos editan toda la colección de candidatos de los proveedores activos. Los candidatos
desactivados siguen siendo editables hasta que terminan todas las transformaciones; `update` solo puede añadir un modelo
bajo un proveedor disponible.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.model.transform((editor) => {
      editor.list("anthropic").forEach((model) => {
        editor.update(model.providerID, model.id, (draft) => {
          draft.enabled = draft.capabilities.tools
        })
      })
      editor.default.set("anthropic", "claude-sonnet-4-5")
      editor.remove("anthropic", "legacy-model")
    })
  }),
```

Los callbacks editan las sobrescrituras sin procesar de los modelos. Los valores predeterminados del proveedor se
combinan una sola vez cuando OpenCode confirma el resultado; las lecturas sin cambios reutilizan ese resultado.
`editor.provider` lee las definiciones inmutables de las fuentes, incluidas las plantillas inactivas, y no la salida de
las transformaciones de modelos.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const model = ctx.model
    yield* model.transform((editor) => {
      const source = editor.provider.get("anthropic")?.models.get("claude-sonnet-4-5")
      if (!source) return
      editor.update("anthropic", source.id, (draft) => {
        draft.limit.context = Math.min(draft.limit.context, source.limit.context)
      })
    })
    yield* model.reload()
  }),
```

Esquema: [`Model.Info`](/api#schema-Model.Info).

```ts
interface ModelEditor {
  list(providerID?: string): readonly Types.DeepMutable<Model.Info>[]
  get(providerID: string, modelID: string): Types.DeepMutable<Model.Info> | undefined
  update(providerID: string, modelID: string, update: (model: Types.DeepMutable<Model.Info>) => void): void
  remove(providerID: string, modelID: string): void
  readonly default: {
    get(): { providerID: string; modelID: string } | undefined
    set(providerID: string, modelID: string): void
  }
  readonly provider: {
    list(): readonly ProviderRecord[]

  }

  readonly transform: Transform<ModelEditor>

}
```

### Comandos

Lee los comandos disponibles en la ubicación actual.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const command = ctx.command
    const commands = yield* command.list().pipe(Effect.orDie)
    yield* Effect.logInfo("commands", { names: commands.data.map((item) => item.name) })
  }),
```

Por ahora, la transformación de comandos solo permite añadir. Un ejecutor recibe la sesión, los adjuntos del prompt y
el modo de entrega.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const command = ctx.command
    const session = ctx.session
    yield* command.transform((editor) => {
      editor.add({
        name: "security-review",
        description: "Review changes for security issues",
        execute: (input) =>
          session.prompt({
            ...input.prompt,
            sessionID: input.sessionID,
            text: `Review these changes for security issues.\n\n${input.prompt.text}`,
            delivery: input.delivery,
          }).pipe(Effect.asVoid),
      })
    })
    yield* command.reload()
  }),
```

Esquemas: [`Command.Info`](/api#schema-Command.Info),
[`Session.Inbox.Delivery`](/api#schema-Session.Inbox.Delivery).

```ts

```

### Integraciones

Lee las integraciones y resuelve la credencial activa, si existe.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const integration = ctx.integration
    const integrations = yield* integration.list().pipe(Effect.orDie)
    const github = yield* integration.get({ integrationID: Integration.ID.make("github") }).pipe(Effect.orDie)
    const connection = yield* integration.connection.active("github")
    const credential = connection ? yield* integration.connection.resolve(connection).pipe(Effect.orDie) : undefined
    yield* Effect.logInfo("integration", {
      count: integrations.data.length,
      github: github.data.name,
      credential: credential?.type,
    })
  }),
```

Conéctate con una clave o gestiona un intento de OAuth a través de la API conectada.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const integration = ctx.integration
    const token = yield* Config.Redacted("GITHUB_TOKEN").pipe(Effect.orDie)
    yield* integration.connect
      .key({ integrationID: Integration.ID.make("github"), key: Redacted.value(token) })
      .pipe(Effect.orDie)

    const attempt = yield* integration.oauth
      .connect({
        integrationID: Integration.ID.make("acme"),
        methodID: Integration.MethodID.make("oauth"),
      })
      .pipe(Effect.orDie)
    const status = yield* integration.oauth
      .status({
        integrationID: Integration.ID.make("acme"),
        attemptID: attempt.data.attemptID,
      })
      .pipe(Effect.orDie)
    yield* Effect.logInfo("OAuth status", { status: status.data })
  }),
```

Transforma las integraciones y los métodos de autenticación. Los callbacks de los métodos OAuth son Effects y
pueden adquirir recursos con ámbito.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const integration = ctx.integration
    yield* integration.transform((editor) => {
      editor.update("acme", (item) => (item.name = "Acme"))
      editor.method.update({
        integrationID: "acme",
        method: { id: "device", type: "oauth", label: "Sign in with Acme" },
        authorize: () =>
          Effect.succeed({
            mode: "code",
            url: "https://acme.example/device",
            instructions: "Enter the displayed code",
            callback: (code) => exchangeCode(code),
          }),
      })
    })
    yield* integration.reload()
  }),
```

Esquemas: [`Integration.Info`](/api#schema-Integration.Info), [`Integration.Method`](/api#schema-Integration.Method),
[`Connection.Info`](/api#schema-Connection.Info), [`Form.Answer`](/api#schema-Form.Answer).

```ts

  readonly transform: Transform<IntegrationEditor>

```

### MCP

Lista los servidores MCP y su estado de conexión actual.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const mcp = ctx.mcp
    const servers = yield* mcp.list().pipe(Effect.orDie)
    yield* Effect.logInfo("MCP servers", { count: servers.data.length })
  }),
```

Los plugins gestionan los servidores MCP únicamente mediante transformaciones. Usa `editor.set` para añadir o
reemplazar un servidor, `editor.update` para cambiar su configuración y `editor.remove` para eliminarlo. Consulta la
configuración con `editor.list` y `editor.get`.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const mcp = ctx.mcp
    yield* mcp.transform((editor) => {
      const servers = editor.list()
      const docs = editor.get("docs")
      editor.set("docs", { type: "remote", url: "https://mcp.example.com" })
      editor.update("docs", (server) => (server.disabled = false))
      editor.remove("legacy")
    })
  }),
```

Establece `disabled: true` en una transformación para desactivar un servidor y desconectarlo, o `disabled: false`
para activarlo y permitir que OpenCode se conecte. OpenCode concilia el ciclo de vida de los servidores a partir de la
configuración transformada.

Llama a `reload()` cuando cambie el estado externo que usa una transformación para volver a aplicar las
transformaciones y conciliar los servidores.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const mcp = ctx.mcp
    yield* mcp.reload()
  }),
```

Esquemas: [`Mcp.Server`](/api#schema-Mcp.Server), [`Mcp.LocalConfigEncoded`](/api#schema-Mcp.LocalConfigEncoded),
[`Mcp.RemoteConfigEncoded`](/api#schema-Mcp.RemoteConfigEncoded).

```ts

  update(name: string, update: (config: Types.DeepMutable<Mcp.ServerConfig>) => void): void
  remove(name: string): void
}

interface MCPDomain extends Pick<McpApi<unknown>, "list"> {
  readonly transform: Transform<MCPEditor>

```

### Plugins

Lista los plugins activos, fallidos y resueltos en la ubicación actual.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const plugin = ctx.plugin
    const plugins = yield* plugin.list().pipe(Effect.orDie)
    yield* Effect.forEach(plugins.data, (item) => Effect.logInfo("plugin", item), { discard: true })
  }),
```

Filtra los valores del esquema en un pipeline de Effect cuando solo importan los plugins activos.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const plugin = ctx.plugin
    const active = yield* plugin.list().pipe(
      Effect.orDie,
      Effect.map((result) => result.data.filter((item) => item.status === "active")),
    )
    yield* Effect.logInfo("active plugin count", { count: active.length })
  }),
```

Esquemas: [`Plugin.Info`](/api#schema-Plugin.Info), [`Plugin.Source`](/api#schema-Plugin.Source).

### Referencias

Lee las referencias disponibles en la ubicación actual.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const reference = ctx.reference
    const references = yield* reference.list().pipe(Effect.orDie)
    yield* Effect.logInfo("references", { count: references.data.length })
  }),
```

Añade o elimina referencias locales y de Git, y recarga después de que cambie el estado externo. `get(name)` devuelve
la fuente configurada actual, o `undefined` si el nombre no existe.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const reference = ctx.reference
    yield* reference.transform((editor) => {
      editor.add("handbook", { type: "local", path: "/workspace/docs/handbook" })
      editor.add("standards", { type: "git", repository: "https://github.com/acme/standards", branch: "main" })
      const handbook = editor.get("handbook")
      editor.remove("legacy")
    })
    yield* reference.reload()
  }),
```

Esquemas: [`Reference.Info`](/api#schema-Reference.Info), [`Reference.LocalSource`](/api#schema-Reference.LocalSource),
[`Reference.GitSource`](/api#schema-Reference.GitSource).

```ts
interface ReferenceEditor {
```

### Herramientas

Registra herramientas tipadas con `Schema` de Effect. El ejecutor recibe la entrada decodificada y devuelve un
Effect que contiene salida tipada, contenido para mostrar o metadatos.

El editor admite `add`, `update` y `remove`. El callback de la transformación es síncrono: no debe devolver un
Effect ni una Promise. Carga los datos externos antes de registrar o recargar. OpenCode vuelve a aplicar las
transformaciones activas en orden de registro sobre un editor nuevo; para un mismo nombre efectivo de herramienta, un
registro válido posterior sobrescribe a uno anterior.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const tool = ctx.tool
    yield* tool.transform((editor) => {
      editor.namespace({
        name: "acme",
        description: "Customer account tools",
      })
      editor.add({
        name: "greeting",
        description: "Create a greeting",
        input: Schema.Struct({ name: Schema.String }),
        output: Schema.Struct({ greeting: Schema.String }),
        options: { namespace: "acme", codemode: true },
        execute: ({ name }, context) =>
          Effect.gen(function* () {
            yield* context.progress({ status: "greeting" })
            return { output: { greeting: `Hello ${name}!` } }
          }),
      })
    })
  }),
```

Llama a `yield* ctx.tool.reload()` después de cambiar los datos de origen que captura el callback. La recarga
vuelve a aplicar las transformaciones activas sin cambiar su orden; no vuelve a ejecutar el effect del plugin.

Las herramientas tienen un `id` que contiene su nombre efectivo, y `get()` devuelve `undefined` si ese ID no
existe. Usa `update` y `remove` con el nombre efectivo de la herramienta, incluido su espacio de nombres
(`acme_greeting` en el ejemplo anterior). Los puntos en los espacios de nombres y los caracteres no admitidos en los
nombres de herramientas se convierten en `_`. Los nombres inexistentes se ignoran; para crear una herramienta hace falta
`add` con una definición completa. Las actualizaciones conservan el nombre y el espacio de nombres. Para reemplazar
esquemas u opciones, asigna valores nuevos en lugar de mutar los valores anidados. Las actualizaciones no válidas se
registran en el log y dejan intacta la definición anterior.

```ts
yield *
  ctx.tool.transform((editor) => {
    editor.update("acme_greeting", (tool) => {
      tool.description = "Greet the user by name"
    })
    editor.remove("acme_obsolete")
  })
```

Las actualizaciones y eliminaciones se vuelven a aplicar en orden junto con las adiciones, también después de
actualizar el catálogo de MCP.

`transform` devuelve un registro con ámbito. Ejecuta `yield* registration.dispose` para eliminar su
transformación y reconstruir a partir de las transformaciones restantes, lo que vuelve a mostrar cualquier definición
anterior que hubiera sobrescrito. La liberación es idempotente, y cerrar el scope del plugin también libera sus registros.

Cada solicitud al modelo captura una instantánea de las herramientas. La recarga y la liberación afectan a las
instantáneas futuras, no a las definiciones ni a los ejecutores ya capturados por una solicitud existente. Los ejecutores
que capturan datos mutables del plugin siguen viendo esos datos; captura un valor dentro de la transformación cuando deba
seguir ligado a esa definición.

Esquemas: [`Tool.Content`](/api#schema-Tool.Content), [`Tool.TextContent`](/api#schema-Tool.TextContent),
[`Tool.FileContent`](/api#schema-Tool.FileContent).

## Hooks

Los hooks interceptan operaciones en curso. Varios plugins pueden registrar el mismo hook; OpenCode los ejecuta en
orden de plugins, de modo que los hooks posteriores ven los cambios de los anteriores. Los registros permanecen activos
mientras dure el scope del plugin.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook("context", () => Effect.void)
  }),
```

### Sesiones

Modifica las instrucciones del sistema ensambladas, los mensajes o las herramientas justo antes de enviarlos al
modelo. `context` se ejecuta para el bucle del agente; `compaction`, `generate` y `title` se ejecutan para esas
solicitudes auxiliares. `compaction` y `title` aceptan un `result` que omite la llamada al modelo.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook("context", (event) =>
      Effect.sync(() => {
        event.system.push({ type: "text", text: "Keep the review focused on correctness." })
        delete event.tools.write
      }),
    )
    yield* session.hook("compaction", (event) =>
      Effect.map(summarize(event.messages), (summary) => {
        event.result = { summary }
      }),
    )
  }),
```

Modifica los ajustes de la solicitud al modelo y, opcionalmente, limita el hook a un proveedor. El evento lleva el
mismo `kind` que los hooks HTTP que se describen a continuación.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook(
      "model.request",
      (event) => Effect.sync(() => (event.headers["x-plugin"] = "review")),
      { providerID: "anthropic" },
    )
  }),
```

Modifica las solicitudes o respuestas nativas del proveedor. Sus cuerpos son streams de un solo uso; clona o
reemplaza un cuerpo antes de leerlo. Ambos hooks se ejecutan en cada solicitud que emite una sesión; `event.kind` es
`"primary"`, `"compaction"`, `"title"` o `"generate"`, según el flujo que la haya emitido.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook("http.request", (event) =>
      Effect.sync(() => {
        event.request.headers.set("x-session-id", event.sessionID)
        if (event.kind === "title") event.request.headers.set("x-priority", "background")
      }),
    )
    yield* session.hook("http.response", (event) =>
      Effect.sync(() => {
        event.response = new Response(event.response.body, {
          status: event.response.status,
          headers: { ...Object.fromEntries(event.response.headers), "x-plugin": "review" },
        })
      }),
    )
  }),
```

Los proveedores que hacen streaming por WebSocket reutilizan una conexión por sesión, por lo que los hooks HTTP nunca
ven ese tráfico. El hook experimental `experimental.ws.handshake` se ejecuta una vez por llamada al modelo, antes de
seleccionar la conexión, y expone la `url` y los `headers` de la conexión; cambiar cualquiera de los dos vuelve a abrir
el socket. Los hooks HTTP siguen ejecutándose para cualquier solicitud en la que una ruta WebSocket recurra a HTTP.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.session.hook(
      "experimental.ws.handshake",
      (event) =>
        Effect.gen(function* () {
          event.headers.authorization = `Bearer ${yield* mintToken(event.url)}`
          delete event.headers["api-key"]
        }),
      { providerID: "azure" },
    )
  }),
```

`experimental.ws.send` y `experimental.ws.receive` exponen los propios frames: `send` se ejecuta después de que
el driver del proveedor construya un frame de salida, y `receive` se ejecuta en cada frame de entrada antes de que el
driver lo procese. Lo que contenga `frame` cuando el hook termina es lo que se envía por la red o llega al driver;
OpenCode no lo valida.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.session.hook(
      "experimental.ws.send",
      (event) =>
        Effect.sync(() => {
          const body = JSON.parse(event.frame)
          if (body.type === "response.create") body.metadata = { ...body.metadata, session: event.sessionID }
          event.frame = JSON.stringify(body)
        }),
      { providerID: "openai" },
    )
  }),
```

Sobrescribe la decisión de reintento ante un fallo del proveedor o reemplaza su retraso en milisegundos. El hook se
ejecuta después de que OpenCode clasifique el fallo y proponga su política, pero antes de programar cualquier reintento.
No expone cómo realiza OpenCode internamente el siguiente intento.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.session.hook("retry", (event) =>
      Effect.sync(() => {
        if (event.error.status === 429) {
          event.decision = { retry: true, delay: 10_000 }
          return
        }
        if (event.error.type === "provider.invalid-request" && event.attempt === 2) {
          event.decision = { retry: true, delay: 0 }
          return
        }
        if (event.attempt >= 3) event.decision = { retry: false }
      }),
    )
  }),
```

La `decision` inicial es la política de OpenCode, así que los hooks pueden hacer reintentable un fallo del proveedor
que normalmente sería definitivo o vetar un reintento propuesto. Si hay varios hooks, se ejecutan en orden de registro y
los posteriores ven la decisión actual. El número máximo de intentos integrado sigue siendo un límite estricto.
`attempt` es el intento físico que se propone; la solicitud inicial es el intento `1`, así que el primer reintento es el
intento `2`. Los retrasos no válidos (`NaN`, infinito o valores negativos) recurren al retraso calculado. La
recuperación por desbordamiento del contexto es independiente, porque compacta la conversación en lugar de reintentar la
misma solicitud.

```ts
}
```

Los tipos de registro compartidos muestran qué operaciones requieren el scope del plugin.

```ts
interface Registration {
  readonly dispose: Effect.Effect<void>
}

type Hooks<Spec, Failures extends Record<keyof Spec, unknown> = Record<keyof Spec, never>> = <Name extends keyof Spec>(
  name: Name,
  callback: (input: Spec[Name]) => Effect.Effect<void, Failures[Name]>,
) => Effect.Effect<Registration, never, Scope.Scope>

type Transform<Input> = (callback: (input: Input) => void) => Effect.Effect<Registration, never, Scope.Scope>
```

## Publicar

Un plugin empaquetado usa la misma exportación predeterminada que un plugin local de Effect. Exporta la
implementación de Effect desde el punto de entrada principal y declara `effect` como `peerDependency`.

```json title="package.json"
{
  "name": "opencode-acme-effect-plugin",
  "version": "1.0.0",
  "type": "module",
  "exports": {
    ".": "./src/index.ts"
  },
  "dependencies": {
    "@opencode/plugin": "latest"
  },
  "peerDependencies": {
    "effect": "^4.0.0"
  }
}
```

OpenCode redirige las importaciones de `effect`, de las subrutas exportadas `effect/*` y de `@opencode/plugin`
(incluidas las importaciones desde dependencias en el `node_modules` del plugin) a las instancias del entorno de
ejecución del host, para que los fibers, los loggers y los analizadores de `Schema` compartan una única copia del
runtime.

- No empaquetes `effect` en el artefacto publicado del plugin. Si usas un bundler, marca `effect` y `effect/*`
  como externos.
- Los plugins y sus dependencias de `node_modules` siempre se ejecutan con la instancia de `effect` de la versión de
  OpenCode del host. Usa API y rutas de módulo de `effect` compatibles con la versión de OpenCode a la que te diriges;
  las dependencias compiladas sobre otra versión mayor de `effect` (como Effect 3) también reciben el `effect` del host
  y no son compatibles.
- Solo se proporcionan las subrutas públicas de `effect`. Un plugin que importe uno de los módulos privados `internal`
  de Effect no se carga y muestra un error con la ruta.
- El binario compilado de OpenCode no incluye los recursos de Scalar y Swagger UI que usan las páginas de documentación
  de la API HTTP de Effect; si un plugin sirve esas páginas, se muestra un aviso en su lugar.

El punto de entrada del paquete exporta `Plugin.define` con una función `effect`.

```ts title="src/index.ts"
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "acme.published",
  effect: (ctx) =>
    Effect.gen(function* () {
      const storage = ctx.storage
      yield* storage.set("installed", true)
    }),
})
```

Usa versiones compatibles con la versión de OpenCode a la que te diriges y prueba el paquete instalado, no solo una
copia enlazada desde el workspace.

```sh
bun pm pack
bun add ./opencode-acme-effect-plugin-1.0.0.tgz
```
