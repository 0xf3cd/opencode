---
title: "Plugins"
---

La CLI carga automáticamente los plugins configurados en `opencode.json(c)` que exponen un componente de TUI. Para
aprender a crear plugins, consulta [Crear plugins](/build/plugins). No hace falta añadir el mismo paquete a `cli.json`. La
CLI obtiene la lista de plugins activos del servidor de OpenCode al que está conectada, así que esto también funciona
cuando el servidor es remoto.

Usa `cli.json` para los plugins exclusivos de la CLI. Estos plugins se ejecutan localmente en la terminal y siguen
activos cuando la CLI se conecta a un servidor remoto:

```json title="cli.json"
{
  "plugins": [
    "opencode.example",
    "opencode.example@1.0.0",
    "@example/opencode-tui",
    "@example/opencode-tui@1.0.0",
    "./plugins/status",
    "../plugins/status",
    "/home/user/plugins/status",
    "file:///home/user/plugins/status"
  ]
}
```

Las entradas se procesan en orden. Antepón `-` a un ID o a un comodín para desactivar los plugins que coincidan:

```json title="cli.json"
{
  "plugins": ["*", "-opencode.notifications", "-team.*"]
}
```

Pasa opciones a un plugin con la forma de objeto:

```json title="cli.json"
{
  "plugins": [
    {
      "package": "@example/opencode-tui",
      "options": {
        "compact": true
      }
    }
  ]
}
```

OpenCode también detecta plugins en el directorio de configuración global y en los directorios `.opencode` de los
proyectos. Cada plugin usa la misma estructura que un paquete publicado, con los puntos de entrada del servidor y de la
TUI juntos.

```text title="Plugin discovery paths"
<global-config>/plugins/status/index.ts
<global-config>/plugins/status/tui.ts
<project>/.opencode/plugins/status/index.ts
<project>/.opencode/plugins/status/tui.ts
```

Los plugins detectados pueden importar `@opencode/plugin/tui` directamente; OpenCode resuelve el paquete en tiempo de
ejecución. Consulta [Crear plugins para la CLI](/build/plugins/cli) para ver ejemplos.
