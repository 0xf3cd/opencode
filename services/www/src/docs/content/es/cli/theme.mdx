title: "Tema"
---

OpenCode incluye muchos temas integrados para los modos claro y oscuro. Elige uno en los ajustes o combina tus propios colores.

## Elegir un tema

Pulsa `Ctrl+P`, selecciona **Open settings** y abre **Theme**. El tema predeterminado es `opencode`.

También puedes definirlo en tus [ajustes globales de la CLI](/cli/config):

```json title="~/.config/opencode/cli.json"
{
  "$schema": "https://opencode.ai/v2/cli.json",
  "theme": {
    "name": "tokyonight",
    "mode": "dark"
  }
}
```

Ejecuta `/themes` para cambiar de tema sin abrir los ajustes.

## Colores del sistema

Cuando OpenCode puede leer la paleta de tu terminal, el selector de temas incluye el tema `system`. Este tema deriva sus colores del color de primer plano, el fondo y la paleta ANSI de tu terminal.

El nombre de tema `system` selecciona los colores derivados de la terminal. El modo `system` sigue la apariencia clara u oscura de la terminal.

## Modo

Usa `system` para seguir la apariencia de tu terminal o fija el tema en modo claro u oscuro:

| Modo | Comportamiento |
| --- | --- |
| `system` | Sigue la apariencia clara u oscura detectada en la terminal. |
| `dark` | Usa siempre los colores oscuros del tema. |
| `light` | Usa siempre los colores claros del tema. |

Corresponde al campo `mode` dentro de `theme` en tu configuración de la CLI. Si un tema personalizado solo ofrece un modo, OpenCode usa ese modo aunque se pida el otro.

## Añadir un tema

Para añadir un tema que hayas descargado o que te haya pasado otra persona, copia su archivo JSON en el directorio global de temas:

```bash
cp theme.json ~/.config/opencode/themes/
```

También puedes colocar el tema en el directorio `.opencode/themes` de un proyecto para que solo esté disponible en ese proyecto.

El nombre del archivo pasa a ser el nombre del tema. Por ejemplo, `my-theme.json` aparece como `my-theme`. Reinicia OpenCode después de añadir el archivo y ejecuta `/themes` para seleccionarlo.

OpenCode solo lee archivos `.json`. Un tema más cercano al directorio actual reemplaza a un tema global o de un directorio superior con el mismo nombre.

## Usar temas en plugins

Los [plugins de la CLI](/build/plugins/cli) leen los colores resueltos mediante `context.theme` y el modo activo mediante `context.themeMode`. Usa tokens semánticos para que tu plugin siga el tema seleccionado:

```tsx title="Inside a CLI plugin component"
import { usePlugin } from "@opencode/plugin/tui"

function Status() {
  const context = usePlugin()
  return <text fg={context.theme.text.base}>Ready</text>
}
```

La API pública de plugins de la CLI no registra temas. Añade las definiciones de temas personalizados como archivos JSON en los directorios anteriores.

## Crear un tema

Usa nuestra [herramienta de temas](https://opencode.ai/theme/) para crear o editar temas. Con ella es fácil entender la estructura, modificarla y definir colores personalizados. La explicación siguiente sirve como referencia.

Un tema separa los tokens semánticos compartidos de las paletas específicas de cada modo:

| Sección | Propósito |
| --- | --- |
| `base` | El árbol completo de tokens compartido por todos los modos. |
| `light`, `dark` | Una paleta completa de tonos y sobrescrituras opcionales de tokens para ese modo. |

Todo tema proporciona un `base` completo y define al menos uno de los modos `light` o `dark`. Los modos heredan del `base` del archivo; no heredan del tema integrado de OpenCode ni entre sí.

Los ejemplos siguientes muestran solo las secciones relevantes para cada concepto. Usa el editor de temas para generar un archivo completo antes de personalizarlo.

### Estructura

Coloca en `base` los colores que usan ambos modos y sobrescríbelos dentro de `light` o `dark` cuando haga falta:

```json title="theme.json (excerpt)"
{
  "$schema": "https://opencode.ai/theme.json",
  "base": {
    "text": {
      "base": "$hue.neutral.200",
      "muted": "$hue.neutral.400"
    }
  },
  "light": {
    "hue": {}
  },
  "dark": {
    "hue": {},
    "text": {
      "muted": "$hue.neutral.300"
    }
  }
}
```

El `base` completo proporciona todos los tokens semánticos. Cada modo proporciona todos los tonos obligatorios y puede sobrescribir cualquier parte del árbol de tokens de `base`.

### Colores y referencias

Un color puede ser un valor hexadecimal, `"transparent"` o una referencia a otro color del tema:

```json title="Inside base or a mode"
{
  "text": {
    "base": "#eeeeee",
    "muted": "$hue.neutral.400"
  },
  "border": {
    "base": "$text.muted"
  }
}
```

### Tonos

Los tonos (hues) son escalas de color de nueve pasos. Cada modo define los ocho tonos base y tres alias:

| Tipo | Valores |
| --- | --- |
| Base | `gray`, `red`, `orange`, `yellow`, `green`, `cyan`, `blue`, `purple` |
| Alias | `accent`, `interactive`, `neutral` |
| Paso | `100`, `200`, `300`, `400`, `500`, `600`, `700`, `800`, `900` |

Define los nueve pasos de un tono base o haz que un tono sea alias de otro:

```json title="Inside light or dark"
{
  "hue": {
    "purple": {
      "100": "#b38ff4",
      "200": "#9d7cd8",
      "300": "#8869bd",
      "400": "#7357a2",
      "500": "#5f4688",
      "600": "#4b356f",
      "700": "#392557",
      "800": "#271640",
      "900": "#17072b"
    },
    "accent": "$hue.purple"
  }
}
```

Los pasos de cada tono siguen la dirección de contraste del modo. Los temas claros van de oscuro en `100` a claro en `900`; los temas oscuros van de claro en `100` a oscuro en `900`.

El array `categorical` de `base` define los tonos, en orden, que se usan para distinguir agentes y otros elementos repetidos:

```json title="Inside base"
{
  "categorical": ["accent", "purple", "green", "blue"]
}
```

### Tokens semánticos

Los tokens semánticos asignan colores a funciones de la interfaz. Los componentes usan estas funciones en lugar de elegir colores directamente.

| Grupo | Propósito |
| --- | --- |
| `text` | Texto base, atenuado, de acciones, de campos de formulario, de estado y de feedback. |
| `background` | Fondo base, superficies elevadas, acciones, campos de formulario y rellenos de feedback. |
| `border`, `scrollbar` | Colores de bordes y barras de desplazamiento. |
| `diff` | Colores de líneas añadidas, eliminadas, de contexto, resaltados y números de línea. |
| `syntax` | Resaltado de código fuente. |
| `markdown` | Elementos de Markdown. |

Por ejemplo, `text.muted` controla el texto secundario, mientras que `background.raised` define superficies con una elevación progresiva:

```json title="Inside base"
{
  "text": {
    "base": "$hue.neutral.200",
    "muted": "$hue.neutral.400"
  },
  "background": {
    "base": "$hue.neutral.800",
    "raised": {
      "base": "$hue.neutral.700",
      "high": "$hue.neutral.600",
      "max": "$hue.neutral.500"
    }
  }
}
```

Las claves de sintaxis son `comment`, `keyword`, `function`, `variable`, `string`, `number`, `type`, `operator` y `punctuation`.

Las claves de Markdown son `text`, `heading`, `link`, `linkText`, `code`, `blockQuote`, `emphasis`, `strong`, `horizontalRule`, `listItem`, `listEnumeration`, `image`, `imageText` y `codeBlock`.

### Acciones y estados

Las acciones tienen las variantes `primary`, `secondary` y `destructive`. Las acciones y los campos de formulario usan `base` y, opcionalmente, estados de interacción:

```json title="Inside base or a mode"
{
  "text": {
    "action": {
      "primary": {
        "base": "$hue.interactive.400",
        "$hovered": "$hue.interactive.300",
        "$disabled": "$hue.neutral.600"
      }
    }
  }
}
```

Las claves de estado son `$hovered`, `$focused`, `$pressed`, `$selected` y `$disabled`. Un estado no especificado usa el color `base` de esa acción o campo de formulario.

### Superficie de diálogos

Los paneles, diálogos, menús y notificaciones (toasts) eligen su profundidad a partir de `background.raised`. Además, los diálogos pueden sobrescribir tokens semánticos con `@dialog`:

```json title="Inside base or a mode"
{
  "@dialog": {
    "background": {
      "base": "$background.raised.base",
      "action": {
        "primary": {
          "$hovered": "$background.raised.high"
        }
      }
    }
  }
}
```

La TUI vuelve a resolver las referencias después de aplicar `@dialog`, así que los tokens que hacen referencia a `$background.base` siguen el fondo del diálogo. El `base` de una acción contextual pasa a ser el valor de respaldo de sus estados no especificados; las sobrescrituras explícitas de estado siguen teniendo prioridad.
