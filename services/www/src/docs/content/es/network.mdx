---
title: Red
description: Configura proxies y autoridades de certificación personalizadas.
---

Define las variables de proxy estándar y excluye las direcciones de loopback. La CLI de OpenCode se comunica con su
servicio en segundo plano mediante conexiones HTTP locales, por lo que debes excluir el loopback siempre que configures
un proxy en el entorno de la CLI.

```bash
export HTTP_PROXY=http://proxy.example.com:8080
export HTTPS_PROXY=http://proxy.example.com:8080
export NO_PROXY=localhost,127.0.0.1,::1

opencode
```

`HTTP_PROXY` se aplica a los destinos HTTP y `HTTPS_PROXY`, a los destinos HTTPS. La URL del proxy puede usar `http://`
en ambas variables. `NO_PROXY` es una lista separada por comas de hosts y direcciones a los que se conecta directamente,
sin pasar por el proxy.

## Servicio

Las variables exportadas en la shell solo afectan al servicio en segundo plano si este se inicia desde esa shell. Guarda
las variables de forma persistente en la configuración del servicio gestionado para que los siguientes inicios del servicio
usen la misma configuración de red.

```bash
opencode service set env HTTP_PROXY http://proxy.example.com:8080
opencode service set env HTTPS_PROXY http://proxy.example.com:8080
opencode service set env NO_PROXY localhost,127.0.0.1,::1
opencode service start
```

Al cambiar una variable de entorno gestionada, el servicio en ejecución se detiene. `service start` lo vuelve a iniciar
con el nuevo entorno. Si la shell de la CLI también define un proxy, mantén `NO_PROXY` en ella, ya que las variables del
servicio gestionado se aplican al proceso del servidor, no al de la CLI.

Para eliminar una variable guardada, usa `service unset env`:

```bash
opencode service unset env HTTPS_PROXY
```

## Autenticación

Si el proxy acepta credenciales en la URL, incluye el nombre de usuario y la contraseña en cada URL de proxy que requiera
autenticación. Codifica con porcentajes (percent-encoding) los caracteres como `@`, `:` y `/` que aparezcan en el usuario
o en la contraseña.

```bash
export HTTPS_PROXY='http://user:p%40ssword@proxy.example.com:8080'
```

Para el servicio en segundo plano, guarda la URL completa. El valor se almacena en la configuración privada del servicio y
`opencode service get env` lo muestra, así que no compartas esa salida.

```bash
opencode service set env HTTPS_PROXY 'http://user:p%40ssword@proxy.example.com:8080'
```

## Certificados

Si el proxy o el destino usan un certificado firmado por una autoridad de certificación privada, asigna a
`NODE_EXTRA_CA_CERTS` la ruta de un archivo PEM. Las autoridades adicionales se añaden al almacén de confianza del entorno
de ejecución cuando se inicia el proceso.

```bash
export NODE_EXTRA_CA_CERTS=/etc/company/ca.pem
opencode --standalone
```

Guarda la ruta del archivo en la configuración del servicio en segundo plano y reinícialo:

```bash
opencode service set env NODE_EXTRA_CA_CERTS /etc/company/ca.pem
opencode service start
```

## Primer plano

`--standalone` y `serve` usan el entorno de su propio proceso. `opencode service set env` no configura estos procesos.

```bash
HTTP_PROXY=http://proxy.example.com:8080 \
HTTPS_PROXY=http://proxy.example.com:8080 \
NO_PROXY=localhost,127.0.0.1,::1 \
opencode --standalone
```

Aplica el mismo patrón a un servidor en primer plano:

```bash
HTTPS_PROXY=http://proxy.example.com:8080 \
NO_PROXY=localhost,127.0.0.1,::1 \
opencode serve
```

## Verificación

Después de aplicar la configuración, comprueba que la CLI puede comunicarse con el servicio en segundo plano:

```bash
opencode api get /api/info
```

Una respuesta correcta de la comprobación de estado confirma la conexión local entre el cliente y el servicio. Para
verificar el proxy de salida y la ruta de certificados del servicio, haz una solicitud normal a un proveedor.
