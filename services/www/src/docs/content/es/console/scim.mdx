---
title: "Sincronización de directorios"
description: "Añade y quita miembros del espacio de trabajo automáticamente desde Okta, Microsoft Entra ID o cualquier proveedor de identidad SCIM 2.0."
---

La sincronización de directorios (SCIM 2.0) añade personas al espacio de trabajo cuando las asignas en tu proveedor de
identidad y les retira el acceso cuando anulas la asignación. Los roles se siguen gestionando en Console.

```text
https://opencode.ai/console/scim/v2
```

## Antes de empezar

- Configura el [SSO](/console/sso) para el espacio de trabajo.
- [Verifica](/console/sso#verify-email-domains) todos los dominios de correo con los que inician sesión tus usuarios.
  La sincronización de directorios solo añade personas de un dominio verificado; invita a cualquier otra persona desde
  [Miembros](/console/members).

## Crear un token

1. Abre **Settings › Security** y haz clic en **Set up** en **Directory sync**.
2. Copia la **SCIM base URL** y el token. El token solo se muestra una vez, así que guárdalo en un gestor de secretos.

Tu proveedor de identidad envía el token en cada solicitud.

```text
Authorization: Bearer <token>
```

## Conectar tu proveedor de identidad

### Okta

1. Añade la aplicación **SCIM 2.0 Test App (Header Auth)**.
2. Define la URL base e introduce `Bearer ` seguido del token en **API Token**.
3. Activa **Create Users**, **Update User Attributes** y **Deactivate Users**. Deja desactivados **Import Groups** y la
   sincronización de contraseñas.

### Microsoft Entra ID

1. En tu aplicación empresarial, abre **Provisioning** y cambia el modo a **Automatic**.
2. Introduce la URL base como **Tenant URL** y el token como **Secret Token**.
3. Asigna usuarios y grupos, y después inicia el aprovisionamiento.

### Otros proveedores

Usa una aplicación SCIM 2.0 con autenticación por token en la cabecera que apunte a la URL base. Console admite los
endpoints `/Users` y `/Groups`.

Asigna primero a una persona de prueba. **Directory sync** muestra **Connected to your identity provider** tras la
primera solicitud.

## Qué se sincroniza

| En tu proveedor de identidad   | En Console                                                                                        |
| ------------------------------ | ------------------------------------------------------------------------------------------------- |
| Asignar a una persona          | Se añade como **Member**. Los miembros existentes conservan su rol.                               |
| Actualizar un nombre           | Se actualiza el perfil.                                                                           |
| Anular la asignación o desactivar | Se suspende el acceso y se muestra como **Deactivated**. Se revocan las claves de API que haya creado. |
| Volver a asignar               | Se restablece el acceso. Las claves revocadas siguen revocadas.                                   |
| Eliminar                       | Se quita del espacio de trabajo. Su cuenta y sus otros espacios de trabajo no se ven afectados.   |

- La sincronización de directorios no cambia los roles ni las direcciones de correo.
- El último propietario no se puede desactivar ni eliminar.
- Los espacios de trabajo con una suscripción a [Go](/console/go) no pueden añadir miembros mediante la sincronización
  de directorios.

## Grupos

Envía grupos para etiquetar a sus miembros, por ejemplo con **Push Groups** de Okta o con la asignación de grupos de
Entra. Asigna a las personas antes de enviar sus grupos.

```text
Platform Admins  →  platform-admins
```

Cada grupo etiqueta a sus miembros con una etiqueta que lleva el nombre del grupo. En
**Settings › Security › Group tags** puedes renombrar una etiqueta, hacer que varios grupos apunten a la misma etiqueta
o dejar de etiquetar un grupo. Al salir de un grupo se quita su etiqueta.

## Rotar el token

1. Haz clic en **New token** e instálalo en tu proveedor de identidad.
2. Espera a que el nuevo token muestre un último uso.
3. Revoca el token anterior.

Revocar un token detiene las actualizaciones futuras, pero no modifica los miembros existentes. Al eliminar la conexión
SSO se revocan todos los tokens.

## SSO y sincronización de directorios

En cuanto un espacio de trabajo emite un token, el SSO deja de [añadir miembros automáticamente](/console/sso#automatic-membership).
El directorio decide quién pertenece al espacio de trabajo, aunque el token se revoque después.
