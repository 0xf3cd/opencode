---
title: "API de proveedores"
description: "Llama a los proveedores conectados a tu espacio de trabajo a través del gateway de Console con una clave de Console."
---

Cada [proveedor](/console/providers) conectado a tu espacio de trabajo se sirve a través del gateway de Console en su
propia URL. OpenCode lo usa automáticamente después de `/connect`; llámalo directamente para usar los mismos
proveedores desde tus propias herramientas. Console añade la credencial del proveedor antes de reenviar la solicitud,
así que el secreto del proveedor nunca sale del espacio de trabajo.

```bash
curl -X POST "https://opencode.ai/inference/custom/conn_.../chat/completions" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "deepseek-chat",
    "messages": [{ "role": "user", "content": "Say hi" }]
  }'
```

## URL del proveedor

Copia la **Console API URL** desde la página del proveedor en **Providers**.

```text
https://opencode.ai/inference/custom/<connection_id>
```

## Autenticación

Sustituye `<token>` por una [clave de cuenta de servicio](/console/api#service-accounts) creada en Console. Console la
cambia por la credencial de la conexión antes de reenviar la solicitud.

```text
Authorization: Bearer <token>
```

Console también lee la clave de `x-api-key`, `api-key` o `x-goog-api-key`, así que los SDK de los proveedores funcionan
cuando se apuntan a la Console API URL.

## Endpoints

Añade la ruta de la API del proveedor a la Console API URL. Console reenvía la solicitud a la URL base de la conexión y
devuelve la respuesta del proveedor sin cambios.

| Formato              | Ruta                              |
| -------------------- | --------------------------------- |
| Chat Completions     | `/chat/completions`               |
| Responses API        | `/responses`                      |
| Anthropic Compatible | `/messages`                       |
| Google Generative AI | `/models/<model>:generateContent` |

Envía el ID del modelo tal como aparece en la página del proveedor. Si un modelo tiene un ID de API distinto en el
proveedor de origen, Console lo reescribe. Las solicitudes de modelos que no están activados en la conexión se
rechazan.

### Chat Completions

```bash
curl -X POST "https://opencode.ai/inference/custom/conn_.../chat/completions" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "deepseek-chat",
    "messages": [{ "role": "user", "content": "Say hi" }]
  }'
```

### Responses API

```bash
curl -X POST "https://opencode.ai/inference/custom/conn_.../responses" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-5.4",
    "input": "Say hi"
  }'
```

### Anthropic Compatible

`max_tokens` es obligatorio.

```bash
curl -X POST "https://opencode.ai/inference/custom/conn_.../messages" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "claude-sonnet-4-6",
    "max_tokens": 1024,
    "messages": [{ "role": "user", "content": "Say hi" }]
  }'
```

### Google Generative AI

El modelo y el método forman parte de la ruta. Sustituye `:generateContent` por `:streamGenerateContent` para recibir
la respuesta en streaming.

```bash
curl -X POST "https://opencode.ai/inference/custom/conn_.../models/gemini-3.1-pro:generateContent" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [{ "parts": [{ "text": "Say hi" }] }]
  }'
```

## Uso

Las solicitudes cuentan para los [presupuestos](/console/budgets) según el precio definido en cada modelo. El proveedor
te factura los tokens.
