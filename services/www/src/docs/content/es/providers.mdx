---
title: "Proveedores"
---

OpenCode incluye un catálogo de proveedores y modelos de [models.dev](https://models.dev). Con la mayoría de los
proveedores, primero conectas una cuenta y después seleccionas un modelo.

## Configuración inicial

Ejecuta `/connect`, elige un proveedor e introduce sus credenciales. Después ejecuta `/models` para seleccionar uno de sus
modelos.

```text
/connect
/models
```

## Go

[OpenCode Go](/console/go) es una suscripción opcional para modelos de programación probados por el equipo de OpenCode.
Suscríbete en [OpenCode Console](https://opencode.ai/console), copia tu clave de API y conéctala como **OpenCode Go**.

```text
/connect
# Select OpenCode Go, then paste your API key.
/models
```

Consulta la [guía de Go](/console/go) para conocer los límites de uso, los endpoints y los detalles de privacidad.

## Personalizado

Añade un proveedor cuando su API no esté ya en el catálogo. Este ejemplo compatible con OpenAI define a la vez la
credencial, el paquete de runtime, el endpoint y el primer modelo.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "acme": {
      "name": "Acme",
      "env": ["ACME_API_KEY"],
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "https://llm.acme.example/v1",
      },
      "models": {
        "qwen3-coder": {
          "name": "Qwen 3 Coder",
        },
      },
    },
  },
}
```

Las claves del objeto `providers` son los ID de proveedor que se usan en las referencias a modelos, como
`acme/qwen3-coder`.

| Campo | Función |
| --- | --- |
| `name` | Nombre visible. |
| `env` | Nombres de variables de entorno, en orden, que pueden proporcionar la credencial. |
| `package` | Paquete de runtime del proveedor. |
| `canonical` | ID de un proveedor integrado cuyos valores predeterminados del catálogo hereda este proveedor. |
| `compatibility` | Sobrescrituras de compatibilidad de solicitudes y respuestas para todos los modelos de este proveedor. El `compatibility` de un modelo sobrescribe campos individuales. `supportsThinkingBlockBinding` y `supportsEffortUpdates` solo existen a nivel de modelo. |
| `settings` | Controles tipados de OpenCode y opciones JSON que se pasan al paquete de runtime. |
| `headers` | Cabeceras HTTP con valores de tipo cadena que se añaden a las solicitudes. |
| `body` | Campos JSON que se combinan con el cuerpo de las solicitudes. |
| `models` | Modelos que se añaden o se sobrescriben, con el ID de modelo de OpenCode como clave. |

## Endpoint

Sobrescribe `settings.baseURL` para enviar un proveedor del catálogo a través de un proxy o de un endpoint compatible. Su
paquete, sus modelos y su conexión existentes se siguen aplicando.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "anthropic": {
      "settings": {
        "baseURL": "https://llm-proxy.example.com/anthropic",
      },
    },
  },
}
```

`settings` depende del paquete. Un campo solo tiene efecto si el paquete seleccionado lo admite.

## Solicitudes

Usa `headers` para añadir cabeceras HTTP y `body` para campos JSON que deban combinarse con el cuerpo de cada solicitud.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "headers": {
        "X-Gateway-Tenant": "engineering",
      },
      "body": {
        "metadata": {
          "application": "opencode",
        },
      },
    },
  },
}
```

Ambos campos también pueden definirse en un modelo o en una variante cuando solo una parte del tráfico del proveedor
necesita la sobrescritura.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "models": {
        "gpt-5.2": {
          "headers": { "X-Model-Tier": "coding" },
          "variants": [
            {
              "id": "batch",
              "body": { "service_tier": "flex" },
            },
          ],
        },
      },
    },
  },
}
```

## Tiempos de espera

Las solicitudes HTTP esperan hasta cinco minutos a las cabeceras de la respuesta y hasta cinco minutos entre fragmentos
de la respuesta en streaming. Asigna a `settings.headerTimeout` o `settings.chunkTimeout` del proveedor un número de
milisegundos para cambiar un límite, o `false` para desactivarlo. `settings.timeout` limita además la solicitud completa,
desde el envío hasta que termina la respuesta; no tiene valor predeterminado. Estos ajustes se aplican a todo el
proveedor, no por modelo ni por variante. Con un transporte WebSocket, `chunkTimeout` limita en cambio el intervalo entre
tramas y su valor predeterminado es de treinta minutos.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "anthropic": {
      "settings": {
        "headerTimeout": 600000,
        "chunkTimeout": false,
      },
    },
  },
}
```

Una solicitud que supera cualquiera de los dos límites falla con un error de transporte. OpenCode reintenta una solicitud
que ha agotado el tiempo de espera hasta tres veces antes de darse por vencido.

## Codificación de solicitudes

`settings.encoding` comprime el cuerpo de las solicitudes HTTP con `"zstd"` o `"gzip"`, o envía JSON sin comprimir con
`"none"`. Defínelo en un proveedor, un modelo o una variante; gana el valor más específico. Activa solo una codificación
que el endpoint sepa decodificar: la mayoría de los proveedores y gateways rechazan los cuerpos comprimidos. OpenAI usa
`"zstd"` de forma predeterminada cuando inicias sesión con ChatGPT y no hay un `baseURL` personalizado configurado; con
claves de API se envía JSON sin comprimir. Los mensajes WebSocket no se ven afectados.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "settings": { "encoding": "none" },
    },
  },
}
```

## Paquetes

El campo `package` selecciona el runtime que se comunica con un proveedor. Usa el runtime compatible para las API que
implementan el formato de solicitud de OpenAI.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "acme": {
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "https://llm.acme.example/v1",
      },
      "models": {
        "qwen3-coder": {},
      },
    },
  },
}
```

Los paquetes nativos disponibles incluyen:

- `@opencode/ai/providers/openai`
- `@opencode/ai/providers/openai/chat`
- `@opencode/ai/providers/openai/responses`
- `@opencode/ai/providers/openai-compatible`
- `@opencode/ai/providers/openai-compatible/responses`
- `@opencode/ai/providers/anthropic`
- `@opencode/ai/providers/anthropic-compatible`
- `@opencode/ai/providers/google`
- `@opencode/ai/providers/google-vertex`
- `@opencode/ai/providers/google-vertex/gemini`
- `@opencode/ai/providers/google-vertex/chat`
- `@opencode/ai/providers/google-vertex/responses`
- `@opencode/ai/providers/google-vertex/messages`
- `@opencode/ai/providers/azure`
- `@opencode/ai/providers/azure/chat`
- `@opencode/ai/providers/azure/responses`
- `@opencode/ai/providers/amazon-bedrock`
- `@opencode/ai/providers/amazon-bedrock/mantle`
- `@opencode/ai/providers/amazon-bedrock/mantle/chat`
- `@opencode/ai/providers/amazon-bedrock/mantle/responses`
- `@opencode/ai/providers/openrouter`
- `@opencode/ai/providers/xai`

También puedes usar un paquete de npm, como `@acme/opencode-provider`, o una URL `file://` absoluta para un paquete local.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "acme": {
      "package": "@acme/opencode-provider",
      "models": { "acme-coder": {} },
    },
  },
}
```

## Modelos

Añade o sobrescribe modelos en el mapa `models` de un proveedor. La clave del mapa es el ID de modelo que usa OpenCode;
`modelID` cambia el ID que se envía al proveedor.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "openai/coding",
  "providers": {
    "openai": {
      "models": {
        "coding": {
          "modelID": "gpt-5.2",
          "name": "GPT-5.2 Coding",
        },
      },
    },
  },
}
```

| Campo | Función |
| --- | --- |
| `modelID` | ID del modelo o del despliegue que se envía al proveedor. |
| `name` | Nombre visible. |
| `family` | Familia del modelo, para agrupar modelos relacionados. |
| `package` | Runtime específico para este modelo. |
| `settings` | Controles de OpenCode a nivel de modelo y ajustes JSON específicos del paquete. |
| `headers` | Cabeceras de solicitud adicionales con valores de tipo cadena. |
| `body` | Campos adicionales del cuerpo JSON de la solicitud. |
| `capabilities` | Compatibilidad con herramientas y tipos de contenido de entrada y salida aceptados. |
| `compatibility` | Sobrescrituras de compatibilidad de solicitudes y respuestas. |
| `variants` | Variantes con nombre que tienen sus propios `settings`, `headers` y `body`. |
| `cost` | Precio de entrada, de salida y, opcionalmente, de caché por millón de tokens. |
| `limit` | Límites de tokens de contexto, de entrada y de salida. |
| `disabled` | Quita el modelo de la selección cuando es `true`. |

Consulta [Modelos](/models) para conocer la selección, los valores predeterminados, las capacidades, los límites, los
costes y las variantes.

## Azure

El endpoint estándar del catálogo de Azure necesita un nombre de recurso además de la credencial. Define
`settings.resourceName` una vez y después conecta una clave de API o usa la sesión de Microsoft Entra ID de la CLI de
Azure, como se describe en [Cuentas de proveedores](/cli/providers).

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "azure": {
      "settings": {
        "resourceName": "my-models",
      },
    },
  },
}
```

Encontrarás el **Resource name** en el [portal de Azure](https://portal.azure.com/) o en
[Microsoft Foundry](https://ai.azure.com/). También es la primera parte de endpoints como
`https://my-models.openai.azure.com/` y `https://my-models.services.ai.azure.com/`.

```bash
az cognitiveservices account list \
  --query "[].{name:name,resourceGroup:resourceGroup}" \
  --output table
```

Para usar Entra ID, instala la [CLI de Azure](https://learn.microsoft.com/en-us/cli/azure/install-azure-cli), inicia
sesión y elige **Microsoft Entra ID (Azure CLI)** al conectar Azure.

```bash
az login
```

Introduce el nombre del recurso al conectar si no lo proporcionan ya la configuración o el entorno. Un nombre de recurso
guardado con una conexión tiene prioridad sobre la configuración; vuelve a conectar para cambiarlo.

Las conexiones mediante la CLI de Azure usan la cuenta seleccionada en la CLI de Azure. Para un recurso de otro tenant o
de otra suscripción, selecciona ambos explícitamente.

```bash
az login --tenant TENANT_ID
az account set --subscription NAME_OR_ID
```

En lugar de la configuración, `AZURE_RESOURCE_NAME` proporciona el nombre del recurso al servidor de OpenCode. La
variable heredada `AZURE_COGNITIVE_SERVICES_RESOURCE_NAME` también funciona.

### Despliegues

Azure solo sirve un modelo a través de un despliegue, así que OpenCode lista los despliegues de tu recurso y muestra esos
en lugar de todo el catálogo de Azure. La lista se carga en segundo plano tras el inicio, tras conectar y tras cambiar de
cuenta. Para que aparezca un despliegue añadido más tarde, reinicia OpenCode o vuelve a conectar.

- Hasta que la lista se carga para una conexión, o si falla, sigue disponible todo el catálogo.
- Si falla una recarga para la misma conexión, se conserva su último inventario completo.
- Al cambiar de cuenta nunca se muestra el inventario de la cuenta anterior; la cuenta nueva empieza con todo el
  catálogo.
- Los despliegues heredan los límites, los costes y las capacidades de sus modelos del catálogo.

Los nombres de los despliegues son sus ID de modelo, en minúsculas porque Azure no distingue mayúsculas y minúsculas en
los nombres; por ejemplo, `azure/gpt-production`. Un despliegue con el nombre de su modelo, como `gpt-5-mini`, conserva
el ID del catálogo. Estos ID se mantienen estables cuando se añaden o eliminan otros despliegues.

OpenCode asocia un despliegue con el catálogo por el modelo que despliega, o por su nombre cuando Azure escribe el
modelo de otra forma, como `gpt-4` para GPT-4 Turbo. Un despliegue con el nombre de otro modelo, como `gpt-5` que
despliega `gpt-5-mini`, muestra el nombre, los límites y los costes de ese modelo.

Con la CLI de Azure, OpenCode lista los despliegues a través de la API de administración de Azure, que necesita acceso de
lectura al recurso. Si eso falla, y siempre que se usa una clave de API, recurre al inventario de despliegues heredado
del recurso. La detección lee todas las páginas antes de publicar la lista. Con un `settings.baseURL` personalizado se
mantiene el catálogo.

Configura un despliegue explícitamente cuando su modelo no esté en el catálogo, como un modelo ajustado (fine-tuned), o
para asociar tú mismo un ID de modelo a un despliegue. OpenCode registra una advertencia con el nombre de esos
despliegues. Los modelos configurados explícitamente siempre se conservan.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "azure": {
      "models": {
        "gpt-5-mini": {
          "modelID": "gpt-production",
        },
      },
    },
  },
}
```

Tu identidad necesita uno de estos roles:

- **Cognitive Services OpenAI User** para los modelos de Azure OpenAI.
- **Cognitive Services User** para otros modelos de Foundry.

Si una solicitud usa un token del tenant equivocado, vuelve a iniciar sesión con el tenant necesario.

```bash
az login --tenant TENANT_ID
```

## Bedrock

Amazon Bedrock usa la cadena de credenciales predeterminada de AWS. Un perfil de AWS con nombre es la configuración
duradera más sencilla; OpenCode también reconoce entornos con claves de acceso, web identity y credenciales de
contenedor.

```bash
aws configure sso --profile work
aws sso login --profile work
```

Selecciona el perfil y la región en los ajustes del proveedor. Un `profile` configurado, `AWS_PROFILE`,
`AWS_ACCESS_KEY_ID`, un archivo de token de web identity o una URI de credenciales de contenedor activan el proveedor;
una región por sí sola no lo hace.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "amazon-bedrock": {
      "settings": {
        "profile": "work",
        "region": "us-west-2",
      },
    },
  },
}
```

Sin una región explícita, OpenCode usa `AWS_REGION`, después `AWS_DEFAULT_REGION` y, por último, `us-east-1`. Para un
endpoint privado o de VPC, define `baseURL` manteniendo el mismo perfil y la misma región.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "amazon-bedrock": {
      "settings": {
        "profile": "work",
        "region": "us-west-2",
        "baseURL": "https://bedrock-runtime.vpce.example.com",
      },
    },
  },
}
```

Las claves de API de Bedrock usan `AWS_BEARER_TOKEN_BEDROCK`. Las demás variables de AWS alimentan SigV4 y no se guardan
como cuentas de clave de API de OpenCode.

## Vertex

Google Vertex usa Application Default Credentials (ADC) y necesita un proyecto antes de que sus modelos estén
disponibles. Crea las ADC locales y después define el proyecto y la ubicación en los ajustes del proveedor.

```bash
gcloud auth application-default login
```

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "google-vertex": {
      "settings": {
        "project": "my-project",
        "location": "us-central1",
      },
    },
  },
}
```

OpenCode también resuelve el proyecto a partir de `GOOGLE_VERTEX_PROJECT`, `GOOGLE_CLOUD_PROJECT`, `GCP_PROJECT` o
`GCLOUD_PROJECT`, en ese orden. Resuelve la ubicación a partir de `GOOGLE_VERTEX_LOCATION`, `GOOGLE_CLOUD_LOCATION` o
`VERTEX_LOCATION`, y usa `us-central1` de forma predeterminada.

```bash
GOOGLE_CLOUD_PROJECT=my-project GOOGLE_VERTEX_LOCATION=europe-west4 opencode --standalone
```

Las cuentas de servicio funcionan por la misma vía de ADC. Apunta `GOOGLE_APPLICATION_CREDENTIALS` al archivo JSON de la
cuenta de servicio y proporciona igualmente un proyecto mediante los ajustes o una de las variables de proyecto
anteriores.

```bash
GOOGLE_APPLICATION_CREDENTIALS=/secure/vertex.json \
GOOGLE_CLOUD_PROJECT=my-project \
opencode --standalone
```

Usa el ID de proveedor único `google-vertex` para los modelos del catálogo de Vertex de Gemini, de Anthropic y
compatibles con OpenAI. El antiguo ID de proveedor `google-vertex-anthropic` no está disponible en V2.

## Copilot

GitHub Copilot admite OAuth de dispositivo en lugar de introducir manualmente una clave de API. Conecta
**GitHub Copilot**, elige GitHub.com o GitHub Enterprise, completa el flujo de dispositivo y abre `/models`.

```text
/connect
# Select GitHub Copilot, then Login with GitHub Copilot.
/models
```

Para GitHub Enterprise, introduce la URL o el dominio del despliegue cuando se te pida. OpenCode usa el endpoint de la
API de Copilot que devuelve GitHub cuando está disponible; si no, deduce el endpoint a partir del dominio de la empresa.

```text
company.ghe.com
```

La cuenta conectada necesita acceso a Copilot Chat. Si GitHub indica que no tienes derecho de uso, regístrate en Copilot
Free o pide a la organización que te asigne una licencia de Copilot y vuelve a conectar. OpenCode obtiene la lista de
modelos actual de la cuenta después de iniciar sesión y cada vez que cambia la cuenta de Copilot activa.

## Ollama

Inicia Ollama y descarga un modelo. OpenCode sondea `http://127.0.0.1:11434`, detecta los modelos de completado y los
añade a `/models` sin necesidad de conectar una cuenta.

```bash
ollama serve
ollama pull qwen3:8b
```

Apunta OpenCode a un servidor Ollama remoto o detrás de un proxy con `settings.baseURL`. Incluye `/v1`; OpenCode deduce a
partir de él las rutas de detección nativas `/api/tags` y `/api/show`. `apiKey` es opcional y se envía como token bearer
en las solicitudes de detección y de modelo.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "ollama": {
      "settings": {
        "baseURL": "https://ollama.example.com/v1",
        "apiKey": "{env:OLLAMA_API_KEY}",
      },
    },
  },
}
```

La detección se actualiza periódicamente y conserva el último inventario correcto durante una interrupción temporal. Los
modelos que solo generan embeddings no aparecen, porque OpenCode solo añade modelos cuyos metadatos de Ollama incluyen la
capacidad `completion`.

## Entornos de ejecución

LM Studio y vLLM también tienen detección local integrada. Sus endpoints predeterminados son `http://127.0.0.1:1234/v1`
y `http://127.0.0.1:8000/v1`.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "lmstudio": {
      "settings": { "baseURL": "http://gpu-host:1234/v1" },
    },
    "vllm": {
      "settings": { "baseURL": "http://gpu-host:8000/v1" },
    },
  },
}
```

LM Studio detecta los modelos de lenguaje desde `/api/v1/models`. vLLM comprueba `/health` antes de leer `/v1/models`; su
detección no puede deducir si hay compatibilidad con herramientas, así que los modelos de vLLM detectados empiezan con las
herramientas desactivadas. Para otro runtime compatible con OpenAI, sigue la receta del
[proveedor personalizado](#custom) y lista sus modelos explícitamente.

## Gateways

OpenRouter usa su runtime y su catálogo nativos. Proporciona `OPENROUTER_API_KEY` al servidor de OpenCode o conecta una
cuenta de OpenRouter, y después haz referencia a los modelos con el ID de modelo completo de OpenRouter tras el prefijo
del proveedor.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "openrouter/anthropic/claude-sonnet-4",
}
```

Mantén el paquete nativo de OpenRouter cuando sobrescribas su endpoint o enrutes el tráfico a través de un gateway
compatible con OpenRouter. Así se conserva el comportamiento de OpenRouter en las solicitudes y el razonamiento.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openrouter": {
      "settings": {
        "baseURL": "https://openrouter-gateway.example.com/api/v1",
      },
      "headers": {
        "X-Gateway-Tenant": "engineering",
      },
    },
  },
}
```

Para un gateway que expone una API compatible con OpenAI pero tiene su propio inventario de modelos, define en su lugar
un proveedor personalizado. La clave de configuración se convierte en el prefijo del proveedor y cada clave de `models`,
en un ID de modelo seleccionable.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "company/coder",
  "providers": {
    "company": {
      "env": ["COMPANY_GATEWAY_KEY"],
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "https://gateway.example.com/v1",
      },
      "models": {
        "coder": { "modelID": "upstream/coder-v2" },
      },
    },
  },
}
```

## Errores

Los errores de proveedores y modelos suelen indicar la fase que ha fallado. Revisa el entorno del proceso del servidor y
el ID exacto del modelo antes de cambiar de paquete.

| Error o síntoma | Qué revisar |
| --- | --- |
| `No model is available for session ...` | No hay ningún modelo habilitado seleccionable. Completa la configuración específica del proveedor y elige un modelo en `/models`. |
| `Model unavailable: provider/model` | El proveedor está inactivo, el ID del modelo no existe o está deshabilitado, o la detección dinámica ya no lo devuelve. En los alias personalizados, revisa la clave del mapa `models`, no `modelID`. |
| `Cannot initialize provider/model: NAME is required to resolve the provider endpoint` | Queda un marcador `${NAME}` en `baseURL`. Define esa variable en el servidor de OpenCode o sustituye la plantilla por un endpoint completo. |
| `Azure resource name is missing` | Define `providers.azure.settings.resourceName`, `AZURE_RESOURCE_NAME` o un `settings.baseURL` completo. |
| Vertex no aparece | Define un proyecto resoluble en los ajustes del proveedor o en una variable de proyecto admitida. Las ADC por sí solas no activan el proveedor. |
| Bedrock no aparece | Proporciona un perfil u otra entrada admitida de la cadena de credenciales de AWS. `AWS_REGION` por sí sola solo selecciona una región. |
| Ollama no tiene modelos | Confirma que el servidor expone `/api/tags` y `/api/show` en la ruta deducida de `baseURL` y que `/api/show` indica la capacidad `completion`. |
| Copilot no tiene modelos | Confirma que la cuenta OAuth activa tiene acceso a Copilot Chat. Si falla la sincronización de modelos, se registra `failed to sync GitHub Copilot models`. |

V2 rechaza los ID de proveedor retirados que tienen un sustituto directo. Usa `azure/<model>` en lugar de
`azure-cognitive-services/<model>` y `google-vertex/<model>` en lugar de `google-vertex-anthropic/<model>`.

## WebSockets

Los modelos de OpenAI, xAI y los modelos de Azure Responses compatibles pueden mantener abierta una conexión WebSocket
por sesión. Los pasos consecutivos reutilizan el prefijo de la solicitud que no ha cambiado y solo envían el contenido
añadido desde la respuesta anterior, lo que reduce los datos enviados en las sesiones largas.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "settings": { "transport": "http" },
    },
  },
}
```

El comportamiento de WebSocket sigue estas reglas:

- Los proveedores integrados activan las rutas compatibles según su propia política.
- `settings.transport: "websocket"` en el proveedor lo activa; `"http"` lo desactiva.
- `"websocket"` en una ruta sin canal WebSocket registra una advertencia y recurre a HTTP.
- La compactación del proveedor OpenAI usa la misma conexión.
- xAI solo continúa a partir de respuestas almacenadas. Con su valor predeterminado `store: false`, cada paso se envía
  completo por la conexión reutilizada.
- Un socket cerrado se vuelve a conectar en el siguiente paso. Si la conexión no puede abrirse, la sesión continúa por
  HTTP.
- Los plugins de proveedor con hooks `http.request` o `http.response` se quedan en HTTP para que cada solicitud siga
  siendo observable.
