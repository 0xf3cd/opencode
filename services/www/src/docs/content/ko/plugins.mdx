---
title: "플러그인"
---

게시된 패키지, 버전을 지정한 패키지, 범위(scope) 패키지, 로컬 플러그인 디렉터리를 `opencode.json(c)`에 추가하세요.

## 구성

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": [
    "opencode-acme-plugin",
    "opencode-acme-plugin@1.2.0",
    "@acme/opencode-plugin",
    "./plugins/local",
    "../shared/plugin.ts",
    "/absolute/path/plugin.ts",
    "file:///home/me/plugins/local",
    {
      "package": "@acme/opencode-plugin",
      "options": {
        "agent": "reviewer",
        "strict": true,
      },
    },
  ],
}
```

상대 경로는 해당 항목이 있는 구성 파일을 기준으로 해석됩니다. 적용되는 구성 파일들의 플러그인 배열은 서로 대체되지 않고
우선순위가 낮은 것부터 높은 순서로 적용됩니다.

```text
~/.config/opencode/opencode.jsonc
./opencode.jsonc
./.opencode/opencode.jsonc
```

## 탐색

OpenCode는 발견된 모든 `.opencode/plugins/` 디렉터리에서 바로 아래에 있는 `.ts`, `.js` 파일과 플러그인 패키지
디렉터리도 로드합니다.

```text
.opencode/
└── plugins/
    ├── concise.ts
    ├── reviewer.js
    └── acme-package/
```

전역 플러그인은 OpenCode 구성 디렉터리 아래에서 같은 탐색 구조를 사용합니다.

```text
~/.config/opencode/plugins/
```

프로젝트 루트의 `opencode.json(c)` 옆에 있는 `plugins/` 디렉터리는 자동으로 탐색되지 않습니다. 그 안의 파일을 명시적으로
구성하거나 디렉터리를 `.opencode/` 아래로 옮기세요.

```jsonc title="opencode.jsonc"
{
  "plugins": ["./plugins/local"]
}
```

## 제어

플러그인 항목은 순서대로 처리됩니다. ID나 와일드카드 앞에 `-`를 붙이면 비활성화되고, `*`는 모든 플러그인을 의미하며,
`.*`는 ID 접두사와 일치합니다. 뒤에 다시 ID를 지정하면 플러그인이 다시 활성화됩니다.

```jsonc title="opencode.jsonc"
{
  "plugins": ["*", "-opencode.provider.*", "opencode.provider.openai", "-acme.reviewer"]
}
```

저장소에서 [정책](/policies) 적용을 끌 수 없도록, 두 가지 기본 제공 플러그인은 제거 지정을 무시합니다.
`opencode.config.policy`와, 조직 정책을 전달하는 Console 연결인 `opencode.provider.opencode`입니다.

## 관리

CLI로 전역 패키지 플러그인을 설치, 조회, 확인, 업데이트, 제거할 수 있습니다.

```sh
opencode plugin add opencode-acme-plugin@1.2.0
opencode plugin list
opencode plugin list --builtin
opencode plugin check
opencode plugin update
opencode plugin update opencode-acme-plugin
opencode plugin remove opencode-acme-plugin@1.2.0
```

`plugin check`는 서버 패키지 플러그인과 TUI 전용 패키지 플러그인의 업데이트를 확인합니다. `plugin update`는 오래된
패키지를 모두 업데이트합니다. 구성된 패키지 대상을 지정하면 해당 패키지만 확인하거나 업데이트합니다. 로컬 플러그인과
정확한 리비전으로 고정된 패키지는 건너뜁니다.

패키지 설치에는 버전, 태그, 범위를 지정한 npm 이름과 npm 호환 Git 패키지 지정자를 사용할 수 있습니다. Git 저장소는 호스팅
단축 표기, HTTPS, SSH를 사용할 수 있으며, 기존 Git 자격 증명으로 접근할 수 있는 비공개 저장소도 포함됩니다.

```sh
opencode plugin add @acme/opencode-plugin@latest
opencode plugin add github:acme/opencode-plugin
opencode plugin add git+ssh://git@github.com/acme/opencode-plugin.git#main
opencode plugin add 'github:acme/plugins#main::path:packages/opencode-plugin'
```

브랜치, 태그, 전체 커밋 해시, 저장소 하위 디렉터리를 선택하는 npm의 `::path:` 지정자를 지원합니다. 로컬 경로는 구성에서
직접 지정하세요. `plugin add`는 tarball과 npm 별칭 대상을 허용하지 않습니다.

## 다시 로드

감시 중인 구성 디렉터리 아래의 변경 사항은 자동으로 다시 로드됩니다. 서버가 시작되면 캐시된 패키지 플러그인을 즉시
로드하고, 누락된 패키지는 백그라운드에서 설치하며, 고정되지 않은 npm 및 Git 플러그인은 설치된 패키지를 바꾸지 않고
업데이트만 확인합니다. 정확한 npm 버전과 전체 Git 커밋 해시는 고정된 상태로 유지됩니다. 감시되지 않는 로컬 의존성을
변경한 경우에는 여전히 OpenCode를 다시 시작해야 할 수 있습니다.

```sh
touch .opencode/plugins/concise/index.ts
opencode service restart
```

## 터미널

CLI 전용 플러그인은 따로 구성하며, 원격 서버에 연결된 상태에서도 활성 상태로 유지됩니다.

```json title="cli.json"
{
  "plugins": ["opencode-acme-cli"]
}
```
