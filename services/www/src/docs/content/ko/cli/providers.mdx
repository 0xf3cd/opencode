TUI에서 제공자를 연결한 다음 해당 제공자의 모델을 선택하세요.

```text
/connect
/models
```

`/connect`는 현재 서버와 프로젝트에서 사용할 수 있는 통합 목록을 표시합니다. 제공자를 선택하고, 인증 방법이 여러
개라면 하나를 고른 다음 안내에 따라 진행하세요.

## TUI

TUI는 API 키, OAuth, 제공자 인증 명령을 지원합니다. OAuth는 인증 URL을 열거나 입력할 코드를 표시합니다. `o`를 누르면
URL이 열리고, `c`를 누르면 인증 정보가 복사됩니다.

```text
/connect
# Select OpenAI, then Codex device code (legacy).
```

다른 계정을 추가하려면 `/connect`를 다시 실행하세요. 이미 연결된 제공자를 선택하면 계정 목록이 열리며, 여기서 저장된
계정을 활성화하거나 이름을 바꾸거나 삭제할 수 있습니다.

## CLI

TUI를 열지 않고 같은 제공자 인증 방법을 사용하려면 `auth login`을 사용하세요. 제공자 인자 없이 실행하면 대화형 제공자
선택 화면이 열립니다.

```bash
opencode auth login
```

통합 ID나 이름을 전달하면 첫 번째 선택 화면을 건너뜁니다. API 키 입력을 명시적으로 선택하려면 `--method key`를
사용하세요.

```bash
opencode auth login anthropic --method key
```

방법 ID는 제공자마다 다릅니다. 제공자에 인증 방법이 여러 개 있을 때 사용 가능한 방법을 확인하려면 `--method` 없이
명령을 실행하세요.

```bash
opencode auth login openai
```

API 키 입력과 제공자 양식에는 대화형 터미널이 필요합니다. 인증 코드를 붙여 넣어야 하는 OAuth 방법도 마찬가지입니다.

## 인증 방법

OpenCode는 네 가지 통합 방법으로 제공자 자격 증명을 받습니다.

| 방법 | 동작 |
| --- | --- |
| API 키 | 비밀 값을 입력받아 제공자 계정으로 저장합니다. |
| OAuth | 브라우저 URL, 기기 코드, 인증 코드 입력 중 하나를 제공한 다음 토큰을 저장하고, 지원되는 경우 토큰을 갱신합니다. |
| 명령 | 제공자가 지정한 인증 명령을 실행하고 표준 출력을 키로 저장합니다. |
| 환경 변수 | 서버 프로세스에서 지원되는 변수를 읽으며, 값을 저장하지는 않습니다. |

제공자는 Azure 리소스 이름이나 GitHub Enterprise 도메인처럼 필요한 정보를 받기 위해 API 키 및 OAuth 방법에 양식을
추가할 수 있습니다. CLI와 TUI는 인증을 시작하기 전에 이 양식을 표시합니다.

## 환경 변수

모델 요청을 실행하는 서버 프로세스에 제공자가 지원하는 환경 변수를 설정하세요. 일회성 비공개 서버라면 독립 실행 모드로
시작할 때 전달하면 됩니다.

```bash
ANTHROPIC_API_KEY=sk-ant-... opencode --standalone
```

공유 백그라운드 서버라면 관리형 환경에 변수를 추가하세요. 이렇게 하면 실행 중인 서비스가 중지되며, 다음 OpenCode
명령이 새 값으로 서비스를 시작합니다.

```bash
opencode service set env ANTHROPIC_API_KEY sk-ant-...
opencode auth list
```

환경 변수로 연결된 항목은 `auth list`에 `environment` 유형으로 표시됩니다. 이 항목은 계정이 아니므로 `auth logout`으로
제거할 수 없습니다. 연결을 해제하려면 변수를 제거하세요. 같은 통합에 대해서는 저장된 계정이 환경 변수 연결보다 우선
적용됩니다.

```bash
opencode auth list
opencode service unset env ANTHROPIC_API_KEY
```

일부 클라우드 제공자는 API 키 변수 대신 자체 앰비언트 자격 증명 체인도 사용합니다.

- Amazon Bedrock은 프로필, 액세스 키 환경 변수, 웹 ID, 컨테이너 자격 증명을 포함한 AWS 기본 자격 증명 체인을
  지원합니다. `AWS_BEARER_TOKEN_BEDROCK`도 지원합니다.
- Google Vertex는 Application Default Credentials와 확인 가능한 프로젝트를 사용합니다. 예를 들어
  `gcloud auth application-default login`으로 인증하고 `GOOGLE_CLOUD_PROJECT`를 설정하세요.
- Azure는 `az`가 설치되어 있으면 <strong>Microsoft Entra ID (Azure CLI)</strong>를 연결 방법으로 제공합니다. 먼저 `az login`을
  실행한 다음 `/connect` 또는 `auth login azure`에서 이 방법을 선택하세요.

```bash
gcloud auth application-default login
GOOGLE_CLOUD_PROJECT=my-project opencode
```

제공자별 설정과 서버 측 설정은 [제공자](/providers)를 참고하세요.

## 계정

API 키, OAuth, 명령으로 로그인에 성공할 때마다 저장된 계정이 하나씩 생성됩니다. 가장 최근 계정이 활성 계정이 되며,
레이블이나 자격 증명 ID로 활성 계정을 전환할 수 있습니다.

```bash
opencode auth list
opencode auth switch anthropic work
```

저장된 계정은 `auth logout`으로 제거합니다. 두 명령 모두 인자를 생략하면 선택 화면이 열립니다.

```bash
opencode auth logout anthropic work
```

TUI에서는 `/connect`로 저장된 계정을 추가, 활성화, 이름 변경, 삭제하는 작업을 똑같이 할 수 있습니다.

## 저장 위치

저장된 API 키와 OAuth 토큰은 서버의 SQLite 데이터베이스에 보관됩니다. 로컬 서버의 데이터베이스 경로는 다음 명령으로
출력합니다.

```bash
opencode debug paths db
```

일반적인 릴리스 경로는 `~/.local/share/opencode/opencode.db`이며, `XDG_DATA_HOME`, 릴리스 채널, `OPENCODE_DB`에 따라
달라질 수 있습니다. 자격 증명을 관리하려고 데이터베이스를 직접 편집하지 마세요. `/connect`나 `auth` 명령을 사용하세요.

V2는 데이터베이스 마이그레이션 과정에서 OpenCode 데이터 디렉터리에 있는 기존 `auth.json`의 지원되는 자격 증명을
가져옵니다. 새로 추가하거나 변경한 자격 증명은 이 파일에 다시 쓰지 않고 SQLite에 저장됩니다.
