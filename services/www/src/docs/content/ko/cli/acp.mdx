`opencode acp`는 OpenCode를 [Agent Client Protocol](https://agentclientprotocol.com) 에이전트로 실행하므로, Zed 같은
ACP 클라이언트에서 OpenCode를 사용할 수 있습니다. 다음은 Zed에 OpenCode를 추가하는 예입니다.

```json title="~/.config/zed/settings.json"
{
  "agent_servers": {
    "OpenCode": {
      "command": "opencode",
      "args": ["acp"]
    }
  }
}
```

다른 ACP 클라이언트도 같은 명령과 `acp` 인자를 사용하지만, 구성 파일과 필드 이름은 다를 수 있습니다. GUI
클라이언트가 `opencode`를 찾지 못하면 `command`를 `which opencode`가 출력하는 절대 경로로 설정하세요.

## 인증

OpenCode는 이미 저장된 제공자 자격 증명을 사용합니다. ACP 클라이언트를 시작하기 전에 터미널에서 로그인하세요.

```bash
opencode auth login
```

OpenCode는 `opencode-login`이라는 인증 방법 하나를 제공합니다. 기본적으로는 에이전트 인증 방법입니다.
`authenticate` 요청은 이 방법만 받으며 자격 증명을 수집하지 않습니다. 제공자 인증이 필요해 프롬프트가 실패하면
OpenCode는 ACP의 `auth_required` 오류를 반환합니다.

클라이언트가 `clientCapabilities.auth.terminal`을 `true`로 설정하면 인증 방법은 터미널 인증 방법이 됩니다.

```json
{
  "id": "opencode-login",
  "name": "Login with opencode",
  "description": "Run `opencode auth login` in the terminal",
  "type": "terminal",
  "args": ["--login"]
}
```

클라이언트는 이 방법을 `authenticate`로 보내면 안 됩니다. 대신 OpenCode를 시작하는 명령에 `--login`을 추가하고(예:
`opencode acp --login`) 터미널에서 실행합니다. OpenCode는 `opencode auth login` 흐름을 실행한 뒤 종료합니다. 종료
상태 0은 로그인에 성공했다는 뜻입니다. 그런 다음 클라이언트는 다시 연결해 `initialize`를 다시 보냅니다.

클라이언트가 `clientCapabilities._meta["terminal-auth"]`를 `true`로 설정하면 인증 방법에 로그인 명령이 포함됩니다.

```json
{
  "id": "opencode-login",
  "name": "Login with opencode",
  "description": "Run `opencode auth login` in the terminal",
  "_meta": { "terminal-auth": { "command": "opencode", "args": ["auth", "login"], "label": "OpenCode Login" } }
}
```

## 문제 해결

`opencode acp`는 stdin으로 ACP 메시지를 기다리므로 터미널에서 직접 실행하면 멈춘 것처럼 보입니다. ACP 클라이언트에서
시작하세요.

클라이언트가 프로세스가 종료되었다거나 잘못된 프로토콜 출력을 썼다고 보고하면, 클라이언트 인자에서 `acp` 앞에
`--print-logs`를 추가하세요. 그러면 OpenCode가 ACP 로그와 비공개 서버 로그를 stderr에 씁니다. stdout에는 ACP
메시지만 출력됩니다.

```bash
opencode --print-logs acp
```

## 프로토콜 레퍼런스

이 섹션은 ACP 클라이언트 개발자를 위한 내용입니다. OpenCode가 지원하는 ACP 기능과 OpenCode가 추가하는 `_meta` 키를
설명합니다. 이 키를 인식하지 못하는 클라이언트는 무시해도 됩니다. 메시지 정의는
[ACP 문서](https://agentclientprotocol.com)를 참고하세요.

### 전송

클라이언트는 `opencode acp`를 자식 프로세스로 시작합니다. 두 프로세스는 ACP 프로토콜 버전 1을 사용해 stdin과
stdout으로 줄 단위 JSON-RPC 메시지를 주고받습니다.

`opencode acp`는 자체적으로 사용할 비공개 OpenCode 서버를 시작합니다. 공유 백그라운드 서비스에 연결하지 않으며,
ACP용 네트워크 포트도 열지 않습니다. 프로세스 하나로 여러 ACP 세션을 처리할 수 있으며, 클라이언트가 stdin을 닫으면
종료됩니다.

### 기능

OpenCode의 `initialize` 응답에는 다음 에이전트 기능(capability)이 포함됩니다.

```json
{
  "loadSession": true,
  "mcpCapabilities": { "http": true, "sse": false },
  "promptCapabilities": { "embeddedContext": true, "image": true },
  "sessionCapabilities": {
    "additionalDirectories": {},
    "close": {},
    "delete": {},
    "fork": {},
    "list": {},
    "resume": {}
  }
}
```

OpenCode는 다음 클라이언트 기능을 읽습니다.

| 기능 | 효과 |
| --- | --- |
| `auth.terminal`을 `true`로 설정 | 인증 방법이 [터미널 인증 방법](#authentication)이 됩니다. |
| `elicitation.form` | OpenCode가 [질문](#questions)을 양식으로 묻습니다. |
| `session.compaction` | OpenCode가 ACP 업데이트로 [컨텍스트 압축](#compaction)을 보고합니다. |
| `_meta["terminal-auth"]`를 `true`로 설정 | 인증 방법에 [로그인 명령](#authentication)이 포함됩니다. |

### 세션

클라이언트는 세션을 만들 때 작업 디렉터리를 지정합니다. OpenCode는 해당 디렉터리의 구성을 사용하며, 여기에는 모델,
에이전트, 명령, 스킬, 지침, 플러그인, MCP 서버가 포함됩니다.

- `cwd`는 절대 경로여야 합니다. 상대 경로 `cwd`는 invalid params 오류로 거부됩니다.
- `session/load`는 저장된 메시지를 재생합니다. `session/resume`과 `session/fork`는 재생하지 않습니다.
- 세션을 로드, 재개, 포크하려면 클라이언트가 해당 세션의 디렉터리를 `cwd`로 전달해야 합니다. 다른 `cwd`는 invalid
  params 오류로 거부됩니다.
- `session/list`는 페이지당 최대 100개의 세션을 반환합니다. `cwd` 필터와 `cursor`를 받습니다.
- `session/close`는 진행 중인 작업을 중단하고 세션을 ACP 프로세스에서 분리합니다. 저장된 세션은 유지됩니다.
- `session/delete`는 `session/cancel`처럼 진행 중인 프롬프트를 종료한 다음 세션을 제거합니다. 존재하지 않는 세션을
  삭제해도 성공으로 처리됩니다.
- 세션은 한 번에 프롬프트 하나만 실행합니다. 첫 번째 프롬프트가 진행 중일 때 두 번째 `session/prompt`를 보내면
  OpenCode가 오류를 반환합니다.

### 취소

`session/cancel`은 진행 중인 프롬프트를 `stopReason: "cancelled"`로 종료합니다. 프롬프트 요청에 대한
`$/cancel_request`도 같은 효과가 있습니다. OpenCode는 대기 중인 권한 요청을 거부하고, 취소 후에도 끝나지 않은 도구
호출은 `failed`로 보고합니다.

### 추가 디렉터리

클라이언트는 `session/new`, `session/load`, `session/resume`, `session/fork`에 `additionalDirectories`를 전달할 수
있습니다.

```json
{ "cwd": "/work/app", "additionalDirectories": ["/work/shared"], "mcpServers": [] }
```

- 각 항목은 `*`나 `?`가 없는 절대 경로여야 합니다.
- OpenCode는 각 루트 안에서 외부 디렉터리 접근을 허용합니다. 읽기, 편집, 셸 권한 규칙은 그대로 적용됩니다.
- [additional directories RFD](https://agentclientprotocol.com/rfds/additional-directories)에 명시된 대로, 각 요청의
  목록은 세션의 이전 목록을 대체합니다.
- OpenCode는 허용 목록을 세션에 저장하므로 다른 OpenCode 클라이언트가 세션을 사용할 때도 적용됩니다. 하위 세션은
  생성될 때 허용 목록을 복사합니다.

`session/list`는 각 세션에 저장된 목록을 `additionalDirectories`로 반환합니다.

### 구성 옵션

새 세션은 디렉터리의 기본 모델과 주 에이전트(primary agent)를 사용합니다. `session/new`, `session/load`,
`session/resume`, `session/fork`의 응답에는 다음 구성 옵션이 포함됩니다.

| ID | 범주 | 값 |
| --- | --- | --- |
| `model` | `model` | 활성화된 모델을 `provider/model` 형식으로 지정합니다. `/variant` 접미사를 붙이면 effort도 함께 설정됩니다. |
| `effort` | `thought_level` | 모델의 변형과 `default`입니다. 변형이 있는 모델에만 있습니다. |
| `mode` | `mode` | 표시되는 주 에이전트입니다. |

`session/set_config_option`은 문자열 값을 받습니다.

```json
{ "sessionId": "ses_123", "configId": "model", "value": "anthropic/claude-sonnet-4" }
```

`session/set_mode`로도 에이전트를 설정할 수 있습니다. 사용 가능한 모델이나 에이전트가 바뀌면 OpenCode가
`config_option_update`를 보냅니다. 다른 클라이언트가 세션의 모델이나 에이전트를 변경할 때도 보냅니다.

### 프롬프트 콘텐츠

프롬프트에는 텍스트, 이미지, 임베디드 리소스, 리소스 링크를 넣을 수 있습니다. OpenCode는 오디오 블록을 무시하며,
나머지 블록은 다음과 같이 처리합니다.

| 블록 | OpenCode의 처리 방식 |
| --- | --- |
| `text` | 모델에 보냅니다. |
| audience가 `assistant`뿐인 `text` | 사용자 메시지와 분리된 별도 컨텍스트로 모델에 보냅니다. |
| audience가 `user`뿐인 `text` | 모델 입력에서 제외합니다. |
| `data`가 있는 `image` | 프롬프트에 첨부합니다. |
| `uri`만 있는 `image` | 리소스 링크로 처리합니다. |
| `text`가 있는 `resource` | 리소스의 경로나 URI 뒤에 텍스트를 인라인으로 넣습니다. |
| `blob`이 있는 `resource` | `mimeType`이 있으면 첨부하고, 없으면 버립니다. |
| `file://` URI를 가리키는 `resource_link` | 파일을 첨부합니다. 파일이 없거나 읽을 수 없으면 대신 Markdown 링크를 보냅니다. |
| `path` 쿼리가 있는 `zed://` URI를 가리키는 `resource_link` | `path`의 파일을 첨부합니다. |
| 그 밖의 URI를 가리키는 `resource_link` | `[spec](https://example.com/spec.md)` 같은 Markdown 링크를 보냅니다. |

audience는 블록의 `annotations`에서 가져옵니다. `data`와 `uri`가 모두 없는 `image` 블록은 거부됩니다. 다음 블록은
모델에만 전달되는 컨텍스트입니다.

```json
{ "type": "text", "text": "Open file: src/app.ts", "annotations": { "audience": ["assistant"] } }
```

### 명령

`session/new`, `session/load`, `session/resume`, `session/fork` 후에 OpenCode는 디렉터리의 명령과 내장 `compact`
명령이 담긴 `available_commands_update`를 보냅니다. 명령이 바뀌면 업데이트를 다시 보냅니다.

```json
{
  "sessionUpdate": "available_commands_update",
  "availableCommands": [{ "name": "compact", "description": "Compact the session" }]
}
```

프롬프트가 `/`와 사용 가능한 명령 이름으로 시작하면, OpenCode는 나머지 텍스트를 인자로 해당 명령을 실행합니다. `/`로
시작하는 그 밖의 텍스트는 일반 프롬프트로 보냅니다. `/compact`는 [컨텍스트 압축](/compaction)을 실행합니다.

### MCP 서버

클라이언트는 `session/new`, `session/load`, `session/resume`, `session/fork`에 stdio 및 HTTP MCP 서버를 전달할 수
있습니다. OpenCode는 `opencode acp` 프로세스가 실행되는 동안 이 서버를 세션의 디렉터리에 추가하므로, 같은 디렉터리의
다른 세션에서도 사용할 수 있습니다. 이 서버에는 HTTP 헤더를 그대로 전달하며 OAuth는 사용하지 않습니다. SSE를 통한
MCP는 광고하지 않으며, ACP를 통한 MCP는 지원하지 않습니다.

```json
{ "type": "http", "name": "docs", "url": "https://mcp.example.com", "headers": [] }
```

### 권한

권한 요청은 세 가지 옵션을 제공합니다.

```json
[
  { "optionId": "once", "kind": "allow_once", "name": "Allow once" },
  { "optionId": "always", "kind": "allow_always", "name": "Always allow" },
  { "optionId": "reject", "kind": "reject_once", "name": "Reject" }
]
```

파일을 변경하는 요청이면 OpenCode는 변경 사항의 미리 보기를 만들 수 있는 경우 `diff` 콘텐츠를 포함합니다.

### 질문

클라이언트가 `elicitation.form`을 광고하면 OpenCode는 양식 모드의 `elicitation/create`로 질문합니다. OpenCode가 해당
도구 호출을 이 세션의 `session/update`로 보낸 경우 요청에 `toolCallId`가 포함됩니다.

```json
{
  "mode": "form",
  "sessionId": "ses_123",
  "toolCallId": "call_1",
  "message": "Which package manager?",
  "requestedSchema": {
    "type": "object",
    "properties": { "pm": { "type": "string", "oneOf": [{ "const": "bun", "title": "Bun" }] } },
    "required": ["pm"]
  }
}
```

- OpenCode는 비밀 정보를 수집할 수 있는 양식은 보내지 않습니다.
- 필드가 옵션 외에 직접 입력한 답변도 받는다면, 스키마에 선택적 `<key>_custom` 문자열 속성이 추가됩니다. 단일
  선택에서는 비어 있지 않은 직접 입력 답변이 선택한 옵션을 대체합니다. 다중 선택에서는 선택한 옵션에 추가됩니다.
- 사용자가 양식을 거절하거나 취소하면 OpenCode는 질문을 취소합니다.

OpenCode가 질문을 표시할 수 없으면 질문을 취소하고 답변 없이 계속 진행하도록 모델에 알립니다.

### 컨텍스트 압축

클라이언트가 `session.compaction`을 광고하면 OpenCode는 ACP의
[session compaction](https://agentclientprotocol.com/rfds/session-compaction) RFD(Preview 단계)에 정의된
`compaction_update`와 `compaction_summary_chunk` 업데이트로 컨텍스트 압축을 보고합니다. 클라이언트가 세션을 로드하면
OpenCode는 완료되었거나 실패한 각 압축을 업데이트 하나로 재생합니다.

```json
{
  "sessionUpdate": "compaction_update",
  "compactionId": "msg_123",
  "status": "completed",
  "summary": [{ "type": "text", "text": "..." }]
}
```

다른 클라이언트는 대신 [압축 마커](#compaction-marker)를 받습니다. 하위 세션의 압축도 마찬가지입니다.

### 사용량

프롬프트 응답에는 [end-turn usage](https://agentclientprotocol.com/rfds/end-turn-token-usage) RFD(초안)에 정의된
`usage`가 포함됩니다. `usage`는 이 세션에서 해당 프롬프트가 수행한 모델 호출을 합산하며, 하위 세션은 포함하지
않습니다.

```json
{ "stopReason": "end_turn", "usage": { "inputTokens": 1200, "outputTokens": 340, "totalTokens": 1540 }, "_meta": {} }
```

응답 전에 OpenCode는 [session usage](https://agentclientprotocol.com/rfds/session-usage) RFD에 정의된 `usage_update`를
보냅니다. 프롬프트가 토큰을 사용했고 OpenCode가 모델의 컨텍스트 크기를 알고 있을 때만 보냅니다. `cost`는 세션의
총비용(USD)입니다.

```json
{ "sessionUpdate": "usage_update", "used": 1540, "size": 200000, "cost": { "amount": 0.012, "currency": "USD" } }
```

### 하위 세션

프롬프트가 실행되는 동안 OpenCode는 하위 세션의 업데이트를 프롬프트 세션의 `session/update` 알림으로 보냅니다. 각
업데이트에는 `_meta["opencode/child-session"]`이 포함됩니다. 도구 호출 ID 앞에는 `<childSessionId>:`가 붙고, 하위
세션에 제목이 있으면 도구 호출 제목 앞에 하위 세션 제목이 붙습니다.

```json
{
  "sessionUpdate": "tool_call",
  "toolCallId": "ses_child:call_1",
  "title": "Explore the codebase: src/app.ts",
  "_meta": {
    "opencode/child-session": { "id": "ses_child", "parentID": "ses_123", "depth": 1, "title": "Explore the codebase" }
  }
}
```

| 필드 | 유형 | 설명 |
| --- | --- | --- |
| `id` | `string` | 하위 세션의 ID입니다. |
| `parentID` | `string` | 하위 세션의 상위 세션 ID입니다. |
| `depth` | `number` | 프롬프트 세션의 하위 세션이면 1, 그 하위 세션의 하위 세션이면 2와 같은 식으로 증가합니다. |
| `title` | `string` | 하위 세션의 제목입니다. 하위 세션에 제목이 없으면 생략됩니다. |

하위 세션의 권한 요청에는 `toolCall._meta`에 같은 키가 포함됩니다. 프롬프트가 끝나면 OpenCode는 하위 세션 업데이트를
더 이상 보내지 않습니다. 하위 세션의 권한 요청과 질문은 계속 클라이언트에 전달됩니다.

### 재시도 상태

모델 호출이 실패해 OpenCode가 재시도를 예약하면 `_meta["opencode/retry"]`가 포함된 `session_info_update`를 보냅니다.
재시도가 시작되면 `"opencode/retry": null`을 보냅니다. 프롬프트 응답이 도착하면 재시도 상태를 모두 지우세요.

```json
{
  "sessionUpdate": "session_info_update",
  "_meta": {
    "opencode/retry": {
      "attempt": 1,
      "nextRetryAt": "2026-10-02T12:00:05.000Z",
      "error": { "type": "provider.rate-limit", "message": "Rate limit exceeded", "status": 429 }
    }
  }
}
```

| 필드 | 유형 | 설명 |
| --- | --- | --- |
| `attempt` | `number` | 재시도 횟수입니다. |
| `nextRetryAt` | `string` | 다음 시도 시각이며 ISO 8601 형식입니다. |
| `error` | `object` | `type`과 `message`를 포함합니다. 제공자가 보낸 경우 `status`와 `response.body`도 포함합니다. |

### 압축 마커

클라이언트가 `session.compaction`을 광고하지 않으면 OpenCode는 `_meta["opencode/compaction"]`이 포함된
`session_info_update`로 압축 진행 상황을 보고합니다. 하위 세션의 압축에는 항상 이 마커를 사용합니다.

```json
{
  "sessionUpdate": "session_info_update",
  "_meta": { "opencode/compaction": { "status": "started", "messageId": "msg_123", "reason": "auto" } }
}
```

| 필드 | 유형 | 설명 |
| --- | --- | --- |
| `status` | `string` | `started`, `completed`, `failed` 중 하나입니다. 취소된 압축은 `failed`입니다. |
| `messageId` | `string` | 압축의 시작과 끝을 연결합니다. 불투명한 키로 취급하세요. |
| `reason` | `string` | `auto` 또는 `manual`입니다. |
| `error` | `object` | `status`가 `failed`일 때 포함됩니다. [재시도](#retry-status)의 `error`와 형식이 같습니다. |

마커에는 요약이 포함되지 않습니다. 자동 압축은 `started` 마커 없이 실패할 수 있습니다. 클라이언트가 세션을 로드하면
OpenCode는 완료되었거나 실패한 각 압축을 마커 하나로 재생합니다.
