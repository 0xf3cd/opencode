프로젝트에서 CLI를 실행하면 전체 화면 터미널 인터페이스가 열립니다.

```bash
opencode
```

다른 프로젝트에서 작업하려면 디렉터리를 전달하세요.

```bash
opencode ~/code/my-project
```

권장 터미널:

- [Ghostty](https://ghostty.org)
- [WezTerm](https://wezterm.org)
- [Alacritty](https://alacritty.org)
- [Kitty](https://sw.kovidgoyal.net/kitty/)

트루컬러를 지원하는 터미널에서는 테마 색상이 가장 정확하게 표시됩니다. 지원하지 않는 터미널에서는 사용 가능한
팔레트로 근사한 색상을 사용합니다.

## 자동화

대화형 인터페이스를 열지 않고 프롬프트를 제출하려면 `opencode run`을 사용하세요. 스크립트, CI 작업 등 모델 출력을
터미널에서 바로 받아야 하는 워크플로를 위해 설계되었습니다.

```bash
opencode run "Explain this repository"
```

## Mini

전체 화면 TUI 대신 OpenCode의 최소 대화형 인터페이스를 시작하려면 `opencode mini`를 사용하세요.

```bash
opencode mini
```

세션, 모델, 에이전트, 프롬프트, 재생 옵션을 확인하려면 `opencode mini --help`를 실행하세요.

## 백그라운드 서비스

기본적으로 OpenCode는 사용자 계정마다 하나의 공유 백그라운드 서버를 찾거나 시작합니다. 모든 로컬 OpenCode
클라이언트는 이 서버에 연결하며, 세션, 구성, 통합, 권한, 도구 실행은 모두 이 서버가 담당합니다.

비공개 서버로 실행하려면 `--standalone`을, 특정 서버 URL에 연결하려면 `--server`를 사용하세요.

```bash
opencode --standalone
opencode --server http://localhost:4096
```

CLI 명령이 공유 서비스를 시작하지 않고 기본적으로 비공개 서버를 사용하게 하려면 공유 서비스를 비활성화하세요.

```bash
opencode service set disabled true
opencode
```

이 명령은 실행 중인 백그라운드 서비스를 중지합니다. 비활성화한 뒤에도 `--server`로 명시적으로 지정한 서버에 연결할 수
있고, `opencode service start`로 공유 서비스를 직접 시작할 수도 있습니다. 서비스 자동 사용으로 되돌리려면
`opencode service unset disabled`를 실행하세요. 페어링은 공유 서비스가 필요하므로 비활성화된 동안에는 사용할 수
없습니다.

공유 서비스 진단은 [문제 해결](/troubleshooting)을, 서버 엔드포인트는 [API 레퍼런스](/api)를 참고하세요.

## 경로

다른 도구에서 사용할 특정 로컬 경로를 출력합니다.

```bash
opencode debug paths db
sqlite3 "$(opencode debug paths db)"
```

선택 인자로 `db`, `home`, `data`, `config`, `cache`, `state`, `tmp`, `bin`, `log`, `repos` 중 하나를 지정할 수 있으며,
경로와 줄바꿈만 출력합니다. 데이터베이스 경로는 릴리스 채널과 `OPENCODE_DB`를 따릅니다. 데이터베이스 경로를 상대
경로로 재정의하면 데이터 디렉터리를 기준으로 해석되며, `:memory:`는 그대로 출력됩니다. 이 명령은 서버를 시작하거나
데이터베이스를 열지 않습니다.

선택 인자를 생략하면 모든 경로를 레이블과 함께 표시합니다.

```bash
opencode debug paths
```

## 제거

제거될 파일과 설치를 미리 확인합니다.

```bash
opencode uninstall --dry-run
```

제거를 확정하려면 `opencode uninstall`을 실행하세요. OpenCode는 등록된 백그라운드 서비스와 영구 터미널을 중지한 뒤,
OpenCode 버전과 채널이 함께 사용하는 전역 캐시 디렉터리를 제거합니다. 세션 데이터, 구성, 상태는 제거되지 않습니다.

- `--force`(`-f`)는 확인 절차를 건너뜁니다. 비대화형으로 제거할 때 사용하세요.
- 패키지 관리자로 설치한 경우 감지된 패키지 관리자를 사용해 제거합니다. curl로 설치한 경우 실행 파일을 직접 제거하는
  마지막 명령을 출력합니다.
