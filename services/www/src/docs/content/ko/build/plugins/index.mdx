플러그인으로 OpenCode의 동작을 변경하고 새 기능을 추가할 수 있습니다. 터미널 UI를 변경하려면 [CLI
플러그인](/build/plugins/cli)을 만드세요.

기존 OpenCode 1 플러그인을 마이그레이션하고 있다면 [V1 플러그인 마이그레이션 가이드](/build/plugins/migrate-v1)를
따르세요.

```ts title=".opencode/plugins/example/index.ts"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "example",
  async setup(ctx) {
    await ctx.storage.set("loaded", true)
  },
})
```

위의 로컬 예제처럼 `.opencode/plugins/` 아래에 있는 플러그인은 자동으로 로드됩니다. 게시된 패키지나 다른 위치에 있는
플러그인 디렉터리를 로드하려면 `opencode.json(c)`의 `plugins`에 추가하세요.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": [
    "opencode-acme-plugin",
    "opencode-acme-plugin@1.2.0",
    "@acme/opencode-plugin",
    "./plugins/local",
    "../shared/plugin",
    "/absolute/path/plugin",
    "file:///home/me/plugins/local",
    {
      "package": "@acme/opencode-plugin",
      "options": {
        "agent": "reviewer",
        "strict": true,
      },
    },
  ],
}
```

로드 및 구성 옵션에 대한 자세한 내용은 [플러그인 구성](/plugins)을 참고하세요.

## 수명 주기

`setup`은 플러그인이 로드될 때 실행됩니다. 플러그인이 언로드될 때 실행할 정리 함수를 반환할 수 있습니다.

```ts
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "example",
  setup(ctx) {
    console.log(`loaded in OpenCode ${ctx.app.version}`)
    return () => console.log("unloaded")
  },
})
```

### 컨텍스트

플러그인 컨텍스트는 본질적으로 [OpenCode 서버 클라이언트](/build/client)입니다. 읽기 메서드와 작업 메서드는
클라이언트와 같은 입력과 응답을 사용합니다. 여기에 변환, 런타임 훅, 다시 로드, 등록, 플러그인 옵션을 위한 플러그인
전용 메서드가 추가됩니다.

```ts
setup(ctx) {
  console.log(ctx.app.version)
}
```

`ctx.location`은 이 플러그인 인스턴스가 로드된 위치를 나타냅니다. 여기에는 `directory`, 선택적인 `workspaceID`,
`project` 메타데이터(`id`, `directory`, `canonical`)가 포함됩니다. Promise 플러그인과 Effect 플러그인 모두에서 사용할
수 있습니다. 이는 플러그인 인스턴스의 위치이며, 플러그인이 접근할 수 있는 모든 세션이나 수신하는 모든 이벤트의 위치를
뜻하지는 않습니다.

```ts
setup(ctx) {
  console.log(ctx.location.directory)
  console.log(ctx.location.project.canonical)
}
```

### 옵션

플러그인 옵션은 `opencode.json(c)`에서 객체 형식으로 전달합니다.

```jsonc title="opencode.jsonc"
{
  "plugins": [
    {
      "package": "./plugins/company",
      "options": {
        "strict": true,
      },
    },
  ],
}
```

`setup`에서 `ctx.options`로 해당 값을 읽습니다.

```ts title="plugins/company/index.ts"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "company",
  setup(ctx) {
    const strict = ctx.options.strict === true
  },
})
```

## 변환

변환(transform)은 OpenCode 도메인 상태에 대한 동기식 편집이며, 각 변환은 같은 도메인에서 앞서 등록된 내용 위에
적용됩니다. `ctx.model.list()` 같은 레지스트리 읽기에는 플러그인 설정 중을 포함해 지금까지의 모든 등록이 반영됩니다.
시작 시 일괄 처리는 업데이트 알림을 합칠 뿐, 읽기 결과를 지연시키지 않습니다. 리소스 상태 API는 여전히 실행 중인
리소스의 상태를 보고합니다. 정의가 등록되었다고 해서 연결이나 기타 리소스 작업이 완료되었다는 뜻은 아닙니다.

소스는 `ctx.provider.transform`을 통해 제공자와 변경할 수 없는 모델 정의를 추가합니다.

```ts title="plugins/models/index.ts"
import { Model, Plugin, Provider } from "@opencode/plugin"

export default Plugin.define({
  id: "company.models",
  async setup(ctx) {
    const providerID = Provider.ID.make("acme")
    const models = [{ ...Model.Info.default(providerID, Model.ID.make("reasoner")), name: "Acme Reasoner" }]
    await ctx.provider.transform((editor) => {
      editor.add({
        info: {
          ...Provider.Info.empty(providerID),
          name: "Acme",
          activation: "enabled",
          package: "@opencode/ai/providers/openai-compatible",
          settings: { baseURL: "http://127.0.0.1:8000/v1" },
        },
        models,
      })
    })

    const available = await ctx.model.list()
  },
})
```

등록, 제거, `reload()`가 일어나면 레지스트리가 변경된 것으로 표시되고, 다음 읽기에서 활성 변환을 모두 등록 순서대로
새 값에 다시 적용해 레지스트리를 재구성합니다. 변환은 가볍고 반복 실행해도 안전하게 유지하세요. 이미 읽은 값은 이후
재구성으로 변경되지 않습니다.

제공자 변환과 사용 가능 여부가 확정되면 OpenCode는 활성 제공자의 모델을 구체화하고 모든 모델 변환을 순서대로 다시
적용합니다. 모델 정책은 새로 갱신된 소스를 포함해 전체 후보 컬렉션을 검사할 수 있습니다.

```ts title="plugins/model-budget/index.ts"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "company.model-budget",
  async setup(ctx) {
    await ctx.model.transform((editor) => {
      editor
        .list()
        .filter((model) => model.cost.some((tier) => tier.output > 20))
        .forEach((model) => {
          editor.remove(model.providerID, model.id)
        })
    })
  },
})
```

캡처한 입력은 자동으로 감시되지 않습니다. 동기식 콜백 전에 외부 데이터를 로드하고, 해당 입력이 바뀌면 `reload()`를
호출하세요. 다음 예제에서 `loadFromSource()`는 `{ info: Provider.Info, models: readonly Model.Info[] }` 항목을
반환합니다.

```ts title="plugins/models/index.ts"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "company.models",
  async setup(ctx) {
    const source = { providers: await loadFromSource() }

    await ctx.provider.transform((editor) => {
      source.providers.forEach((provider) => editor.add(provider))
    })

    const refresh = async () => {
      source.providers = await loadFromSource()
      await ctx.provider.reload()
    }

    const timer = setInterval(() => void refresh().catch(console.error), 60_000)
    return () => clearInterval(timer)
  },
})
```

제공자가 변경되면 활성 모델 결과 전체가 무효화되므로, 출력 가격 정책은 갱신된 모델에도 그대로 적용됩니다. 모델
변환이 캡처한 입력만 바뀐 경우에는 `ctx.model.reload()`를 사용하세요.

## API

### 에이전트

모든 에이전트를 읽거나 ID로 하나를 가져옵니다.

```ts
const agents = await ctx.agent.list()
const build = await ctx.agent.get({ agentID: "build" })
```

변환을 등록해 에이전트를 검사, 수정, 제거하거나 기본 에이전트를 선택합니다.

```ts
await ctx.agent.transform((editor) => {
  const agents = editor.list()
  const build = editor.get("build")

  editor.default("build")
  editor.update("build", (agent) => {
    agent.description = "Builds features and fixes bugs"
  })
  editor.remove("legacy")
})
```

변환이 사용하는 외부 상태가 바뀌면 에이전트를 다시 로드하세요.

```ts
await ctx.agent.reload()
```

#### 참조

스키마: [`Agent.Info`](/api#schema-Agent.Info)


### 제공자

사용 가능한 제공자를 읽거나 ID로 특정 제공자의 메타데이터를 확인합니다.

```ts
const providers = await ctx.provider.list()
const provider = await ctx.provider.get({ providerID: "anthropic" })
```

제공자 변환은 제공자 설정과 소스 정의를 편집합니다. 편집기에서 읽는 값에는 비활성 제공자도 포함되며 변경할 수 없는
정의가 노출됩니다. `models.update`는 소스 모델의 자체 복사본을 편집합니다.

```ts
await ctx.provider.transform((editor) => {
  editor.update("anthropic", (provider) => {
    provider.headers = { ...provider.headers, "x-company": "engineering" }
  })
  editor.models.update("anthropic", "claude-sonnet-4-5", (model) => {
    model.name = "Team Sonnet"
  })
  editor.models.remove("anthropic", "legacy-model")
  editor.remove("legacy-provider")
})
```

`models.set`으로 제공자의 소스 모델 목록을 교체하고, 캡처한 정의가 바뀌면 다시 로드하세요.

```ts
const source = { models: await loadModels() }
await ctx.provider.transform((editor) => {
  editor.models.set("acme", source.models)
})

source.models = await loadModels()
await ctx.provider.reload()
```

계정별로 모델을 검색한다면 목록을 로드할 때 사용한 연결을 `sourceConnection`으로 전달하세요. 다른 연결이 선택되어
있으면 플러그인이 갱신된 목록을 게시할 때까지 OpenCode는 해당 제공자를 제외합니다.

```ts
const connection = await ctx.integration.connection.active("acme")
if (!connection) return
const inventory = await loadInventory(connection)
await ctx.provider.transform((editor) => {
  editor.add({ info: inventory.provider, models: inventory.models, sourceConnection: connection })
})
```

### 모델

사용 가능한 모델과 기본 선택을 읽습니다.

```ts
const models = await ctx.model.list()
const selected = await ctx.model.default()
```

모델 변환은 활성 제공자의 전체 후보 컬렉션을 편집합니다. 비활성화된 후보도 모든 변환이 끝날 때까지는 편집할 수
있습니다. `update`는 사용 가능한 제공자 아래에만 모델을 추가할 수 있습니다.

```ts
await ctx.model.transform((editor) => {
  editor.list("anthropic").forEach((model) => {
    editor.update(model.providerID, model.id, (draft) => {
      draft.enabled = draft.capabilities.tools
    })
  })
  editor.default.set("anthropic", "claude-sonnet-4-5")
  editor.remove("anthropic", "legacy-model")
})
```

콜백은 원시 모델 재정의를 편집합니다. 제공자 기본값은 OpenCode가 결과를 확정할 때 한 번 병합되며, 변경이 없으면
이후 읽기에서 그 결과를 재사용합니다. `editor.provider`는 모델 변환 결과가 아니라 비활성 템플릿을 포함한 변경할 수
없는 소스 정의를 노출합니다.

```ts
await ctx.model.transform((editor) => {
  const source = editor.provider.get("anthropic")?.models.get("claude-sonnet-4-5")
  if (!source) return
  editor.update("anthropic", source.id, (model) => {
    model.limit.context = Math.min(model.limit.context, source.limit.context)
  })
})

await ctx.model.reload()
```

### 명령

특정 위치에서 사용할 수 있는 명령을 읽습니다.

```ts
const commands = await ctx.command.list()
```

변환으로 명령을 등록합니다. 실행 함수는 세션, 프롬프트 첨부 파일, 요청된 전달 모드를 받습니다.

```ts
await ctx.command.transform((editor) => {
  editor.add({
    name: "security-review",
    description: "Review changes for security issues",
    execute: async ({ sessionID, prompt, delivery }) => {
      await ctx.session.prompt({
        ...prompt,
        sessionID,
        text: `Review these changes for security issues.\n\n${prompt.text}`,
        delivery,
      })
    },
  })
})
```

변환이 사용하는 외부 상태가 바뀌면 명령을 다시 로드하세요.

```ts
await ctx.command.reload()
```

### 통합

통합을 읽고 활성 자격 증명을 확인합니다.

```ts
const integrations = await ctx.integration.list()
const github = await ctx.integration.get({ integrationID: "github" })
const connection = await ctx.integration.connection.active("github")
const credential = connection ? await ctx.integration.connection.resolve(connection) : undefined
```

API 키로 통합을 연결합니다.

```ts
await ctx.integration.connect.key({
  integrationID: "github",
  key: process.env.GITHUB_TOKEN!,
})
```

OAuth 연결 시도를 시작, 확인, 완료하거나 취소합니다.

```ts
const attempt = await ctx.integration.oauth.connect({ integrationID: "github", methodID: "oauth" })
const status = await ctx.integration.oauth.status({ integrationID: "github", attemptID: attempt.data.attemptID })
await ctx.integration.oauth.complete({ integrationID: "github", attemptID: attempt.data.attemptID, code })
await ctx.integration.oauth.cancel({ integrationID: "github", attemptID: attempt.data.attemptID })
```

명령 기반 연결도 같은 시작, 상태 확인, 취소 흐름을 제공합니다.

```ts
const attempt = await ctx.integration.command.connect({ integrationID: "acme", methodID: "cli" })
const status = await ctx.integration.command.status({ integrationID: "acme", attemptID: attempt.data.attemptID })
await ctx.integration.command.cancel({ integrationID: "acme", attemptID: attempt.data.attemptID })
```

변환을 등록해 통합을 검사하고 인증 방법을 관리합니다.

```ts
await ctx.integration.transform((editor) => {
  const integrations = editor.list()
  const acme = editor.get("acme")

  editor.update("acme", (integration) => {
    integration.name = "Acme"
  })
  editor.method.update({
    integrationID: "acme",
    method: { id: "cli", type: "command", label: "Sign in with Acme CLI", command: ["acme", "login"] },
  })

  const methods = editor.method.list("acme")
  const legacy = methods.find((method) => method.type === "command" && method.id === "legacy")
  if (legacy) editor.method.remove("acme", legacy)
  editor.remove("legacy")
})
```

변환이 사용하는 외부 상태가 바뀌면 통합을 다시 로드하세요.

```ts
await ctx.integration.reload()
```

### MCP

### 도구

모든 변환이 적용된 후 현재 등록된 도구를 변환 콜백 밖에서 읽습니다. 각 도구에는 실제 적용되는 이름을 담은 `id`가
있습니다.

```ts
const tools = await ctx.tool.list()
const read = tools.find((tool) => tool.id === "read")
```

Promise 플러그인을 포함해 모든 플러그인에서 도구는 동기식 변환으로 등록, 수정, 제거합니다. 외부 데이터는 등록하거나
다시 로드하기 전에 로드하세요. 실제 도구 이름이 같으면 나중에 유효하게 등록된 쪽이 재정의합니다.

```ts
const registration = await ctx.tool.transform((editor) => {
  editor.namespace({
    name: "acme",
    description: "Customer account tools",
  })
  editor.add({
    name: "greeting",
    description: "Create a greeting",
    input: {
      type: "object",
      properties: { name: { type: "string" } },
      required: ["name"],
      additionalProperties: false,
    },
    options: { namespace: "acme", codemode: true },
    execute: async (input, context) => {
      await context.progress({ status: "greeting" })
      return { content: `Hello ${(input as { name: string }).name}!` }
    },
  })
})
```

Promise 도구 실행 함수는 `context.signal`을 받습니다. 세션을 중지할 때 내부 작업도 함께 중지되도록 `fetch` 같은
취소 가능한 작업에 이를 전달하세요.

```ts
execute: async ({ url }, context) => {
  const response = await fetch(url, { signal: context.signal })
  return { content: await response.text() }
}
```

콜백이 캡처한 소스 데이터를 변경한 후에는 `reload()`를 호출하세요. 다시 로드하면 활성 변환이 순서 변경 없이 다시
적용되며, 플러그인 설정은 다시 실행되지 않습니다.

```ts
await ctx.tool.reload()
```

편집기에 현재 있는 도구는 `list()`와 `get()`으로 확인합니다. 도구에는 실제 적용되는 이름을 담은 `id`가 있으며,
해당 ID가 없으면 `get()`은 `undefined`를 반환합니다. `update`와 `remove`에는 네임스페이스를 포함한 실제 도구 이름(위
예제의 `acme_greeting`)을 사용하세요. 네임스페이스의 점과 도구 이름에서 지원되지 않는 문자는 `_`로 바뀝니다. 존재하지
않는 이름은 무시되며, 도구를 새로 만들려면 완전한 정의로 `add`를 호출해야 합니다. 수정해도 이름과 네임스페이스는
유지됩니다. 스키마나 옵션을 바꾸려면 중첩된 값을 변경하지 말고 새 값을 할당하세요. 유효하지 않은 수정은 로그에
기록되며 이전 정의가 그대로 유지됩니다.

```ts
await ctx.tool.transform((editor) => {
  editor.update("acme_greeting", (tool) => {
    tool.description = "Greet the user by name"
  })
  editor.remove("acme_obsolete")
})
```

수정과 제거는 MCP 카탈로그가 갱신된 후를 포함해 추가 작업과 함께 순서대로 다시 적용됩니다. 해당 등록을 해제하면 그
변경 사항이 제거되고 나머지 변환으로 다시 구성됩니다.

등록을 해제(dispose)하면 해당 변환이 제거되고 나머지 변환으로 다시 구성되므로, 그 변환이 재정의했던 이전 정의가 다시
드러납니다. 해제는 여러 번 호출해도 결과가 같으며, 플러그인을 언로드해도 해당 플러그인의 등록이 해제됩니다.

```ts
await registration.dispose()
```

각 모델 요청은 안정적이고 실행 가능한 도구 스냅샷을 캡처합니다. 이후의 변환, 다시 로드, 해제는 앞으로의 스냅샷에만
영향을 주며, 이미 캡처된 정의, Code Mode 네임스페이스 설명, 실행 함수에는 영향을 주지 않습니다. 단, 변경 가능한
플러그인 데이터를 클로저로 참조하는 실행 함수는 그 데이터의 변경을 그대로 보게 됩니다. 값이 해당 정의에 고정되어야
한다면 변환 안에서 값을 캡처하세요.

감지된 저장소 유형이 아니라 ID로 제공자를 선택합니다(기본값은 Git). 위치에 아직 저장소가 없더라도 `init`이 있는

검색합니다. 새로운 저장소 형식은 이 콜백 외에 별도의 검색 지원이 여전히 필요합니다.


### Worktree

일반적인 플러그인 수명 주기를 사용해 로컬 worktree 전략을 등록합니다. 이 예제의 구현 모듈은 옵션 검증과 백엔드의
`create`, `remove`, `list` 작업을 담당합니다.

```ts title="plugins/worktrees/index.ts"
import { Plugin } from "@opencode/plugin"
import { makeStrategy } from "./strategy"

export default Plugin.define({
  id: "company.worktrees",
  async setup(ctx) {
    const strategy = makeStrategy(ctx.options)
    await ctx.worktree.transform((editor) => {
      editor.add(strategy)
    })
  },
})
```

`plugins`로 플러그인을 로드하고, 공통 대상 위치는 별도로 구성하세요.

```jsonc title="opencode.jsonc"
{
  "worktree": { "directory": "../worktrees" },
  "plugins": [{ "package": "./plugins/worktrees", "options": {} }],
}
```

- 전략을 추가하면 자동으로 선택됩니다. 마지막으로 활성화된 등록이 적용되므로 전략 선택 구성이 필요 없습니다.
- 등록을 해제하거나 플러그인을 언로드하면 이전 구현이 복원되며, 최종적으로는 기본 제공 Git 전략으로 돌아갑니다.
- `reload()`는 캡처한 입력이 바뀐 후 변환을 다시 적용하며, 플러그인 설정은 다시 실행하지 않습니다.
- 생성에 실패해도 Git으로 재시도하지 않습니다. 기존 worktree는 기본값이 바뀌어도 기록된 소유자를 유지합니다.
- 전략은 로컬 디렉터리를 관리합니다. 원격 워크스페이스 프로비저닝은 이 인터페이스의 범위가 아닙니다.

#### 작업

플러그인 컨텍스트는 클라이언트와 같은 프로젝트 기반 worktree 작업을 제공합니다. 모든 작업에는 `projectID`가
필요합니다. `list`는 같은 프로젝트의 알려진 체크아웃을 포함해 저장된 목록만 읽으며, 구성을 로드하거나 플러그인을
시작하거나 파일 시스템 변경 사항을 검색하지 않습니다.

```ts
const projectID = ctx.location.project.id
const created = await ctx.worktree.create({ projectID, name: "task" })
const inventory = await ctx.worktree.list({ projectID })
await ctx.worktree.refresh({ projectID })
await ctx.worktree.remove({ projectID, directory: created.directory, force: false })
```

생성 작업은 프로젝트에 저장된 `canonical` 디렉터리에서 구성과 플러그인을 로드하고, 거기서 선택된 전략을 사용합니다.
선택적으로 상위 `directory`, 소스 `from`, 시작 `branch`, `name`을 받습니다. 소스의 기본값은 정규 체크아웃이며,
`from`으로 재정의할 경우 같은 프로젝트에 속해야 합니다. 소스를 선택해도 구성 루트는 바뀌지 않습니다. 시작 ref를
지정하려면 선택된 전략이 이를 지원해야 합니다. 예를 들어 Rift의 네이티브 스냅샷 작업에는 ref 선택 옵션이 없습니다.

생성과 새로 고침은 정규 체크아웃의 플러그인이 활성화될 때까지 기다립니다. 해당 체크아웃의 플러그인 설정 중에 호출하면
지금까지의 등록만 반영되며, 자신의 활성화를 기다리지 않습니다.

제거 작업은 정규 구성을 로드하고 해당 플러그인을 활성화한 다음, 현재 선택된 기본 전략이 아니라 worktree에 기록된
전략을 사용합니다. 기록된 소유자를 사용할 수 없으면 오류가 발생합니다. worktree의 대상 위치는 다른 곳에 있어도
됩니다.

```ts
await ctx.worktree.remove({
  directory: "/worktrees/task",
  projectID,
  force: false,
})
```

소유자가 없으면 Git으로 대체하지 않고 제거가 실패합니다. 전략은 Core나 Git 오류에 의존하지 않고 강제 실행 확인을
요청하기 위해, `@opencode/plugin`에서 `Worktree`를 가져와 `new Worktree.OperationError({
message: "Uncommitted changes", forceRequired: true })`를 던질 수 있습니다.

새로 고침 작업은 정규 구성을 로드하고, 사용 가능한 모든 전략에 알려진 체크아웃 루트 전체에서 worktree를 찾도록
요청합니다. 결과를 합치고, 기록된 소유권을 유지하며, 없어진 디렉터리는 정리합니다. 검색에 실패한 소스는 로그에
기록되고 나머지 소스는 계속 진행됩니다. 존재하는 디렉터리는 어떤 전략도 보고하지 않더라도 저장된 상태로 유지됩니다.
변경된 목록을 읽으려면 `worktree.updated`를 관찰하고 `list`를 다시 호출하세요.

```ts
await ctx.worktree.refresh({ projectID })
```

#### 참조

구현은 이름 지정과 충돌 처리를 거친 권장 대상 위치를 받습니다. `create`에서는 실제 디렉터리를 반환하세요. 백엔드에
고유한 레이아웃이 필요하면 권장 위치와 다를 수 있습니다. OpenCode는 반환된 경로를 확인한 뒤 목록, 시작 명령, API
결과에 사용합니다. 반환된 디렉터리는 반드시 존재해야 합니다.

다른 대상 위치를 선택하는 전략은 그 위치에서의 이름 충돌을 직접 처리합니다. 그래도 OpenCode는 전략을 호출하기 전에
권장된 상위 디렉터리를 만듭니다. `list`는 전략이 소유한 디렉터리와 저장소 루트만 보고해야 합니다.

```ts
interface WorktreeDefinition {
  readonly id: string
  create(
    input: { sourceDirectory: string; directory: string; branch?: string },
    context: { signal: AbortSignal },
  ): Promise<{ directory: string }>
  remove(input: { directory: string; force: boolean }, context: { signal: AbortSignal }): Promise<void>
  list(
    sourceDirectory: string,
    context: { signal: AbortSignal },
  ): Promise<readonly { directory: string; type: "root" | "worktree" }[]>
}

interface WorktreeEditor {
  add(definition: WorktreeDefinition): void
}

interface WorktreeDomain extends WorktreeApi {
  transform(callback: (editor: WorktreeEditor) => void): Promise<Registration>
  reload(): Promise<void>
}
```

Promise 콜백은 `signal` 취소에 협조해야 합니다. Effect 콜백은 Effect를 반환하며 대신 Effect 중단(interruption)을
사용합니다. 등록은 플러그인 런타임 범위로 유지되며, 프로젝트 작업은 정규 체크아웃의 레지스트리를 사용합니다. Core
구성 어댑터가 디렉터리 설정을 그 레지스트리에 전달합니다.

### 웹 검색

웹 검색 제공자를 나열하거나 선택한 제공자로 검색을 실행합니다.

```ts
const providers = await ctx.websearch.providers()
const results = await ctx.websearch.query({ query: "OpenCode plugins", providerID: "internal" })
```

변환으로 제공자를 등록하고 기본 제공자를 선택합니다.

```ts
await ctx.websearch.transform((editor) => {
  editor.add({
    id: "internal",
    name: "Internal search",
    execute: async ({ query }, { signal }) => {
      const response = await fetch(`https://search.example.com?q=${encodeURIComponent(query)}`, { signal })
      const result = await response.json()
      return [{ url: result.url, title: result.title, content: result.content, time: {} }]
    },
  })
  editor.default.set("internal")
})
```

`false`를 선택해 웹 검색을 비활성화하거나, 외부 상태가 바뀐 후 제공자를 다시 로드합니다.

```ts
await ctx.websearch.transform((editor) => editor.default.set(false))
await ctx.websearch.reload()
```

## 훅

훅은 진행 중인 작업을 가로챕니다. 훅을 해당 도메인에 등록하고, 더 이상 필요하지 않으면 반환된 등록을 해제하세요.

```ts
const registration = await ctx.session.hook("context", () => {})
await registration.dispose()
```

여러 플러그인이 같은 훅을 등록할 수 있습니다. OpenCode는 플러그인 순서대로 훅을 실행하므로, 나중 훅은 앞선 훅이 만든
변경 사항을 볼 수 있습니다.

### 세션

세션 훅은 프롬프트 수락, 모델 호출, 네이티브 HTTP, 재시도를 가로챕니다.

#### 프롬프트 수락

들어오는 사용자 프롬프트를 첨부 파일 및 스킬 확인과 영구 인박스 수락(admission) 전에 가로챕니다.

```ts
await ctx.session.hook("prompt", (event) => {
  event.prompt.text = event.prompt.text.replaceAll("company-secret", "[redacted]")
  event.prompt.files ??= []
  event.prompt.files.push({ uri: "file:///project/policy.md" })
  event.metadata = { ...event.metadata, source: "company-policy" }
  event.delivery = "queue"
})
```

훅은 직접 수정할 수 있는 초안 객체를 받습니다.

- `prompt`에는 `text`, `files`, `agents`의 에이전트 멘션, 선택된 `skills`가 포함됩니다.
- `metadata`에는 애플리케이션에서 정의한 수락 메타데이터가 포함됩니다.
- `delivery`의 기본값은 `"steer"`이며 `"queue"`로 바꿀 수 있습니다.
- 세션 ID와 메시지 ID는 읽기 전용이므로 훅이 수락 대상을 바꿀 수 없습니다.

훅이 추가한 파일과 스킬은 일반적인 확인 및 검증 과정을 거칩니다. 텍스트를 다시 쓸 때는 더 이상 맞지 않는 첨부 파일
`mention` 오프셋을 수정하거나 제거하세요. 에이전트 멘션은 세션의 활성 에이전트를 전환하지 않습니다.

프롬프트 훅은 다음 조건에서 실행됩니다.

- 세션 위치의 플러그인이 준비된 후 등록 순서대로 실행됩니다.
- `session.prompt`를 통해 제출하는 명령은 훅을 실행합니다.
- 합성 메시지, 셸 메시지, 압축 제어, 이동 제어는 훅을 실행하지 않습니다.
- 훅은 모델 호출마다가 아니라 수락 시 한 번 실행됩니다.
- 모델 확인이 수락 이후에 이루어지므로 제공자 범위 지정은 사용할 수 없습니다.

수정한 내용이 영구 저장되는 정식 사용자 입력이 됩니다. 준비 과정이 실패하거나 중단되면 OpenCode는 프롬프트를
수락하지 않습니다.

프롬프트 훅은 재시도해도 안전하게 작성하세요. 프롬프트 훅은 부수 효과가 정확히 한 번만 일어나도록 보장하는 지점이
아닙니다.

- 이미 대기 중이거나 전달된 ID로 재시도하면 훅을 다시 실행하지 않고 원래 수락 결과를 반환합니다.
- 동시에 제출하면 훅이 여러 번 실행될 수 있지만, 처음으로 성공한 수락만 적용됩니다.
- 프롬프트 훅은 입력을 변환할 뿐이며, 타입이 지정된 거부 API를 제공하지 않습니다.

#### 모델 요청

모델에 요청을 보내기 직전에 조합된 시스템 지침, 메시지, 도구, 요청 옵션을 수정합니다. 세션이 보내는 요청 종류마다
별도의 훅이 있으므로, 플러그인은 에이전트 루프와 보조 요청을 다르게 처리할 수 있습니다.

- `context`는 도구 호출로 이어지는 후속 요청을 포함해 에이전트 루프에서 실행됩니다.
- `compaction`은 체크포인트 요약에서 실행됩니다. `messages`는 요약할 대화 기록이며, OpenCode는 훅이 실행된 후 요약
  프롬프트를 덧붙입니다. `result`를 설정하면 직접 압축 결과를 기록하고 모델 호출을 건너뜁니다. 이 값은 완료된 압축
  메시지와 같은 필드를 받습니다.
- `generate`는 일회성 `ctx.session.generate` 호출에서 실행됩니다.
- `title`은 제목 생성에서 실행됩니다. `agent`와 `tools`가 없습니다. `result`를 설정하면 제목을 직접 지정할 수 있습니다.

```ts
await ctx.session.hook("context", (event) => {
  event.system.push({ type: "text", text: "Keep the review focused on correctness." })
  delete event.tools.write
  event.options.temperature = 0.2
  event.options.maxTokens = 8_000
})

await ctx.session.hook("compaction", async (event) => {
  event.result = { summary: await summarize(event.messages) }
})
```

변경 사항은 나가는 모델 호출에만 적용되며, 저장된 기록이나 구성에는 영향을 주지 않습니다. 모든 요청에 적용해야 하는
훅은 요청 종류마다 등록해야 합니다.

요청 재정의는 다음 규칙을 따릅니다.

- `options`는 모델 호출마다 빈 상태로 시작하며, 확정된 모델 설정을 담고 있지 않습니다.
- 타입이 지정된 키는 생성 설정이며, 그 밖의 키는 제공자 옵션으로 선택된 프로토콜에 전달됩니다.
- 훅은 등록 순서대로 실행되며 앞선 훅이 만든 재정의를 볼 수 있습니다.
- 요청 재정의는 모델 기본값보다 우선 적용되고, 모델 기본값은 라우트 기본값보다 우선 적용됩니다.
- 제공자 옵션 객체는 재귀적으로 병합되며, 배열과 스칼라 값은 이전 값을 대체합니다.
- 재정의를 삭제하거나 `undefined`로 설정하면 기본값이 제거되는 것이 아니라 구성된 기본값으로 대체됩니다.
- 원시 HTTP 본문 오버레이는 프로토콜 변환 후에 적용되며, 변환 결과 필드를 재정의할 수 있습니다.

#### 제공자 옵션

제공자 옵션에는 원시 HTTP 본문 필드가 아니라 선택된 프로토콜의 시맨틱 옵션 이름을 사용합니다. 제공자별 설정은 해당
제공자로 범위를 지정하세요. 예를 들어 OpenAI Responses는 `reasoningEffort`를 사용합니다.

```ts
await ctx.session.hook(
  "context",
  (event) => {
    event.options.reasoningEffort = "high"
  },
  { providerID: "openai" },
)
```

생성 옵션은 선택된 프로토콜과 모델에 따라 다릅니다.

- `maxTokens`는 시맨틱 출력 토큰 한도입니다.
- Gemini는 `topK`를 지원하지만 OpenAI Responses는 이를 제공하지 않습니다.

#### 모델 요청 설정

모델 요청 설정을 수정하고, 필요하면 훅의 범위를 특정 제공자로 지정합니다. 이벤트에는 아래 HTTP 훅과 같은 `kind`가
포함됩니다.

```ts
await ctx.session.hook(
  "model.request",
  (event) => {
    event.headers["x-plugin"] = "review"
  },
  { providerID: "anthropic" },
)
```

#### 네이티브 HTTP

제공자의 네이티브 요청이나 응답을 수정합니다. 본문은 한 번만 읽을 수 있는 스트림이므로, 읽기 전에 본문을 복제하거나
교체하세요.

두 훅은 세션이 보내는 모든 요청에서 실행됩니다. `event.kind`는 요청을 보낸 흐름을 나타냅니다. 에이전트 루프는
`"primary"`, 체크포인트 요약은 `"compaction"`, 제목 생성은 `"title"`, 일회성 `ctx.session.generate` 호출은
`"generate"`입니다. 보조 요청을 구분할 때는 에이전트 ID 대신 이 값을 사용하세요.

```ts
await ctx.session.hook("http.request", (event) => {
  event.request.headers.set("x-session-id", event.sessionID)
  if (event.kind === "title") event.request.headers.set("x-priority", "background")
})

await ctx.session.hook("http.response", (event) => {
  event.response = new Response(event.response.body, {
    status: event.response.status,
    headers: { ...Object.fromEntries(event.response.headers), "x-plugin": "review" },
  })
})
```

#### 네이티브 WebSocket(실험적)

WebSocket으로 스트리밍하는 제공자는 세션마다 연결을 하나 열고 여러 요청에서 재사용하므로, `http.request`와
`http.response`는 이 트래픽을 보지 못합니다. `experimental.ws.handshake` 훅은 모델 호출마다 연결이 선택되기 전에 한
번 실행됩니다. 이 훅에는 HTTP 훅과 같은 `sessionID`, `agent`, `model`, `kind`와 함께 연결의 `url`, `headers`가
포함됩니다. `url`이나 `headers`를 변경하면 요청이 사용하는 소켓이 달라지므로, 베어러 토큰을 교체하면 연결이 다시
열립니다.

HTTP 훅은 WebSocket 라우트가 폴백으로 보내는 요청을 포함해 모든 HTTP 요청에서 계속 실행됩니다.

```ts
await ctx.session.hook(
  "experimental.ws.handshake",
  async (event) => {
    event.headers.authorization = `Bearer ${await mintToken(event.url)}`
    delete event.headers["api-key"]
  },
  { providerID: "azure" },
)
```

`experimental.ws.send`와 `experimental.ws.receive`는 프레임 자체를 노출하며, HTTP 요청이나 응답 본문을 편집하는
것에 해당하는 WebSocket 기능입니다. `send`는 제공자 드라이버가 나가는 프레임을 만든 후 전송하기 전에 실행되고,
`receive`는 들어오는 각 프레임을 드라이버가 처리하기 전에 실행됩니다. 두 훅 모두 프레임을 문자열로 전달하며, 훅이
반환될 때 `frame`에 담긴 값을 사용합니다.

OpenCode는 다시 쓴 프레임을 검증하지 않습니다. 드라이버는 제공자의 응답을 바탕으로 상태를 추적하므로, 다시 쓴 HTTP
본문과 마찬가지로 프로토콜의 의미를 바꾸는 수정은 플러그인이 책임져야 합니다.

```ts
await ctx.session.hook(
  "experimental.ws.send",
  (event) => {
    const body = JSON.parse(event.frame)
    if (body.type === "response.create") body.metadata = { ...body.metadata, session: event.sessionID }
    event.frame = JSON.stringify(body)
  },
  { providerID: "openai" },
)

await ctx.session.hook("experimental.ws.receive", (event) => {
  if (event.frame.includes('"type":"error"')) console.error(event.frame)
})
```

이 훅들은 실험적 기능이며 이름이나 형태가 바뀔 수 있습니다.

#### 재시도 정책

제공자 실패에 대한 재시도 결정을 재정의하거나 지연 시간(밀리초)을 바꿉니다. 이 훅은 OpenCode가 실패를 분류하고
정책을 제안한 후, 재시도가 예약되기 전에 실행됩니다. OpenCode가 내부적으로 다음 시도를 어떻게 수행하는지는 노출하지
않습니다.

```ts
await ctx.session.hook("retry", (event) => {
  if (event.error.status === 429) {
    event.decision = { retry: true, delay: 10_000 }
    return
  }
  if (event.error.type === "provider.invalid-request" && event.attempt === 2) {
    event.decision = { retry: true, delay: 0 }
    return
  }
  if (event.attempt >= 3) event.decision = { retry: false }
})
```

재시도 훅은 최종 실패를 재시도 가능하게 만들거나 제안된 재시도를 거부해 OpenCode의 초기 `decision`을 바꿀 수
있습니다.

재시도 결정은 다음 규칙을 따릅니다.

- 여러 훅이 등록 순서대로 실행되며, 나중 훅은 현재 결정을 볼 수 있습니다.
- 기본 제공 최대 시도 횟수는 넘을 수 없는 한도로 유지됩니다.
- `attempt`는 검토 중인 실제 시도 번호입니다. 최초 요청이 `1`이므로 첫 번째 재시도는 `2`입니다.
- `NaN`, 무한대, 음수 같은 유효하지 않은 지연 시간은 계산된 지연 시간으로 대체됩니다.
- 컨텍스트 초과 복구는 같은 요청을 재시도하는 대신 대화를 압축하므로 별도로 처리됩니다.

### 권한

구성된 규칙이 평가된 후, 작업이 실행되거나 권한 요청이 게시되기 전에 권한 결정을 검토합니다.

```ts
await ctx.permission.hook("evaluate", async (event) => {
  if (event.action === "read") return

  const messages = await ctx.session.context({ sessionID: event.sessionID })
  const review = await ctx.generate.text({
    model: { providerID: "anthropic", id: "claude-sonnet-4-6" },
    prompt: buildSafetyPrompt({ messages, action: event.action, resources: event.resources }),
  })
  const decision = parseDecision(review.text)

  event.effect = decision.effect
  event.message = decision.reason
})
```

권한 훅은 다음 규칙을 따릅니다.

- 훅은 `allow`와 `ask` 결정에서 실행됩니다.
- 명시적으로 구성된 `deny`는 최종 결정이며 훅을 호출하지 않습니다.
- 훅은 `effect`를 `allow`, `ask`, `deny` 중 하나로 바꿀 수 있습니다.
- `message`는 승인을 요청하는 권한 요청에 표시되거나 거부 사유가 됩니다.

#### 참조

```ts
  readonly agent?: string
  readonly action: string
  readonly resources: readonly string[]
  readonly metadata?: Record<string, unknown>
  readonly source?: { type: "tool"; messageID: string; id: string }
```

## 게시

패키지 플러그인은 로컬 플러그인과 같은 기본 내보내기를 사용합니다. 최소한의 매니페스트는 다음과 같습니다.

```json title="package.json"
{
  "name": "opencode-acme-plugin",
  "version": "1.0.0",
  "type": "module",
  "exports": {
    ".": "./src/index.ts",
    "./rpc": "./src/rpc.ts"
  },
  "dependencies": {
    "@opencode/plugin": "latest"
  }
}
```

`./rpc` 내보내기는 선택 사항입니다. 다른 플러그인과 클라이언트가 구현을 로드하지 않고 가져올 수 있는 공유
[RPC 계약](/build/plugins/rpc)을 게시할 때 포함하세요.

대상 OpenCode 릴리스와 호환되는 버전을 사용하고, 워크스페이스에 링크된 복사본만이 아니라 실제로 설치한 패키지를
테스트하세요. 새로운 API 계약을 도입하면 호환되는 플러그인 업데이트를 게시하세요.

## V1 지원

플러그인은 같은 패키지 진입점에서 V1과 V2를 모두 지원할 수 있습니다. V1용 `server()` 함수와 V2용 `setup()` 함수를
가진 객체 하나를 기본 내보내기로 내보내세요.

```ts title="src/index.ts"
import { Plugin } from "@opencode/plugin"

export default {
  ...Plugin.define({
    id: "example",
    async setup(ctx) {
      await ctx.tool.hook("execute.before", () => {
        console.log("A tool is about to run")
      })
    },
  }),
  async server() {
    return {
      "tool.execute.before": async () => {
        console.log("A tool is about to run")
      },
    }
  },
}
```

- V1은 `server()`를 호출하고 반환된 훅을 사용합니다.
- V2는 기본 내보내기의 `id`와 `setup()`(Effect 플러그인은 `effect()`)을 읽고 `server()`는 무시합니다.
- 각 구현은 자신의 API를 사용하도록 유지하세요. 내보내기를 공유한다고 V1 훅이 V2 훅으로 변환되지는 않습니다.
- 내보내는 객체에 `Plugin.define(...)`을 스프레드해, V2 정의가 `server()`와 별도로 타입 검사되도록 하세요.

V1 객체 형식은 OpenCode `1.18.29`에서 지원됩니다. 그보다 오래된 V1 릴리스는 함수 내보내기를 요구할 수 있으므로,
지원하려는 가장 오래된 V1 릴리스와 V2에서 설치한 패키지를 테스트하세요.
