title: "V1 플러그인 마이그레이션"
---

플러그인 구성은 자동으로 변환할 수 있지만, 플러그인 구현 코드는 직접 이식해야 합니다. V1 플러그인 함수는 도구와 훅을
담은 객체 하나를 반환합니다. V2 플러그인은 `id`와 `setup(ctx)`를 가진 정의를 기본 내보내기(default export)로
내보내며, `setup`에서 컨텍스트를 통해 훅, 변환, 도구, 구독을 등록합니다.

<Callout type="warning">
  V1 플러그인 구현은 V2에서 실행되지 않습니다. 파일을 옮기거나 구성 항목의 이름을 바꾸는 것만으로는 충분하지 않습니다.
</Callout>

## 플러그인 구성 마이그레이션

`plugin`을 `plugins`로 이름을 바꾸세요. 패키지와 옵션으로 이루어진 튜플은 객체로 바꿉니다.

```jsonc
// V1
{
  "plugin": [
    "opencode-example-plugin",
    ["./plugin/local.ts", { "enabled": true }]
  ]
}

// V2
{
  "plugins": [
    "opencode-example-plugin",
    {
      "package": "./plugin/local.ts",
      "options": { "enabled": true }
    }
  ]
}
```

V2는 `.opencode/plugin/`과 `.opencode/plugins/` 양쪽에서 로컬 플러그인을 찾습니다. V2 파일에는 `.opencode/plugins/`를
사용하세요. 플러그인을 옮길 때는 보조 모듈도 플러그인 옆에 함께 두세요. 로컬 플러그인과 패키지 플러그인은 같은 구현
API를 사용합니다.

## 진입점 교체

패키지 import를 변경하고, 내보내던 플러그인 함수를 `Plugin.define`으로 바꾼 뒤, 초기화 코드를 `setup`으로 옮기세요.

```ts title="V1"
import type { Plugin } from "@opencode-ai/plugin"

export const ExamplePlugin: Plugin = async ({ directory, project, client }) => {
  await client.app.log({
    body: { service: "example", level: "info", message: `Loaded for ${project.id}` },
  })

  return {
    // V1 tools and hooks
  }
}
```

```ts title="V2"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "example",
  async setup(ctx) {
    await ctx.storage.set("last-project", ctx.location.project.id)
    console.log(`Loaded for ${ctx.location.directory}`)
  },
})
```

모든 V2 플러그인에는 변하지 않는 `id`가 필요합니다. 플러그인 저장소는 이 ID 단위로 분리되며, 상태 표시와 진단에서도
이 ID로 플러그인을 식별합니다. 게시하는 플러그인은 대상 OpenCode 릴리스와 호환되는 `@opencode/plugin` 버전에
의존해야 합니다.

## 컨텍스트 마이그레이션

V2 컨텍스트는 OpenCode 클라이언트이자 플러그인 확장 API입니다. 대부분의 작업은 별도의 `client` 속성에 있지 않고
도메인별로 묶여 있습니다.

| V1                                      | V2                                                                  |
| --------------------------------------- | ------------------------------------------------------------------- |
| `directory`                             | `ctx.location.directory`                                            |
| `project`                               | `ctx.location.project`                                              |
| `client`                                | `ctx.session`, `ctx.permission`, `ctx.agent` 같은 도메인 메서드 |
| 플러그인 옵션 인수                 | `ctx.options`                                                       |
| 반환하던 `dispose()` 훅               | `setup`이 반환하는 정리 함수                                |
| 반환하던 `event` 훅                   | `ctx.event.subscribe()`                                             |
| 반환하던 구성, 모델, 도구 변경 | 도메인의 `transform(...)`                                           |
| `$` Bun 셸 헬퍼                    | 플러그인이 사용하는 프로세스 API를 직접 가져와 관리                  |

`ctx.location`은 이 플러그인 인스턴스가 로드된 위치를 나타냅니다. 플러그인이 관찰하는 모든 세션이나 이벤트의 위치를
뜻하지는 않습니다. 이 구분이 중요하다면 세션이나 이벤트 데이터를 읽으세요.

컨텍스트는 표에 나온 것보다 훨씬 많은 도메인을 제공합니다. 카탈로그, 명령, 통합, MCP 서버, 디렉터리 참조, 스킬, 저장소,
VCS, worktree, 웹 검색 등이 있습니다. [전체 플러그인 컨텍스트](/build/plugins#api)를 참고하세요.

## `setup`에서 훅 등록

V1은 문자열 키로 훅을 반환합니다. V2는 각 훅을 해당 작업을 소유한 도메인에 등록합니다. 콜백은 `input`과 `output`
객체를 따로 받는 대신 변경 가능한 이벤트 하나를 받습니다.

```ts title="V1"
import type { Plugin } from "@opencode-ai/plugin"

export const GuardPlugin: Plugin = async () => ({
  "tool.execute.before": async (input, output) => {
    if (input.tool === "read" && output.args.filePath.includes(".env")) {
      throw new Error("Do not read .env files")
    }
  },
  "shell.env": async (_input, output) => {
    output.env.COMPANY_ENV = "development"
  },
})
```

```ts title="V2"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "company.guard",
  async setup(ctx) {
    await ctx.tool.hook("execute.before", (event) => {
      const input = event.input as { filePath?: string }
      if (event.tool === "read" && input.filePath?.includes(".env")) {
        throw new Error("Do not read .env files")
      }
    })

    await ctx.shell.hook("create.before", (event) => {
      event.env.COMPANY_ENV = "development"
    })
  },
})
```

등록은 플러그인이 살아 있는 동안 유지되며, 플러그인이 언로드되면 해제됩니다. 특정 훅이나 변환을 그보다 먼저
`registration.dispose()`로 제거해야 할 때만 반환된 등록 객체를 보관하세요.

다음 표에서 각 V1 훅에 가장 가까운 V2 API를 찾을 수 있습니다.

| V1 확장 지점                     | V2 API                                                       |
| -------------------------------------- | ------------------------------------------------------------ |
| `event`                                | `ctx.event.subscribe()`                                      |
| `dispose`                              | `setup`이 반환하는 정리 함수                         |
| `config`                               | 영향을 받는 도메인의 변환                           |
| `tool` 맵                             | `ctx.tool.transform(...)`                                    |
| `auth`                                 | `ctx.integration.transform(...)`과 통합 API        |
| `provider`                             | `ctx.provider.transform(...)`과 `ctx.model.transform(...)` |
| `chat.message`                         | `ctx.session.hook("prompt", ...)`                            |
| `chat.params`                          | `ctx.session.hook("context", ...)`                           |
| `chat.headers`                         | `ctx.session.hook("model.request", ...)` 또는 `"http.request"` |
| `permission.ask`                       | `ctx.permission.hook("evaluate", ...)`                       |
| `command.execute.before`               | 목적에 따라 명령 변환 또는 prompt 훅   |
| `tool.execute.before`                  | `ctx.tool.hook("execute.before", ...)`                       |
| `tool.execute.after`                   | `ctx.tool.hook("execute.after", ...)`                        |
| `shell.env`                            | `ctx.shell.hook("create.before", ...)`                       |
| `tool.definition`                      | `ctx.tool.transform(...)`                                    |
| `experimental.chat.system.transform`   | `ctx.session.hook("context", ...)`에서 `event.system` 편집   |
| `experimental.chat.messages.transform` | `ctx.session.hook("context", ...)`에서 `event.messages` 편집 |
| `experimental.session.compacting`      | `ctx.session.hook("compaction", ...)`                        |

이 표는 마이그레이션 대상을 안내할 뿐, 항상 이름만 바꾸면 되는 것은 아닙니다. 특히 V2 `prompt` 훅은 프롬프트가
영구적으로 수락(admission)되기 전에 실행되고, `context`는 에이전트의 모델 요청 직전에 실행됩니다. 변환을 모든 종류의
모델 요청에 적용해야 한다면 `context`, `compaction`, `generate`, `title`을 각각 등록하세요.

모든 실험적 V1 훅에 대응하는 V2 훅이 있는 것은 아닙니다. `experimental.compaction.autocontinue`,
`experimental.provider.small_model`, `experimental.text.complete`를 사용하는 플러그인은 내부 수명 주기에 대한 가정을
그대로 유지하려 하지 말고, V2의 세션, 제공자, 모델, 이벤트 API를 기준으로 다시 검토하세요.

`command.execute.before`에도 일대일로 대응하는 전역 훅이 없습니다. 플러그인이 해당 명령을 소유한다면
`ctx.command.transform`으로 명령을 등록하세요. 실제 목적이 명령과 기타 프롬프트 소스에서 제출된 프롬프트를 수정하는
것이라면 prompt 훅을 사용하세요.

## 요청 훅 마이그레이션

V2는 프롬프트 수락, 모델이 보는 컨텍스트, 시맨틱 모델 옵션, 네이티브 HTTP를 분리합니다. 플러그인에 필요한 가장 좁은
계층을 선택하세요.

```ts title="V1"
export const RequestPlugin = async () => ({
  "chat.params": async (_input, output) => {
    output.temperature = 0.2
    output.maxOutputTokens = 8_000
  },
  "chat.headers": async (_input, output) => {
    output.headers["x-plugin"] = "review"
  },
  "experimental.chat.system.transform": async (_input, output) => {
    output.system.push("Focus on correctness.")
  },
})
```

```ts title="V2"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "review-request",
  async setup(ctx) {
    await ctx.session.hook("context", (event) => {
      event.system.push({ type: "text", text: "Focus on correctness." })
      event.options.temperature = 0.2
      event.options.maxTokens = 8_000
    })

    await ctx.session.hook("model.request", (event) => {
      event.headers["x-plugin"] = "review"
    })
  },
})
```

`event.options`에는 시맨틱 제공자 옵션을 사용하세요. 모델 요청 헤더와 원시 요청 설정에는 `model.request`를 사용하고,
`http.request`나 `http.response`는 플러그인이 제공자와의 네이티브 HTTP 교환에 접근해야 할 때만 사용하세요. 특정
제공자 전용 훅은 `ctx.session.hook`의 세 번째 인수로 `{ providerID: "..." }`를 전달할 수 있습니다.

## 사용자 지정 도구 마이그레이션

V1은 예전 `tool()` 헬퍼로 만든 `tool` 맵을 반환합니다. V2는 동기식 `ctx.tool.transform` 편집기를 통해 도구 정의를
등록합니다. 도구 스키마는 JSON Schema를 사용하고, 실행 결과로 구조화된 콘텐츠를 반환합니다.

```ts title="V1"
import { tool } from "@opencode-ai/plugin"

export const ToolsPlugin = async () => ({
  tool: {
    greeting: tool({
      description: "Create a greeting",
      args: { name: tool.schema.string() },
      async execute(args) {
        return `Hello ${args.name}!`
      },
    }),
  },
})
```

```ts title="V2"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "greeting",
  async setup(ctx) {
    await ctx.tool.transform((editor) => {
      editor.add({
        name: "greeting",
        description: "Create a greeting",
        input: {
          type: "object",
          properties: { name: { type: "string" } },
          required: ["name"],
          additionalProperties: false,
        },
        async execute(input) {
          return { content: `Hello ${(input as { name: string }).name}!` }
        },
      })
    })
  },
})
```

변환은 다시 실행될 수 있는 상태 편집입니다. 콜백은 동기식으로 가볍게 유지하고, 한 번만 일어나야 하는 부수 효과를
넣지 마세요. 외부 데이터는 등록 전에 로드해 콜백에서 캡처하고, 그 데이터가 바뀌면 해당 도메인의 `reload()` 메서드를
호출하세요. 나중에 등록된 플러그인 변환은 앞선 변경 사항을 볼 수 있으며, 이를 수정하거나 대체하거나 제거할 수 있습니다.

같은 변환 패턴이 V1의 `config`와 `provider` 훅을 대체하지만, V2는 변경 가능한 전역 구성 객체 하나를 노출하지
않습니다. 변경 사항은 이를 소유한 도메인에 등록하세요: `ctx.agent`, `ctx.provider`, `ctx.model`, `ctx.command`,
`ctx.integration`, `ctx.mcp`, `ctx.reference`, `ctx.skill`, `ctx.tool`, `ctx.vcs`, `ctx.websearch`, `ctx.worktree`.
인증 방법은 통합에 속합니다. 제공자 변환은 소스 정의와 제공자 설정을 추가하고, 모델 변환은 활성 제공자의 전체 모델
컬렉션에 제한과 재정의를 적용합니다.

```ts
await ctx.provider.transform((editor) => {
  editor.update("anthropic", (provider) => {
    provider.headers = { ...provider.headers, "x-company": "engineering" }
  })
})

await ctx.model.transform((editor) => {
  editor.list("anthropic").forEach((model) => {
    if (!model.capabilities.tools) editor.remove(model.providerID, model.id)
  })
})
```

## 이벤트와 정리 마이그레이션

V1의 `event` 콜백은 공개 서버 이벤트 스트림에 대한 비동기 구독으로 바뀝니다. `setup`이 반환하는 정리 함수에서 구독을
중단(abort)하세요.

```ts title="V2"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "notifications",
  setup(ctx) {
    const controller = new AbortController()

    void (async () => {
      for await (const event of ctx.event.subscribe({ signal: controller.signal })) {
        if (event.type === "session.idle") console.log("Session completed")
      }
    })()

    return () => controller.abort()
  },
})
```

정리 함수는 타이머, 하위 프로세스, 소켓 등 플러그인이 소유한 리소스를 정리하는 데 사용하세요. 훅과 변환 등록은
플러그인 범위로 관리되므로 자동으로 정리됩니다.

## 옵션과 영구 상태 마이그레이션

옵션은 `ctx.options`에서 읽습니다. 플러그인에 속한 상태라면 전역 파일을 따로 만들지 말고 `ctx.storage`를 사용하세요.
여기에 저장한 JSON 값은 영구적으로 유지되며 플러그인 범위로 분리됩니다.

```ts
const strict = ctx.options.strict === true
await ctx.storage.set("settings", { strict })
const settings = await ctx.storage.get("settings")
```

## 하나의 패키지로 V1과 V2 지원

패키지는 하나의 기본 내보내기로 두 구현을 한시적으로 함께 노출할 수 있습니다. V1은 `server()`를, V2는 `setup()`을
호출합니다. 두 API는 여전히 별개이며, 이 형태가 훅을 자동으로 변환해 주지는 않습니다.

```ts title="src/index.ts"
import { Plugin } from "@opencode/plugin"

export default {
  ...Plugin.define({
    id: "example",
    async setup(ctx) {
      await ctx.tool.hook("execute.before", () => {
        console.log("A tool is about to run")
      })
    },
  }),
  async server() {
    return {
      "tool.execute.before": async () => {
        console.log("A tool is about to run")
      },
    }
  },
}
```

V1 객체 진입점은 OpenCode `1.18.29` 이상에서 지원됩니다. 그보다 오래된 V1 릴리스를 지원한다면 패키지 버전이나
진입점을 분리하고, 지원한다고 명시한 가장 오래된 릴리스에서 테스트하세요. 지원 기간이 끝나면 V1 구현을 제거하세요.

## 이식한 플러그인 확인

각 플러그인에 대해 다음을 확인하세요.

1. 활성 플러그인 목록에 해당 ID와 소스가 표시되는지 확인합니다.
2. 등록된 모든 훅, 변환, 도구, 명령, 이벤트 구독을 실제로 실행해 봅니다.
3. 플러그인을 다시 로드하거나 제거해 정리가 제대로 되는지 확인합니다.
4. 깨끗한 프로젝트에서 플러그인 옵션과 저장된 상태를 테스트합니다.
5. 게시한 패키지라면 워크스페이스에 링크된 복사본만이 아니라 실제로 설치한 패키지를 테스트합니다.

전체 Promise API는 [플러그인 가이드](/build/plugins)를, Effect 진입점은 [Effect 플러그인](/build/plugins/effect)을,
사용자 지정 메서드와 이벤트는 [플러그인 RPC](/build/plugins/rpc)를, TUI 확장은 [CLI 플러그인](/build/plugins/cli)을
참고하세요.
