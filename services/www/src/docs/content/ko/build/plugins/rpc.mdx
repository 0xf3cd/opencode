---
title: "RPC"
---

플러그인은 서버에서 실행되는 사용자 지정 메서드와 이벤트를 노출할 수 있으며, 다른 플러그인이나 클라이언트가 이를
호출할 수 있습니다.

## 정의

`Rpc.define`으로 RPC의 메서드, 오류, 이벤트를 나열합니다.

```ts title="src/rpc.ts"
import { Rpc } from "@opencode/plugin/rpc"

export const Acme = Rpc.define({
  id: "acme",
  methods: {
    search: {
      input: {
        type: "object",
        properties: { query: { type: "string" } },
        required: ["query"],
        additionalProperties: false,
      },
      output: {
        type: "object",
        properties: { text: { type: "string" } },
        required: ["text"],
        additionalProperties: false,
      },
      errors: {
        not_found: {
          type: "object",
          properties: { query: { type: "string" } },
          required: ["query"],
          additionalProperties: false,
        },
      },
    },
  },
  events: {
    updated: {
      schema: {
        type: "object",
        properties: {
          itemID: { type: "string" },
          text: { type: "string" },
        },
        required: ["itemID", "text"],
        additionalProperties: false,
      },
    },
  },
})
```

### 유효성 검사

RPC 정의는 메서드의 입력과 출력, 이벤트, 오류의 형태를 기술합니다. 두 가지 스키마 형식을 지원합니다.

- JSON Schema: 간단하며 의존성이 필요하지 않습니다.
- Standard Schema를 준수하는 모든 검증 라이브러리
  - Zod
  - Valibot
  - ArkType

### 입력과 출력

각 메서드는 인수를 위한 `input` 스키마와 반환값을 위한 `output` 스키마를 정의할 수 있습니다. 메서드가 값을 받지
않거나 반환하지 않으면 해당 스키마를 생략하세요.

```ts
search: {
  input: {
    type: "object",
    properties: { query: { type: "string" } },
    required: ["query"],
  },
  output: {
    type: "object",
    properties: { text: { type: "string" } },
    required: ["text"],
  },
}
```

JSON Schema 값은 TypeScript에서 `unknown` 타입이므로 사용하기 전에 타입을 좁혀야 합니다. Standard Schema는 입력과
출력 타입을 추론합니다.

### 오류

예상되는 실패에 대비해 메서드에 `errors` 맵을 추가하세요. 각 키는 오류의 `type`이 되고, 해당 스키마는 오류의 `data`를
정의합니다.

```ts
errors: {
  not_found: {
    type: "object",
    properties: { query: { type: "string" } },
    required: ["query"],
    additionalProperties: false,
  },
}
```

`rpc.`로 시작하는 오류 이름은 OpenCode가 예약해 두었습니다.

### 이벤트

최상위 `events` 맵에 이벤트를 추가합니다. 각 이벤트에는 구독자에게 전송되는 데이터의 스키마가 있습니다.

이벤트 데이터는 객체여야 합니다. 데이터가 없을 때는 빈 객체 스키마를 사용하세요.

```ts
events: {
  refreshed: {
    schema: { type: "object", additionalProperties: false },
  },
}
```

스칼라, 배열, `null`, `undefined`는 이벤트 데이터로 사용할 수 없습니다.

## 구현

`setup` 안에서 구현을 등록합니다.

```ts title="src/index.ts"
import { Plugin } from "@opencode/plugin"
import { Acme } from "./rpc.js"

export default Plugin.define({
  id: "acme-plugin",
  async setup(ctx) {
    const registration = await ctx.rpc.register(Acme, {
      search: async (input, context) => {
        const { query } = input as { query: string }
        const text = await findText(query, { signal: context.signal })
        if (!text) return context.error("not_found", "Result not found", { query })
        return { text }
      },
    })

    const acme = ctx.rpc(Acme)
    const result = await acme.search({ query: "hello" })

    await registration.events.emit("updated", { itemID: "item-1", text: "ready" })
  },
})
```

RPC를 등록하면 같은 플러그인에서 `ctx.rpc(Acme)`로 호출할 수 있습니다.

두 번째 인수에는 취소를 위한 `signal`과 선언된 오류를 위한 `context.error(...)`가 포함됩니다. 오류는 반환하거나 던질
수 있습니다.

하나의 플러그인이 여러 RPC를 등록할 수 있습니다. 등록을 해제(dispose)하면 해당 RPC가 제거됩니다.

## 호출

RPC가 등록되면 HTTP로 또는 다른 플러그인에서 호출할 수 있습니다.

### HTTP

OpenCode 클라이언트를 만든 다음 `client.rpc`로 해당 RPC의 하위 클라이언트를 만듭니다.

```ts
import { OpenCode } from "@opencode/client"
import { Acme } from "opencode-acme-plugin/rpc"

const client = OpenCode.make({
  baseUrl: "http://localhost:4096",
})

const acme = client.rpc(Acme)
const result = await acme.search({ query: "hello" })
```

### 플러그인

플러그인에는 이미 OpenCode 클라이언트가 있습니다. 예를 들어 TUI 플러그인은 `context.client`에서 같은 RPC 하위
클라이언트를 만들 수 있습니다.

```ts title="src/tui.ts"
import { Plugin } from "@opencode/plugin/tui"
import { Acme } from "opencode-acme-plugin/rpc"

export default Plugin.define({
  id: "acme-tui",
  async setup(context) {
    const acme = context.client.rpc(Acme)
    const result = await acme.search({ query: "hello" })
    console.log(result)
  },
})
```

### 구독

콜백 방식에는 `events.on`을 사용하고, 리스너가 더 이상 필요하지 않으면 구독을 해제하세요.

```ts
const unsubscribe = acme.events.on("updated", (event) => {
  console.log(event.type, event.location.directory, event.data.text)
})

unsubscribe()
```

비동기 이터러블이 필요하면 `events.subscribe("updated")`를 사용합니다.

```ts
for await (const event of acme.events.subscribe("updated")) {
  console.log(event.data.text)
}
```

이벤트 구독은 실시간으로만 동작하므로, 연결이 끊긴 구독자는 그동안의 이벤트를 받지 못합니다.

- `updated`처럼 로컬 이름으로 구독합니다.
- 수신되는 타입에는 `rpc.acme.updated`처럼 접두사가 붙습니다.
- 각 이벤트에는 `data`와 `location`이 포함됩니다.
- 플러그인이 언로드되면 해당 구독이 닫힙니다.

외부 클라이언트는 모든 위치의 이벤트를 받으므로 필요하면 `event.location`을 확인하세요. 이 경우에도 서버 플러그인이
구성되어 실행 중이어야 합니다.
