`@opencode/client`는 OpenCode HTTP API용 TypeScript 클라이언트입니다. 애플리케이션이 네트워크를 통해 OpenCode 서버에
연결할 때 사용하세요. 네이티브 타입과 메서드는 [API 레퍼런스](/api)와 같은 계약에서 생성됩니다. 플러그인 RPC 타입은
import한 RPC 정의에서 가져옵니다.

## 설치

```sh
bun add @opencode/client
```

## 클라이언트 만들기

서버 URL로 클라이언트를 만든 다음, API 리소스별로 묶인 메서드를 호출합니다.

```ts
import { OpenCode } from "@opencode/client"

const client = OpenCode.make({
  baseUrl: "http://localhost:4096",
})

const session = await client.session.create({
  location: { directory: "/workspace" },
})

await client.session.prompt({
  sessionID: session.id,
  text: "Review the current changes",
})
```

## 헤더와 요청

기본 인증 헤더나 애플리케이션 헤더는 `headers`로 `OpenCode.make`에 전달합니다. 사용자 지정 `fetch` 구현을 제공할
수도 있습니다. 각 작업은 마지막 인수로 요청 옵션을 받으며, 여기에 `AbortSignal`이나 요청별 헤더를 지정할 수
있습니다. 단, 이벤트 구독은 예외로, 구독자 단위의 취소만 받고 기본 클라이언트의 헤더를 사용합니다.

```ts
const client = OpenCode.make({
  baseUrl: "https://opencode.example.com",
  headers: {
    authorization: `Bearer ${process.env.OPENCODE_TOKEN}`,
  },
})

await client.session.list(undefined, {
  signal: AbortSignal.timeout(10_000),
})
```

## 이벤트 스트리밍

스트리밍 엔드포인트는 비동기 이터러블을 반환합니다.

```ts
for await (const event of client.event.subscribe()) {
  console.log(event.type)
}
```

네이티브 이벤트 구독자와 RPC 이벤트 구독자는 클라이언트마다 하나의 지연 연결을 공유합니다. 클라이언트, 핸들,
이터러블을 만드는 것만으로는 이벤트 연결이 열리지 않으며, 소비를 시작해야 연결됩니다. 반복을 중단하거나 구독자를
중단(abort)하면 해당 이터레이터만 종료됩니다. 마지막 구독자가 떠나면 연결이 닫힙니다. 공유 소스는 각 이벤트를 모든
활성 구독자가 받을 때까지 기다리므로, 느린 작업을 수행하는 소비자는 먼저 버퍼링해야 합니다.

구독은 실시간 전용이며, 재생이나 자동 재연결은 없습니다. 소스가 실패하면 현재 구독이 종료되므로, 복구된 후 다시
구독하세요. 늦게 구독한 네이티브 구독자는 지난 비즈니스 이벤트가 아니라 현재 `server.connected` 마커를 받습니다.

## 플러그인 RPC

플러그인의 공유 계약을 import해 `client.rpc`에 전달합니다.

```ts
import { OpenCode } from "@opencode/client"
import { Acme } from "opencode-acme-plugin/rpc"

const acme = client.rpc(Acme)
const result = await acme.search(
  { query: "hello" },
  { location: { directory: "/workspace" }, signal: AbortSignal.timeout(10_000) },
)

const unsubscribe = acme.events.on("updated", (event) => {
  console.log(event.type, event.location.directory, event.data.text)
})
```

메서드의 두 번째 선택적 인수에는 플러그인이 정의한 입력과는 별도로 `location`, `signal`, `headers`를 지정합니다.
위치를 생략하면 네이티브 요청의 기본값을 따릅니다. 즉 기본 위치 헤더를 사용하고, 없으면 서버의 작업 디렉터리를
사용합니다. 하위 클라이언트를 만들 때는 위치가 선택되지 않습니다.

메서드는 정의에서 인수와 결과 타입을 추론합니다. 스키마 파싱은 계약 경계에서 이루어집니다. 호출자는 허용되는 입력
표현을 보내고, 핸들러는 파싱된 값을 받습니다. Promise 클라이언트는 Standard Schema 정의나 일반 JSON Schema 정의를
받으며, 스키마 파서를 로컬에서 실행하지 않습니다. 서버가 이미 파싱되고 변환된 출력을 반환하기 때문입니다. Effect
Schema 정의에는 Effect 클라이언트가 필요합니다.

선언된 메서드 오류는 다른 Promise 클라이언트 엔드포인트의 오류와 같은 방식으로 reject되며, catch한 오류에는 타입이
없습니다. 타입이 지정된 하위 클라이언트는 범용 HTTP RPC 오류 래퍼를 제거합니다. 예약된 `rpc.*` 프레임워크 실패는
일반 RPC 실패로 남고, 관련 없는 인증, 전송, 프로토콜 오류는 일반적인 클라이언트 표현을 유지합니다.

RPC 구독은 로컬 이름을 사용하며, 모든 위치에서 발생한 해당 RPC의 이벤트를 받습니다. 필터링하려면 필수 필드인
`event.location`을 확인하세요. `events.subscribe`는 네이티브 비동기 이터러블 API와 같습니다.

```ts
for await (const event of acme.events.subscribe("updated")) {
  console.log(event.data.text)
}
```

`events.on`은 같은 소스를 감싼 편의 래퍼로, 구독 해지 함수를 반환합니다. 비동기 콜백은 순차적으로 await됩니다.
콜백이나 소스가 실패하면 로그에 기록되고 해당 리스너가 종료됩니다. 네이티브 구독과 타입이 지정된 구독은 모두 같은
일반 `rpc.<rpcID>.<event>` 엔벌로프를 받으며, 이벤트 데이터는 객체로 직접 전달됩니다. 실시간 구독은 놓친 이벤트를
재생하지 않습니다.

서버 플러그인이 구성되어 있고 RPC를 구현해야 합니다. 정의를 import하는 것만으로는 등록되지 않습니다. 정의 및 등록
API는 [플러그인 RPC](/build/plugins/rpc)를 참고하세요. 모든 HTTP 클라이언트는 범용
`POST /api/rpc/{rpcID}/{method}` 경로를 `{ "input": ... }`로 호출하고 `{ "output": ... }`를 받을 수도 있습니다.
input/output 필드를 생략하면 값이 없음을 뜻합니다.

## 로컬 백그라운드 서비스

메인 클라이언트 엔트리포인트는 브라우저와 호환되며 로컬 프로세스 관리를 포함하지 않습니다. Node 애플리케이션에서는
`@opencode/client/service`에서 네이티브 Promise 서비스 API를 import하세요.

- `Service.discover()`는 프로세스를 시작하지 않고 정상 상태의 등록된 엔드포인트를 반환합니다.
- `Service.ensure()`는 호환되는 서비스를 반환하며, 필요하면 서비스를 시작합니다.
- `Service.stop()`은 등록된 바로 그 서비스 인스턴스를 중지합니다.
- `Service.headers(endpoint)`는 클라이언트용 인증 헤더를 만듭니다.

```ts
import { OpenCode } from "@opencode/client"
import { Service } from "@opencode/client/service"

const endpoint = await Service.ensure()
const client = OpenCode.make({
  baseUrl: endpoint.url,
  headers: Service.headers(endpoint),
})

const info = await client.server.info()
```

`Service.ensure()`는 선택적으로 등록 파일, 버전, 서비스 명령, `onStart` 콜백을 받습니다. `version`에는 정확한 값이나
호환성 조건자(predicate)를 지정할 수 있습니다.

```ts
const endpoint = await Service.ensure({
  file: "/var/run/opencode/service.json",
  version: (version) => version.startsWith("2."),
  command: ["opencode", "serve", "--service"],
  onStart(reason, previousVersion) {
    console.log(reason, previousVersion)
  },
})
```

이 옵션을 생략하면 표준 등록 경로와 `opencode serve --service` 명령을 사용합니다.
