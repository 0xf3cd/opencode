## 첨부

로컬 파일을 첨부한 뒤 프롬프트에서 OpenCode에 그 파일을 사용하도록 요청하세요. 데스크톱 또는 웹 클라이언트에서는
**Attach file**을 선택하거나, 파일을 붙여 넣거나, 프롬프트로 끌어다 놓으면 됩니다.

```text
Summarize the attached README.md and list the required setup steps.
```

데스크톱 파일 선택기에서는 합계 최대 20 MiB까지 선택할 수 있습니다. 다른 인터페이스에서는 클라이언트 측 한도가 더 낮을
수 있습니다.

<Callout type="warning">
  이미지를 첨부하기 전에 이미지 입력을 지원하는 모델을 선택하세요. OpenCode는 지원되는 이미지를 제공자에게 전달할 수
  있지만, 형식, 크기(해상도), 파일 수, 용량 제한은 제공자와 모델이 자체적으로 적용합니다. 텍스트 전용 모델은 요청을
  거부할 수 있습니다.
</Callout>

## 구문

V2의 프롬프트 및 명령 입력은 `uri`와 선택 사항인 `name`, `description`으로 첨부 파일을 설명합니다.

```json
{
  "uri": "file:///home/me/project/src/server.ts",
  "name": "server.ts",
  "description": "HTTP server entrypoint"
}
```

서버에서 접근할 수 있는 파일이나 디렉터리에는 절대 `file:` URL을 사용하세요. 텍스트 파일에서는 양수인 `start`와 `end`
매개변수로 줄 범위를 지정할 수 있습니다(1부터 시작).

```text
file:///home/me/project/src/server.ts?start=20&end=60
```

콘텐츠를 인라인으로 보내려면 `data:` URL을 사용하세요.

```json
{
  "uri": "data:text/plain;base64,SGVsbG8sIE9wZW5Db2RlIQ==",
  "name": "greeting.txt"
}
```

HTTP 및 HTTPS 첨부 URL은 지원하지 않습니다. 프로그래밍 방식으로 프롬프트를 제출하는 방법은 자동 생성된
[API 레퍼런스](/api)를 참고하세요.

## 형식

현재 V2 세션에서는 다음 첨부 파일 형식이 모델에 전달됩니다.

| 입력 | 모델이 받는 내용 | 예시 |
| --- | --- | --- |
| UTF-8 텍스트 파일 | 파일 이름과 디코딩된 텍스트 | `README.md` |
| 디렉터리 | 바로 아래에 있는 파일과 디렉터리 목록(재귀 아님) | `file:///home/me/` |
| PNG, JPEG, GIF, WebP | 이미지 미디어 | `diagram.png` |

SVG는 텍스트로 처리됩니다. PDF, AVIF, BMP, 오디오, 비디오 및 기타 바이너리 첨부 파일은 모델 요청에 포함되지 않습니다.
지원되지 않는 바이너리는 먼저 텍스트나 지원되는 이미지로 변환하세요. 예를 들어 PDF 페이지를 `page-1.png`로 내보낸 뒤
첨부하면 됩니다.

OpenCode는 프롬프트를 접수하기 전에 각 첨부 파일을 읽습니다. 잘못된 URL, 읽을 수 없는 경로, 파일이나 디렉터리가 아닌
경로, 디코딩 후 20 MiB를 초과하는 첨부 파일은 거부합니다. 미디어 타입은 실제 바이트 내용으로 감지하므로, 파일 이름이나
`data:` URL의 미디어 타입을 바꿔도 지원되지 않는 바이너리가 모델에 전달되지는 않습니다.

## 이미지

이미지 정규화는 `opencode.json` 또는 `opencode.jsonc`에서 구성합니다.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "media": {
    "image": {
      "auto_resize": true,
      "max_width": 2000,
      "max_height": 2000,
      "max_base64_bytes": 5242880,
    },
  },
}
```

모든 필드는 선택 사항입니다.

| 필드 | 기본값 | 동작 |
| --- | --- | --- |
| `auto_resize` | `true` | 구성된 한도를 넘는 이미지의 크기를 조정합니다. `false`이면 이미지를 거부합니다. |
| `max_width` | `2000` | 최대 너비(픽셀)입니다. 양의 정수여야 합니다. |
| `max_height` | `2000` | 최대 높이(픽셀)입니다. 양의 정수여야 합니다. |
| `max_base64_bytes` | `5242880` | Base64로 인코딩된 이미지의 최대 바이트 수입니다. 양의 정수여야 합니다. |

예를 들어 다음 구성은 너비가 1200픽셀을 넘는 이미지를 크기 조정하지 않고 거부합니다.

```jsonc title="opencode.jsonc"
{
  "media": {
    "image": {
      "auto_resize": false,
      "max_width": 1200,
    },
  },
}
```

이 설정은 프롬프트에 첨부한 지원 이미지와 기본 제공 `read` 도구가 반환하는 이미지 모두에 적용됩니다.

## 처리

`read` 도구는 내용을 기준으로 PNG, JPEG, GIF, WebP를 인식하며, 원본 이미지 데이터를 최대 20 MiB까지 읽습니다. 너비,
높이, Base64 길이는 구성된 이미지 한도와 비교해 확인합니다.

`auto_resize: true`이면 OpenCode는 가로세로 비율을 유지한 채 크기 한도에 맞게 축소합니다. 그런 다음 Base64 한도를
만족할 때까지 점점 더 작은 PNG 및 JPEG 인코딩을 시도하므로, 출력 미디어 타입이 바뀔 수 있습니다.

```text
Input:  4000 × 2000 WebP
Limits: 2000 × 2000
Output: 2000 × 1000 PNG or JPEG
```

어떤 인코딩도 한도에 맞지 않으면 처리가 실패합니다. `auto_resize: false`이면 한도를 하나라도 넘는 이미지는 수정 없이
실패하며, 디코딩할 수 없는 이미지도 실패합니다.

```text
Input:  2400 × 1600 JPEG
Limit:  max_width = 2000, auto_resize = false
Result: Image processing fails
```

이미지 크기 조정 기능을 사용할 수 없으면 OpenCode는 원본 이미지를 변경하지 않고 그대로 전달합니다. 따라서 이미지 설정은
처리 한도일 뿐, 업로드 제한이나 보안 경계가 아닙니다.

## 한도

| 한도 | 값 또는 동작 | 예시 |
| --- | --- | --- |
| 직접 첨부 | 항목당 디코딩 기준 20 MiB. 클라이언트가 더 낮은 한도를 적용할 수 있음 | 12 MiB 파일 두 개는 항목당 한도를 통과함 |
| 데스크톱 선택기 | 합계 20 MiB | 12 MiB 파일 두 개는 선택 한도를 초과함 |
| `max_base64_bytes` | 전체 `data:` URL이 아닌 인코딩된 Base64 부분만 계산 | `SGVsbG8=`는 8바이트로 계산됨 |
| 제공자 이미지 한도 | OpenCode 처리 후에 적용됨 | OpenCode가 받아들인 이미지도 제공자가 거부할 수 있음 |
| 텍스트 첨부 파일의 모델 지원 | 멀티모달 모델이 필요하지 않음 | `notes.txt`는 프롬프트 텍스트로 삽입됨 |
| `read` 텍스트 한도 | 별도의 페이지 나누기 및 잘라내기 한도를 사용 | 큰 로그는 페이지 단위로 읽음 |

클라이언트가 파일을 받아들였다고 해서 그 내용이 모델에 전달된다는 보장은 없습니다. 첨부 파일은 모델에 전달되는 형식이어야
하며, OpenCode와 제공자의 한도를 모두 충족해야 합니다.
