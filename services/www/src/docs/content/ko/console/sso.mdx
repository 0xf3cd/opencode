---
title: "SSO"
description: "OIDC 또는 SAML을 사용해 ID 공급자를 통해 OpenCode Console 워크스페이스에 로그인합니다."
---

SSO(Single Sign-On)를 사용하면 워크스페이스 멤버가 로그인할 때 회사의 ID 공급자를 거치게 됩니다. 소유자와 관리자가
**Settings › Security**에서 설정하며, 모든 워크스페이스에 포함되어 있습니다.

| 프로토콜       | 공급자                                                                                 |
| -------------- | -------------------------------------------------------------------------------------- |
| OpenID Connect | Google Workspace, Microsoft Entra ID, Okta, Auth0, Ping Identity 또는 모든 OIDC 공급자 |
| SAML 2.0       | Google Workspace, Microsoft Entra ID, Okta 또는 모든 SAML 공급자                       |

워크스페이스마다 SSO 연결은 하나입니다.

## OIDC 설정

1. **Settings › Security**를 열고 **Configure SSO**를 클릭한 다음, **OpenID Connect**와 사용하는 공급자를 선택하세요.
2. 표시되는 단계에 따라 공급자에서 `openid`, `email`, `profile` 범위를 가진 앱을 만드세요.
3. **Issuer URL**(또는 테넌트나 도메인)과 함께 **Client ID**, **Client Secret**, **Display Name**을 입력하고
   **Save**를 클릭하세요.
4. 연결에 표시된 **Callback URL**을 복사해 공급자의 허용된 리디렉션 URI에 추가하세요.

```text
https://opencode.ai/console/auth/sso/ssoconn_.../callback
```

저장할 때 Console이 발급자(issuer)에 접근할 수 있는지 확인합니다. 연결을 저장하는 즉시 SSO가 활성화됩니다.

## SAML 설정

1. **Settings › Security**를 열고 **Configure SSO**를 클릭한 다음, **SAML 2.0**과 사용하는 공급자를 선택하세요.
2. **ACS URL**과 **SP Entity ID**를 복사해 공급자에 입력하세요. 사용자 지정 공급자는 대신 **SP Metadata URL**을
   사용하거나 XML을 다운로드할 수 있습니다.
3. URL, XML 업로드, 붙여 넣기 중 한 가지 방법으로 공급자의 메타데이터를 추가하세요. **IdP Entity ID**, **IdP SSO
   URL**, **IdP Certificate**를 직접 입력할 수도 있습니다.
4. 세부 정보를 검토하고 **Activate SSO**를 클릭하세요.

```text
ACS URL:       https://opencode.ai/console/auth/sso/ssoconn_.../callback
SP Entity ID:  https://opencode.ai/console/auth/sso/ssoconn_.../metadata
```

공급자는 응답 또는 어설션에 서명해야 하며, 사용자의 이메일을 `email` 속성이나 NameID로 보내야 합니다.

## 이메일 도메인 인증

인증된 도메인의 이메일로 [Console](https://opencode.ai/console)에 로그인하는 사람은 ID 공급자로 이동합니다. SSO가
활성화되면 **Email domains** 아래에서 **Add domain**을 클릭하고 도메인을 입력한 다음, 표시된 TXT 레코드를 게시하세요.

```text
Name:   _opencode-console-challenge.example.com
Type:   TXT
Value:  oc-verify=...
```

레코드를 게시한 후 **Verify Domain**을 클릭하세요. DNS 변경 사항이 전파되기까지 시간이 걸릴 수 있습니다. 각 도메인은
하나의 워크스페이스에만 속할 수 있습니다.

## SSO 강제 적용

워크스페이스에 SSO가 설정되면 관리자와 멤버는 SSO로 로그인해야 워크스페이스를 열 수 있으며, Console이 자동으로
리디렉션합니다. `/connect`로 OpenCode를 연결할 때도 같은 규칙이 적용됩니다.

소유자는 SSO 없이도 로그인할 수 있으므로, 공급자 구성이 잘못되어도 워크스페이스 설정에 접근하지 못하게 되는 일은
없습니다.

## 자동 멤버 추가

인증된 도메인의 사용자는 SSO로 처음 로그인할 때 **Member**로 워크스페이스에 참여합니다. 다음 경우에는 자동으로 추가되지
않습니다.

- 대기 중인 초대가 있는 경우. 대신 초대가 사용됩니다.
- 워크스페이스가 [디렉터리 동기화](/console/scim)를 사용하는 경우. 멤버십은 디렉터리 동기화가 결정합니다.
- 워크스페이스에 [Go](/console/go) 구독이 있는 경우.

SSO 워크스페이스로 초대받은 사람은 링크를 열면 ID 공급자로 이동합니다.

## 기존 계정

같은 이메일의 Console 계정이 이미 있으면 Console이 SSO를 연결하기 위해 해당 계정으로 한 번 로그인하도록 요청합니다.
초대받은 사람과 디렉터리 동기화로 추가된 사람은 자동으로 연결됩니다.

## 편집 또는 삭제

연결에서 **Edit**를 클릭해 세부 정보를 변경하세요. 시크릿이나 인증서를 비워 두면 현재 값이 유지됩니다. OIDC와 SAML 간에
전환하려면 연결을 삭제하고 새로 만드세요.

<strong>⋯ › Delete...</strong>에서 연결을 삭제하세요. 멤버는 기존의 다른 로그인 방식으로 돌아가고, 디렉터리 동기화가 중지되며 토큰이
취소됩니다. 이메일 도메인은 유지됩니다.
