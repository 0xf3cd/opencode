---
title: "디렉터리 참조"
---

디렉터리 참조를 사용하면 현재 프로젝트 밖의 디렉터리에 이름을 붙여 OpenCode가 접근하게 할 수 있습니다.
`opencode.json` 또는 `opencode.jsonc`에 참조를 추가한 다음, 필요할 때 클라이언트에서 해당 별칭을 첨부하세요.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "references": {
    "docs": {
      "path": "../product-docs",
      "description": "Use for product behavior and terminology",
    },
  },
}
```

`docs`를 첨부한 뒤 에이전트에게 관련 경로를 살펴보라고 요청하세요.

```text
Read the attached docs reference and summarize api/authentication.md.
```

참조는 문서, 공유 라이브러리, 예제, 다른 저장소의 소스 코드 등에 활용할 수 있습니다.

## 로컬

로컬 디렉터리에는 `path`를 사용하세요.

```jsonc
{
  "references": {
    "design-system": {
      "path": "../design-system",
      "description": "Use when working with components or design tokens",
    },
  },
}
```

경로는 다음과 같이 처리됩니다.

- 상대 경로는 구성 파일이 있는 디렉터리를 기준으로 해석됩니다.
- 절대 경로를 지원합니다.
- `~/docs`처럼 홈 디렉터리 기준 경로를 지원합니다.

다른 필드가 필요 없다면 문자열 축약형을 사용하세요.

```jsonc
{
  "references": {
    "docs": "../docs",
    "shared": "~/work/shared",
  },
}
```

<Callout type="note">
  축약형 문자열은 `.`, `/`, `~`로 시작할 때만 로컬 경로로 인식됩니다. `docs`가 아니라 `./docs`로 작성하세요. 접두사
  없는 `docs` 값은 Git 저장소로 해석됩니다.
</Callout>

## Git

원격 Git 저장소에는 `repository`를 사용하세요.

```jsonc
{
  "references": {
    "effect": {
      "repository": "Effect-TS/effect",
      "branch": "main",
    },
    "internal-sdk": {
      "repository": "git@gitlab.example.com:platform/sdk.git",
      "branch": "release/v2",
    },
  },
}
```

지원되는 원격 형식은 다음과 같습니다.

- GitHub `owner/repo` 축약형
- Git URL
- 호스트/경로 형식
- SCP 스타일 원격 주소

로컬 `file:` 저장소는 지원하지 않습니다.

원격 저장소의 기본 브랜치를 따르려면 문자열 축약형을 사용하세요.

```jsonc
{
  "references": {
    "effect": "Effect-TS/effect",
    "sdk": "gitlab.com/platform/sdk",
  },
}
```

`branch`가 없으면 OpenCode는 원격 저장소의 기본 브랜치를 체크아웃하고 갱신합니다. 브랜치 이름에는 영문자, 숫자, `/`,
`_`, `.`, `-`를 사용할 수 있지만, `-`로 시작하거나 `..`를 포함할 수는 없습니다.

```jsonc
{
  "references": {
    "sdk": {
      "repository": "example/sdk",
      "branch": "release/v2.1",
    },
  },
}
```

## 저장 위치

OpenCode는 각 원격 주소를 정규화하고, 전역 데이터 디렉터리 아래에 원격 저장소와 브랜치 조합마다 체크아웃을 하나씩
저장합니다. 브랜치를 명시하지 않으면 경로는 다음과 같은 형태입니다.

```text
opencode/repos/<host>/<repository-path>
```

일반적인 Linux 환경에서 `Effect-TS/effect`는 다음 위치에 저장됩니다.

```text
~/.local/share/opencode/repos/github.com/Effect-TS/effect
```

브랜치를 명시하면 인코딩된 `@<branch>` 접미사가 붙습니다.

```text
~/.local/share/opencode/repos/github.com/Effect-TS/effect@main
```

## 갱신

아직 없는 저장소는 비동기로 클론됩니다. 기존 체크아웃은 참조가 로드되거나 다시 로드될 때, 그리고 해당 위치(Location)에서
새 사용자 프롬프트가 접수된 후에 백그라운드에서 확인됩니다.

```text
Prompt admitted → refresh check starts in background → agent continues
```

마지막 갱신 시도가 24시간 이상 지났거나 기록된 시도가 없으면 체크아웃을 갱신할 수 있습니다. 갱신하면 fetch를 실행한
뒤 구성된 브랜치 또는 원격 저장소의 기본 브랜치로 재설정(reset)합니다.

```text
Last attempt: 25 hours ago → eligible
Last attempt: 2 hours ago  → skipped
```

갱신은 다음 규칙을 따릅니다.

- 타임스탬프는 서비스를 다시 시작해도 유지됩니다.
- 같은 체크아웃을 사용하는 위치들은 타임스탬프를 공유합니다.
- 실패한 시도는 로그에 기록되며, 마찬가지로 24시간 제한이 적용됩니다.
- 위치가 사용되지 않는 동안에는 주기적으로 확인하지 않습니다.
- 클론이나 갱신에 실패해도 다른 참조는 계속 로드됩니다.

프롬프트는 클론이나 갱신을 기다리지 않습니다. 따라서 첨부 파일에는 이전 내용이 담겨 있어도 이후 도구로 읽을 때는 갱신된
체크아웃이 보일 수 있으며, 새 참조는 체크아웃이 준비되기 전에 표시될 수 있습니다.

```text
Attachment created → cached content
Background refresh completes → later tool read sees newer content
```

<Callout type="warning">
  캐시된 체크아웃은 공유되며, 에이전트가 사용하는 도중에도 업데이트될 수 있습니다. 갱신 시 재설정되므로 캐시된
  체크아웃은 직접 수정하지 마세요.
</Callout>

## 안내

`description`은 에이전트에게 참조가 언제 유용한지 알려 줍니다. 설명이 있는 참조는 별칭 및 해석된 경로와 함께 에이전트
지침에 표시됩니다.

```jsonc
{
  "references": {
    "docs": {
      "path": "../docs",
      "description": "Use for product behavior and terminology",
    },
  },
}
```

설명이 없는 참조도 클라이언트에서는 사용할 수 있지만, 에이전트에게 자동으로 안내되지는 않습니다.

```jsonc
{
  "references": {
    "archive": {
      "path": "../archive",
    },
  },
}
```

## 표시 여부

대화형 클라이언트의 선택 목록에서 참조를 숨기려면 `hidden`을 `true`로 설정하세요.

```jsonc
{
  "references": {
    "internal": {
      "path": "../internal",
      "description": "Use for internal service behavior",
      "hidden": true,
    },
  },
}
```

`hidden`은 대화형 화면의 표시 여부에만 영향을 줍니다. 참조는 참조 API에 계속 남아 있으며, 설명이 있다면 에이전트 지침에도
계속 포함됩니다.

## 사용법

클라이언트는 루트 별칭으로 참조를 첨부합니다. 첨부 파일에는 루트 바로 아래에 있는 파일과 디렉터리 목록(재귀 아님)이
담깁니다.

```text
Attached alias: docs
Ask: Inspect docs/guides/deployment.md and explain the deployment steps.
```

루트 아래의 내용이 필요하면 에이전트에게 특정 경로를 살펴보라고 요청하세요.

## 권한

참조는 추가 도구 권한을 부여하지 않습니다. 활성 위치 밖에 접근할 때는 여전히 일반 도구 규칙과 `external_directory`
권한이 적용되며, 수정하려면 해당하는 편집 권한도 필요합니다.

```text
Read ../product-docs/api.md
```

이 요청은 활성 권한이 해당 외부 읽기를 허용할 때만 성공합니다.

## 필드

| 필드 | 로컬 | Git | 설명 |
| --- | --- | --- | --- |
| `path` | 필수 | 아니요 | 로컬 디렉터리 경로 |
| `repository` | 아니요 | 필수 | 원격 Git 저장소 |
| `branch` | 아니요 | 선택 | fetch하고 체크아웃할 브랜치 |
| `description` | 선택 | 선택 | 에이전트가 언제 사용해야 하는지 설명하는 안내 |
| `hidden` | 선택 | 선택 | 대화형 클라이언트 선택 목록에서 숨김 |

완전한 Git 항목에는 Git과 호환되는 모든 필드를 사용할 수 있습니다.

```jsonc
{
  "references": {
    "sdk": {
      "repository": "example/sdk",
      "branch": "main",
      "description": "Use for SDK implementation details",
      "hidden": false,
    },
  },
}
```

## 별칭

별칭은 비어 있을 수 없으며 `/`, `\`, 공백, 백틱, 쉼표를 포함할 수 없습니다.

```text
Valid:   docs
Invalid: product docs
Invalid: docs/api
```
