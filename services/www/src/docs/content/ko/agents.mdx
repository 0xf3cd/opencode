---
title: "에이전트"
---

Markdown 파일을 만들어 재사용 가능한 에이전트를 추가하세요. 다음 예시는 메인 에이전트가 코드 리뷰에 활용할 수 있는 읽기 전용 리뷰어를 추가합니다.

```md title=".opencode/agents/reviewer.md"
---
description: Reviews changes for correctness and regressions
mode: subagent
model: anthropic/claude-sonnet-4-5#high
permissions:
  - action: edit
    resource: "*"
    effect: deny
  - action: shell
    resource: "*"
    effect: deny
---

Review the current changes. List findings in severity order with file and line references.
```

주 에이전트(primary agent)에게 이 에이전트를 사용하라고 요청하세요.

```text
Use the reviewer subagent to review my current changes.
```

에이전트는 시스템 프롬프트, 선호 모델, 권한, 표시 정보를 하나로 묶은 이름 있는 어시스턴트 프로필입니다.

## 위치

Markdown 에이전트는 모든 프로젝트에서 사용하도록 전역으로 저장하거나 프로젝트 안에 저장하세요.

```text
~/.config/opencode/agents/<name>.md
.opencode/agents/<name>.md
```

OpenCode는 현재 디렉터리부터 프로젝트 루트까지 프로젝트의 `.opencode` 디렉터리를 탐색합니다. 중첩된 경로는 에이전트 ID의 일부가 됩니다.

```text
.opencode/agents/team/reviewer.md  →  team/reviewer
```

## 형식

### Markdown

프런트매터에는 `agents` 구성 항목과 같은 필드를 사용할 수 있습니다. Markdown 본문은 에이전트의 `system` 프롬프트가 됩니다.

```md title=".opencode/agents/explainer.md"
---
description: Explains code without changing it
mode: subagent
---

Explain the relevant code with short examples. Do not edit files.
```

### JSONC

어떤 [OpenCode 구성 파일](/config)에서든 `agents` 아래에 에이전트를 정의할 수 있습니다.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "agents": {
    "reviewer": {
      "description": "Reviews current changes",
      "mode": "subagent",
      "system": "Report findings in severity order.",
      "permissions": [
        { "action": "edit", "resource": "*", "effect": "deny" },
      ],
    },
  },
}
```

## 선택

세션에서 에이전트를 선택하지 않았을 때 사용할 주 에이전트를 설정합니다.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "default_agent": "writer",
  "agents": {
    "writer": { "mode": "primary" },
  },
}
```

지정한 기본 에이전트는 존재해야 하고, 표시되어야 하며, 주 에이전트로 사용할 수 있어야 합니다. 그렇지 않으면 OpenCode는 `build`를 사용하고, 그것도 안 되면 주 에이전트로 사용할 수 있는 첫 번째 표시 에이전트를 사용합니다. 이 설정을 변경해도 기존 세션에 저장된 에이전트는 바뀌지 않습니다.

## 모드

에이전트를 실행할 위치에 따라 `mode`를 설정하세요.

```jsonc
{
  "agents": {
    "reviewer": { "mode": "subagent" },
  },
}
```

| 모드 | 동작 |
| --- | --- |
| `primary` | 세션의 메인 에이전트로 실행됩니다. 새 사용자 지정 에이전트의 기본값입니다. |
| `subagent` | `subagent` 도구를 통해 하위 세션에서만 실행됩니다. |
| `all` | 주 에이전트나 서브에이전트 어느 쪽으로든 실행됩니다. |

서브에이전트는 포그라운드 또는 백그라운드 하위 세션에서 새로운 컨텍스트로 실행됩니다. 상위 에이전트의 `subagent` 권한이 실행할 수 있는 에이전트를 제어하며, 하위 에이전트는 자체적으로 구성된 권한을 사용합니다.

```jsonc
{
  "agents": {
    "orchestrator": {
      "permissions": [
        { "action": "subagent", "resource": "*", "effect": "deny" },
        { "action": "subagent", "resource": "reviewer", "effect": "allow" },
      ],
    },
  },
}
```

## 기본 제공 에이전트

OpenCode에는 다음과 같은 표시 에이전트가 포함되어 있습니다.

| 에이전트 | 모드 | 용도 |
| --- | --- | --- |
| **Build** (`build`) | `primary` | 기본 코딩 에이전트입니다. 도구는 기본적으로 허용되며, 민감한 환경 파일 읽기와 워크스페이스 외부 접근은 승인을 요청합니다. |
| **Plan** (`plan`) | `primary` | 일반 프로젝트 파일을 편집하지 않고 탐색하고 계획합니다. 요청하면 OpenCode 계획 파일을 작성할 수 있으며, 셸 명령은 계속 권한으로 제어됩니다. |
| **General** (`general`) | `subagent` | 폭넓은 도구 접근 권한으로 조사와 여러 단계의 작업을 처리하지만, 서브에이전트를 추가로 실행할 수는 없습니다. |
| **Explore** (`explore`) | `subagent` | 파일을 편집하지 않고 코드나 웹 자료를 검색하고 읽습니다. |

같은 ID를 사용하면 기본 제공 에이전트를 재정의할 수 있습니다.

```jsonc
{
  "agents": {
    "build": {
      "permissions": [
        { "action": "shell", "resource": "git push *", "effect": "ask" },
      ],
    },
  },
}
```

숨겨진 `compaction`, `title`, `summary` 에이전트는 유지 관리 작업을 수행하며 직접 선택할 수 없습니다. V2에는 기본 제공 `scout` 에이전트가 없습니다.

## 병합

에이전트 정의는 구성 순서대로 병합됩니다. 나중에 나온 스칼라 값이 이전 값을 대체하고, 요청 맵은 키 단위로 병합되며, 권한 규칙은 뒤에 추가됩니다.

```jsonc
{
  "permissions": [
    { "action": "shell", "resource": "*", "effect": "ask" },
  ],
  "agents": {
    "build": {
      "permissions": [
        { "action": "shell", "resource": "git status", "effect": "allow" },
      ],
    },
  },
}
```

전역 `permissions`는 에이전트별 규칙보다 먼저 적용되므로, 뒤에 오는 에이전트 규칙으로 이를 세분화할 수 있습니다.

## 옵션

### 설명

`description`은 에이전트의 용도를 설명합니다. OpenCode는 실행할 에이전트를 고르는 모델에 이 설명을 보여 주므로 서브에이전트에는 반드시 추가하세요.

```yaml
description: Reviews database migrations for safety
```

### 모드

`mode`에는 `primary`, `subagent`, `all`을 지정할 수 있습니다. 새 사용자 지정 에이전트에서 생략하면 기본값은 `primary`입니다.

```yaml
mode: all
```

### 모델

`model`은 `provider/model` 형식을 사용하며, 선택적으로 `#variant`를 붙일 수 있습니다.

```yaml
model: anthropic/claude-sonnet-4-5#high
```

JSON 구성에서는 확장 형식도 사용할 수 있습니다.

```jsonc
{
  "agents": {
    "reviewer": {
      "model": {
        "providerID": "anthropic",
        "model": "claude-sonnet-4-5",
        "variant": "high",
      },
    },
  },
}
```

- 서브에이전트는 구성된 모델을 사용하며, 구성된 모델이 없으면 상위 세션의 모델을 상속합니다.
- 세션은 선택된 모델을 별도로 저장합니다. ID로 주 에이전트를 선택해도 그 모델은 바뀌지 않습니다.

### 시스템 프롬프트

`system`은 에이전트의 시스템 프롬프트를 설정합니다. 비어 있지 않은 값을 지정하면 해당 에이전트에서는 제공자의 기본 프롬프트를 대체합니다.

```jsonc
{
  "agents": {
    "reviewer": { "system": "Review only. Do not modify files." },
  },
}
```

프로젝트 지침, 스킬, 디렉터리 참조, 기타 지침 소스는 여전히 추가됩니다. Markdown 에이전트에서는 `system` 프런트매터 필드 대신 문서 본문에 이 내용을 작성하세요.

### 권한

`permissions`는 순서가 있는 일치 규칙 목록입니다.

```jsonc
{
  "agents": {
    "reviewer": {
      "permissions": [
        { "action": "*", "resource": "*", "effect": "deny" },
        { "action": "read", "resource": "src/**", "effect": "allow" },
      ],
    },
  },
}
```

| 필드 | 의미 |
| --- | --- |
| `action` | 도구 또는 권한 작업입니다. 와일드카드를 지원합니다. |
| `resource` | 경로, 명령, 에이전트 ID 등 작업과 대조할 값입니다. 와일드카드를 지원합니다. |
| `effect` | `allow`, `ask`, `deny` 중 하나입니다. |

마지막으로 일치한 규칙이 적용되므로, 넓은 범위의 규칙을 예외보다 앞에 두세요. 주요 작업은 다음과 같습니다.

| 작업 | 대상 |
| --- | --- |
| `shell` | 셸 명령 |
| `edit` | 편집, 쓰기, 패치 도구 |
| `subagent` | 하위 에이전트 |
| `read`, `glob`, `grep` | 로컬 탐색 도구 |
| `webfetch`, `websearch` | 웹 도구 |
| `skill` | 스킬 로드 |

`read`, `edit`, `external_directory` 리소스에서는 OpenCode가 `~`와 `$HOME`을 확장합니다.

```jsonc
{ "action": "read", "resource": "~/notes/**", "effect": "allow" }
```

셸 리소스는 원래의 명령 텍스트 그대로 유지되며 이러한 값을 확장하지 않습니다.

### 단계

`steps`는 모델 단계의 최대 횟수를 양수로 설정합니다.

```yaml
steps: 8
```

마지막 단계에서 OpenCode는 도구를 제거하고 모델에게 텍스트로 요약하도록 요청합니다. 새로운 사용자 입력이 들어오면 허용 횟수가 초기화됩니다.

### 숨김

`hidden`은 일반 목록, 대화형 탐색, 서브에이전트 카탈로그에서 에이전트를 숨깁니다.

```yaml
hidden: true
```

이 옵션은 보안이 아니라 표시 여부를 제어합니다. 동작을 제한하려면 권한을 사용하세요.

### 색상

`color`는 6자리 16진수 값으로 에이전트의 UI 색상을 설정합니다.

```yaml
color: "#ff6b6b"
```

### 비활성화

`disabled`는 구성을 로드하는 해당 시점에서 기본 제공 에이전트나 사용자 지정 에이전트를 제거합니다.

```jsonc
{
  "agents": {
    "plan": { "disabled": true },
  },
}
```

### 요청

`request`에는 에이전트별로 덧붙일 헤더와 JSON 본문을 지정할 수 있습니다.

```jsonc
{
  "agents": {
    "reviewer": {
      "request": {
        "headers": { "x-agent": "reviewer" },
        "body": { "temperature": 0.1 },
      },
    },
  },
}
```

<Callout type="warning">
  V2 세션 실행기는 이 값을 보존하지만 아직 모델 요청에 포함해 보내지는 않습니다. 실제로 적용할 요청 설정은 제공자, 모델,
  모델 변형에서 구성하세요.
</Callout>

새 V2 에이전트 구성에서는 `temperature`, `top_p`, `prompt`, `permission`, `tools`, `disable`, `maxSteps` 같은 레거시 최상위 필드를 사용하지 마세요.
