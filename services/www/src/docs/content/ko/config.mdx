---
title: "구성"
---

프로젝트에 `opencode.jsonc`를 만들어 OpenCode를 구성하세요. 편집기에서 검증할 수 있도록 스키마를 추가한 다음, 필요한 옵션만 설정하면 됩니다.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "anthropic/claude-sonnet-4-5",
}
```

OpenCode에 이 파일을 대신 수정해 달라고 요청할 수도 있습니다.

## 형식

OpenCode는 JSON과 JSONC를 지원합니다. 주석이나 후행 쉼표를 사용하려면 JSONC를 사용하세요.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  // Use this model by default.
  "model": "anthropic/claude-sonnet-4-5",
}
```

## 위치

머신 전체에 적용되는 관리형 설정은 시스템 구성 디렉터리에 두세요.

| 플랫폼 | 디렉터리                                |
| -------- | --------------------------------------- |
| macOS    | `/Library/Application Support/opencode` |
| Linux    | `/etc/opencode`                         |
| Windows  | `%ProgramData%\opencode`                |

시스템 디렉터리는 전역 디렉터리와 같은 방식으로 동작합니다. `opencode.json(c)` 외에도 `agents/`, `commands/`,
`skills/`, `plugins/`를 머신의 모든 사용자에게 로드합니다.

```text
/etc/opencode/
├── opencode.json
├── agents/review.md
├── commands/release.md
└── skills/deploy/SKILL.md
```

macOS에서는 MDM 도구가 `ai.opencode.managed` 도메인에 배포한 관리형 환경설정(managed preferences)도 읽습니다.
사용자별 프로필이 있으면 머신 전체 프로필 대신 사용됩니다.

```text
/Library/Managed Preferences/<user>/ai.opencode.managed.plist
/Library/Managed Preferences/ai.opencode.managed.plist
```

관리형 설정은 우선순위가 가장 높으므로 사용자와 프로젝트는 여기서 지정한 값을 재정의할 수 없으며, 관리형 환경설정은
시스템 디렉터리보다 우선 적용됩니다. 다만 설정만으로는 사용자가 제공자, MCP 서버, 에이전트, 플러그인을 추가하는 것을 막을
수 없습니다. 제한을 강제하려면 관리형 구성에서 [정책](/policies#precedence)을 사용하세요.

모든 프로젝트에 적용할 사용자 설정은 전역 구성에 두세요.

```text
~/.config/opencode/opencode.json(c)
```

프로젝트 설정은 다음 파일 중 하나에 두세요.

```text
/home/user/projects/my-app/opencode.json(c)
/home/user/projects/my-app/.opencode/opencode.json(c)
```

OpenCode는 현재 디렉터리부터 파일 시스템 루트까지 탐색합니다. 먼저 디렉터리에 바로 있는 `opencode.json(c)` 파일을 가장
먼 디렉터리부터 가장 가까운 디렉터리 순으로 병합한 다음, `.opencode` 디렉터리 안의 파일을 같은 순서로 병합합니다. 따라서
발견된 모든 `.opencode` 구성이 디렉터리에 바로 있는 모든 구성보다 우선합니다. 이 동작이 필요한 경우가 아니라면 디렉터리
트리 전체에서 한 가지 형식만 사용하세요.

예를 들어 `/home/user/projects/acme/packages/web`에서 OpenCode를 시작한다고 가정합니다.

```text
/etc/opencode/opencode.json
~/.config/opencode/opencode.json

/home/user/projects/acme/
├── opencode.json
└── packages/
    └── web/
        ├── opencode.json
        └── src/
```

OpenCode는 우선순위가 낮은 파일부터 높은 파일 순으로 적용합니다.

1. `~/.config/opencode/opencode.json`
2. `/home/user/projects/acme/opencode.json`
3. `/home/user/projects/acme/packages/web/opencode.json`
4. `/etc/opencode/opencode.json`

패키지 구성은 저장소 구성에서 겹치는 설정을 재정의하고, 저장소 구성은 전역 구성을 재정의합니다. 시스템 구성은 이 모두를
재정의합니다. 충돌하지 않는 설정은 그대로 유지됩니다. 전역 파일과 프로젝트 파일의 [정책](/policies#precedence)은 반대
순서로 평가되며, 시스템 정책이 이 모두보다 우선합니다.

## 스키마

전체 OpenCode 구성 스키마는 [opencode.ai/config.json](https://opencode.ai/config.json)에서 확인할 수 있습니다.

구성 파일에 `$schema` 필드를 추가하면 JSON Schema를 지원하는 편집기에서 검증과 자동 완성을 사용할 수 있습니다.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json"
}
```

사용 가능한 필드, 허용되는 값, 중첩된 구성 구조는 스키마를 기준으로 확인하세요.

### 셸

터미널과 셸 도구에서 사용할 셸을 설정합니다.

```jsonc
{
  "shell": "/bin/zsh",
}
```

### 모델

기본 모델을 `provider/model` 형식으로 설정합니다. 현재 루트 기본값에는 `#variant`가 유지되지 않으며, 에이전트와 명령의
모델 참조에서는 변형을 선택할 수 있습니다.

```jsonc
{
  "model": "anthropic/claude-sonnet-4-5",
}
```

모델 선택과 로컬 모델은 [모델 가이드](/models)를 참고하세요.

### 기본 에이전트

세션에서 에이전트를 명시적으로 선택하지 않았을 때 사용할 주 에이전트(primary agent)를 지정합니다.

```jsonc
{
  "default_agent": "build",
}
```

기본 제공 에이전트와 사용자 지정 에이전트는 [에이전트 가이드](/agents)를 참고하세요.

### 업데이트

업데이트 확인은 전역 구성에서 제어합니다. `update`를 `"disable"`로 설정하면 확인을 건너뛰고, `"notify"`로 설정하면
설치 전에 사용 가능한 업데이트를 알려 주며, `"auto"`로 설정하면 업데이트를 자동으로 설치합니다. 생략하면 `update`의
기본값은 `"notify"`입니다.

자동 설치는 실행 중인 서버를 다시 시작하지 않습니다. 설치된 업데이트를 적용하려면 서버를 직접 다시 시작하세요.
프로젝트 수준 값은 무시됩니다.

```jsonc
{
  "update": "notify",
}
```

### 공유

세션 공유 정책을 설정합니다. OpenCode는 이 필드를 허용하지만, 세션 공유는 아직 지원되지 않습니다.

```jsonc
{
  "share": "manual",
}
```

자세한 내용은 [공유 가이드](/sharing)를 참고하세요.

### 사용자 이름

사용자 이름을 설정합니다. OpenCode는 이 필드를 허용하지만 대화에는 표시하지 않습니다.

```jsonc
{
  "username": "alice",
}
```

### 권한

에이전트가 일치하는 리소스에 도구를 사용하기 전에 허용, 거부, 확인 요청 중 무엇을 할지 정하는 규칙을 순서대로
정의합니다.

```jsonc
{
  "permissions": [
    {
      "action": "shell",
      "resource": "git push *",
      "effect": "ask",
    },
  ],
}
```

규칙 일치 방식과 사용 가능한 작업은 [권한 가이드](/permissions)를 참고하세요.

### 정책

순서가 있는 정책 문(statement)으로 제공자 사용을 허용하거나 거부하고, 권한 검사를 강제로 거부하거나, MCP 서버·스킬·
플러그인을 차단합니다. 이 정책 문은 더 넓은 범위의 구성에서 재정의할 수 있습니다.

```jsonc
{
  "policies": [
    { "action": "provider.use", "resource": "*", "effect": "deny" },
    { "action": "provider.use", "resource": "anthropic", "effect": "allow" },
    { "action": "tool.use", "resource": "shell:git push *", "effect": "deny" },
  ],
}
```

일치 방식, 구성 파일 간 우선순위, Console에서 관리하는 정책은 [정책 가이드](/policies)를 참고하세요.

### 에이전트

기본 제공 에이전트를 재정의하거나, 자체 모델·지침·모드·권한을 갖춘 특화 에이전트를 정의합니다.

```jsonc
{
  "agents": {
    "reviewer": {
      "description": "Review changes without editing files",
      "mode": "subagent",
      "system": "Focus on correctness, security, and missing tests.",
      "permissions": [{ "action": "edit", "resource": "*", "effect": "deny" }],
    },
  },
}
```

모든 에이전트 옵션과 파일 기반 에이전트는 [에이전트 가이드](/agents)를 참고하세요.

### 스냅샷

실행 취소와 되돌리기 동작에 사용하는 파일 시스템 스냅샷을 켜거나 끕니다.

```jsonc
{
  "snapshots": false,
}
```

실행 취소와 다시 실행 동작은 [스냅샷 가이드](/snapshots)를 참고하세요.

### 감시자

파일 시스템 업데이트를 트리거하지 않아야 하는 파일과 디렉터리를 무시합니다.

```jsonc
{
  "watcher": {
    "ignore": ["dist/**", "coverage/**"],
  },
}
```

### 포매터

`write`, `edit`, `patch` 도구가 파일을 변경한 후 파일을 포맷합니다. `formatter`를 `true`로 설정하면 사용 가능한 기본
제공 포매터가 활성화됩니다.

```jsonc
{
  "formatter": true,
}
```

기본 제공 포매터와 사용자 지정 포매터는 [포매터 가이드](/formatters)를 참고하세요.

### 미디어

`read` 도구가 불러온 이미지가 너무 클 때, 모델에 보내기 전에 크기를 줄일지 거부할지 제어합니다.

```jsonc
{
  "media": {
    "image": {
      "auto_resize": true,
      "max_width": 2000,
      "max_height": 2000,
      "max_base64_bytes": 5242880,
    },
  },
}
```

이미지 처리와 한도는 [첨부 파일 가이드](/attachments)를 참고하세요.

### 출력

도구 결과에서 유지할 최대 줄 수와 바이트 수를 설정합니다.

```jsonc
{
  "tool_output": {
    "max_lines": 2000,
    "max_bytes": 51200,
  },
}
```

### 검색

OpenCode가 웹을 검색하는 방식을 선택합니다. `"random"`을 사용하면 사용 가능한 제공자를 자동으로 선택합니다.

```jsonc
{
  "websearch": {
    "provider": "random",
  },
}
```

제공자, 자격 증명, 선택 방식, 속도 제한, 검색 비활성화는 [웹 검색 가이드](/websearch)를 참고하세요.

### MCP

로컬 및 원격 Model Context Protocol 서버를 구성합니다. 전역 타임아웃은 개별 서버에서 재정의할 수 있습니다.

```jsonc
{
  "mcp": {
    "servers": {
      "playwright": {
        "type": "local",
        "command": ["bunx", "@playwright/mcp"],
      },
    },
  },
}
```

원격 서버, OAuth, 환경 변수, 타임아웃은 [MCP 가이드](/mcp-servers)를 참고하세요.

### 컨텍스트 압축

자동 컨텍스트 압축과, 압축 시 최근 컨텍스트를 얼마나 보존할지 제어합니다.

```jsonc
{
  "compaction": {
    "auto": true,
    "keep": {
      "tokens": 15000,
    },
    "buffer": 20000,
  },
}
```

기본값은 여전히 로컬 요약입니다. 자동 요청과 수동 요청 모두에 제공자 네이티브 압축을 사용하려면 제공자 또는 모델 정책으로
설정하세요.

```jsonc
{
  "providers": {
    "openai": {
      "settings": { "compaction": { "type": "native" } },
      "models": {
        "gpt-4.1": { "settings": { "compaction": { "type": "summary" } } },
      },
    },
  },
}
```

모델 설정은 제공자 설정보다 우선합니다. 자동 압축은 선택한 모델에서 사용할 수 있는 입력 예산을 기준으로 합니다. 제공자
체크포인트는 로컬 요약이 유지하는 최근 부분과 같은 `compaction.keep.tokens` 예산 안에서 최근 사용자 메시지를 유지합니다.
최상위 `compaction.auto: false`는 이미 설치된 체크포인트를 버리지 않고 새로운 자동 압축만 비활성화합니다. 예산 계산과
오버플로 복구는 [컨텍스트 압축 가이드](/compaction)를 참고하세요.

### 세션 예열

주기적인 일회성 요청을 보내 최근 활성 상태였던 모델 세션을 예열된 상태로 유지합니다. 세션 예열은 기본적으로
비활성화되어 있습니다. `true`로 설정하면 4분 유휴 간격과 30분 활성 구간을 사용합니다.

```jsonc
{
  "warming": {
    "prompt": "Do not perform any work. Reply with exactly: OK",
    "interval": "4 minutes",
    "duration": "30 minutes",
  },
}
```

요청 동작, 사용자 지정, 비용 고려 사항은 [세션 예열 가이드](/warming)를 참고하세요.

### 스킬

OpenCode가 에이전트 스킬을 찾을 디렉터리나 URL을 추가합니다.

```jsonc
{
  "skills": ["./team-skills", "https://example.com/.well-known/skills/"],
}
```

스킬 구조와 `.opencode/skills/` 아래의 자동 탐색은 [스킬 가이드](/skills)를 참고하세요.

### 명령

재사용 가능한 슬래시 명령을 이름이 있는 프롬프트 템플릿으로 정의합니다.

```jsonc
{
  "commands": {
    "review": {
      "description": "Review the current changes",
      "template": "Review the current diff for correctness and missing tests.",
    },
  },
}
```

인수, 모델, 에이전트, 파일 기반 명령은 [명령 가이드](/commands)를 참고하세요.

### 지침

추가 지침 파일, glob 패턴, URL을 선언합니다. OpenCode는 이 필드를 허용하지만 항목을 로드하지는 않습니다. 지침에는
`AGENTS.md`를 사용하세요.

```jsonc
{
  "instructions": ["CONTRIBUTING.md", "docs/guidelines/*.md"],
}
```

프로젝트 지침과 `AGENTS.md`는 [지침 가이드](/instructions)를 참고하세요.

### 디렉터리 참조

로컬 디렉터리나 Git 저장소를 이름이 있는 보조 컨텍스트로 제공합니다.

```jsonc
{
  "references": {
    "docs": {
      "path": "../product-docs",
      "description": "Product behavior and terminology",
    },
    "effect": {
      "repository": "Effect-TS/effect",
      "branch": "main",
    },
  },
}
```

축약 표기, 공개 범위, 경로 해석은 [디렉터리 참조 가이드](/references)를 참고하세요.

### worktree

새 로컬 worktree를 만들 상위 디렉터리를 설정합니다. OpenCode는 요청되거나 생성된 worktree 이름을 이 경로 뒤에
붙입니다.

```jsonc
{
  "worktree": {
    "directory": "../worktrees",
  },
}
```

상대 경로는 프로젝트에 저장된 정식(canonical) 체크아웃을 기준으로 해석됩니다. 이는 전역 구성과 프로젝트 구성 모두에
동일하게 적용됩니다. 절대 경로는 그대로 사용되며, `~/`는 사용자의 홈 디렉터리를 기준으로 해석됩니다.

예를 들어 다음 전역 구성은 새 worktree를 각 프로젝트의 `.lane/trees/` 디렉터리 아래에 만듭니다.

```jsonc
{
  "worktree": {
    "directory": ".lane/trees",
  },
}
```

이 설정이 없으면 서버 데이터 디렉터리의 `worktree/<first-six-project-ID-characters>` 아래에 생성됩니다. worktree를
생성하거나 새로 고칠 때는 다른 클론이 같은 프로젝트 ID를 공유하는 경우에도 프로젝트에 저장된 정식 체크아웃에서 구성을
로드합니다. 이 설정을 변경해도 기존 worktree는 이동하지 않습니다.

기본 제공 기본값은 Git입니다. 전략을 등록하는 [플러그인](/build/plugins#worktrees)은 해당 플러그인 런타임에서 자동으로
기본값이 됩니다. 프로젝트 작업은 정식 체크아웃의 런타임을 사용합니다. 전략별 옵션은 `worktree` 구성 객체가 아니라 해당
플러그인에서 설정합니다.

### 플러그인

패키지나 로컬 플러그인 디렉터리에서 플러그인을 로드합니다. 플러그인이 옵션을 받는 경우 객체 형식을 사용하세요.

```jsonc
{
  "plugins": [
    "opencode-example-plugin",
    {
      "package": "./plugins/local",
      "options": {
        "enabled": true,
      },
    },
  ],
}
```

플러그인 로드와 구성은 [플러그인 가이드](/plugins)를 참고하세요.

### 제공자

제공자를 구성하고, 모델·요청 설정·헤더·모델 변형을 추가하거나 재정의합니다.

```jsonc
{
  "providers": {
    "openai": {
      "models": {
        "gpt-5.2-custom": {
          "modelID": "gpt-5.2",
          "name": "GPT-5.2 Custom",
          "limit": {
            "context": 200000,
            "output": 32000,
          },
        },
      },
    },
  },
}
```

제공자의 `settings.transport: "websocket"`은 해당 제공자의 세션 WebSocket을 선택합니다.

자격 증명, 사용자 지정 엔드포인트, 제공자 패키지, WebSocket 전송 방식, 모델 구성은 [제공자 가이드](/providers)를
참고하세요.
