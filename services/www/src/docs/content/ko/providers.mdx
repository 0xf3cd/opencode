title: "제공자"
---

OpenCode에는 [models.dev](https://models.dev)의 제공자 및 모델 카탈로그가 포함되어 있습니다. 대부분의 제공자는 먼저
계정을 연결한 다음 모델을 선택하면 됩니다.

## 설정

`/connect`를 실행하고 제공자를 선택한 뒤 자격 증명을 입력하세요. 그런 다음 `/models`를 실행해 해당 제공자의 모델을
선택하세요.

```text
/connect
/models
```

## Go

[OpenCode Go](/console/go)는 OpenCode 팀이 테스트한 코딩 모델을 사용할 수 있는 선택형 구독입니다.
[콘솔](https://opencode.ai/console)에서 구독하고 API 키를 복사한 다음, **OpenCode Go**로 연결하세요.

```text
/connect
# Select OpenCode Go, then paste your API key.
/models
```

사용 한도, 엔드포인트, 개인정보 보호에 관한 자세한 내용은 [Go 가이드](/console/go)를 참고하세요.

## 사용자 지정

카탈로그에 없는 API는 제공자로 직접 추가하세요. 다음 OpenAI 호환 예시는 자격 증명, 런타임 패키지, 엔드포인트, 첫 번째
모델을 한 번에 정의합니다.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "acme": {
      "name": "Acme",
      "env": ["ACME_API_KEY"],
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "https://llm.acme.example/v1",
      },
      "models": {
        "qwen3-coder": {
          "name": "Qwen 3 Coder",
        },
      },
    },
  },
}
```

`providers` 객체의 키는 `acme/qwen3-coder` 같은 모델 참조에 사용되는 제공자 ID입니다.

| 필드 | 용도 |
| --- | --- |
| `name` | 표시 이름입니다. |
| `env` | 자격 증명을 제공할 수 있는 환경 변수 이름 목록입니다(순서대로 확인). |
| `package` | 런타임 제공자 패키지입니다. |
| `canonical` | 이 제공자가 카탈로그 기본값을 상속받을 기본 제공 제공자 ID입니다. |
| `compatibility` | 이 제공자의 모든 모델에 적용되는 요청 및 응답 호환성 재정의입니다. 모델의 `compatibility`가 개별 필드를 재정의합니다. `supportsThinkingBlockBinding`과 `supportsEffortUpdates`는 모델에서만 지정할 수 있습니다. |
| `settings` | 런타임 패키지에 전달되는, 타입이 지정된 OpenCode 제어 옵션과 JSON 옵션입니다. |
| `headers` | 요청에 추가할 문자열 값의 HTTP 헤더입니다. |
| `body` | 요청 본문에 병합할 JSON 필드입니다. |
| `models` | 추가하거나 재정의할 모델로, OpenCode 모델 ID를 키로 사용합니다. |

## 엔드포인트

카탈로그 제공자의 요청을 프록시나 호환 엔드포인트로 보내려면 `settings.baseURL`을 재정의하세요. 기존 패키지, 모델,
연결은 그대로 적용됩니다.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "anthropic": {
      "settings": {
        "baseURL": "https://llm-proxy.example.com/anthropic",
      },
    },
  },
}
```

`settings`는 패키지마다 다릅니다. 선택한 패키지가 지원하는 필드만 효과가 있습니다.

## 요청

추가 HTTP 헤더에는 `headers`를, 모든 요청 본문에 병합할 JSON 필드에는 `body`를 사용하세요.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "headers": {
        "X-Gateway-Tenant": "engineering",
      },
      "body": {
        "metadata": {
          "application": "opencode",
        },
      },
    },
  },
}
```

제공자 트래픽의 일부에만 재정의가 필요하다면 두 필드를 모델이나 변형(variant)에 지정할 수도 있습니다.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "models": {
        "gpt-5.2": {
          "headers": { "X-Model-Tier": "coding" },
          "variants": [
            {
              "id": "batch",
              "body": { "service_tier": "flex" },
            },
          ],
        },
      },
    },
  },
}
```

## 제한 시간

HTTP 요청은 응답 헤더를 최대 5분, 스트리밍 응답 청크 사이의 간격을 최대 5분까지 기다립니다. 한도를 변경하려면 제공자의
`settings.headerTimeout` 또는 `settings.chunkTimeout`을 밀리초 단위 숫자로 설정하고, 비활성화하려면 `false`로
설정하세요. `settings.timeout`은 이와 별도로 요청을 보낸 시점부터 응답이 완료될 때까지의 전체 시간을 제한하며, 기본값은
없습니다. 이 구성 설정은 모델이나 변형별이 아니라 제공자 전체에 적용됩니다. WebSocket 전송에서는 `chunkTimeout`이
프레임 사이의 간격을 제한하며, 기본값은 30분입니다.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "anthropic": {
      "settings": {
        "headerTimeout": 600000,
        "chunkTimeout": false,
      },
    },
  },
}
```

어느 한도든 초과한 요청은 전송 오류로 실패합니다. OpenCode는 제한 시간을 초과한 요청을 최대 세 번까지 다시 시도한 뒤
포기합니다.

## 요청 인코딩

`settings.encoding`은 HTTP 요청 본문을 `"zstd"` 또는 `"gzip"`으로 압축하거나, `"none"`이면 일반 JSON으로 보냅니다.
제공자, 모델, 변형에 설정할 수 있으며 가장 구체적인 값이 적용됩니다. 엔드포인트가 디코딩할 수 있는 인코딩만
활성화하세요. 대부분의 제공자와 게이트웨이는 압축된 본문을 거부합니다. OpenAI는 ChatGPT로 로그인했고 사용자 지정
`baseURL`이 구성되지 않은 경우 기본값이 `"zstd"`이며, API 키를 사용하면 일반 JSON을 보냅니다. WebSocket 메시지에는
영향이 없습니다.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "settings": { "encoding": "none" },
    },
  },
}
```

## 패키지

`package` 필드는 제공자와 통신할 런타임을 선택합니다. OpenAI 요청 형식을 구현한 API에는 호환 런타임을 사용하세요.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "acme": {
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "https://llm.acme.example/v1",
      },
      "models": {
        "qwen3-coder": {},
      },
    },
  },
}
```

사용할 수 있는 네이티브 패키지는 다음과 같습니다.

- `@opencode/ai/providers/openai`
- `@opencode/ai/providers/openai/chat`
- `@opencode/ai/providers/openai/responses`
- `@opencode/ai/providers/openai-compatible`
- `@opencode/ai/providers/openai-compatible/responses`
- `@opencode/ai/providers/anthropic`
- `@opencode/ai/providers/anthropic-compatible`
- `@opencode/ai/providers/google`
- `@opencode/ai/providers/google-vertex`
- `@opencode/ai/providers/google-vertex/gemini`
- `@opencode/ai/providers/google-vertex/chat`
- `@opencode/ai/providers/google-vertex/responses`
- `@opencode/ai/providers/google-vertex/messages`
- `@opencode/ai/providers/azure`
- `@opencode/ai/providers/azure/chat`
- `@opencode/ai/providers/azure/responses`
- `@opencode/ai/providers/amazon-bedrock`
- `@opencode/ai/providers/amazon-bedrock/mantle`
- `@opencode/ai/providers/amazon-bedrock/mantle/chat`
- `@opencode/ai/providers/amazon-bedrock/mantle/responses`
- `@opencode/ai/providers/openrouter`
- `@opencode/ai/providers/xai`

`@acme/opencode-provider` 같은 npm 패키지나, 로컬 패키지를 가리키는 절대 `file://` URL도 사용할 수 있습니다.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "acme": {
      "package": "@acme/opencode-provider",
      "models": { "acme-coder": {} },
    },
  },
}
```

## 모델

제공자의 `models` 맵에서 모델을 추가하거나 재정의하세요. 맵의 키는 OpenCode가 사용하는 모델 ID이며, `modelID`는
제공자에게 보내는 ID를 바꿉니다.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "openai/coding",
  "providers": {
    "openai": {
      "models": {
        "coding": {
          "modelID": "gpt-5.2",
          "name": "GPT-5.2 Coding",
        },
      },
    },
  },
}
```

| 필드 | 용도 |
| --- | --- |
| `modelID` | 제공자에게 보내는 모델 또는 배포 ID입니다. |
| `name` | 표시 이름입니다. |
| `family` | 관련 모델을 묶는 데 사용하는 모델 계열입니다. |
| `package` | 이 모델에 대한 런타임 재정의입니다. |
| `settings` | 모델 수준의 OpenCode 제어 옵션과 패키지별 JSON 설정입니다. |
| `headers` | 추가할 문자열 값의 요청 헤더입니다. |
| `body` | 추가할 JSON 요청 본문 필드입니다. |
| `capabilities` | 도구 지원 여부와 허용되는 입력 및 출력 미디어 타입입니다. |
| `compatibility` | 요청 및 응답 호환성 재정의입니다. |
| `variants` | 각자의 `settings`, `headers`, `body`를 가진 이름이 지정된 변형입니다. |
| `cost` | 100만 토큰당 입력, 출력, 캐시(선택 사항) 가격입니다. |
| `limit` | 컨텍스트, 입력, 출력 토큰 한도입니다. |
| `disabled` | `true`이면 선택 목록에서 모델을 제거합니다. |

선택, 기본값, 기능, 한도, 비용, 변형은 [모델](/models)을 참고하세요.

## Azure

Azure의 표준 카탈로그 엔드포인트에는 자격 증명 외에 리소스 이름도 필요합니다. `settings.resourceName`을 한 번 설정한
다음, [제공자 계정](/cli/providers)에 설명된 대로 API 키를 연결하거나 Azure CLI의 Microsoft Entra ID 세션을
사용하세요.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "azure": {
      "settings": {
        "resourceName": "my-models",
      },
    },
  },
}
```

**Resource name**은 [Azure 포털](https://portal.azure.com/) 또는 [Microsoft Foundry](https://ai.azure.com/)에서 확인할
수 있습니다. `https://my-models.openai.azure.com/`이나 `https://my-models.services.ai.azure.com/` 같은 엔드포인트의 첫
부분이기도 합니다.

```bash
az cognitiveservices account list \
  --query "[].{name:name,resourceGroup:resourceGroup}" \
  --output table
```

Entra ID를 사용하려면 [Azure CLI](https://learn.microsoft.com/en-us/cli/azure/install-azure-cli)를 설치하고 로그인한
다음, Azure를 연결할 때 **Microsoft Entra ID (Azure CLI)** 옵션을 선택하세요.

```bash
az login
```

구성이나 환경에서 리소스 이름을 아직 제공하지 않았다면 연결할 때 입력하세요. 연결과 함께 저장된 리소스 이름은 구성보다
우선 적용되며, 변경하려면 다시 연결하세요.

Azure CLI 연결은 Azure CLI에서 선택된 계정을 사용합니다. 다른 테넌트나 구독에 있는 리소스를 사용하려면 둘 다 명시적으로
선택하세요.

```bash
az login --tenant TENANT_ID
az account set --subscription NAME_OR_ID
```

구성 대신 `AZURE_RESOURCE_NAME`으로 OpenCode 서버에 리소스 이름을 제공할 수도 있습니다. 이전 방식의
`AZURE_COGNITIVE_SERVICES_RESOURCE_NAME` 변수도 동작합니다.

### 배포

Azure는 배포를 통해서만 모델을 제공하므로, OpenCode는 Azure 카탈로그 전체 대신 리소스의 배포 목록을 가져와 표시합니다.
목록은 시작 후, 연결 후, 계정 전환 후에 백그라운드에서 로드됩니다. 나중에 추가한 배포를 반영하려면 OpenCode를 다시
시작하거나 다시 연결하세요.

- 연결에 대한 목록이 로드되기 전이나 로드에 실패한 경우에는 전체 카탈로그를 계속 사용할 수 있습니다.
- 같은 연결에서 다시 로드하다 실패하면 마지막으로 완전히 로드된 목록을 유지합니다.
- 계정을 전환하면 이전 계정의 목록은 표시되지 않으며, 새 계정은 전체 카탈로그에서 시작합니다.
- 배포는 카탈로그 모델의 한도, 비용, 기능을 상속받습니다.

배포 이름이 모델 ID가 되며, Azure는 이름의 대소문자를 구분하지 않으므로 소문자로 표시됩니다(예:
`azure/gpt-production`). `gpt-5-mini`처럼 모델 이름을 그대로 쓴 배포는 카탈로그 ID를 유지합니다. 이 ID는 다른 배포를
추가하거나 제거해도 바뀌지 않습니다.

OpenCode는 배포가 배포하는 모델을 기준으로 카탈로그와 연결하며, GPT-4 Turbo를 `gpt-4`로 표기하는 경우처럼 Azure의 모델
표기가 다르면 배포 이름을 기준으로 연결합니다. `gpt-5-mini`를 배포하면서 이름은 `gpt-5`인 경우처럼 다른 모델의 이름을
붙인 배포에는 실제로 배포된 모델의 이름, 한도, 비용이 표시됩니다.

Azure CLI를 사용하면 OpenCode는 Azure 관리 API로 배포 목록을 가져오며, 이를 위해 리소스에 대한 읽기 권한이 필요합니다.
이 방법이 실패하거나 API 키를 사용하는 경우에는 항상 리소스의 이전 방식 배포 목록을 사용합니다. 탐색은 모든 페이지를
읽은 뒤에 목록을 게시합니다. 사용자 지정 `settings.baseURL`을 사용하면 카탈로그가 유지됩니다.

미세 조정된 모델처럼 카탈로그에 없는 모델을 배포했거나, 모델 ID를 배포에 직접 매핑하려면 배포를 명시적으로
구성하세요. OpenCode는 이러한 배포의 이름을 담아 경고를 기록합니다. 명시적으로 구성한 모델은 항상 유지됩니다.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "azure": {
      "models": {
        "gpt-5-mini": {
          "modelID": "gpt-production",
        },
      },
    },
  },
}
```

인증에 사용하는 ID(identity)에는 다음 역할 중 하나가 필요합니다.

- Azure OpenAI 모델: **Cognitive Services OpenAI User**
- 기타 Foundry 모델: **Cognitive Services User**

요청이 잘못된 테넌트의 토큰을 사용한다면 필요한 테넌트로 다시 로그인하세요.

```bash
az login --tenant TENANT_ID
```

## Bedrock

Amazon Bedrock은 AWS 기본 자격 증명 체인을 사용합니다. 가장 간단하면서 지속적으로 쓸 수 있는 방법은 이름이 지정된 AWS
프로필입니다. OpenCode는 액세스 키 환경 변수, 웹 ID, 컨테이너 자격 증명도 인식합니다.

```bash
aws configure sso --profile work
aws sso login --profile work
```

제공자 설정에서 프로필과 리전을 선택하세요. 구성된 `profile`, `AWS_PROFILE`, `AWS_ACCESS_KEY_ID`, 웹 ID 토큰 파일,
컨테이너 자격 증명 URI 중 하나가 있으면 제공자가 활성화됩니다. 리전만으로는 활성화되지 않습니다.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "amazon-bedrock": {
      "settings": {
        "profile": "work",
        "region": "us-west-2",
      },
    },
  },
}
```

리전을 명시하지 않으면 OpenCode는 `AWS_REGION`, `AWS_DEFAULT_REGION`, `us-east-1` 순서로 사용합니다. 프라이빗 또는
VPC 엔드포인트를 사용하려면 프로필과 리전은 그대로 두고 `baseURL`을 설정하세요.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "amazon-bedrock": {
      "settings": {
        "profile": "work",
        "region": "us-west-2",
        "baseURL": "https://bedrock-runtime.vpce.example.com",
      },
    },
  },
}
```

Bedrock API 키는 `AWS_BEARER_TOKEN_BEDROCK`을 사용합니다. 다른 AWS 변수는 SigV4 서명에 사용되며, OpenCode API 키 계정으로
저장되지 않습니다.

## Vertex

Google Vertex는 애플리케이션 기본 사용자 인증 정보(ADC)를 사용하며, 모델을 사용하려면 프로젝트가 필요합니다. 로컬 ADC를
생성한 다음 제공자 설정에서 프로젝트와 위치를 설정하세요.

```bash
gcloud auth application-default login
```

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "google-vertex": {
      "settings": {
        "project": "my-project",
        "location": "us-central1",
      },
    },
  },
}
```

OpenCode는 `GOOGLE_VERTEX_PROJECT`, `GOOGLE_CLOUD_PROJECT`, `GCP_PROJECT`, `GCLOUD_PROJECT` 순서로 프로젝트를 확인합니다.
위치는 `GOOGLE_VERTEX_LOCATION`, `GOOGLE_CLOUD_LOCATION`, `VERTEX_LOCATION`에서 확인하며, 기본값은 `us-central1`입니다.

```bash
GOOGLE_CLOUD_PROJECT=my-project GOOGLE_VERTEX_LOCATION=europe-west4 opencode --standalone
```

서비스 계정도 같은 ADC 경로로 동작합니다. `GOOGLE_APPLICATION_CREDENTIALS`가 서비스 계정 JSON 파일을 가리키도록 하고,
프로젝트는 여전히 설정이나 위의 프로젝트 변수 중 하나로 제공하세요.

```bash
GOOGLE_APPLICATION_CREDENTIALS=/secure/vertex.json \
GOOGLE_CLOUD_PROJECT=my-project \
opencode --standalone
```

Gemini, Anthropic, OpenAI 호환 Vertex 카탈로그 모델에는 모두 단일 `google-vertex` 제공자 ID를 사용하세요. 이전의
`google-vertex-anthropic` 제공자 ID는 V2에서 사용할 수 없습니다.

## Copilot

GitHub Copilot은 API 키를 직접 입력하는 대신 디바이스 OAuth를 지원합니다. **GitHub Copilot**을 연결하고 GitHub.com
또는 GitHub Enterprise를 선택한 다음, 디바이스 인증 흐름을 완료하고 `/models`를 여세요.

```text
/connect
# Select GitHub Copilot, then Login with GitHub Copilot.
/models
```

GitHub Enterprise의 경우 메시지가 표시되면 배포 URL이나 도메인을 입력하세요. OpenCode는 GitHub가 반환한 Copilot API
엔드포인트가 있으면 이를 사용하고, 없으면 엔터프라이즈 도메인에서 엔드포인트를 유추합니다.

```text
company.ghe.com
```

연결된 계정에 Copilot Chat 접근 권한이 있어야 합니다. GitHub에서 사용 권한이 없다고 표시되면 Copilot Free에 가입하거나
조직에 Copilot 시트 할당을 요청한 뒤 다시 연결하세요. OpenCode는 로그인 후, 그리고 활성 Copilot 계정이 바뀔 때마다
계정의 현재 모델 목록을 가져옵니다.

## Ollama

Ollama를 시작하고 모델을 받으세요. OpenCode는 `http://127.0.0.1:11434`를 확인해 완성(completion) 모델을 찾고, 계정을
연결하지 않아도 `/models`에 추가합니다.

```bash
ollama serve
ollama pull qwen3:8b
```

원격 또는 프록시를 거치는 Ollama 서버를 사용하려면 `settings.baseURL`을 지정하세요. `/v1`을 포함해야 하며, OpenCode는
이 값에서 네이티브 탐색 경로인 `/api/tags`와 `/api/show`를 유추합니다. `apiKey`는 선택 사항이며, 탐색 요청과 모델
요청에 bearer 토큰으로 전송됩니다.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "ollama": {
      "settings": {
        "baseURL": "https://ollama.example.com/v1",
        "apiKey": "{env:OLLAMA_API_KEY}",
      },
    },
  },
}
```

탐색은 주기적으로 갱신되며, 일시적인 장애 중에는 마지막으로 성공한 목록을 유지합니다. OpenCode는 Ollama 메타데이터에
`completion` 기능이 포함된 모델만 추가하므로, 임베딩 전용 모델은 표시되지 않습니다.

## 런타임

LM Studio와 vLLM도 기본 제공 로컬 탐색을 지원합니다. 기본 엔드포인트는 각각 `http://127.0.0.1:1234/v1`과
`http://127.0.0.1:8000/v1`입니다.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "lmstudio": {
      "settings": { "baseURL": "http://gpu-host:1234/v1" },
    },
    "vllm": {
      "settings": { "baseURL": "http://gpu-host:8000/v1" },
    },
  },
}
```

LM Studio는 `/api/v1/models`에서 언어 모델을 찾습니다. vLLM은 `/v1/models`를 읽기 전에 `/health`를 확인합니다. vLLM
탐색으로는 도구 지원 여부를 알 수 없으므로, 탐색된 vLLM 모델은 도구가 비활성화된 상태로 시작합니다. 다른 OpenAI 호환
런타임은 [사용자 지정 제공자](#custom) 방법을 따라 모델을 명시적으로 나열하세요.

## 게이트웨이

OpenRouter는 자체 네이티브 런타임과 카탈로그를 사용합니다. OpenCode 서버에 `OPENROUTER_API_KEY`를 제공하거나
OpenRouter 계정을 연결한 다음, 제공자 접두사 뒤에 OpenRouter의 전체 모델 ID를 붙여 모델을 지정하세요.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "openrouter/anthropic/claude-sonnet-4",
}
```

엔드포인트를 재정의하거나 OpenRouter 호환 게이트웨이를 거칠 때도 네이티브 OpenRouter 패키지를 유지하세요. 그래야
OpenRouter의 요청 및 추론(reasoning) 동작이 유지됩니다.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openrouter": {
      "settings": {
        "baseURL": "https://openrouter-gateway.example.com/api/v1",
      },
      "headers": {
        "X-Gateway-Tenant": "engineering",
      },
    },
  },
}
```

OpenAI 호환 API를 제공하지만 자체 모델 목록을 가진 게이트웨이라면 사용자 지정 제공자를 정의하세요. 구성 키가 제공자
접두사가 되고, 각 `models` 키가 선택 가능한 모델 ID가 됩니다.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "company/coder",
  "providers": {
    "company": {
      "env": ["COMPANY_GATEWAY_KEY"],
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "https://gateway.example.com/v1",
      },
      "models": {
        "coder": { "modelID": "upstream/coder-v2" },
      },
    },
  },
}
```

## 오류

제공자 및 모델 오류에는 대개 실패한 단계가 표시됩니다. 패키지를 바꾸기 전에 서버 프로세스의 환경과 정확한 모델 ID를
확인하세요.

| 오류 또는 증상 | 확인 사항 |
| --- | --- |
| `No model is available for session ...` | 현재 선택할 수 있는 활성화된 모델이 없습니다. 제공자별 설정을 마친 뒤 `/models`에서 모델을 선택하세요. |
| `Model unavailable: provider/model` | 제공자가 비활성 상태이거나, 모델 ID가 없거나 비활성화되었거나, 동적 탐색에서 더 이상 반환되지 않습니다. 사용자 지정 별칭이라면 `modelID`가 아니라 `models` 맵의 키를 확인하세요. |
| `Cannot initialize provider/model: NAME is required to resolve the provider endpoint` | `baseURL`에 `${NAME}` 자리 표시자가 남아 있습니다. OpenCode 서버에 해당 변수를 설정하거나, 템플릿을 완전한 엔드포인트로 바꾸세요. |
| `Azure resource name is missing` | `providers.azure.settings.resourceName`, `AZURE_RESOURCE_NAME` 또는 완전한 `settings.baseURL`을 설정하세요. |
| Vertex가 표시되지 않음 | 제공자 설정이나 지원되는 프로젝트 변수에 확인 가능한 프로젝트를 설정하세요. ADC만으로는 제공자가 활성화되지 않습니다. |
| Bedrock이 표시되지 않음 | 프로필이나 지원되는 다른 AWS 자격 증명 체인 입력을 제공하세요. `AWS_REGION`만으로는 리전만 선택됩니다. |
| Ollama에 모델이 없음 | 서버가 `baseURL`에서 유추한 경로에 `/api/tags`와 `/api/show`를 제공하는지, `/api/show`가 `completion` 기능을 보고하는지 확인하세요. |
| Copilot에 모델이 없음 | 활성 OAuth 계정에 Copilot Chat 접근 권한이 있는지 확인하세요. 모델 동기화에 실패하면 `failed to sync GitHub Copilot models`가 로그에 기록됩니다. |

V2는 직접적인 대체 ID가 있는 폐기된 제공자 ID를 거부합니다. `azure-cognitive-services/<model>` 대신 `azure/<model>`을,
`google-vertex-anthropic/<model>` 대신 `google-vertex/<model>`을 사용하세요.

## WebSocket

OpenAI, xAI 및 지원되는 Azure Responses 모델은 세션마다 WebSocket 연결 하나를 열어 둘 수 있습니다. 연속된 단계에서는
변경되지 않은 요청 앞부분을 재사용하고 이전 응답 이후에 추가된 내용만 보내므로, 긴 세션에서 업로드량이 줄어듭니다.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "settings": { "transport": "http" },
    },
  },
}
```

WebSocket 동작은 다음 규칙을 따릅니다.

- 기본 제공 제공자는 각자의 정책에 따라 지원되는 경로에 WebSocket을 적용합니다.
- 제공자의 `settings.transport: "websocket"`은 WebSocket을 활성화하고, `"http"`는 비활성화합니다.
- WebSocket 채널이 없는 경로에 `"websocket"`을 지정하면 경고를 기록하고 HTTP로 대체합니다.
- OpenAI 제공자의 컨텍스트 압축도 같은 연결을 사용합니다.
- xAI는 저장된 응답에서만 이어서 진행합니다. 기본값인 `store: false`에서는 재사용된 연결을 통해 매 단계 전체 내용을
  보냅니다.
- 소켓이 닫히면 다음 단계에서 다시 연결합니다. 연결을 열 수 없으면 세션은 HTTP로 계속 진행됩니다.
- `http.request` 또는 `http.response` 훅이 있는 제공자 플러그인은 각 요청을 관찰할 수 있도록 HTTP를 계속 사용합니다.
