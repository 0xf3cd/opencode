title: "Web"
description: "Uruchamianie OpenCode w przeglądarce."
---

OpenCode zawiera interfejs webowy serwowany przez ten sam serwer, który obsługuje TUI. Jest domyślnie dostępny i
chroniony hasłem.

## Dostęp

```bash
$ opencode pair

  Open a link to connect. Links work once and expire in 5 minutes.

  http://127.0.0.1:49374/auth/connect/...

  █▀▀▀▀▀█ ...
```

Otwarcie linku w przeglądarce loguje ją za pomocą ciasteczka sesji i wczytuje interfejs webowy. Zeskanowanie kodu QR w
aplikacji OpenCode lub wklejenie linku w jej polu adresu serwera łączy aplikację w ten sam sposób. Sesje są ważne 30
dni; zmiana hasła serwera wylogowuje wszystkie sesje.

### Przez SSH

Gdy serwer nasłuchuje tylko na localhost, przekieruj jego port ze swojego komputera i otwórz wyświetlony link lokalnie:

```bash
$ ssh -L 49374:127.0.0.1:49374 my-server
```

Domyślnie serwer działa na porcie 49374 i nasłuchuje tylko na localhost. Tę konfigurację możesz zmienić poleceniem
`opencode service`.

### Dostęp zdalny

Aby łączyć się z dowolnego miejsca, sparuj urządzenie przez zdalny adres
[OpenTunnel](https://github.com/anomalyco/opentunnel):

```bash
$ opencode pair --remote
```

Przy pierwszym włączeniu dostępu zdalnego polecenie prosi o potwierdzenie:

```text
▲  This will expose your OpenCode server to the internet.
│  Traffic is end-to-end encrypted, and access requires your server password.
│  To pair locally instead, run `opencode pair` without the --remote flag.
│
◆  Expose your server to the internet?
│  ● Yes / ○ No
```

Bez interaktywnego terminala polecenie kończy się błędem, chyba że przekażesz `--yes`, aby zaakceptować. Po akceptacji
kolejne uruchomienia pomijają to pytanie, nawet jeśli dostęp zdalny został w międzyczasie wyłączony poleceniem
`opencode service set remote false`.

## Konfiguracja

Każdą opcję ustawisz poleceniem `opencode service set`:

```bash
# Listen on every network interface
$ opencode service set hostname 0.0.0.0

# Use a fixed port instead of the channel default
$ opencode service set port 49374

# Replace the generated password
$ opencode service set password "a-long-secret"

# Allow a web client served from another origin
$ opencode service set cors https://app.example.com,https://other.example.com

# Pass an environment variable to the server process
$ opencode service set env OPENCODE_LOG_LEVEL DEBUG
```

Zmiana ustawienia zatrzymuje serwer działający w tle. Aby zastosować nową konfigurację, uruchom:

```bash
$ opencode service start
```

## Tryb samodzielny

`opencode serve` uruchamia ten sam serwer na pierwszym planie zamiast przez współdzieloną usługę w tle.

```bash
$ opencode serve --hostname 0.0.0.0 --port 4096
server listening on http://0.0.0.0:4096
server password <password>
```

Użyj go, gdy chcesz:

- Uruchomić OpenCode na współdzielonym, stale działającym lub zdalnym hoście, a następnie łączyć klientów poleceniem
  `opencode --server <url>`.
- Kontrolować nazwę hosta, port i originy CORS dla pojedynczego procesu.
- Uruchomić serwer pod nadzorcą, takim jak systemd, Docker lub inne środowisko oczekujące procesu pierwszoplanowego.
- Utrzymywać dedykowany serwer zamiast współdzielonej usługi w tle.

Połącz z nim klienta za pomocą `--server`:

```bash
$ opencode --server http://127.0.0.1:4096
```
