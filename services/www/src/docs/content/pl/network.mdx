Ustaw standardowe zmienne proxy i wyklucz adresy pętli zwrotnej (loopback). CLI komunikuje się z usługą OpenCode
działającą w tle przez lokalne połączenia HTTP, dlatego jeśli w środowisku CLI skonfigurowano proxy, wykluczenie adresów
loopback jest wymagane.

```bash
export HTTP_PROXY=http://proxy.example.com:8080
export HTTPS_PROXY=http://proxy.example.com:8080
export NO_PROXY=localhost,127.0.0.1,::1

opencode
```

`HTTP_PROXY` obsługuje połączenia z adresami docelowymi HTTP, a `HTTPS_PROXY` – z adresami docelowymi HTTPS. Sam URL
proxy może w obu zmiennych używać schematu `http://`. `NO_PROXY` to rozdzielona przecinkami lista hostów i adresów, z
którymi OpenCode łączy się bezpośrednio.

## Usługa w tle

Zmienne wyeksportowane w powłoce działają na usługę w tle tylko wtedy, gdy została ona uruchomiona z tej powłoki. Zapisz
je na stałe w konfiguracji zarządzanej usługi, aby każde kolejne uruchomienie usługi korzystało z tych samych ustawień
sieci.

```bash
opencode service set env HTTP_PROXY http://proxy.example.com:8080
opencode service set env HTTPS_PROXY http://proxy.example.com:8080
opencode service set env NO_PROXY localhost,127.0.0.1,::1
opencode service start
```

Zmiana zarządzanej zmiennej środowiskowej zatrzymuje działającą usługę. `service start` uruchamia ją ponownie z nowym
środowiskiem. Jeśli powłoka, w której uruchamiasz CLI, ustawia proxy, zachowaj w niej również `NO_PROXY` – zmienne
zarządzanej usługi dotyczą procesu serwera, a nie procesu CLI.

Zapisaną zmienną usuniesz poleceniem `service unset env`:

```bash
opencode service unset env HTTPS_PROXY
```

## Uwierzytelnianie

Jeśli proxy akceptuje dane uwierzytelniające w URL-u, podaj nazwę użytkownika i hasło w każdym URL-u proxy, który wymaga
uwierzytelnienia. Znaki takie jak `@`, `:` i `/` w nazwie użytkownika lub haśle zakoduj procentowo.

```bash
export HTTPS_PROXY='http://user:p%40ssword@proxy.example.com:8080'
```

W przypadku usługi w tle zapisz pełny URL. Wartość jest przechowywana w prywatnej konfiguracji usługi i wyświetla ją
polecenie `opencode service get env`, więc nie udostępniaj jego wyniku.

```bash
opencode service set env HTTPS_PROXY 'http://user:p%40ssword@proxy.example.com:8080'
```

## Certyfikaty

Jeśli proxy lub serwer docelowy używa certyfikatu podpisanego przez prywatny urząd certyfikacji, ustaw w
`NODE_EXTRA_CA_CERTS` ścieżkę do pliku PEM. Przy starcie procesu dodatkowe urzędy certyfikacji trafiają do magazynu zaufanych
certyfikatów środowiska uruchomieniowego.

```bash
export NODE_EXTRA_CA_CERTS=/etc/company/ca.pem
opencode --standalone
```

Zapisz ścieżkę do pliku na stałe dla usługi w tle, a następnie uruchom ją ponownie:

```bash
opencode service set env NODE_EXTRA_CA_CERTS /etc/company/ca.pem
opencode service start
```

## Procesy pierwszoplanowe

`--standalone` i `serve` korzystają ze środowiska własnego procesu. `opencode service set env` nie konfiguruje tych
procesów.

```bash
HTTP_PROXY=http://proxy.example.com:8080 \
HTTPS_PROXY=http://proxy.example.com:8080 \
NO_PROXY=localhost,127.0.0.1,::1 \
opencode --standalone
```

W ten sam sposób skonfiguruj serwer działający na pierwszym planie:

```bash
HTTPS_PROXY=http://proxy.example.com:8080 \
NO_PROXY=localhost,127.0.0.1,::1 \
opencode serve
```

## Weryfikacja

Po zastosowaniu ustawień sprawdź, czy CLI może połączyć się z usługą w tle:

```bash
opencode api get /api/info
```

Poprawna odpowiedź o stanie usługi potwierdza, że lokalne połączenie klienta z usługą działa. Aby sprawdzić wychodzące
proxy usługi i ścieżkę certyfikatów, wyślij zwykłe żądanie do dostawcy.
