`@opencode/client` to klient TypeScript dla HTTP API OpenCode. Użyj go, gdy Twoja aplikacja łączy się z serwerem
OpenCode przez sieć. Jego natywne typy i metody są generowane z tego samego kontraktu co
[dokumentacja API](/api). Typy RPC wtyczek pochodzą z importowanych definicji RPC.

## Instalacja

```sh
bun add @opencode/client
```

## Tworzenie klienta

Utwórz klienta, podając URL serwera, a następnie wywołuj metody pogrupowane według zasobów API:

```ts
import { OpenCode } from "@opencode/client"

const client = OpenCode.make({
  baseUrl: "http://localhost:4096",
})

const session = await client.session.create({
  location: { directory: "/workspace" },
})

await client.session.prompt({
  sessionID: session.id,
  text: "Review the current changes",
})
```

## Nagłówki i żądania

Domyślne nagłówki uwierzytelniające lub nagłówki aplikacji przekaż do `OpenCode.make` w opcji `headers`. Możesz też
podać własną implementację `fetch`. Każda operacja przyjmuje jako ostatni argument opcje żądania, w których można
przekazać `AbortSignal` lub nagłówki dla pojedynczego żądania. Wyjątkiem są subskrypcje zdarzeń: przyjmują wyłącznie
anulowanie lokalne dla subskrybenta i używają nagłówków klienta bazowego.

```ts
const client = OpenCode.make({
  baseUrl: "https://opencode.example.com",
  headers: {
    authorization: `Bearer ${process.env.OPENCODE_TOKEN}`,
  },
})

await client.session.list(undefined, {
  signal: AbortSignal.timeout(10_000),
})
```

## Strumieniowanie zdarzeń

Endpointy strumieniowe zwracają asynchroniczne obiekty iterowalne (async iterables):

```ts
for await (const event of client.event.subscribe()) {
  console.log(event.type)
}
```

Natywni subskrybenci zdarzeń i subskrybenci zdarzeń RPC współdzielą jedno leniwie otwierane połączenie na klienta.
Utworzenie klienta, uchwytu ani obiektu iterowalnego nie otwiera połączenia ze strumieniem zdarzeń – nawiązuje je
dopiero rozpoczęcie konsumpcji. Przerwanie iteracji lub anulowanie subskrybenta kończy tylko ten iterator. Połączenie
zamyka się, gdy odejdzie ostatni subskrybent. Wspólne źródło czeka, aż aktywni subskrybenci przyjmą każde zdarzenie,
dlatego konsumenci powinni buforować zdarzenia przed wykonaniem czasochłonnej pracy.

Subskrypcje działają wyłącznie na żywo, bez odtwarzania historii i bez automatycznego ponownego łączenia. Awaria źródła
kończy bieżące subskrypcje; po przywróceniu działania zasubskrybuj ponownie. Natywny subskrybent, który dołączy później,
otrzymuje bieżący znacznik `server.connected`, a nie wcześniejsze zdarzenia biznesowe.

## RPC wtyczek

Zaimportuj współdzielony kontrakt wtyczki i przekaż go do `client.rpc`:

```ts
import { OpenCode } from "@opencode/client"
import { Acme } from "opencode-acme-plugin/rpc"

const acme = client.rpc(Acme)
const result = await acme.search(
  { query: "hello" },
  { location: { directory: "/workspace" }, signal: AbortSignal.timeout(10_000) },
)

const unsubscribe = acme.events.on("updated", (event) => {
  console.log(event.type, event.location.directory, event.data.text)
})
```

Drugi, opcjonalny argument metody zawiera `location`, `signal` i `headers` – oddzielnie od wejścia zdefiniowanego przez
wtyczkę. Jeśli pominiesz lokalizację, obowiązują domyślne ustawienia natywnych żądań: najpierw bazowe nagłówki
lokalizacji, a potem katalog roboczy serwera. Utworzenie podklienta nie wybiera żadnej lokalizacji.

Metody wyprowadzają typy argumentów i wyników z definicji. Parsowanie schematów należy do granicy kontraktu: wywołujący
wysyłają akceptowaną reprezentację wejścia, a handlery otrzymują już sparsowane wartości. Klient Promise akceptuje
definicje Standard Schema lub zwykłe definicje JSON Schema i nie uruchamia parserów schematów lokalnie: serwer zwraca
wyjście już sparsowane i przekształcone. Definicje Effect Schema wymagają klienta Effect.

Zadeklarowane błędy metod odrzucają Promise tak samo jak błędy z innych endpointów klienta Promise, a przechwycone błędy
pozostają nietypowane. Typowany podklient usuwa ogólne opakowania błędów HTTP RPC. Zarezerwowane błędy frameworka
`rpc.*` pozostają zwykłymi błędami RPC, a niezwiązane z nimi błędy uwierzytelniania, transportu i protokołu zachowują
swoją standardową reprezentację w kliencie.

Subskrypcje RPC używają lokalnych nazw i otrzymują zdarzenia danego RPC ze wszystkich lokalizacji. Aby je filtrować,
sprawdzaj wymagane pole `event.location`. `events.subscribe` odpowiada natywnemu API asynchronicznych obiektów
iterowalnych:

```ts
for await (const event of acme.events.subscribe("updated")) {
  console.log(event.data.text)
}
```

`events.on` to wygodna nakładka na to samo źródło. Zwraca funkcję anulującą subskrypcję; asynchroniczne callbacki są
wywoływane i oczekiwane po kolei. Błędy callbacku lub źródła są logowane i kończą danego listenera. Subskrypcje natywne
i typowane otrzymują tę samą standardową kopertę (envelope) `rpc.<rpcID>.<event>` z danymi zdarzenia w postaci bezpośredniego
obiektu. Subskrypcje na żywo nie odtwarzają pominiętych zdarzeń.

Wtyczka serwerowa musi być skonfigurowana i implementować RPC – sam import definicji jej nie rejestruje. API definicji
i rejestracji opisano w sekcji [RPC wtyczek](/build/plugins/rpc). Dowolny klient HTTP może też wywołać ogólną trasę
`POST /api/rpc/{rpcID}/{method}` z treścią `{ "input": ... }` i otrzymać `{ "output": ... }`. Pominięte pola
input/output oznaczają brak wartości.

## Lokalna usługa w tle

Główne punkty wejścia klienta są zgodne z przeglądarkami i nie obejmują zarządzania lokalnymi procesami. W aplikacji
Node.js zaimportuj natywne API usługi oparte na Promise z `@opencode/client/service`.

- `Service.discover()` zwraca działający, zarejestrowany endpoint bez uruchamiania procesu.
- `Service.ensure()` zwraca zgodną usługę i w razie potrzeby ją uruchamia.
- `Service.stop()` zatrzymuje dokładnie tę zarejestrowaną instancję usługi.
- `Service.headers(endpoint)` tworzy nagłówki uwierzytelniające dla klienta.

```ts
import { OpenCode } from "@opencode/client"
import { Service } from "@opencode/client/service"

const endpoint = await Service.ensure()
const client = OpenCode.make({
  baseUrl: endpoint.url,
  headers: Service.headers(endpoint),
})

const info = await client.server.info()
```

`Service.ensure()` przyjmuje opcjonalnie plik rejestracji, wersję, polecenie uruchamiające usługę i callback `onStart`.
`version` przyjmuje dokładną wartość albo predykat zgodności:

```ts
const endpoint = await Service.ensure({
  file: "/var/run/opencode/service.json",
  version: (version) => version.startsWith("2."),
  command: ["opencode", "serve", "--service"],
  onStart(reason, previousVersion) {
    console.log(reason, previousVersion)
  },
})
```

Pomiń te opcje, aby użyć standardowej ścieżki rejestracji i polecenia `opencode serve --service`.
