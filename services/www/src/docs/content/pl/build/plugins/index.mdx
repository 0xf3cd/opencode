Wtyczki mogą zmieniać zachowanie OpenCode i dodawać nowe funkcje. Aby zmienić interfejs terminalowy, zbuduj
[wtyczkę CLI](/build/plugins/cli).

Migrujesz istniejącą wtyczkę z OpenCode 1? Skorzystaj z [przewodnika migracji wtyczek z V1](/build/plugins/migrate-v1).

```ts title=".opencode/plugins/example/index.ts"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "example",
  async setup(ctx) {
    await ctx.storage.set("loaded", true)
  },
})
```

Wtyczki w `.opencode/plugins/` są wczytywane automatycznie, tak jak powyższy przykład lokalny. Aby wczytać opublikowane
pakiety lub katalogi wtyczek z innych lokalizacji, dodaj je do `plugins` w `opencode.json(c)`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": [
    "opencode-acme-plugin",
    "opencode-acme-plugin@1.2.0",
    "@acme/opencode-plugin",
    "./plugins/local",
    "../shared/plugin",
    "/absolute/path/plugin",
    "file:///home/me/plugins/local",
    {
      "package": "@acme/opencode-plugin",
      "options": {
        "agent": "reviewer",
        "strict": true,
      },
    },
  ],
}
```

Więcej opcji wczytywania i konfiguracji znajdziesz w sekcji [Konfigurowanie wtyczek](/plugins).

## Cykl życia

`setup` uruchamia się podczas wczytywania wtyczki. Może zwrócić funkcję czyszczącą, która zostanie wywołana przy
wyładowaniu wtyczki.

```ts
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "example",
  setup(ctx) {
    console.log(`loaded in OpenCode ${ctx.app.version}`)
    return () => console.log("unloaded")
  },
})
```

### Kontekst

Kontekst wtyczki to w zasadzie [klient serwera OpenCode](/build/client). Jego metody odczytu i akcji przyjmują te same
dane wejściowe i zwracają te same odpowiedzi co klient. Dodatkowo udostępnia metody dostępne tylko dla wtyczek:
transformacje, hooki środowiska uruchomieniowego, przeładowywanie, rejestracje i opcje wtyczki.

```ts
setup(ctx) {
  console.log(ctx.app.version)
}
```

`ctx.location` opisuje lokalizację, w której wczytano daną instancję wtyczki. Zawiera `directory`, opcjonalne
`workspaceID` oraz metadane `project` (`id`, `directory` i `canonical`). Jest dostępne zarówno we wtyczkach opartych na
Promise, jak i na Effect. To lokalizacja instancji wtyczki, a nie lokalizacja każdej sesji, do której wtyczka ma dostęp,
czy każdego zdarzenia, które otrzymuje.

```ts
setup(ctx) {
  console.log(ctx.location.directory)
  console.log(ctx.location.project.canonical)
}
```

### Opcje

Opcje wtyczki przekazuj w formie obiektu w `opencode.json(c)`.

```jsonc title="opencode.jsonc"
{
  "plugins": [
    {
      "package": "./plugins/company",
      "options": {
        "strict": true,
      },
    },
  ],
}
```

Odczytaj te wartości z `ctx.options` w `setup`.

```ts title="plugins/company/index.ts"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "company",
  setup(ctx) {
    const strict = ctx.options.strict === true
  },
})
```

## Transformacje

Transformacje to synchroniczne edycje stanu domen OpenCode. Każda z nich bazuje na wcześniejszych rejestracjach w swojej
domenie. Odczyty rejestru, takie jak `ctx.model.list()`, uwzględniają wszystkie dotychczasowe rejestracje, także podczas
konfiguracji wtyczki; grupowanie przy starcie łączy jedynie powiadomienia o aktualizacjach i nigdy nie opóźnia tego, co
zwraca odczyt. API statusu zasobów nadal raportują stan działających zasobów: zarejestrowanie definicji nie oznacza, że
połączenie czy inna praca związana z zasobem zostały zakończone.

Źródła dostarczają dostawców i niemodyfikowalne definicje modeli przez `ctx.provider.transform`.

```ts title="plugins/models/index.ts"
import { Model, Plugin, Provider } from "@opencode/plugin"

export default Plugin.define({
  id: "company.models",
  async setup(ctx) {
    const providerID = Provider.ID.make("acme")
    const models = [{ ...Model.Info.default(providerID, Model.ID.make("reasoner")), name: "Acme Reasoner" }]
    await ctx.provider.transform((editor) => {
      editor.add({
        info: {
          ...Provider.Info.empty(providerID),
          name: "Acme",
          activation: "enabled",
          package: "@opencode/ai/providers/openai-compatible",
          settings: { baseURL: "http://127.0.0.1:8000/v1" },
        },
        models,
      })
    })

    const available = await ctx.model.list()
  },
})
```

Każda rejestracja, usunięcie lub wywołanie `reload()` oznacza rejestr jako zmieniony; następny odczyt odbudowuje go,
odtwarzając wszystkie aktywne transformacje w kolejności rejestracji na świeżej wartości. Transformacje powinny być
tanie i powtarzalne. Wartość, którą już odczytano, nigdy nie jest modyfikowana przez późniejsze odbudowy.

Po rozwiązaniu transformacji dostawców i ich dostępności OpenCode tworzy modele aktywnych dostawców i odtwarza po kolei
wszystkie transformacje modeli. Zasada dotycząca modeli może więc przeanalizować całą kolekcję kandydatów, łącznie ze
świeżo odświeżonymi źródłami.

```ts title="plugins/model-budget/index.ts"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "company.model-budget",
  async setup(ctx) {
    await ctx.model.transform((editor) => {
      editor
        .list()
        .filter((model) => model.cost.some((tier) => tier.output > 20))
        .forEach((model) => {
          editor.remove(model.providerID, model.id)
        })
    })
  },
})
```

Przechwycone dane wejściowe nie są obserwowane automatycznie. Wczytaj dane zewnętrzne przed synchronicznym callbackiem,
a po zmianie tych danych wywołaj `reload()`. W tym przykładzie `loadFromSource()` zwraca wpisy
`{ info: Provider.Info, models: readonly Model.Info[] }`.

```ts title="plugins/models/index.ts"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "company.models",
  async setup(ctx) {
    const source = { providers: await loadFromSource() }

    await ctx.provider.transform((editor) => {
      source.providers.forEach((provider) => editor.add(provider))
    })

    const refresh = async () => {
      source.providers = await loadFromSource()
      await ctx.provider.reload()
    }

    const timer = setInterval(() => void refresh().catch(console.error), 60_000)
    return () => clearInterval(timer)
  },
})
```

Zmiany dostawców unieważniają cały wynik aktywnych modeli, więc zasada dotycząca ceny wyjścia nadal filtruje odświeżone
modele. Użyj `ctx.model.reload()`, gdy zmieniają się tylko dane przechwycone przez transformację modeli.

## API

### Agenci

Odczytaj wszystkich agentów lub pobierz jednego według ID.

```ts
const agents = await ctx.agent.list()
const build = await ctx.agent.get({ agentID: "build" })
```

Zarejestruj transformację, aby przeglądać, aktualizować lub usuwać agentów albo wybrać agenta domyślnego.

```ts
await ctx.agent.transform((editor) => {
  const agents = editor.list()
  const build = editor.get("build")

  editor.default("build")
  editor.update("build", (agent) => {
    agent.description = "Builds features and fixes bugs"
  })
  editor.remove("legacy")
})
```

Przeładuj agentów, gdy zmieni się stan zewnętrzny używany przez transformację.

```ts
await ctx.agent.reload()
```

Schemat: [`Agent.Info`](/api#schema-Agent.Info)

```ts
  list(input?: AgentListInput, requestOptions?: RequestOptions): Promise<AgentListOutput>
```

### Dostawcy

Odczytaj dostępnych dostawców lub sprawdź metadane jednego dostawcy według ID.

```ts
const providers = await ctx.provider.list()
const provider = await ctx.provider.get({ providerID: "anthropic" })
```

Transformacje dostawców edytują ustawienia dostawców i definicje źródeł. Odczyty w edytorze obejmują nieaktywnych
dostawców i udostępniają niemodyfikowalne definicje; `models.update` edytuje własną kopię modelu źródłowego.

```ts
await ctx.provider.transform((editor) => {
  editor.update("anthropic", (provider) => {
    provider.headers = { ...provider.headers, "x-company": "engineering" }
  })
  editor.models.update("anthropic", "claude-sonnet-4-5", (model) => {
    model.name = "Team Sonnet"
  })
  editor.models.remove("anthropic", "legacy-model")
  editor.remove("legacy-provider")
})
```

Zastąp zestaw modeli źródłowych dostawcy za pomocą `models.set`, a po zmianie przechwyconych definicji wywołaj
przeładowanie.

```ts
const source = { models: await loadModels() }
await ctx.provider.transform((editor) => {
  editor.models.set("acme", source.models)
})

source.models = await loadModels()
await ctx.provider.reload()
```

Przy wykrywaniu modeli specyficznych dla konta przekaż połączenie użyte do wczytania zestawu jako `sourceConnection`.
OpenCode wyklucza tego dostawcę, gdy wybrane jest inne połączenie, dopóki wtyczka nie opublikuje odświeżonego zestawu.

```ts
const connection = await ctx.integration.connection.active("acme")
if (!connection) return
const inventory = await loadInventory(connection)
await ctx.provider.transform((editor) => {
  editor.add({ info: inventory.provider, models: inventory.models, sourceConnection: connection })
})
```

#### Referencja

Schematy: [`Provider.Info`](/api#schema-Provider.Info), [`Model.Info`](/api#schema-Model.Info)

```ts
interface ProviderDomain extends ProviderApi {
  transform(callback: (editor: ProviderEditor) => void): Promise<Registration>
  reload(): Promise<void>
}

interface ProviderRecord {
  readonly provider: Provider.Info
  readonly models: ReadonlyMap<string, Model.Info>
  readonly sourceConnection?: ConnectionInfo
}

interface ProviderEditor {
  list(): readonly ProviderRecord[]
  get(providerID: string): ProviderRecord | undefined
  add(input: { info: Provider.Info; models: readonly Model.Info[]; sourceConnection?: ConnectionInfo }): void
  update(providerID: string, update: (provider: DeepMutable<Provider.Info>) => void): void
  remove(providerID: string): void
  readonly models: {
    set(providerID: string, models: readonly Model.Info[]): void
    update(providerID: string, modelID: string, update: (model: DeepMutable<Model.Info>) => void): void

  }
}
```

### Modele

Odczytaj dostępne modele i domyślny wybór.

```ts
const models = await ctx.model.list()
const selected = await ctx.model.default()
```

Transformacje modeli edytują całą kolekcję kandydatów od aktywnych dostawców. Wyłączone modele można edytować, dopóki
nie zakończą się wszystkie transformacje; `update` może dodać model tylko u dostępnego dostawcy.

```ts
await ctx.model.transform((editor) => {
  editor.list("anthropic").forEach((model) => {
    editor.update(model.providerID, model.id, (draft) => {
      draft.enabled = draft.capabilities.tools
    })
  })
  editor.default.set("anthropic", "claude-sonnet-4-5")
  editor.remove("anthropic", "legacy-model")
})
```

Callbacki edytują surowe nadpisania modeli. Wartości domyślne dostawcy są scalane raz, gdy OpenCode zatwierdza wynik;
niezmienione odczyty używają tego wyniku ponownie. `editor.provider` udostępnia niemodyfikowalne definicje źródłowe,
w tym nieaktywne szablony, a nie wynik transformacji modeli.

```ts
await ctx.model.transform((editor) => {
  const source = editor.provider.get("anthropic")?.models.get("claude-sonnet-4-5")
  if (!source) return
  editor.update("anthropic", source.id, (model) => {
    model.limit.context = Math.min(model.limit.context, source.limit.context)
  })
})

await ctx.model.reload()
```

### Polecenia

Odczytaj polecenia dostępne w danej lokalizacji.

```ts
const commands = await ctx.command.list()
```

Rejestruj polecenia za pomocą transformacji. Funkcja wykonująca otrzymuje sesję, załączniki promptu i żądany tryb
dostarczenia.

```ts
await ctx.command.transform((editor) => {
  editor.add({
    name: "security-review",

        ...prompt,
        sessionID,
        text: `Review these changes for security issues.\n\n${prompt.text}`,
        delivery,
      })
    },
  })
})
```

```ts
await ctx.command.reload()
```

### Integracje

Odczytaj integracje i sprawdź aktywne dane uwierzytelniające.

```ts
const integrations = await ctx.integration.list()
const github = await ctx.integration.get({ integrationID: "github" })
const connection = await ctx.integration.connection.active("github")
const credential = connection ? await ctx.integration.connection.resolve(connection) : undefined
```

Połącz integracje za pomocą klucza API.

```ts
await ctx.integration.connect.key({
  integrationID: "github",
  key: process.env.GITHUB_TOKEN!,
})
```

Rozpocznij, sprawdź, dokończ lub anuluj próbę połączenia OAuth.

```ts
const attempt = await ctx.integration.oauth.connect({ integrationID: "github", methodID: "oauth" })
const status = await ctx.integration.oauth.status({ integrationID: "github", attemptID: attempt.data.attemptID })
await ctx.integration.oauth.complete({ integrationID: "github", attemptID: attempt.data.attemptID, code })
await ctx.integration.oauth.cancel({ integrationID: "github", attemptID: attempt.data.attemptID })
```

Połączenia oparte na poleceniach udostępniają ten sam przepływ rozpoczęcia, sprawdzania statusu i anulowania.

```ts
const attempt = await ctx.integration.command.connect({ integrationID: "acme", methodID: "cli" })
const status = await ctx.integration.command.status({ integrationID: "acme", attemptID: attempt.data.attemptID })
await ctx.integration.command.cancel({ integrationID: "acme", attemptID: attempt.data.attemptID })
```

Zarejestruj transformację, aby przeglądać integracje i zarządzać ich metodami uwierzytelniania.

```ts
await ctx.integration.transform((editor) => {
  const integrations = editor.list()
  const acme = editor.get("acme")

  editor.update("acme", (integration) => {
    integration.name = "Acme"
  })
  editor.method.update({
    integrationID: "acme",
    method: { id: "cli", type: "command", label: "Sign in with Acme CLI", command: ["acme", "login"] },
  })

  const methods = editor.method.list("acme")
  const legacy = methods.find((method) => method.type === "command" && method.id === "legacy")
  if (legacy) editor.method.remove("acme", legacy)
  editor.remove("legacy")
})
```

Przeładuj integracje, gdy zmieni się stan zewnętrzny używany przez transformację.

```ts
await ctx.integration.reload()
```

### MCP

Wyświetl listę serwerów MCP i ich bieżący stan połączenia.

```ts
const servers = await ctx.mcp.list()
```

Wtyczki zarządzają serwerami MCP wyłącznie przez transformacje. Użyj `editor.set`, aby dodać lub zastąpić serwer,
`editor.update`, aby zmienić jego konfigurację, i `editor.remove`, aby go usunąć. Konfigurację sprawdzisz za pomocą
`editor.list` i `editor.get`.

```ts
await ctx.mcp.transform((editor) => {
  const servers = editor.list()
  const docs = editor.get("docs")
  editor.set("docs", { type: "remote", url: "https://mcp.example.com" })
  editor.update("docs", (server) => {
    server.disabled = false
  })
  editor.remove("legacy")
})
```

Ustaw w transformacji `disabled: true`, aby wyłączyć serwer i go rozłączyć, albo `disabled: false`, aby go włączyć
i pozwolić OpenCode się z nim połączyć. OpenCode uzgadnia cykl życia serwerów na podstawie przekształconej konfiguracji.

Gdy zmieni się stan zewnętrzny używany przez transformację, wywołaj `reload()`, aby ponownie zastosować transformacje
i uzgodnić stan serwerów.

```ts
await ctx.mcp.reload()
```

### Narzędzia

Poza callbackiem transformacji możesz odczytać aktualnie zarejestrowane narzędzia po zastosowaniu wszystkich
transformacji. Każde narzędzie ma `id` zawierające jego efektywną nazwę.

```ts
const tools = await ctx.tool.list()
const read = tools.find((tool) => tool.id === "read")
```

Rejestruj, aktualizuj i usuwaj narzędzia za pomocą synchronicznej transformacji, także we wtyczkach opartych na Promise.
Dane zewnętrzne wczytaj przed rejestracją lub przeładowaniem. Późniejsza poprawna rejestracja nadpisuje narzędzie
o tej samej efektywnej nazwie.

```ts
const registration = await ctx.tool.transform((editor) => {
  editor.namespace({
    name: "acme",
    description: "Customer account tools",
  })
  editor.add({
    name: "greeting",
    description: "Create a greeting",
    input: {
      type: "object",
      properties: { name: { type: "string" } },
      required: ["name"],
      additionalProperties: false,
    },
    options: { namespace: "acme", codemode: true },
    execute: async (input, context) => {
      await context.progress({ status: "greeting" })
      return { content: `Hello ${(input as { name: string }).name}!` }
    },
  })
})
```

Funkcje wykonujące narzędzia we wtyczkach opartych na Promise otrzymują `context.signal`. Przekaż go do operacji, które
można anulować, np. `fetch`, aby zatrzymanie sesji zatrzymywało też samą operację.

```ts
execute: async ({ url }, context) => {
  const response = await fetch(url, { signal: context.signal })
  return { content: await response.text() }
}
```

Po zmianie danych źródłowych przechwyconych przez callback wywołaj `reload()`. Przeładowanie odtwarza aktywne
transformacje bez zmiany ich kolejności; nie uruchamia ponownie konfiguracji wtyczki.

```ts
await ctx.tool.reload()
```

Użyj `list()` i `get()`, aby sprawdzić narzędzia znajdujące się obecnie w edytorze. Narzędzia mają `id` zawierające ich
efektywną nazwę, a `get()` zwraca `undefined`, gdy takiego ID nie ma. W `update` i `remove` podawaj efektywną nazwę
narzędzia wraz z przestrzenią nazw (powyżej `acme_greeting`). Kropki w przestrzeniach nazw i nieobsługiwane znaki
w nazwach narzędzi są zamieniane na `_`. Nieistniejące nazwy są ignorowane; utworzenie narzędzia wymaga wywołania `add`
z pełną definicją. Aktualizacje zachowują nazwę i przestrzeń nazw. Aby zastąpić schematy lub opcje, przypisz nowe
wartości zamiast modyfikować zagnieżdżone pola. Niepoprawne aktualizacje są logowane, a poprzednia definicja pozostaje
bez zmian.

```ts
await ctx.tool.transform((editor) => {
  editor.update("acme_greeting", (tool) => {
    tool.description = "Greet the user by name"
  })
  editor.remove("acme_obsolete")
})
```

Aktualizacje i usunięcia są odtwarzane w kolejności razem z dodaniami, także po odświeżeniu katalogu MCP. Zwolnienie ich
rejestracji usuwa te zmiany i odbudowuje stan z pozostałych transformacji.

Zwolnij rejestrację, aby usunąć jej transformację i odbudować stan z pozostałych transformacji. Ujawni to wcześniejszą
definicję, którą nadpisywała. Zwolnienie jest idempotentne, a wyładowanie wtyczki również zwalnia jej rejestracje.

```ts
await registration.dispose()
```

Każde żądanie do modelu przechwytuje stabilną, wykonywalną migawkę narzędzi. Późniejsze transformacje, przeładowania
i zwolnienia wpływają na przyszłe migawki, a nie na już przechwycone definicje, opisy przestrzeni nazw Code Mode czy
funkcje wykonujące. Funkcje wykonujące, które domykają modyfikowalne dane wtyczki, nadal widzą te dane; jeśli wartość
musi pozostać związana z daną definicją, przechwyć ją wewnątrz transformacji.

### Worktree

Zarejestruj lokalną strategię worktree w ramach zwykłego cyklu życia wtyczki. W tym przykładzie moduł implementacji
odpowiada za walidację opcji i operacje backendu `create`, `remove` oraz `list`.

```ts title="plugins/worktrees/index.ts"
import { Plugin } from "@opencode/plugin"
import { makeStrategy } from "./strategy"

export default Plugin.define({
  id: "company.worktrees",
  async setup(ctx) {
    const strategy = makeStrategy(ctx.options)
    await ctx.worktree.transform((editor) => {
      editor.add(strategy)
    })
  },
})
```

Wczytaj wtyczkę przez `plugins`, a wspólny katalog docelowy skonfiguruj osobno:

```jsonc title="opencode.jsonc"
{
  "worktree": { "directory": "../worktrees" },
  "plugins": [{ "package": "./plugins/worktrees", "options": {} }],
}
```

- Dodanie strategii automatycznie ją wybiera. Wygrywa ostatnia aktywna rejestracja; konfiguracja wyboru strategii nie
  jest potrzebna.
- Zwolnienie rejestracji lub wyładowanie wtyczki przywraca poprzednią implementację, a ostatecznie wbudowaną strategię
  Git.
- `reload()` odtwarza transformacje po zmianie przechwyconych danych; nie uruchamia ponownie konfiguracji wtyczki.
- Nieudane tworzenie nie jest ponawiane przez Git. Istniejące worktree zachowują zapisanego właściciela nawet po zmianie
  strategii domyślnej.
- Strategie zarządzają lokalnymi katalogami. Udostępnianie zdalnych obszarów roboczych nie jest częścią tego interfejsu.

#### Operacje

Kontekst wtyczki udostępnia te same operacje na worktree w obrębie projektu co klient. Każda operacja wymaga
`projectID`. `list` odczytuje tylko zapisany spis, w tym znane kopie robocze tego samego projektu; nie wczytuje
konfiguracji, nie uruchamia wtyczek ani nie wykrywa zmian w systemie plików.

```ts
const projectID = ctx.location.project.id
const created = await ctx.worktree.create({ projectID, name: "task" })
const inventory = await ctx.worktree.list({ projectID })
await ctx.worktree.refresh({ projectID })
await ctx.worktree.remove({ projectID, directory: created.directory, force: false })
```

Tworzenie wczytuje konfigurację i wtyczki z zapisanego katalogu `canonical` projektu i używa wybranej przez nie
strategii. Przyjmuje opcjonalny katalog nadrzędny `directory`, źródło `from`, gałąź początkową `branch` i nazwę `name`.
Domyślnym źródłem jest kanoniczna kopia robocza, a źródło podane w `from` musi należeć do tego projektu. Wybór źródła nie
zmienia katalogu głównego konfiguracji. Podana referencja początkowa musi być obsługiwana przez wybraną strategię – na
przykład natywna operacja migawki w Rift nie ma opcji wyboru referencji.

Tworzenie i odświeżanie czekają na aktywację wtyczek kanonicznej kopii roboczej. Wywołania wykonane podczas konfiguracji
wtyczek tej kopii widzą dotychczasowe rejestracje i nie czekają na własną aktywację.

Usuwanie wczytuje kanoniczną konfigurację i aktywuje jej wtyczki, a następnie używa strategii zapisanej dla danego
worktree, a nie aktualnie wybranej strategii domyślnej. Niedostępny zapisany właściciel powoduje błąd. Katalog docelowy
worktree może znajdować się gdzie indziej:

```ts
await ctx.worktree.remove({
  directory: "/worktrees/task",
  projectID,
  force: false,
})
```

Brak właściciela kończy usuwanie błędem zamiast przejścia na Git. Strategia może rzucić
`new Worktree.OperationError({ message: "Uncommitted changes", forceRequired: true })`, importując `Worktree`
z `@opencode/plugin`, aby zażądać potwierdzenia wymuszenia bez zależności od błędów Core czy Git.

Odświeżanie wczytuje kanoniczną konfigurację i prosi wszystkie dostępne strategie o znalezienie worktree we wszystkich
znanych katalogach głównych kopii roboczych. Łączy wyniki, zachowuje zapisanych właścicieli i usuwa nieistniejące
katalogi. Błąd jednego źródła wykrywania jest logowany, a pozostałe źródła działają dalej. Istniejące katalogi pozostają
zapisane, nawet jeśli żadna dostępna strategia ich nie zgłasza. Aby odczytać zmieniony spis, nasłuchuj zdarzenia
`worktree.updated` i ponownie wywołaj `list`.

```ts
await ctx.worktree.refresh({ projectID })
```

#### Referencja

Implementacje otrzymują sugerowany katalog docelowy po nadaniu nazwy i obsłużeniu kolizji. Zwróć z `create` faktyczny
katalog; może się różnić, jeśli backend wymaga własnego układu. OpenCode rozwiązuje zwróconą ścieżkę i używa jej
w spisie, poleceniach startowych i wyniku API. Zwrócony katalog musi istnieć.

Strategie, które wybierają inny katalog docelowy, same obsługują tam kolizje nazw. OpenCode i tak tworzy sugerowany
katalog nadrzędny przed wywołaniem strategii. `list` musi zgłaszać tylko katalogi należące do strategii oraz ewentualne
katalogi główne repozytoriów.

## Hooki

Hooki przechwytują operacje w trakcie ich wykonywania. Zarejestruj hook w jego domenie i zwolnij zwróconą rejestrację,
gdy nie jest już potrzebna.

```ts
const registration = await ctx.session.hook("context", () => {})
await registration.dispose()
```

Ten sam hook może zarejestrować wiele wtyczek. OpenCode uruchamia je w kolejności wtyczek, więc późniejsze hooki widzą
zmiany wprowadzone przez wcześniejsze.

### Sesje

Hooki sesji przechwytują przyjmowanie promptów, wywołania modelu, natywne HTTP i ponawianie prób.

#### Przyjmowanie promptów

Przechwytuj przychodzące prompty użytkownika przed rozwiązaniem załączników i umiejętności oraz przed trwałym przyjęciem
do skrzynki odbiorczej (inbox):

```ts
await ctx.session.hook("prompt", (event) => {
  event.prompt.text = event.prompt.text.replaceAll("company-secret", "[redacted]")
  event.prompt.files ??= []
  event.prompt.files.push({ uri: "file:///project/policy.md" })
  event.metadata = { ...event.metadata, source: "company-policy" }
  event.delivery = "queue"
})
```

Hook otrzymuje własną, modyfikowalną wersję roboczą:

- `prompt` zawiera `text`, `files`, wzmianki o agentach w `agents` i wybrane `skills`.
- `metadata` zawiera definiowane przez aplikację metadane przyjęcia.
- `delivery` ma domyślnie wartość `"steer"` i można je zmienić na `"queue"`.
- ID sesji i wiadomości są tylko do odczytu; hook nie może przekierować przyjęcia.

Pliki i umiejętności dodane przez hook przechodzą zwykłą ścieżkę rozwiązywania i walidacji. Jeśli zmieniasz tekst,
zaktualizuj lub usuń przesunięcia `mention` załączników, które przestały pasować. Wzmianki o agentach nie zmieniają
aktywnego agenta sesji.

Hooki promptów działają na następujących warunkach:

- Hooki są uruchamiane w kolejności rejestracji, gdy wtyczki lokalizacji sesji są gotowe.
- Polecenia, które wysyłają prompt przez `session.prompt`, uruchamiają hook.
- Wiadomości syntetyczne, wiadomości powłoki, sterowanie kompaktowaniem i sterowanie przenoszeniem – nie.
- Hook jest uruchamiany raz podczas przyjęcia, a nie przed każdym wywołaniem modelu.
- Zawężenie do dostawcy jest niedostępne, ponieważ model jest rozwiązywany dopiero po przyjęciu.

Wprowadzone zmiany stają się kanonicznymi, zapisywanymi danymi wejściowymi użytkownika. Jeśli przygotowanie się nie
powiedzie lub zostanie przerwane, OpenCode nie przyjmie promptu.

Hooki promptów muszą być bezpieczne przy ponawianiu. Nie gwarantują, że efekty uboczne wystąpią dokładnie raz:

- Ponowienie z ID, które już oczekuje lub zostało dostarczone, zwraca pierwotne przyjęcie bez ponownego uruchamiania
  hooków.
- Przy równoczesnych wysyłkach hooki mogą zostać uruchomione więcej niż raz, ale wygrywa tylko pierwsze udane przyjęcie.
- Hooki promptów przekształcają dane wejściowe i nie udostępniają typowanego API odrzucania.

#### Żądania do modelu

Modyfikuj złożone instrukcje systemowe, wiadomości, narzędzia lub opcje żądania bezpośrednio przed wysłaniem do modelu.
Każdy rodzaj żądania wysyłanego przez sesję ma własny hook, więc wtyczka może inaczej traktować pętlę agenta, a inaczej
żądania pomocnicze:

- `context` działa w pętli agenta, łącznie z kontynuacjami wynikającymi z wywołań narzędzi.
- `compaction` działa przy podsumowaniach punktów kontrolnych. `messages` to podsumowywana transkrypcja; OpenCode dołącza
  swój prompt podsumowania po uruchomieniu hooków. Ustaw `result`, aby samodzielnie zapisać wynik kompaktowania
  i pominąć wywołanie modelu; przyjmuje on te same pola co ukończona wiadomość kompaktowania.
- `generate` działa przy jednorazowych wywołaniach `ctx.session.generate`.
- `title` działa przy generowaniu tytułu. Nie ma `agent` ani `tools`. Ustaw `result`, aby samodzielnie podać tytuł.

```ts
await ctx.session.hook("context", (event) => {
  event.system.push({ type: "text", text: "Keep the review focused on correctness." })
  delete event.tools.write
  event.options.temperature = 0.2
  event.options.maxTokens = 8_000
})

await ctx.session.hook("compaction", async (event) => {
  event.result = { summary: await summarize(event.messages) }
})
```

Zmiany wpływają tylko na wychodzące wywołanie modelu, a nie na zapisaną historię czy konfigurację. Hook, który ma
działać dla każdego żądania, musi zostać zarejestrowany dla każdego rodzaju.

Nadpisania żądań podlegają tym regułom:

- `options` jest puste na początku każdego wywołania modelu; nie zawiera rozwiązanych ustawień modelu.
- Typowane klucze to ustawienia generowania; każdy inny klucz jest przekazywany do wybranego protokołu jako opcja
  dostawcy.
- Hooki są uruchamiane w kolejności rejestracji i widzą nadpisania wprowadzone przez wcześniejsze hooki.
- Nadpisania żądania mają pierwszeństwo przed wartościami domyślnymi modelu, a te – przed wartościami domyślnymi trasy.
- Obiekty opcji dostawcy są scalane rekurencyjnie; tablice i wartości skalarne zastępują wcześniejsze wartości.
- Usunięcie nadpisania lub ustawienie go na `undefined` przywraca skonfigurowane wartości domyślne, a nie usuwa ich.
- Nakładki na surowe ciało żądania HTTP są stosowane po przetłumaczeniu na protokół i mogą nadpisać wynikowe pola.

#### Opcje dostawcy

Opcje dostawcy używają semantycznych nazw opcji wybranego protokołu, a nie surowych pól ciała żądania HTTP. Ustawienia
specyficzne dla dostawcy zawężaj do odpowiedniego dostawcy. Na przykład OpenAI Responses używa `reasoningEffort`:

```ts
await ctx.session.hook(
  "context",
  (event) => {
    event.options.reasoningEffort = "high"
  },
  { providerID: "openai" },
)
```

Opcje generowania zależą od wybranego protokołu i modelu:

- `maxTokens` to semantyczny limit tokenów wyjściowych.
- Gemini obsługuje `topK`; OpenAI Responses go nie udostępnia.

#### Żądanie do modelu

Modyfikuj ustawienia żądania do modelu i opcjonalnie zawęź hook do jednego dostawcy. Zdarzenie zawiera to samo pole
`kind` co opisane niżej hooki HTTP.

```ts
await ctx.session.hook(
  "model.request",
  (event) => {
    event.headers["x-plugin"] = "review"
  },
  { providerID: "anthropic" },
)
```

#### Natywne HTTP

Modyfikuj natywne żądania i odpowiedzi dostawcy. Ich ciała to strumienie jednorazowego odczytu; przed odczytem sklonuj
lub zastąp ciało.

Oba hooki działają dla każdego żądania wysyłanego przez sesję. `event.kind` wskazuje, który przepływ je wysłał:
`"primary"` – pętla agenta, `"compaction"` – podsumowania punktów kontrolnych, `"title"` – generowanie tytułu,
a `"generate"` – jednorazowe wywołania `ctx.session.generate`. Do rozróżniania żądań pomocniczych używaj tego pola, a nie
ID agenta.

```ts
await ctx.session.hook("http.request", (event) => {
  event.request.headers.set("x-session-id", event.sessionID)
  if (event.kind === "title") event.request.headers.set("x-priority", "background")
})

await ctx.session.hook("http.response", (event) => {
  event.response = new Response(event.response.body, {
    status: event.response.status,
    headers: { ...Object.fromEntries(event.response.headers), "x-plugin": "review" },
  })
})
```

#### Natywny WebSocket (eksperymentalne)

Dostawcy, którzy przesyłają strumień przez WebSocket, otwierają jedno połączenie na sesję i używają go ponownie dla
kolejnych żądań, więc `http.request` i `http.response` nigdy nie widzą tego ruchu. Hook `experimental.ws.handshake` jest
uruchamiany raz na wywołanie modelu, przed wybraniem połączenia. Zawiera te same pola `sessionID`, `agent`, `model`
i `kind` co hooki HTTP oraz `url` i `headers` połączenia. Zmiana `url` lub `headers` zmienia gniazdo używane przez
żądanie, więc zrotowany token typu bearer powoduje ponowne otwarcie połączenia.

Hooki HTTP nadal działają dla każdego żądania HTTP, w tym dla żądania, na które przechodzi trasa WebSocket w razie
niepowodzenia.

```ts
await ctx.session.hook(
  "experimental.ws.handshake",
  async (event) => {
    event.headers.authorization = `Bearer ${await mintToken(event.url)}`
    delete event.headers["api-key"]
  },
  { providerID: "azure" },
)
```

`experimental.ws.send` i `experimental.ws.receive` udostępniają same ramki – to odpowiednik edycji ciała żądania lub
odpowiedzi HTTP w świecie WebSocket. `send` działa po zbudowaniu ramki wychodzącej przez sterownik dostawcy, a przed jej
zapisaniem; `receive` działa dla każdej ramki przychodzącej, zanim zobaczy ją sterownik. Oba przekazują ramkę jako ciąg
znaków i wysyłają to, co zawiera `frame` po zakończeniu hooka.

OpenCode nie waliduje zmodyfikowanych ramek. Sterownik śledzi stan na podstawie odpowiedzi dostawcy, więc za zmianę,
która modyfikuje znaczenie protokołu, odpowiada wtyczka – tak samo jak w przypadku zmodyfikowanego ciała HTTP.

```ts
await ctx.session.hook(
  "experimental.ws.send",
  (event) => {
    const body = JSON.parse(event.frame)
    if (body.type === "response.create") body.metadata = { ...body.metadata, session: event.sessionID }
    event.frame = JSON.stringify(body)
  },
  { providerID: "openai" },
)

await ctx.session.hook("experimental.ws.receive", (event) => {
  if (event.frame.includes('"type":"error"')) console.error(event.frame)
})
```

Te hooki są eksperymentalne, a ich nazwy lub struktura mogą się zmienić.

#### Zasady ponawiania

Nadpisz decyzję o ponowieniu po błędzie dostawcy lub zastąp jej opóźnienie (w milisekundach). Hook działa po tym, jak
OpenCode sklasyfikuje błąd i zaproponuje zasadę ponawiania, ale przed zaplanowaniem jakiejkolwiek ponownej próby. Nie
ujawnia, jak OpenCode wewnętrznie wykonuje kolejną próbę.

```ts
await ctx.session.hook("retry", (event) => {
  if (event.error.status === 429) {
    event.decision = { retry: true, delay: 10_000 }
    return
  }
  if (event.error.type === "provider.invalid-request" && event.attempt === 2) {
    event.decision = { retry: true, delay: 0 }
    return
  }
  if (event.attempt >= 3) event.decision = { retry: false }
})
```

Hooki ponawiania mogą zmienić początkową decyzję (`decision`) OpenCode, sprawiając, że błąd końcowy zostanie ponowiony,
albo blokując zaproponowane ponowienie.

Decyzje o ponawianiu podlegają tym regułom:

- Wiele hooków jest uruchamianych w kolejności rejestracji, a późniejsze hooki widzą bieżącą decyzję.
- Wbudowana maksymalna liczba prób pozostaje twardym limitem.
- `attempt` to rozważana fizyczna próba. Pierwsze żądanie ma numer `1`, więc pierwsze ponowienie to `2`.
- Niepoprawne opóźnienia, takie jak `NaN`, nieskończoność lub wartości ujemne, są zastępowane wyliczonym opóźnieniem.
- Obsługa przepełnienia kontekstu jest osobnym mechanizmem, ponieważ kompaktuje rozmowę zamiast ponawiać to samo
  żądanie.

### Uprawnienia

Weryfikuj decyzje dotyczące uprawnień po ocenie skonfigurowanych reguł, a przed wykonaniem akcji lub opublikowaniem
prośby o uprawnienie.

```ts
await ctx.permission.hook("evaluate", async (event) => {
  if (event.action === "read") return

  const messages = await ctx.session.context({ sessionID: event.sessionID })
  const review = await ctx.generate.text({
    model: { providerID: "anthropic", id: "claude-sonnet-4-6" },
    prompt: buildSafetyPrompt({ messages, action: event.action, resources: event.resources }),
  })
  const decision = parseDecision(review.text)

  event.effect = decision.effect
  event.message = decision.reason
})
```

Hooki uprawnień podlegają tym regułom:

- Hooki są uruchamiane dla decyzji `allow` i `ask`.
- Jawnie skonfigurowane `deny` jest ostateczne i nie wywołuje hooka.
- Hook może zmienić `effect` na `allow`, `ask` lub `deny`.
- `message` pojawia się w eskalowanym żądaniu uprawnienia lub staje się powodem odmowy.

## Publikowanie

Wtyczka w pakiecie używa tego samego eksportu domyślnego co wtyczka lokalna. Minimalny manifest wygląda tak:

```json title="package.json"
{
  "name": "opencode-acme-plugin",
  "version": "1.0.0",
  "type": "module",
  "exports": {
    ".": "./src/index.ts",
    "./rpc": "./src/rpc.ts"
  },
  "dependencies": {
    "@opencode/plugin": "latest"
  }
}
```

Eksport `./rpc` jest opcjonalny. Dodaj go, jeśli publikujesz współdzielony [kontrakt RPC](/build/plugins/rpc), który
inne wtyczki i klienci mogą importować bez wczytywania Twojej implementacji.

Używaj wersji zgodnych z wydaniem OpenCode, na które celujesz, i testuj zainstalowany pakiet, a nie tylko kopię
podlinkowaną w obszarze roboczym. Gdy przechodzisz na nowszy kontrakt API, opublikuj zgodną aktualizację wtyczki.

## Obsługa V1

Wtyczka może obsługiwać V1 i V2 z tego samego punktu wejścia pakietu. Wyeksportuj domyślnie jeden obiekt z funkcją
`server()` dla V1 i funkcją `setup()` dla V2:

```ts title="src/index.ts"
import { Plugin } from "@opencode/plugin"

export default {
  ...Plugin.define({
    id: "example",
    async setup(ctx) {
      await ctx.tool.hook("execute.before", () => {
        console.log("A tool is about to run")
      })
    },
  }),
  async server() {
    return {
      "tool.execute.before": async () => {
        console.log("A tool is about to run")
      },
    }
  },
}
```

- V1 wywołuje `server()` i używa zwróconych hooków.
- V2 odczytuje `id` i `setup()` z eksportu domyślnego (lub `effect()` w przypadku wtyczek Effect), ignorując `server()`.
- Każda implementacja powinna korzystać z własnego API; wspólny eksport nie tłumaczy hooków V1 na hooki V2.
- Rozwiń `Plugin.define(...)` w eksportowanym obiekcie (spread), aby definicja V2 była sprawdzana pod względem typów
  niezależnie od `server()`.

Obiektowa forma V1 jest obsługiwana w OpenCode `1.18.29`. Starsze wydania V1 mogą oczekiwać eksportów funkcji; przetestuj
zainstalowany pakiet z najstarszym wydaniem V1, które zamierzasz obsługiwać, oraz z V2.
