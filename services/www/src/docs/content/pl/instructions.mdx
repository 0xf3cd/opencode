---
title: "Instrukcje"
---

Dodaj plik `AGENTS.md`, aby przekazać OpenCode stałe wskazówki dotyczące projektu. Umieść w nim polecenia budowania, uwagi o architekturze, konwencje kodu i wymagania dotyczące weryfikacji.

```md title="AGENTS.md"
# Project instructions

- Run `bun typecheck` after changing TypeScript.
- Keep database queries in `src/database`.
- Do not edit generated files directly.
```

Commituj pliki instrukcji projektu, aby każdy, kto pracuje w repozytorium, otrzymywał te same wskazówki.

## Zakres

Umieść `AGENTS.md` w katalogu, którego mają dotyczyć zawarte w nim wskazówki. OpenCode wczytuje plik globalny, a następnie każdy plik `AGENTS.md` od bieżącego katalogu obszaru roboczego w górę, w stronę katalogu domowego. W przypadku obszarów roboczych spoza katalogu domowego zatrzymuje się na katalogu głównym projektu.

```text
~/.config/opencode/AGENTS.md
~/code/my-project/AGENTS.md
~/code/my-project/packages/AGENTS.md
~/code/my-project/packages/web/AGENTS.md  ← current workspace
```

W tym przykładzie wczytywane są wszystkie cztery pliki. Są łączone w następującej kolejności:

```text
~/.config/opencode/AGENTS.md
packages/web/AGENTS.md
packages/AGENTS.md
AGENTS.md
```

Wskazówki obowiązujące wszędzie trzymaj w pliku globalnym. Wskazówki dla całego repozytorium umieść w katalogu głównym projektu, a bardziej szczegółowe – bliżej kodu, którego dotyczą. OpenCode łączy pliki i nie rozstrzyga konfliktów między nimi.

Jeśli obszar roboczy znajduje się poza katalogiem głównym projektu, wczytywany jest tylko plik globalny. Ustaw `OPENCODE_DISABLE_PROJECT_CONFIG=1`, aby pominąć wyszukiwanie plików `AGENTS.md` projektu bez wyłączania pliku globalnego.

<Callout type="note">
  OpenCode V2 rozpoznaje wyłącznie `AGENTS.md`. Nie używa `CLAUDE.md` jako pliku zapasowego.
</Callout>

## Wykrywanie

Pliki instrukcji znajdujące się poniżej obszaru roboczego są wykrywane w miarę, jak agent eksploruje projekt. Odczyt pliku lub wylistowanie katalogu wczytuje wszystkie pliki `AGENTS.md` leżące między tym celem a obszarem roboczym.

```text
my-project/                         ← current workspace
├── AGENTS.md                       loaded initially
└── packages/
    └── web/
        ├── AGENTS.md               loaded when this area is read
        └── src/
            └── app.ts              read target
```

Zagnieżdżone pliki są wczytywane od najbliższego i deduplikowane, dopóki ich wpis instrukcji pozostaje w historii widocznej dla modelu. Ponowny odczyt tego samego obszaru zwykle nie wstrzykuje ich ponownie. Jeśli kompaktowanie kontekstu lub wycofanie usunie ten wpis, późniejszy odczyt może wczytać plik jeszcze raz.

Zmiany w zagnieżdżonym pliku po jego wczytaniu nie są wykrywane automatycznie. Jeśli zaktualizowany tekst ma obowiązywać od razu, rozpocznij nową sesję.

## Kolejność

Najpierw wysyłany jest prompt systemowy wybranego agenta lub dostawcy. Następnie OpenCode składa początkowe instrukcje w tej kolejności:

```text
1. Agent or provider system prompt
2. Built-in environment and date context
3. Code Mode tool guidance, when enabled
4. Global and project AGENTS.md files
5. Available skill, reference, and MCP guidance
6. Session-specific instruction entries supplied through the API
```

Te źródła są łączone, a nie wzajemnie nadpisywane. Zagnieżdżone pliki `AGENTS.md` wykryte później są dodawane do historii sesji w kolejności wykrycia.

## Aktualizacje

Aby zaktualizować wskazówki działającej sesji, edytuj globalny plik `AGENTS.md` lub plik wykryty w katalogach nadrzędnych.

```bash
$ printf '\n- Run the integration suite before committing.\n' >> AGENTS.md
```

Przed następnym żądaniem do modelu OpenCode wykrywa zmianę i dodaje aktualizację instrukcji, zanim dostarczy oczekujące dane wejściowe:

```text
AGENTS.md changes
→ instruction update
→ next prompt
```

- Usunięcie wszystkich stale wczytywanych plików `AGENTS.md` (globalnego i z katalogów nadrzędnych) informuje sesję, że poprzednie instrukcje z tych plików przestały obowiązywać.
- Chwilowy błąd odczytu zachowuje ostatnie znane instrukcje, zamiast traktować je jak usunięte.
- Przeniesienie sesji zachowuje jej stan instrukcji, więc wskazówki z katalogu docelowego są wprowadzane jako aktualizacja.
- Zatwierdzenie wycofania w sesji czyści jej stan instrukcji i ponownie wczytuje instrukcje przed następnym promptem.

Treść instrukcji pozostaje uprzywilejowana. Klienty widzą, które źródła się zmieniły, ale nie widzą ich zawartości.

## Plik konfiguracyjny

Schemat konfiguracji V2 akceptuje tablicę `instructions`, ale V2 obecnie nie rozwiązuje wskazanych w niej plików, wzorców glob ani URL-i. Ta konfiguracja na razie nie dodaje instrukcji do modelu:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "instructions": ["CONTRIBUTING.md", "docs/guidelines/*.md", "https://example.com/instructions.md"],
}
```

Aktywne instrukcje w V2 umieszczaj w `AGENTS.md`. Lokalizacje plików konfiguracyjnych i kolejność pierwszeństwa opisano w sekcji [Konfiguracja](/config).
