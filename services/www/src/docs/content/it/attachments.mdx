## Allegare file

Allega un file locale, poi chiedi a OpenCode di usarlo nel prompt. Nel client desktop o web
scegli **Attach file**, incolla un file o trascinalo nel prompt.

```text
Summarize the attached README.md and list the required setup steps.
```

I file scelti con il selettore di file dell'app desktop possono arrivare in totale a 20 MiB. Altre
interfacce possono applicare limiti inferiori lato client.

<Callout type="warning">
  Prima di allegare un'immagine, scegli un modello che accetti immagini in input. OpenCode può passare al provider le
  immagini supportate, ma il provider e il modello applicano comunque i propri vincoli su formati, dimensioni, numero e
  peso dei file. Un modello solo testuale può rifiutare la richiesta.
</Callout>

## Sintassi

Gli input dei prompt e dei comandi di V2 descrivono un allegato con un `uri` e con i campi
facoltativi `name` e `description`:

```json
{
  "uri": "file:///home/me/project/src/server.ts",
  "name": "server.ts",
  "description": "HTTP server entrypoint"
}
```

Usa un URL `file:` assoluto per un file o una directory accessibile al server. Per i file di
testo, i parametri positivi `start` ed `end` selezionano le righe, numerate a partire da uno.

```text
file:///home/me/project/src/server.ts?start=20&end=60
```

Usa un URL `data:` per inviare il contenuto inline:

```json
{
  "uri": "data:text/plain;base64,SGVsbG8sIE9wZW5Db2RlIQ==",
  "name": "greeting.txt"
}
```

Gli URL HTTP e HTTPS non sono supportati come allegati. Per l'invio di prompt tramite codice,
consulta il [riferimento dell'API](/api) generato.

## Formati

Nelle sessioni V2 attuali, questi tipi di allegato sono visibili al modello:

| Input                      | Cosa riceve il modello                                          | Esempio            |
| -------------------------- | --------------------------------------------------------------- | ------------------ |
| File di testo UTF-8        | Nome del file e testo decodificato                              | `README.md`        |
| Directory                  | Elenco non ricorsivo dei file e delle directory di primo livello | `file:///home/me/` |
| PNG, JPEG, GIF o WebP      | Contenuto multimediale dell'immagine                            | `diagram.png`      |

SVG viene trattato come testo. PDF, AVIF, BMP, audio, video e altri allegati binari non vengono
inclusi nella richiesta al modello. Converti prima un file binario non supportato in testo o in
un'immagine supportata; ad esempio, esporta una pagina di un PDF come `page-1.png` prima di
allegarla.

OpenCode legge ogni allegato prima di accettare il prompt. Rifiuta URL non validi, percorsi
illeggibili, percorsi che non siano file o directory e allegati che, una volta decodificati,
superano i 20 MiB. Il tipo di contenuto viene rilevato dai byte, quindi cambiare il nome di un file
o il tipo indicato in un URL `data:` non rende visibile un file binario non supportato.

## Immagini

Configura la normalizzazione delle immagini in `opencode.json` o `opencode.jsonc`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "media": {
    "image": {
      "auto_resize": true,
      "max_width": 2000,
      "max_height": 2000,
      "max_base64_bytes": 5242880,
    },
  },
}
```

Tutti i campi sono facoltativi:

| Campo              | Predefinito | Comportamento                                                                          |
| ------------------ | ----------- | -------------------------------------------------------------------------------------- |
| `auto_resize`      | `true`      | Ridimensiona un'immagine che supera un limite configurato; se `false`, la rifiuta.      |
| `max_width`        | `2000`      | Larghezza massima in pixel; deve essere un intero positivo.                            |
| `max_height`       | `2000`      | Altezza massima in pixel; deve essere un intero positivo.                              |
| `max_base64_bytes` | `5242880`   | Numero massimo di byte dell'immagine codificata in Base64; deve essere un intero positivo. |

Ad esempio, questa configurazione rifiuta, invece di ridimensionarla, un'immagine più larga di
1200 pixel:

```jsonc title="opencode.jsonc"
{
  "media": {
    "image": {
      "auto_resize": false,
      "max_width": 1200,
    },
  },
}
```

Queste impostazioni si applicano sia alle immagini supportate allegate ai prompt sia alle immagini
restituite dallo strumento integrato `read`.

## Elaborazione

Lo strumento `read` riconosce PNG, JPEG, GIF e WebP dal loro contenuto e legge fino a 20 MiB di
dati dell'immagine originale. Confronta larghezza, altezza e lunghezza in Base64 con i limiti
configurati per le immagini.

Con `auto_resize: true`, OpenCode mantiene le proporzioni e riduce l'immagine entro i limiti di
dimensione. Prova poi codifiche PNG e JPEG via via più compatte finché non rispetta il limite
Base64, quindi il tipo di contenuto in uscita può cambiare.

```text
Input:  4000 × 2000 WebP
Limits: 2000 × 2000
Output: 2000 × 1000 PNG or JPEG
```

Se nessuna codifica rientra nel limite, l'elaborazione fallisce. Con `auto_resize: false`,
un'immagine che supera uno qualsiasi dei limiti fallisce senza essere modificata; fallisce anche
un'immagine che non può essere decodificata.

```text
Input:  2400 × 1600 JPEG
Limit:  max_width = 2000, auto_resize = false
Result: Image processing fails
```

Se il ridimensionatore di immagini non è disponibile, OpenCode passa l'immagine originale senza
modificarla. Le impostazioni delle immagini sono quindi limiti di elaborazione, non un limite di
caricamento né una barriera di sicurezza.

## Limiti

| Limite                                  | Valore o comportamento                                          | Esempio                                                  |
| --------------------------------------- | --------------------------------------------------------------- | -------------------------------------------------------- |
| Allegato diretto                        | 20 MiB decodificati per elemento; i client possono imporre limiti inferiori | Due file da 12 MiB rispettano il limite per elemento |
| Selezione con il selettore desktop      | 20 MiB in totale                                                | Due file da 12 MiB superano il limite della selezione    |
| `max_base64_bytes`                      | Solo il Base64 codificato, escluso l'URL `data:` completo       | `SGVsbG8=` conta come 8 byte                             |
| Limiti del provider per le immagini     | Si applicano dopo l'elaborazione di OpenCode                    | Un provider può rifiutare un'immagine accettata          |
| Supporto del modello agli allegati di testo | Non richiede un modello multimodale                         | `notes.txt` viene inserito come testo del prompt         |
| Limiti di testo di `read`               | Usa limiti separati per la paginazione e il troncamento         | Leggi un log di grandi dimensioni a pagine               |

Il fatto che un client accetti un file non garantisce che il suo contenuto arrivi al modello.
L'allegato deve usare un formato visibile al modello e rispettare sia i limiti di OpenCode sia
quelli del provider.
