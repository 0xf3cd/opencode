OpenCode include un catalogo di provider e modelli proveniente da [models.dev](https://models.dev). Per la maggior parte
dei provider, collega prima un account e poi seleziona un modello.

## Configurazione iniziale

Esegui `/connect`, scegli un provider e inserisci le sue credenziali. Poi esegui `/models` per selezionare uno dei suoi
modelli.

```text
/connect
/models
```

## Go

[OpenCode Go](/console/go) è un abbonamento facoltativo per modelli di programmazione testati dal team di OpenCode.
Abbonati nella [console](https://opencode.ai/console), copia la tua chiave API e collegala come **OpenCode Go**.

```text
/connect
# Select OpenCode Go, then paste your API key.
/models
```

Consulta la [guida di Go](/console/go) per i limiti di utilizzo, gli endpoint e i dettagli sulla privacy.

## Provider personalizzati

Aggiungi un provider quando la sua API non è già presente nel catalogo. Questo esempio compatibile con OpenAI definisce
insieme la credenziale, il pacchetto di runtime, l'endpoint e il primo modello.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "acme": {
      "name": "Acme",
      "env": ["ACME_API_KEY"],
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "https://llm.acme.example/v1",
      },
      "models": {
        "qwen3-coder": {
          "name": "Qwen 3 Coder",
        },
      },
    },
  },
}
```

Le chiavi dell'oggetto `providers` sono gli ID dei provider usati nei riferimenti ai modelli, come `acme/qwen3-coder`.

| Campo | Scopo |
| --- | --- |
| `name` | Nome visualizzato. |
| `env` | Nomi delle variabili d'ambiente, in ordine, che possono fornire la credenziale. |
| `package` | Pacchetto di runtime del provider. |
| `canonical` | ID del provider integrato da cui questo provider eredita i valori predefiniti del catalogo. |
| `compatibility` | Override di compatibilità di richieste e risposte per tutti i modelli di questo provider. Il campo `compatibility` del modello sovrascrive i singoli campi. `supportsThinkingBlockBinding` e `supportsEffortUpdates` sono disponibili solo a livello di modello. |
| `settings` | Controlli tipizzati di OpenCode e opzioni JSON passate al pacchetto di runtime. |
| `headers` | Intestazioni HTTP con valori stringa aggiunte alle richieste. |
| `body` | Campi JSON uniti al corpo delle richieste. |
| `models` | Modelli da aggiungere o sovrascrivere, indicizzati per ID del modello in OpenCode. |

## Endpoint

Sovrascrivi `settings.baseURL` per far passare un provider del catalogo attraverso un proxy o un endpoint compatibile. Il
pacchetto, i modelli e la connessione esistenti continuano a valere.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "anthropic": {
      "settings": {
        "baseURL": "https://llm-proxy.example.com/anthropic",
      },
    },
  },
}
```

`settings` dipende dal pacchetto: un campo ha effetto solo se il pacchetto selezionato lo supporta.

## Richieste

Usa `headers` per aggiungere intestazioni HTTP e `body` per i campi JSON da unire al corpo di ogni richiesta.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "headers": {
        "X-Gateway-Tenant": "engineering",
      },
      "body": {
        "metadata": {
          "application": "opencode",
        },
      },
    },
  },
}
```

Entrambi i campi possono essere impostati anche su un modello o una variante, quando l'override serve solo per una parte
del traffico di un provider.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "models": {
        "gpt-5.2": {
          "headers": { "X-Model-Tier": "coding" },
          "variants": [
            {
              "id": "batch",
              "body": { "service_tier": "flex" },
            },
          ],
        },
      },
    },
  },
}
```

## Timeout

Le richieste HTTP attendono fino a cinque minuti le intestazioni della risposta e fino a cinque minuti tra un chunk e
l'altro della risposta in streaming. Imposta `settings.headerTimeout` o `settings.chunkTimeout` del provider su un numero
di millisecondi per modificare un limite, oppure su `false` per disabilitarlo. `settings.timeout` limita inoltre l'intera
richiesta, dall'invio fino al completamento della risposta; non ha un valore predefinito. Queste impostazioni valgono per
l'intero provider, non per singolo modello o variante. Con un trasporto WebSocket, `chunkTimeout` limita invece
l'intervallo tra i frame e il valore predefinito è di trenta minuti.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "anthropic": {
      "settings": {
        "headerTimeout": 600000,
        "chunkTimeout": false,
      },
    },
  },
}
```

Una richiesta che supera uno dei due limiti fallisce con un errore di trasporto. OpenCode ritenta una richiesta scaduta
fino a tre volte prima di rinunciare.

## Codifica delle richieste

`settings.encoding` comprime il corpo delle richieste HTTP con `"zstd"` o `"gzip"`, oppure invia JSON non compresso con
`"none"`. Puoi impostarlo su un provider, un modello o una variante; prevale il valore più specifico. Abilita solo una
codifica che l'endpoint è in grado di decodificare: la maggior parte dei provider e dei gateway rifiuta i corpi
compressi. Per OpenAI il valore predefinito è `"zstd"` quando hai effettuato l'accesso con ChatGPT e non è configurato un
`baseURL` personalizzato; con le chiavi API viene inviato JSON non compresso. I messaggi WebSocket non sono interessati.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "settings": { "encoding": "none" },
    },
  },
}
```

## Pacchetti

Il campo `package` seleziona il runtime che comunica con un provider. Per le API che implementano il formato di richiesta
di OpenAI, usa il runtime compatibile.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "acme": {
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "https://llm.acme.example/v1",
      },
      "models": {
        "qwen3-coder": {},
      },
    },
  },
}
```

I pacchetti nativi disponibili includono:

- `@opencode/ai/providers/openai`
- `@opencode/ai/providers/openai/chat`
- `@opencode/ai/providers/openai/responses`
- `@opencode/ai/providers/openai-compatible`
- `@opencode/ai/providers/openai-compatible/responses`
- `@opencode/ai/providers/anthropic`
- `@opencode/ai/providers/anthropic-compatible`
- `@opencode/ai/providers/google`
- `@opencode/ai/providers/google-vertex`
- `@opencode/ai/providers/google-vertex/gemini`
- `@opencode/ai/providers/google-vertex/chat`
- `@opencode/ai/providers/google-vertex/responses`
- `@opencode/ai/providers/google-vertex/messages`
- `@opencode/ai/providers/azure`
- `@opencode/ai/providers/azure/chat`
- `@opencode/ai/providers/azure/responses`
- `@opencode/ai/providers/amazon-bedrock`
- `@opencode/ai/providers/amazon-bedrock/mantle`
- `@opencode/ai/providers/amazon-bedrock/mantle/chat`
- `@opencode/ai/providers/amazon-bedrock/mantle/responses`
- `@opencode/ai/providers/openrouter`
- `@opencode/ai/providers/xai`

Puoi anche usare un pacchetto npm come `@acme/opencode-provider` oppure un URL `file://` assoluto per un pacchetto locale.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "acme": {
      "package": "@acme/opencode-provider",
      "models": { "acme-coder": {} },
    },
  },
}
```

## Modelli

Aggiungi o sovrascrivi i modelli nella mappa `models` di un provider. La chiave della mappa è l'ID del modello usato da
OpenCode; `modelID` cambia l'ID inviato al provider.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "openai/coding",
  "providers": {
    "openai": {
      "models": {
        "coding": {
          "modelID": "gpt-5.2",
          "name": "GPT-5.2 Coding",
        },
      },
    },
  },
}
```

| Campo | Scopo |
| --- | --- |
| `modelID` | ID del modello o del deployment inviato al provider. |
| `name` | Nome visualizzato. |
| `family` | Famiglia del modello, usata per raggruppare modelli correlati. |
| `package` | Override del runtime per questo modello. |
| `settings` | Controlli di OpenCode a livello di modello e impostazioni JSON specifiche del pacchetto. |
| `headers` | Intestazioni aggiuntive della richiesta, con valori stringa. |
| `body` | Campi aggiuntivi del corpo JSON della richiesta. |
| `capabilities` | Supporto degli strumenti e tipi di contenuto accettati in input e in output. |
| `compatibility` | Override di compatibilità di richieste e risposte. |
| `variants` | Varianti con nome, ciascuna con i propri `settings`, `headers` e `body`. |
| `cost` | Prezzi di input, output e, facoltativamente, della cache per milione di token. |
| `limit` | Limiti di token per contesto, input e output. |
| `disabled` | Se `true`, rimuove il modello dalla selezione. |

Consulta [Modelli](/models) per selezione, valori predefiniti, capacità, limiti, costi e varianti.

## Azure

L'endpoint standard del catalogo di Azure richiede, oltre alla credenziale, il nome di una risorsa. Imposta una volta
`settings.resourceName`, poi collega una chiave API oppure usa la sessione Microsoft Entra ID della Azure CLI, come
descritto in [Account dei provider](/cli/providers).

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "azure": {
      "settings": {
        "resourceName": "my-models",
      },
    },
  },
}
```

Trovi il **Resource name** nel [portale di Azure](https://portal.azure.com/) o in
[Microsoft Foundry](https://ai.azure.com/). È anche la prima parte di endpoint come
`https://my-models.openai.azure.com/` e `https://my-models.services.ai.azure.com/`.

```bash
az cognitiveservices account list \
  --query "[].{name:name,resourceGroup:resourceGroup}" \
  --output table
```

Per usare Entra ID, installa la [Azure CLI](https://learn.microsoft.com/en-us/cli/azure/install-azure-cli), effettua
l'accesso e scegli **Microsoft Entra ID (Azure CLI)** quando colleghi Azure.

```bash
az login
```

Se il nome della risorsa non è già fornito dalla configurazione o dall'ambiente, inseriscilo durante il collegamento. Un
nome di risorsa salvato con una connessione ha la precedenza sulla configurazione; per cambiarlo, collegati di nuovo.

Le connessioni tramite Azure CLI usano l'account selezionato nella Azure CLI. Per una risorsa in un altro tenant o in
un'altra sottoscrizione, selezionali entrambi esplicitamente.

```bash
az login --tenant TENANT_ID
az account set --subscription NAME_OR_ID
```

In alternativa alla configurazione, `AZURE_RESOURCE_NAME` fornisce il nome della risorsa al server di OpenCode. Funziona
anche la variabile legacy `AZURE_COGNITIVE_SERVICES_RESOURCE_NAME`.

### Deployment

Azure rende disponibile un modello solo tramite un deployment, quindi OpenCode elenca i deployment della tua risorsa e
mostra quelli anziché l'intero catalogo di Azure. L'elenco viene caricato in background dopo l'avvio, dopo il
collegamento e dopo il cambio di account. Per rilevare un deployment aggiunto in seguito, riavvia OpenCode o collegati di
nuovo.

- Finché l'elenco non viene caricato per una connessione, o se il caricamento fallisce, resta disponibile l'intero catalogo.
- Se il ricaricamento per la stessa connessione fallisce, viene mantenuto l'ultimo inventario completo.
- Il cambio di account non mostra mai l'inventario dell'account precedente; il nuovo account parte dall'intero catalogo.
- I deployment ereditano limiti, costi e capacità dai rispettivi modelli del catalogo.

I nomi dei deployment sono i loro ID di modello, in minuscolo perché Azure non distingue maiuscole e minuscole nei nomi,
ad esempio `azure/gpt-production`. Un deployment che porta il nome del proprio modello, come `gpt-5-mini`, mantiene l'ID
del catalogo. Questi ID restano stabili quando altri deployment vengono aggiunti o rimossi.

OpenCode associa un deployment al catalogo in base al modello che distribuisce, oppure in base al nome quando Azure scrive
il modello in modo diverso, come `gpt-4` per GPT-4 Turbo. Un deployment che porta il nome di un altro modello, ad esempio
`gpt-5` che distribuisce `gpt-5-mini`, mostra nome, limiti e costi di quel modello.

Con la Azure CLI, OpenCode elenca i deployment tramite l'API di gestione di Azure, che richiede l'accesso in lettura alla
risorsa. Se questo non riesce, e sempre quando si usa una chiave API, OpenCode usa l'inventario legacy dei deployment
della risorsa. Il rilevamento legge tutte le pagine prima di pubblicare l'elenco. Con un `settings.baseURL` personalizzato
resta in uso il catalogo.

Configura esplicitamente un deployment quando il suo modello non è nel catalogo, come nel caso di un modello sottoposto a
fine-tuning, oppure per associare tu stesso un ID di modello a un deployment. OpenCode registra nei log un avviso con il
nome di questi deployment. I modelli configurati esplicitamente vengono sempre mantenuti.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "azure": {
      "models": {
        "gpt-5-mini": {
          "modelID": "gpt-production",
        },
      },
    },
  },
}
```

La tua identità deve avere uno di questi ruoli:

- **Cognitive Services OpenAI User** per i modelli Azure OpenAI.
- **Cognitive Services User** per gli altri modelli Foundry.

Se una richiesta usa un token del tenant sbagliato, accedi di nuovo con il tenant richiesto.

```bash
az login --tenant TENANT_ID
```

## Bedrock

Amazon Bedrock usa la catena di credenziali predefinita di AWS. Un profilo AWS con nome è la configurazione persistente
più semplice; OpenCode riconosce anche ambienti con chiavi di accesso, web identity e credenziali del container.

```bash
aws configure sso --profile work
aws sso login --profile work
```

Seleziona il profilo e la regione nelle impostazioni del provider. Il provider si attiva con un `profile` configurato,
`AWS_PROFILE`, `AWS_ACCESS_KEY_ID`, un file di token web identity o un URI di credenziali del container; la sola regione
non basta.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "amazon-bedrock": {
      "settings": {
        "profile": "work",
        "region": "us-west-2",
      },
    },
  },
}
```

Senza una regione esplicita, OpenCode usa `AWS_REGION`, poi `AWS_DEFAULT_REGION` e infine `us-east-1`. Per un endpoint
privato o VPC, imposta `baseURL` mantenendo lo stesso profilo e la stessa regione.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "amazon-bedrock": {
      "settings": {
        "profile": "work",
        "region": "us-west-2",
        "baseURL": "https://bedrock-runtime.vpce.example.com",
      },
    },
  },
}
```

Le chiavi API di Bedrock usano `AWS_BEARER_TOKEN_BEDROCK`. Le altre variabili AWS alimentano SigV4 e non vengono salvate
come account con chiave API di OpenCode.

## Vertex

Google Vertex usa le Application Default Credentials (ADC) e richiede un progetto prima che i suoi modelli diventino
disponibili. Crea le ADC locali, poi imposta il progetto e la località nelle impostazioni del provider.

```bash
gcloud auth application-default login
```

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "google-vertex": {
      "settings": {
        "project": "my-project",
        "location": "us-central1",
      },
    },
  },
}
```

OpenCode ricava il progetto anche da `GOOGLE_VERTEX_PROJECT`, `GOOGLE_CLOUD_PROJECT`, `GCP_PROJECT` o `GCLOUD_PROJECT`,
in quest'ordine. Ricava la località da `GOOGLE_VERTEX_LOCATION`, `GOOGLE_CLOUD_LOCATION` o `VERTEX_LOCATION`; il valore
predefinito è `us-central1`.

```bash
GOOGLE_CLOUD_PROJECT=my-project GOOGLE_VERTEX_LOCATION=europe-west4 opencode --standalone
```

Gli account di servizio funzionano tramite lo stesso meccanismo ADC. Fai puntare `GOOGLE_APPLICATION_CREDENTIALS` al file
JSON dell'account di servizio e fornisci comunque un progetto tramite le impostazioni o una delle variabili di progetto
indicate sopra.

```bash
GOOGLE_APPLICATION_CREDENTIALS=/secure/vertex.json \
GOOGLE_CLOUD_PROJECT=my-project \
opencode --standalone
```

Usa l'unico ID di provider `google-vertex` per i modelli Gemini, Anthropic e compatibili con OpenAI del catalogo Vertex.
Il vecchio ID di provider `google-vertex-anthropic` non è disponibile in V2.

## Copilot

GitHub Copilot supporta OAuth tramite dispositivo anziché l'inserimento manuale di una chiave API. Collega **GitHub
Copilot**, scegli GitHub.com o GitHub Enterprise, completa il flusso di autorizzazione del dispositivo e apri `/models`.

```text
/connect
# Select GitHub Copilot, then Login with GitHub Copilot.
/models
```

Per GitHub Enterprise, inserisci l'URL o il dominio dell'istanza quando richiesto. OpenCode usa l'endpoint dell'API di
Copilot restituito da GitHub, se disponibile; altrimenti ricava l'endpoint dal dominio enterprise.

```text
company.ghe.com
```

L'account collegato deve avere accesso a Copilot Chat. Se GitHub segnala che non hai diritto al servizio, iscriviti a
Copilot Free o chiedi all'organizzazione di assegnarti una licenza Copilot, poi collegati di nuovo. OpenCode recupera
l'elenco aggiornato dei modelli dell'account dopo l'accesso e ogni volta che cambia l'account Copilot attivo.

## Ollama

Avvia Ollama e scarica un modello. OpenCode interroga `http://127.0.0.1:11434`, individua i modelli di completamento e li
aggiunge a `/models` senza bisogno di collegare un account.

```bash
ollama serve
ollama pull qwen3:8b
```

Per usare un server Ollama remoto o dietro un proxy, imposta `settings.baseURL`. Includi `/v1`; OpenCode ne ricava i
percorsi di rilevamento nativi `/api/tags` e `/api/show`. `apiKey` è facoltativo e viene inviato come bearer token sia
nelle richieste di rilevamento sia in quelle al modello.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "ollama": {
      "settings": {
        "baseURL": "https://ollama.example.com/v1",
        "apiKey": "{env:OLLAMA_API_KEY}",
      },
    },
  },
}
```

Il rilevamento si aggiorna periodicamente e, durante un'interruzione temporanea, mantiene l'ultimo inventario ottenuto con
successo. I modelli solo di embedding non compaiono, perché OpenCode aggiunge solo i modelli i cui metadati Ollama
includono la capacità `completion`.

## Runtime

Anche LM Studio e vLLM dispongono di un rilevamento locale integrato. I loro endpoint predefiniti sono
`http://127.0.0.1:1234/v1` e `http://127.0.0.1:8000/v1`.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "lmstudio": {
      "settings": { "baseURL": "http://gpu-host:1234/v1" },
    },
    "vllm": {
      "settings": { "baseURL": "http://gpu-host:8000/v1" },
    },
  },
}
```

LM Studio rileva i modelli linguistici da `/api/v1/models`. vLLM controlla `/health` prima di leggere `/v1/models`; il suo
rilevamento non può dedurre il supporto degli strumenti, quindi i modelli vLLM rilevati partono con gli strumenti
disabilitati. Per un altro runtime compatibile con OpenAI, segui la procedura del [provider personalizzato](#custom) ed
elenca esplicitamente i suoi modelli.

## Gateway

OpenRouter usa il proprio runtime e catalogo nativi. Fornisci `OPENROUTER_API_KEY` al server di OpenCode o collega un
account OpenRouter, poi indica i modelli con l'ID completo del modello OpenRouter dopo il prefisso del provider.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "openrouter/anthropic/claude-sonnet-4",
}
```

Mantieni il pacchetto nativo di OpenRouter quando ne sovrascrivi l'endpoint o instradi il traffico attraverso un gateway
compatibile con OpenRouter. In questo modo si conserva il comportamento di OpenRouter per le richieste e il ragionamento.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openrouter": {
      "settings": {
        "baseURL": "https://openrouter-gateway.example.com/api/v1",
      },
      "headers": {
        "X-Gateway-Tenant": "engineering",
      },
    },
  },
}
```

Per un gateway che espone un'API compatibile con OpenAI ma ha un proprio inventario di modelli, definisci invece un
provider personalizzato. La chiave di configurazione diventa il prefisso del provider e ogni chiave di `models` diventa un
ID di modello selezionabile.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "company/coder",
  "providers": {
    "company": {
      "env": ["COMPANY_GATEWAY_KEY"],
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "https://gateway.example.com/v1",
      },
      "models": {
        "coder": { "modelID": "upstream/coder-v2" },
      },
    },
  },
}
```

## Errori

Gli errori dei provider e dei modelli di solito indicano la fase non riuscita. Prima di cambiare pacchetto, controlla
l'ambiente del processo del server e l'ID esatto del modello.

| Errore o sintomo | Verifica |
| --- | --- |
| `No model is available for session ...` | Al momento non è selezionabile alcun modello abilitato. Completa la configurazione specifica del provider, poi scegli un modello in `/models`. |
| `Model unavailable: provider/model` | Il provider non è attivo, l'ID del modello è assente o disabilitato, oppure il rilevamento dinamico non lo restituisce più. Per gli alias personalizzati, controlla la chiave della mappa `models` anziché `modelID`. |
| `Cannot initialize provider/model: NAME is required to resolve the provider endpoint` | In `baseURL` è rimasto un segnaposto `${NAME}`. Imposta quella variabile sul server di OpenCode o sostituisci il template con un endpoint completo. |
| `Azure resource name is missing` | Imposta `providers.azure.settings.resourceName`, `AZURE_RESOURCE_NAME` o un `settings.baseURL` completo. |
| Vertex non compare | Imposta un progetto risolvibile nelle impostazioni del provider o in una delle variabili di progetto supportate. Le sole ADC non attivano il provider. |
| Bedrock non compare | Fornisci un profilo o un altro input supportato dalla catena di credenziali AWS. `AWS_REGION` da sola seleziona solo una regione. |
| Ollama non ha modelli | Verifica che il server esponga `/api/tags` e `/api/show` nel percorso ricavato da `baseURL` e che `/api/show` riporti la capacità `completion`. |
| Copilot non ha modelli | Verifica che l'account OAuth attivo abbia accesso a Copilot Chat. Una sincronizzazione dei modelli non riuscita viene registrata come `failed to sync GitHub Copilot models`. |

V2 rifiuta gli ID di provider dismessi che hanno un sostituto diretto. Usa `azure/<model>` al posto di
`azure-cognitive-services/<model>` e `google-vertex/<model>` al posto di `google-vertex-anthropic/<model>`.

## WebSocket

I modelli OpenAI, xAI e Azure Responses supportati possono mantenere aperta una connessione WebSocket per sessione. Gli
step consecutivi riutilizzano il prefisso invariato della richiesta e inviano solo il contenuto aggiunto dopo la risposta
precedente, riducendo i dati caricati nelle sessioni lunghe.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "settings": { "transport": "http" },
    },
  },
}
```

Il comportamento WebSocket segue queste regole:

- I provider integrati abilitano le route supportate secondo i propri criteri.
- `settings.transport: "websocket"` del provider lo abilita; `"http"` lo disabilita.
- `"websocket"` su una route senza canale WebSocket registra un avviso nei log e ripiega su HTTP.
- La compattazione del provider OpenAI usa la stessa connessione.
- xAI riprende solo da risposte memorizzate. Con il valore predefinito `store: false`, ogni step viene inviato per intero
  sulla connessione riutilizzata.
- Un socket chiuso si riconnette allo step successivo. Se la connessione non può essere aperta, la sessione prosegue via
  HTTP.
- I plugin dei provider con hook `http.request` o `http.response` restano su HTTP, così ogni richiesta resta osservabile.
