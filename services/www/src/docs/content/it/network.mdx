---
title: Rete
description: Configura proxy e autorità di certificazione personalizzate.
---

Imposta le variabili standard per il proxy ed escludi gli indirizzi di loopback. La CLI di OpenCode comunica con il proprio
servizio in background tramite connessioni HTTP locali, quindi se nell'ambiente della CLI è configurato un proxy l'esclusione
del loopback è obbligatoria.

```bash
export HTTP_PROXY=http://proxy.example.com:8080
export HTTPS_PROXY=http://proxy.example.com:8080
export NO_PROXY=localhost,127.0.0.1,::1

opencode
```

`HTTP_PROXY` gestisce le destinazioni HTTP e `HTTPS_PROXY` quelle HTTPS. In entrambe le variabili l'URL del proxy può usare
`http://`. `NO_PROXY` è un elenco, separato da virgole, di host e indirizzi a cui collegarsi direttamente.

## Servizio

Le variabili esportate nella shell valgono per il servizio in background solo se il servizio viene avviato da quella shell.
Rendi persistenti le variabili nella configurazione del servizio gestito, così ogni avvio successivo userà le stesse
impostazioni di rete.

```bash
opencode service set env HTTP_PROXY http://proxy.example.com:8080
opencode service set env HTTPS_PROXY http://proxy.example.com:8080
opencode service set env NO_PROXY localhost,127.0.0.1,::1
opencode service start
```

La modifica di una variabile d'ambiente gestita arresta il servizio in esecuzione; `service start` lo riavvia con il nuovo
ambiente. Se la shell della CLI imposta un proxy, mantieni `NO_PROXY` anche lì: le variabili del servizio gestito si
applicano al processo del server, non a quello della CLI.

Per rimuovere una variabile persistente, usa `service unset env`:

```bash
opencode service unset env HTTPS_PROXY
```

## Autenticazione

Se il proxy accetta credenziali nell'URL, includi nome utente e password in ogni URL di proxy che richiede
l'autenticazione. Applica la codifica percentuale (percent-encoding) a caratteri come `@`, `:` e `/` presenti nel nome
utente o nella password.

```bash
export HTTPS_PROXY='http://user:p%40ssword@proxy.example.com:8080'
```

Per il servizio in background, salva l'URL completo. Il valore viene memorizzato nella configurazione privata del servizio
e compare nell'output di `opencode service get env`, quindi non condividere quell'output.

```bash
opencode service set env HTTPS_PROXY 'http://user:p%40ssword@proxy.example.com:8080'
```

## Certificati

Se il proxy o la destinazione usano un certificato firmato da un'autorità di certificazione privata, imposta
`NODE_EXTRA_CA_CERTS` sul percorso di un file PEM. All'avvio del processo, le autorità aggiuntive vengono aggiunte
all'archivio dei certificati attendibili del runtime.

```bash
export NODE_EXTRA_CA_CERTS=/etc/company/ca.pem
opencode --standalone
```

Salva il percorso del file per il servizio in background, quindi riavvialo:

```bash
opencode service set env NODE_EXTRA_CA_CERTS /etc/company/ca.pem
opencode service start
```

## Processi in primo piano

`--standalone` e `serve` usano l'ambiente del proprio processo. `opencode service set env` non configura questi processi.

```bash
HTTP_PROXY=http://proxy.example.com:8080 \
HTTPS_PROXY=http://proxy.example.com:8080 \
NO_PROXY=localhost,127.0.0.1,::1 \
opencode --standalone
```

Lo stesso schema vale per un server in primo piano:

```bash
HTTPS_PROXY=http://proxy.example.com:8080 \
NO_PROXY=localhost,127.0.0.1,::1 \
opencode serve
```

## Verifica

Dopo aver applicato le impostazioni, controlla che la CLI riesca a raggiungere il servizio in background:

```bash
opencode api get /api/info
```

Una risposta positiva al controllo di stato conferma la connessione locale tra client e servizio. Per verificare il proxy
in uscita e la configurazione dei certificati del servizio, invia una normale richiesta a un provider.
