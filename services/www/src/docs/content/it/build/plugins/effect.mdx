---
title: "Effect"
---

`@opencode/plugin/effect` è la versione nativa per Effect dell'API dei plugin di OpenCode. Le operazioni del contesto
restituiscono Effect o Stream, le callback restituiscono Effect e il ciclo di vita del plugin è rappresentato da `Scope`.

Quando carica i plugin e le relative dipendenze in `node_modules`, OpenCode fornisce a runtime `effect` (compresi i
sottopercorsi `effect/*` esportati) e `@opencode/plugin`. Installali come dipendenze peer/dev per il controllo dei tipi e i
test in locale, invece di includerli nel bundle del plugin.

```sh
bun add --peer @opencode/plugin effect
```

Esporta un plugin Effect da `.opencode/plugins/` per caricarlo automaticamente.

```ts title=".opencode/plugins/concise/index.ts"
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "example",
  effect: (ctx) =>
    Effect.gen(function* () {
      const storage = ctx.storage
      yield* storage.set("loaded", true)
    }),
})
```

I pacchetti pubblicati e le directory di plugin esterne a `.opencode/plugins/` usano la stessa configurazione `plugins`
degli altri plugin del server.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": [
    "opencode-acme-effect-plugin",
    "opencode-acme-effect-plugin@1.2.0",
    "@acme/opencode-effect-plugin",
    "./plugins/local-effect",
    {
      "package": "@acme/opencode-effect-plugin",
      "options": { "agent": "reviewer", "strict": true },
    },
  ],
}
```

Consulta [Configurare i plugin](/plugins) per l'abilitazione, la risoluzione dei pacchetti e la precedenza della
configurazione.

```ts title="plugins/local-effect/index.ts"
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "local-effect",
  effect: (ctx) =>
    Effect.gen(function* () {
      yield* Effect.logInfo("Effect plugin loaded", { version: ctx.app.version })
    }),
})
```

## Ciclo di vita

L'`effect` viene eseguito al caricamento del plugin. Il suo scope si chiude quando il plugin viene ricaricato o scaricato,
quindi registrazioni, fiber con scope e finalizzatori vengono rilasciati insieme.

```ts
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "lifecycle",
  effect: (ctx) =>
    Effect.gen(function* () {
      yield* Effect.logInfo("loaded", { version: ctx.app.version })
      yield* Effect.addFinalizer(() => Effect.logInfo("unloaded"))
    }),
})
```

Usa fiber con scope per il lavoro in background. Lo scope del plugin interrompe il fiber durante la pulizia.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const storage = ctx.storage
    yield* Effect.repeat(
      storage.set("heartbeat", { time: Date.now() }),
      { schedule: Schedule.spaced("1 minute") },
    ).pipe(Effect.forkScoped)
  }),
```

### Contesto

Il contesto espone il client Effect per il server OpenCode connesso, più trasformazioni, hook, archiviazione,
ricaricamenti e opzioni riservati ai plugin. Non espone i servizi Core privati di OpenCode.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const plugins = ctx.plugin
    const active = yield* plugins.list().pipe(Effect.orDie)
    yield* Effect.logInfo("active plugins", { count: active.data.length })
  }),
```

La definizione del plugin e il contesto completo sono dichiarati come segue.

```ts

interface Plugin<R = Scope.Scope> {
  readonly id: string

}
```

### Opzioni

Passa le opzioni con la forma a oggetto in `opencode.json(c)`.

```jsonc title="opencode.jsonc"
{
  "plugins": [
    {
      "package": "./plugins/company-effect",
      "options": { "strict": true },
    },
  ],
}
```

Leggi le opzioni da `ctx.options`. Restringi il tipo dei valori sconosciuti prima di usarli.

```ts title="plugins/company-effect/index.ts"
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "company",
  effect: (ctx) =>
    Effect.gen(function* () {
      const strict = ctx.options.strict === true
      yield* Effect.logInfo("company plugin configured", { strict })
    }),
})
```

## Trasformazioni

Le trasformazioni modificano lo stato in modo sincrono tramite un editor. All'interno di ciascun dominio, OpenCode applica
le trasformazioni nell'ordine di registrazione. Prima le sorgenti forniscono i provider e le definizioni immutabili dei
modelli; poi le trasformazioni dei modelli modificano i candidati dei provider attivi. Eseguire `yield*` sulla
registrazione la mantiene nello scope del plugin.

```ts title="plugins/models-effect/index.ts"
import { Model, Plugin, Provider } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "company.models",
  effect: (ctx) =>
    Effect.gen(function* () {
      const providerID = Provider.ID.make("acme")
      const models = [{ ...Model.Info.default(providerID, Model.ID.make("reasoner")), name: "Acme Reasoner" }]
      yield* ctx.provider.transform((editor) => {
        editor.add({
          info: {
            ...Provider.Info.empty(providerID),
            name: "Acme",
            activation: "enabled",
            package: "@opencode/ai/providers/openai-compatible",
            settings: { baseURL: "http://127.0.0.1:8000/v1" },
          },
          models,
        })
      })
    }),
})
```

Una trasformazione dei modelli può applicare una policy all'intera raccolta di candidati dei provider attivi.

```ts title="plugins/model-budget-effect/index.ts"
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.model.transform((editor) => {
      editor
        .list()
        .filter((model) => model.cost.some((tier) => tier.output > 20))
        .forEach((model) => {
          editor.remove(model.providerID, model.id)
        })
    })
  }),
```

Chiama `reload` quando cambia lo stato esterno usato da una trasformazione. Qui `loadFromSource()` restituisce voci
`{ info: Provider.Info, models: readonly Model.Info[] }`; il ricaricamento dei provider invalida anche l'intero risultato
dei modelli.

```ts title="plugins/models-effect/index.ts"
effect: (ctx) =>
  Effect.gen(function* () {
    const provider = ctx.provider
    const source = { providers: yield* loadFromSource() }

    yield* provider.transform((editor) => {
      source.providers.forEach((provider) => editor.add(provider))
    })

    yield* Effect.repeat(
      Effect.gen(function* () {
        source.providers = yield* loadFromSource()
        yield* provider.reload()
      }),
      { schedule: Schedule.spaced("1 minute") },
    ).pipe(Effect.forkScoped)
  }),
```

## API

### Agente

Leggi tutti gli agenti o recuperane uno per ID. Le risposte del client includono la posizione risolta e i dati dello
schema.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const agent = ctx.agent
    const agents = yield* agent.list().pipe(Effect.orDie)
    const build = yield* agent.get({ agentID: Agent.ID.make("build") }).pipe(Effect.orDie)
    yield* Effect.logInfo("agents", { count: agents.data.length, build: build.data.name })
  }),
```

Trasforma o ricarica gli agenti.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const agent = ctx.agent
    yield* agent.transform((editor) => {
      editor.default("build")
      editor.update("build", (item) => (item.description = "Builds features and fixes bugs"))
      editor.remove("legacy")
    })
    yield* agent.reload()
  }),
```

Schema: [`Agent.Info`](/api#schema-Agent.Info).

```ts
interface AgentEditor {
  list(): readonly Types.DeepMutable<Agent.Info>[]
  get(id: string): Types.DeepMutable<Agent.Info> | undefined
  default(id: string | undefined): void
  update(id: string, update: (agent: Types.DeepMutable<Agent.Info>) => void): void
  remove(id: string): void
}

interface AgentDomain extends AgentApi<unknown> {
  readonly transform: Transform<AgentEditor>
  readonly reload: () => Effect.Effect<void>
}
```

### Provider

Leggi i provider disponibili o esamina i metadati di un provider tramite il suo ID.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const provider = ctx.provider
    const providers = yield* provider.list().pipe(Effect.orDie)
    const anthropic = yield* provider.get({ providerID: Provider.ID.make("anthropic") }).pipe(Effect.orDie)
    yield* Effect.logInfo("providers", {
      providers: providers.data.length,
      anthropic: anthropic.data.name,
    })
  }),
```

Le trasformazioni dei provider modificano le impostazioni dei provider e le definizioni delle sorgenti. Le letture
dall'editor includono i provider inattivi ed espongono definizioni immutabili; `models.update` modifica una copia di
proprietà del modello sorgente.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.provider.transform((editor) => {
      editor.update("anthropic", (provider) => {
        provider.headers = { ...provider.headers, "x-company": "engineering" }
      })
      editor.models.update("anthropic", "claude-sonnet-4-5", (model) => (model.name = "Team Sonnet"))
      editor.models.remove("anthropic", "legacy-model")
      editor.remove("legacy-provider")
    })
  }),
```

Sostituisci l'inventario di una sorgente con `models.set`, quindi ricarica quando cambiano le definizioni acquisite.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const provider = ctx.provider
    const source = { models: yield* loadModels() }
    yield* provider.transform((editor) => editor.models.set("acme", source.models))
    source.models = yield* loadModels()
    yield* provider.reload()
  }),
```

Per il rilevamento specifico di un account, passa come `sourceConnection` la connessione usata per caricare l'inventario.
Quando è selezionata un'altra connessione, OpenCode esclude quel provider finché il plugin non pubblica l'inventario
aggiornato.

```ts
const connection = yield * ctx.integration.connection.active("acme")
if (!connection) return
const inventory = yield * loadInventory(connection)
yield *
  ctx.provider.transform((editor) => {
    editor.add({ info: inventory.provider, models: inventory.models, sourceConnection: connection })
  })
```

Schema: [`Provider.Info`](/api#schema-Provider.Info), [`Model.Info`](/api#schema-Model.Info).

```ts
interface ProviderRecord {
  readonly provider: Provider.Info
  readonly models: ReadonlyMap<string, Model.Info>
  readonly sourceConnection?: ConnectionInfo
}

interface ProviderEditor {
  list(): readonly ProviderRecord[]
  get(providerID: string): ProviderRecord | undefined
  add(input: { info: Provider.Info; models: readonly Model.Info[]; sourceConnection?: ConnectionInfo }): void
  update(providerID: string, update: (provider: Types.DeepMutable<Provider.Info>) => void): void
  remove(providerID: string): void
  readonly models: {
    set(providerID: string, models: readonly Model.Info[]): void
    update(providerID: string, modelID: string, update: (model: Types.DeepMutable<Model.Info>) => void): void
    remove(providerID: string, modelID: string): void
  }
}

interface ProviderDomain extends ProviderApi<unknown> {
  readonly transform: Transform<ProviderEditor>
  readonly reload: () => Effect.Effect<void>
}
```

### Modelli

Leggi i modelli disponibili e la selezione predefinita.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const model = ctx.model
    const models = yield* model.list().pipe(Effect.orDie)
    const selected = yield* model.default().pipe(Effect.orDie)
    yield* Effect.logInfo("models", { count: models.data.length, selected: selected.data?.name })
  }),
```

Le trasformazioni dei modelli modificano l'intera raccolta di candidati dei provider attivi. I candidati disabilitati
restano modificabili fino al termine di tutte le trasformazioni; `update` può aggiungere un modello solo sotto un provider
disponibile.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.model.transform((editor) => {
      editor.list("anthropic").forEach((model) => {
        editor.update(model.providerID, model.id, (draft) => {
          draft.enabled = draft.capabilities.tools
        })
      })
      editor.default.set("anthropic", "claude-sonnet-4-5")
      editor.remove("anthropic", "legacy-model")
    })
  }),
```

Le callback modificano gli override grezzi dei modelli. I valori predefiniti dei provider vengono uniti una sola volta,
quando OpenCode conferma il risultato; le letture senza modifiche riutilizzano quel risultato. `editor.provider` legge le
definizioni immutabili delle sorgenti, compresi i template inattivi, anziché l'output delle trasformazioni dei modelli.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const model = ctx.model
    yield* model.transform((editor) => {
      const source = editor.provider.get("anthropic")?.models.get("claude-sonnet-4-5")
      if (!source) return
      editor.update("anthropic", source.id, (draft) => {
        draft.limit.context = Math.min(draft.limit.context, source.limit.context)
      })
    })
    yield* model.reload()
  }),
```

Schema: [`Model.Info`](/api#schema-Model.Info).

```ts
interface ModelEditor {
  list(providerID?: string): readonly Types.DeepMutable<Model.Info>[]
  get(providerID: string, modelID: string): Types.DeepMutable<Model.Info> | undefined
  update(providerID: string, modelID: string, update: (model: Types.DeepMutable<Model.Info>) => void): void
  remove(providerID: string, modelID: string): void
  readonly default: {
    get(): { providerID: string; modelID: string } | undefined
    set(providerID: string, modelID: string): void
  }
  readonly provider: {
    list(): readonly ProviderRecord[]
    get(providerID: string): ProviderRecord | undefined
  }
}

interface ModelDomain extends ModelApi<unknown> {
  readonly transform: Transform<ModelEditor>
  readonly reload: () => Effect.Effect<void>
}
```

### Comandi

Leggi i comandi disponibili nella posizione corrente.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const command = ctx.command
    const commands = yield* command.list().pipe(Effect.orDie)
    yield* Effect.logInfo("commands", { names: commands.data.map((item) => item.name) })
  }),
```

Al momento la trasformazione dei comandi consente solo aggiunte. Un executor riceve la sessione, gli allegati del prompt e
la modalità di consegna.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const command = ctx.command
    const session = ctx.session
    yield* command.transform((editor) => {
      editor.add({
        name: "security-review",
        description: "Review changes for security issues",
        execute: (input) =>
          session.prompt({
            ...input.prompt,
            sessionID: input.sessionID,
            text: `Review these changes for security issues.\n\n${input.prompt.text}`,
            delivery: input.delivery,
          }).pipe(Effect.asVoid),
      })
    })
    yield* command.reload()
  }),
```

Schema: [`Command.Info`](/api#schema-Command.Info),
[`Session.Inbox.Delivery`](/api#schema-Session.Inbox.Delivery).

### Integrazioni

Leggi le integrazioni e risolvi la credenziale attiva, se presente.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const integration = ctx.integration
    const integrations = yield* integration.list().pipe(Effect.orDie)
    const github = yield* integration.get({ integrationID: Integration.ID.make("github") }).pipe(Effect.orDie)
    const connection = yield* integration.connection.active("github")
    const credential = connection ? yield* integration.connection.resolve(connection).pipe(Effect.orDie) : undefined
    yield* Effect.logInfo("integration", {
      count: integrations.data.length,
      github: github.data.name,
      credential: credential?.type,
    })
  }),
```

Connettiti con una chiave o gestisci un tentativo OAuth tramite l'API connessa.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const integration = ctx.integration
    const token = yield* Config.Redacted("GITHUB_TOKEN").pipe(Effect.orDie)
    yield* integration.connect
      .key({ integrationID: Integration.ID.make("github"), key: Redacted.value(token) })
      .pipe(Effect.orDie)

    const attempt = yield* integration.oauth
      .connect({
        integrationID: Integration.ID.make("acme"),
        methodID: Integration.MethodID.make("oauth"),
      })
      .pipe(Effect.orDie)
    const status = yield* integration.oauth
      .status({
        integrationID: Integration.ID.make("acme"),
        attemptID: attempt.data.attemptID,
      })
      .pipe(Effect.orDie)
    yield* Effect.logInfo("OAuth status", { status: status.data })
  }),
```

Trasforma le integrazioni e i metodi di autenticazione. Le callback dei metodi OAuth sono Effect e possono acquisire
risorse con scope.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const integration = ctx.integration
    yield* integration.transform((editor) => {
      editor.update("acme", (item) => (item.name = "Acme"))
      editor.method.update({
        integrationID: "acme",
        method: { id: "device", type: "oauth", label: "Sign in with Acme" },
        authorize: () =>
          Effect.succeed({
            mode: "code",
            url: "https://acme.example/device",
            instructions: "Enter the displayed code",
            callback: (code) => exchangeCode(code),
          }),
      })
    })
    yield* integration.reload()
  }),
```

Schema: [`Integration.Info`](/api#schema-Integration.Info), [`Integration.Method`](/api#schema-Integration.Method),
[`Connection.Info`](/api#schema-Connection.Info), [`Form.Answer`](/api#schema-Form.Answer).

```ts

  readonly url: string

)

  readonly integrationID: string
  readonly method: IntegrationOAuthMethod

  readonly transform: Transform<IntegrationEditor>

```

### MCP

Elenca i server MCP e il loro stato di connessione attuale.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const mcp = ctx.mcp
    const servers = yield* mcp.list().pipe(Effect.orDie)
    yield* Effect.logInfo("MCP servers", { count: servers.data.length })
  }),
```

I plugin gestiscono i server MCP solo tramite trasformazioni. Usa `editor.set` per aggiungere o sostituire un server,
`editor.update` per modificarne la configurazione ed `editor.remove` per rimuoverlo. Esamina la configurazione con
`editor.list` ed `editor.get`.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const mcp = ctx.mcp
    yield* mcp.transform((editor) => {
      const servers = editor.list()
      const docs = editor.get("docs")
      editor.set("docs", { type: "remote", url: "https://mcp.example.com" })
      editor.update("docs", (server) => (server.disabled = false))
      editor.remove("legacy")
    })
  }),
```

In una trasformazione, imposta `disabled: true` per disabilitare un server e disconnetterlo, oppure `disabled: false` per
abilitarlo e consentire a OpenCode di connettersi. OpenCode riconcilia il ciclo di vita dei server in base alla
configurazione trasformata.

Chiama `reload()` quando cambia lo stato esterno usato da una trasformazione, per riapplicare le trasformazioni e
riconciliare i server.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const mcp = ctx.mcp
    yield* mcp.reload()
  }),
```

Schema: [`Mcp.Server`](/api#schema-Mcp.Server), [`Mcp.LocalConfigEncoded`](/api#schema-Mcp.LocalConfigEncoded),
[`Mcp.RemoteConfigEncoded`](/api#schema-Mcp.RemoteConfigEncoded).

```ts

  update(name: string, update: (config: Types.DeepMutable<Mcp.ServerConfig>) => void): void
  remove(name: string): void
}

```

### Plugin

Elenca i plugin attivi, non riusciti e risolti nella posizione corrente.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const plugin = ctx.plugin
    const plugins = yield* plugin.list().pipe(Effect.orDie)
    yield* Effect.forEach(plugins.data, (item) => Effect.logInfo("plugin", item), { discard: true })
  }),
```

Filtra i valori dello schema in una pipeline Effect quando ti interessano solo i plugin attivi.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const plugin = ctx.plugin
    const active = yield* plugin.list().pipe(
      Effect.orDie,
      Effect.map((result) => result.data.filter((item) => item.status === "active")),
    )
    yield* Effect.logInfo("active plugin count", { count: active.length })
  }),
```

Schema: [`Plugin.Info`](/api#schema-Plugin.Info), [`Plugin.Source`](/api#schema-Plugin.Source).

```ts
interface PluginApi<E = never> {
  readonly list: PluginListOperation<E>
}

interface Context {
  readonly plugin: PluginApi<unknown>
}
```

### Riferimenti

Leggi i riferimenti disponibili nella posizione corrente.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const reference = ctx.reference
    const references = yield* reference.list().pipe(Effect.orDie)
    yield* Effect.logInfo("references", { count: references.data.length })
  }),
```

Aggiungi o rimuovi riferimenti locali e Git, quindi ricarica quando cambia lo stato esterno. `get(name)` restituisce la
sorgente configurata attuale, oppure `undefined` se il nome non esiste.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const reference = ctx.reference
    yield* reference.transform((editor) => {
      editor.add("handbook", { type: "local", path: "/workspace/docs/handbook" })
      editor.add("standards", { type: "git", repository: "https://github.com/acme/standards", branch: "main" })
      const handbook = editor.get("handbook")
      editor.remove("legacy")
    })
    yield* reference.reload()
  }),
```

Schema: [`Reference.Info`](/api#schema-Reference.Info), [`Reference.LocalSource`](/api#schema-Reference.LocalSource),
[`Reference.GitSource`](/api#schema-Reference.GitSource).

### Strumenti

Registra strumenti tipizzati con `Schema` di Effect. L'executor riceve l'input decodificato e restituisce un Effect che
contiene output tipizzato, contenuto da visualizzare o metadati.

L'editor supporta `add`, `update` e `remove`. La callback della trasformazione è sincrona: non deve restituire un Effect né
una Promise. Carica i dati esterni prima della registrazione o del ricaricamento. OpenCode riesegue le trasformazioni
attive nell'ordine di registrazione su un editor nuovo; a parità di nome effettivo dello strumento, una registrazione
valida successiva sovrascrive quella precedente.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const tool = ctx.tool
    yield* tool.transform((editor) => {
      editor.namespace({
        name: "acme",
        description: "Customer account tools",
      })
      editor.add({
        name: "greeting",
        description: "Create a greeting",
        input: Schema.Struct({ name: Schema.String }),
        output: Schema.Struct({ greeting: Schema.String }),
        options: { namespace: "acme", codemode: true },
        execute: ({ name }, context) =>
          Effect.gen(function* () {
            yield* context.progress({ status: "greeting" })
            return { output: { greeting: `Hello ${name}!` } }
          }),
      })
    })
  }),
```

Chiama `yield* ctx.tool.reload()` dopo aver modificato i dati sorgente acquisiti dalla callback. Il ricaricamento
riesegue le trasformazioni attive senza cambiarne l'ordine; non riesegue l'effect del plugin.

Gli strumenti hanno un `id` che contiene il loro nome effettivo e `get()` restituisce `undefined` quando quell'ID non è
presente. Usa `update` e `remove` con il nome effettivo dello strumento, namespace compreso (`acme_greeting` nell'esempio
sopra). I punti nei namespace e i caratteri non supportati nei nomi degli strumenti diventano `_`. I nomi inesistenti
vengono ignorati; per creare uno strumento serve `add` con una definizione completa. Gli aggiornamenti mantengono nome e
namespace. Per sostituire schemi o opzioni assegnane di nuovi, invece di modificare i valori annidati. Gli aggiornamenti
non validi vengono registrati nel log e lasciano intatta la definizione precedente.

```ts
yield *
  ctx.tool.transform((editor) => {
    editor.update("acme_greeting", (tool) => {
      tool.description = "Greet the user by name"
    })
    editor.remove("acme_obsolete")
  })
```

Aggiornamenti e rimozioni vengono rieseguiti in ordine insieme alle aggiunte, anche dopo gli aggiornamenti del catalogo
MCP.

`transform` restituisce una registrazione con scope. Esegui `yield* registration.dispose` per rimuoverne la
trasformazione e ricostruire lo stato dalle trasformazioni rimanenti, facendo riemergere l'eventuale definizione
precedente che sovrascriveva. Il rilascio è idempotente e anche la chiusura dello scope del plugin rilascia le sue
registrazioni.

Ogni richiesta al modello acquisisce uno snapshot degli strumenti. Ricaricamento e rilascio influiscono sugli snapshot
futuri, non sulle definizioni o sugli executor già acquisiti da una richiesta esistente. Gli executor che catturano in una
closure dati modificabili del plugin continuano a vederne i cambiamenti; se un valore deve restare legato a quella
definizione, acquisiscilo all'interno della trasformazione.

Schema: [`Tool.Content`](/api#schema-Tool.Content), [`Tool.TextContent`](/api#schema-Tool.TextContent),
[`Tool.FileContent`](/api#schema-Tool.FileContent).

## Hook

Gli hook intercettano le operazioni in corso. Più plugin possono registrare lo stesso hook; OpenCode li esegue nell'ordine
dei plugin, così gli hook successivi vedono le modifiche di quelli precedenti. Le registrazioni restano attive per tutta la
durata dello scope del plugin.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook("context", () => Effect.void)
  }),
```

### Sessioni

Modifica le istruzioni di sistema assemblate, i messaggi o gli strumenti subito prima dell'invio al modello. `context`
viene eseguito per il ciclo dell'agente; `compaction`, `generate` e `title` per le rispettive richieste ausiliarie.
`compaction` e `title` accettano un `result` che salta la chiamata al modello.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook("context", (event) =>
      Effect.sync(() => {
        event.system.push({ type: "text", text: "Keep the review focused on correctness." })
        delete event.tools.write
      }),
    )
    yield* session.hook("compaction", (event) =>
      Effect.map(summarize(event.messages), (summary) => {
        event.result = { summary }
      }),
    )
  }),
```

Modifica le impostazioni delle richieste al modello e, facoltativamente, limita l'hook a un solo provider. L'evento
contiene lo stesso `kind` degli hook HTTP descritti sotto.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook(
      "model.request",
      (event) => Effect.sync(() => (event.headers["x-plugin"] = "review")),
      { providerID: "anthropic" },
    )
  }),
```

Modifica le richieste o le risposte native del provider. I loro body sono stream leggibili una sola volta: clona o
sostituisci un body prima di leggerlo. Entrambi gli hook vengono eseguiti per ogni richiesta emessa da una sessione;
`event.kind` vale `"primary"`, `"compaction"`, `"title"` o `"generate"` a seconda del flusso che l'ha emessa.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook("http.request", (event) =>
      Effect.sync(() => {
        event.request.headers.set("x-session-id", event.sessionID)
        if (event.kind === "title") event.request.headers.set("x-priority", "background")
      }),
    )
    yield* session.hook("http.response", (event) =>
      Effect.sync(() => {
        event.response = new Response(event.response.body, {
          status: event.response.status,
          headers: { ...Object.fromEntries(event.response.headers), "x-plugin": "review" },
        })
      }),
    )
  }),
```

I provider che trasmettono in streaming tramite WebSocket riutilizzano una sola connessione per sessione, quindi gli hook
HTTP non vedono mai quel traffico. L'hook sperimentale `experimental.ws.handshake` viene eseguito una volta per ogni
chiamata al modello, prima che venga selezionata la connessione, ed espone `url` e `headers` della connessione; modificarli
riapre il socket. Gli hook HTTP vengono comunque eseguiti per ogni richiesta su cui una route WebSocket ripiega.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.session.hook(
      "experimental.ws.handshake",
      (event) =>
        Effect.gen(function* () {
          event.headers.authorization = `Bearer ${yield* mintToken(event.url)}`
          delete event.headers["api-key"]
        }),
      { providerID: "azure" },
    )
  }),
```

`experimental.ws.send` ed `experimental.ws.receive` espongono i frame stessi: `send` viene eseguito dopo che il driver
del provider ha costruito un frame in uscita, `receive` su ogni frame in entrata prima che il driver lo osservi. Il valore
di `frame` al ritorno dall'hook è esattamente ciò che viene trasmesso o che arriva al driver; OpenCode non lo convalida.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.session.hook(
      "experimental.ws.send",
      (event) =>
        Effect.sync(() => {
          const body = JSON.parse(event.frame)
          if (body.type === "response.create") body.metadata = { ...body.metadata, session: event.sessionID }
          event.frame = JSON.stringify(body)
        }),
      { providerID: "openai" },
    )
  }),
```

Sovrascrivi la decisione di ritentare dopo un errore del provider o sostituiscine il ritardo in millisecondi. L'hook viene
eseguito dopo che OpenCode ha classificato l'errore e proposto la sua policy, ma prima che venga pianificato qualsiasi
nuovo tentativo. Non espone il modo in cui OpenCode esegue internamente il tentativo successivo.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.session.hook("retry", (event) =>
      Effect.sync(() => {
        if (event.error.status === 429) {
          event.decision = { retry: true, delay: 10_000 }
          return
        }
        if (event.error.type === "provider.invalid-request" && event.attempt === 2) {
          event.decision = { retry: true, delay: 0 }
          return
        }
        if (event.attempt >= 3) event.decision = { retry: false }
      }),
    )
  }),
```

La `decision` iniziale è la policy di OpenCode, quindi gli hook possono rendere ritentabile un errore del provider
normalmente definitivo o annullare un nuovo tentativo proposto. Più hook vengono eseguiti nell'ordine di registrazione e
quelli successivi vedono la decisione corrente. Il numero massimo di tentativi integrato resta un limite invalicabile.
`attempt` è il tentativo fisico proposto: la richiesta iniziale è il tentativo `1`, quindi il primo nuovo tentativo è il
`2`. I ritardi non validi (`NaN`, infinito o valori negativi) ripiegano sul ritardo calcolato. Il ripristino in caso di
superamento del contesto resta separato, perché compatta la conversazione invece di ritentare la stessa richiesta.

```ts
interface ToolFailures extends Record<keyof ToolHooks, unknown> {
  readonly "execute.before": Tool.Error
  readonly "execute.after": never
}

interface ToolHookDomain {
  readonly hook: Hooks<ToolHooks, ToolFailures>
}
```

I tipi di registrazione condivisi mostrano quali operazioni richiedono lo scope del plugin.

```ts
interface Registration {
  readonly dispose: Effect.Effect<void>
}

type Hooks<Spec, Failures extends Record<keyof Spec, unknown> = Record<keyof Spec, never>> = <Name extends keyof Spec>(
  name: Name,
  callback: (input: Spec[Name]) => Effect.Effect<void, Failures[Name]>,
) => Effect.Effect<Registration, never, Scope.Scope>

type Transform<Input> = (callback: (input: Input) => void) => Effect.Effect<Registration, never, Scope.Scope>
```

## Pubblicazione

Un plugin distribuito come pacchetto usa lo stesso export predefinito di un plugin Effect locale. Esporta
l'implementazione Effect dall'entrypoint principale e dichiara `effect` come `peerDependency`.

```json title="package.json"
{
  "name": "opencode-acme-effect-plugin",
  "version": "1.0.0",
  "type": "module",
  "exports": {
    ".": "./src/index.ts"
  },
  "dependencies": {
    "@opencode/plugin": "latest"
  },
  "peerDependencies": {
    "effect": "^4.0.0"
  }
}
```

OpenCode reindirizza le importazioni di `effect`, dei sottopercorsi `effect/*` esportati e di `@opencode/plugin`
(comprese quelle provenienti dalle dipendenze in `node_modules` del plugin) alle istanze del runtime host, così fiber,
logger e parser `Schema` condividono un'unica copia del runtime.

- Non includere `effect` nel bundle dell'artefatto pubblicato del plugin. Se usi un bundler, contrassegna `effect` ed
  `effect/*` come esterni.
- I plugin e le relative dipendenze in `node_modules` vengono sempre eseguiti con l'istanza di `effect` della release di
  OpenCode che li ospita. Usa API e percorsi di modulo di `effect` compatibili con la release di OpenCode a cui ti
  rivolgi; anche le dipendenze compilate per un'altra major di `effect` (come Effect 3) ricevono l'`effect` dell'host e
  non sono supportate.
- Vengono forniti solo i sottopercorsi pubblici di `effect`. Un plugin che importa uno dei moduli privati `internal` di
  Effect non viene caricato e restituisce un errore che indica il percorso.
- Il binario compilato di OpenCode non include le risorse di Scalar e Swagger UI usate dalle pagine di documentazione
  dell'API HTTP di Effect; se un plugin serve quelle pagine, viene mostrato un avviso al loro posto.

L'entrypoint del pacchetto esporta `Plugin.define` con una funzione `effect`.

```ts title="src/index.ts"
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "acme.published",
  effect: (ctx) =>
    Effect.gen(function* () {
      const storage = ctx.storage
      yield* storage.set("installed", true)
    }),
})
```

Usa versioni compatibili con la release di OpenCode a cui ti rivolgi e testa il pacchetto installato, non solo una copia
collegata al workspace.

```sh
bun pm pack
bun add ./opencode-acme-effect-plugin-1.0.0.tgz
```
