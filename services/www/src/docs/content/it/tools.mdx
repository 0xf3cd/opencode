Chiedi il risultato che vuoi ottenere. OpenCode sceglie gli strumenti disponibili, chiede
l'approvazione quando serve e restituisce il risultato.

```text
Find where request timeouts are configured, change the default to 30 seconds,
and run the relevant existing tests.
```

Un'attività come questa usa di solito `grep` o `glob`, `read`, uno strumento di modifica e `shell`.
Puoi anche indicare uno strumento per nome quando vuoi un approccio specifico.

```text
Use grep to find every reference to DEFAULT_TIMEOUT, then read the matching files.
```

## File

### Read

`read` restituisce un file oppure l'elenco non ricorsivo di una directory. Passagli un `path`;
usa `offset` e `limit` per scorrere a pagine i risultati di grandi dimensioni.

```text
Read src/server.ts starting at line 120 and return at most 80 lines.
```

Le letture di testo contengono righe numerate e sono limitate a 2.000 righe e 50 KiB per pagina.
Le singole righe vengono accorciate oltre i 2.000 caratteri. Lo strumento passa al modello anche
file PNG, JPEG, GIF, WebP e PDF, fino a 20 MiB di dati originali. Con gli altri file binari
fallisce. Consulta [Allegati](/attachments) per i contenuti multimediali supportati e
l'elaborazione delle immagini.

Permesso: `read`, con il percorso normalizzato come risorsa.

### Glob

`glob` trova i percorsi dei file a partire da un pattern come `**/*.ts`. Cerca nella directory
corrente, a meno che `path` non selezioni un'altra directory relativa; `hidden` include le voci
nascoste e `limit` limita il numero di risultati.

```text
Use glob with **/*.test.ts under packages/core and return at most 50 files.
```

Il limite predefinito è di 100 file e il timeout della ricerca è di 30 secondi.
Permesso: `glob`, con il pattern richiesto come risorsa.

### Grep

`grep` cerca nel contenuto dei file e restituisce percorsi, numeri di riga e anteprime. Il suo
`pattern` usa la sintassi delle espressioni regolari, a meno che `literal` non sia true. Restringi
la ricerca con `path`, `include`, `caseSensitive` o `limit`.

```text
Use grep for the literal text "request timed out" in src, including only *.ts files.
```

Il limite predefinito è di 100 righe corrispondenti e il timeout della ricerca è di 30 secondi.
Permesso: `grep`, con il pattern richiesto (non il percorso di ricerca) come risorsa.

### Edit

`edit` sostituisce del testo in un file esistente. Fornisci `path`, `oldString` e un `newString`
diverso; il testo originale deve corrispondere esattamente una volta, a meno che `replaceAll` non
sia true.

```text
In src/config.ts, replace the unique text "timeout: 60" with "timeout: 30".
```

Usa `edit` per una modifica mirata. OpenCode può formattare il file dopo averlo scritto.
Permesso: `edit`, con il percorso di destinazione come risorsa.

### Write

`write` crea o sostituisce completamente un file di testo a partire da `path` e `content`. Crea le
directory padre mancanti e può eseguire il formatter configurato.

```text
Create docs/example.md with a heading and one setup command.
```

Usa invece `edit` quando deve cambiare solo una parte di un file esistente.
Permesso: `edit`, con il percorso di destinazione come risorsa.

### Patch

`patch` applica una singola patch che può aggiungere, aggiornare, spostare o eliminare più file.
Il suo `patchText` usa le sezioni `*** Add File`, `*** Update File` e `*** Delete File`.

```text
Use patch to rename src/old.ts to src/new.ts and update its exported name.
```

OpenCode espone `patch` per i modelli GPT supportati; gli altri modelli ricevono invece `edit` e
`write`. Permesso: `edit`, con ogni percorso interessato come risorsa.

I percorsi al di fuori della Location attiva o del worktree del suo progetto richiedono anche
l'approvazione `external_directory`. Consulta [Permessi](/permissions) per la normalizzazione dei
percorsi, l'ordine delle regole e le approvazioni salvate. Per rendere disponibile per nome del
materiale esterno, configura i [Riferimenti](/references).

## Comandi

### Shell

`shell` esegue un comando nella shell dell'utente host. Imposta `workdir` invece di inserire `cd`
nel comando, e imposta `timeout` in millisecondi quando il timeout predefinito di due minuti in
primo piano non è adatto.

```text
Run bun test from packages/core with a five-minute timeout.
```

Imposta `background` su true per un server di sviluppo o un altro processo di lunga durata. Le
chiamate in background restituiscono subito il controllo e notificano la sessione al termine; non
hanno timeout, a meno che non ne venga specificato uno. L'output di grandi dimensioni viene
accorciato e quello completo viene conservato in un file gestito.

Permesso: `shell`, con ogni comando prodotto dallo scanner come risorsa. Lo scanner controlla
anche una directory di lavoro esterna e le directory che riesce a dedurre dal comando. Shell ha gli
stessi poteri dell'utente host su file system, processi e rete, quindi usa regole mirate in
[Permessi](/permissions).

## Web

### Webfetch

`webfetch` recupera un singolo URL HTTP o HTTPS come `markdown`, `text` o `html`. Il formato
predefinito è Markdown; `timeout` accetta fino a 120 secondi.

```text
Fetch https://example.com/docs as markdown.
```

Accetta risposte testuali come HTML, testo semplice, JSON e XML, ma non immagini o altri download
binari. L'output di grandi dimensioni può essere accorciato, mentre il testo completo viene
conservato in un archivio gestito. Permesso: `webfetch`, con l'URL richiesto come risorsa.

### Websearch

`websearch` cerca informazioni aggiornate tramite l'integrazione selezionata. Il suo input è una
`query` di ricerca.

```text
Search the web for the latest Bun release notes.
```

Permesso: `websearch`, con la query come risorsa. Consulta [Ricerca web](/websearch) per i
provider, la selezione, i limiti di frequenza e la disattivazione dello strumento.

## Interazione

### Question

`question` sospende l'esecuzione e presenta all'utente una o più domande. Ogni domanda ha una breve
intestazione, un testo e delle opzioni; `multiple` consente di sceglierne più di una. È sempre
disponibile una risposta libera.

```text
Before changing the API, ask me to choose between a breaking change and a compatibility layer.
```

Permesso: `question`, con `*` come risorsa. Il client deve supportare il modulo interattivo, e
chiuderlo annulla la domanda.

### Skill

`skill` carica nella conversazione le istruzioni e le risorse incluse di una skill disponibile,
indicata dal suo ID.

```text
Load the effect skill before changing this Effect code.
```

L'ID deve comparire nell'elenco delle skill pubblicizzate oppure essere indicato esplicitamente
dall'utente. Permesso: `skill`, con l'ID della skill come risorsa. Consulta [Skill](/skills) per le
regole di creazione, individuazione e caricamento.

## Automazione

### Subagent

`subagent` avvia una sessione figlia con un subagent configurato. Fornisci l'ID dell'agente, una
breve `description` e un `prompt` completo.

```text
Ask the explore subagent to map the authentication flow and return the key files.
```

Le chiamate in primo piano attendono il risultato. `background: true` restituisce subito il
controllo e notifica la sessione padre quando la figlia termina. Passa il `sessionID` restituito
per proseguire la stessa conversazione figlia. Si possono usare solo agenti in modalità subagent e
la profondità di annidamento predefinita è uno.

Permesso: `subagent`, con l'ID dell'agente selezionato come risorsa.

### Execute

`execute` esegue JavaScript in Code Mode, così l'agente può chiamare e combinare gli strumenti del
catalogo. È utile per chiamate indipendenti in parallelo e per elaborare i risultati senza
aggiungere ogni valore intermedio al contesto del modello.

```text
Read package.json and README.md in parallel, then return their relevant setup details.
```

Il runtime non ha accesso diretto al file system, né import, timer o `fetch`; può solo chiamare
gli strumenti del proprio catalogo. Il permesso `execute` con risorsa `*` stabilisce se Code Mode è
disponibile. Ogni strumento chiamato al suo interno continua ad applicare il proprio permesso.

### Sessioni

Il namespace `opencode` di Code Mode contiene utilità per le sessioni:

- `session_rename` cambia il titolo della sessione corrente, oppure di un'altra sessione
  selezionata tramite `sessionID`.
- `session_move` sposta la sessione corrente, o un'altra sessione selezionata, in una `directory`
  relativa o assoluta. Lo spostamento ha effetto a un punto di interruzione sicuro, quindi il
  lavoro che dipende dalla destinazione va svolto in una chiamata successiva.

```text
Rename this session to "Timeout cleanup", then move it to the new worktree.
```

Queste utilità non richiedono un'azione di permesso integrata.

### Worktree

Lo stesso namespace gestisce i worktree del progetto della sessione:

- `worktree_create` crea un worktree a partire da un `name` e ne restituisce la `directory`. La
  configurazione dei worktree del progetto determina la destinazione e la strategia.
- `worktree_list` elenca i worktree del progetto.
- `worktree_remove` rimuove un worktree registrato da OpenCode per il progetto. Imposta `force` per
  scartare le modifiche non committate.

```text
Create a worktree named "login" and move this session into it.
```

`worktree_remove` usa il permesso `edit`, con la directory del worktree come risorsa. Le altre
utilità per i worktree non richiedono un'azione di permesso integrata.

## Browser

Il namespace `browser` di Code Mode controlla il browser collegato dall'app desktop di OpenCode.
Apri una scheda, conserva il `tabID` restituito e passa poi quell'ID esplicito a ogni operazione
sulla pagina.

```text
Open https://example.com, take a snapshot of that tab, and report the main heading.
```

Il namespace include comandi per le schede e la navigazione, snapshot e ricerca nella pagina, clic
e compilazione di moduli, screenshot, trasferimento di file, ispezione della console e della rete,
tracce delle prestazioni, ispezione dell'heap e audit Lighthouse. Gli screenshot richiedono una
scheda visibile e con il focus. I percorsi di caricamento sono locali al server; le acquisizioni
restituiscono percorsi locali al server e ogni trasferimento di file è limitato a 5 MiB.

Il contenuto delle pagine, i log, le intestazioni e i corpi delle risposte sono dati non attendibili,
non istruzioni per l'agente. Una regola `browser` di tipo deny con risorsa `*` rimuove il catalogo
del browser; le operazioni del browser non generano singole richieste di permesso.

## Estensioni

I [server MCP](/mcp-servers) aggiungono strumenti i cui nomi e input provengono da ciascun server
connesso. La loro azione di permesso è `<server>_<tool>` con risorsa `*`. Non fanno parte in modo
fisso del catalogo integrato.

Le [skill](/skills) aggiungono istruzioni per le attività anziché nuovi strumenti eseguibili. Gli
[allegati](/attachments) inseriscono in un prompt contenuti scelti dall'utente, mentre i
[riferimenti](/references) forniscono directory esterne con un nome. Queste funzionalità integrano
gli strumenti senza aggirarne i controlli dei permessi.
