---
title: "主题"
---

OpenCode 内置了许多支持浅色和深色模式的主题。你可以在设置中选择一个，也可以自行搭配颜色。

## 选择主题

按 `Ctrl+P`，选择 **Open settings**，然后打开 **Theme**。默认主题为 `opencode`。

你也可以在全局 [CLI 设置](/cli/config)中设置主题：

```json title="~/.config/opencode/cli.json"
{
  "$schema": "https://opencode.ai/v2/cli.json",
  "theme": {
    "name": "tokyonight",
    "mode": "dark"
  }
}
```

运行 `/themes` 可以直接切换主题，无需打开设置。

## 系统颜色

如果 OpenCode 能读取终端的调色板，主题选择器中会出现 `system` 主题。它会根据终端的前景色、背景色和 ANSI 调色板生成配色。

主题名称 `system` 表示使用从终端派生的颜色；模式 `system` 则表示跟随终端的浅色或深色外观。

## 模式

使用 `system` 跟随终端外观，或者将主题固定为浅色或深色模式：

| 模式 | 行为 |
| --- | --- |
| `system` | 跟随检测到的终端浅色或深色外观。 |
| `dark` | 始终使用主题的深色配色。 |
| `light` | 始终使用主题的浅色配色。 |

该设置对应 CLI 配置中 `theme` 下的 `mode` 字段。如果自定义主题只提供了一种模式，那么在请求另一种模式时，OpenCode 也会使用已提供的那种模式。

## 添加主题

如果要添加下载的或他人分享的主题，请将其 JSON 文件复制到全局主题目录：

```bash
cp theme.json ~/.config/opencode/themes/
```

你也可以将主题放到项目的 `.opencode/themes` 目录中，使其仅在该项目中可用。

文件名即主题名称。例如，`my-theme.json` 会显示为 `my-theme`。添加文件后重启 OpenCode，然后运行 `/themes` 选择它。

OpenCode 只读取 `.json` 文件。离当前目录更近的主题会替换同名的全局主题或上级目录中的主题。

## 在插件中使用主题

[CLI 插件](/build/plugins/cli)可以通过 `context.theme` 读取解析后的颜色，通过 `context.themeMode` 读取当前模式。请使用语义化 token，让插件跟随所选主题：

```tsx title="Inside a CLI plugin component"
import { usePlugin } from "@opencode/plugin/tui"

function Status() {
  const context = usePlugin()
  return <text fg={context.theme.text.base}>Ready</text>
}
```

公开的 CLI 插件 API 不支持注册主题。如需添加自定义主题定义，请将 JSON 文件放在上述目录中。

## 创建主题

使用我们的[主题工具](https://opencode.ai/theme/)创建或编辑主题。借助该工具，你可以轻松理解主题结构、修改结构并定义自定义颜色。以下说明仅供参考。

主题将共享的语义化 token 与各模式专属的调色板分开：

| 部分 | 用途 |
| --- | --- |
| `base` | 所有模式共享的完整 token 树。 |
| `light`、`dark` | 该模式的完整色相调色板，以及可选的 token 覆盖。 |

每个主题都要提供完整的 `base`，并至少定义 `light` 或 `dark` 其中之一。各模式继承自该文件的 `base`，不会继承内置的 OpenCode 主题，模式之间也不会相互继承。

以下示例只展示与各个概念相关的部分。建议先用主题编辑器生成完整文件，再进行自定义。

### 结构

将两种模式都会用到的颜色放在 `base` 中，需要时再在 `light` 或 `dark` 中覆盖：

```json title="theme.json (excerpt)"
{
  "$schema": "https://opencode.ai/theme.json",
  "base": {
    "text": {
      "base": "$hue.neutral.200",
      "muted": "$hue.neutral.400"
    }
  },
  "light": {
    "hue": {}
  },
  "dark": {
    "hue": {},
    "text": {
      "muted": "$hue.neutral.300"
    }
  }
}
```

完整的 `base` 提供所有语义化 token。每种模式都要提供所有必需的色相，并且可以覆盖 base token 树中的任意部分。

### 颜色与引用

颜色可以是十六进制值、`"transparent"`，或对其他主题颜色的引用：

```json title="Inside base or a mode"
{
  "text": {
    "base": "#eeeeee",
    "muted": "$hue.neutral.400"
  },
  "border": {
    "base": "$text.muted"
  }
}
```

### 色相

色相是包含九个色阶的颜色梯度。每种模式都要定义八种基础色相和三个别名：

| 类型 | 取值 |
| --- | --- |
| 基础色相 | `gray`、`red`、`orange`、`yellow`、`green`、`cyan`、`blue`、`purple` |
| 别名 | `accent`、`interactive`、`neutral` |
| 色阶 | `100`、`200`、`300`、`400`、`500`、`600`、`700`、`800`、`900` |

为基础色相定义全部九个色阶，或者将某个色相设为另一个色相的别名：

```json title="Inside light or dark"
{
  "hue": {
    "purple": {
      "100": "#b38ff4",
      "200": "#9d7cd8",
      "300": "#8869bd",
      "400": "#7357a2",
      "500": "#5f4688",
      "600": "#4b356f",
      "700": "#392557",
      "800": "#271640",
      "900": "#17072b"
    },
    "accent": "$hue.purple"
  }
}
```

色阶顺序遵循该模式的对比方向。浅色主题从 `100` 的深色过渡到 `900` 的浅色；深色主题则从 `100` 的浅色过渡到 `900` 的深色。

`base` 中的 `categorical` 数组设置一组有序的色相，用于区分代理和其他重复出现的条目：

```json title="Inside base"
{
  "categorical": ["accent", "purple", "green", "blue"]
}
```

### 语义化 token

语义化 token 为界面角色分配颜色。组件使用这些角色，而不是直接选择颜色。

| 分组 | 用途 |
| --- | --- |
| `text` | 基础、次要、操作、表单字段、状态和反馈文本。 |
| `background` | 基础背景、浮层表面、操作、表单字段和反馈填充色。 |
| `border`、`scrollbar` | 边框和滚动条颜色。 |
| `diff` | 新增、删除、上下文、高亮和行号颜色。 |
| `syntax` | 源代码高亮。 |
| `markdown` | Markdown 元素。 |

例如，`text.muted` 控制次要文本，`background.raised` 定义层级逐渐升高的表面：

```json title="Inside base"
{
  "text": {
    "base": "$hue.neutral.200",
    "muted": "$hue.neutral.400"
  },
  "background": {
    "base": "$hue.neutral.800",
    "raised": {
      "base": "$hue.neutral.700",
      "high": "$hue.neutral.600",
      "max": "$hue.neutral.500"
    }
  }
}
```

语法高亮的键包括 `comment`、`keyword`、`function`、`variable`、`string`、`number`、`type`、`operator` 和 `punctuation`。

Markdown 的键包括 `text`、`heading`、`link`、`linkText`、`code`、`blockQuote`、`emphasis`、`strong`、`horizontalRule`、`listItem`、`listEnumeration`、`image`、`imageText` 和 `codeBlock`。

### 操作与状态

操作有 `primary`、`secondary` 和 `destructive` 三种变体。操作和表单字段使用 `base`，并可选择定义交互状态：

```json title="Inside base or a mode"
{
  "text": {
    "action": {
      "primary": {
        "base": "$hue.interactive.400",
        "$hovered": "$hue.interactive.300",
        "$disabled": "$hue.neutral.600"
      }
    }
  }
}
```

状态键包括 `$hovered`、`$focused`、`$pressed`、`$selected` 和 `$disabled`。未指定的状态会使用该操作或表单字段的 `base` 颜色。

### 对话框表面

面板、对话框、菜单和通知提示从 `background.raised` 中选择各自的层级。对话框还可以通过 `@dialog` 额外覆盖语义化 token：

```json title="Inside base or a mode"
{
  "@dialog": {
    "background": {
      "base": "$background.raised.base",
      "action": {
        "primary": {
          "$hovered": "$background.raised.high"
        }
      }
    }
  }
}
```

TUI 在应用 `@dialog` 之后会重新解析引用，因此引用 `$background.base` 的 token 会跟随对话框背景。上下文覆盖中的操作 `base` 会成为其未指定状态的回退值；显式指定的状态覆盖仍然优先。
