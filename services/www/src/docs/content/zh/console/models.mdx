OpenCode Console 提供一份经过 OpenCode 团队测试和验证的模型列表。登录、充值额度并获取 API 密钥后，就可以在 OpenCode 或其他编程代理中使用这些模型。

Console 在 OpenCode 中的用法和其他提供商一样。它**完全是可选的**，你也可以改用任何其他提供商。如果想要包含一定用量的订阅，请参阅 [OpenCode Go](/console/go)。

## 工作原理

1. 登录 [Console](https://opencode.ai/console)，添加账单信息并充值额度，然后复制你的 API 密钥。
2. 在 TUI 中运行 `/connect`，选择 OpenCode 按量付费提供商，然后粘贴 API 密钥。

   ```text
   /connect
   ```

3. 运行 `/models` 查看可用模型并选择一个。

   ```text
   /models
   ```

费用按请求计算，你可以随时为账号充值额度。

### Jev

Jev 是 TypeSafe AI 推出的 System One 模型，专为快速、结构化的决策而设计。它不生成文本，而是根据带类型的问题评估一个 `state`，并返回可直接在代码中使用的值和概率。它支持是非题（`noul`）、选择题（`choice`）和基于评分标准的打分题（`score`）。

请使用 OpenCode Console API 密钥调用 `https://opencode.ai/inference/v1/systemone` 端点。下面的示例判断一条支持请求是否紧急：

```bash
curl https://opencode.ai/inference/v1/systemone \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "jev-1.13",
    "state": "My payments have failed for three days and I am losing sales. Please help now.",
    "questions": {
      "is_urgent": {
        "type": "noul",
        "instructions": "Does this request require urgent attention?"
      }
    }
  }'
```

一次请求中可以包含多个问题。Jev 会并行评估这些问题，并在对应的问题 ID 下返回各自的答案：

```bash
curl https://opencode.ai/inference/v1/systemone \
  -H "Authorization: Bearer $OPENCODE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "jev-1.13",
    "state": "My order arrived late and the item is damaged. I want a refund.",
    "questions": {
      "department": {
        "type": "choice",
        "instructions": "Which team should handle this request?",
        "criteria": {
          "returns": "Refunds, exchanges, or damaged items",
          "shipping": "Delivery delays or lost packages",
          "billing": "Charges, invoices, or payment problems"
        }
      },
      "frustration": {
        "type": "score",
        "instructions": "How frustrated is the customer?",
        "criteria": ["Calm", "Frustrated", "Very angry"]
      }
    }
  }'
```

将 `jev-1.13` 换成 `jev-1.13-free`，即可使用限时免费的模型。关于问题类型和响应字段的详细说明，请参阅 [TypeSafe AI 文档](https://docs.typesafe.ai/)。

## 背景

可用的模型很多，但真正适合作为编程代理的只有少数几个。不同提供商的配置、性能和质量也各不相同，因此通过 OpenRouter 等网关访问的模型，表现可能会有所差异。

<Callout type="tip">我们测试了一批与 OpenCode 配合良好的模型和提供商。</Callout>

为了建立这份模型目录，我们：

1. 测试了一批精选模型，并与各模型团队交流了最佳运行方式。
2. 与提供商合作，确保模型以正确的方式提供服务。
3. 对每个模型与提供商的组合进行基准测试，整理出一份我们愿意推荐的列表。

Console 是一个 AI 网关，让你可以访问这些模型。

## 目标

我们打造 Console 的目标是：

1. 为编程代理**基准测试**最好的模型和提供商。
2. 提供**最高质量**的选项，不降低性能，也不将请求路由到更便宜的提供商。
3. 以成本价销售，让你享受到**降价**带来的好处，加价仅用于覆盖手续费。
4. **没有锁定**：你可以在任何编程代理中使用 Console，也可以在 OpenCode 中使用其他提供商。
