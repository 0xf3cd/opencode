---
title: "SSO"
description: "通过 OIDC 或 SAML，使用你的身份提供商登录 OpenCode Console 工作区。"
---

单点登录（SSO）会让工作区成员在登录时跳转到你公司的身份提供商。所有者和管理员可以在 **Settings › Security** 中进行设置，所有工作区都包含此功能。

| 协议           | 身份提供商                                                                             |
| -------------- | -------------------------------------------------------------------------------------- |
| OpenID Connect | Google Workspace、Microsoft Entra ID、Okta、Auth0、Ping Identity 或任何 OIDC 提供商   |
| SAML 2.0       | Google Workspace、Microsoft Entra ID、Okta 或任何 SAML 提供商                          |

每个工作区只能有一个 SSO 连接。

## 设置 OIDC

1. 打开 **Settings › Security**，点击 **Configure SSO**，然后选择 **OpenID Connect** 和你的身份提供商。
2. 按照页面上显示的步骤在身份提供商中创建应用，并包含 `openid`、`email` 和 `profile` 作用域。
3. 填写 **Issuer URL**（或者你的租户或域名），以及 **Client ID**、**Client Secret** 和 **Display Name**，然后点击 **Save**。
4. 从连接中复制 **Callback URL**，将其添加到身份提供商允许的重定向 URI 中。

```text
https://opencode.ai/console/auth/sso/ssoconn_.../callback
```

保存时，Console 会检查颁发者（issuer）是否可以访问。连接保存后，SSO 立即生效。

## 设置 SAML

1. 打开 **Settings › Security**，点击 **Configure SSO**，然后选择 **SAML 2.0** 和你的身份提供商。
2. 将 **ACS URL** 和 **SP Entity ID** 复制到身份提供商中。自定义提供商也可以改用 **SP Metadata URL**，或下载 XML。
3. 通过 URL、上传 XML 或粘贴的方式添加身份提供商的元数据。你也可以手动填写 **IdP Entity ID**、**IdP SSO URL** 和 **IdP Certificate**。
4. 检查各项信息，然后点击 **Activate SSO**。

```text
ACS URL:       https://opencode.ai/console/auth/sso/ssoconn_.../callback
SP Entity ID:  https://opencode.ai/console/auth/sso/ssoconn_.../metadata
```

身份提供商必须对响应或断言进行签名，并通过 `email` 属性或 NameID 发送用户的电子邮件地址。

## 验证邮箱域名

使用已验证域名下的邮箱登录 [Console](https://opencode.ai/console) 的用户，会被转到你的身份提供商。SSO 生效后，在 **Email domains** 下点击 **Add domain**，输入你的域名，然后发布页面上显示的 TXT 记录。

```text
Name:   _opencode-console-challenge.example.com
Type:   TXT
Value:  oc-verify=...
```

记录发布后，点击 **Verify Domain**。DNS 更改可能需要一段时间才能生效。每个域名只能属于一个工作区。

## 强制使用 SSO

工作区启用 SSO 后，管理员和成员必须通过 SSO 登录才能打开该工作区，Console 会自动将他们重定向到身份提供商。使用 `/connect` 连接 OpenCode 时也遵循同样的规则。

所有者也可以不通过 SSO 登录，这样即使身份提供商配置有误，也不会导致无法进入工作区设置。

## 自动加入

已验证域名下的用户首次通过 SSO 登录时，会以 **Member** 身份加入工作区。以下情况不会自动添加：

- 用户有待处理的邀请。此时会改用该邀请。
- 工作区使用[目录同步](/console/scim)，由目录同步决定成员资格。
- 工作区订阅了 [Go](/console/go)。

对于启用了 SSO 的工作区，受邀者打开邀请链接时会被转到你的身份提供商。

## 现有账号

如果某人已经有使用相同邮箱的 Console 账号，Console 会要求其登录该账号一次，以关联 SSO。受邀用户和通过目录同步添加的用户会自动关联。

## 编辑或删除

点击连接上的 **Edit** 可以修改其信息。将密钥或证书留空即可保留当前值。如需在 OIDC 和 SAML 之间切换，请删除现有连接并新建一个。

通过 **⋯ › Delete...** 删除连接。删除后，成员会改用其他登录方式，目录同步也会停止，其令牌会被撤销。邮箱域名会保留。
