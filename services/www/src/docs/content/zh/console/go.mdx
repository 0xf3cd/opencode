OpenCode Go 让你稳定地使用热门的开源编程模型，提供两种按月订阅的套餐：

| 套餐        | 价格          | 包含用量                                    |
| ----------- | ------------- | ------------------------------------------- |
| **Go**      | **$10/月**    | 以更低成本使用下列模型                      |
| **Go Plus** | **$40/月**    | 下列模型的用量上限更高                      |

Go 在 OpenCode 中的用法和其他提供商一样：订阅 OpenCode Go 后获取 API 密钥即可。它**完全是可选的**，不订阅也能正常使用 OpenCode。

该服务主要面向国际用户设计，提供稳定的全球访问。

## 工作原理

1. 登录 [OpenCode Console](https://opencode.ai/console)，订阅 Go 或 Go Plus，添加账单信息，然后复制你的 API 密钥。
2. 在 TUI 中运行 `/connect`，选择 **OpenCode Go**，然后粘贴 API 密钥。

   ```text
   /connect
   ```

3. 运行 `/models`，选择一个 Go 提供的模型。

   ```text
   /models
   ```

<Callout>
  Go 和 Go Plus 仅适用于只有一名成员的工作区，例如注册时自动创建的 **Personal** 工作区。订阅了 Go 的工作区无法邀请成员。
</Callout>

## 可以在哪里使用？

OpenCode Go 专为 [OpenCode](https://opencode.ai) 以及会产生类似请求的其他编程代理而设计。我们会监控流量，防止滥用行为影响其他用户的体验。

你的客户端应当：

1. 发送典型的编程代理流量。
2. 使用自己的 User-Agent 标识自身，例如 `my-coding-agent/1.0`，而不是通用 SDK 或 HTTP 库的名称。
3. 为每个对话在 `x-opencode-session` 中发送稳定的会话 ID，以便我们优化路由和提示词缓存。

### 已验证的客户端

除 OpenCode 外，以下客户端已经过验证，可以与 OpenCode Go 正常配合使用。不过，我们不保证它们今后仍能持续正常工作。

| 客户端            | 会话支持                                                                                                                                                                                       |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Hermes**        | 包含 [PR #101864](https://github.com/NousResearch/hermes-agent/pull/101864) 的构建会在主请求和辅助 OpenCode 请求中发送该请求头。该修复在 v0.21.0 之后合并，单独的 v0.21.0 版本并不包含它。 |
| **Claude Code**   | Go 能识别它原生的会话请求头，无需使用自定义请求头包装。                                                                                                                                        |
| **Codex**         | Go 能识别它原生的会话请求头。部分版本和代理配置仍会省略该请求头；转发请求时请保留会话请求头。                                                                                                  |
| **ZCode**         | Go 能识别它原生的会话请求头。我们提出的[支持 `x-opencode-session` 的请求](https://github.com/zai-org/feedback/issues/492)仍未关闭，但现在已无需再发送这个特定请求头。                          |
| **Pi**            | 当前版本会为 OpenCode 发送会话信息。请更新旧版本安装。                                                                                                                                         |
| **jcode**         | 请更新到 **v0.81.6 或更高版本**，其中包含[会话请求头修复](https://github.com/1jehuang/jcode/issues/1167)。                                                                                     |
| **Kilo Code CLI** | 包含 [PR #13752](https://github.com/Kilo-Org/kilocode/pull/13752) 的构建恢复了 OpenCode 会话请求头。该修复仅适用于 CLI，不包括 VS Code 扩展。参见 [issue #13723](https://github.com/Kilo-Org/kilocode/issues/13723)。 |

### 已知存在问题的客户端

在我们调查过的版本中，以下客户端缺少会话支持或支持不完整。相关链接中跟踪了修复进展和临时解决方案。

| 客户端                  | 状态与跟踪                                                                                                                                                                       |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **DeepSeek Harness**    | 部分模型路径会携带会话信息，其他路径则缺失。我们能识别它原生的请求头，剩下的工作是在所有适配器中都发送该请求头。[Discussion #5495](https://github.com/deepseek-ai/deepseek-harness/discussions/5495)。 |
| **GitHub Copilot Chat** | 已在 [VS Code issue #334186](https://github.com/microsoft/vscode/issues/334186) 中请求自动支持会话请求头。                                                                      |
| **Kimi Code**           | 已在 [issue #3506](https://github.com/MoonshotAI/kimi-code/issues/3506) 中请求自动支持会话请求头。                                                                              |
| **MiMo Code**           | [Issue #2317](https://github.com/XiaomiMiMo/MiMo-Code/issues/2317) 已在 [PR #2327](https://github.com/XiaomiMiMo/MiMo-Code/pull/2327) 中提出修复，但尚未合并。                  |

### 超出限额后的用量

如果你的 Console 余额中还有额度，可以在 Console 中开启 **Use balance** 选项。开启后，达到用量限额时 Go 会回退到你的[按量付费余额](/console/models#pricing)，而不是直接拒绝请求。

### 为什么部分模型的用量较低

使用 Go 时，每月包含的用量因模型而异。

对于大多数模型，我们通过批量折扣和预留 GPU 容量来实现这一点，再把节省下来的成本以更高的每月用量回馈给你。

对于部分模型，我们还没有机会谈下折扣或以更低成本托管，原因可能是模型较新，也可能是其公开价格本身已经打过折。

对于这些模型，你得到的用量仍比直接向模型提供商付费略多一些，这也是它们每月包含用量较低的原因。

## 背景

开源模型已经变得非常强大，在编程任务上的表现已接近专有模型。而且由于有众多提供商可以相互竞争地提供服务，它们的价格通常要便宜得多。

然而，要稳定、低延迟地使用这些模型并不容易，不同提供商的质量和可用性参差不齐。

<Callout type="tip">我们测试了一批与 OpenCode 配合良好的模型和提供商。</Callout>

为了解决这个问题，我们做了几件事：

1. 测试了一批精选的开源模型，并与各模型团队交流了最佳运行方式。
2. 与几家提供商合作，确保这些模型以正确的方式提供服务。
3. 对模型与提供商的组合进行基准测试，整理出一份我们愿意推荐的列表。

Go 和 Go Plus 都可以使用这些模型，根据你的使用量选择合适的套餐即可。

## 目标

我们打造 OpenCode Go 的目标是：

1. 以低价订阅让更多人**用得起** AI 编程。
2. 提供**稳定可靠**的方式来使用最好的开源编程模型。
3. 精选经过**测试和基准评估**、适合编程代理使用的模型。
4. **没有锁定**：你同样可以在 OpenCode 中使用任何其他提供商。
