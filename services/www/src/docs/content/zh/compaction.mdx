---
title: 上下文压缩
---

上下文压缩会用一份摘要替换较早的对话，从而在长会话中腾出空间，让会话在超出模型上下文上限后仍能继续。

## 工作原理

当会话接近模型的上下文上限时，OpenCode 会对最近的一段对话（默认约 15,000 个 token）之外的所有内容生成摘要。摘要生成后，会被放在这段最近对话的前面，会话随后从这里继续。

```text
before   [ system prompt ][ older conversation ............ ][ recent 15k ][ pending work ]
after    [ system prompt ][ summary ][ recent 15k ][ pending work ]
```

模型会把摘要当作过去的对话。之后的压缩会更新同一份摘要，而不是从头开始。

## 开启

自动压缩默认开启：

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "compaction": {
    "auto": true,
    "keep": { "tokens": 15000 },
  },
}
```

压缩是有损的。如果最近对话中的精确细节很重要，可以增大 `keep.tokens`，或者在自动压缩之前自己手动请求压缩。

## 手动压缩

你可以随时请求压缩，即使历史很短也可以：

```sh
opencode api post /api/session/ses_example/compact --data '{}'
```

`api` 命令会自动发现后台服务并完成身份验证。它的响应只确认请求已被接受，不会等待摘要生成。订阅 `session.compaction.*` 事件即可得知压缩何时完成。完整的操作说明请参阅 [API 参考](/api)。

| 规则 | 行为 |
| --- | --- |
| 时机 | 在下一个安全点运行，早于仍在等待的提示词。 |
| 重复请求 | 在已有请求等待期间发出的新请求会合并到其中。 |
| 自动压缩开关 | 即使 `compaction.auto` 为 `false` 也能使用。 |

传入 `id` 可以让完全相同的重试具有幂等性。将同一个 ID 用于不同的请求会返回冲突。

```sh
opencode api post /api/session/ses_example/compact --data '{"id":"msg_compact_once"}'
```

## 设置

在任意 [OpenCode 配置文件](/config)中添加 `compaction`：

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "compaction": {
    "auto": false,
    "keep": { "tokens": 24000 },
    "buffer": 16000,
  },
}
```

| 字段 | 默认值 | 行为 |
| --- | ---: | --- |
| `auto` | `true` | 在接近上下文上限时自动压缩；当提供商因请求过长而拒绝时，压缩后重试一次。手动压缩始终可用。 |
| `keep.tokens` | `15000` | 与摘要一同保留的最近对话的大致 token 数。值越大，保留的细节越多，但留给新工作的空间越少。 |
| `buffer` | 上限的 10% | 在模型上限以下预留的空闲 token 数。值越大，自动压缩开始得越早。 |

`keep.tokens` 和 `buffer` 接受非负整数。

## 提供商

默认情况下，OpenCode 会使用会话的模型自行生成摘要。有些提供商可以改为在其服务端压缩对话。使用 `settings.compaction` 可以按提供商或模型启用此功能：

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "settings": { "compaction": { "type": "native" } },
      "models": {
        "gpt-4.1": { "settings": { "compaction": { "type": "summary" } } },
      },
    },
  },
}
```

模型级设置会覆盖提供商级设置。`native` 使用提供商的压缩功能；`summary` 使用 OpenCode 自己的压缩。

使用原生压缩时，OpenCode 会把对话发送到提供商的压缩端点。提供商会返回一个不透明的加密条目，用来代替较早的对话。你最近的消息和附件（最多 `keep.tokens`）会与它一起保留：

```text
before   [ older conversation ........................ ][ recent user messages ]
after    [ encrypted checkpoint + recent user messages ]
```

| 主题 | 行为 |
| --- | --- |
| 支持范围 | OpenAI Responses 模型。具体支持情况因部署和模型而异。 |
| 触发阈值 | 与摘要压缩使用相同的 `auto` 和 `buffer` 设置。手动请求同样可用。 |
| 可移植性 | 加密检查点只能用于相同的提供商、模型和端点。如果切换模型，会话会改为从原始对话继续。 |
| 过长 | 如果提供商以过长为由拒绝压缩请求，OpenCode 会用更小的请求重试，而不会改用摘要。 |

## 摘要

摘要采用结构化格式，方便另一个代理据此接手工作：

```md
## Objective
Finish the authentication migration.

## Next Move
- Update the callback handler.
- Verify the login flow.
```

摘要涵盖目标和需求、已做出的决定、已完成和进行中的工作、阻碍和下一步，以及相关文件。在与其一同保留的最近对话中，较长的工具输出会被截短，附件数据会被替换为简短的描述。

压缩之后，你的指令文件的当前版本会成为该会话的新基线；请参阅[指令](/instructions)。

## 限制

| 限制 | 结果 |
| --- | --- |
| 模型 | 压缩使用会话的模型，没有单独的压缩模型。 |
| 历史 | 压缩需要有较早的对话可供替换。如果请求的大部分内容是固定的指令和工具 schema，压缩就无法腾出空间。 |
| 大小 | 如果待压缩的对话本身过长，OpenCode 会发送截短后的文本版本，并可能省略最早的几轮交流。 |
| 恢复 | 因过长而被拒绝的请求会被压缩并重试一次。如果再次被拒绝，则会返回错误。 |
| 存储 | 较早的消息即使不再发送给模型，也仍会被保存。 |

例如，在下面这种情况下，压缩无济于事：

```text
128k context = 120k fixed instructions and tools + 8k conversation
```

## 迁移

V1 使用保留末尾轮次和修剪的机制。V2 改用摘要和 `compaction.keep.tokens`：

```jsonc
{
  "compaction": {
    "keep": { "tokens": 15000 }
  }
}
```

本页中的设置和行为适用于 V2。
