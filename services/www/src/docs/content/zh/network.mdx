设置标准代理环境变量，并排除回环地址。OpenCode 的 CLI 与其后台服务之间使用本地 HTTP 连接，因此在 CLI 环境中配置代理时，必须排除回环地址。

```bash
export HTTP_PROXY=http://proxy.example.com:8080
export HTTPS_PROXY=http://proxy.example.com:8080
export NO_PROXY=localhost,127.0.0.1,::1

opencode
```

`HTTP_PROXY` 用于 HTTP 目标地址，`HTTPS_PROXY` 用于 HTTPS 目标地址。两个变量中的代理 URL 本身都可以使用 `http://`。`NO_PROXY` 是以逗号分隔的主机和地址列表，这些地址将直接连接。

## 后台服务

只有当后台服务从 shell 启动时，shell 中导出的变量才会对其生效。请将这些变量持久化到托管服务配置中，以便之后每次启动服务时都使用相同的网络设置。

```bash
opencode service set env HTTP_PROXY http://proxy.example.com:8080
opencode service set env HTTPS_PROXY http://proxy.example.com:8080
opencode service set env NO_PROXY localhost,127.0.0.1,::1
opencode service start
```

修改托管环境变量会停止正在运行的服务，`service start` 会使用新的环境重新启动它。如果 CLI 所在的 shell 设置了代理，也要在该 shell 中保留 `NO_PROXY`，因为托管服务变量只作用于服务器进程，而不作用于 CLI 进程。

使用 `service unset env` 删除已持久化的变量：

```bash
opencode service unset env HTTPS_PROXY
```

## 身份验证

如果代理支持在 URL 中携带凭据，请在每个需要身份验证的代理 URL 中包含用户名和密码。用户名或密码中的 `@`、`:`、`/` 等字符需要进行百分号编码。

```bash
export HTTPS_PROXY='http://user:p%40ssword@proxy.example.com:8080'
```

对于后台服务，请持久化完整的 URL。该值存储在私有服务配置中，并会由 `opencode service get env` 显示出来，因此请勿分享该命令的输出。

```bash
opencode service set env HTTPS_PROXY 'http://user:p%40ssword@proxy.example.com:8080'
```

## 证书

如果代理或目标地址使用由私有证书颁发机构签发的证书，请将 `NODE_EXTRA_CA_CERTS` 设置为一个 PEM 文件。进程启动时，这些额外的证书颁发机构会被添加到运行时的信任存储中。

```bash
export NODE_EXTRA_CA_CERTS=/etc/company/ca.pem
opencode --standalone
```

为后台服务持久化该文件路径，然后重启服务：

```bash
opencode service set env NODE_EXTRA_CA_CERTS /etc/company/ca.pem
opencode service start
```

## 前台进程

`--standalone` 和 `serve` 使用各自进程的环境变量，`opencode service set env` 不会配置这些进程。

```bash
HTTP_PROXY=http://proxy.example.com:8080 \
HTTPS_PROXY=http://proxy.example.com:8080 \
NO_PROXY=localhost,127.0.0.1,::1 \
opencode --standalone
```

对前台服务器使用相同的方式：

```bash
HTTPS_PROXY=http://proxy.example.com:8080 \
NO_PROXY=localhost,127.0.0.1,::1 \
opencode serve
```

## 验证

应用设置后，检查 CLI 能否连接到后台服务：

```bash
opencode api get /api/info
```

成功的健康检查响应可以验证本地客户端与服务之间的连接。再发起一次正常的提供商请求，以验证服务的出站代理和证书路径。
