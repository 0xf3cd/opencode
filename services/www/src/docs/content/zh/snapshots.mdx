---
title: 快照
---

快照让你可以同时撤销最近的对话和文件改动。它适合用来修改最近的工作，但重要内容仍应通过 Git 提交或备份来保存。

## 工作流程

在得到想要修改的回答后，运行 `/undo`。OpenCode 会暂存这次回滚，恢复受影响的文件，并把被移除的提示词放回输入框，方便你编辑。

```text
/undo

# Edit the restored prompt, then submit it again.
Add validation without changing the public API.
```

提交编辑后的提示词时，暂存的回滚会被正式提交。在提交之前，可以运行 `/redo` 取消回滚，恢复到 `/undo` 之前的对话和文件状态。

```text
/redo
```

终端还提供了默认快捷键：

| 操作 | 命令 | 快捷键 |
| --- | --- | --- |
| 暂存对上一条消息的回滚 | `/undo` | `<leader>u` |
| 取消暂存的回滚 | `/redo` | `<leader>r` |

你也可以选中更早的一条消息，然后选择 **Revert**，暂存一次回滚到该位置的操作。

## 捕获

对于每个模型步骤，OpenCode 会在调用模型之前尝试拍一次快照，并在该步骤被记录为成功或失败时再拍一次。助手消息会记录两次快照之间发生变化的路径。

```text
before model step ── snapshot A
model edits src/api.ts
step finishes ────── snapshot B ── changed: src/api.ts
```

快照捕获会尽力而为。如果任一快照不可用，对话会继续进行，但该步骤的文件改动可能无法恢复。

## 范围

快照覆盖的是 Git worktree 中会话的当前目录。例如，在 `packages/app` 中打开的会话会捕获 `packages/app` 下符合条件的文件，而不会捕获仓库其他位置的改动。

| 内容 | 是否捕获 | 示例 |
| --- | --- | --- |
| 当前目录中已跟踪的文件 | 是 | `packages/app/src/app.tsx` |
| 未被忽略的未跟踪文件，每个不超过 2 MiB | 是 | `packages/app/notes.txt` |
| 被 Git 忽略的文件 | 否 | `packages/app/dist/app.js` |
| 单个大于 2 MiB 的未跟踪文件 | 否 | `packages/app/debug.log` |
| 当前目录之外的文件 | 否 | `packages/server/src/index.ts` |
| Git 元数据和其他副作用 | 否 | 提交、分支、数据库或进程 |

文件系统快照需要 Git 仓库。在 Git 仓库之外，`/undo` 仍可以回滚对话历史，但无法恢复文件。

## 恢复

回滚只会恢复所选对话位置之后、由助手步骤改动的路径。每个路径都会回到第一个被回滚的步骤之前的状态；如果某个文件是这些步骤创建的，并且当时并不存在，则会被删除。

| 时间线 | `src/api.ts` | `src/new.ts` |
| --- | --- | --- |
| 所选位置 | 版本 A | 不存在 |
| 之后的助手步骤 | 版本 B | 已创建 |
| 回滚之后 | 版本 A | 已删除 |

不属于这些步骤的路径不会被改动。受影响路径上的当前编辑可能会被覆盖，因此在继续之前，请检查恢复摘要和 `git diff`。

```sh
git diff --stat
git diff
```

## 存储

OpenCode 将快照存储在本地，位于其数据目录下一个独立的内部 Git 对象数据库中。捕获快照不会创建提交、移动分支，也不会有意修改你仓库的索引。

```sh
# Your repository remains an ordinary dirty worktree after capture.
git status --short
```

快照对象可能包含已跟踪文件和符合条件的未跟踪文件的完整内容。请将 OpenCode 数据目录视为敏感的本地数据。

## 设置

快照默认启用。在[配置](/config#snapshots)中将 `snapshots` 设为 `false`，即可停止后续的文件系统捕获。

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "snapshots": false,
}
```

禁用快照不会删除已经存储的快照。对话回滚仍然可用，但如果没有捕获文件系统状态，就无法恢复相关的文件改动。

## 安全性

快照只是一种便利功能，并不是事务或备份：

- Shell 命令可能会更改服务、进程、网络资源、数据库、Git 状态、被忽略的输出，或当前目录之外的文件。恢复快照无法撤销这些影响。
- 当捕获失败或没有可用的快照对时，中断或失败的工作可能会留下改动。
- 恢复受影响的路径会覆盖其当前内容。取消暂存的回滚也可能覆盖之后的编辑。
- 会话运行期间，OpenCode 会拒绝回滚操作，但外部编辑器和命令仍可能在捕获和恢复之间修改 worktree。
- 提交回滚只会从当前的对话视图中移除消息，而不会从持久化的会话历史或已有的快照存储中删除。这不是安全擦除。

在有未提交改动的 worktree 上使用 `/undo` 之前，请先提交或备份重要的工作。
