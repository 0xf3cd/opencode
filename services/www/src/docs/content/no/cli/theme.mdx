---
title: "Tema"
---

OpenCode leveres med mange innebygde temaer for lys og mørk modus. Velg et i innstillingene, eller sett sammen dine egne farger.

## Velg et tema

Trykk `Ctrl+P`, velg **Open settings**, og åpne deretter **Theme**. Standardtemaet er `opencode`.

Du kan også angi temaet i de globale [CLI-innstillingene](/cli/config):

```json title="~/.config/opencode/cli.json"
{
  "$schema": "https://opencode.ai/v2/cli.json",
  "theme": {
    "name": "tokyonight",
    "mode": "dark"
  }
}
```

Kjør `/themes` for å bytte tema uten å åpne innstillingene.

## Systemfarger

Når OpenCode kan lese terminalpaletten din, inneholder temavelgeren temaet `system`. Det henter fargene fra forgrunnen, bakgrunnen og ANSI-paletten i terminalen din.

Temanavnet `system` velger farger avledet fra terminalen. Modusen `system` følger terminalens lyse eller mørke utseende.

## Modus

Bruk `system` for å følge terminalens utseende, eller lås temaet til lys eller mørk modus:

| Modus | Virkemåte |
| --- | --- |
| `system` | Følger terminalens registrerte lyse eller mørke utseende. |
| `dark` | Bruker alltid temaets mørke farger. |
| `light` | Bruker alltid temaets lyse farger. |

Dette tilsvarer feltet `mode` i `theme` i CLI-konfigurasjonen. Hvis et egendefinert tema bare har én modus, bruker OpenCode den modusen også når den andre blir etterspurt.

## Legge til et tema

Vil du legge til et tema du har lastet ned eller fått fra noen andre, kopierer du JSON-filen til den globale temakatalogen:

```bash
cp theme.json ~/.config/opencode/themes/
```

Du kan også legge temaet i katalogen `.opencode/themes` i et prosjekt, slik at det bare er tilgjengelig i det prosjektet.

Filnavnet blir temanavnet. `my-theme.json` vises for eksempel som `my-theme`. Start OpenCode på nytt etter at du har lagt til filen, og kjør deretter `/themes` for å velge temaet.

OpenCode leser bare `.json`-filer. Et tema som ligger nærmere gjeldende katalog, erstatter et globalt tema eller et tema fra en overordnet katalog med samme navn.

## Bruke temaer i plugins

[CLI-plugins](/build/plugins/cli) leser ferdig oppløste farger gjennom `context.theme` og aktiv modus gjennom `context.themeMode`. Bruk semantiske tokens, slik at pluginen følger det valgte temaet:

```tsx title="Inside a CLI plugin component"
import { usePlugin } from "@opencode/plugin/tui"

function Status() {
  const context = usePlugin()
  return <text fg={context.theme.text.base}>Ready</text>
}
```

Det offentlige API-et for CLI-plugins registrerer ikke temaer. Legg til egendefinerte temadefinisjoner med JSON-filer i katalogene ovenfor.

## Lage et tema

Bruk [temaverktøyet](https://opencode.ai/theme/) vårt for å lage eller redigere temaer. Med verktøyet er det enkelt å forstå strukturen, endre den og definere egne farger. Forklaringen nedenfor er ment som referanse.

Et tema skiller felles semantiske tokens fra paletter for hver modus:

| Seksjon | Formål |
| --- | --- |
| `base` | Det komplette tokentreet som deles av alle moduser. |
| `light`, `dark` | En komplett fargetonepalett og valgfrie tokenoverstyringer for den modusen. |

Hvert tema har en komplett `base` og definerer minst én av `light` og `dark`. Modusene arver fra `base` i filen. De arver ikke fra det innebygde OpenCode-temaet eller fra hverandre.

Eksemplene nedenfor viser bare seksjonene som er relevante for hvert konsept. Bruk temaredigeringsverktøyet til å generere en komplett fil før du tilpasser den.

### Struktur

Legg farger som brukes av begge modusene, i `base`, og overstyr dem i `light` eller `dark` ved behov:

```json title="theme.json (excerpt)"
{
  "$schema": "https://opencode.ai/theme.json",
  "base": {
    "text": {
      "base": "$hue.neutral.200",
      "muted": "$hue.neutral.400"
    }
  },
  "light": {
    "hue": {}
  },
  "dark": {
    "hue": {},
    "text": {
      "muted": "$hue.neutral.300"
    }
  }
}
```

Den komplette `base` gir alle semantiske tokens. Hver modus gir alle påkrevde fargetoner og kan overstyre en hvilken som helst del av tokentreet i `base`.

### Farger og referanser

En farge kan være en heksadesimal verdi, `"transparent"` eller en referanse til en annen farge i temaet:

```json title="Inside base or a mode"
{
  "text": {
    "base": "#eeeeee",
    "muted": "$hue.neutral.400"
  },
  "border": {
    "base": "$text.muted"
  }
}
```

### Fargetoner

Fargetoner er fargeskalaer med ni trinn. Hver modus definerer de åtte grunnleggende fargetonene og tre aliaser:

| Type | Verdier |
| --- | --- |
| Grunntone | `gray`, `red`, `orange`, `yellow`, `green`, `cyan`, `blue`, `purple` |
| Alias | `accent`, `interactive`, `neutral` |
| Trinn | `100`, `200`, `300`, `400`, `500`, `600`, `700`, `800`, `900` |

Definer alle ni trinnene for en grunntone, eller gjør én fargetone til et alias for en annen:

```json title="Inside light or dark"
{
  "hue": {
    "purple": {
      "100": "#b38ff4",
      "200": "#9d7cd8",
      "300": "#8869bd",
      "400": "#7357a2",
      "500": "#5f4688",
      "600": "#4b356f",
      "700": "#392557",
      "800": "#271640",
      "900": "#17072b"
    },
    "accent": "$hue.purple"
  }
}
```

Trinnene følger kontrastretningen til modusen. Lyse temaer går fra mørkt ved `100` til lyst ved `900`, mens mørke temaer går fra lyst ved `100` til mørkt ved `900`.

Matrisen `categorical` i `base` angir de ordnede fargetonene som brukes til å skille agenter og andre gjentatte elementer fra hverandre:

```json title="Inside base"
{
  "categorical": ["accent", "purple", "green", "blue"]
}
```

### Semantiske tokens

Semantiske tokens knytter farger til roller i brukergrensesnittet. Komponentene bruker disse rollene i stedet for å velge farger direkte.

| Gruppe | Formål |
| --- | --- |
| `text` | Grunntekst, dempet tekst og tekst for handlinger, skjemafelt, status og tilbakemeldinger. |
| `background` | Grunnbakgrunn, hevede flater, handlinger, skjemafelt og fyll for tilbakemeldinger. |
| `border`, `scrollbar` | Farger for kantlinjer og rullefelt. |
| `diff` | Farger for tillegg, fjerninger, kontekst, utheving og linjenumre. |
| `syntax` | Syntaksutheving av kildekode. |
| `markdown` | Markdown-elementer. |

`text.muted` styrer for eksempel sekundær tekst, mens `background.raised` definerer flater som er hevet trinnvis høyere:

```json title="Inside base"
{
  "text": {
    "base": "$hue.neutral.200",
    "muted": "$hue.neutral.400"
  },
  "background": {
    "base": "$hue.neutral.800",
    "raised": {
      "base": "$hue.neutral.700",
      "high": "$hue.neutral.600",
      "max": "$hue.neutral.500"
    }
  }
}
```

Nøklene for syntaks er `comment`, `keyword`, `function`, `variable`, `string`, `number`, `type`, `operator` og `punctuation`.

Nøklene for Markdown er `text`, `heading`, `link`, `linkText`, `code`, `blockQuote`, `emphasis`, `strong`, `horizontalRule`, `listItem`, `listEnumeration`, `image`, `imageText` og `codeBlock`.

### Handlinger og tilstander

Handlinger finnes i variantene `primary`, `secondary` og `destructive`. Handlinger og skjemafelt bruker `base` og valgfrie interaksjonstilstander:

```json title="Inside base or a mode"
{
  "text": {
    "action": {
      "primary": {
        "base": "$hue.interactive.400",
        "$hovered": "$hue.interactive.300",
        "$disabled": "$hue.neutral.600"
      }
    }
  }
}
```

Tilstandsnøklene er `$hovered`, `$focused`, `$pressed`, `$selected` og `$disabled`. En tilstand som ikke er angitt, bruker `base`-fargen til handlingen eller skjemafeltet.

### Dialogflate

Paneler, dialoger, menyer og toast-varsler velger dybden sin fra `background.raised`. Dialoger kan i tillegg overstyre semantiske tokens med `@dialog`:

```json title="Inside base or a mode"
{
  "@dialog": {
    "background": {
      "base": "$background.raised.base",
      "action": {
        "primary": {
          "$hovered": "$background.raised.high"
        }
      }
    }
  }
}
```

TUI-en løser opp referansene på nytt etter at `@dialog` er brukt, slik at tokens som viser til `$background.base`, følger bakgrunnen i dialogen. En kontekstuell `base` for en handling blir fallback for tilstandene som ikke er angitt. Eksplisitte overstyringer av tilstander vinner fortsatt.
