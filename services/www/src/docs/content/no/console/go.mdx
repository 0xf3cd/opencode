OpenCode Go gir deg pålitelig tilgang til populære åpne kodemodeller, med to månedlige planer:

| Plan        | Pris           | Inkludert bruk                                     |

| **Go**      | **$10/måned**  | Rimeligere tilgang til modellene nedenfor          |
| **Go Plus** | **$40/måned**  | Høyere bruksgrenser for modellene nedenfor         |

Go fungerer som alle andre leverandører i OpenCode. Du abonnerer på OpenCode Go og får API-nøkkelen din. Det er **helt valgfritt**, og du trenger det ikke for å bruke OpenCode.

Tjenesten er først og fremst laget for internasjonale brukere og gir stabil tilgang over hele verden.

## Slik fungerer det

1. Logg inn på [OpenCode Console](https://opencode.ai/console), abonner på Go eller Go Plus, legg inn faktureringsopplysningene dine og kopier API-nøkkelen.
2. Kjør `/connect` i TUI-en, velg **OpenCode Go** og lim inn API-nøkkelen.

   ```text
   /connect
   ```

3. Kjør `/models` for å velge en modell som er tilgjengelig gjennom Go.

   ```text
   /models
   ```

<Callout>
  Go og Go Plus er for arbeidsområder med ett enkelt medlem, for eksempel **Personal**-arbeidsområdet som opprettes når
  du registrerer deg. Et arbeidsområde med et Go-abonnement kan ikke invitere medlemmer.
</Callout>

## Hvor kan jeg bruke det?

OpenCode Go er laget for [OpenCode](https://opencode.ai) og andre kodeagenter som
sender lignende typer forespørsler. Trafikken overvåkes for misbruk som svekker
opplevelsen for andre brukere.

Klienten din bør:

1. Sende typisk trafikk for en kodeagent.
2. Identifisere seg med sin egen user agent, for eksempel `my-coding-agent/1.0`, i stedet
   for navnet på et generisk SDK- eller HTTP-bibliotek.
3. Sende en stabil økt-ID i `x-opencode-session` for hver samtale, slik at vi kan optimalisere ruting og
   prompt-caching.

### Validerte klienter

I tillegg til OpenCode er følgende klienter validert for å fungere riktig med
OpenCode Go. Vi garanterer likevel ikke at de vil fortsette å fungere i fremtiden.

| Klient            | Støtte for økter                                                                                                                                                                                                                            |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Hermes**        | Bygg som inneholder [PR #101864](https://github.com/NousResearch/hermes-agent/pull/101864), sender headeren på både hoved- og hjelpeforespørsler til OpenCode. Rettelsen ble slått sammen etter v0.21.0; den versjonen alene inneholder den ikke.                 |
| **Claude Code**   | Go gjenkjenner den innebygde økt-headeren. Du trenger ingen wrapper med egendefinert header.                                                                                                                                                                |
| **Codex**         | Go gjenkjenner den innebygde økt-headeren. Noen versjoner og proxyoppsett utelater den fortsatt; behold økt-headeren når du videresender forespørsler.                                                                                                |
| **ZCode**         | Go gjenkjenner den innebygde økt-headeren. [Forespørselen vår om `x-opencode-session`](https://github.com/zai-org/feedback/issues/492) er fortsatt åpen, men det er ikke lenger nødvendig å sende akkurat den headeren.                                   |
| **Pi**            | Nåværende bygg sender øktinformasjon til OpenCode. Oppdater eldre installasjoner.                                                                                                                                                           |
| **jcode**         | Oppdater til **v0.81.6 eller nyere**, som inneholder [rettelsen for økt-headeren](https://github.com/1jehuang/jcode/issues/1167).                                                                                                                     |
| **Kilo Code CLI** | Bygg som inneholder [PR #13752](https://github.com/Kilo-Org/kilocode/pull/13752), gjenoppretter økt-headerne for OpenCode. Rettelsen gjelder CLI-en, ikke VS Code-utvidelsen. Se [issue #13723](https://github.com/Kilo-Org/kilocode/issues/13723). |

| **GitHub Copilot Chat** | Automatisk støtte for økt-headeren er etterspurt i [VS Code issue #334186](https://github.com/microsoft/vscode/issues/334186).                                                                                                                           |
| **Kimi Code**           | Automatisk støtte for økt-headeren er etterspurt i [issue #3506](https://github.com/MoonshotAI/kimi-code/issues/3506).                                                                                                                                   |

### Hvorfor noen modeller har lavere bruk

Med Go varierer den inkluderte månedlige bruken fra modell til modell.

For de fleste modellene får vi dette til gjennom volumrabatter og reservert GPU-kapasitet. Disse besparelsene gir vi videre til deg som høyere månedlig bruk.

For noen modeller har vi ikke hatt mulighet til å forhandle frem rabatt eller drifte dem rimeligere, enten fordi modellen er ny, eller fordi den offentlige prisen allerede er rabattert.

For disse modellene får du fortsatt litt mer enn om du betalte modelleverandørene direkte; derfor er den inkluderte månedlige bruken lavere.

## Bakgrunn

Åpne modeller har blitt virkelig gode. Til kodeoppgaver yter de nå nesten like godt som proprietære modeller. Fordi mange leverandører kan levere dem til konkurransedyktige priser, er de som regel langt billigere.

Det kan likevel være vanskelig å få pålitelig tilgang til dem med lav forsinkelse. Leverandørene varierer i kvalitet og tilgjengelighet.

<Callout type="tip">Vi har testet et utvalg modeller og leverandører som fungerer godt med OpenCode.</Callout>

For å løse dette har vi gjort et par ting:

1. Vi testet et utvalg åpne modeller og snakket med teamene bak dem om hvordan de best kjøres.
2. Vi samarbeidet med noen leverandører for å sikre at modellene ble levert riktig.
3. Vi benchmarket kombinasjonene av modell og leverandør og kom frem til en liste vi trygt kan anbefale.

Både Go og Go Plus gir tilgang til disse modellene; velg planen som passer til hvor mye du bruker dem.

## Mål

Vi laget OpenCode Go for å:

1. Gjøre AI-koding **tilgjengelig** for flere med et rimelig abonnement.
2. Gi **pålitelig** tilgang til de beste åpne kodemodellene.
3. Kuratere modeller som er **testet og benchmarket** for bruk med kodeagenter.
4. Unngå **innlåsing** ved at du også kan bruke en hvilken som helst annen leverandør med OpenCode.
