Sett de vanlige proxy-variablene, og unnta loopback-adresser. OpenCode bruker lokale HTTP-tilkoblinger mellom CLI-en og
bakgrunnstjenesten, så loopback-unntaket er påkrevd når en proxy er konfigurert i CLI-miljøet.

```bash
export HTTP_PROXY=http://proxy.example.com:8080
export HTTPS_PROXY=http://proxy.example.com:8080
export NO_PROXY=localhost,127.0.0.1,::1

opencode
```

`HTTP_PROXY` brukes for HTTP-destinasjoner og `HTTPS_PROXY` for HTTPS-destinasjoner. Selve proxy-URL-en kan bruke
`http://` i begge variablene. `NO_PROXY` er en kommaseparert liste over verter og adresser som skal kobles til direkte.

## Tjeneste

Variabler du eksporterer i skallet, påvirker bare en bakgrunnstjeneste som startes fra det samme skallet. Lagre variablene
i konfigurasjonen for den administrerte tjenesten, slik at senere oppstarter bruker de samme nettverksinnstillingene.

```bash
opencode service set env HTTP_PROXY http://proxy.example.com:8080
opencode service set env HTTPS_PROXY http://proxy.example.com:8080
opencode service set env NO_PROXY localhost,127.0.0.1,::1
opencode service start
```

Når du endrer en administrert miljøvariabel, stoppes tjenesten som kjører. `service start` starter den igjen med det nye
miljøet. Behold `NO_PROXY` også i CLI-skallet hvis det skallet setter en proxy, fordi administrerte tjenestevariabler
gjelder for serverprosessen, ikke for CLI-prosessen.

Fjern en lagret variabel med `service unset env`:

```bash
opencode service unset env HTTPS_PROXY
```

## Autentisering

Hvis proxyen godtar legitimasjon i URL-en, tar du med brukernavn og passord i hver proxy-URL som krever autentisering.
Prosentkod tegn som `@`, `:` og `/` i brukernavnet eller passordet.

```bash
export HTTPS_PROXY='http://user:p%40ssword@proxy.example.com:8080'
```

For bakgrunnstjenesten lagrer du hele URL-en. Verdien lagres i den private tjenestekonfigurasjonen og vises av
`opencode service get env`, så ikke del utdataene derfra.

```bash
opencode service set env HTTPS_PROXY 'http://user:p%40ssword@proxy.example.com:8080'
```

## Sertifikater

Sett `NODE_EXTRA_CA_CERTS` til en PEM-fil når proxyen eller destinasjonen bruker et sertifikat som er signert av en
privat sertifiseringsinstans (CA). De ekstra sertifiseringsinstansene legges til i runtimens tillitslager når prosessen
starter.

```bash
export NODE_EXTRA_CA_CERTS=/etc/company/ca.pem
opencode --standalone
```

Lagre filbanen for bakgrunnstjenesten, og start den deretter på nytt:

```bash
opencode service set env NODE_EXTRA_CA_CERTS /etc/company/ca.pem
opencode service start
```

## Forgrunn

`--standalone` og `serve` bruker miljøet til sin egen prosess. `opencode service set env` konfigurerer ikke disse
prosessene.

```bash
HTTP_PROXY=http://proxy.example.com:8080 \
HTTPS_PROXY=http://proxy.example.com:8080 \
NO_PROXY=localhost,127.0.0.1,::1 \
opencode --standalone
```

Bruk samme mønster for en server i forgrunnen:

```bash
HTTPS_PROXY=http://proxy.example.com:8080 \
NO_PROXY=localhost,127.0.0.1,::1 \
opencode serve
```

## Kontroller

Sjekk at CLI-en når bakgrunnstjenesten etter at du har tatt i bruk innstillingene:

```bash
opencode api get /api/info
```

Et vellykket svar fra helsesjekken bekrefter den lokale tilkoblingen mellom klienten og tjenesten. Kjør en vanlig
forespørsel mot en leverandør for å bekrefte tjenestens utgående proxy og sertifikatoppsett.
