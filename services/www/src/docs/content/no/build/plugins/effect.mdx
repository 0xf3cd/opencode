---
title: "Effect"
---

`@opencode/plugin/effect` er den Effect-native versjonen av OpenCodes plugin-API. Operasjonene i konteksten returnerer
Effects eller Streams, callbacks returnerer Effects, og pluginens levetid representeres av `Scope`.

OpenCode leverer `effect` (inkludert eksporterte `effect/*`-understier) og `@opencode/plugin` under kjøring når plugins
og `node_modules`-avhengighetene deres lastes inn. Installer dem som peer- eller dev-avhengigheter for lokal typesjekking
og testing, i stedet for å pakke dem inn i pluginen.

```sh
bun add --peer @opencode/plugin effect
```

Eksporter en Effect-plugin fra `.opencode/plugins/` for å laste den inn automatisk.

```ts title=".opencode/plugins/concise/index.ts"
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "example",
  effect: (ctx) =>
    Effect.gen(function* () {
      const storage = ctx.storage
      yield* storage.set("loaded", true)
    }),
})
```

Publiserte pakker og plugin-kataloger utenfor `.opencode/plugins/` bruker den samme `plugins`-konfigurasjonen som andre
serverplugins.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": [
    "opencode-acme-effect-plugin",
    "opencode-acme-effect-plugin@1.2.0",
    "@acme/opencode-effect-plugin",
    "./plugins/local-effect",
    {
      "package": "@acme/opencode-effect-plugin",
      "options": { "agent": "reviewer", "strict": true },
    },
  ],
}
```

Se [Konfigurer plugins](/plugins) for aktivering, pakkeoppslag og prioritet i konfigurasjonen.

```ts title="plugins/local-effect/index.ts"
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "local-effect",
  effect: (ctx) =>
    Effect.gen(function* () {
      yield* Effect.logInfo("Effect plugin loaded", { version: ctx.app.version })
    }),
})
```

## Livssyklus

`effect` kjører når pluginen lastes inn. Scopet lukkes når pluginen lastes inn på nytt eller fjernes, så registreringer,
scopede fibers og finalizers frigjøres samtidig.

```ts
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "lifecycle",
  effect: (ctx) =>
    Effect.gen(function* () {
      yield* Effect.logInfo("loaded", { version: ctx.app.version })
      yield* Effect.addFinalizer(() => Effect.logInfo("unloaded"))
    }),
})
```

Bruk scopede fibers til bakgrunnsarbeid. Pluginens scope avbryter fiberen under oppryddingen.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const storage = ctx.storage
    yield* Effect.repeat(
      storage.set("heartbeat", { time: Date.now() }),
      { schedule: Schedule.spaced("1 minute") },
    ).pipe(Effect.forkScoped)
  }),
```

### Kontekst

Konteksten eksponerer Effect-klienten for den tilkoblede OpenCode-serveren, i tillegg til transformasjoner, hooks,
lagring, omlasting og alternativer som bare finnes for plugins. Den eksponerer ikke OpenCodes private Core-tjenester.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const plugins = ctx.plugin
    const active = yield* plugins.list().pipe(Effect.orDie)
    yield* Effect.logInfo("active plugins", { count: active.data.length })
  }),
```

Plugin-definisjonen og hele konteksten er deklarert slik:

```ts

  readonly id: string

```

### Alternativer

Send alternativer med objektformen i `opencode.json(c)`.

```jsonc title="opencode.jsonc"
{
  "plugins": [
    {
      "package": "./plugins/company-effect",
      "options": { "strict": true },
    },
  ],
}
```

Les alternativene fra `ctx.options`. Snevre inn ukjente verdier før du bruker dem.

```ts title="plugins/company-effect/index.ts"
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "company",
  effect: (ctx) =>
    Effect.gen(function* () {
      const strict = ctx.options.strict === true
      yield* Effect.logInfo("company plugin configured", { strict })
    }),
})
```

## Transformasjoner

Transformasjoner redigerer tilstand synkront gjennom en editor. OpenCode bruker transformasjonene i
registreringsrekkefølge innenfor hvert domene. Kilder bidrar først med leverandører og uforanderlige modelldefinisjoner;
deretter redigerer modelltransformasjoner kandidatene til de aktive leverandørene. Når du yielder registreringen, holdes
den i pluginens scope.

```ts title="plugins/models-effect/index.ts"
import { Model, Plugin, Provider } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "company.models",
  effect: (ctx) =>
    Effect.gen(function* () {
      const providerID = Provider.ID.make("acme")
      const models = [{ ...Model.Info.default(providerID, Model.ID.make("reasoner")), name: "Acme Reasoner" }]
      yield* ctx.provider.transform((editor) => {
        editor.add({
          info: {
            ...Provider.Info.empty(providerID),
            name: "Acme",
            activation: "enabled",
            package: "@opencode/ai/providers/openai-compatible",
            settings: { baseURL: "http://127.0.0.1:8000/v1" },
          },
          models,
        })
      })
    }),
})
```

En modelltransformasjon kan håndheve en policy på tvers av hele samlingen av kandidater fra aktive leverandører.

```ts title="plugins/model-budget-effect/index.ts"
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.model.transform((editor) => {
      editor
        .list()
        .filter((model) => model.cost.some((tier) => tier.output > 20))
        .forEach((model) => {
          editor.remove(model.providerID, model.id)
        })
    })
  }),
```

Kall `reload` når ekstern tilstand som en transformasjon bruker, endres. Her returnerer `loadFromSource()` oppføringer av
typen `{ info: Provider.Info, models: readonly Model.Info[] }`; omlasting av leverandører ugyldiggjør også hele
modellresultatet.

```ts title="plugins/models-effect/index.ts"
effect: (ctx) =>
  Effect.gen(function* () {
    const provider = ctx.provider
    const source = { providers: yield* loadFromSource() }

    yield* provider.transform((editor) => {
      source.providers.forEach((provider) => editor.add(provider))
    })

    yield* Effect.repeat(
      Effect.gen(function* () {
        source.providers = yield* loadFromSource()
        yield* provider.reload()
      }),
      { schedule: Schedule.spaced("1 minute") },
    ).pipe(Effect.forkScoped)
  }),
```

## API

### Agent

Les alle agenter, eller hent én etter ID. Klientsvarene inneholder den oppløste location-verdien og schema-data.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const agent = ctx.agent
    const agents = yield* agent.list().pipe(Effect.orDie)
    const build = yield* agent.get({ agentID: Agent.ID.make("build") }).pipe(Effect.orDie)
    yield* Effect.logInfo("agents", { count: agents.data.length, build: build.data.name })
  }),
```

Transformer agenter eller last dem inn på nytt.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const agent = ctx.agent
    yield* agent.transform((editor) => {
      editor.default("build")
      editor.update("build", (item) => (item.description = "Builds features and fixes bugs"))
      editor.remove("legacy")
    })
    yield* agent.reload()
  }),
```

Schema: [`Agent.Info`](/api#schema-Agent.Info).

```ts
interface AgentEditor {
  list(): readonly Types.DeepMutable<Agent.Info>[]
  get(id: string): Types.DeepMutable<Agent.Info> | undefined
  default(id: string | undefined): void
  update(id: string, update: (agent: Types.DeepMutable<Agent.Info>) => void): void
  remove(id: string): void
}

interface AgentDomain extends AgentApi<unknown> {
  readonly transform: Transform<AgentEditor>
  readonly reload: () => Effect.Effect<void>
}
```

### Leverandører

Les tilgjengelige leverandører, eller se metadataene til én leverandør etter ID.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const provider = ctx.provider
    const providers = yield* provider.list().pipe(Effect.orDie)
    const anthropic = yield* provider.get({ providerID: Provider.ID.make("anthropic") }).pipe(Effect.orDie)
    yield* Effect.logInfo("providers", {
      providers: providers.data.length,
      anthropic: anthropic.data.name,
    })
  }),
```

Leverandørtransformasjoner redigerer leverandørinnstillinger og kildedefinisjoner. Lesing i editoren inkluderer inaktive
leverandører og gir uforanderlige definisjoner; `models.update` redigerer en egen kopi av en kildemodell.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.provider.transform((editor) => {
      editor.update("anthropic", (provider) => {
        provider.headers = { ...provider.headers, "x-company": "engineering" }
      })
      editor.models.update("anthropic", "claude-sonnet-4-5", (model) => (model.name = "Team Sonnet"))
      editor.models.remove("anthropic", "legacy-model")
      editor.remove("legacy-provider")
    })
  }),
```

Erstatt en kildes modelloversikt med `models.set`, og last inn på nytt når definisjonene den har fanget, endres.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const provider = ctx.provider
    const source = { models: yield* loadModels() }
    yield* provider.transform((editor) => editor.models.set("acme", source.models))
    source.models = yield* loadModels()
    yield* provider.reload()
  }),
```

For kontospesifikk oppdagelse sender du tilkoblingen som ble brukt til å laste inn oversikten, som `sourceConnection`.
OpenCode utelater den leverandøren mens en annen tilkobling er valgt, helt til pluginen din publiserer den oppdaterte
oversikten.

```ts
const connection = yield * ctx.integration.connection.active("acme")
if (!connection) return
const inventory = yield * loadInventory(connection)
yield *
  ctx.provider.transform((editor) => {
    editor.add({ info: inventory.provider, models: inventory.models, sourceConnection: connection })
  })
```

Schemaer: [`Provider.Info`](/api#schema-Provider.Info), [`Model.Info`](/api#schema-Model.Info).

```ts
interface ProviderRecord {
  readonly provider: Provider.Info
  readonly models: ReadonlyMap<string, Model.Info>
  readonly sourceConnection?: ConnectionInfo
}

interface ProviderEditor {
  list(): readonly ProviderRecord[]
  get(providerID: string): ProviderRecord | undefined
  add(input: { info: Provider.Info; models: readonly Model.Info[]; sourceConnection?: ConnectionInfo }): void
  update(providerID: string, update: (provider: Types.DeepMutable<Provider.Info>) => void): void
  remove(providerID: string): void
  readonly models: {
    set(providerID: string, models: readonly Model.Info[]): void
    update(providerID: string, modelID: string, update: (model: Types.DeepMutable<Model.Info>) => void): void
    remove(providerID: string, modelID: string): void
  }
}

interface ProviderDomain extends ProviderApi<unknown> {
  readonly transform: Transform<ProviderEditor>
  readonly reload: () => Effect.Effect<void>
}
```

### Modeller

Les tilgjengelige modeller og standardvalget.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const model = ctx.model
    const models = yield* model.list().pipe(Effect.orDie)
    const selected = yield* model.default().pipe(Effect.orDie)
    yield* Effect.logInfo("models", { count: models.data.length, selected: selected.data?.name })
  }),
```

Modelltransformasjoner redigerer hele samlingen av kandidater fra aktive leverandører. Deaktiverte kandidater kan
redigeres til alle transformasjonene er ferdige; `update` kan bare legge til en modell under en tilgjengelig leverandør.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.model.transform((editor) => {
      editor.list("anthropic").forEach((model) => {
        editor.update(model.providerID, model.id, (draft) => {
          draft.enabled = draft.capabilities.tools
        })
      })
      editor.default.set("anthropic", "claude-sonnet-4-5")
      editor.remove("anthropic", "legacy-model")
    })
  }),
```

Callbackene redigerer rå modelloverstyringer. Leverandørens standardverdier flettes inn én gang når OpenCode lagrer
resultatet; uendrede lesinger gjenbruker det resultatet. `editor.provider` leser uforanderlige kildedefinisjoner,
inkludert inaktive maler, ikke utdata fra modelltransformasjoner.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const model = ctx.model
    yield* model.transform((editor) => {
      const source = editor.provider.get("anthropic")?.models.get("claude-sonnet-4-5")
      if (!source) return
      editor.update("anthropic", source.id, (draft) => {
        draft.limit.context = Math.min(draft.limit.context, source.limit.context)
      })
    })
    yield* model.reload()
  }),
```

Schema: [`Model.Info`](/api#schema-Model.Info).

```ts
interface ModelEditor {
  list(providerID?: string): readonly Types.DeepMutable<Model.Info>[]
  get(providerID: string, modelID: string): Types.DeepMutable<Model.Info> | undefined
  update(providerID: string, modelID: string, update: (model: Types.DeepMutable<Model.Info>) => void): void
  remove(providerID: string, modelID: string): void
  readonly default: {
    get(): { providerID: string; modelID: string } | undefined
    set(providerID: string, modelID: string): void
  }
  readonly provider: {
    list(): readonly ProviderRecord[]
    get(providerID: string): ProviderRecord | undefined
  }
}

interface ModelDomain extends ModelApi<unknown> {
  readonly transform: Transform<ModelEditor>
  readonly reload: () => Effect.Effect<void>
}
```

### Kommandoer

Les kommandoene som er tilgjengelige på gjeldende location.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const command = ctx.command
    const commands = yield* command.list().pipe(Effect.orDie)
    yield* Effect.logInfo("commands", { names: commands.data.map((item) => item.name) })
  }),
```

Kommandotransformasjonen kan foreløpig bare legge til. En executor mottar økten, prompt-vedleggene og leveringsmodusen.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const command = ctx.command
    const session = ctx.session
    yield* command.transform((editor) => {
      editor.add({
        name: "security-review",
        description: "Review changes for security issues",
        execute: (input) =>
          session.prompt({
            ...input.prompt,
            sessionID: input.sessionID,
            text: `Review these changes for security issues.\n\n${input.prompt.text}`,
            delivery: input.delivery,
          }).pipe(Effect.asVoid),
      })
    })
    yield* command.reload()
  }),
```

Schemaer: [`Command.Info`](/api#schema-Command.Info),
[`Session.Inbox.Delivery`](/api#schema-Session.Inbox.Delivery).

```ts

```

### Integrasjoner

Les integrasjoner, og hent den aktive legitimasjonen når den finnes.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const integration = ctx.integration
    const integrations = yield* integration.list().pipe(Effect.orDie)
    const github = yield* integration.get({ integrationID: Integration.ID.make("github") }).pipe(Effect.orDie)
    const connection = yield* integration.connection.active("github")
    const credential = connection ? yield* integration.connection.resolve(connection).pipe(Effect.orDie) : undefined
    yield* Effect.logInfo("integration", {
      count: integrations.data.length,
      github: github.data.name,
      credential: credential?.type,
    })
  }),
```

Koble til med en nøkkel, eller kjør et OAuth-forsøk gjennom det tilkoblede API-et.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const integration = ctx.integration
    const token = yield* Config.Redacted("GITHUB_TOKEN").pipe(Effect.orDie)
    yield* integration.connect
      .key({ integrationID: Integration.ID.make("github"), key: Redacted.value(token) })
      .pipe(Effect.orDie)

    const attempt = yield* integration.oauth
      .connect({
        integrationID: Integration.ID.make("acme"),
        methodID: Integration.MethodID.make("oauth"),
      })
      .pipe(Effect.orDie)
    const status = yield* integration.oauth
      .status({
        integrationID: Integration.ID.make("acme"),
        attemptID: attempt.data.attemptID,
      })
      .pipe(Effect.orDie)
    yield* Effect.logInfo("OAuth status", { status: status.data })
  }),
```

Transformer integrasjoner og autentiseringsmetoder. Callbacks for OAuth-metoder er Effects og kan skaffe scopede
ressurser.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const integration = ctx.integration
    yield* integration.transform((editor) => {
      editor.update("acme", (item) => (item.name = "Acme"))
      editor.method.update({
        integrationID: "acme",
        method: { id: "device", type: "oauth", label: "Sign in with Acme" },
        authorize: () =>
          Effect.succeed({
            mode: "code",
            url: "https://acme.example/device",
            instructions: "Enter the displayed code",
            callback: (code) => exchangeCode(code),
          }),
      })
    })
    yield* integration.reload()
  }),
```

Schemaer: [`Integration.Info`](/api#schema-Integration.Info), [`Integration.Method`](/api#schema-Integration.Method),
[`Connection.Info`](/api#schema-Connection.Info), [`Form.Answer`](/api#schema-Form.Answer).

```ts

  readonly url: string
  readonly instructions: string

} & (

)

  readonly integrationID: string
  readonly method: IntegrationOAuthMethod

  get(id: string): IntegrationRef | undefined

  readonly transform: Transform<IntegrationEditor>

  }
}
```

### MCP

List opp MCP-servere og den gjeldende tilkoblingsstatusen deres.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const mcp = ctx.mcp
    const servers = yield* mcp.list().pipe(Effect.orDie)
    yield* Effect.logInfo("MCP servers", { count: servers.data.length })
  }),
```

Plugins administrerer MCP-servere bare gjennom transformasjoner. Bruk `editor.set` for å legge til eller erstatte en
server, `editor.update` for å endre konfigurasjonen og `editor.remove` for å fjerne den. Se konfigurasjonen med
`editor.list` og `editor.get`.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const mcp = ctx.mcp
    yield* mcp.transform((editor) => {
      const servers = editor.list()
      const docs = editor.get("docs")
      editor.set("docs", { type: "remote", url: "https://mcp.example.com" })
      editor.update("docs", (server) => (server.disabled = false))
      editor.remove("legacy")
    })
  }),
```

Sett `disabled: true` i en transformasjon for å deaktivere en server og koble den fra, eller `disabled: false` for å
aktivere den og la OpenCode koble til. OpenCode avstemmer serverens livssyklus ut fra den transformerte konfigurasjonen.

Kall `reload()` når ekstern tilstand som en transformasjon bruker, endres, for å bruke transformasjonene på nytt og
avstemme serverne.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const mcp = ctx.mcp
    yield* mcp.reload()
  }),
```

Schemaer: [`Mcp.Server`](/api#schema-Mcp.Server), [`Mcp.LocalConfigEncoded`](/api#schema-Mcp.LocalConfigEncoded),
[`Mcp.RemoteConfigEncoded`](/api#schema-Mcp.RemoteConfigEncoded).

```ts
  update(name: string, update: (config: Types.DeepMutable<Mcp.ServerConfig>) => void): void
  remove(name: string): void
}

  readonly transform: Transform<MCPEditor>

```

### Plugins

List opp aktive, mislykkede og oppløste plugins på gjeldende location.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const plugin = ctx.plugin
    const plugins = yield* plugin.list().pipe(Effect.orDie)
    yield* Effect.forEach(plugins.data, (item) => Effect.logInfo("plugin", item), { discard: true })
  }),
```

Filtrer schema-verdiene i en Effect-pipeline når bare aktive plugins er relevante.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const plugin = ctx.plugin
    const active = yield* plugin.list().pipe(
      Effect.orDie,
      Effect.map((result) => result.data.filter((item) => item.status === "active")),
    )
    yield* Effect.logInfo("active plugin count", { count: active.length })
  }),
```

Schemaer: [`Plugin.Info`](/api#schema-Plugin.Info), [`Plugin.Source`](/api#schema-Plugin.Source).

```ts
interface PluginApi<E = never> {

  readonly plugin: PluginApi<unknown>

```

### Referanser

Les referansene som er tilgjengelige på gjeldende location.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const reference = ctx.reference
    const references = yield* reference.list().pipe(Effect.orDie)
    yield* Effect.logInfo("references", { count: references.data.length })
  }),
```

Legg til eller fjern lokale referanser og Git-referanser, og last inn på nytt når ekstern tilstand endres. `get(name)`
returnerer den gjeldende konfigurerte kilden, eller `undefined` når navnet ikke finnes.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const reference = ctx.reference
    yield* reference.transform((editor) => {
      editor.add("handbook", { type: "local", path: "/workspace/docs/handbook" })
      editor.add("standards", { type: "git", repository: "https://github.com/acme/standards", branch: "main" })
      const handbook = editor.get("handbook")
      editor.remove("legacy")
    })
    yield* reference.reload()
  }),
```

### Verktøy

Registrer typede verktøy med Effect `Schema`. Executoren mottar dekodet input og returnerer en Effect med typet output,
visningsinnhold eller metadata.

Editoren støtter `add`, `update` og `remove`. Transformasjonscallbacken er synkron: Den må ikke returnere en Effect eller
en Promise. Last inn eksterne data før du registrerer eller laster inn på nytt. OpenCode spiller av de aktive
transformasjonene i registreringsrekkefølge på en ny editor; for samme effektive verktøynavn overstyrer en senere gyldig
registrering en tidligere.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const tool = ctx.tool
    yield* tool.transform((editor) => {
      editor.namespace({
        name: "acme",
        description: "Customer account tools",
      })
      editor.add({
        name: "greeting",
        description: "Create a greeting",
        input: Schema.Struct({ name: Schema.String }),
        output: Schema.Struct({ greeting: Schema.String }),
        options: { namespace: "acme", codemode: true },
        execute: ({ name }, context) =>
          Effect.gen(function* () {
            yield* context.progress({ status: "greeting" })
            return { output: { greeting: `Hello ${name}!` } }
          }),
      })
    })
  }),
```

Kall `yield* ctx.tool.reload()` etter at du har endret kildedata som callbacken har fanget. Omlasting spiller av de
aktive transformasjonene uten å endre rekkefølgen; den kjører ikke plugin-effecten på nytt.

Verktøy har en `id` som inneholder det effektive navnet, og `get()` returnerer `undefined` når den ID-en ikke finnes.
Bruk `update` og `remove` med det effektive verktøynavnet, inkludert navnerommet (`acme_greeting` over). Punktum i
navnerom og tegn som ikke støttes i verktøynavn, blir til `_`. Navn som mangler, ignoreres; for å opprette et verktøy
trenger du `add` med en fullstendig definisjon. Oppdateringer beholder navnet og navnerommet. Tilordne nye schemaer eller
alternativer for å erstatte dem, i stedet for å endre nestede verdier. Ugyldige oppdateringer logges, og den forrige
definisjonen beholdes uendret.

```ts
yield *
  ctx.tool.transform((editor) => {
    editor.update("acme_greeting", (tool) => {
      tool.description = "Greet the user by name"
    })
    editor.remove("acme_obsolete")
  })
```

Oppdateringer og fjerninger spilles av i rekkefølge sammen med tillegg, også etter at MCP-katalogen er oppdatert.

`transform` returnerer en scopet registrering. Kjør `yield* registration.dispose` for å fjerne transformasjonen og bygge
på nytt fra de gjenværende transformasjonene, slik at en eventuell tidligere definisjon den overstyrte, blir synlig igjen.
Dispose er idempotent, og når pluginens scope lukkes, frigjøres også registreringene.

Hver modellforespørsel fanger et snapshot av verktøyene. Omlasting og dispose påvirker fremtidige snapshots, ikke
definisjonene eller executorene som en eksisterende forespørsel allerede har fanget. Executorer som lukker over
foranderlige plugin-data, ser fortsatt endringer i disse dataene; fang en verdi inne i transformasjonen når den må
forbli knyttet til den definisjonen.

Schemaer: [`Tool.Content`](/api#schema-Tool.Content), [`Tool.TextContent`](/api#schema-Tool.TextContent),
[`Tool.FileContent`](/api#schema-Tool.FileContent).

## Hooks

Hooks fanger opp operasjoner mens de pågår. Flere plugins kan registrere samme hook; OpenCode kjører dem i
plugin-rekkefølge, slik at senere hooks ser tidligere endringer. Registreringene er aktive så lenge pluginens scope er
åpent.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook("context", () => Effect.void)
  }),
```

### Økter

Endre de sammensatte systeminstruksjonene, meldingene eller verktøyene rett før forespørselen sendes til modellen.
`context` kjører for agentløkken; `compaction`, `generate` og `title` kjører for de tilhørende hjelpeforespørslene.
`compaction` og `title` godtar et `result` som hopper over modellkallet.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook("context", (event) =>
      Effect.sync(() => {
        event.system.push({ type: "text", text: "Keep the review focused on correctness." })
        delete event.tools.write
      }),
    )
    yield* session.hook("compaction", (event) =>
      Effect.map(summarize(event.messages), (summary) => {
        event.result = { summary }
      }),
    )
  }),
```

Endre innstillingene for modellforespørselen, og begrens eventuelt hooken til én leverandør. Hendelsen har samme `kind`
som HTTP-hookene nedenfor.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook(
      "model.request",
      (event) => Effect.sync(() => (event.headers["x-plugin"] = "review")),
      { providerID: "anthropic" },
    )
  }),
```

Endre native forespørsler til eller svar fra leverandøren. Kroppene er strømmer som bare kan leses én gang; klon eller
erstatt en kropp før du leser den. Begge hookene kjører for hver forespørsel en økt sender; `event.kind` er `"primary"`,
`"compaction"`, `"title"` eller `"generate"`, avhengig av hvilken flyt som sendte den.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook("http.request", (event) =>
      Effect.sync(() => {
        event.request.headers.set("x-session-id", event.sessionID)
        if (event.kind === "title") event.request.headers.set("x-priority", "background")
      }),
    )
    yield* session.hook("http.response", (event) =>
      Effect.sync(() => {
        event.response = new Response(event.response.body, {
          status: event.response.status,
          headers: { ...Object.fromEntries(event.response.headers), "x-plugin": "review" },
        })
      }),
    )
  }),
```

Leverandører som strømmer over en WebSocket, gjenbruker én tilkobling per økt, så HTTP-hookene ser aldri den trafikken.
Den eksperimentelle hooken `experimental.ws.handshake` kjører én gang per modellkall før tilkoblingen velges, og
eksponerer tilkoblingens `url` og `headers`; endrer du en av dem, åpnes socketen på nytt. HTTP-hooks kjører fortsatt for
alle forespørsler som en WebSocket-rute faller tilbake på.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.session.hook(
      "experimental.ws.handshake",
      (event) =>
        Effect.gen(function* () {
          event.headers.authorization = `Bearer ${yield* mintToken(event.url)}`
          delete event.headers["api-key"]
        }),
      { providerID: "azure" },
    )
  }),
```

`experimental.ws.send` og `experimental.ws.receive` eksponerer selve rammene: `send` kjører etter at leverandørdriveren
har bygget en utgående ramme, og `receive` kjører på hver innkommende ramme før driveren ser den. Det `frame` inneholder
når hooken returnerer, er det som sendes over linjen eller når driveren; OpenCode validerer det ikke.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.session.hook(
      "experimental.ws.send",
      (event) =>
        Effect.sync(() => {
          const body = JSON.parse(event.frame)
          if (body.type === "response.create") body.metadata = { ...body.metadata, session: event.sessionID }
          event.frame = JSON.stringify(body)
        }),
      { providerID: "openai" },
    )
  }),
```

Overstyr beslutningen om nye forsøk for en leverandørfeil, eller erstatt ventetiden i millisekunder. Hooken kjører etter
at OpenCode har klassifisert feilen og foreslått en policy, men før et nytt forsøk planlegges. Den eksponerer ikke
hvordan OpenCode internt utfører neste forsøk.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.session.hook("retry", (event) =>
      Effect.sync(() => {
        if (event.error.status === 429) {
          event.decision = { retry: true, delay: 10_000 }
          return
        }
        if (event.error.type === "provider.invalid-request" && event.attempt === 2) {
          event.decision = { retry: true, delay: 0 }
          return
        }
        if (event.attempt >= 3) event.decision = { retry: false }
      }),
    )
  }),
```

Den første `decision` er OpenCodes policy, så hooks kan gjøre en leverandørfeil som normalt er endelig, mulig å prøve på
nytt, eller nedlegge veto mot et foreslått nytt forsøk. Flere hooks kjører i registreringsrekkefølge, og senere hooks ser
den gjeldende beslutningen. Det innebygde maksimale antallet forsøk er fortsatt en absolutt grense. `attempt` er det
fysiske forsøket som foreslås; den første forespørselen er forsøk `1`, så det første nye forsøket er forsøk `2`.
Ugyldige ventetider (`NaN`, uendelig eller negative verdier) faller tilbake på den beregnede ventetiden. Gjenoppretting
etter kontekstoverflyt holdes atskilt, fordi den komprimerer samtalen i stedet for å prøve den samme forespørselen på
nytt.

#### Referanse

```ts
interface ToolHooks {
  readonly "execute.before": ToolExecuteBefore
  readonly "execute.after": ToolExecuteAfter
}

interface ToolFailures extends Record<keyof ToolHooks, unknown> {
  readonly "execute.before": Tool.Error
  readonly "execute.after": never
}

interface ToolHookDomain {
  readonly hook: Hooks<ToolHooks, ToolFailures>
}
```

De delte registreringstypene viser hvilke operasjoner som krever pluginens scope.

```ts
interface Registration {
  readonly dispose: Effect.Effect<void>
}

type Hooks<Spec, Failures extends Record<keyof Spec, unknown> = Record<keyof Spec, never>> = <Name extends keyof Spec>(
  name: Name,
  callback: (input: Spec[Name]) => Effect.Effect<void, Failures[Name]>,
) => Effect.Effect<Registration, never, Scope.Scope>

type Transform<Input> = (callback: (input: Input) => void) => Effect.Effect<Registration, never, Scope.Scope>
```

## Publiser

En pakkeplugin bruker samme standardeksport som en lokal Effect-plugin. Eksporter Effect-implementasjonen fra
hovedinngangspunktet, og deklarer `effect` som en `peerDependency`.

```json title="package.json"
{
  "name": "opencode-acme-effect-plugin",
  "version": "1.0.0",
  "type": "module",
  "exports": {
    ".": "./src/index.ts"
  },
  "dependencies": {
    "@opencode/plugin": "latest"
  },
  "peerDependencies": {
    "effect": "^4.0.0"
  }
}
```

OpenCode omdirigerer importer av `effect`, eksporterte `effect/*`-understier og `@opencode/plugin` (også importer fra
avhengigheter i pluginens `node_modules`) til vertens runtime-instanser, slik at fibers, loggere og `Schema`-parsere
deler én runtime-kopi.

- Ikke pakk `effect` inn i den publiserte plugin-artefakten. Hvis du bygger med en bundler, merker du `effect` og
  `effect/*` som eksterne.
- Plugins og `node_modules`-avhengighetene deres kjører alltid mot `effect`-instansen i vertens OpenCode-versjon. Bruk
  `effect`-API-er og modulstier som er kompatible med OpenCode-versjonen du sikter mot; avhengigheter som er bygget på en
  annen hovedversjon av `effect` (for eksempel Effect 3), får også vertens `effect` og støttes ikke.
- Bare offentlige `effect`-understier leveres. En plugin som importerer en av Effects private `internal`-moduler, kan
  ikke lastes inn og gir en feil som oppgir stien.
- Den kompilerte OpenCode-binærfilen inneholder ikke Scalar- og Swagger UI-ressursene som brukes av Effects
  dokumentasjonssider for HTTP-API; serverer en plugin disse sidene, vises en melding i stedet.

Pakkens inngangspunkt eksporterer `Plugin.define` med en `effect`-funksjon.

```ts title="src/index.ts"
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "acme.published",
  effect: (ctx) =>
    Effect.gen(function* () {
      const storage = ctx.storage
      yield* storage.set("installed", true)
    }),
})
```

Bruk versjoner som er kompatible med OpenCode-versjonen du sikter mot, og test den installerte pakken, ikke bare en kopi
som er lenket inn i workspacet.

```sh
bun pm pack
bun add ./opencode-acme-effect-plugin-1.0.0.tgz
```
