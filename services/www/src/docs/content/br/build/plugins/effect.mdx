---
title: "Effect"
---

`@opencode/plugin/effect` é a versão nativa em Effect da API de plugins do OpenCode. As operações do contexto retornam
Effects ou Streams, os callbacks retornam Effects e o ciclo de vida do plugin é representado por um `Scope`.

Ao carregar plugins e as dependências deles em `node_modules`, o OpenCode fornece `effect` (incluindo os subcaminhos
exportados `effect/*`) e `@opencode/plugin` em tempo de execução. Instale esses pacotes como dependências peer/dev para
checagem de tipos e testes locais, em vez de empacotá-los no seu plugin.

```sh
bun add --peer @opencode/plugin effect
```

Exporte um plugin Effect a partir de `.opencode/plugins/` para que ele seja carregado automaticamente.

```ts title=".opencode/plugins/concise/index.ts"
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "example",
  effect: (ctx) =>
    Effect.gen(function* () {
      const storage = ctx.storage
      yield* storage.set("loaded", true)
    }),
})
```

Pacotes publicados e diretórios de plugin fora de `.opencode/plugins/` usam a mesma configuração `plugins` dos demais
plugins de servidor.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": [
    "opencode-acme-effect-plugin",
    "opencode-acme-effect-plugin@1.2.0",
    "@acme/opencode-effect-plugin",
    "./plugins/local-effect",
    {
      "package": "@acme/opencode-effect-plugin",
      "options": { "agent": "reviewer", "strict": true },
    },
  ],
}
```

Consulte [Configurar plugins](/plugins) para saber sobre ativação, resolução de pacotes e precedência de configuração.

```ts title="plugins/local-effect/index.ts"
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "local-effect",
  effect: (ctx) =>
    Effect.gen(function* () {
      yield* Effect.logInfo("Effect plugin loaded", { version: ctx.app.version })
    }),
})
```

## Ciclo de vida

O `effect` é executado quando o plugin é carregado. O escopo dele é fechado quando o plugin é recarregado ou
descarregado, então registros, fibers com escopo e finalizadores são liberados juntos.

```ts
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "lifecycle",
  effect: (ctx) =>
    Effect.gen(function* () {
      yield* Effect.logInfo("loaded", { version: ctx.app.version })
      yield* Effect.addFinalizer(() => Effect.logInfo("unloaded"))
    }),
})
```

Use fibers com escopo para trabalho em segundo plano. O escopo do plugin interrompe a fiber durante a limpeza.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const storage = ctx.storage
    yield* Effect.repeat(
      storage.set("heartbeat", { time: Date.now() }),
      { schedule: Schedule.spaced("1 minute") },
    ).pipe(Effect.forkScoped)
  }),
```

### Contexto

O contexto expõe o cliente Effect do servidor OpenCode conectado, além de transformações, hooks, armazenamento,
recarregamentos e opções exclusivos de plugins. Ele não expõe os serviços privados do Core do OpenCode.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const plugins = ctx.plugin
    const active = yield* plugins.list().pipe(Effect.orDie)
    yield* Effect.logInfo("active plugins", { count: active.data.length })
  }),
```

A definição do plugin e o contexto completo são declarados assim:

```ts
interface Context {
  readonly app: App
  readonly location: Location.Info
  readonly options: PluginOptions
  readonly agent: AgentDomain
  readonly aisdk: AISDKDomain
  readonly command: CommandDomain
  readonly event: EventDomain
  readonly experimental: {
    readonly terminal: Pick<ExperimentalApi<unknown>["persistentPty"], "read">
  }
  readonly integration: IntegrationDomain
  readonly mcp: MCPDomain
  readonly model: ModelDomain
  readonly generate: GenerateApi<unknown>
  readonly permission: PermissionDomain
  readonly plugin: Pick<PluginApi<unknown>, "list">
  readonly provider: ProviderDomain
  readonly reference: ReferenceDomain
  readonly rpc: RpcDomain
  readonly session: SessionDomain
  readonly shell: ShellDomain
  readonly skill: SkillDomain
  readonly storage: StorageDomain
  readonly tool: ToolDomain
  readonly vcs: VcsDomain
  readonly websearch: WebSearchDomain
  readonly worktree: WorktreeDomain
}

interface Plugin<R = Scope.Scope> {
  readonly id: string
  readonly effect: (context: Context) => Effect.Effect<void, never, R>
}
```

### Opções

Passe opções usando a forma de objeto em `opencode.json(c)`.

```jsonc title="opencode.jsonc"
{
  "plugins": [
    {
      "package": "./plugins/company-effect",
      "options": { "strict": true },
    },
  ],
}
```

Leia as opções em `ctx.options`. Restrinja o tipo dos valores desconhecidos antes de usá-los.

```ts title="plugins/company-effect/index.ts"
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "company",
  effect: (ctx) =>
    Effect.gen(function* () {
      const strict = ctx.options.strict === true
      yield* Effect.logInfo("company plugin configured", { strict })
    }),
})
```

## Transformações

As transformações editam o estado de forma síncrona por meio de um editor. Em cada domínio, o OpenCode aplica as
transformações na ordem de registro. Primeiro, as fontes contribuem com provedores e definições imutáveis de modelos;
depois, as transformações de modelo editam os candidatos dos provedores ativos. Fazer `yield` do registro o mantém no
escopo do plugin.

```ts title="plugins/models-effect/index.ts"
import { Model, Plugin, Provider } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "company.models",
  effect: (ctx) =>
    Effect.gen(function* () {
      const providerID = Provider.ID.make("acme")
      const models = [{ ...Model.Info.default(providerID, Model.ID.make("reasoner")), name: "Acme Reasoner" }]
      yield* ctx.provider.transform((editor) => {
        editor.add({
          info: {
            ...Provider.Info.empty(providerID),
            name: "Acme",
            activation: "enabled",
            package: "@opencode/ai/providers/openai-compatible",
            settings: { baseURL: "http://127.0.0.1:8000/v1" },
          },
          models,
        })
      })
    }),
})
```

Uma transformação de modelo pode aplicar uma política a toda a coleção de candidatos dos provedores ativos.

```ts title="plugins/model-budget-effect/index.ts"
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.model.transform((editor) => {
      editor
        .list()
        .filter((model) => model.cost.some((tier) => tier.output > 20))
        .forEach((model) => {
          editor.remove(model.providerID, model.id)
        })
    })
  }),
```

Chame `reload` quando um estado externo usado por uma transformação mudar. Aqui, `loadFromSource()` retorna entradas
`{ info: Provider.Info, models: readonly Model.Info[] }`; recarregar provedores também invalida todo o resultado dos
modelos.

```ts title="plugins/models-effect/index.ts"
effect: (ctx) =>
  Effect.gen(function* () {
    const provider = ctx.provider
    const source = { providers: yield* loadFromSource() }

    yield* provider.transform((editor) => {
      source.providers.forEach((provider) => editor.add(provider))
    })

    yield* Effect.repeat(
      Effect.gen(function* () {
        source.providers = yield* loadFromSource()
        yield* provider.reload()
      }),
      { schedule: Schedule.spaced("1 minute") },
    ).pipe(Effect.forkScoped)
  }),
```

## API

### Agente

Leia todos os agentes ou busque um pelo ID. As respostas do cliente incluem a localização resolvida e os dados do schema.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const agent = ctx.agent
    const agents = yield* agent.list().pipe(Effect.orDie)
    const build = yield* agent.get({ agentID: Agent.ID.make("build") }).pipe(Effect.orDie)
    yield* Effect.logInfo("agents", { count: agents.data.length, build: build.data.name })
  }),
```

Transforme ou recarregue agentes.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const agent = ctx.agent
    yield* agent.transform((editor) => {
      editor.default("build")
      editor.update("build", (item) => (item.description = "Builds features and fixes bugs"))
      editor.remove("legacy")
    })
    yield* agent.reload()
  }),
```

Schema: [`Agent.Info`](/api#schema-Agent.Info).

```ts
interface AgentEditor {
  list(): readonly Types.DeepMutable<Agent.Info>[]
  get(id: string): Types.DeepMutable<Agent.Info> | undefined
  default(id: string | undefined): void
  update(id: string, update: (agent: Types.DeepMutable<Agent.Info>) => void): void
  remove(id: string): void
}

interface AgentDomain extends AgentApi<unknown> {
  readonly transform: Transform<AgentEditor>
  readonly reload: () => Effect.Effect<void>
}
```

### Provedores

Leia os provedores disponíveis ou inspecione os metadados de um provedor pelo ID.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const provider = ctx.provider
    const providers = yield* provider.list().pipe(Effect.orDie)
    const anthropic = yield* provider.get({ providerID: Provider.ID.make("anthropic") }).pipe(Effect.orDie)
    yield* Effect.logInfo("providers", {
      providers: providers.data.length,
      anthropic: anthropic.data.name,
    })
  }),
```

As transformações de provedor editam as configurações dos provedores e as definições de origem. As leituras do editor
incluem provedores inativos e expõem definições imutáveis; `models.update` edita uma cópia própria de um modelo de
origem.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.provider.transform((editor) => {
      editor.update("anthropic", (provider) => {
        provider.headers = { ...provider.headers, "x-company": "engineering" }
      })
      editor.models.update("anthropic", "claude-sonnet-4-5", (model) => (model.name = "Team Sonnet"))
      editor.models.remove("anthropic", "legacy-model")
      editor.remove("legacy-provider")
    })
  }),
```

Substitua um inventário de origem com `models.set` e recarregue depois que as definições capturadas mudarem.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const provider = ctx.provider
    const source = { models: yield* loadModels() }
    yield* provider.transform((editor) => editor.models.set("acme", source.models))
    source.models = yield* loadModels()
    yield* provider.reload()
  }),
```

Para descoberta específica de uma conta, passe em `sourceConnection` a conexão usada para carregar o inventário. Enquanto
outra conexão estiver selecionada, o OpenCode exclui esse provedor até que o seu plugin publique o inventário
atualizado.

```ts
const connection = yield * ctx.integration.connection.active("acme")
if (!connection) return
const inventory = yield * loadInventory(connection)
yield *
  ctx.provider.transform((editor) => {
    editor.add({ info: inventory.provider, models: inventory.models, sourceConnection: connection })
  })
```

Schemas: [`Provider.Info`](/api#schema-Provider.Info), [`Model.Info`](/api#schema-Model.Info).

```ts
interface ProviderRecord {
  readonly provider: Provider.Info
  readonly models: ReadonlyMap<string, Model.Info>
  readonly sourceConnection?: ConnectionInfo
}

interface ProviderEditor {
  list(): readonly ProviderRecord[]
  get(providerID: string): ProviderRecord | undefined
  add(input: { info: Provider.Info; models: readonly Model.Info[]; sourceConnection?: ConnectionInfo }): void
  update(providerID: string, update: (provider: Types.DeepMutable<Provider.Info>) => void): void
  remove(providerID: string): void
  readonly models: {
    set(providerID: string, models: readonly Model.Info[]): void
    update(providerID: string, modelID: string, update: (model: Types.DeepMutable<Model.Info>) => void): void
    remove(providerID: string, modelID: string): void
  }
}

interface ProviderDomain extends ProviderApi<unknown> {
  readonly transform: Transform<ProviderEditor>
  readonly reload: () => Effect.Effect<void>
}
```

### Modelos

Leia os modelos disponíveis e a seleção padrão.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const model = ctx.model
    const models = yield* model.list().pipe(Effect.orDie)
    const selected = yield* model.default().pipe(Effect.orDie)
    yield* Effect.logInfo("models", { count: models.data.length, selected: selected.data?.name })
  }),
```

As transformações de modelo editam toda a coleção de candidatos dos provedores ativos. Candidatos desativados continuam
editáveis até que todas as transformações terminem; `update` só pode adicionar um modelo sob um provedor disponível.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.model.transform((editor) => {
      editor.list("anthropic").forEach((model) => {
        editor.update(model.providerID, model.id, (draft) => {
          draft.enabled = draft.capabilities.tools
        })
      })
      editor.default.set("anthropic", "claude-sonnet-4-5")
      editor.remove("anthropic", "legacy-model")
    })
  }),
```

Os callbacks editam as sobrescritas brutas dos modelos. Os padrões do provedor são mesclados uma única vez, quando o
OpenCode confirma o resultado; leituras sem alterações reutilizam esse resultado. `editor.provider` lê as definições de
origem imutáveis, incluindo templates inativos, e não a saída das transformações de modelo.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const model = ctx.model
    yield* model.transform((editor) => {
      const source = editor.provider.get("anthropic")?.models.get("claude-sonnet-4-5")
      if (!source) return
      editor.update("anthropic", source.id, (draft) => {
        draft.limit.context = Math.min(draft.limit.context, source.limit.context)
      })
    })
    yield* model.reload()
  }),
```

Schema: [`Model.Info`](/api#schema-Model.Info).

```ts
interface ModelEditor {
  list(providerID?: string): readonly Types.DeepMutable<Model.Info>[]
  get(providerID: string, modelID: string): Types.DeepMutable<Model.Info> | undefined
  update(providerID: string, modelID: string, update: (model: Types.DeepMutable<Model.Info>) => void): void
  remove(providerID: string, modelID: string): void
  readonly default: {
    get(): { providerID: string; modelID: string } | undefined
    set(providerID: string, modelID: string): void
  }
  readonly provider: {
    list(): readonly ProviderRecord[]
    get(providerID: string): ProviderRecord | undefined
  }
}

interface ModelDomain extends ModelApi<unknown> {
  readonly transform: Transform<ModelEditor>
  readonly reload: () => Effect.Effect<void>
}
```

### Comandos

Leia os comandos disponíveis na localização atual.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const command = ctx.command
    const commands = yield* command.list().pipe(Effect.orDie)
    yield* Effect.logInfo("commands", { names: commands.data.map((item) => item.name) })
  }),
```

Por enquanto, a transformação de comandos só permite adicionar. Um executor recebe a sessão, os anexos do prompt e o modo
de entrega.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const command = ctx.command
    const session = ctx.session
    yield* command.transform((editor) => {
      editor.add({
        name: "security-review",
        description: "Review changes for security issues",
        execute: (input) =>
          session.prompt({
            ...input.prompt,
            sessionID: input.sessionID,
            text: `Review these changes for security issues.\n\n${input.prompt.text}`,
            delivery: input.delivery,
          }).pipe(Effect.asVoid),
      })
    })
    yield* command.reload()
  }),
```

Schemas: [`Command.Info`](/api#schema-Command.Info),
[`Session.Inbox.Delivery`](/api#schema-Session.Inbox.Delivery).

```ts

  readonly sessionID: Session.ID

  add(definition: CommandDefinition): void

  readonly transform: Transform<CommandEditor>

```

### Integrações

Leia as integrações e resolva a credencial ativa, quando houver uma.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const integration = ctx.integration
    const integrations = yield* integration.list().pipe(Effect.orDie)
    const github = yield* integration.get({ integrationID: Integration.ID.make("github") }).pipe(Effect.orDie)
    const connection = yield* integration.connection.active("github")
    const credential = connection ? yield* integration.connection.resolve(connection).pipe(Effect.orDie) : undefined
    yield* Effect.logInfo("integration", {
      count: integrations.data.length,
      github: github.data.name,
      credential: credential?.type,
    })
  }),
```

Conecte com uma chave ou conduza uma tentativa de OAuth pela API conectada.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const integration = ctx.integration
    const token = yield* Config.Redacted("GITHUB_TOKEN").pipe(Effect.orDie)
    yield* integration.connect
      .key({ integrationID: Integration.ID.make("github"), key: Redacted.value(token) })
      .pipe(Effect.orDie)

    const attempt = yield* integration.oauth
      .connect({
        integrationID: Integration.ID.make("acme"),
        methodID: Integration.MethodID.make("oauth"),
      })
      .pipe(Effect.orDie)
    const status = yield* integration.oauth
      .status({
        integrationID: Integration.ID.make("acme"),
        attemptID: attempt.data.attemptID,
      })
      .pipe(Effect.orDie)
    yield* Effect.logInfo("OAuth status", { status: status.data })
  }),
```

Transforme integrações e métodos de autenticação. Os callbacks de métodos OAuth são Effects e podem adquirir recursos com
escopo.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const integration = ctx.integration
    yield* integration.transform((editor) => {
      editor.update("acme", (item) => (item.name = "Acme"))
      editor.method.update({
        integrationID: "acme",
        method: { id: "device", type: "oauth", label: "Sign in with Acme" },
        authorize: () =>
          Effect.succeed({
            mode: "code",
            url: "https://acme.example/device",
            instructions: "Enter the displayed code",
            callback: (code) => exchangeCode(code),
          }),
      })
    })
    yield* integration.reload()
  }),
```

Schemas: [`Integration.Info`](/api#schema-Integration.Info), [`Integration.Method`](/api#schema-Integration.Method),
[`Connection.Info`](/api#schema-Connection.Info), [`Form.Answer`](/api#schema-Form.Answer).


### MCP

Liste os servidores MCP e o estado atual da conexão de cada um.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const mcp = ctx.mcp
    const servers = yield* mcp.list().pipe(Effect.orDie)
    yield* Effect.logInfo("MCP servers", { count: servers.data.length })
  }),
```

Plugins gerenciam servidores MCP apenas por meio de transformações. Use `editor.set` para adicionar ou substituir um
servidor, `editor.update` para alterar a configuração dele e `editor.remove` para removê-lo. Inspecione a configuração com
`editor.list` e `editor.get`.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const mcp = ctx.mcp
    yield* mcp.transform((editor) => {
      const servers = editor.list()
      const docs = editor.get("docs")
      editor.set("docs", { type: "remote", url: "https://mcp.example.com" })
      editor.update("docs", (server) => (server.disabled = false))
      editor.remove("legacy")
    })
  }),
```

Defina `disabled: true` em uma transformação para desativar um servidor e desconectá-lo, ou `disabled: false` para
ativá-lo e permitir que o OpenCode se conecte. O OpenCode reconcilia o ciclo de vida dos servidores a partir da
configuração transformada.

Chame `reload()` depois que um estado externo usado por uma transformação mudar, para reaplicar as transformações e
reconciliar os servidores.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const mcp = ctx.mcp
    yield* mcp.reload()
  }),
```

Schemas: [`Mcp.Server`](/api#schema-Mcp.Server), [`Mcp.LocalConfigEncoded`](/api#schema-Mcp.LocalConfigEncoded),
[`Mcp.RemoteConfigEncoded`](/api#schema-Mcp.RemoteConfigEncoded).

```ts
  update(name: string, update: (config: Types.DeepMutable<Mcp.ServerConfig>) => void): void
  remove(name: string): void

```

### Plugins

Liste os plugins ativos, com falha e resolvidos na localização atual.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const plugin = ctx.plugin
    const plugins = yield* plugin.list().pipe(Effect.orDie)
    yield* Effect.forEach(plugins.data, (item) => Effect.logInfo("plugin", item), { discard: true })
  }),
```

Filtre os valores do schema em um pipeline Effect quando só os plugins ativos interessarem.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const plugin = ctx.plugin
    const active = yield* plugin.list().pipe(
      Effect.orDie,
      Effect.map((result) => result.data.filter((item) => item.status === "active")),
    )
    yield* Effect.logInfo("active plugin count", { count: active.length })
  }),
```

Schemas: [`Plugin.Info`](/api#schema-Plugin.Info), [`Plugin.Source`](/api#schema-Plugin.Source).

```ts
interface PluginApi<E = never> {

  readonly plugin: PluginApi<unknown>
```

### Referências

Leia as referências disponíveis na localização atual.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const reference = ctx.reference
    const references = yield* reference.list().pipe(Effect.orDie)
    yield* Effect.logInfo("references", { count: references.data.length })
  }),
```

Adicione ou remova referências locais e Git e recarregue depois que o estado externo mudar. `get(name)` retorna a origem
configurada atual, ou `undefined` quando o nome não existe.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const reference = ctx.reference
    yield* reference.transform((editor) => {
      editor.add("handbook", { type: "local", path: "/workspace/docs/handbook" })
      editor.add("standards", { type: "git", repository: "https://github.com/acme/standards", branch: "main" })
      const handbook = editor.get("handbook")
      editor.remove("legacy")
    })
    yield* reference.reload()
  }),
```

Schemas: [`Reference.Info`](/api#schema-Reference.Info), [`Reference.LocalSource`](/api#schema-Reference.LocalSource),
[`Reference.GitSource`](/api#schema-Reference.GitSource).

```ts
interface ReferenceEditor {
  add(name: string, source: ReferenceLocalSource | ReferenceGitSource): void
  remove(name: string): void
  list(): readonly (readonly [string, ReferenceLocalSource | ReferenceGitSource])[]
  get(name: string): ReferenceLocalSource | ReferenceGitSource | undefined
```

### Ferramentas

Registre ferramentas tipadas com o `Schema` do Effect. O executor recebe a entrada decodificada e retorna um Effect com
saída tipada, conteúdo de exibição ou metadados.

O editor oferece `add`, `update` e `remove`. O callback da transformação é síncrono: ele não pode retornar um Effect nem uma Promise. Carregue
dados externos antes de registrar ou recarregar. O OpenCode reaplica as transformações ativas na ordem de registro sobre
um editor novo; para o mesmo nome efetivo de ferramenta, um registro válido posterior sobrescreve o anterior.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const tool = ctx.tool
    yield* tool.transform((editor) => {
      editor.namespace({
        name: "acme",
        description: "Customer account tools",
      })
      editor.add({
        name: "greeting",
        description: "Create a greeting",
        input: Schema.Struct({ name: Schema.String }),
        output: Schema.Struct({ greeting: Schema.String }),
        options: { namespace: "acme", codemode: true },
        execute: ({ name }, context) =>
          Effect.gen(function* () {
            yield* context.progress({ status: "greeting" })
            return { output: { greeting: `Hello ${name}!` } }
          }),
      })
    })
  }),
```

Chame `yield* ctx.tool.reload()` depois de alterar os dados de origem capturados pelo callback. O recarregamento reaplica
as transformações ativas sem mudar a ordem delas; ele não executa novamente o effect do plugin.

As ferramentas têm um `id` com o nome efetivo, e `get()` retorna `undefined` quando esse ID não existe. Use `update` e
`remove` com o nome efetivo da ferramenta, incluindo o namespace (`acme_greeting` no exemplo acima). Pontos em namespaces
e caracteres não suportados em nomes de ferramentas viram `_`. Nomes inexistentes são ignorados; para criar uma
ferramenta, use `add` com uma definição completa. Atualizações preservam o nome e o namespace. Para substituir schemas ou
opções, atribua novos valores em vez de modificar valores aninhados. Atualizações inválidas são registradas no log e
mantêm a definição anterior intacta.

```ts
yield *
  ctx.tool.transform((editor) => {
    editor.update("acme_greeting", (tool) => {
      tool.description = "Greet the user by name"
    })
    editor.remove("acme_obsolete")
  })
```

Atualizações e remoções são reaplicadas em ordem junto com as adições, inclusive depois de atualizações do catálogo MCP.

`transform` retorna um registro com escopo. Execute `yield* registration.dispose` para remover a transformação e
reconstruir a partir das transformações restantes, revelando qualquer definição anterior que ela tenha sobrescrito. O
descarte é idempotente, e fechar o escopo do plugin também descarta os registros dele.

Cada requisição ao modelo captura um snapshot das ferramentas. O recarregamento e o descarte afetam os snapshots futuros,
não as definições nem os executores já capturados por uma requisição em andamento. Executores que fazem closure sobre
dados mutáveis do plugin continuam enxergando esses dados; capture um valor dentro da transformação quando ele precisar
ficar vinculado àquela definição.

Schemas: [`Tool.Content`](/api#schema-Tool.Content), [`Tool.TextContent`](/api#schema-Tool.TextContent),
[`Tool.FileContent`](/api#schema-Tool.FileContent).

## Hooks

Hooks interceptam operações em andamento. Vários plugins podem registrar o mesmo hook; o OpenCode os executa na ordem dos
plugins, então os hooks posteriores enxergam as alterações dos anteriores. Os registros permanecem ativos enquanto durar
o escopo do plugin.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook("context", () => Effect.void)
  }),
```

### Sessões

Modifique as instruções de sistema montadas, as mensagens ou as ferramentas imediatamente antes do envio ao modelo.
`context` é executado no loop do agente; `compaction`, `generate` e `title` são executados nessas requisições auxiliares.
`compaction` e `title` aceitam um `result` que pula a chamada ao modelo.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook("context", (event) =>
      Effect.sync(() => {
        event.system.push({ type: "text", text: "Keep the review focused on correctness." })
        delete event.tools.write
      }),
    )
    yield* session.hook("compaction", (event) =>
      Effect.map(summarize(event.messages), (summary) => {
        event.result = { summary }
      }),
    )
  }),
```

Modifique as configurações da requisição ao modelo e, opcionalmente, restrinja o hook a um provedor. O evento traz o
mesmo `kind` dos hooks HTTP abaixo.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook(
      "model.request",
      (event) => Effect.sync(() => (event.headers["x-plugin"] = "review")),
      { providerID: "anthropic" },
    )
  }),
```

Modifique as requisições ou respostas nativas do provedor. Os corpos delas são streams de leitura única; clone ou
substitua um corpo antes de lê-lo. Os dois hooks são executados em todas as requisições que uma sessão faz; `event.kind`
é `"primary"`, `"compaction"`, `"title"` ou `"generate"`, conforme o fluxo que fez a requisição.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook("http.request", (event) =>
      Effect.sync(() => {
        event.request.headers.set("x-session-id", event.sessionID)
        if (event.kind === "title") event.request.headers.set("x-priority", "background")
      }),
    )
    yield* session.hook("http.response", (event) =>
      Effect.sync(() => {
        event.response = new Response(event.response.body, {
          status: event.response.status,
          headers: { ...Object.fromEntries(event.response.headers), "x-plugin": "review" },
        })
      }),
    )
  }),
```

Provedores que fazem streaming por WebSocket reutilizam uma conexão por sessão, então os hooks HTTP nunca veem esse
tráfego. O hook experimental `experimental.ws.handshake` é executado uma vez por chamada ao modelo, antes de a conexão ser
selecionada, e expõe a `url` e os `headers` da conexão; alterar qualquer um deles reabre o socket. Os hooks HTTP
continuam sendo executados em qualquer requisição para a qual uma rota WebSocket recorra como fallback.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.session.hook(
      "experimental.ws.handshake",
      (event) =>
        Effect.gen(function* () {
          event.headers.authorization = `Bearer ${yield* mintToken(event.url)}`
          delete event.headers["api-key"]
        }),
      { providerID: "azure" },
    )
  }),
```

`experimental.ws.send` e `experimental.ws.receive` expõem os próprios frames: `send` é executado depois que o driver do
provedor monta um frame de saída, e `receive` é executado em cada frame de entrada antes de o driver observá-lo. O que estiver em `frame` quando o hook retornar é o que vai pela conexão ou chega ao driver;
o OpenCode não valida esse conteúdo.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.session.hook(
      "experimental.ws.send",
      (event) =>
        Effect.sync(() => {
          const body = JSON.parse(event.frame)
          if (body.type === "response.create") body.metadata = { ...body.metadata, session: event.sessionID }
          event.frame = JSON.stringify(body)
        }),
      { providerID: "openai" },
    )
  }),
```

Sobrescreva a decisão de nova tentativa para uma falha do provedor ou substitua o atraso dela em milissegundos. O hook é
executado depois que o OpenCode classifica a falha e propõe a política, mas antes de qualquer nova tentativa ser agendada.
Ele não expõe como o OpenCode executa internamente a próxima tentativa.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.session.hook("retry", (event) =>
      Effect.sync(() => {
        if (event.error.status === 429) {
          event.decision = { retry: true, delay: 10_000 }
          return
        }
        if (event.error.type === "provider.invalid-request" && event.attempt === 2) {
          event.decision = { retry: true, delay: 0 }
          return
        }
        if (event.attempt >= 3) event.decision = { retry: false }
      }),
    )
  }),
```

O `decision` inicial é a política do OpenCode, então os hooks podem tornar repetível uma falha de provedor normalmente
definitiva ou vetar uma nova tentativa proposta. Vários hooks são executados na ordem de registro, e os posteriores veem a
decisão atual. O número máximo de tentativas nativo continua sendo um limite rígido. `attempt` é a tentativa física
proposta; a requisição inicial é a tentativa `1`, então a primeira nova tentativa é a `2`. Atrasos inválidos (`NaN`,
infinito ou valores negativos) recorrem ao atraso calculado. A recuperação de estouro de contexto continua separada,
porque ela compacta a conversa em vez de repetir a mesma requisição.


## Publicar

Um plugin empacotado usa o mesmo export padrão de um plugin Effect local. Exporte a implementação Effect pelo ponto de
entrada principal e declare `effect` como `peerDependency`.

```json title="package.json"
{
  "name": "opencode-acme-effect-plugin",
  "version": "1.0.0",
  "type": "module",
  "exports": {
    ".": "./src/index.ts"
  },
  "dependencies": {
    "@opencode/plugin": "latest"
  },
  "peerDependencies": {
    "effect": "^4.0.0"
  }
}
```

O OpenCode redireciona as importações de `effect`, dos subcaminhos exportados `effect/*` e de `@opencode/plugin`
(incluindo importações feitas por dependências em `node_modules` do plugin) para as instâncias do runtime do host, para
que fibers, loggers e parsers de `Schema` compartilhem uma única cópia do runtime.

- Não empacote `effect` no artefato publicado do plugin. Se você usa um bundler, marque `effect` e `effect/*` como
  externos.
- Plugins e as dependências deles em `node_modules` sempre são executados com a instância de `effect` da versão do
  OpenCode do host. Use APIs e caminhos de módulo de `effect` compatíveis com a versão do OpenCode que você tem como alvo;
  dependências criadas com outra versão major de `effect` (como Effect 3) também recebem o `effect` do host e não são
  suportadas.
- Somente os subcaminhos públicos de `effect` são fornecidos. Um plugin que importa um dos módulos privados `internal` do
  Effect falha ao carregar, com um erro que indica o caminho.
- O binário compilado do OpenCode não inclui os assets do Scalar e do Swagger UI usados pelas páginas de documentação da
  HTTP API do Effect; ao servir essas páginas a partir de um plugin, é exibido um aviso no lugar delas.

O ponto de entrada do pacote exporta `Plugin.define` com uma função `effect`.

```ts title="src/index.ts"
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "acme.published",
  effect: (ctx) =>
    Effect.gen(function* () {
      const storage = ctx.storage
      yield* storage.set("installed", true)
    }),
})
```

Use versões compatíveis com a versão do OpenCode que você tem como alvo e teste o pacote instalado, não apenas uma cópia
vinculada ao workspace.

```sh
bun pm pack
bun add ./opencode-acme-effect-plugin-1.0.0.tgz
```
