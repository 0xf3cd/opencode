---
title: "RPC"
---

Plugins podem expor métodos e eventos personalizados que são executados no servidor e podem ser chamados por outros
plugins ou clientes.

## Definir

Use `Rpc.define` para listar os métodos, erros e eventos da RPC.

```ts title="src/rpc.ts"
import { Rpc } from "@opencode/plugin/rpc"

export const Acme = Rpc.define({
  id: "acme",
  methods: {
    search: {
      input: {
        type: "object",
        properties: { query: { type: "string" } },
        required: ["query"],
        additionalProperties: false,
      },
      output: {
        type: "object",
        properties: { text: { type: "string" } },
        required: ["text"],
        additionalProperties: false,
      },
      errors: {
        not_found: {
          type: "object",
          properties: { query: { type: "string" } },
          required: ["query"],
          additionalProperties: false,
        },
      },
    },
  },
  events: {
    updated: {
      schema: {
        type: "object",
        properties: {
          itemID: { type: "string" },
          text: { type: "string" },
        },
        required: ["itemID", "text"],
        additionalProperties: false,
      },
    },
  },
})
```

### Validação

Uma definição de RPC descreve o formato da entrada e da saída de métodos, eventos e erros. Ela aceita dois formatos de
schema:

- JSON Schema, simples e sem dependências.
- Qualquer validador compatível com Standard Schema
  - Zod
  - Valibot
  - ArkType

### Entrada e saída

Cada método pode definir um schema `input` para o argumento e um schema `output` para o valor de retorno. Omita
qualquer um deles se o método não receber ou não retornar um valor.

```ts
search: {
  input: {
    type: "object",
    properties: { query: { type: "string" } },
    required: ["query"],
  },
  output: {
    type: "object",
    properties: { text: { type: "string" } },
    required: ["text"],
  },
}
```

Valores de JSON Schema são `unknown` no TypeScript, então restrinja o tipo antes de usá-los. Com Standard Schema, os
tipos de entrada e saída são inferidos.

### Erros

Adicione um mapa `errors` a um método para falhas esperadas. Cada chave vira o `type` do erro, e o schema dela define o
`data` do erro.

```ts
errors: {
  not_found: {
    type: "object",
    properties: { query: { type: "string" } },
    required: ["query"],
    additionalProperties: false,
  },
}
```

Nomes de erro que começam com `rpc.` são reservados pelo OpenCode.

### Eventos

Adicione eventos ao mapa `events` de nível superior. Cada evento tem um schema para os dados enviados aos assinantes.

Os dados do evento precisam ser um objeto. Use um schema de objeto vazio quando não houver dados:

```ts
events: {
  refreshed: {
    schema: { type: "object", additionalProperties: false },
  },
}
```

Escalares, arrays, `null` e `undefined` não são dados de evento válidos.

## Implementar

Registre a implementação dentro de `setup`:

```ts title="src/index.ts"
import { Plugin } from "@opencode/plugin"
import { Acme } from "./rpc.js"

export default Plugin.define({
  id: "acme-plugin",
  async setup(ctx) {
    const registration = await ctx.rpc.register(Acme, {
      search: async (input, context) => {
        const { query } = input as { query: string }
        const text = await findText(query, { signal: context.signal })
        if (!text) return context.error("not_found", "Result not found", { query })
        return { text }
      },
    })

    const acme = ctx.rpc(Acme)
    const result = await acme.search({ query: "hello" })

    await registration.events.emit("updated", { itemID: "item-1", text: "ready" })
  },
})
```

Depois de registrar a RPC, o próprio plugin pode chamá-la com `ctx.rpc(Acme)`.

O segundo argumento inclui `signal` para cancelamento e `context.error(...)` para erros declarados. Você pode retornar
ou lançar o erro.

Um plugin pode registrar mais de uma RPC. Descartar o registro remove a RPC.

## Chamar

Depois de registrada, a RPC pode ser chamada por HTTP ou a partir de outro plugin.

### HTTP

Crie um cliente do OpenCode e use `client.rpc` para criar um subcliente para a RPC:

```ts
import { OpenCode } from "@opencode/client"
import { Acme } from "opencode-acme-plugin/rpc"

const client = OpenCode.make({
  baseUrl: "http://localhost:4096",
})

const acme = client.rpc(Acme)
const result = await acme.search({ query: "hello" })
```

### Plugin

Plugins já têm um cliente do OpenCode. Por exemplo, um plugin da TUI pode criar o mesmo subcliente de RPC a partir de
`context.client`:

```ts title="src/tui.ts"
import { Plugin } from "@opencode/plugin/tui"
import { Acme } from "opencode-acme-plugin/rpc"

export default Plugin.define({
  id: "acme-tui",
  async setup(context) {
    const acme = context.client.rpc(Acme)
    const result = await acme.search({ query: "hello" })
    console.log(result)
  },
})
```

### Assinar

Use `events.on` para registrar um callback e cancele a assinatura quando o listener não for mais necessário:

```ts
const unsubscribe = acme.events.on("updated", (event) => {
  console.log(event.type, event.location.directory, event.data.text)
})

unsubscribe()
```

Para um iterável assíncrono, use `events.subscribe("updated")`:

```ts
for await (const event of acme.events.subscribe("updated")) {
  console.log(event.data.text)
}
```

As assinaturas de eventos são apenas ao vivo, então assinantes desconectados perdem eventos.

- Assine com o nome local, como `updated`.
- O tipo recebido tem prefixo, como `rpc.acme.updated`.
- Cada evento inclui `data` e `location`.
- Descarregar o plugin encerra as assinaturas dele.

Clientes externos recebem eventos de todas as localizações, então verifique `event.location` quando necessário. O
plugin de servidor ainda precisa estar configurado e em execução.
