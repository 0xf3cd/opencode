| **Go Plus** | **$40/mês**   | Limites de uso maiores nos modelos abaixo   |

O Go funciona como qualquer outro provedor no OpenCode. Você assina o OpenCode Go e recebe a sua chave de API. Ele é **totalmente opcional**, e você não precisa dele para usar o OpenCode.

O serviço foi projetado principalmente para usuários internacionais e oferece acesso global estável.

## Como funciona

1. Entre no [OpenCode Console](https://opencode.ai/console), assine o Go ou o Go Plus, adicione seus dados de cobrança e copie a sua chave de API.
2. Execute `/connect` na TUI, selecione **OpenCode Go** e cole a sua chave de API.

   ```text
   /connect
   ```

3. Execute `/models` para selecionar um modelo disponível no Go.

   ```text
   /models
   ```

<Callout>
  O Go e o Go Plus são para workspaces com um único membro, como o workspace **Personal** criado quando você se
  cadastra. Um workspace com assinatura do Go não pode convidar membros.
</Callout>

## Onde posso usar?

O OpenCode Go foi projetado para o [OpenCode](https://opencode.ai) e outros agentes de programação que geram tipos de
requisição semelhantes. O tráfego é monitorado para detectar abusos que prejudicam a experiência de outros usuários.

O seu cliente deve:

1. Enviar tráfego típico de um agente de programação
2. Identificar-se com o próprio user agent, como `my-coding-agent/1.0`, em vez do nome genérico de um SDK ou de uma
   biblioteca HTTP.
3. Enviar um ID de sessão estável em `x-opencode-session` para cada conversa, para que possamos otimizar o roteamento e o
   cache de prompts.

### Clientes validados

Além do OpenCode, os clientes a seguir foram validados e funcionam corretamente com o OpenCode Go. No entanto, não
garantimos que continuarão funcionando no futuro.

| Cliente           | Suporte a sessões                                                                                                                                                                                                                           |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Hermes**        | Builds que contêm o [PR #101864](https://github.com/NousResearch/hermes-agent/pull/101864) enviam o header nas requisições principais e auxiliares ao OpenCode. A correção foi incorporada depois da v0.21.0; essa versão, por si só, não a inclui. |
| **Claude Code**   | O Go reconhece o header de sessão nativo dele. Não é preciso nenhum wrapper de header personalizado.                                                                                                                                       |
| **Codex**         | O Go reconhece o header de sessão nativo dele. Algumas versões e configurações de proxy ainda o omitem; preserve o header de sessão ao encaminhar requisições.                                                                             |
| **ZCode**         | O Go reconhece o header de sessão nativo dele. A nossa [solicitação de suporte a `x-opencode-session`](https://github.com/zai-org/feedback/issues/492) continua aberta, mas não é mais necessário enviar esse header específico.          |
| **Pi**            | As builds atuais enviam informações de sessão para o OpenCode. Atualize instalações mais antigas.                                                                                                                                          |
| **jcode**         | Atualize para a **v0.81.6 ou posterior**, que inclui a [correção do header de sessão](https://github.com/1jehuang/jcode/issues/1167).                                                                                                      |
| **Kilo Code CLI** | Builds que contêm o [PR #13752](https://github.com/Kilo-Org/kilocode/pull/13752) restauram os headers de sessão do OpenCode. A correção vale para a CLI, não para a extensão do VS Code. Consulte a [issue #13723](https://github.com/Kilo-Org/kilocode/issues/13723). |

### Clientes com problemas conhecidos

Estes clientes não têm suporte a sessões, ou têm suporte incompleto, nas versões que investigamos. Os relatos indicados

| **GitHub Copilot Chat** | O suporte automático ao header de sessão foi solicitado na [issue #334186 do VS Code](https://github.com/microsoft/vscode/issues/334186).                                                                                                              |
| **Kimi Code**           | O suporte automático ao header de sessão foi solicitado na [issue #3506](https://github.com/MoonshotAI/kimi-code/issues/3506).                                                                                                                        |
| **MiMo Code**           | A [issue #2317](https://github.com/XiaomiMiMo/MiMo-Code/issues/2317) tem uma correção proposta no [PR #2327](https://github.com/XiaomiMiMo/MiMo-Code/pull/2327), que ainda não foi incorporado.                                                       |

### Uso além dos limites

Se você também tiver créditos no saldo do Console, pode ativar a opção **Use balance** no console. Com ela ativada,
depois que você atingir os limites de uso, o Go recorre ao seu [saldo pré-pago](/console/models#pricing) em vez de
bloquear as requisições.

### Por que alguns modelos têm uso menor

No Go, o uso mensal incluído varia de acordo com o modelo.

Para a maioria dos modelos, conseguimos isso com descontos por volume e capacidade de GPU reservada. Depois, repassamos essa economia para você na forma de mais uso mensal.

Para alguns modelos, ainda não tivemos a oportunidade de negociar um desconto ou de hospedá-los a um custo menor, seja porque o modelo é novo, seja porque o preço público dele já tem desconto.

Nesses modelos, você ainda recebe um pouco mais do que pagaria diretamente aos provedores; é por isso que o uso mensal incluído deles é menor.

## Contexto

Os modelos abertos ficaram muito bons. Hoje eles chegam a um desempenho próximo ao dos modelos proprietários em tarefas de programação. Como muitos provedores conseguem servi-los de forma competitiva, eles costumam ser bem mais baratos.

No entanto, conseguir acesso confiável e com baixa latência a eles pode ser difícil. Os provedores variam em qualidade e disponibilidade.

<Callout type="tip">Testamos um grupo seleto de modelos e provedores que funcionam bem com o OpenCode.</Callout>

Para resolver isso, fizemos algumas coisas:

1. Testamos um grupo seleto de modelos abertos e conversamos com as equipes deles sobre a melhor forma de executá-los.
2. Trabalhamos com alguns provedores para garantir que esses modelos fossem servidos corretamente.
3. Fizemos benchmarks das combinações de modelo e provedor e chegamos a uma lista que recomendamos com confiança.

Tanto o Go quanto o Go Plus dão acesso a esses modelos; escolha o plano que combina com o quanto você os usa.

## Objetivos

Criamos o OpenCode Go para:

1. Tornar a programação com IA **acessível** a mais pessoas com uma assinatura de baixo custo.
2. Oferecer acesso **confiável** aos melhores modelos abertos de programação.
3. Selecionar modelos **testados e avaliados com benchmarks** para uso em agentes de programação.
4. Não ter **lock-in**, permitindo que você também use qualquer outro provedor com o OpenCode.
