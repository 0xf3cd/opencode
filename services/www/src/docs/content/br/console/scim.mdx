---
title: "Sincronização de diretório"
description: "Adicione e remova membros do workspace automaticamente a partir do Okta, do Microsoft Entra ID ou de qualquer provedor de identidade SCIM 2.0."
---

A sincronização de diretório (SCIM 2.0) adiciona pessoas ao workspace quando você as atribui no seu provedor de
identidade e remove o acesso delas quando você cancela a atribuição. As funções continuam sendo gerenciadas no Console.

```text
https://opencode.ai/console/scim/v2
```

## Antes de começar

- Configure o [SSO](/console/sso) para o workspace.
- [Verifique](/console/sso#verify-email-domains) todos os domínios de e-mail que as pessoas usam para entrar. A
  sincronização de diretório só adiciona pessoas de um domínio verificado; convide as demais em
  [Membros](/console/members).

## Criar um token

1. Abra **Settings › Security** e clique em **Set up** em **Directory sync**.
2. Copie a **SCIM base URL** e o token. O token é exibido uma única vez, então guarde-o em um gerenciador de segredos.

O seu provedor de identidade envia o token em todas as requisições.

```text
Authorization: Bearer <token>
```

## Conectar o seu provedor de identidade

### Okta

1. Adicione o app **SCIM 2.0 Test App (Header Auth)**.
2. Defina a URL base e informe `Bearer ` seguido do token em **API Token**.
3. Ative **Create Users**, **Update User Attributes** e **Deactivate Users**. Deixe **Import Groups** e a
   sincronização de senhas desativados.

### Microsoft Entra ID

1. No seu aplicativo empresarial, abra **Provisioning** e defina o modo como **Automatic**.
2. Informe a URL base como **Tenant URL** e o token como **Secret Token**.
3. Atribua usuários e grupos e inicie o provisionamento.

### Outros provedores

Use um app SCIM 2.0 com autenticação por token no header, apontado para a URL base. O Console aceita os endpoints
`/Users` e `/Groups`.

Atribua primeiro uma pessoa de teste. **Directory sync** mostra **Connected to your identity provider** depois da
primeira requisição.

## O que é sincronizado

| No seu provedor de identidade | No Console                                                                        |
| ----------------------------- | --------------------------------------------------------------------------------- |
| Atribuir uma pessoa           | Adicionada como **Member**. Membros existentes mantêm a função.                   |
| Atualizar um nome             | Perfil atualizado.                                                                |
| Cancelar a atribuição ou desativar | Acesso suspenso e exibido como **Deactivated**. As chaves de API criadas pela pessoa são revogadas. |
| Atribuir de novo              | Acesso restaurado. As chaves revogadas continuam revogadas.                       |
| Excluir                       | Removida do workspace. A conta dela e os outros workspaces não são afetados.      |

- A sincronização de diretório não altera funções nem endereços de e-mail.
- O último proprietário não pode ser desativado nem excluído.
- Workspaces com assinatura do [Go](/console/go) não podem adicionar membros pela sincronização de diretório.

## Grupos

Envie grupos para marcar os membros deles com tags, por exemplo com **Push Groups** do Okta ou com a atribuição de grupos
do Entra. Atribua as pessoas antes de enviar os grupos delas.

```text
Platform Admins  →  platform-admins
```

Cada grupo marca os membros com uma tag que leva o nome do grupo. Em **Settings › Security › Group tags**, você pode
renomear uma tag, apontar vários grupos para a mesma tag ou deixar de marcar um grupo. Sair de um grupo remove a tag
dele.

## Fazer a rotação do token

1. Clique em **New token** e instale-o no seu provedor de identidade.
2. Aguarde até que o novo token mostre um último uso.
3. Revogue o token antigo.

Revogar um token interrompe as próximas atualizações, mas não altera os membros existentes. Excluir a conexão de SSO
revoga todos os tokens.

## SSO e sincronização de diretório

Depois que um workspace emite um token, o SSO deixa de [adicionar membros automaticamente](/console/sso#automatic-membership).
O diretório decide quem faz parte, mesmo que o token seja revogado depois.
