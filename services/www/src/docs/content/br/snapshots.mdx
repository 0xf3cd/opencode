---
title: "Snapshots"
---

Com os snapshots, você desfaz alterações recentes na conversa e nos arquivos ao mesmo tempo. Use-os para revisar trabalho
recente, mas mantenha commits do Git ou backups de tudo o que for importante.

## Fluxo de trabalho

Execute `/undo` depois de uma resposta que você queira revisar. O OpenCode prepara a reversão, restaura os arquivos
afetados e devolve o prompt removido ao campo de mensagem para que você possa editá-lo.

```text
/undo

# Edit the restored prompt, then submit it again.
Add validation without changing the public API.
```

Enviar o prompt editado confirma a reversão preparada. Antes de enviar, execute `/redo` para cancelá-la e restaurar a
conversa e os arquivos como estavam antes do `/undo`.

```text
/redo
```

O terminal também oferece atalhos padrão:

| Ação | Comando | Atalho |
| --- | --- | --- |
| Preparar a reversão da mensagem anterior | `/undo` | `<leader>u` |
| Cancelar a reversão preparada | `/redo` | `<leader>r` |

Você também pode selecionar uma mensagem anterior e escolher **Revert** para preparar uma reversão até esse ponto.

## Captura

Em cada etapa do modelo, o OpenCode tenta criar um snapshot imediatamente antes da chamada ao modelo e outro quando a
etapa termina com sucesso ou falha registrados. A mensagem do assistente registra quais caminhos mudaram entre esses
snapshots.

```text
before model step ── snapshot A
model edits src/api.ts
step finishes ────── snapshot B ── changed: src/api.ts
```

A captura é feita na base do melhor esforço. Se algum dos snapshots não estiver disponível, a conversa continua, mas
talvez não haja alterações de arquivos dessa etapa para restaurar.

## Escopo

Os snapshots cobrem o diretório ativo da sessão dentro de um worktree do Git. Por exemplo, uma sessão aberta em
`packages/app` captura os arquivos elegíveis dentro de `packages/app`, e não alterações em outras partes do repositório.

| Conteúdo | Capturado | Exemplo |
| --- | --- | --- |
| Arquivos rastreados no diretório ativo | Sim | `packages/app/src/app.tsx` |
| Arquivos não rastreados e não ignorados de até 2 MiB cada | Sim | `packages/app/notes.txt` |
| Arquivos ignorados pelo Git | Não | `packages/app/dist/app.js` |
| Arquivos não rastreados individuais com mais de 2 MiB | Não | `packages/app/debug.log` |
| Arquivos fora do diretório ativo | Não | `packages/server/src/index.ts` |
| Metadados do Git e outros efeitos colaterais | Não | commits, branches, bancos de dados ou processos |

Snapshots do sistema de arquivos exigem um repositório Git. Fora de um repositório, o `/undo` ainda consegue reverter o
histórico da conversa, mas não restaura arquivos.

## Restauração

Uma reversão restaura apenas os caminhos atribuídos às etapas do assistente posteriores ao ponto da conversa selecionado.
Cada caminho volta ao estado anterior à primeira etapa revertida; um arquivo criado por essas etapas é removido se não
existia naquele momento.

| Linha do tempo | `src/api.ts` | `src/new.ts` |
| --- | --- | --- |
| Ponto selecionado | versão A | inexistente |
| Etapas posteriores do assistente | versão B | criado |
| Após a reversão | versão A | removido |

Caminhos não atribuídos a essas etapas não são alterados. Edições atuais em um caminho afetado podem ser sobrescritas,
então revise o resumo da restauração e o `git diff` antes de continuar.

```sh
git diff --stat
git diff
```

## Armazenamento

O OpenCode armazena os snapshots localmente, em um banco de objetos Git interno e separado, dentro do seu diretório de
dados. A captura de snapshots não cria commits, não move branches e não altera intencionalmente o índice do seu
repositório.

```sh
# Your repository remains an ordinary dirty worktree after capture.
git status --short
```

Os objetos de snapshot podem conter o conteúdo completo dos arquivos rastreados e dos não rastreados elegíveis. Trate o
diretório de dados do OpenCode como dados locais sensíveis.

## Configurações

Os snapshots vêm ativados por padrão. Defina `snapshots` como `false` na sua [configuração](/config#snapshots) para
interromper as próximas capturas do sistema de arquivos.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "snapshots": false,
}
```

Desativar os snapshots não exclui os que já estão armazenados. A reversão da conversa continua disponível, mas, sem um
estado do sistema de arquivos capturado, ela não consegue restaurar as alterações de arquivos relacionadas.

## Segurança

Os snapshots são uma conveniência, não uma transação nem um backup:

- Comandos de shell podem alterar serviços, processos, recursos de rede, bancos de dados, o estado do Git, saídas
  ignoradas ou arquivos fora do diretório ativo. Restaurar um snapshot não desfaz esses efeitos.
- Trabalhos interrompidos ou com falha podem deixar alterações quando a captura falha ou não existe um par de snapshots
  utilizável.
- Restaurar os caminhos afetados sobrescreve o conteúdo atual deles. Cancelar uma reversão preparada também pode
  sobrescrever edições posteriores.
- O OpenCode rejeita operações de reversão enquanto a sessão está em execução, mas editores e comandos externos ainda
  podem alterar o worktree entre a captura e a restauração.
- Confirmar uma reversão remove mensagens da visualização da conversa ativa, mas não do histórico durável da sessão nem
  do armazenamento de snapshots existente. Não se trata de uma exclusão segura.

Faça commit ou backup do trabalho importante antes de usar `/undo` em um worktree com alterações pendentes.
