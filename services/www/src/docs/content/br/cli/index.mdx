Execute a CLI em um projeto para abrir a interface de terminal em tela cheia:

```bash
opencode
```

Passe um diretório para trabalhar em outro projeto:

```bash
opencode ~/code/my-project
```

Terminais recomendados:

- [Ghostty](https://ghostty.org)
- [WezTerm](https://wezterm.org)
- [Alacritty](https://alacritty.org)
- [Kitty](https://sw.kovidgoyal.net/kitty/)

Com suporte a truecolor, os temas exibem as cores mais fiéis; terminais sem esse suporte usam uma aproximação com a
paleta disponível.

## Automação

Use `opencode run` para enviar um prompt sem abrir a interface interativa. Ele foi pensado para scripts, jobs de CI e
outros fluxos que precisam da saída do modelo diretamente no terminal.

```bash
opencode run "Explain this repository"
```

## Mini

Use `opencode mini` para iniciar a interface interativa mínima do OpenCode em vez da TUI em tela cheia.

```bash
opencode mini
```

Execute `opencode mini --help` para ver as opções de sessão, modelo, agente, prompt e replay.

## Serviço em segundo plano

Por padrão, o OpenCode localiza ou inicia um único servidor compartilhado em segundo plano para a sua conta de usuário.
Todos os clientes locais do OpenCode se conectam a esse servidor, que é responsável por sessões, configuração,
integrações, permissões e execução de ferramentas.

Use `--standalone` para executar com um servidor privado, ou `--server` para se conectar à URL de um servidor específico:

```bash
opencode --standalone
opencode --server http://localhost:4096
```

Para que os comandos da CLI usem servidores privados por padrão em vez de iniciar o serviço compartilhado, desative-o:

```bash
opencode service set disabled true
opencode
```

Isso interrompe o serviço em segundo plano em execução. `--server` continua se conectando a um servidor selecionado
explicitamente, e `opencode service start` ainda pode iniciar o serviço compartilhado de forma explícita. Para voltar a
usar o serviço automaticamente, execute `opencode service unset disabled`. O pareamento exige o serviço compartilhado e
fica indisponível enquanto ele estiver desativado.

Consulte [Solução de problemas](/troubleshooting) para diagnosticar o serviço compartilhado e a
[referência da API](/api) para ver os endpoints do servidor.

## Caminhos

Exiba um caminho local específico para usar com outras ferramentas:

```bash
opencode debug paths db
sqlite3 "$(opencode debug paths db)"
```

O seletor opcional aceita `db`, `home`, `data`, `config`, `cache`, `state`, `tmp`, `bin`, `log` ou `repos` e exibe
apenas o caminho seguido de uma quebra de linha. O caminho do banco de dados respeita o canal de release e
`OPENCODE_DB`; caminhos relativos definidos para o banco são resolvidos dentro do diretório de dados, e `:memory:` é
exibido sem alterações. Esse comando não inicia um servidor nem abre o banco de dados.

Omita o seletor para exibir todos os caminhos com seus rótulos:

```bash
opencode debug paths
```

## Desinstalar

Veja uma prévia dos arquivos e da instalação que serão removidos:

```bash
opencode uninstall --dry-run
```

Execute `opencode uninstall` para confirmar a remoção. O OpenCode encerra os serviços em segundo plano registrados e os
terminais persistentes antes de remover o diretório global de cache, que é compartilhado entre versões e canais do
OpenCode. Dados de sessão, configuração e estado nunca são removidos.

- `--force` (`-f`) pula a confirmação; use-o para remoção não interativa.
- Instalações feitas por gerenciador de pacotes usam o gerenciador detectado. Instalações via curl exibem o comando
  final para remover o executável manualmente.
