title: "Tema"
---

O OpenCode vem com vários temas integrados para os modos claro e escuro. Escolha um nas configurações ou combine suas
próprias cores.

## Escolher um tema

Pressione `Ctrl+P`, selecione **Open settings** e abra **Theme**. O tema padrão é `opencode`.

Você também pode definir o tema nas suas [configurações globais da CLI](/cli/config):

```json title="~/.config/opencode/cli.json"
{
  "$schema": "https://opencode.ai/v2/cli.json",
  "theme": {
    "name": "tokyonight",
    "mode": "dark"
  }
}
```

Execute `/themes` para trocar de tema sem abrir as configurações.

## Cores do sistema

Quando o OpenCode consegue ler a paleta do terminal, o seletor de temas inclui o tema `system`. Ele deriva as cores do
primeiro plano, do fundo e da paleta ANSI do seu terminal.

O nome de tema `system` seleciona as cores derivadas do terminal. Já o modo `system` segue a aparência clara ou escura
do terminal.

## Modo

Use `system` para seguir a aparência do terminal ou fixe o tema no modo claro ou escuro:

| Modo | Comportamento |
| --- | --- |
| `system` | Segue a aparência clara ou escura detectada no terminal. |
| `dark` | Sempre usa as cores escuras do tema. |
| `light` | Sempre usa as cores claras do tema. |

Isso corresponde ao campo `mode` dentro de `theme` na configuração da CLI. Se um tema personalizado oferece apenas um
modo, o OpenCode usa esse modo quando o outro é solicitado.

## Adicionar um tema

Para adicionar um tema que você baixou ou recebeu de outra pessoa, copie o arquivo JSON dele para o diretório global de
temas:

```bash
cp theme.json ~/.config/opencode/themes/
```

Você também pode colocar o tema no diretório `.opencode/themes` de um projeto para disponibilizá-lo apenas nesse
projeto.

O nome do arquivo vira o nome do tema. Por exemplo, `my-theme.json` aparece como `my-theme`. Reinicie o OpenCode depois
de adicionar o arquivo e execute `/themes` para selecioná-lo.

O OpenCode lê apenas arquivos `.json`. Um tema mais próximo do diretório atual substitui um tema global ou de um
diretório pai com o mesmo nome.

## Usar temas em plugins

[Plugins da CLI](/build/plugins/cli) leem as cores resolvidas por `context.theme` e o modo ativo por
`context.themeMode`. Use tokens semânticos para que o seu plugin acompanhe o tema selecionado:

```tsx title="Inside a CLI plugin component"
import { usePlugin } from "@opencode/plugin/tui"

function Status() {
  const context = usePlugin()
  return <text fg={context.theme.text.base}>Ready</text>
}
```

A API pública de plugins da CLI não registra temas. Adicione definições de temas personalizados com arquivos JSON nos
diretórios mencionados acima.

## Criar um tema

Use a nossa [ferramenta de temas](https://opencode.ai/theme/) para criar ou editar temas. Ela facilita entender a
estrutura, alterá-la e definir cores personalizadas. A explicação abaixo serve como referência.

Um tema separa os tokens semânticos compartilhados das paletas específicas de cada modo:

| Seção | Finalidade |
| --- | --- |
| `base` | A árvore completa de tokens compartilhada por todos os modos. |
| `light`, `dark` | Uma paleta completa de matizes e sobrescritas opcionais de tokens para aquele modo. |

Todo tema fornece um `base` completo e define pelo menos um entre `light` e `dark`. Os modos herdam do `base` do
arquivo; eles não herdam do tema integrado do OpenCode nem um do outro.

Os exemplos abaixo mostram apenas as seções relevantes para cada conceito. Use o editor de temas para gerar um arquivo
completo antes de personalizá-lo.

### Estrutura

Coloque em `base` as cores usadas pelos dois modos e sobrescreva-as dentro de `light` ou `dark` quando necessário:

```json title="theme.json (excerpt)"
{
  "$schema": "https://opencode.ai/theme.json",
  "base": {
    "text": {
      "base": "$hue.neutral.200",
      "muted": "$hue.neutral.400"
    }
  },
  "light": {
    "hue": {}
  },
  "dark": {
    "hue": {},
    "text": {
      "muted": "$hue.neutral.300"
    }
  }
}
```

O `base` completo fornece todos os tokens semânticos. Cada modo fornece todos os matizes obrigatórios e pode sobrescrever
qualquer parte da árvore de tokens do `base`.

### Cores e referências

Uma cor pode ser um valor hexadecimal, `"transparent"` ou uma referência a outra cor do tema:

```json title="Inside base or a mode"
{
  "text": {
    "base": "#eeeeee",
    "muted": "$hue.neutral.400"
  },
  "border": {
    "base": "$text.muted"
  }
}
```

### Matizes

Matizes (hues) são escalas de cor com nove níveis. Todo modo define os oito matizes base e três aliases:

| Tipo | Valores |
| --- | --- |
| Base | `gray`, `red`, `orange`, `yellow`, `green`, `cyan`, `blue`, `purple` |
| Alias | `accent`, `interactive`, `neutral` |
| Nível | `100`, `200`, `300`, `400`, `500`, `600`, `700`, `800`, `900` |

Defina os nove níveis de um matiz base ou crie um alias de um matiz para outro:

```json title="Inside light or dark"
{
  "hue": {
    "purple": {
      "100": "#b38ff4",
      "200": "#9d7cd8",
      "300": "#8869bd",
      "400": "#7357a2",
      "500": "#5f4688",
      "600": "#4b356f",
      "700": "#392557",
      "800": "#271640",
      "900": "#17072b"
    },
    "accent": "$hue.purple"
  }
}
```

Os níveis dos matizes seguem a direção de contraste do modo. Temas claros vão do escuro em `100` ao claro em `900`;
temas escuros vão do claro em `100` ao escuro em `900`.

O array `categorical` em `base` define, em ordem, os matizes usados para distinguir agentes e outros itens repetidos:

```json title="Inside base"
{
  "categorical": ["accent", "purple", "green", "blue"]
}
```

### Tokens semânticos

Os tokens semânticos atribuem cores a papéis da interface. Os componentes usam esses papéis em vez de escolher cores
diretamente.

| Grupo | Finalidade |
| --- | --- |
| `text` | Texto base, atenuado, de ações, de campos de formulário, de status e de feedback. |
| `background` | Fundo base, superfícies elevadas, ações, campos de formulário e preenchimentos de feedback. |
| `border`, `scrollbar` | Cores de borda e da barra de rolagem. |
| `diff` | Cores de linhas adicionadas, removidas, de contexto, de destaque e dos números de linha. |
| `syntax` | Realce de código-fonte. |
| `markdown` | Elementos Markdown. |

Por exemplo, `text.muted` controla o texto secundário, enquanto `background.raised` define superfícies cada vez mais
elevadas:

```json title="Inside base"
{
  "text": {
    "base": "$hue.neutral.200",
    "muted": "$hue.neutral.400"
  },
  "background": {
    "base": "$hue.neutral.800",
    "raised": {
      "base": "$hue.neutral.700",
      "high": "$hue.neutral.600",
      "max": "$hue.neutral.500"
    }
  }
}
```

As chaves de sintaxe são `comment`, `keyword`, `function`, `variable`, `string`, `number`, `type`, `operator` e
`punctuation`.

As chaves de Markdown são `text`, `heading`, `link`, `linkText`, `code`, `blockQuote`, `emphasis`, `strong`,
`horizontalRule`, `listItem`, `listEnumeration`, `image`, `imageText` e `codeBlock`.

### Ações e estados

As ações têm as variantes `primary`, `secondary` e `destructive`. Ações e campos de formulário usam `base` e, opcionalmente,
estados de interação:

```json title="Inside base or a mode"
{
  "text": {
    "action": {
      "primary": {
        "base": "$hue.interactive.400",
        "$hovered": "$hue.interactive.300",
        "$disabled": "$hue.neutral.600"
      }
    }
  }
}
```

As chaves de estado são `$hovered`, `$focused`, `$pressed`, `$selected` e `$disabled`. Um estado não especificado usa a
cor `base` daquela ação ou daquele campo de formulário.

### Superfície de diálogos

Painéis, caixas de diálogo, menus e notificações (toasts) escolhem a profundidade a partir de `background.raised`. As
caixas de diálogo também podem sobrescrever tokens semânticos com `@dialog`:

```json title="Inside base or a mode"
{
  "@dialog": {
    "background": {
      "base": "$background.raised.base",
      "action": {
        "primary": {
          "$hovered": "$background.raised.high"
        }
      }
    }
  }
}
```

A TUI resolve as referências de novo depois de aplicar `@dialog`, então tokens que referenciam `$background.base`
acompanham o fundo da caixa de diálogo. O `base` de uma ação contextual passa a ser o fallback dos estados não
especificados dela; sobrescritas explícitas de estado continuam prevalecendo.
