Defina as variáveis de proxy padrão e exclua os endereços de loopback. O OpenCode usa conexões HTTP locais entre a CLI e
o serviço em segundo plano, então essa exclusão é obrigatória quando há um proxy configurado no ambiente da CLI.

```bash
export HTTP_PROXY=http://proxy.example.com:8080
export HTTPS_PROXY=http://proxy.example.com:8080
export NO_PROXY=localhost,127.0.0.1,::1

opencode
```

`HTTP_PROXY` atende destinos HTTP e `HTTPS_PROXY` atende destinos HTTPS. A URL do próprio proxy pode usar `http://` nas
duas variáveis. `NO_PROXY` é uma lista, separada por vírgulas, de hosts e endereços que se conectam diretamente, sem
passar pelo proxy.

## Serviço

Variáveis exportadas no shell só afetam o serviço em segundo plano quando ele é iniciado a partir desse shell. Persista as
variáveis na configuração do serviço gerenciado para que as próximas inicializações usem as mesmas configurações de rede.

```bash
opencode service set env HTTP_PROXY http://proxy.example.com:8080
opencode service set env HTTPS_PROXY http://proxy.example.com:8080
opencode service set env NO_PROXY localhost,127.0.0.1,::1
opencode service start
```

Alterar uma variável de ambiente gerenciada interrompe o serviço em execução. `service start` o inicia novamente com o
novo ambiente. Se o shell da CLI também define um proxy, mantenha `NO_PROXY` nele, porque as variáveis do serviço gerenciado
valem para o processo do servidor, não para o processo da CLI.

Para remover uma variável persistida, use `service unset env`:

```bash
opencode service unset env HTTPS_PROXY
```

## Autenticação

Se o proxy aceita credenciais na URL, inclua o usuário e a senha em cada URL de proxy que exige autenticação. Codifique
com percent-encoding caracteres como `@`, `:` e `/` no usuário ou na senha.

```bash
export HTTPS_PROXY='http://user:p%40ssword@proxy.example.com:8080'
```

Para o serviço em segundo plano, persista a URL completa. O valor fica armazenado na configuração privada do serviço e é
exibido por `opencode service get env`, então não compartilhe essa saída.

```bash
opencode service set env HTTPS_PROXY 'http://user:p%40ssword@proxy.example.com:8080'
```

## Certificados

Defina `NODE_EXTRA_CA_CERTS` com o caminho de um arquivo PEM quando o proxy ou o destino usar um certificado assinado por
uma autoridade certificadora privada. As autoridades extras são adicionadas ao repositório de confiança do runtime quando
o processo é iniciado.

```bash
export NODE_EXTRA_CA_CERTS=/etc/company/ca.pem
opencode --standalone
```

Persista o caminho do arquivo para o serviço em segundo plano e reinicie-o:

```bash
opencode service set env NODE_EXTRA_CA_CERTS /etc/company/ca.pem
opencode service start
```

## Primeiro plano

`--standalone` e `serve` usam o ambiente do próprio processo. `opencode service set env` não configura esses processos.

```bash
HTTP_PROXY=http://proxy.example.com:8080 \
HTTPS_PROXY=http://proxy.example.com:8080 \
NO_PROXY=localhost,127.0.0.1,::1 \
opencode --standalone
```

Use o mesmo padrão para um servidor em primeiro plano:

```bash
HTTPS_PROXY=http://proxy.example.com:8080 \
NO_PROXY=localhost,127.0.0.1,::1 \
opencode serve
```

## Verificar

Depois de aplicar as configurações, verifique se a CLI consegue acessar o serviço em segundo plano:

```bash
opencode api get /api/info
```

Uma resposta de health check bem-sucedida confirma a conexão local entre o cliente e o serviço. Para verificar o proxy de
saída e o caminho dos certificados do serviço, faça uma requisição normal a um provedor.
