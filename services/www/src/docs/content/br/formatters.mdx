---
title: "Formatadores"
---

O OpenCode pode formatar arquivos depois que as ferramentas `write`, `edit` ou `patch` os alteram. Os formatadores vêm
desativados por padrão, então ative-os na sua configuração:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "formatter": true,
}
```

## Ativar

Defina `formatter` como `true` para ativar todos os formatadores nativos. O OpenCode só executa um formatador nativo
quando o executável dele e os eventuais requisitos específicos do projeto estão disponíveis.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "formatter": true,
}
```

Um objeto também ativa os formatadores nativos e permite sobrescrevê-los ou adicionar formatadores personalizados. Um
objeto vazio preserva as configurações de formatadores herdadas, enquanto `true` as redefine para os formatadores
nativos.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "formatter": {},
}
```

## Nativos

O OpenCode inclui as definições de formatadores abaixo. A maioria exige que o comando indicado esteja disponível; as
definições com regras de detecção adicionais as listam na tabela.

| --- | --- | --- |
| `gofmt` | `.go` | Comando `gofmt` |
| `mix` | `.ex`, `.exs`, `.eex`, `.heex`, `.leex`, `.neex`, `.sface` | Comando `mix` |
| `oxfmt` | `.js`, `.jsx`, `.mjs`, `.cjs`, `.ts`, `.tsx`, `.mts`, `.cts` | Dependência `oxfmt` no `package.json` |
| `prettier` | `.js`, `.jsx`, `.mjs`, `.cjs`, `.ts`, `.tsx`, `.mts`, `.cts`, `.html`, `.htm`, `.css`, `.scss`, `.sass`, `.less`, `.vue`, `.svelte`, `.json`, `.jsonc`, `.yaml`, `.yml`, `.toml`, `.xml`, `.md`, `.mdx`, `.graphql`, `.gql` | Dependência `prettier` no `package.json` |
| `biome` | As mesmas extensões do `prettier` acima | `biome.json` ou `biome.jsonc` e um binário `@biomejs/biome` instalado |

Por exemplo, ao ativar os formatadores nativos, o OpenCode pode descobrir e executar uma dependência local do Prettier no
projeto para os arquivos correspondentes:

```jsonc title="opencode.jsonc"
{
  "formatter": true,
}
```

## Personalizar

Adicione uma entrada nomeada para alterar um formatador nativo ou definir um formatador personalizado. Um formatador
personalizado precisa de `command` e de `extensions` para ser executado.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "formatter": {
    "prettier": {
      "environment": {
        "NODE_ENV": "development",
      },
      "extensions": [".js", ".ts"],
    },
    "deno-markdown": {
      "command": ["deno", "fmt", "$FILE"],
      "extensions": [".md"],
    },
  },
}
```

| Campo | Tipo | Comportamento |
| --- | --- | --- |
| `disabled` | `boolean` | Remove o formatador nomeado quando `true`. |
| `command` | `string[]` | Substitui o comando nativo ou define um comando personalizado. |
| `environment` | `Record<string, string>` | Adiciona variáveis de ambiente, preservando o ambiente do processo pai. |
| `extensions` | `string[]` | Substitui a lista de extensões nativa ou define a lista personalizada. Inclua o ponto inicial. |

Todos os campos são opcionais. Uma entrada nativa herda os valores omitidos, enquanto uma entrada nova sem comando ou
sem extensões não pode ser executada.

```jsonc title="opencode.jsonc"
{
  "formatter": {
    "prettier": {
      "extensions": [".md", ".mdx"],
    },
  },
}
```

## Comandos

`command` é um array de argumentos, não uma string de comando de shell. O OpenCode substitui `$FILE` pelo caminho
absoluto do arquivo e executa o comando a partir do diretório do projeto ativo.

```jsonc title="opencode.jsonc"
{
  "formatter": {
    "custom": {
      "command": ["custom-fmt", "--write", "$FILE"],
      "extensions": [".custom"],
    },
  },
}
```

## Correspondência

O OpenCode compara a extensão final do arquivo com `extensions`. A correspondência diferencia maiúsculas de minúsculas,
e entradas compostas como `.part.md` não correspondem a `notes.part.md`, porque a extensão final desse arquivo é `.md`.

```jsonc title="opencode.jsonc"
{
  "formatter": {
    "markdown": {
      "command": ["deno", "fmt", "$FILE"],
      "extensions": [".md"],
    },
  },
}
```

Quando vários formatadores correspondem, o OpenCode os tenta na ordem de registro e para depois do primeiro comando
bem-sucedido. Os formatadores nativos mantêm a ordem nativa; as entradas personalizadas vêm em seguida, na ordem do
objeto. Se um deles terminar sem sucesso, o OpenCode registra a falha no log e tenta a próxima correspondência.

```jsonc title="opencode.jsonc"
{
  "formatter": {
    "preferred": {
      "command": ["preferred-fmt", "$FILE"],
      "extensions": [".foo"],
    },
    "fallback": {
      "command": ["fallback-fmt", "$FILE"],
      "extensions": [".foo"],
    },
  },
}
```

## Desativar

A formatação fica desativada quando nenhum arquivo de configuração define `formatter`. Para desativar a formatação que
um arquivo de prioridade menor ativou, defina-o como `false`.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "formatter": false,
}
```

Para desativar um formatador nativo e manter os demais ativos, marque a entrada nomeada dele como desativada.

```jsonc title="opencode.jsonc"
{
  "formatter": {
    "prettier": {
      "disabled": true,
    },
  },
}
```
