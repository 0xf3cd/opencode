title: "Agentes"
---

Crie um arquivo Markdown para adicionar um agente reutilizável. Este exemplo adiciona um revisor somente leitura que o
agente principal pode acionar para revisar código:

```md title=".opencode/agents/reviewer.md"
---
description: Reviews changes for correctness and regressions
mode: subagent
model: anthropic/claude-sonnet-4-5#high
permissions:
  - action: edit
    resource: "*"
    effect: deny
  - action: shell
    resource: "*"
    effect: deny
---

Review the current changes. List findings in severity order with file and line references.
```

Peça ao seu agente primário que o use:

```text
Use the reviewer subagent to review my current changes.
```

Um agente reúne um prompt de sistema, uma preferência de modelo, permissões e detalhes de exibição em um perfil de
assistente com nome.

## Locais

Salve agentes em Markdown globalmente, para todos os projetos, ou dentro de um projeto:

```text
~/.config/opencode/agents/<name>.md
.opencode/agents/<name>.md
```

O OpenCode descobre os diretórios `.opencode` do projeto a partir do diretório atual até a raiz do projeto. Um caminho
aninhado passa a fazer parte do ID do agente:

```text
.opencode/agents/team/reviewer.md  →  team/reviewer
```

## Formatos

### Markdown

O frontmatter aceita os mesmos campos de uma entrada da configuração `agents`. O corpo em Markdown vira o prompt
`system` do agente:

```md title=".opencode/agents/explainer.md"
---
description: Explains code without changing it
mode: subagent
---

Explain the relevant code with short examples. Do not edit files.
```

### JSONC

Defina agentes em `agents` em qualquer [arquivo de configuração do OpenCode](/config):

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "agents": {
    "reviewer": {
      "description": "Reviews current changes",
      "mode": "subagent",
      "system": "Report findings in severity order.",
      "permissions": [
        { "action": "edit", "resource": "*", "effect": "deny" },
      ],
    },
  },
}
```

## Seleção

Defina o agente primário usado quando uma sessão ainda não selecionou nenhum:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "default_agent": "writer",
  "agents": {
    "writer": { "mode": "primary" },
  },
}
```

O padrão selecionado precisa existir, estar visível e poder ser usado como primário. Caso contrário, o OpenCode usa
`build` e, depois, o primeiro agente visível que possa ser primário. Alterar essa configuração não substitui o agente
salvo em uma sessão existente.

## Modos

Defina `mode` de acordo com onde o agente deve ser executado:

```jsonc
{
  "agents": {
    "reviewer": { "mode": "subagent" },
  },
}
```

| Modo | Comportamento |
| --- | --- |
| `primary` | É executado como agente principal de uma sessão. É o padrão para um novo agente personalizado. |
| `subagent` | É executado apenas em uma sessão filha, pela ferramenta `subagent`. |
| `all` | Pode ser executado como agente primário ou como subagente. |

Os subagentes são executados com contexto novo, em sessões filhas em primeiro ou segundo plano. As permissões
`subagent` do agente pai controlam quais agentes ele pode acionar; o filho usa as próprias permissões configuradas.

```jsonc
{
  "agents": {
    "orchestrator": {
      "permissions": [
        { "action": "subagent", "resource": "*", "effect": "deny" },
        { "action": "subagent", "resource": "reviewer", "effect": "allow" },
      ],
    },
  },
}
```

## Agentes integrados

O OpenCode inclui estes agentes visíveis:

| Agente | Modo | Finalidade |
| --- | --- | --- |
| **Build** (`build`) | `primary` | Agente de programação padrão. As ferramentas são permitidas por padrão; leituras de arquivos de ambiente sensíveis e acessos fora do workspace pedem aprovação. |
| **Plan** (`plan`) | `primary` | Explora e planeja sem editar os arquivos normais do projeto. Pode gravar arquivos de plano do OpenCode quando solicitado, e os comandos de shell continuam sujeitos a permissão. |
| **General** (`general`) | `subagent` | Cuida de pesquisas e tarefas de várias etapas com amplo acesso a ferramentas, mas não pode acionar outros subagentes. |
| **Explore** (`explore`) | `subagent` | Pesquisa e lê código ou fontes da web sem editar arquivos. |

Para sobrescrever um agente integrado, use o mesmo ID:

```jsonc
{
  "agents": {
    "build": {
      "permissions": [
        { "action": "shell", "resource": "git push *", "effect": "ask" },
      ],
    },
  },
}
```

Os agentes ocultos `compaction`, `title` e `summary` cuidam de tarefas de manutenção e não podem ser selecionados
diretamente. A V2 não tem um agente integrado `scout`.

## Mesclagem

As definições de agentes são mescladas na ordem da configuração. Valores escalares posteriores substituem os anteriores,
mapas de requisição são mesclados por chave e regras de permissão são acrescentadas:

```jsonc
{
  "permissions": [
    { "action": "shell", "resource": "*", "effect": "ask" },
  ],
  "agents": {
    "build": {
      "permissions": [
        { "action": "shell", "resource": "git status", "effect": "allow" },
      ],
    },
  },
}
```

As `permissions` globais são aplicadas antes das regras específicas do agente, então as regras do agente, que vêm
depois, podem refiná-las.

## Opções

### Descrição

`description` explica a finalidade do agente. Adicione-a aos subagentes, porque o OpenCode a mostra ao modelo que
escolhe qual agente acionar:

```yaml
description: Reviews database migrations for safety
```

### Modo

`mode` aceita `primary`, `subagent` ou `all`. Quando omitido em um novo agente personalizado, o padrão é `primary`:

```yaml
mode: all
```

### Modelo

`model` usa o formato `provider/model`, com um `#variant` opcional:

```yaml
model: anthropic/claude-sonnet-4-5#high
```

A configuração em JSON também aceita a forma expandida:

```jsonc
{
  "agents": {
    "reviewer": {
      "model": {
        "providerID": "anthropic",
        "model": "claude-sonnet-4-5",
        "variant": "high",
      },
    },
  },
}
```

- Um subagente usa o modelo configurado ou, se não houver nenhum, herda o modelo da sessão pai.
- Uma sessão guarda o modelo selecionado separadamente. Selecionar um agente primário pelo ID não muda esse modelo.

### Prompt de sistema

`system` define o prompt de sistema do agente. Um valor não vazio substitui o prompt base do provedor para esse agente:

```jsonc
{
  "agents": {
    "reviewer": { "system": "Review only. Do not modify files." },
  },
}
```

As instruções do projeto, as skills, as referências e as demais fontes de instruções continuam sendo adicionadas. Em um
agente em Markdown, coloque esse texto no corpo do documento, e não em um campo `system` do frontmatter.

### Permissões

`permissions` é uma lista ordenada de regras de correspondência:

```jsonc
{
  "agents": {
    "reviewer": {
      "permissions": [
        { "action": "*", "resource": "*", "effect": "deny" },
        { "action": "read", "resource": "src/**", "effect": "allow" },
      ],
    },
  },
}
```

| Campo | Significado |
| --- | --- |
| `action` | Ferramenta ou ação de permissão. Aceita curingas. |
| `resource` | Caminho, comando, ID de agente ou outro valor comparado pela ação. Aceita curingas. |
| `effect` | `allow`, `ask` ou `deny`. |

A última regra correspondente prevalece, então coloque as regras amplas antes das exceções. Ações comuns:

| Ação | Abrange |
| --- | --- |
| `shell` | Comandos de shell |
| `edit` | Ferramentas de edição, escrita e patch |
| `subagent` | Agentes filhos |
| `read`, `glob`, `grep` | Ferramentas de descoberta local |
| `webfetch`, `websearch` | Ferramentas da web |
| `skill` | Carregamento de skills |

Nos recursos de `read`, `edit` e `external_directory`, o OpenCode expande `~` e `$HOME`:

```jsonc
{ "action": "read", "resource": "~/notes/**", "effect": "allow" }
```

Os recursos de shell continuam sendo o texto bruto do comando e não expandem esses valores.

### Etapas

`steps` define um número máximo positivo de etapas do modelo:

```yaml
steps: 8
```

Na última etapa, o OpenCode remove as ferramentas e pede ao modelo que faça um resumo em texto. Uma nova entrada do
usuário reinicia a contagem.

### Oculto

`hidden` remove um agente das listagens normais, da descoberta interativa e do catálogo de subagentes:

```yaml
hidden: true
```

Isso controla a visibilidade, não a segurança. Use permissões para restringir o comportamento.

### Cor

`color` define a cor do agente na interface, usando um valor hexadecimal de seis dígitos:

```yaml
color: "#ff6b6b"
```

### Desativado

`disabled` remove um agente integrado ou personalizado naquele ponto do carregamento da configuração:

```jsonc
{
  "agents": {
    "plan": { "disabled": true },
  },
}
```

### Requisição

`request` aceita sobreposições de headers e de corpo JSON por agente:

```jsonc
{
  "agents": {
    "reviewer": {
      "request": {
        "headers": { "x-agent": "reviewer" },
        "body": { "temperature": 0.1 },
      },
    },
  },
}
```

<Callout type="warning">
  O executor de sessões da V2 preserva esses valores, mas ainda não os envia nas requisições ao modelo. Configure as
  opções de requisição efetivas no provedor, no modelo ou na variante do modelo.
</Callout>

Não use campos legados de nível superior, como `temperature`, `top_p`, `prompt`, `permission`, `tools`, `disable` ou
`maxSteps`, em configurações de agentes novas da V2.
