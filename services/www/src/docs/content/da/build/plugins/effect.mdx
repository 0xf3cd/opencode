---
title: "Effect"
---

`@opencode/plugin/effect` er den Effect-native version af OpenCodes plugin-API. Operationerne på konteksten returnerer
Effects eller Streams, callbacks returnerer Effects, og pluginets levetid repræsenteres af et `Scope`.

OpenCode leverer `effect` (inklusive eksporterede `effect/*`-understier) og `@opencode/plugin` i runtime, når plugins og
deres `node_modules`-afhængigheder indlæses. Installer dem som peer-/dev-afhængigheder til lokal typekontrol og test i
stedet for at bundle dem i dit plugin.

```sh
bun add --peer @opencode/plugin effect
```

Eksporter et Effect-plugin fra `.opencode/plugins/`, så indlæses det automatisk.

```ts title=".opencode/plugins/concise/index.ts"
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "example",
  effect: (ctx) =>
    Effect.gen(function* () {
      const storage = ctx.storage
      yield* storage.set("loaded", true)
    }),
})
```

Udgivne pakker og plugin-mapper uden for `.opencode/plugins/` bruger samme `plugins`-konfiguration som andre
serverplugins.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": [
    "opencode-acme-effect-plugin",
    "opencode-acme-effect-plugin@1.2.0",
    "@acme/opencode-effect-plugin",
    "./plugins/local-effect",
    {
      "package": "@acme/opencode-effect-plugin",
      "options": { "agent": "reviewer", "strict": true },
    },
  ],
}
```

Se [Konfigurer plugins](/plugins) for aktivering, pakkeopløsning og konfigurationens prioritet.

```ts title="plugins/local-effect/index.ts"
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "local-effect",
  effect: (ctx) =>
    Effect.gen(function* () {
      yield* Effect.logInfo("Effect plugin loaded", { version: ctx.app.version })
    }),
})
```

## Livscyklus

`effect` kører, når pluginet indlæses. Dets scope lukkes, når pluginet genindlæses eller fjernes, så registreringer,
scopede fibers og finalizers frigives samlet.

```ts
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "lifecycle",
  effect: (ctx) =>
    Effect.gen(function* () {
      yield* Effect.logInfo("loaded", { version: ctx.app.version })
      yield* Effect.addFinalizer(() => Effect.logInfo("unloaded"))
    }),
})
```

Brug scopede fibers til baggrundsarbejde. Pluginets scope afbryder fiberen under oprydningen.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const storage = ctx.storage
    yield* Effect.repeat(
      storage.set("heartbeat", { time: Date.now() }),
      { schedule: Schedule.spaced("1 minute") },
    ).pipe(Effect.forkScoped)
  }),
```

### Kontekst

Konteksten giver adgang til Effect-klienten for den tilsluttede OpenCode-server samt transformationer, hooks, lager,
genindlæsning og indstillinger, der kun findes for plugins. Den giver ikke adgang til OpenCodes private Core-tjenester.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const plugins = ctx.plugin
    const active = yield* plugins.list().pipe(Effect.orDie)
    yield* Effect.logInfo("active plugins", { count: active.data.length })
  }),
```

Plugindefinitionen og den komplette kontekst er erklæret sådan her.

## Transformationer

Transformationer redigerer tilstand synkront via en editor. OpenCode anvender transformationer i
registreringsrækkefølge inden for hvert domæne. Først bidrager kilder med udbydere og uforanderlige modeldefinitioner;
derefter redigerer modeltransformationer kandidaterne fra de aktive udbydere. Når du yielder registreringen, bliver den
i pluginets scope.

```ts title="plugins/models-effect/index.ts"
import { Model, Plugin, Provider } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "company.models",
  effect: (ctx) =>
    Effect.gen(function* () {
      const providerID = Provider.ID.make("acme")
      const models = [{ ...Model.Info.default(providerID, Model.ID.make("reasoner")), name: "Acme Reasoner" }]
      yield* ctx.provider.transform((editor) => {
        editor.add({
          info: {
            ...Provider.Info.empty(providerID),
            name: "Acme",
            activation: "enabled",
            package: "@opencode/ai/providers/openai-compatible",
            settings: { baseURL: "http://127.0.0.1:8000/v1" },
          },
          models,
        })
      })
    }),
})
```

En modeltransformation kan håndhæve en politik på tværs af hele samlingen af kandidater fra aktive udbydere.

```ts title="plugins/model-budget-effect/index.ts"
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.model.transform((editor) => {
      editor
        .list()
        .filter((model) => model.cost.some((tier) => tier.output > 20))
        .forEach((model) => {
          editor.remove(model.providerID, model.id)
        })
    })
  }),
```

Kald `reload`, når ekstern tilstand, som en transformation bruger, ændrer sig. Her returnerer `loadFromSource()`
`{ info: Provider.Info, models: readonly Model.Info[] }`-poster; genindlæsning af udbydere ugyldiggør også hele
modelresultatet.

```ts title="plugins/models-effect/index.ts"
effect: (ctx) =>
  Effect.gen(function* () {
    const provider = ctx.provider
    const source = { providers: yield* loadFromSource() }

    yield* provider.transform((editor) => {
      source.providers.forEach((provider) => editor.add(provider))
    })

    yield* Effect.repeat(
      Effect.gen(function* () {
        source.providers = yield* loadFromSource()
        yield* provider.reload()
      }),
      { schedule: Schedule.spaced("1 minute") },
    ).pipe(Effect.forkScoped)
  }),
```

## API

### Agent

Læs alle agenter, eller hent én efter ID. Klientsvar indeholder den opløste placering og schemadata.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const agent = ctx.agent
    const agents = yield* agent.list().pipe(Effect.orDie)
    const build = yield* agent.get({ agentID: Agent.ID.make("build") }).pipe(Effect.orDie)
    yield* Effect.logInfo("agents", { count: agents.data.length, build: build.data.name })
  }),
```

Transformer eller genindlæs agenter.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const agent = ctx.agent
    yield* agent.transform((editor) => {
      editor.default("build")
      editor.update("build", (item) => (item.description = "Builds features and fixes bugs"))
      editor.remove("legacy")
    })
    yield* agent.reload()
  }),
```

Schema: [`Agent.Info`](/api#schema-Agent.Info).

```ts
interface AgentEditor {
  list(): readonly Types.DeepMutable<Agent.Info>[]
  get(id: string): Types.DeepMutable<Agent.Info> | undefined
  default(id: string | undefined): void
  update(id: string, update: (agent: Types.DeepMutable<Agent.Info>) => void): void
  remove(id: string): void
}

interface AgentDomain extends AgentApi<unknown> {
  readonly transform: Transform<AgentEditor>
  readonly reload: () => Effect.Effect<void>
}
```

### Udbydere

Læs tilgængelige udbydere, eller se metadata for én udbyder efter ID.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const provider = ctx.provider
    const providers = yield* provider.list().pipe(Effect.orDie)
    const anthropic = yield* provider.get({ providerID: Provider.ID.make("anthropic") }).pipe(Effect.orDie)
    yield* Effect.logInfo("providers", {
      providers: providers.data.length,
      anthropic: anthropic.data.name,
    })
  }),
```

Udbydertransformationer redigerer udbyderindstillinger og kildedefinitioner. Læsninger i editoren omfatter inaktive
udbydere og viser uforanderlige definitioner; `models.update` redigerer en egen kopi af en kildemodel.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.provider.transform((editor) => {
      editor.update("anthropic", (provider) => {
        provider.headers = { ...provider.headers, "x-company": "engineering" }
      })
      editor.models.update("anthropic", "claude-sonnet-4-5", (model) => (model.name = "Team Sonnet"))
      editor.models.remove("anthropic", "legacy-model")
      editor.remove("legacy-provider")
    })
  }),
```

Erstat en kildes modelbeholdning med `models.set`, og genindlæs, når de indfangede definitioner ændrer sig.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const provider = ctx.provider
    const source = { models: yield* loadModels() }
    yield* provider.transform((editor) => editor.models.set("acme", source.models))
    source.models = yield* loadModels()
    yield* provider.reload()
  }),
```

Ved kontospecifik opdagelse skal du angive den forbindelse, der blev brugt til at indlæse beholdningen, som
`sourceConnection`. OpenCode udelukker udbyderen, mens en anden forbindelse er valgt, indtil dit plugin udgiver sin
opdaterede beholdning.

```ts
const connection = yield * ctx.integration.connection.active("acme")
if (!connection) return
const inventory = yield * loadInventory(connection)
yield *
  ctx.provider.transform((editor) => {
    editor.add({ info: inventory.provider, models: inventory.models, sourceConnection: connection })
  })
```

Schemaer: [`Provider.Info`](/api#schema-Provider.Info), [`Model.Info`](/api#schema-Model.Info).

```ts
interface ProviderRecord {
  readonly provider: Provider.Info
  readonly models: ReadonlyMap<string, Model.Info>
  readonly sourceConnection?: ConnectionInfo
}

interface ProviderEditor {
  list(): readonly ProviderRecord[]
  get(providerID: string): ProviderRecord | undefined
  add(input: { info: Provider.Info; models: readonly Model.Info[]; sourceConnection?: ConnectionInfo }): void
  update(providerID: string, update: (provider: Types.DeepMutable<Provider.Info>) => void): void
  remove(providerID: string): void
  readonly models: {
    set(providerID: string, models: readonly Model.Info[]): void
    update(providerID: string, modelID: string, update: (model: Types.DeepMutable<Model.Info>) => void): void
    remove(providerID: string, modelID: string): void
  }
}

interface ProviderDomain extends ProviderApi<unknown> {
  readonly transform: Transform<ProviderEditor>
  readonly reload: () => Effect.Effect<void>
}
```

### Modeller

Læs tilgængelige modeller og standardvalget.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const model = ctx.model
    const models = yield* model.list().pipe(Effect.orDie)
    const selected = yield* model.default().pipe(Effect.orDie)
    yield* Effect.logInfo("models", { count: models.data.length, selected: selected.data?.name })
  }),
```

Modeltransformationer redigerer hele samlingen af kandidater fra aktive udbydere. Deaktiverede kandidater kan stadig
redigeres, indtil alle transformationer er færdige; `update` kan kun tilføje en model under en tilgængelig udbyder.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.model.transform((editor) => {
      editor.list("anthropic").forEach((model) => {
        editor.update(model.providerID, model.id, (draft) => {
          draft.enabled = draft.capabilities.tools
        })
      })
      editor.default.set("anthropic", "claude-sonnet-4-5")
      editor.remove("anthropic", "legacy-model")
    })
  }),
```

Callbacks redigerer rå modeltilsidesættelser. Udbyderens standardværdier flettes ind én gang, når OpenCode gemmer
resultatet; uændrede læsninger genbruger det resultat. `editor.provider` læser uforanderlige kildedefinitioner,
inklusive inaktive skabeloner, og ikke output fra modeltransformationer.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const model = ctx.model
    yield* model.transform((editor) => {
      const source = editor.provider.get("anthropic")?.models.get("claude-sonnet-4-5")
      if (!source) return
      editor.update("anthropic", source.id, (draft) => {
        draft.limit.context = Math.min(draft.limit.context, source.limit.context)
      })
    })
    yield* model.reload()
  }),
```

Schema: [`Model.Info`](/api#schema-Model.Info).

```ts
interface ModelEditor {
  list(providerID?: string): readonly Types.DeepMutable<Model.Info>[]
  get(providerID: string, modelID: string): Types.DeepMutable<Model.Info> | undefined
  update(providerID: string, modelID: string, update: (model: Types.DeepMutable<Model.Info>) => void): void
  remove(providerID: string, modelID: string): void
  readonly default: {
    get(): { providerID: string; modelID: string } | undefined
    set(providerID: string, modelID: string): void
  }
  readonly provider: {
    list(): readonly ProviderRecord[]
    get(providerID: string): ProviderRecord | undefined
  }
}

  readonly transform: Transform<ModelEditor>

}
```

### Kommandoer

Læs de kommandoer, der er tilgængelige på den aktuelle placering.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const command = ctx.command
    const commands = yield* command.list().pipe(Effect.orDie)
    yield* Effect.logInfo("commands", { names: commands.data.map((item) => item.name) })
  }),
```

Den nuværende kommandotransformation kan kun tilføje. En executor modtager sessionen, promptens vedhæftninger og
leveringstilstanden.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const command = ctx.command
    const session = ctx.session
    yield* command.transform((editor) => {
      editor.add({
        name: "security-review",
        description: "Review changes for security issues",
        execute: (input) =>
          session.prompt({
            ...input.prompt,
            sessionID: input.sessionID,
            text: `Review these changes for security issues.\n\n${input.prompt.text}`,
            delivery: input.delivery,
          }).pipe(Effect.asVoid),
      })
    })
    yield* command.reload()
  }),
```

Schemaer: [`Command.Info`](/api#schema-Command.Info),
[`Session.Inbox.Delivery`](/api#schema-Session.Inbox.Delivery).

### Integrationer

Læs integrationer, og opløs de aktive legitimationsoplysninger, hvis der findes nogen.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const integration = ctx.integration
    const integrations = yield* integration.list().pipe(Effect.orDie)
    const github = yield* integration.get({ integrationID: Integration.ID.make("github") }).pipe(Effect.orDie)
    const connection = yield* integration.connection.active("github")
    const credential = connection ? yield* integration.connection.resolve(connection).pipe(Effect.orDie) : undefined
    yield* Effect.logInfo("integration", {
      count: integrations.data.length,
      github: github.data.name,
      credential: credential?.type,
    })
  }),
```

Opret forbindelse med en nøgle, eller gennemfør et OAuth-forsøg via det tilsluttede API.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const integration = ctx.integration
    const token = yield* Config.Redacted("GITHUB_TOKEN").pipe(Effect.orDie)
    yield* integration.connect
      .key({ integrationID: Integration.ID.make("github"), key: Redacted.value(token) })
      .pipe(Effect.orDie)

    const attempt = yield* integration.oauth
      .connect({
        integrationID: Integration.ID.make("acme"),
        methodID: Integration.MethodID.make("oauth"),
      })
      .pipe(Effect.orDie)
    const status = yield* integration.oauth
      .status({
        integrationID: Integration.ID.make("acme"),
        attemptID: attempt.data.attemptID,
      })
      .pipe(Effect.orDie)
    yield* Effect.logInfo("OAuth status", { status: status.data })
  }),
```

Transformer integrationer og godkendelsesmetoder. Callbacks i OAuth-metoder er Effects og kan erhverve scopede
ressourcer.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const integration = ctx.integration
    yield* integration.transform((editor) => {
      editor.update("acme", (item) => (item.name = "Acme"))
      editor.method.update({
        integrationID: "acme",
        method: { id: "device", type: "oauth", label: "Sign in with Acme" },
        authorize: () =>
          Effect.succeed({
            mode: "code",
            url: "https://acme.example/device",
            instructions: "Enter the displayed code",
            callback: (code) => exchangeCode(code),
          }),
      })
    })
    yield* integration.reload()
  }),
```

Schemaer: [`Integration.Info`](/api#schema-Integration.Info), [`Integration.Method`](/api#schema-Integration.Method),
[`Connection.Info`](/api#schema-Connection.Info), [`Form.Answer`](/api#schema-Form.Answer).


### MCP

Vis MCP-servere og deres aktuelle forbindelsestilstand.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const mcp = ctx.mcp
    const servers = yield* mcp.list().pipe(Effect.orDie)
    yield* Effect.logInfo("MCP servers", { count: servers.data.length })
  }),
```

Plugins administrerer kun MCP-servere via transformationer. Brug `editor.set` til at tilføje eller erstatte en server,
`editor.update` til at ændre dens konfiguration og `editor.remove` til at fjerne den. Se konfigurationen med
`editor.list` og `editor.get`.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const mcp = ctx.mcp
    yield* mcp.transform((editor) => {
      const servers = editor.list()
      const docs = editor.get("docs")
      editor.set("docs", { type: "remote", url: "https://mcp.example.com" })
      editor.update("docs", (server) => (server.disabled = false))
      editor.remove("legacy")
    })
  }),
```

Sæt `disabled: true` i en transformation for at deaktivere en server og afbryde forbindelsen, eller `disabled: false`
for at aktivere den, så OpenCode kan oprette forbindelse. OpenCode afstemmer serverens livscyklus ud fra den
transformerede konfiguration.

Kald `reload()`, når ekstern tilstand, som en transformation bruger, har ændret sig, så transformationerne anvendes igen
og serverne afstemmes.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const mcp = ctx.mcp
    yield* mcp.reload()
  }),
```

Schemaer: [`Mcp.Server`](/api#schema-Mcp.Server), [`Mcp.LocalConfigEncoded`](/api#schema-Mcp.LocalConfigEncoded),
[`Mcp.RemoteConfigEncoded`](/api#schema-Mcp.RemoteConfigEncoded).

```ts
  update(name: string, update: (config: Types.DeepMutable<Mcp.ServerConfig>) => void): void
  remove(name: string): void
}

  readonly transform: Transform<MCPEditor>

```

### Plugins

Vis aktive, fejlede og opløste plugins på den aktuelle placering.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const plugin = ctx.plugin
    const plugins = yield* plugin.list().pipe(Effect.orDie)
    yield* Effect.forEach(plugins.data, (item) => Effect.logInfo("plugin", item), { discard: true })
  }),
```

Filtrer schemaværdierne i en Effect-pipeline, når kun aktive plugins er relevante.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const plugin = ctx.plugin
    const active = yield* plugin.list().pipe(
      Effect.orDie,
      Effect.map((result) => result.data.filter((item) => item.status === "active")),
    )
    yield* Effect.logInfo("active plugin count", { count: active.length })
  }),
```

Schemaer: [`Plugin.Info`](/api#schema-Plugin.Info), [`Plugin.Source`](/api#schema-Plugin.Source).

### Referencer

Læs de referencer, der er tilgængelige på den aktuelle placering.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const reference = ctx.reference
    const references = yield* reference.list().pipe(Effect.orDie)
    yield* Effect.logInfo("references", { count: references.data.length })
  }),
```

Tilføj eller fjern lokale referencer og Git-referencer, og genindlæs, når ekstern tilstand ændrer sig. `get(name)`
returnerer den aktuelt konfigurerede kilde eller `undefined`, hvis navnet ikke findes.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const reference = ctx.reference
    yield* reference.transform((editor) => {
      editor.add("handbook", { type: "local", path: "/workspace/docs/handbook" })
      editor.add("standards", { type: "git", repository: "https://github.com/acme/standards", branch: "main" })
      const handbook = editor.get("handbook")
      editor.remove("legacy")
    })
    yield* reference.reload()
  }),
```

Schemaer: [`Reference.Info`](/api#schema-Reference.Info), [`Reference.LocalSource`](/api#schema-Reference.LocalSource),

### Værktøjer

Registrer typede værktøjer med Effect `Schema`. Executoren modtager dekodet input og returnerer en Effect med typet
output, visningsindhold eller metadata.

Editoren understøtter `add`, `update` og `remove`. Transformationens callback er synkron: Den må ikke returnere en Effect
eller et Promise. Indlæs eksterne data, før du registrerer eller genindlæser. OpenCode afspiller de aktive
transformationer igen i registreringsrækkefølge på en frisk editor; for samme effektive værktøjsnavn tilsidesætter en
senere gyldig registrering en tidligere.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const tool = ctx.tool
    yield* tool.transform((editor) => {
      editor.namespace({
        name: "acme",
        description: "Customer account tools",
      })
      editor.add({
        name: "greeting",
        description: "Create a greeting",
        input: Schema.Struct({ name: Schema.String }),
        output: Schema.Struct({ greeting: Schema.String }),
        options: { namespace: "acme", codemode: true },
        execute: ({ name }, context) =>
          Effect.gen(function* () {
            yield* context.progress({ status: "greeting" })
            return { output: { greeting: `Hello ${name}!` } }
          }),
      })
    })
  }),
```

Kald `yield* ctx.tool.reload()`, når du har ændret kildedata, som callbacken har indfanget. Genindlæsning afspiller de
aktive transformationer igen uden at ændre deres rækkefølge; plugin-effekten køres ikke igen.

Værktøjer har et `id` med deres effektive navn, og `get()` returnerer `undefined`, hvis det ID ikke findes. Brug
`update` og `remove` med det effektive værktøjsnavn inklusive navnerum (`acme_greeting` ovenfor). Punktummer i navnerum
og ikke-understøttede tegn i værktøjsnavne bliver til `_`. Manglende navne ignoreres; et værktøj oprettes kun med `add`
og en komplet definition. Opdateringer bevarer navn og navnerum. Tildel nye schemaer eller indstillinger for at erstatte
dem i stedet for at ændre indlejrede værdier. Ugyldige opdateringer logges, og den tidligere definition forbliver uændret.

```ts
yield *
  ctx.tool.transform((editor) => {
    editor.update("acme_greeting", (tool) => {
      tool.description = "Greet the user by name"
    })
    editor.remove("acme_obsolete")
  })
```

Opdateringer og fjernelser afspilles igen i rækkefølge sammen med tilføjelser, også efter opdateringer af MCP-kataloget.

`transform` returnerer en scopet registrering. Kør `yield* registration.dispose` for at fjerne dens transformation og
genopbygge ud fra de resterende transformationer, så en eventuel tidligere definition, den tilsidesatte, kommer frem
igen. Frigivelse er idempotent, og når pluginets scope lukkes, frigives dets registreringer også.

Hver modelanmodning indfanger et snapshot af værktøjerne. Genindlæsning og frigivelse påvirker fremtidige snapshots,
ikke de definitioner eller executors, som en eksisterende anmodning allerede har indfanget. Executors, der lukker over
foranderlige plugindata, ser stadig de data; indfang en værdi inde i transformationen, når den skal forblive knyttet til
netop den definition.

Schemaer: [`Tool.Content`](/api#schema-Tool.Content), [`Tool.TextContent`](/api#schema-Tool.TextContent),
[`Tool.FileContent`](/api#schema-Tool.FileContent).

## Hooks

Hooks opfanger operationer, mens de kører. Flere plugins kan registrere samme hook; OpenCode kører dem i
plugin-rækkefølge, så senere hooks ser tidligere ændringer. Registreringer forbliver aktive, så længe pluginets scope
består.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook("context", () => Effect.void)
  }),
```

### Sessioner

Rediger de samlede systeminstruktioner, beskeder eller værktøjer lige før de sendes til modellen. `context` kører for
agent-løkken; `compaction`, `generate` og `title` kører for de tilsvarende hjælpeanmodninger. `compaction` og `title`
accepterer et `result`, der springer modelkaldet over.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook("context", (event) =>
      Effect.sync(() => {
        event.system.push({ type: "text", text: "Keep the review focused on correctness." })
        delete event.tools.write
      }),
    )
    yield* session.hook("compaction", (event) =>
      Effect.map(summarize(event.messages), (summary) => {
        event.result = { summary }
      }),
    )
  }),
```

Rediger indstillingerne for modelanmodningen, og afgræns eventuelt hooken til én udbyder. Hændelsen har samme `kind` som
HTTP-hooksene nedenfor.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook(
      "model.request",
      (event) => Effect.sync(() => (event.headers["x-plugin"] = "review")),
      { providerID: "anthropic" },
    )
  }),
```

Rediger udbyderens native anmodninger eller svar. Deres bodies er streams, der kun kan læses én gang; klon eller erstat
en body, før du læser den. Begge hooks kører for hver anmodning, en session sender; `event.kind` er `"primary"`,
`"compaction"`, `"title"` eller `"generate"`, afhængigt af hvilket flow der sendte den.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    const session = ctx.session
    yield* session.hook("http.request", (event) =>
      Effect.sync(() => {
        event.request.headers.set("x-session-id", event.sessionID)
        if (event.kind === "title") event.request.headers.set("x-priority", "background")
      }),
    )
    yield* session.hook("http.response", (event) =>
      Effect.sync(() => {
        event.response = new Response(event.response.body, {
          status: event.response.status,
          headers: { ...Object.fromEntries(event.response.headers), "x-plugin": "review" },
        })
      }),
    )
  }),
```

Udbydere, der streamer over en WebSocket, genbruger én forbindelse pr. session, så HTTP-hooksene ser aldrig den trafik.
Den eksperimentelle hook `experimental.ws.handshake` kører én gang pr. modelkald, før forbindelsen vælges, og giver
adgang til forbindelsens `url` og `headers`; ændrer du en af dem, åbnes socketten igen. HTTP-hooks kører stadig for
enhver anmodning, som en WebSocket-rute falder tilbage til.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.session.hook(
      "experimental.ws.handshake",
      (event) =>
        Effect.gen(function* () {
          event.headers.authorization = `Bearer ${yield* mintToken(event.url)}`
          delete event.headers["api-key"]
        }),
      { providerID: "azure" },
    )
  }),
```

`experimental.ws.send` og `experimental.ws.receive` giver adgang til selve rammerne: `send` kører, efter at udbyderens
driver har bygget en udgående ramme, og `receive` kører på hver indgående ramme, før driveren ser den. Det, `frame`
indeholder, når hooken returnerer, er det, der sendes over forbindelsen eller når driveren; OpenCode validerer det ikke.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.session.hook(
      "experimental.ws.send",
      (event) =>
        Effect.sync(() => {
          const body = JSON.parse(event.frame)
          if (body.type === "response.create") body.metadata = { ...body.metadata, session: event.sessionID }
          event.frame = JSON.stringify(body)
        }),
      { providerID: "openai" },
    )
  }),
```

Tilsidesæt beslutningen om genforsøg ved en udbyderfejl, eller erstat forsinkelsen i millisekunder. Hooken kører, efter
at OpenCode har klassificeret fejlen og foreslået sin politik, men før et genforsøg planlægges. Den viser ikke, hvordan
OpenCode internt udfører næste forsøg.

```ts
effect: (ctx) =>
  Effect.gen(function* () {
    yield* ctx.session.hook("retry", (event) =>
      Effect.sync(() => {
        if (event.error.status === 429) {
          event.decision = { retry: true, delay: 10_000 }
          return
        }
        if (event.error.type === "provider.invalid-request" && event.attempt === 2) {
          event.decision = { retry: true, delay: 0 }
          return
        }
        if (event.attempt >= 3) event.decision = { retry: false }
      }),
    )
  }),
```

Den oprindelige `decision` er OpenCodes politik, så hooks kan gøre en udbyderfejl, der normalt er endelig, mulig at
prøve igen eller nedlægge veto mod et foreslået genforsøg. Flere hooks kører i registreringsrækkefølge, og senere hooks
ser den aktuelle beslutning. Det indbyggede maksimale antal forsøg er fortsat en hård grænse. `attempt` er det fysiske
forsøg, der foreslås; den første anmodning er forsøg `1`, så første genforsøg er forsøg `2`. Ugyldige forsinkelser
(`NaN`, uendelig eller negative værdier) falder tilbage til den beregnede forsinkelse. Gendannelse efter overløb af
konteksten håndteres separat, fordi den komprimerer samtalen i stedet for at gentage samme anmodning.

```ts
interface ToolFailures extends Record<keyof ToolHooks, unknown> {
  readonly "execute.before": Tool.Error
  readonly "execute.after": never
}

interface ToolHookDomain {
  readonly hook: Hooks<ToolHooks, ToolFailures>
}
```

De fælles registreringstyper viser, hvilke operationer der kræver pluginets scope.

```ts
interface Registration {
  readonly dispose: Effect.Effect<void>
}

type Hooks<Spec, Failures extends Record<keyof Spec, unknown> = Record<keyof Spec, never>> = <Name extends keyof Spec>(
  name: Name,
  callback: (input: Spec[Name]) => Effect.Effect<void, Failures[Name]>,
) => Effect.Effect<Registration, never, Scope.Scope>

type Transform<Input> = (callback: (input: Input) => void) => Effect.Effect<Registration, never, Scope.Scope>
```

## Udgiv

Et pakkeplugin bruger samme standardeksport som et lokalt Effect-plugin. Eksporter Effect-implementeringen fra
hovedindgangspunktet, og erklær `effect` som `peerDependency`.

```json title="package.json"
{
  "name": "opencode-acme-effect-plugin",
  "version": "1.0.0",
  "type": "module",
  "exports": {
    ".": "./src/index.ts"
  },
  "dependencies": {
    "@opencode/plugin": "latest"
  },
  "peerDependencies": {
    "effect": "^4.0.0"
  }
}
```

OpenCode omdirigerer imports af `effect`, eksporterede `effect/*`-understier og `@opencode/plugin` (inklusive imports fra
afhængigheder i pluginets `node_modules`) til værtens runtime-instanser, så fibers, loggere og `Schema`-parsere deler én
runtime-kopi.

- Bundle ikke `effect` ind i det udgivne plugin-artefakt. Hvis du bygger med en bundler, skal du markere `effect` og
  `effect/*` som eksterne.
- Plugins og deres `node_modules`-afhængigheder kører altid mod `effect`-instansen i værtens OpenCode-version. Brug
  `effect`-API'er og modulstier, der er kompatible med den OpenCode-version, du målretter; afhængigheder, der er bygget
  på en anden `effect`-hovedversion (f.eks. Effect 3), får også værtens `effect` og understøttes ikke.
- Kun offentlige `effect`-understier leveres. Et plugin, der importerer et af Effects private `internal`-moduler, kan
  ikke indlæses og giver en fejl, der nævner stien.
- Den kompilerede OpenCode-binærfil indeholder ikke de Scalar- og Swagger UI-ressourcer, som Effects
  HTTP API-dokumentationssider bruger; serveres de sider fra et plugin, vises en meddelelse i stedet.

Pakkens indgangspunkt eksporterer `Plugin.define` med en `effect`-funktion.

```ts title="src/index.ts"
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "acme.published",
  effect: (ctx) =>
    Effect.gen(function* () {
      const storage = ctx.storage
      yield* storage.set("installed", true)
    }),
})
```

Brug versioner, der er kompatible med den OpenCode-version, du målretter, og test den installerede pakke i stedet for kun
en kopi, der er linket i dit arbejdsområde.

```sh
bun pm pack
bun add ./opencode-acme-effect-plugin-1.0.0.tgz
```
