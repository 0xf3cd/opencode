title: "Udbydere"

OpenCode indeholder et katalog over udbydere og modeller fra [models.dev](https://models.dev). For de fleste udbydere skal
du først forbinde en konto og derefter vælge en model.

## Opsætning

Kør `/connect`, vælg en udbyder, og indtast dens legitimationsoplysninger. Kør derefter `/models` for at vælge en af
dens modeller.

```text
/connect
/models
```

## Go

[OpenCode Go](/console/go) er et valgfrit abonnement på kodningsmodeller, som OpenCode-teamet har testet. Tegn abonnement
i [Console](https://opencode.ai/console), kopier din API-nøgle, og forbind den som **OpenCode Go**.

```text
/connect
# Select OpenCode Go, then paste your API key.
/models
```

Se [Go-vejledningen](/console/go) for forbrugsgrænser, endpoints og oplysninger om privatliv.

## Brugerdefineret

Tilføj en udbyder, når dens API ikke allerede findes i kataloget. Dette OpenAI-kompatible eksempel definerer
legitimationsoplysningen, runtime-pakken, endpointet og den første model på én gang.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "acme": {
      "name": "Acme",
      "env": ["ACME_API_KEY"],
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "https://llm.acme.example/v1",
      },
      "models": {
        "qwen3-coder": {
          "name": "Qwen 3 Coder",
        },
      },
    },
  },
}
```

Nøglerne i `providers`-objektet er de udbyder-ID'er, der bruges i modelreferencer, f.eks. `acme/qwen3-coder`.

| Felt | Formål |
| --- | --- |
| `name` | Visningsnavn. |
| `env` | Ordnet liste over navne på miljøvariabler, der kan levere legitimationsoplysningen. |
| `package` | Runtime-pakke til udbyderen. |
| `canonical` | ID på en indbygget udbyder, hvis katalogstandarder denne udbyder arver. |
| `compatibility` | Tilsidesættelser af kompatibilitet for anmodninger og svar for alle modeller hos denne udbyder. Modellens `compatibility` tilsidesætter enkelte felter. `supportsThinkingBlockBinding` og `supportsEffortUpdates` findes kun på modelniveau. |
| `settings` | Typede OpenCode-indstillinger og JSON-indstillinger, der sendes videre til runtime-pakken. |
| `headers` | HTTP-headere med strengværdier, der føjes til anmodninger. |
| `body` | JSON-felter, der flettes ind i anmodningernes body. |
| `models` | Modeller, der skal tilføjes eller tilsidesættes, med OpenCode-model-ID'et som nøgle. |

## Endpoint

Tilsidesæt `settings.baseURL` for at sende trafik til en katalogudbyder via en proxy eller et kompatibelt endpoint.
Udbyderens eksisterende pakke, modeller og forbindelse gælder stadig.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "anthropic": {
      "settings": {
        "baseURL": "https://llm-proxy.example.com/anthropic",
      },
    },
  },
}
```

`settings` er pakkespecifik. Et felt har kun effekt, hvis den valgte pakke understøtter det.

## Anmodninger

Brug `headers` til ekstra HTTP-headere og `body` til JSON-felter, der skal flettes ind i body'en på hver anmodning.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "headers": {
        "X-Gateway-Tenant": "engineering",
      },
      "body": {
        "metadata": {
          "application": "opencode",
        },
      },
    },
  },
}
```

Begge felter kan også angives på en model eller variant, når kun en del af udbyderens trafik skal tilsidesættes.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "models": {
        "gpt-5.2": {
          "headers": { "X-Model-Tier": "coding" },
          "variants": [
            {
              "id": "batch",
              "body": { "service_tier": "flex" },
            },
          ],
        },
      },
    },
  },
}
```

## Timeouts

HTTP-anmodninger venter op til fem minutter på svarheadere og op til fem minutter mellem streamede bidder af svaret.
Sæt udbyderens `settings.headerTimeout` eller `settings.chunkTimeout` til et antal millisekunder for at ændre en
grænse, eller til `false` for at slå den fra. `settings.timeout` begrænser desuden hele anmodningen, fra den sendes,
til svaret er færdigt; den har ingen standardværdi. Disse indstillinger gælder for hele udbyderen, ikke pr. model eller
variant. Ved WebSocket-transport begrænser `chunkTimeout` i stedet pausen mellem frames og er som standard tredive
minutter.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "anthropic": {
      "settings": {
        "headerTimeout": 600000,
        "chunkTimeout": false,
      },
    },
  },
}
```

En anmodning, der overskrider en af grænserne, fejler med en transportfejl. OpenCode prøver en anmodning med timeout
igen op til tre gange, før den giver op.

## Kodning af anmodninger

`settings.encoding` komprimerer body'en i HTTP-anmodninger med `"zstd"` eller `"gzip"` eller sender almindelig JSON med
`"none"`. Angiv den på en udbyder, model eller variant; den mest specifikke værdi vinder. Slå kun en kodning til, som
endpointet kan afkode: de fleste udbydere og gateways afviser komprimerede bodies. OpenAI bruger som standard `"zstd"`,
når du er logget ind med ChatGPT, og der ikke er konfigureret en brugerdefineret `baseURL`; API-nøgler sender
almindelig JSON. WebSocket-beskeder påvirkes ikke.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "settings": { "encoding": "none" },
    },
  },
}
```

## Pakker

Feltet `package` vælger den runtime, der kommunikerer med en udbyder. Brug den kompatible runtime til API'er, der
implementerer OpenAIs anmodningsformat.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "acme": {
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "https://llm.acme.example/v1",
      },
      "models": {
        "qwen3-coder": {},
      },
    },
  },
}
```

De native pakker omfatter:

- `@opencode/ai/providers/openai`
- `@opencode/ai/providers/openai/chat`
- `@opencode/ai/providers/openai/responses`
- `@opencode/ai/providers/openai-compatible`
- `@opencode/ai/providers/openai-compatible/responses`
- `@opencode/ai/providers/anthropic`
- `@opencode/ai/providers/anthropic-compatible`
- `@opencode/ai/providers/google`
- `@opencode/ai/providers/google-vertex`
- `@opencode/ai/providers/google-vertex/gemini`
- `@opencode/ai/providers/google-vertex/chat`
- `@opencode/ai/providers/google-vertex/responses`
- `@opencode/ai/providers/google-vertex/messages`
- `@opencode/ai/providers/azure`
- `@opencode/ai/providers/azure/chat`
- `@opencode/ai/providers/azure/responses`
- `@opencode/ai/providers/amazon-bedrock`
- `@opencode/ai/providers/amazon-bedrock/mantle`
- `@opencode/ai/providers/amazon-bedrock/mantle/chat`
- `@opencode/ai/providers/amazon-bedrock/mantle/responses`
- `@opencode/ai/providers/openrouter`
- `@opencode/ai/providers/xai`

Du kan også bruge en npm-pakke som `@acme/opencode-provider` eller en absolut `file://`-URL til en lokal pakke.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "acme": {
      "package": "@acme/opencode-provider",
      "models": { "acme-coder": {} },
    },
  },
}
```

## Modeller

Tilføj eller tilsidesæt modeller i udbyderens `models`-map. Nøglen er det model-ID, OpenCode bruger; `modelID` ændrer
det ID, der sendes til udbyderen.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "openai/coding",
  "providers": {
    "openai": {
      "models": {
        "coding": {
          "modelID": "gpt-5.2",
          "name": "GPT-5.2 Coding",
        },
      },
    },
  },
}
```

| Felt | Formål |
| --- | --- |
| `modelID` | Model- eller deployment-ID, der sendes til udbyderen. |
| `name` | Visningsnavn. |
| `family` | Modelfamilie, der bruges til at gruppere beslægtede modeller. |
| `package` | Runtime-tilsidesættelse for denne model. |
| `settings` | OpenCode-indstillinger på modelniveau og pakkespecifikke JSON-indstillinger. |
| `headers` | Ekstra anmodningsheadere med strengværdier. |
| `body` | Ekstra JSON-felter i anmodningens body. |
| `capabilities` | Understøttelse af værktøjer samt accepterede medietyper for input og output. |
| `compatibility` | Tilsidesættelser af kompatibilitet for anmodninger og svar. |
| `variants` | Navngivne varianter med egne `settings`, `headers` og `body`. |
| `cost` | Pris for input, output og eventuelt cache pr. million tokens. |
| `limit` | Tokengrænser for kontekst, input og output. |
| `disabled` | Fjerner modellen fra valgmulighederne, når den er `true`. |

Se [Modeller](/models) om valg, standarder, egenskaber, grænser, omkostninger og varianter.

## Azure

Azures standardkatalog-endpoint kræver et ressourcenavn ud over legitimationsoplysningerne. Angiv
`settings.resourceName` én gang, og forbind derefter en API-nøgle, eller brug Microsoft Entra ID-sessionen fra Azure CLI
som beskrevet i [Udbyderkonti](/cli/providers).

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "azure": {
      "settings": {
        "resourceName": "my-models",
      },
    },
  },
}
```

Du finder **Resource name** i [Azure-portalen](https://portal.azure.com/) eller
[Microsoft Foundry](https://ai.azure.com/). Det er også første del af endpoints som
`https://my-models.openai.azure.com/` og `https://my-models.services.ai.azure.com/`.

```bash
az cognitiveservices account list \
  --query "[].{name:name,resourceGroup:resourceGroup}" \
  --output table
```

Hvis du vil bruge Entra ID, skal du installere [Azure CLI](https://learn.microsoft.com/en-us/cli/azure/install-azure-cli),
logge ind og derefter vælge **Microsoft Entra ID (Azure CLI)**, når du forbinder Azure.

```bash
az login
```

Indtast ressourcenavnet, når du forbinder, hvis det ikke allerede kommer fra konfigurationen eller miljøet. Et
ressourcenavn, der er gemt sammen med en forbindelse, har forrang for konfigurationen; forbind igen for at ændre det.

Forbindelser via Azure CLI bruger den konto, der er valgt i Azure CLI. Hvis ressourcen ligger i en anden tenant eller et
andet abonnement, skal du vælge begge eksplicit.

```bash
az login --tenant TENANT_ID
az account set --subscription NAME_OR_ID
```

I stedet for konfiguration kan `AZURE_RESOURCE_NAME` give OpenCode-serveren ressourcenavnet. Den ældre variabel
`AZURE_COGNITIVE_SERVICES_RESOURCE_NAME` virker også.

### Deployments

Azure stiller kun en model til rådighed via et deployment, så OpenCode henter deployments for din ressource og viser
dem i stedet for hele Azure-kataloget. Listen indlæses i baggrunden efter opstart, efter du har forbundet, og efter du
har skiftet konto. Genstart OpenCode, eller forbind igen, for at få et deployment med, der er tilføjet senere.

- Indtil listen er indlæst for en forbindelse, eller hvis indlæsningen fejler, er hele kataloget tilgængeligt.
- Hvis en genindlæsning for samme forbindelse fejler, beholdes den sidste komplette oversigt.
- Når du skifter konto, vises den tidligere kontos oversigt aldrig; den nye konto starter med hele kataloget.
- Deployments arver grænser, omkostninger og egenskaber fra deres katalogmodeller.

Deployment-navne bruges som model-ID'er, med små bogstaver, fordi Azure ikke skelner mellem store og små bogstaver i
navne, f.eks. `azure/gpt-production`. Et deployment, der er opkaldt efter sin model, f.eks. `gpt-5-mini`, beholder
katalog-ID'et. Disse ID'er forbliver stabile, når andre deployments tilføjes eller fjernes.

OpenCode matcher et deployment med kataloget ud fra den model, det deployer, eller ud fra navnet, når Azure staver
modellen anderledes, som med `gpt-4` for GPT-4 Turbo. Et deployment, der er opkaldt efter en anden model, f.eks. `gpt-5`
som deployer `gpt-5-mini`, viser den deployede models navn, grænser og omkostninger.

Med Azure CLI henter OpenCode deployments via Azures management-API, hvilket kræver læseadgang til ressourcen. Hvis det
fejler, og altid ved brug af en API-nøgle, bruges ressourcens ældre oversigt over deployments. Opdagelsen læser alle
sider, før listen offentliggøres. En brugerdefineret `settings.baseURL` beholder kataloget.

Konfigurer et deployment eksplicit, når dets model ikke findes i kataloget, f.eks. en finjusteret model, eller hvis du
selv vil knytte et model-ID til et deployment. OpenCode logger en advarsel, der navngiver sådanne deployments. Eksplicit
konfigurerede modeller bevares altid.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "azure": {
      "models": {
        "gpt-5-mini": {
          "modelID": "gpt-production",
        },
      },
    },
  },
}
```

Din identitet skal have en af disse roller:

- **Cognitive Services OpenAI User** til Azure OpenAI-modeller.
- **Cognitive Services User** til andre Foundry-modeller.

Hvis en anmodning bruger et token fra den forkerte tenant, skal du logge ind igen med den påkrævede tenant.

```bash
az login --tenant TENANT_ID
```

## Bedrock

Amazon Bedrock bruger AWS' standardkæde til legitimationsoplysninger. En navngiven AWS-profil er den enkleste varige
opsætning; OpenCode genkender også miljøer med adgangsnøgler, web identity og container-legitimationsoplysninger.

```bash
aws configure sso --profile work
aws sso login --profile work
```

Vælg profil og region i udbyderindstillingerne. En konfigureret `profile`, `AWS_PROFILE`, `AWS_ACCESS_KEY_ID`, en
token-fil til web identity eller en URI til container-legitimationsoplysninger aktiverer udbyderen; en region alene gør
ikke.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "amazon-bedrock": {
      "settings": {
        "profile": "work",
        "region": "us-west-2",
      },
    },
  },
}
```

Uden en eksplicit region bruger OpenCode `AWS_REGION`, derefter `AWS_DEFAULT_REGION` og til sidst `us-east-1`. Til et
privat endpoint eller et VPC-endpoint skal du angive `baseURL` og beholde samme profil og region.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "amazon-bedrock": {
      "settings": {
        "profile": "work",
        "region": "us-west-2",
        "baseURL": "https://bedrock-runtime.vpce.example.com",
      },
    },
  },
}
```

Bedrock-API-nøgler bruger `AWS_BEARER_TOKEN_BEDROCK`. Andre AWS-variabler bruges til SigV4 og gemmes ikke som
API-nøglekonti i OpenCode.

## Vertex

Google Vertex bruger Application Default Credentials (ADC) og kræver et projekt, før modellerne bliver tilgængelige.
Opret lokale ADC, og angiv derefter projekt og location i udbyderindstillingerne.

```bash
gcloud auth application-default login
```

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "google-vertex": {
      "settings": {
        "project": "my-project",
        "location": "us-central1",
      },
    },
  },
}
```

OpenCode finder også projektet ud fra `GOOGLE_VERTEX_PROJECT`, `GOOGLE_CLOUD_PROJECT`, `GCP_PROJECT` eller
`GCLOUD_PROJECT`, i den rækkefølge. Location findes ud fra `GOOGLE_VERTEX_LOCATION`, `GOOGLE_CLOUD_LOCATION` eller
`VERTEX_LOCATION` og er som standard `us-central1`.

```bash
GOOGLE_CLOUD_PROJECT=my-project GOOGLE_VERTEX_LOCATION=europe-west4 opencode --standalone
```

Tjenestekonti virker via samme ADC-mekanisme. Peg `GOOGLE_APPLICATION_CREDENTIALS` på JSON-filen for tjenestekontoen, og
angiv stadig et projekt via indstillingerne eller en af projektvariablerne ovenfor.

```bash
GOOGLE_APPLICATION_CREDENTIALS=/secure/vertex.json \
GOOGLE_CLOUD_PROJECT=my-project \
opencode --standalone
```

Brug det samme udbyder-ID, `google-vertex`, til Gemini-, Anthropic- og OpenAI-kompatible modeller i Vertex-kataloget.
Det gamle udbyder-ID `google-vertex-anthropic` findes ikke i V2.

## Copilot

GitHub Copilot understøtter device OAuth i stedet for manuel indtastning af en API-nøgle. Forbind **GitHub Copilot**,
vælg GitHub.com eller GitHub Enterprise, gennemfør device-flowet, og åbn derefter `/models`.

```text
/connect
# Select GitHub Copilot, then Login with GitHub Copilot.
/models
```

Til GitHub Enterprise skal du indtaste deployment-URL'en eller domænet, når du bliver bedt om det. OpenCode bruger et
Copilot-API-endpoint, som GitHub returnerer, hvis det er tilgængeligt; ellers udledes endpointet af enterprise-domænet.

```text
company.ghe.com
```

Den forbundne konto skal have adgang til Copilot Chat. Hvis GitHub melder, at kontoen ikke har adgang, skal du tilmelde
dig Copilot Free eller bede organisationen om at tildele dig en Copilot-licens og derefter forbinde igen. OpenCode
henter kontoens aktuelle modelliste efter login, og når den aktive Copilot-konto skifter.

## Ollama

Start Ollama, og hent en model. OpenCode undersøger `http://127.0.0.1:11434`, finder completion-modeller og føjer dem
til `/models` uden en kontoforbindelse.

```bash
ollama serve
ollama pull qwen3:8b
```

Peg OpenCode på en fjern Ollama-server eller en server bag en proxy med `settings.baseURL`. Medtag `/v1`; OpenCode
udleder de native opdagelsesstier `/api/tags` og `/api/show` ud fra den. `apiKey` er valgfri og sendes som bearer-token
til opdagelses- og modelanmodninger.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "ollama": {
      "settings": {
        "baseURL": "https://ollama.example.com/v1",
        "apiKey": "{env:OLLAMA_API_KEY}",
      },
    },
  },
}
```

Opdagelsen opdateres med jævne mellemrum og beholder den sidste vellykkede oversigt under et midlertidigt nedbrud.
Rene embedding-modeller vises ikke, fordi OpenCode kun tilføjer modeller, hvis Ollama-metadata indeholder egenskaben
`completion`.

## Runtimes

LM Studio og vLLM har også indbygget lokal opdagelse. Deres standard-endpoints er
`http://127.0.0.1:1234/v1` og `http://127.0.0.1:8000/v1`.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "lmstudio": {
      "settings": { "baseURL": "http://gpu-host:1234/v1" },
    },
    "vllm": {
      "settings": { "baseURL": "http://gpu-host:8000/v1" },
    },
  },
}
```

LM Studio finder sprogmodeller via `/api/v1/models`. vLLM tjekker `/health`, før `/v1/models` læses; opdagelsen kan
ikke afgøre, om værktøjer understøttes, så fundne vLLM-modeller starter med værktøjer slået fra. Til andre
OpenAI-kompatible runtimes skal du bruge opskriften for [brugerdefinerede udbydere](#custom) og angive modellerne
eksplicit.

## Gateways

OpenRouter bruger sin egen native runtime og sit eget katalog. Giv OpenCode-serveren `OPENROUTER_API_KEY`, eller forbind
en OpenRouter-konto, og angiv derefter modeller med det fulde OpenRouter-model-ID efter udbyderpræfikset.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "openrouter/anthropic/claude-sonnet-4",
}
```

Behold den native OpenRouter-pakke, når du tilsidesætter endpointet eller router trafik via en OpenRouter-kompatibel
gateway. Så bevares OpenRouters adfærd for anmodninger og reasoning.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openrouter": {
      "settings": {
        "baseURL": "https://openrouter-gateway.example.com/api/v1",
      },
      "headers": {
        "X-Gateway-Tenant": "engineering",
      },
    },
  },
}
```

Til en gateway, der udstiller et OpenAI-kompatibelt API, men har sin egen modeloversigt, skal du i stedet definere en
brugerdefineret udbyder. Konfigurationsnøglen bliver udbyderpræfikset, og hver nøgle i `models` bliver et model-ID, der
kan vælges.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "company/coder",
  "providers": {
    "company": {
      "env": ["COMPANY_GATEWAY_KEY"],
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "https://gateway.example.com/v1",
      },
      "models": {
        "coder": { "modelID": "upstream/coder-v2" },
      },
    },
  },
}
```

## Fejl

Fejl fra udbydere og modeller angiver som regel, hvilket trin der fejlede. Kontroller serverprocessens miljø og det
præcise model-ID, før du skifter pakke.

| Fejl eller symptom | Kontroller |
| --- | --- |
| `No model is available for session ...` | Ingen aktiveret model kan vælges lige nu. Gør den udbyderspecifikke opsætning færdig, og vælg derefter en model i `/models`. |
| `Model unavailable: provider/model` | Udbyderen er inaktiv, model-ID'et mangler eller er slået fra, eller den dynamiske opdagelse returnerer det ikke længere. For brugerdefinerede aliasser skal du kontrollere nøglen i `models`-map'et, ikke `modelID`. |
| `Cannot initialize provider/model: NAME is required to resolve the provider endpoint` | Der står stadig en `${NAME}`-pladsholder i `baseURL`. Sæt variablen på OpenCode-serveren, eller erstat skabelonen med et komplet endpoint. |
| `Azure resource name is missing` | Angiv `providers.azure.settings.resourceName`, `AZURE_RESOURCE_NAME` eller en komplet `settings.baseURL`. |
| Vertex vises ikke | Angiv et projekt, der kan findes, i udbyderindstillingerne eller i en understøttet projektvariabel. ADC alene aktiverer ikke udbyderen. |
| Bedrock vises ikke | Angiv en profil eller et andet understøttet input til AWS' kæde af legitimationsoplysninger. `AWS_REGION` vælger alene en region. |
| Ollama har ingen modeller | Kontroller at serveren udstiller `/api/tags` og `/api/show` på den sti, der udledes af `baseURL`, og at `/api/show` rapporterer egenskaben `completion`. |
| Copilot har ingen modeller | Kontroller at den aktive OAuth-konto har adgang til Copilot Chat. En mislykket modelsynkronisering logges som `failed to sync GitHub Copilot models`. |

V2 afviser udgåede udbyder-ID'er, der har en direkte erstatning. Brug `azure/<model>` i stedet for
`azure-cognitive-services/<model>` og `google-vertex/<model>` i stedet for `google-vertex-anthropic/<model>`.

## WebSockets

OpenAI-, xAI- og understøttede Azure Responses-modeller kan holde én WebSocket-forbindelse åben pr. session. Efterfølgende
trin genbruger det uændrede præfiks af anmodningen og sender kun indhold, der er tilføjet siden det forrige svar, så der
uploades mindre i lange sessioner.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "settings": { "transport": "http" },
    },
  },
}
```

WebSocket-adfærden følger disse regler:

- Indbyggede udbydere slår det til for understøttede ruter efter deres egen politik.
- Udbyderens `settings.transport: "websocket"` slår det til; `"http"` slår det fra.
- `"websocket"` på en rute uden WebSocket-kanal logger en advarsel og falder tilbage til HTTP.
- Komprimering hos OpenAI-udbyderen bruger samme forbindelse.
- xAI fortsætter kun fra gemte svar. Med standardværdien `store: false` sendes hvert trin i sin helhed over den
  genbrugte forbindelse.
- En lukket socket genopretter forbindelsen ved næste trin. Hvis forbindelsen ikke kan åbnes, fortsætter sessionen over
  HTTP.
- Udbyder-plugins med `http.request`- eller `http.response`-hooks bliver på HTTP, så hver anmodning fortsat kan
  observeres.
