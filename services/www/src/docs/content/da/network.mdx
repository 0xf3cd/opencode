Angiv standardproxyvariablerne, og undtag loopback-adresser. OpenCode bruger lokale HTTP-forbindelser mellem CLI'en
og dens baggrundstjeneste, så loopback-undtagelsen er påkrævet, når der er konfigureret en proxy i CLI'ens miljø.

```bash
export HTTP_PROXY=http://proxy.example.com:8080
export HTTPS_PROXY=http://proxy.example.com:8080
export NO_PROXY=localhost,127.0.0.1,::1

opencode
```

`HTTP_PROXY` håndterer HTTP-destinationer, og `HTTPS_PROXY` håndterer HTTPS-destinationer. Selve proxy-URL'en kan bruge
`http://` i begge variabler. `NO_PROXY` er en kommasepareret liste over værter og adresser, der forbindes direkte til.

## Tjeneste

Variabler, der eksporteres i shellen, påvirker kun en baggrundstjeneste, hvis tjenesten startes fra den shell. Gem variablerne permanent i
den administrerede tjenestekonfiguration, så senere opstarter af tjenesten bruger de samme netværksindstillinger.

```bash
opencode service set env HTTP_PROXY http://proxy.example.com:8080
opencode service set env HTTPS_PROXY http://proxy.example.com:8080
opencode service set env NO_PROXY localhost,127.0.0.1,::1
opencode service start
```

Når du ændrer en administreret miljøvariabel, stoppes den kørende tjeneste. `service start` starter den igen med det nye
miljø. Behold også `NO_PROXY` i CLI'ens shell, hvis den shell angiver en proxy, for administrerede tjenestevariabler
gælder for serverprocessen, ikke for CLI-processen.

Fjern en gemt variabel med `service unset env`:

```bash
opencode service unset env HTTPS_PROXY
```

## Godkendelse

Hvis proxyen accepterer legitimationsoplysninger i URL'en, skal du inkludere brugernavn og adgangskode i hver proxy-URL,
der kræver godkendelse. Procentkod tegn som `@`, `:` og `/` i brugernavnet eller adgangskoden.

```bash
export HTTPS_PROXY='http://user:p%40ssword@proxy.example.com:8080'
```

For baggrundstjenesten skal du gemme hele URL'en. Værdien gemmes i den private tjenestekonfiguration og vises af
`opencode service get env`, så del ikke det output.

```bash
opencode service set env HTTPS_PROXY 'http://user:p%40ssword@proxy.example.com:8080'
```

## Certifikater

Sæt `NODE_EXTRA_CA_CERTS` til en PEM-fil, hvis proxyen eller destinationen bruger et certifikat, der er signeret af en
privat certifikatudsteder. De ekstra udstedere føjes til runtimens tillidslager, når processen starter.

```bash
export NODE_EXTRA_CA_CERTS=/etc/company/ca.pem
opencode --standalone
```

Gem filstien permanent for baggrundstjenesten, og genstart den derefter:

```bash
opencode service set env NODE_EXTRA_CA_CERTS /etc/company/ca.pem
opencode service start
```

## Forgrund

`--standalone` og `serve` bruger miljøet i deres egen proces. `opencode service set env` konfigurerer ikke disse
processer.

```bash
HTTP_PROXY=http://proxy.example.com:8080 \
HTTPS_PROXY=http://proxy.example.com:8080 \
NO_PROXY=localhost,127.0.0.1,::1 \
opencode --standalone
```

Brug samme mønster til en server i forgrunden:

```bash
HTTPS_PROXY=http://proxy.example.com:8080 \
NO_PROXY=localhost,127.0.0.1,::1 \
opencode serve
```

## Verificer

Kontroller at CLI'en kan nå baggrundstjenesten, når du har anvendt indstillingerne:

```bash
opencode api get /api/info
```

Et vellykket svar fra health-tjekket bekræfter den lokale forbindelse mellem klient og tjeneste. Kør en almindelig
anmodning mod en udbyder for at bekræfte tjenestens udgående proxy og certifikatsti.
