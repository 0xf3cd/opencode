title: "Tema"
---

OpenCode leveres med mange indbyggede temaer til lys og mørk tilstand. Vælg et i indstillingerne, eller sammensæt dine egne farver.

## Vælg et tema

Tryk på `Ctrl+P`, vælg **Open settings**, og åbn derefter **Theme**. Standardtemaet er `opencode`.

Du kan også angive temaet i dine globale [CLI-indstillinger](/cli/config):

```json title="~/.config/opencode/cli.json"
{
  "$schema": "https://opencode.ai/v2/cli.json",
  "theme": {
    "name": "tokyonight",
    "mode": "dark"
  }
}
```

Kør `/themes` for at skifte tema uden at åbne indstillingerne.

## Systemfarver

Når OpenCode kan læse din terminals palet, indeholder temavælgeren temaet `system`. Det afleder farverne fra terminalens forgrund, baggrund og ANSI-palet.

Temanavnet `system` vælger farver afledt fra terminalen. Tilstanden `system` følger terminalens lyse eller mørke udseende.

## Tilstand

Brug `system` for at følge terminalens udseende, eller lås temaet til lys eller mørk tilstand:

| Tilstand | Adfærd |
| --- | --- |
| `system` | Følger terminalens registrerede lyse eller mørke udseende. |
| `dark` | Bruger altid temaets mørke farver. |
| `light` | Bruger altid temaets lyse farver. |

Det svarer til feltet `mode` i `theme` i din CLI-konfiguration. Hvis et brugerdefineret tema kun har én tilstand, bruger OpenCode den tilstand, når den anden bliver valgt.

## Tilføj et tema

Hvis du vil tilføje et tema, som du har downloadet eller fået af en anden, skal du kopiere dets JSON-fil til den globale temamappe:

```bash
cp theme.json ~/.config/opencode/themes/
```

Du kan også lægge temaet i et projekts `.opencode/themes`-mappe, så det kun er tilgængeligt i det projekt.

Filnavnet bliver temaets navn. For eksempel vises `my-theme.json` som `my-theme`. Genstart OpenCode, når du har tilføjet filen, og kør derefter `/themes` for at vælge det.

OpenCode læser kun `.json`-filer. Et tema tættere på den aktuelle mappe erstatter et globalt tema eller et tema i en overordnet mappe med samme navn.

## Brug temaer i plugins

[CLI-plugins](/build/plugins/cli) læser de opløste farver via `context.theme` og den aktive tilstand via `context.themeMode`. Brug semantiske tokens, så dit plugin følger det valgte tema:

```tsx title="Inside a CLI plugin component"
import { usePlugin } from "@opencode/plugin/tui"

function Status() {
  const context = usePlugin()
  return <text fg={context.theme.text.base}>Ready</text>
}
```

Det offentlige API til CLI-plugins registrerer ikke temaer. Tilføj brugerdefinerede temadefinitioner med JSON-filer i mapperne ovenfor.

## Opret et tema

Brug vores [temaværktøj](https://opencode.ai/theme/) til at oprette eller redigere temaer. Med værktøjet er det nemt at forstå strukturen, ændre den og definere egne farver. Forklaringen nedenfor er til reference.

Et tema adskiller fælles semantiske tokens fra paletter, der er specifikke for hver tilstand:

| Sektion | Formål |
| --- | --- |
| `base` | Det komplette tokentræ, som deles af alle tilstande. |
| `light`, `dark` | En komplet farvetonepalet og valgfri tilsidesættelser af tokens for den pågældende tilstand. |

Alle temaer har en komplet `base` og definerer mindst én af `light` og `dark`. Tilstandene arver fra filens `base`. De arver ikke fra det indbyggede OpenCode-tema eller fra hinanden.

Eksemplerne nedenfor viser kun de sektioner, der er relevante for hvert begreb. Brug temaeditoren til at generere en komplet fil, før du tilpasser den.

### Struktur

Læg farver, som begge tilstande bruger, i `base`, og tilsidesæt dem derefter i `light` eller `dark` efter behov:

```json title="theme.json (excerpt)"
{
  "$schema": "https://opencode.ai/theme.json",
  "base": {
    "text": {
      "base": "$hue.neutral.200",
      "muted": "$hue.neutral.400"
    }
  },
  "light": {
    "hue": {}
  },
  "dark": {
    "hue": {},
    "text": {
      "muted": "$hue.neutral.300"
    }
  }
}
```

Den komplette `base` leverer alle semantiske tokens. Hver tilstand leverer alle påkrævede farvetoner og kan tilsidesætte enhver del af base-tokentræet.

### Farver og referencer

En farve kan være en hex-værdi, `"transparent"` eller en reference til en anden farve i temaet:

```json title="Inside base or a mode"
{
  "text": {
    "base": "#eeeeee",
    "muted": "$hue.neutral.400"
  },
  "border": {
    "base": "$text.muted"
  }
}
```

### Farvetoner

Farvetoner er farveskalaer med ni trin. Hver tilstand definerer de otte grundtoner og tre aliasser:

| Type | Værdier |
| --- | --- |
| Grundtone | `gray`, `red`, `orange`, `yellow`, `green`, `cyan`, `blue`, `purple` |
| Alias | `accent`, `interactive`, `neutral` |
| Trin | `100`, `200`, `300`, `400`, `500`, `600`, `700`, `800`, `900` |

Definer alle ni trin for en grundtone, eller lav en farvetone til et alias for en anden:

```json title="Inside light or dark"
{
  "hue": {
    "purple": {
      "100": "#b38ff4",
      "200": "#9d7cd8",
      "300": "#8869bd",
      "400": "#7357a2",
      "500": "#5f4688",
      "600": "#4b356f",
      "700": "#392557",
      "800": "#271640",
      "900": "#17072b"
    },
    "accent": "$hue.purple"
  }
}
```

Trinene følger tilstandens kontrastretning. Lyse temaer går fra mørk ved `100` til lys ved `900`. Mørke temaer går fra lys ved `100` til mørk ved `900`.

Arrayet `categorical` i `base` angiver de ordnede farvetoner, der bruges til at skelne agenter og andre gentagne elementer:

```json title="Inside base"
{
  "categorical": ["accent", "purple", "green", "blue"]
}
```

### Semantiske tokens

Semantiske tokens tildeler farver til roller i brugerfladen. Komponenter bruger disse roller i stedet for at vælge farver direkte.

| Gruppe | Formål |
| --- | --- |
| `text` | Grundtekst, dæmpet tekst og tekst til handlinger, formularfelter, status og feedback. |
| `background` | Grundbaggrund, hævede flader, handlinger, formularfelter og feedbackfyld. |
| `border`, `scrollbar` | Farver til kanter og rullepaneler. |
| `diff` | Farver til tilføjet, fjernet, kontekst, fremhævning og linjenumre. |
| `syntax` | Syntaksfremhævning af kildekode. |
| `markdown` | Markdown-elementer. |

For eksempel styrer `text.muted` sekundær tekst, mens `background.raised` definerer gradvist mere hævede flader:

```json title="Inside base"
{
  "text": {
    "base": "$hue.neutral.200",
    "muted": "$hue.neutral.400"
  },
  "background": {
    "base": "$hue.neutral.800",
    "raised": {
      "base": "$hue.neutral.700",
      "high": "$hue.neutral.600",
      "max": "$hue.neutral.500"
    }
  }
}
```

Syntaksnøglerne er `comment`, `keyword`, `function`, `variable`, `string`, `number`, `type`, `operator` og `punctuation`.

Markdown-nøglerne er `text`, `heading`, `link`, `linkText`, `code`, `blockQuote`, `emphasis`, `strong`, `horizontalRule`, `listItem`, `listEnumeration`, `image`, `imageText` og `codeBlock`.

### Handlinger og tilstande

Handlinger har varianterne `primary`, `secondary` og `destructive`. Handlinger og formularfelter bruger `base` plus valgfri interaktionstilstande:

```json title="Inside base or a mode"
{
  "text": {
    "action": {
      "primary": {
        "base": "$hue.interactive.400",
        "$hovered": "$hue.interactive.300",
        "$disabled": "$hue.neutral.600"
      }
    }
  }
}
```

Tilstandsnøglerne er `$hovered`, `$focused`, `$pressed`, `$selected` og `$disabled`. En tilstand, der ikke er angivet, bruger handlingens eller formularfeltets `base`-farve.

### Dialogflade

Paneler, dialoger, menuer og toast-notifikationer vælger deres dybde fra `background.raised`. Dialoger kan desuden tilsidesætte semantiske tokens med `@dialog`:

```json title="Inside base or a mode"
{
  "@dialog": {
    "background": {
      "base": "$background.raised.base",
      "action": {
        "primary": {
          "$hovered": "$background.raised.high"
        }
      }
    }
  }
}
```

TUI'en opløser referencer igen efter at have anvendt `@dialog`, så tokens, der henviser til `$background.base`, følger dialogens baggrund. En kontekstuel handlings `base` bliver fallback for de tilstande, der ikke er angivet. Eksplicitte tilsidesættelser af tilstande har stadig forrang.
