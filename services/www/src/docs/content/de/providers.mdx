OpenCode enthält einen Anbieter- und Modellkatalog von [models.dev](https://models.dev). Bei den meisten Anbietern
verbindest du zuerst ein Konto und wählst dann ein Modell aus.

## Einrichtung

Führe `/connect` aus, wähle einen Anbieter und gib seine Zugangsdaten ein. Wähle anschließend mit `/models` eines seiner
Modelle aus.

```text
/connect
/models
```

## Go

[OpenCode Go](/console/go) ist ein optionales Abonnement für Coding-Modelle, die das OpenCode-Team getestet hat.
Schließe es in der [Console](https://opencode.ai/console) ab, kopiere deinen API-Schlüssel und verbinde ihn als
**OpenCode Go**.

```text
/connect
# Select OpenCode Go, then paste your API key.
/models
```

Nutzungslimits, Endpunkte und Datenschutzdetails findest du im [Go-Leitfaden](/console/go).

## Eigene Anbieter

Füge einen Anbieter hinzu, wenn seine API noch nicht im Katalog enthalten ist. Dieses OpenAI-kompatible Beispiel legt
Zugangsdaten, Runtime-Paket, Endpunkt und das erste Modell gemeinsam fest.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "acme": {
      "name": "Acme",
      "env": ["ACME_API_KEY"],
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "https://llm.acme.example/v1",
      },
      "models": {
        "qwen3-coder": {
          "name": "Qwen 3 Coder",
        },
      },
    },
  },
}
```

Die Schlüssel des Objekts `providers` sind die Anbieter-IDs, die in Modellreferenzen wie `acme/qwen3-coder` verwendet
werden.

| Feld | Zweck |
| --- | --- |
| `name` | Anzeigename. |
| `env` | Geordnete Namen von Umgebungsvariablen, die die Zugangsdaten liefern können. |
| `package` | Runtime-Paket des Anbieters. |
| `canonical` | ID eines integrierten Anbieters, dessen Katalog-Standardwerte dieser Anbieter erbt. |
| `compatibility` | Kompatibilitätsüberschreibungen für Anfragen und Antworten, die für alle Modelle dieses Anbieters gelten. `compatibility` eines Modells überschreibt einzelne Felder. `supportsThinkingBlockBinding` und `supportsEffortUpdates` gibt es nur auf Modellebene. |
| `settings` | Typisierte OpenCode-Einstellungen und JSON-Optionen, die an das Runtime-Paket übergeben werden. |
| `headers` | HTTP-Header mit String-Werten, die zu Anfragen hinzugefügt werden. |
| `body` | JSON-Felder, die in Anfragetexte eingefügt werden. |
| `models` | Hinzuzufügende oder zu überschreibende Modelle, mit der OpenCode-Modell-ID als Schlüssel. |

## Endpunkt

Überschreibe `settings.baseURL`, um einen Katalog-Anbieter über einen Proxy oder kompatiblen Endpunkt anzusprechen.
Sein bestehendes Paket, seine Modelle und seine Verbindung gelten weiterhin.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "anthropic": {
      "settings": {
        "baseURL": "https://llm-proxy.example.com/anthropic",
      },
    },
  },
}
```

`settings` ist paketspezifisch. Ein Feld wirkt nur, wenn das gewählte Paket es unterstützt.

## Anfragen

Verwende `headers` für zusätzliche HTTP-Header und `body` für JSON-Felder, die in jeden Anfragetext eingefügt werden
sollen.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "headers": {
        "X-Gateway-Tenant": "engineering",
      },
      "body": {
        "metadata": {
          "application": "opencode",
        },
      },
    },
  },
}
```

Beide Felder lassen sich auch für ein Modell oder eine Variante setzen, wenn die Überschreibung nur für einen Teil der
Anfragen eines Anbieters gelten soll.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "models": {
        "gpt-5.2": {
          "headers": { "X-Model-Tier": "coding" },
          "variants": [
            {
              "id": "batch",
              "body": { "service_tier": "flex" },
            },
          ],
        },
      },
    },
  },
}
```

## Zeitlimits

HTTP-Anfragen warten bis zu fünf Minuten auf die Antwort-Header und bis zu fünf Minuten zwischen gestreamten Teilen der
Antwort. Setze `settings.headerTimeout` oder `settings.chunkTimeout` des Anbieters auf eine Anzahl von Millisekunden, um
ein Limit zu ändern, oder auf `false`, um es zu deaktivieren. `settings.timeout` begrenzt zusätzlich die gesamte Anfrage
vom Senden bis zum Abschluss der Antwort; dafür gibt es keinen Standardwert. Diese Einstellungen gelten für den ganzen
Anbieter, nicht pro Modell oder Variante. Bei einem WebSocket-Transport begrenzt `chunkTimeout` stattdessen den Abstand
zwischen Frames und beträgt standardmäßig dreißig Minuten.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "anthropic": {
      "settings": {
        "headerTimeout": 600000,
        "chunkTimeout": false,
      },
    },
  },
}
```

Eine Anfrage, die eines der Limits überschreitet, schlägt mit einem Transportfehler fehl. OpenCode wiederholt eine
Anfrage nach einer Zeitüberschreitung bis zu dreimal, bevor es aufgibt.

## Kodierung von Anfragen

`settings.encoding` komprimiert HTTP-Anfragetexte mit `"zstd"` oder `"gzip"` oder sendet mit `"none"` unkomprimiertes
JSON. Du kannst es für einen Anbieter, ein Modell oder eine Variante setzen; der spezifischste Wert gewinnt. Aktiviere
nur eine Kodierung, die der Endpunkt auch dekodiert: Die meisten Anbieter und Gateways lehnen komprimierte Anfragetexte
ab. Bei OpenAI ist `"zstd"` der Standard, wenn du mit ChatGPT angemeldet bist und keine eigene `baseURL` konfiguriert
ist; mit API-Schlüsseln wird unkomprimiertes JSON gesendet. WebSocket-Nachrichten sind nicht betroffen.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "settings": { "encoding": "none" },
    },
  },
}
```

## Pakete

Das Feld `package` wählt die Runtime, die mit einem Anbieter kommuniziert. Für APIs, die das Anfrageformat von OpenAI
implementieren, verwendest du die kompatible Runtime.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "acme": {
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "https://llm.acme.example/v1",
      },
      "models": {
        "qwen3-coder": {},
      },
    },
  },
}
```

Zu den nativen Paketen gehören:

- `@opencode/ai/providers/openai`
- `@opencode/ai/providers/openai/chat`
- `@opencode/ai/providers/openai/responses`
- `@opencode/ai/providers/openai-compatible`
- `@opencode/ai/providers/openai-compatible/responses`
- `@opencode/ai/providers/anthropic`
- `@opencode/ai/providers/anthropic-compatible`
- `@opencode/ai/providers/google`
- `@opencode/ai/providers/google-vertex`
- `@opencode/ai/providers/google-vertex/gemini`
- `@opencode/ai/providers/google-vertex/chat`
- `@opencode/ai/providers/google-vertex/responses`
- `@opencode/ai/providers/google-vertex/messages`
- `@opencode/ai/providers/azure`
- `@opencode/ai/providers/azure/chat`
- `@opencode/ai/providers/azure/responses`
- `@opencode/ai/providers/amazon-bedrock`
- `@opencode/ai/providers/amazon-bedrock/mantle`
- `@opencode/ai/providers/amazon-bedrock/mantle/chat`
- `@opencode/ai/providers/amazon-bedrock/mantle/responses`
- `@opencode/ai/providers/openrouter`
- `@opencode/ai/providers/xai`

Du kannst auch ein npm-Paket wie `@acme/opencode-provider` oder für ein lokales Paket eine absolute `file://`-URL
verwenden.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "acme": {
      "package": "@acme/opencode-provider",
      "models": { "acme-coder": {} },
    },
  },
}
```

## Modelle

In der Map `models` eines Anbieters fügst du Modelle hinzu oder überschreibst sie. Der Schlüssel ist die Modell-ID, die
OpenCode verwendet; `modelID` ändert die ID, die an den Anbieter gesendet wird.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "openai/coding",
  "providers": {
    "openai": {
      "models": {
        "coding": {
          "modelID": "gpt-5.2",
          "name": "GPT-5.2 Coding",
        },
      },
    },
  },
}
```

| Feld | Zweck |
| --- | --- |
| `modelID` | Modell- oder Deployment-ID, die an den Anbieter gesendet wird. |
| `name` | Anzeigename. |
| `family` | Modellfamilie zum Gruppieren verwandter Modelle. |
| `package` | Runtime-Überschreibung für dieses Modell. |
| `settings` | OpenCode-Einstellungen auf Modellebene und paketspezifische JSON-Einstellungen. |
| `headers` | Zusätzliche Anfrage-Header mit String-Werten. |
| `body` | Zusätzliche JSON-Felder im Anfragetext. |
| `capabilities` | Tool-Unterstützung sowie akzeptierte Medientypen für Ein- und Ausgabe. |
| `compatibility` | Kompatibilitätsüberschreibungen für Anfragen und Antworten. |
| `variants` | Benannte Varianten mit eigenen `settings`, `headers` und `body`. |
| `cost` | Preise für Ein- und Ausgabe sowie optional Cache pro Million Tokens. |
| `limit` | Token-Limits für Kontext, Eingabe und Ausgabe. |
| `disabled` | Entfernt das Modell aus der Auswahl, wenn `true`. |

Auswahl, Standardwerte, Fähigkeiten, Limits, Kosten und Varianten beschreibt [Modelle](/models).

## Azure

Der Standard-Katalogendpunkt von Azure benötigt neben den Zugangsdaten einen Ressourcennamen. Setze einmalig
`settings.resourceName` und verbinde dann einen API-Schlüssel oder nutze die Microsoft-Entra-ID-Sitzung der Azure CLI,
wie unter [Anbieterkonten](/cli/providers) beschrieben.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "azure": {
      "settings": {
        "resourceName": "my-models",
      },
    },
  },
}
```

Den **Resource name** findest du im [Azure-Portal](https://portal.azure.com/) oder in
[Microsoft Foundry](https://ai.azure.com/). Er ist auch der erste Teil von Endpunkten wie
`https://my-models.openai.azure.com/` und `https://my-models.services.ai.azure.com/`.

```bash
az cognitiveservices account list \
  --query "[].{name:name,resourceGroup:resourceGroup}" \
  --output table
```

Um Entra ID zu verwenden, installiere die [Azure CLI](https://learn.microsoft.com/en-us/cli/azure/install-azure-cli),
melde dich an und wähle beim Verbinden von Azure **Microsoft Entra ID (Azure CLI)**.

```bash
az login
```

Gib den Ressourcennamen beim Verbinden ein, falls er nicht bereits über die Konfiguration oder die Umgebung gesetzt ist.
Ein mit einer Verbindung gespeicherter Ressourcenname hat Vorrang vor der Konfiguration; um ihn zu ändern, verbinde dich
erneut.

Verbindungen über die Azure CLI verwenden das in der Azure CLI ausgewählte Konto. Für eine Ressource in einem anderen
Tenant oder Abonnement wählst du beides ausdrücklich aus.

```bash
az login --tenant TENANT_ID
az account set --subscription NAME_OR_ID
```

Statt über die Konfiguration kannst du den Ressourcennamen dem OpenCode-Server auch über `AZURE_RESOURCE_NAME` übergeben.
Die ältere Variable `AZURE_COGNITIVE_SERVICES_RESOURCE_NAME` funktioniert ebenfalls.

### Deployments

Azure stellt ein Modell nur über ein Deployment bereit. OpenCode listet daher die Deployments deiner Ressource auf und
zeigt diese statt des gesamten Azure-Katalogs an. Die Liste wird im Hintergrund nach dem Start, nach dem Verbinden und
nach einem Kontowechsel geladen. Um ein später hinzugefügtes Deployment zu übernehmen, starte OpenCode neu oder verbinde
dich erneut.

- Bis die Liste für eine Verbindung geladen ist oder wenn das Laden fehlschlägt, bleibt der gesamte Katalog verfügbar.
- Schlägt ein erneutes Laden für dieselbe Verbindung fehl, bleibt ihr letzter vollständiger Bestand erhalten.
- Nach einem Kontowechsel wird nie der Bestand des vorherigen Kontos angezeigt; das neue Konto beginnt mit dem gesamten
  Katalog.
- Deployments erben Limits, Kosten und Fähigkeiten von ihren Katalogmodellen.

Die Namen der Deployments sind ihre Modell-IDs, in Kleinbuchstaben, da Azure bei Namen die Groß- und Kleinschreibung
ignoriert, zum Beispiel `azure/gpt-production`. Ein Deployment, das nach seinem Modell benannt ist, etwa `gpt-5-mini`,
behält die Katalog-ID. Diese IDs bleiben stabil, wenn andere Deployments hinzukommen oder entfernt werden.

OpenCode ordnet ein Deployment dem Katalog anhand des bereitgestellten Modells zu oder anhand seines Namens, wenn Azure
das Modell anders schreibt, wie bei `gpt-4` für GPT-4 Turbo. Ein Deployment, das nach einem anderen Modell benannt ist,
etwa `gpt-5`, das `gpt-5-mini` bereitstellt, zeigt den Namen, die Limits und die Kosten dieses Modells an.

Mit der Azure CLI listet OpenCode Deployments über die Azure-Verwaltungs-API auf, die Lesezugriff auf die Ressource
benötigt. Schlägt das fehl, und mit einem API-Schlüssel immer, verwendet es den älteren Deployment-Bestand der Ressource.
Die Erkennung liest alle Seiten, bevor sie die Liste veröffentlicht. Mit einer eigenen `settings.baseURL` bleibt der
Katalog erhalten.

Konfiguriere ein Deployment ausdrücklich, wenn sein Modell nicht im Katalog enthalten ist, etwa bei einem feinabgestimmten
Modell, oder wenn du eine Modell-ID selbst einem Deployment zuordnen möchtest. OpenCode protokolliert eine Warnung, die
solche Deployments nennt. Ausdrücklich konfigurierte Modelle bleiben immer erhalten.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "azure": {
      "models": {
        "gpt-5-mini": {
          "modelID": "gpt-production",
        },
      },
    },
  },
}
```

Deine Identität benötigt eine dieser Rollen:

- **Cognitive Services OpenAI User** für Azure-OpenAI-Modelle.
- **Cognitive Services User** für andere Foundry-Modelle.

Verwendet eine Anfrage einen Token aus dem falschen Tenant, melde dich mit dem benötigten Tenant erneut an.

```bash
az login --tenant TENANT_ID
```

## Bedrock

Amazon Bedrock verwendet die Standard-Credential-Chain von AWS. Ein benanntes AWS-Profil ist die einfachste dauerhafte
Einrichtung; OpenCode erkennt außerdem Umgebungen mit Zugriffsschlüsseln, Web Identity und Container-Zugangsdaten.

```bash
aws configure sso --profile work
aws sso login --profile work
```

Wähle Profil und Region in den Anbietereinstellungen. Ein konfiguriertes `profile`, `AWS_PROFILE`, `AWS_ACCESS_KEY_ID`,
eine Web-Identity-Token-Datei oder eine Container-Credential-URI aktiviert den Anbieter; eine Region allein reicht nicht.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "amazon-bedrock": {
      "settings": {
        "profile": "work",
        "region": "us-west-2",
      },
    },
  },
}
```

Ohne ausdrückliche Region verwendet OpenCode `AWS_REGION`, dann `AWS_DEFAULT_REGION` und schließlich `us-east-1`. Für
einen privaten oder VPC-Endpunkt setzt du `baseURL` und behältst Profil und Region bei.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "amazon-bedrock": {
      "settings": {
        "profile": "work",
        "region": "us-west-2",
        "baseURL": "https://bedrock-runtime.vpce.example.com",
      },
    },
  },
}
```

Bedrock-API-Schlüssel verwenden `AWS_BEARER_TOKEN_BEDROCK`. Andere AWS-Variablen dienen SigV4 und werden nicht als
API-Schlüssel-Konten in OpenCode gespeichert.

## Vertex

Google Vertex verwendet Application Default Credentials (ADC) und benötigt ein Projekt, bevor seine Modelle verfügbar
werden. Erstelle lokale ADC und setze dann Projekt und Standort in den Anbietereinstellungen.

```bash
gcloud auth application-default login
```

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "google-vertex": {
      "settings": {
        "project": "my-project",
        "location": "us-central1",
      },
    },
  },
}
```

OpenCode ermittelt das Projekt außerdem aus `GOOGLE_VERTEX_PROJECT`, `GOOGLE_CLOUD_PROJECT`, `GCP_PROJECT` oder
`GCLOUD_PROJECT`, in dieser Reihenfolge. Den Standort ermittelt es aus `GOOGLE_VERTEX_LOCATION`, `GOOGLE_CLOUD_LOCATION`
oder `VERTEX_LOCATION`; Standard ist `us-central1`.

```bash
GOOGLE_CLOUD_PROJECT=my-project GOOGLE_VERTEX_LOCATION=europe-west4 opencode --standalone
```

Dienstkonten funktionieren über denselben ADC-Weg. Lass `GOOGLE_APPLICATION_CREDENTIALS` auf die JSON-Datei des
Dienstkontos zeigen und gib trotzdem ein Projekt über die Einstellungen oder eine der oben genannten Projektvariablen an.

```bash
GOOGLE_APPLICATION_CREDENTIALS=/secure/vertex.json \
GOOGLE_CLOUD_PROJECT=my-project \
opencode --standalone
```

Verwende für Gemini-, Anthropic- und OpenAI-kompatible Modelle aus dem Vertex-Katalog die einzige Anbieter-ID
`google-vertex`. Die alte Anbieter-ID `google-vertex-anthropic` ist in V2 nicht verfügbar.

## Copilot

GitHub Copilot unterstützt OAuth per Gerätecode statt einer manuellen Eingabe des API-Schlüssels. Verbinde
**GitHub Copilot**, wähle GitHub.com oder GitHub Enterprise, schließe den Geräteablauf ab und öffne dann `/models`.

```text
/connect
# Select GitHub Copilot, then Login with GitHub Copilot.
/models
```

Gib für GitHub Enterprise bei der Abfrage die URL oder Domain der Instanz ein. OpenCode verwendet einen
Copilot-API-Endpunkt, den GitHub zurückgibt, sofern verfügbar; andernfalls leitet es den Endpunkt aus der
Enterprise-Domain ab.

```text
company.ghe.com
```

Das verbundene Konto benötigt Zugriff auf Copilot Chat. Meldet GitHub keine Berechtigung, registriere dich für Copilot
Free oder bitte die Organisation, dir eine Copilot-Lizenz zuzuweisen, und verbinde dich dann erneut. OpenCode ruft die
aktuelle Modellliste des Kontos nach der Anmeldung und bei jedem Wechsel des aktiven Copilot-Kontos ab.

## Ollama

Starte Ollama und lade ein Modell herunter. OpenCode prüft `http://127.0.0.1:11434`, erkennt Completion-Modelle und fügt
sie ohne Kontoverbindung zu `/models` hinzu.

```bash
ollama serve
ollama pull qwen3:8b
```

Mit `settings.baseURL` verweist du OpenCode auf einen entfernten oder über einen Proxy erreichbaren Ollama-Server. Gib
`/v1` mit an; OpenCode leitet daraus die nativen Erkennungspfade `/api/tags` und `/api/show` ab. `apiKey` ist optional
und wird als Bearer-Token bei Erkennungs- und Modellanfragen mitgesendet.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "ollama": {
      "settings": {
        "baseURL": "https://ollama.example.com/v1",
        "apiKey": "{env:OLLAMA_API_KEY}",
      },
    },
  },
}
```

Die Erkennung wird regelmäßig aktualisiert und behält bei einem vorübergehenden Ausfall den letzten erfolgreich
ermittelten Bestand. Reine Embedding-Modelle erscheinen nicht, da OpenCode nur Modelle hinzufügt, deren
Ollama-Metadaten die Fähigkeit `completion` enthalten.

## Laufzeitumgebungen

LM Studio und vLLM bringen ebenfalls eine integrierte lokale Erkennung mit. Ihre Standardendpunkte sind
`http://127.0.0.1:1234/v1` und `http://127.0.0.1:8000/v1`.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "lmstudio": {
      "settings": { "baseURL": "http://gpu-host:1234/v1" },
    },
    "vllm": {
      "settings": { "baseURL": "http://gpu-host:8000/v1" },
    },
  },
}
```

LM Studio erkennt Sprachmodelle über `/api/v1/models`. vLLM prüft `/health`, bevor es `/v1/models` liest. Seine
Erkennung kann keine Tool-Unterstützung ableiten, daher sind Tools bei erkannten vLLM-Modellen zunächst deaktiviert. Für
eine andere OpenAI-kompatible Laufzeitumgebung folgst du der Anleitung für [eigene Anbieter](#custom) und listest ihre
Modelle ausdrücklich auf.

## Gateways

OpenRouter verwendet seine native Runtime und seinen eigenen Katalog. Übergib dem OpenCode-Server `OPENROUTER_API_KEY`
oder verbinde ein OpenRouter-Konto und gib Modelle dann nach dem Anbieterpräfix mit der vollständigen OpenRouter-Modell-ID
an.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "openrouter/anthropic/claude-sonnet-4",
}
```

Behalte das native OpenRouter-Paket bei, wenn du seinen Endpunkt überschreibst oder über ein OpenRouter-kompatibles
Gateway leitest. So bleibt das Anfrage- und Reasoning-Verhalten von OpenRouter erhalten.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openrouter": {
      "settings": {
        "baseURL": "https://openrouter-gateway.example.com/api/v1",
      },
      "headers": {
        "X-Gateway-Tenant": "engineering",
      },
    },
  },
}
```

Für ein Gateway, das eine OpenAI-kompatible API mit eigenem Modellbestand bereitstellt, definierst du stattdessen einen
eigenen Anbieter. Der Konfigurationsschlüssel wird zum Anbieterpräfix, und jeder Schlüssel unter `models` wird zu einer
auswählbaren Modell-ID.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "company/coder",
  "providers": {
    "company": {
      "env": ["COMPANY_GATEWAY_KEY"],
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "https://gateway.example.com/v1",
      },
      "models": {
        "coder": { "modelID": "upstream/coder-v2" },
      },
    },
  },
}
```

## Fehler

Fehler von Anbietern und Modellen nennen meist die Stufe, an der es gescheitert ist. Prüfe die Umgebung des
Serverprozesses und die genaue Modell-ID, bevor du Pakete änderst.

| Fehler oder Symptom | Prüfen |
| --- | --- |
| `No model is available for session ...` | Derzeit ist kein aktiviertes Modell auswählbar. Schließe die anbieterspezifische Einrichtung ab und wähle dann in `/models` ein Modell. |
| `Model unavailable: provider/model` | Der Anbieter ist inaktiv, die Modell-ID fehlt oder ist deaktiviert, oder die dynamische Erkennung liefert sie nicht mehr. Prüfe bei eigenen Aliassen den Schlüssel in der Map `models`, nicht `modelID`. |
| `Cannot initialize provider/model: NAME is required to resolve the provider endpoint` | In `baseURL` steht noch ein Platzhalter `${NAME}`. Setze diese Variable auf dem OpenCode-Server oder ersetze die Vorlage durch einen vollständigen Endpunkt. |
| `Azure resource name is missing` | Setze `providers.azure.settings.resourceName`, `AZURE_RESOURCE_NAME` oder eine vollständige `settings.baseURL`. |
| Vertex erscheint nicht | Setze ein auflösbares Projekt in den Anbietereinstellungen oder über eine unterstützte Projektvariable. ADC allein aktiviert den Anbieter nicht. |
| Bedrock erscheint nicht | Gib ein Profil oder eine andere unterstützte Quelle der AWS-Credential-Chain an. `AWS_REGION` allein wählt nur eine Region aus. |
| Ollama hat keine Modelle | Stelle sicher, dass der Server `/api/tags` und `/api/show` unter dem aus `baseURL` abgeleiteten Pfad bereitstellt und `/api/show` die Fähigkeit `completion` meldet. |
| Copilot hat keine Modelle | Stelle sicher, dass das aktive OAuth-Konto Zugriff auf Copilot Chat hat. Eine fehlgeschlagene Modellsynchronisierung wird als `failed to sync GitHub Copilot models` protokolliert. |

V2 lehnt die ausgemusterten Anbieter-IDs ab, für die es einen direkten Ersatz gibt. Verwende `azure/<model>` statt
`azure-cognitive-services/<model>` und `google-vertex/<model>` statt `google-vertex-anthropic/<model>`.

## WebSockets

Modelle von OpenAI und xAI sowie unterstützte Azure-Responses-Modelle können pro Sitzung eine WebSocket-Verbindung offen
halten. Aufeinanderfolgende Schritte verwenden das unveränderte Anfragepräfix wieder und senden nur Inhalte, die seit der
vorherigen Antwort hinzugekommen sind. Das reduziert in langen Sitzungen die hochgeladene Datenmenge.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "settings": { "transport": "http" },
    },
  },
}
```

Für WebSockets gelten diese Regeln:

- Integrierte Anbieter aktivieren unterstützte Routen nach ihren eigenen Vorgaben.
- `settings.transport: "websocket"` beim Anbieter aktiviert WebSockets; `"http"` deaktiviert sie.
- `"websocket"` auf einer Route ohne WebSocket-Kanal protokolliert eine Warnung und greift auf HTTP zurück.
- Die Kompaktierung durch den Anbieter OpenAI verwendet dieselbe Verbindung.
- xAI setzt nur auf gespeicherten Antworten auf. Mit dem Standardwert `store: false` wird jeder Schritt vollständig über
  die wiederverwendete Verbindung gesendet.
- Ein geschlossener Socket verbindet sich beim nächsten Schritt neu. Lässt sich die Verbindung nicht öffnen, läuft die
  Sitzung über HTTP weiter.
- Anbieter-Plugins mit den Hooks `http.request` oder `http.response` bleiben bei HTTP, damit jede Anfrage beobachtbar
  bleibt.
