---
title: "Agenten"
---

Lege eine Markdown-Datei an, um einen wiederverwendbaren Agenten hinzuzufügen. Dieses Beispiel ergänzt einen Reviewer
mit reinem Lesezugriff, den der Hauptagent für Code-Reviews starten kann:

```md title=".opencode/agents/reviewer.md"
---
description: Reviews changes for correctness and regressions
mode: subagent
model: anthropic/claude-sonnet-4-5#high
permissions:
  - action: edit
    resource: "*"
    effect: deny
  - action: shell
    resource: "*"
    effect: deny
---

Review the current changes. List findings in severity order with file and line references.
```

Bitte deinen Primäragenten, ihn zu verwenden:

```text
Use the reviewer subagent to review my current changes.
```

Ein Agent fasst System-Prompt, bevorzugtes Modell, Berechtigungen und Anzeigedetails zu einem benannten
Assistentenprofil zusammen.

## Speicherorte

Speichere Markdown-Agenten global für alle Projekte oder innerhalb eines Projekts:

```text
~/.config/opencode/agents/<name>.md
.opencode/agents/<name>.md
```

OpenCode sucht `.opencode`-Verzeichnisse vom aktuellen Verzeichnis aufwärts bis zur Projektwurzel. Ein verschachtelter
Pfad wird Teil der Agenten-ID:

```text
.opencode/agents/team/reviewer.md  →  team/reviewer
```

## Formate

### Markdown

Das Frontmatter akzeptiert dieselben Felder wie ein Eintrag unter `agents` in der Konfiguration. Der Markdown-Inhalt wird
zum `system`-Prompt des Agenten:

```md title=".opencode/agents/explainer.md"
---
description: Explains code without changing it
mode: subagent
---

Explain the relevant code with short examples. Do not edit files.
```

### JSONC

Definiere Agenten unter `agents` in einer beliebigen [OpenCode-Konfigurationsdatei](/config):

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "agents": {
    "reviewer": {
      "description": "Reviews current changes",
      "mode": "subagent",
      "system": "Report findings in severity order.",
      "permissions": [
        { "action": "edit", "resource": "*", "effect": "deny" },
      ],
    },
  },
}
```

## Auswahl

Lege den Primäragenten fest, der verwendet wird, wenn in einer Sitzung keiner ausgewählt wurde:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "default_agent": "writer",
  "agents": {
    "writer": { "mode": "primary" },
  },
}
```

Der gewählte Standardagent muss existieren, sichtbar sein und als Primäragent nutzbar sein. Andernfalls verwendet
OpenCode `build` und danach den ersten sichtbaren Agenten, der als Primäragent nutzbar ist. Eine Änderung dieser
Einstellung ersetzt nicht den Agenten, der in einer bestehenden Sitzung gespeichert ist.

## Modi

Setze `mode` je nachdem, wo der Agent laufen soll:

```jsonc
{
  "agents": {
    "reviewer": { "mode": "subagent" },
  },
}
```

| Modus | Verhalten |
| --- | --- |
| `primary` | Läuft als Hauptagent einer Sitzung. Das ist der Standard für einen neuen eigenen Agenten. |
| `subagent` | Läuft nur in einer untergeordneten Sitzung über das Tool `subagent`. |
| `all` | Läuft entweder als Primäragent oder als Subagent. |

Subagenten laufen mit frischem Kontext in untergeordneten Sitzungen im Vorder- oder Hintergrund. Die
`subagent`-Berechtigungen des übergeordneten Agenten legen fest, welche Agenten er starten darf. Der untergeordnete Agent
verwendet seine eigenen konfigurierten Berechtigungen.

```jsonc
{
  "agents": {
    "orchestrator": {
      "permissions": [
        { "action": "subagent", "resource": "*", "effect": "deny" },
        { "action": "subagent", "resource": "reviewer", "effect": "allow" },
      ],
    },
  },
}
```

## Integrierte Agenten

OpenCode enthält diese sichtbaren Agenten:

| Agent | Modus | Zweck |
| --- | --- | --- |
| **Build** (`build`) | `primary` | Standard-Coding-Agent. Tools sind standardmäßig erlaubt; das Lesen sensibler Umgebungsdateien und Zugriffe außerhalb des Workspace erfordern eine Freigabe. |
| **Plan** (`plan`) | `primary` | Erkundet und plant, ohne normale Projektdateien zu bearbeiten. Auf Anfrage kann er OpenCode-Plandateien schreiben; Shell-Befehle bleiben berechtigungspflichtig. |
| **General** (`general`) | `subagent` | Übernimmt Recherchen und mehrstufige Aufgaben mit breitem Tool-Zugriff, kann aber keine weiteren Subagenten starten. |
| **Explore** (`explore`) | `subagent` | Durchsucht und liest Code oder Webquellen, ohne Dateien zu bearbeiten. |

Einen integrierten Agenten überschreibst du, indem du dieselbe ID verwendest:

```jsonc
{
  "agents": {
    "build": {
      "permissions": [
        { "action": "shell", "resource": "git push *", "effect": "ask" },
      ],
    },
  },
}
```

Die versteckten Agenten `compaction`, `title` und `summary` übernehmen Wartungsaufgaben und können nicht direkt
ausgewählt werden. V2 hat keinen integrierten Agenten `scout`.

## Zusammenführen

Agentendefinitionen werden in der Reihenfolge der Konfiguration zusammengeführt. Spätere skalare Werte ersetzen frühere,
Anfrage-Maps werden nach Schlüssel zusammengeführt, und Berechtigungsregeln werden angehängt:

```jsonc
{
  "permissions": [
    { "action": "shell", "resource": "*", "effect": "ask" },
  ],
  "agents": {
    "build": {
      "permissions": [
        { "action": "shell", "resource": "git status", "effect": "allow" },
      ],
    },
  },
}
```

Globale `permissions` gelten vor agentenspezifischen Regeln, sodass spätere Agentenregeln sie verfeinern können.

## Optionen

### Beschreibung

`description` erklärt den Zweck des Agenten. Gib sie bei Subagenten an, denn OpenCode zeigt sie dem Modell, das
entscheidet, welcher Agent gestartet wird:

```yaml
description: Reviews database migrations for safety
```

### Modus

`mode` akzeptiert `primary`, `subagent` oder `all`. Fehlt die Angabe bei einem neuen eigenen Agenten, ist der Standard
`primary`:

```yaml
mode: all
```

### Modell

`model` verwendet das Format `provider/model` mit optionaler `#variant`:

```yaml
model: anthropic/claude-sonnet-4-5#high
```

Die JSON-Konfiguration akzeptiert auch die ausführliche Form:

```jsonc
{
  "agents": {
    "reviewer": {
      "model": {
        "providerID": "anthropic",
        "model": "claude-sonnet-4-5",
        "variant": "high",
      },
    },
  },
}
```

- Ein Subagent verwendet sein konfiguriertes Modell oder übernimmt das Modell der übergeordneten Sitzung, wenn keines
  konfiguriert ist.
- Eine Sitzung speichert ihr ausgewähltes Modell separat. Wird ein Primäragent über seine ID ausgewählt, ändert das
  dieses Modell nicht.

### System

`system` legt den System-Prompt des Agenten fest. Ein nicht leerer Wert ersetzt für diesen Agenten den Basis-Prompt des
Anbieters:

```jsonc
{
  "agents": {
    "reviewer": { "system": "Review only. Do not modify files." },
  },
}
```

Projektanweisungen, Skills, Referenzen und andere Anweisungsquellen werden weiterhin hinzugefügt. Bei einem
Markdown-Agenten schreibst du diesen Text in den Dokumentinhalt statt in ein Frontmatter-Feld `system`.

### Berechtigungen

`permissions` ist eine geordnete Liste von Abgleichsregeln:

```jsonc
{
  "agents": {
    "reviewer": {
      "permissions": [
        { "action": "*", "resource": "*", "effect": "deny" },
        { "action": "read", "resource": "src/**", "effect": "allow" },
      ],
    },
  },
}
```

| Feld | Bedeutung |
| --- | --- |
| `action` | Tool oder Berechtigungsaktion. Platzhalter werden unterstützt. |
| `resource` | Pfad, Befehl, Agenten-ID oder anderer Wert, mit dem die Aktion abgeglichen wird. Platzhalter werden unterstützt. |
| `effect` | `allow`, `ask` oder `deny`. |

Die letzte passende Regel gewinnt. Setze allgemeine Regeln deshalb vor Ausnahmen. Häufige Aktionen sind:

| Aktion | Umfasst |
| --- | --- |
| `shell` | Shell-Befehle |
| `edit` | Tools zum Bearbeiten, Schreiben und Patchen |
| `subagent` | Untergeordnete Agenten |
| `read`, `glob`, `grep` | Lokale Such-Tools |
| `webfetch`, `websearch` | Web-Tools |
| `skill` | Laden von Skills |

Bei Ressourcen von `read`, `edit` und `external_directory` erweitert OpenCode `~` und `$HOME`:

```jsonc
{ "action": "read", "resource": "~/notes/**", "effect": "allow" }
```

Shell-Ressourcen bleiben unveränderter Befehlstext; diese Werte werden dort nicht erweitert.

### Schritte

`steps` legt eine positive Höchstzahl an Modellschritten fest:

```yaml
steps: 8
```

Im letzten Schritt entfernt OpenCode die Tools und bittet das Modell um eine Zusammenfassung in Textform. Neue
Benutzereingaben setzen das Kontingent zurück.

### Versteckt

`hidden` entfernt einen Agenten aus normalen Auflistungen, der interaktiven Suche und dem Subagenten-Katalog:

```yaml
hidden: true
```

Das steuert nur die Sichtbarkeit, nicht die Sicherheit. Verwende Berechtigungen, um das Verhalten einzuschränken.

### Farbe

`color` legt die UI-Farbe des Agenten als sechsstelligen Hex-Wert fest:

```yaml
color: "#ff6b6b"
```

### Deaktiviert

`disabled` entfernt einen integrierten oder eigenen Agenten an dieser Stelle beim Laden der Konfiguration:

```jsonc
{
  "agents": {
    "plan": { "disabled": true },
  },
}
```

### Anfrage

`request` akzeptiert pro Agent Ergänzungen für Header und JSON-Body:

```jsonc
{
  "agents": {
    "reviewer": {
      "request": {
        "headers": { "x-agent": "reviewer" },
        "body": { "temperature": 0.1 },
      },
    },
  },
}
```

<Callout type="warning">
  Der Sitzungs-Runner von V2 behält diese Werte bei, sendet sie aber noch nicht mit Modellanfragen. Konfiguriere wirksame
  Anfrageeinstellungen stattdessen am Anbieter, am Modell oder an der Modellvariante.
</Callout>

Verwende in neuer V2-Agentenkonfiguration keine Legacy-Felder auf oberster Ebene wie `temperature`, `top_p`, `prompt`,
`permission`, `tools`, `disable` oder `maxSteps`.
