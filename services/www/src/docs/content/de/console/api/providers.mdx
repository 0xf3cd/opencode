---
title: "Anbieter-API"
description: "Die mit deinem Workspace verbundenen Anbieter mit einem Console-Schlüssel über das Console-Gateway aufrufen."
---

Jeder mit deinem Workspace verbundene [Anbieter](/console/providers) wird über das Console-Gateway unter einer eigenen
URL bereitgestellt. OpenCode verwendet sie nach `/connect` automatisch; rufe sie direkt auf, um dieselben Anbieter aus
deinen eigenen Tools zu nutzen. Die Console fügt die Zugangsdaten des Anbieters vor dem Weiterleiten hinzu, sodass das
Secret des Anbieters den Workspace nie verlässt.

```bash
curl -X POST "https://opencode.ai/inference/custom/conn_.../chat/completions" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "deepseek-chat",
    "messages": [{ "role": "user", "content": "Say hi" }]
  }'
```

## Anbieter-URL

Kopiere die **Console API URL** von der Seite des Anbieters unter **Providers**.

```text
https://opencode.ai/inference/custom/<connection_id>
```

## Authentifizierung

Ersetze `<token>` durch einen [Dienstkonto-Schlüssel](/console/api#service-accounts), den du in der Console erstellt
hast. Die Console tauscht ihn vor dem Weiterleiten gegen die Zugangsdaten der Verbindung aus.

```text
Authorization: Bearer <token>
```

Die Console liest den Schlüssel auch aus `x-api-key`, `api-key` oder `x-goog-api-key`. SDKs der Anbieter funktionieren
daher, wenn du sie auf die Console API URL richtest.

## Endpunkte

Hänge den API-Pfad des Anbieters an die Console API URL an. Die Console leitet die Anfrage an die Basis-URL der
Verbindung weiter und gibt die Antwort des Anbieters unverändert zurück.

| Format               | Pfad                              |
| -------------------- | --------------------------------- |
| Chat Completions     | `/chat/completions`               |
| Responses API        | `/responses`                      |
| Anthropic Compatible | `/messages`                       |
| Google Generative AI | `/models/<model>:generateContent` |

Sende die Modell-ID so, wie sie auf der Anbieterseite angezeigt wird. Hat ein Modell beim Anbieter eine andere API-ID,
schreibt die Console sie um. Anfragen für Modelle, die in der Verbindung nicht aktiviert sind, werden abgelehnt.

### Chat Completions

```bash
curl -X POST "https://opencode.ai/inference/custom/conn_.../chat/completions" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "deepseek-chat",
    "messages": [{ "role": "user", "content": "Say hi" }]
  }'
```

### Responses API

```bash
curl -X POST "https://opencode.ai/inference/custom/conn_.../responses" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-5.4",
    "input": "Say hi"
  }'
```

### Anthropic Compatible

`max_tokens` ist erforderlich.

```bash
curl -X POST "https://opencode.ai/inference/custom/conn_.../messages" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "claude-sonnet-4-6",
    "max_tokens": 1024,
    "messages": [{ "role": "user", "content": "Say hi" }]
  }'
```

### Google Generative AI

Modell und Methode sind Teil des Pfads. Ersetze `:generateContent` durch `:streamGenerateContent`, um die Antwort zu
streamen.

```bash
curl -X POST "https://opencode.ai/inference/custom/conn_.../models/gemini-3.1-pro:generateContent" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [{ "parts": [{ "text": "Say hi" }] }]
  }'
```

## Nutzung

Anfragen werden anhand der für jedes Modell festgelegten Preise auf [Budgets](/console/budgets) angerechnet. Die Tokens
rechnet der Anbieter direkt mit dir ab.
