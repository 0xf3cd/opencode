CLI-Plugins erweitern das Terminal um Befehle, Routen, Slots, Markdown-Renderer, Benachrichtigungen und lokalen Zustand.

```ts title="src/tui.ts"
import { Plugin } from "@opencode/plugin/tui"

export default Plugin.define({
  id: "acme.cli",
  setup(context) {
    context.ui.toast.show({ message: "CLI plugin loaded", variant: "success" })
  },
})
```

Importiere `@opencode/plugin/tui` direkt. OpenCode löst diesen Import zur Laufzeit auf, daher brauchen lokale
CLI-Plugins keinen absoluten Pfad zu einem OpenCode-Checkout.

## Kontext

`setup` erhält die Konfiguration, App-Metadaten, die aktuelle Location, den OpenCode-Client, zwischengespeicherte Daten,
Theme-Tokens, den OpenTUI-Renderer und die unten beschriebenen UI-APIs.

```ts
setup(context) {
  const compact = context.options.compact === true
  const location = context.location ?? context.data.location.default()
  const version = context.app.version
  const channel = context.app.channel
  const client = context.client
  const renderer = context.renderer
  const theme = context.theme
}
```

Gib eine Cleanup-Funktion für Ressourcen zurück, die dem Plugin gehören.

```ts
setup(context) {
  const stop = context.data.on("session.execution.succeeded", () => {})
  return () => stop()
}
```

## Client

`context.client` ist der generierte OpenCode-Client und kann den verbundenen Server aufrufen, auch einen entfernten
Server.

```ts
const response = await context.client.plugin.list({
  location: context.location ?? context.data.location.default(),
})
const plugins = response.data
```

## Events

Verwende `data.on` für ein einzelnes typisiertes Event oder `data.listen` für alle Server-Events. Beide geben eine
Funktion zum Abmelden zurück.

```ts
const stopPermission = context.data.on("permission.asked", (event) => {
  context.ui.toast.show({ message: `Permission ${event.data.id}` })
})
const stopAll = context.data.listen(({ details }) => console.log(details.type))

return () => {
  stopPermission()
  stopAll()
}
```

## Sitzungen

Die Sitzungsdaten bieten Auflistung, Abruf, Hierarchie, Kosten, Status, Synchronisierung und Invalidierung.

```ts
const sessions = context.data.session.list()
const session = context.data.session.get(sessionID)
const rootID = context.data.session.root(sessionID)
const familyIDs = context.data.session.family(sessionID)
const cost = context.data.session.cost(sessionID)
const status = context.data.session.status(sessionID)
await context.data.session.sync(sessionID)
context.data.session.invalidate(sessionID)
```

Für ausstehende Inbox-Einträge und Nachrichten gibt es APIs zum Auflisten, Abrufen, Synchronisieren und Invalidieren.

```ts
await context.data.session.pending.sync(sessionID)
const pending = context.data.session.pending.list(sessionID)
context.data.session.pending.invalidate(sessionID)

await context.data.session.message.sync(sessionID)
const messages = context.data.session.message.list(sessionID)
const message = context.data.session.message.get(sessionID, messageID)
context.data.session.message.invalidate(sessionID)
```

Berechtigungsanfragen einer Sitzung lassen sich lesen und aktualisieren.

```ts
await context.data.session.permission.sync(sessionID)
const requests = context.data.session.permission.list(sessionID) ?? []
context.data.session.permission.invalidate(sessionID)
```

Formulare lassen sich an einer Location auflisten, aktualisieren, beantworten oder abbrechen.

```ts
import type { FormCancelInput, FormReplyInput } from "@opencode/client"

async function handleForm(reply: FormReplyInput, cancel: FormCancelInput) {
  const location = context.location
  await context.data.session.form.sync(sessionID, location)
  const forms = context.data.session.form.list(sessionID, location) ?? []
  await context.data.session.form.reply(reply, location)
  await context.data.session.form.cancel(cancel, location)
  context.data.session.form.invalidate(sessionID, location)
}
```

## Projekte und Shells

Projekte und gespeicherte Berechtigungen unterstützen Auflisten, Abrufen, Synchronisieren und Invalidieren.

```ts
await context.data.project.sync()
const projects = context.data.project.list()
const project = context.data.project.get(projectID)
context.data.project.invalidate()

await context.data.project.permission.sync(projectID)
const saved = context.data.project.permission.list(projectID) ?? []
context.data.project.permission.invalidate(projectID)
```

Shell-Daten unterstützen Auflisten, Abrufen, Synchronisieren und Invalidieren, jeweils bezogen auf eine Location.

```ts
await context.data.shell.sync(context.location)
const shells = context.data.shell.list(context.location)
const shell = context.data.shell.get(shellID)
context.data.shell.invalidate(context.location)
```

## Location-Daten

Der Location-Zustand stellt die Standard-Location und Steuerungen zum Aktualisieren bereit.

```ts
const location = context.data.location.default()
await context.data.location.sync(location)
context.data.location.invalidate(location)
```

Der Versionskontrollzustand liefert Repository-Informationen zu einer Location.

```ts
await context.data.location.vcs.sync(context.location)
const vcs = context.data.location.vcs.info(context.location)
const branch = vcs?.branch.current
context.data.location.vcs.invalidate(context.location)
```

Agenten, Befehle, Integrationen, Modelle, Anbieter, Referenzen, Skills und MCP-Daten teilen sich die Methoden `list`,
`sync` und `invalidate`.

```ts
const location = context.location
await Promise.all([
  context.data.location.agent.sync(location),
  context.data.location.command.sync(location),
  context.data.location.integration.sync(location),
  context.data.location.model.sync(location),
  context.data.location.provider.sync(location),
  context.data.location.reference.sync(location),
  context.data.location.skill.sync(location),
  context.data.location.mcp.server.sync(location),
  context.data.location.mcp.resource.sync(location),
])

const agents = context.data.location.agent.list(location) ?? []
const commands = context.data.location.command.list(location) ?? []
const integrations = context.data.location.integration.list(location) ?? []
const models = context.data.location.model.list(location) ?? []
const providers = context.data.location.provider.list(location) ?? []
const references = context.data.location.reference.list(location) ?? []
const skills = context.data.location.skill.list(location) ?? []
const servers = context.data.location.mcp.server.list(location) ?? []
const resources = context.data.location.mcp.resource.list(location) ?? []

context.data.location.model.invalidate(location)
```

```ts
const result = await context.attention.notify({
  title: "OpenCode",

  notification: { when: "blurred" },

console.log(result.ok, result.notification, result.sound, result.skipped)
```

## Theme und Renderer

Verwende semantische Theme-Tokens mit OpenTUI-Elementen und übergib `context.renderer` an rendererspezifische Helfer.

```tsx
const Status = () => <text fg={context.theme.text.base}>Ready</text>
const renderer = context.renderer
```

## Solid-Komponenten

Mit `usePlugin` greifst du in JSX, das von einer Route, einem Dialog oder einem Slot gerendert wird, auf den aktuellen
Kontext zu.

```tsx
import { usePlugin } from "@opencode/plugin/tui"

function Status() {
  const context = usePlugin()
  return <text fg={context.theme.text.base}>{context.app.version}</text>
}
```

## Markdown

Registriere einen Renderer für Codeblöcke einer bestimmten Sprache; die zurückgegebene Funktion meldet ihn wieder ab.

```ts
const unregister = context.markdown.registerCodeBlockRenderer("acme", (_token, render) => render.defaultRender())
return unregister
```

## Befehle und Keymaps

Registriere Befehle für die Palette, Slash-Befehle und Tastaturbefehle in einer reaktiven Keymap-Ebene.

```ts
context.keymap.layer(() => ({
  mode: "global",
  priority: 10,
  commands: [
    {
      id: "acme.status",
      title: "Show Acme status",
      group: "Acme",
      bind: "ctrl+g",
      palette: true,
      slash: { name: "acme", aliases: ["status"], arguments: true },
      enabled: () => true,
      suggested: true,
      run: async (input) => context.ui.toast.show({ message: input ?? "Ready" }),
    },
  ],
  bindings: ["acme.status"],
}))
```

Rufe `layer` in `setup` auf, auch nach einem `await`, oder in einer Komponente. Jede Ebene wird entfernt, sobald das
erste der folgenden Ereignisse eintritt:

- Das Plugin wird deaktiviert oder neu geladen, oder sein Setup schlägt fehl.
- Die Komponente oder reaktive Berechnung, die die Ebene erstellt hat, etwa ein Slot, eine Route oder ein Dialog, wird
  freigegeben.

Die Factory der Ebene muss rein sein. OpenCode wertet sie einmal ohne Abhängigkeitsverfolgung aus, um die anfängliche
Struktur der Befehle zu validieren, und danach reaktiv. Fehler in der anfänglichen Befehlsstruktur, etwa ein
Palettenbefehl ohne ID, werden von `layer()` geworfen. Fehler beim Parsen von Bindings behandelt OpenTUI. Fehler aus
späteren reaktiven Aktualisierungen folgen der Fehlerbehandlung von Solid.

```ts
async setup(context) {
  const settings = await loadSettings()
  context.keymap.layer(() => ({
    mode: "global",
    commands: [{ id: "acme.sync", title: "Sync Acme", palette: true, run: () => sync(settings) }],
  }))
}
```

Eine Ebene kann auf ein einzelnes OpenTUI-Renderable abzielen und in einem Befehl `false` zurückgeben, damit die
Tastaturverarbeitung fortgesetzt wird.

```ts
context.keymap.layer(() => ({
  target: () => panel,
  commands: [{ bind: "escape", run: (_input, event) => (event ? false : undefined) }],
}))
```

Löse Befehle aus, prüfe Tastenkürzel und Befehlszustand oder aktiviere vorübergehend einen eigenen Eingabemodus.

```ts
context.keymap.dispatch("acme.status", "verbose")
const shortcuts = context.keymap.shortcuts("acme.status")
const commands = context.keymap.commands()
const pending = context.keymap.pending()
const active = context.keymap.active()
const currentMode = context.keymap.mode.current()
const popMode = context.keymap.mode.push("acme-search")
popMode()
```

## Speicher

Der dauerhafte Speicher bewahrt JSON über Neustarts hinweg auf und wird zwischen TUI-Instanzen synchronisiert.

```ts
const [settings, updateSettings] = context.storage.store("settings", {
  initial: { compact: false },
})
await updateSettings((draft) => {
  draft.compact = true
})
```

Der In-Memory-Speicher übersteht das Neuladen des Plugins, wird aber verworfen, wenn die TUI beendet wird.

```ts
const [state, updateState] = context.storage.memory("state", {
  initial: { count: 0 },
})
updateState((draft) => {
  draft.count++
})
```

## Dialoge und Toasts

Verwende Promise-basierte Dialoge für Hinweise, Bestätigungen, Texteingaben und Auswahlen.

```ts
await context.ui.dialog.alert({ title: "Acme", message: "Ready" })
const confirmed = await context.ui.dialog.confirm({
  title: "Continue?",
  message: "Run the Acme action?",
  label: { confirm: "Run", cancel: "Cancel" },
})
const name = await context.ui.dialog.prompt({ title: "Name", placeholder: "release" })
const mode = await context.ui.dialog.select({
  title: "Mode",
  current: "safe",
  options: [
    { title: "Safe", value: "safe", description: "Ask before changes" },
    { title: "Fast", value: "fast", disabled: false, category: "Advanced" },
  ],
})
```

### Suche in Auswahldialogen

Übergib `search`, um Abgleich und Reihenfolge der Ergebnisse selbst zu bestimmen. Die Funktion läuft bei jeder Suchanfrage, auch bei der leeren, und erhält nur aktivierte Optionen. Die Ergebnisse werden in der zurückgegebenen Reihenfolge aufgelistet, die jeweilige Kategorie wird inline angezeigt.

```ts
const project = await context.ui.dialog.select({
  title: "Projects",
  options: [
    { title: "Alpha", value: "alpha", category: "Recent" },
    { title: "Beta", value: "beta", category: "Pinned" },
  ],
  search: (query, options) =>
    options
      .filter((option) => option.title.toLowerCase().includes(query.toLowerCase()))
      .toSorted((left, right) => right.title.localeCompare(left.title)),
})
```

### Aktionen in Auswahldialogen

Aktionen erscheinen in der Fußzeile und werden über ihr Tastenkürzel, per Klick oder per Tab-Fokus und anschließendem Enter ausgeführt. Standardmäßig erhalten sie den ausgewählten Wert und sind ohne Auswahl nicht verfügbar. Für Aktionen, die keine Auswahl brauchen, verwende `selection: "none"`.

```ts
await context.ui.dialog.select({
  title: "Projects",
  options: [{ title: "Alpha", value: "alpha" }],
  actions: [
    { bind: "ctrl+o", title: "Inspect", onTrigger: (value) => context.ui.toast.show({ message: value }) },
    { bind: "ctrl+a", title: "Close", side: "right", selection: "none", onTrigger: () => context.ui.dialog.clear() },
  ],
})
```

- Eine Aktion schließt den Dialog nicht und löst das Promise nicht auf.
- Enter oder ein Klick auf eine Option löst das Promise mit dem ausgewählten Wert auf.
- Escape, `clear()` oder das Anzeigen eines anderen Dialogs löst es mit `undefined` auf.
- Belege nicht `ctrl+n` oder `ctrl+p`. Der Dialog reserviert sie für die Navigation, und seine eigenen Bindings haben
  Vorrang.

Eigene JSX-Dialoge können ihre Größe festlegen und sich selbst schließen.

```tsx
context.ui.dialog.set({ size: "large", centered: true })
context.ui.dialog.show(
  () => (
    <box>
      <text>Acme</text>
    </box>
  ),
  () => console.log("closed"),
)
context.ui.dialog.clear()
```

Toasts unterstützen Titel, Nachricht, Variante und Anzeigedauer.

```ts
context.ui.toast.show({
  title: "Acme",
  message: "Saved",
  variant: "success",
  duration: 3000,
})
```

## Routen und Tabs

Registriere eine JSX-Route, frage die aktuelle Route ab und navigiere zur Startseite, zu einer Sitzung oder zur
Plugin-Seite.

```tsx
const unregister = context.ui.router.register({
  name: "dashboard",
  render: ({ data }) => <text>{String(data?.title ?? "Acme")}</text>,
})
const current = context.ui.router.current()
context.ui.router.navigate({ type: "plugin", name: "dashboard", data: { title: "Status" } })
context.ui.router.navigate({ type: "session", sessionID })
context.ui.router.navigate({ type: "home" })
return unregister
```

Sind Sitzungs-Tabs aktiviert, lassen sich Tabs auflisten, öffnen, fokussieren, verschieben und schließen. `open` ändert
den Fokus nicht; `focus` öffnet den Tab bei Bedarf.

```ts
if (context.ui.tabs.enabled()) {
  context.ui.tabs.open(backgroundSessionID)
  context.ui.tabs.focus(sessionID)
  const tabs = context.ui.tabs.list()
  context.ui.tabs.move(backgroundSessionID, tabs.length - 1)
  context.ui.tabs.close(sessionID)
  context.ui.tabs.close()
}
```

## Modell

Lies das ausgewählte Modell des Prompts und ändere seine Variante. `current()` und `variant.list()` sind reaktiv, wenn
sie in einer Solid-Berechnung gelesen werden. Eine `variant` mit dem Wert `undefined` steht für den Standard des Modells.

```ts
const selected = context.ui.model.current()
const variants = context.ui.model.variant.list()
context.ui.model.variant.set("high")
context.ui.model.variant.set(undefined)
```

`variant.set` gibt `false` zurück, wenn kein Modell ausgewählt ist oder das Modell diese Variante nicht hat. Binde die
Methode an einen Befehl, um den integrierten Variantenwechsel zu ersetzen, zum Beispiel um den Standard des Modells zu
überspringen:

```ts
context.keymap.layer(() => ({
  commands: [
    {
      id: "acme.variant.cycle",
      title: "Cycle variants",
      bind: "tab",
      run() {
        const variants = context.ui.model.variant.list()
        if (variants.length === 0) return
        const index = variants.indexOf(context.ui.model.current()?.variant ?? "")
        context.ui.model.variant.set(variants[(index + 1) % variants.length])
      },
    },
  ],
}))
```

## Slots

Slots fügen JSX an `app`, `home.footer`, `home.footer.status`, `prompt.footer`, `prompt.footer.status`,
`prompt.footer.file`, `session.composer.top`, `sidebar.content` oder `sidebar.footer` ein oder ersetzen den Inhalt dort.

```tsx
return context.ui.slot({
  append: "sidebar.content",
  render: ({ sessionID }) => <text>{context.data.session.get(sessionID)?.title}</text>,
})
```

Die Platzierung steuerst du mit `prepend`, `append`, `before`, `after` oder `replace`.

```tsx
context.ui.slot({ prepend: "home.footer", render: () => <text>Before footer content</text> })
context.ui.slot({ append: "home.footer", render: () => <text>After footer content</text> })
context.ui.slot({ before: "home.footer", render: () => <text>Before footer slot</text> })
context.ui.slot({ after: "home.footer", render: () => <text>After footer slot</text> })
context.ui.slot({ replace: "home.footer", render: () => <text>New footer</text> })
```

Mit `home.footer.status` fügst du der integrierten Fußzeile Inhalte hinzu, ohne sie zu ersetzen. Statusbeiträge
erscheinen nach den Statusindikatoren von OpenCode und vor der Version.

```tsx
context.ui.slot({ append: "home.footer.status", render: () => <text>SYNCED</text> })
```

### Sitzungspanels

Registriere einen Beitrag für `session.panel` und öffne das Panel dann über einen Befehl. Der Host ist für Größe, Fokus
und Vollbilddarstellung zuständig, das Plugin für den Inhalt. Der ausgewählte Name wird jedem Beitrag als `panel.name`
übergeben, und jeder Beitrag entscheidet selbst, ob er rendert.

```tsx
import { Show } from "solid-js"

context.ui.slot({
  append: "session.panel",
  render: (panel) => (
    <Show when={panel.name === "acme.review"}>
      <ReviewPanel panel={panel} />
    </Show>
  ),
})

context.ui.slot({
  append: "app",
  render: () => {
    context.keymap.layer(() => ({
      mode: "global",
      commands: [
        {
          id: "acme.review",
          title: "Open review",
          slash: { name: "review" },
          run: () => {
            context.ui.panel.open("acme.review")
          },
        },
      ],
    }))
    return null
  },
})
```

- Außerhalb einer Sitzung gibt das Öffnen `false` zurück.
- Es handelt sich um einen gewöhnlichen Slot: Alle fünf Platzierungen und die bestehenden Regeln zur Reihenfolge beim
  Ersetzen gelten.
- Verwende `append` für unabhängig auswählbare Beiträge, damit sie nebeneinander bestehen können. `replace` übernimmt
  den Slot weiterhin vollständig.
- Namen sind gemeinsam genutzte Auswahlwerte, keine registrierten Ansprüche. Verwende einen Namen mit Plugin-Präfix wie `acme.review`, um Kollisionen zu vermeiden. Wird ein Name ohne passenden Renderer geöffnet, bleibt der Slot leer.
- Ein Wechsel der Darstellung erhält die eingebundenen Beiträge. Das Schließen des Panels gibt sie frei; wird ein Plugin deaktiviert, entfernt die normale Slot-Bereinigung seine Beiträge.
- Seine Tastaturebenen und Eingabemodi sind nur aktiv, solange das Panel die Eingabe besitzt.

Der Slot erhält die reaktiven Eigenschaften `name`, `sessionID`, `width`, `presentation` und `focused` sowie die
Aktionen `focus`, `close` und `toggleFullscreen`. In schmalen Terminals bleibt das Panel im Vollbild;
`toggleFullscreen` wirkt erst, wenn genug Platz für ein seitliches Panel ist.

```tsx
import type { PanelInput } from "@opencode/plugin/tui/context"
import { usePlugin } from "@opencode/plugin/tui"

function ReviewPanel(props: { panel: PanelInput }) {
  const context = usePlugin()
  context.keymap.layer(() => ({
    commands: [
      {
        id: "acme.review.fullscreen",
        bind: "f",
        run: props.panel.toggleFullscreen,
      },
    ],
  }))
  return <text>Reviewing {props.panel.sessionID}</text>
}
```

Du kannst von Anfang an eine Vollbilddarstellung anfordern, dein aktives Panel abfragen oder es schließen, ohne das
Panel eines anderen Plugins zu beeinflussen.

```ts
context.ui.panel.open("acme.review", { presentation: "fullscreen" })
const current = context.ui.panel.current()
context.ui.panel.close()
```

## Veröffentlichen und laden

Stelle das CLI-Plugin über `./tui` bereit; füge OpenTUI als Peer-Abhängigkeiten hinzu, wenn das Plugin JSX rendert.

```json title="package.json"
{
  "name": "opencode-acme-plugin",
  "type": "module",
  "exports": {
    ".": "./src/index.ts",
    "./tui": "./src/tui.tsx"
  },
  "dependencies": {
    "@opencode/plugin": "latest"
  },
  "peerDependencies": {
    "@opentui/core": ">=0.5.8",
    "@opentui/solid": ">=0.5.8",
    "solid-js": ">=1.9.0"
  }
}
```

Exportiere `./tui` neben dem [Haupt-Plugin](/build/plugins), damit es automatisch geladen wird.

```ts title="src/index.ts"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "acme.server",
  setup() {},
})
```

Konfiguriere ein reines CLI-Paket in [`cli.json`](/cli/plugins), damit es auch bei entfernten Servern aktiv bleibt.

```json title="cli.json"
{
  "plugins": ["opencode-acme-plugin"]
}
```
