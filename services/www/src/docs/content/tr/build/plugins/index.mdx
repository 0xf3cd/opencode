Eklentiler OpenCode'un davranışını değiştirebilir ve yeni özellikler ekleyebilir. Terminal arayüzünü değiştirmek için
bir [CLI eklentisi](/build/plugins/cli) geliştirin.

Mevcut bir OpenCode 1 eklentisini mi taşıyorsunuz? [V1 eklenti geçiş kılavuzunu](/build/plugins/migrate-v1) izleyin.

```ts title=".opencode/plugins/example/index.ts"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "example",
  async setup(ctx) {
    await ctx.storage.set("loaded", true)
  },
})
```

`.opencode/plugins/` altındaki eklentiler, yukarıdaki yerel örnekte olduğu gibi otomatik olarak yüklenir. Yayımlanmış
paketleri veya başka konumlardaki eklenti dizinlerini yüklemek için bunları `opencode.json(c)` dosyasındaki `plugins`
listesine ekleyin:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": [
    "opencode-acme-plugin",
    "opencode-acme-plugin@1.2.0",
    "@acme/opencode-plugin",
    "./plugins/local",
    "../shared/plugin",
    "/absolute/path/plugin",
    "file:///home/me/plugins/local",
    {
      "package": "@acme/opencode-plugin",
      "options": {
        "agent": "reviewer",
        "strict": true,
      },
    },
  ],
}
```

Diğer yükleme ve yapılandırma seçenekleri için [Eklentileri yapılandırma](/plugins) sayfasına bakın.

## Yaşam döngüsü

`setup`, eklenti yüklendiğinde çalışır. Eklenti kaldırıldığında çalışacak bir temizleme fonksiyonu döndürebilir.

```ts
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "example",
  setup(ctx) {
    console.log(`loaded in OpenCode ${ctx.app.version}`)
    return () => console.log("unloaded")
  },
})
```

### Bağlam

Eklenti bağlamı özünde bir [OpenCode sunucu istemcisidir](/build/client). Okuma ve eylem metotları istemciyle aynı
girdileri ve yanıtları kullanır. Bunlara ek olarak dönüşümler, çalışma zamanı hook'ları, yeniden yüklemeler, kayıtlar ve
eklenti seçenekleri için yalnızca eklentilere özel metotlar sunar.

```ts
setup(ctx) {
  console.log(ctx.app.version)
}
```

`ctx.location`, bu eklenti örneğinin yüklendiği konumu tanımlar. `directory` alanını, isteğe bağlı `workspaceID`
alanını ve `project` meta verilerini (`id`, `directory` ve `canonical`) içerir. Hem Promise hem de Effect eklentilerinde
kullanılabilir. Bu, eklenti örneğinin konumudur; erişebildiği her oturumun veya aldığı her olayın konumu değildir.

```ts
setup(ctx) {
  console.log(ctx.location.directory)
  console.log(ctx.location.project.canonical)
}
```

### Seçenekler

Eklenti seçeneklerini `opencode.json(c)` dosyasında nesne biçimiyle geçirin.

```jsonc title="opencode.jsonc"
{
  "plugins": [
    {
      "package": "./plugins/company",
      "options": {
        "strict": true,
      },
    },
  ],
}
```

Bu değerleri `setup` sırasında `ctx.options` üzerinden okuyun.

```ts title="plugins/company/index.ts"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "company",
  setup(ctx) {
    const strict = ctx.options.strict === true
  },
})
```

## Dönüşümler

Dönüşümler, OpenCode'un alan (domain) durumunda yapılan senkron düzenlemelerdir ve her biri kendi alanındaki önceki
kayıtların üzerine kurulur. `ctx.model.list()` gibi kayıt defteri okumaları, eklenti kurulumu sırasında da dahil olmak
üzere o ana kadarki tüm kayıtları yansıtır. Başlangıçtaki toplu işleme yalnızca güncelleme bildirimlerini birleştirir;
bir okumanın döndürdüğü sonucu asla geciktirmez. Kaynak durumu API'leri ise çalışan kaynakların durumunu bildirmeye devam
eder: bir tanımın kaydedilmiş olması, bağlantısının veya diğer kaynak işlerinin tamamlandığı anlamına gelmez.

Kaynaklar, sağlayıcıları ve değiştirilemez model tanımlarını `ctx.provider.transform` üzerinden ekler.

```ts title="plugins/models/index.ts"
import { Model, Plugin, Provider } from "@opencode/plugin"

export default Plugin.define({
  id: "company.models",
  async setup(ctx) {
    const providerID = Provider.ID.make("acme")
    const models = [{ ...Model.Info.default(providerID, Model.ID.make("reasoner")), name: "Acme Reasoner" }]
    await ctx.provider.transform((editor) => {
      editor.add({
        info: {
          ...Provider.Info.empty(providerID),
          name: "Acme",
          activation: "enabled",
          package: "@opencode/ai/providers/openai-compatible",
          settings: { baseURL: "http://127.0.0.1:8000/v1" },
        },
        models,
      })
    })

    const available = await ctx.model.list()
  },
})
```

Herhangi bir kayıt, kaldırma veya `reload()` çağrısı kayıt defterini değişmiş olarak işaretler. Sonraki okuma, tüm etkin
dönüşümleri kayıt sırasıyla yeni bir değer üzerinde yeniden oynatarak kayıt defterini yeniden oluşturur. Dönüşümleri
hafif ve tekrarlanabilir tutun. Daha önce okuduğunuz bir değer, sonraki yeniden oluşturmalarla asla değişmez.

Sağlayıcı dönüşümleri ve kullanılabilirlik çözümlendikten sonra OpenCode, etkin sağlayıcıların modellerini oluşturur ve
tüm model dönüşümlerini sırayla yeniden oynatır. Bir model politikası, yeni yenilenen kaynaklar da dahil olmak üzere aday
koleksiyonun tamamını inceleyebilir.

```ts title="plugins/model-budget/index.ts"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "company.model-budget",
  async setup(ctx) {
    await ctx.model.transform((editor) => {
      editor
        .list()
        .filter((model) => model.cost.some((tier) => tier.output > 20))
        .forEach((model) => {
          editor.remove(model.providerID, model.id)
        })
    })
  },
})
```

Yakalanan girdiler otomatik olarak izlenmez. Harici verileri senkron geri çağırmadan önce yükleyin, ardından bu girdiler
değiştiğinde `reload()` çağırın. Buradaki `loadFromSource()`, `{ info: Provider.Info, models: readonly Model.Info[] }`
girdileri döndürür.

```ts title="plugins/models/index.ts"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "company.models",
  async setup(ctx) {
    const source = { providers: await loadFromSource() }

    await ctx.provider.transform((editor) => {
      source.providers.forEach((provider) => editor.add(provider))
    })

    const refresh = async () => {
      source.providers = await loadFromSource()
      await ctx.provider.reload()
    }

    const timer = setInterval(() => void refresh().catch(console.error), 60_000)
    return () => clearInterval(timer)
  },
})
```

Sağlayıcı değişiklikleri etkin model sonucunun tamamını geçersiz kılar; bu nedenle çıktı fiyatı politikası yenilenen
modelleri de filtrelemeye devam eder. Yalnızca bir model dönüşümünün yakaladığı bir girdi değiştiğinde
`ctx.model.reload()` kullanın.

## API

### Ajan

Tüm ajanları okuyun veya birini ID ile getirin.

```ts
const agents = await ctx.agent.list()
const build = await ctx.agent.get({ agentID: "build" })
```

Ajanları incelemek, güncellemek, kaldırmak veya varsayılan ajanı seçmek için bir dönüşüm kaydedin.

```ts
await ctx.agent.transform((editor) => {
  const agents = editor.list()
  const build = editor.get("build")

  editor.default("build")
  editor.update("build", (agent) => {
    agent.description = "Builds features and fixes bugs"
  })
  editor.remove("legacy")
})
```

Bir dönüşümün kullandığı harici durum değiştiğinde ajanları yeniden yükleyin.

```ts
await ctx.agent.reload()
```

#### Başvuru

Şema: [`Agent.Info`](/api#schema-Agent.Info)

```ts
interface AgentContext {
  list(input?: AgentListInput, requestOptions?: RequestOptions): Promise<AgentListOutput>
  get(input: AgentGetInput, requestOptions?: RequestOptions): Promise<AgentGetOutput>
  transform(callback: (editor: AgentEditor) => void): Promise<Registration>
  reload(): Promise<void>
}

interface AgentEditor {
  list(): readonly AgentInfo[]
  get(id: string): AgentInfo | undefined
  default(id: string | undefined): void
  update(id: string, update: (agent: AgentInfo) => void): void
  remove(id: string): void
}

interface Registration {
  dispose(): Promise<void>
}
```

### Sağlayıcılar

Kullanılabilir sağlayıcıları okuyun veya bir sağlayıcının meta verilerini ID ile inceleyin.

```ts
const providers = await ctx.provider.list()
const provider = await ctx.provider.get({ providerID: "anthropic" })
```

Sağlayıcı dönüşümleri, sağlayıcı ayarlarını ve kaynak tanımlarını düzenler. Düzenleyici okumaları etkin olmayan
sağlayıcıları da içerir ve değiştirilemez tanımlar sunar; `models.update` ise bir kaynak modelin size ait bir kopyasını
düzenler.

```ts
await ctx.provider.transform((editor) => {
  editor.update("anthropic", (provider) => {
    provider.headers = { ...provider.headers, "x-company": "engineering" }
  })
  editor.models.update("anthropic", "claude-sonnet-4-5", (model) => {
    model.name = "Team Sonnet"
  })
  editor.models.remove("anthropic", "legacy-model")
  editor.remove("legacy-provider")
})
```

Bir sağlayıcının kaynak envanterini `models.set` ile değiştirin, ardından yakalanan tanımlar değiştiğinde yeniden yükleyin.

```ts
const source = { models: await loadModels() }
await ctx.provider.transform((editor) => {
  editor.models.set("acme", source.models)
})

source.models = await loadModels()
await ctx.provider.reload()
```

Hesaba özgü keşif için envanteri yüklerken kullanılan bağlantıyı `sourceConnection` olarak geçirin. Başka bir bağlantı
seçiliyken OpenCode, eklentiniz yenilenmiş envanterini yayımlayana kadar o sağlayıcıyı hariç tutar.

```ts
const connection = await ctx.integration.connection.active("acme")
if (!connection) return
const inventory = await loadInventory(connection)
await ctx.provider.transform((editor) => {
  editor.add({ info: inventory.provider, models: inventory.models, sourceConnection: connection })
})
```

#### Başvuru

Şemalar: [`Provider.Info`](/api#schema-Provider.Info), [`Model.Info`](/api#schema-Model.Info)

```ts
interface ProviderDomain extends ProviderApi {
  transform(callback: (editor: ProviderEditor) => void): Promise<Registration>
  reload(): Promise<void>
}

interface ProviderRecord {
  readonly provider: Provider.Info
  readonly models: ReadonlyMap<string, Model.Info>
  readonly sourceConnection?: ConnectionInfo
}

interface ProviderEditor {
  list(): readonly ProviderRecord[]
  get(providerID: string): ProviderRecord | undefined
  add(input: { info: Provider.Info; models: readonly Model.Info[]; sourceConnection?: ConnectionInfo }): void
  update(providerID: string, update: (provider: DeepMutable<Provider.Info>) => void): void
  remove(providerID: string): void
  readonly models: {
    set(providerID: string, models: readonly Model.Info[]): void
    update(providerID: string, modelID: string, update: (model: DeepMutable<Model.Info>) => void): void
    remove(providerID: string, modelID: string): void
  }
}
```

### Modeller

Kullanılabilir modelleri ve varsayılan seçimi okuyun.

```ts
const models = await ctx.model.list()
const selected = await ctx.model.default()
```

Model dönüşümleri, etkin sağlayıcıların aday koleksiyonunun tamamını düzenler. Devre dışı adaylar, tüm dönüşümler
bitene kadar düzenlenebilir kalır; `update` yalnızca kullanılabilir bir sağlayıcının altına model ekleyebilir.

```ts
await ctx.model.transform((editor) => {
  editor.list("anthropic").forEach((model) => {
    editor.update(model.providerID, model.id, (draft) => {
      draft.enabled = draft.capabilities.tools
    })
  })
  editor.default.set("anthropic", "claude-sonnet-4-5")
  editor.remove("anthropic", "legacy-model")
})
```

Geri çağırmalar ham model geçersiz kılmalarını düzenler. Sağlayıcı varsayılanları, OpenCode sonucu kesinleştirdiğinde bir
kez birleştirilir; değişmeyen okumalar bu sonucu yeniden kullanır. `editor.provider`, model dönüşümünün çıktısını değil,
etkin olmayan şablonlar da dahil olmak üzere değiştirilemez kaynak tanımlarını sunar.

```ts
await ctx.model.transform((editor) => {
  const source = editor.provider.get("anthropic")?.models.get("claude-sonnet-4-5")
  if (!source) return
  editor.update("anthropic", source.id, (model) => {
    model.limit.context = Math.min(model.limit.context, source.limit.context)
  })
})

await ctx.model.reload()
```

Şema: [`Model.Info`](/api#schema-Model.Info)


### Entegrasyonlar

Entegrasyonları okuyun ve etkin kimlik bilgilerini inceleyin.

```ts
const integrations = await ctx.integration.list()
const github = await ctx.integration.get({ integrationID: "github" })
const connection = await ctx.integration.connection.active("github")
const credential = connection ? await ctx.integration.connection.resolve(connection) : undefined
```

Entegrasyonları bir API anahtarıyla bağlayın.

```ts
await ctx.integration.connect.key({
  integrationID: "github",
  key: process.env.GITHUB_TOKEN!,
})
```

Bir OAuth bağlantı girişimini başlatın, inceleyin, tamamlayın veya iptal edin.

```ts
const attempt = await ctx.integration.oauth.connect({ integrationID: "github", methodID: "oauth" })
const status = await ctx.integration.oauth.status({ integrationID: "github", attemptID: attempt.data.attemptID })
await ctx.integration.oauth.complete({ integrationID: "github", attemptID: attempt.data.attemptID, code })
await ctx.integration.oauth.cancel({ integrationID: "github", attemptID: attempt.data.attemptID })
```

Komut tabanlı bağlantılar da aynı başlatma, durum ve iptal akışını sunar.

```ts
const attempt = await ctx.integration.command.connect({ integrationID: "acme", methodID: "cli" })
const status = await ctx.integration.command.status({ integrationID: "acme", attemptID: attempt.data.attemptID })
await ctx.integration.command.cancel({ integrationID: "acme", attemptID: attempt.data.attemptID })
```

Entegrasyonları incelemek ve kimlik doğrulama yöntemlerini yönetmek için bir dönüşüm kaydedin.

```ts
await ctx.integration.transform((editor) => {
  const integrations = editor.list()
  const acme = editor.get("acme")

  editor.update("acme", (integration) => {
    integration.name = "Acme"
  })
  editor.method.update({
    integrationID: "acme",
    method: { id: "cli", type: "command", label: "Sign in with Acme CLI", command: ["acme", "login"] },
  })

  const methods = editor.method.list("acme")
  const legacy = methods.find((method) => method.type === "command" && method.id === "legacy")
  if (legacy) editor.method.remove("acme", legacy)
  editor.remove("legacy")
})
```

Bir dönüşümün kullandığı harici durum değiştiğinde entegrasyonları yeniden yükleyin.

```ts
await ctx.integration.reload()
```

### MCP

MCP sunucularını ve geçerli bağlantı durumlarını listeleyin.

```ts
const servers = await ctx.mcp.list()
```

Eklentiler MCP sunucularını yalnızca dönüşümler aracılığıyla yönetir. Sunucu eklemek veya değiştirmek için `editor.set`,
yapılandırmasını değiştirmek için `editor.update`, kaldırmak için `editor.remove` kullanın. Yapılandırmayı `editor.list`
ve `editor.get` ile inceleyin.

```ts
await ctx.mcp.transform((editor) => {
  const servers = editor.list()
  const docs = editor.get("docs")
  editor.set("docs", { type: "remote", url: "https://mcp.example.com" })
  editor.update("docs", (server) => {
    server.disabled = false
  })
  editor.remove("legacy")
})
```

Bir sunucuyu devre dışı bırakıp bağlantısını kesmek için dönüşümde `disabled: true`, etkinleştirip OpenCode'un
bağlanmasına izin vermek için `disabled: false` ayarlayın. OpenCode, sunucu yaşam döngüsünü dönüştürülmüş yapılandırmaya
göre uzlaştırır.

Bir dönüşümün kullandığı harici durum değiştiğinde, dönüşümleri yeniden uygulamak ve sunucuları uzlaştırmak için
`reload()` çağırın.

```ts
await ctx.mcp.reload()
```

### Referanslar

Bir konumda kullanılabilen referansları okuyun.

```ts
const references = await ctx.reference.list()
```

Yerel ve Git referanslarını incelemek, eklemek veya kaldırmak için bir dönüşüm kaydedin. `get(name)`, yapılandırılmış
geçerli kaynağı, ad yoksa `undefined` döndürür.

```ts
await ctx.reference.transform((editor) => {
  const references = editor.list()
  editor.add("handbook", { type: "local", path: "/workspace/docs/handbook" })
  editor.add("standards", { type: "git", repository: "https://github.com/acme/standards", branch: "main" })
  const handbook = editor.get("handbook")
  editor.remove("legacy")
})
```

### Araçlar

Tüm dönüşümler uygulandıktan sonra o anda kayıtlı olan araçları, bir dönüşüm geri çağırmasının dışında okuyun. Her aracın,
etkin adını içeren bir `id` değeri vardır.

```ts
const tools = await ctx.tool.list()
const read = tools.find((tool) => tool.id === "read")
```

Promise eklentileri de dahil olmak üzere araçları senkron bir dönüşümle kaydedin, güncelleyin ve kaldırın. Harici
verileri kayıttan veya yeniden yüklemeden önce yükleyin. Sonraki geçerli bir kayıt, aynı etkin araç adını geçersiz kılar.

```ts
const registration = await ctx.tool.transform((editor) => {
  editor.namespace({
    name: "acme",
    description: "Customer account tools",
  })
  editor.add({
    name: "greeting",
    description: "Create a greeting",
    input: {
      type: "object",
      properties: { name: { type: "string" } },
      required: ["name"],
      additionalProperties: false,
    },
    options: { namespace: "acme", codemode: true },
    execute: async (input, context) => {
      await context.progress({ status: "greeting" })
      return { content: `Hello ${(input as { name: string }).name}!` }
    },
  })
})
```

Promise araç yürütücüleri `context.signal` alır. Oturum durdurulduğunda alttaki işlemin de durması için bunu `fetch` gibi
iptal edilebilir işlere geçirin.

```ts
execute: async ({ url }, context) => {
  const response = await fetch(url, { signal: context.signal })
  return { content: await response.text() }
}
```

Geri çağırmanın yakaladığı kaynak verileri değiştirdikten sonra `reload()` çağırın. Yeniden yükleme, etkin dönüşümleri
sıralarını değiştirmeden yeniden oynatır; eklenti kurulumunu yeniden çalıştırmaz.

```ts
await ctx.tool.reload()
```

Düzenleyicide o anda bulunan araçları incelemek için `list()` ve `get()` kullanın. Araçların etkin adlarını içeren bir
`id` değeri vardır; bu ID yoksa `get()` `undefined` döndürür. `update` ve `remove` çağrılarında, ad alanı (namespace)
dahil etkin araç adını kullanın (yukarıdaki örnekte `acme_greeting`). Ad alanlarındaki noktalar ve araç adlarındaki
desteklenmeyen karakterler `_` olur. Bulunmayan adlar yok sayılır; araç oluşturmak için tam bir tanımla `add` çağırmak
gerekir. Güncellemeler adı ve ad alanını korur. İç içe değerleri değiştirmek yerine yeni şemalar veya seçenekler atayarak
bunları değiştirin. Geçersiz güncellemeler günlüğe kaydedilir ve önceki tanım olduğu gibi kalır.

```ts
await ctx.tool.transform((editor) => {
  editor.update("acme_greeting", (tool) => {
    tool.description = "Greet the user by name"
  })
  editor.remove("acme_obsolete")
})
```

Güncellemeler ve kaldırmalar, MCP kataloğu yenilendikten sonra da dahil olmak üzere eklemelerle birlikte sırayla yeniden
oynatılır. Kayıtlarını serbest bırakmak bu değişiklikleri kaldırır ve kalan dönüşümlerden yeniden oluşturur.

Bir kaydı serbest bırakarak (dispose) dönüşümünü kaldırın ve kalan dönüşümlerden yeniden oluşturun; böylece geçersiz
kıldığı önceki tanım yeniden ortaya çıkar. Serbest bırakma idempotenttir; eklentiyi kaldırmak da kayıtlarını serbest
bırakır.

```ts
await registration.dispose()
```

Her model isteği, sabit ve çalıştırılabilir bir araç anlık görüntüsü yakalar. Sonraki dönüşümler, yeniden yüklemeler ve
serbest bırakmalar gelecekteki anlık görüntüleri etkiler; önceden yakalanmış tanımları, Code Mode ad alanı
açıklamalarını veya yürütücüleri etkilemez. Değiştirilebilir eklenti verilerini closure ile yakalayan yürütücüler bu
verileri görmeye devam eder; bir değerin o tanıma bağlı kalması gerekiyorsa onu dönüşümün içinde yakalayın.

#### Başvuru

Şemalar: [`Tool.Content`](/api#schema-Tool.Content), [`Tool.TextContent`](/api#schema-Tool.TextContent),

### VCS

Depo bilgilerini, çalışma kopyası durumunu veya dosya farklarını okuyun.


Konum kapsamlı bir VCS sağlayıcısını dönüşümle kaydedin. Algılanan depo türüyle eşleşen sağlayıcı otomatik olarak seçilir;
farklı bir sağlayıcı seçmek için `editor.default.set` kullanın.

```ts
await ctx.vcs.transform((editor) => {
  editor.add({
    id: "custom",
    name: "Custom VCS",
    info: async () => ({ branch: { current: "feature", default: "main" } }),
    branches: async (input, { signal }) => readBranches(input, signal),
    status: async (scope, { signal }) => readStatus(scope.worktree, signal),
    diff: async (input, { signal }) => readDiff(input, signal),

})
```

Sağlayıcı geri çağırmaları geçerli konumu, çalışma kopyası kökünü, kanonik proje kökünü ve isteğe bağlı repository
store'u alır. Diff geri çağırmaları ayrıca seçilen modu, istenen bağlam satırı sayısını ve çıktı bayt
bütçesini alır. Depo keşfi, OpenCode'un yerleşik Git ve Mercurial algılayıcılarını kullanmaya devam eder.

Sağlayıcılar, `scope.worktree` içinde depo oluşturmak için isteğe bağlı olarak `init(scope, { signal })` uygulayabilir.
Başlatma, sağlayıcıyı algılanan depo türüne göre değil, ID'ye göre seçer (varsayılan olarak Git). Konumda henüz depo
olmasa bile `init` içeren bir sağlayıcı kaydedin; OpenCode onu çağırmadan önce dizinin var olduğunu ve depo içermediğini
kontrol eder, ardından projeyi yeniden keşfeder. Yeni depo biçimleri, bu geri çağırmanın ötesinde keşif desteğine yine de
ihtiyaç duyar.

### Worktree'ler

Normal eklenti yaşam döngüsünü kullanarak yerel bir worktree stratejisi kaydedin. Bu örnekteki uygulama modülü, seçenek
doğrulamasından ve arka ucun `create`, `remove` ve `list` işlemlerinden sorumludur.

```ts title="plugins/worktrees/index.ts"
import { Plugin } from "@opencode/plugin"
import { makeStrategy } from "./strategy"

export default Plugin.define({
  id: "company.worktrees",
  async setup(ctx) {
    const strategy = makeStrategy(ctx.options)
    await ctx.worktree.transform((editor) => {
      editor.add(strategy)
    })
  },
})
```

Eklentiyi `plugins` üzerinden yükleyin ve ortak hedef dizini ayrıca yapılandırın:

```jsonc title="opencode.jsonc"
{
  "worktree": { "directory": "../worktrees" },
  "plugins": [{ "package": "./plugins/worktrees", "options": {} }],
}
```

- Bir strateji eklemek onu otomatik olarak seçer. Son etkin kayıt geçerli olur; strateji seçimi için yapılandırma
  gerekmez.
- Kaydını serbest bırakmak veya eklentiyi kaldırmak önceki uygulamayı, en sonunda da paketle gelen Git stratejisini geri
  getirir.
- `reload()`, yakalanan girdiler değiştiğinde dönüşümleri yeniden oynatır; eklenti kurulumunu yeniden çalıştırmaz.
- Oluşturma hatalarında Git üzerinden yeniden deneme yapılmaz. Mevcut worktree'ler, varsayılan değişse bile kayıtlı
  sahiplerini korur.
- Stratejiler yerel dizinleri yönetir. Uzak çalışma alanı hazırlama bu arayüzün parçası değildir.

#### İşlemler

Eklenti bağlamı, istemciyle aynı proje tabanlı worktree işlemlerini sunar. Her işlem bir `projectID` gerektirir. `list`,
aynı projenin bilinen checkout'ları dahil yalnızca kaydedilmiş envanteri okur; yapılandırma yüklemez, eklenti başlatmaz
veya dosya sistemi değişikliklerini keşfetmez.

```ts
const projectID = ctx.location.project.id
const created = await ctx.worktree.create({ projectID, name: "task" })
const inventory = await ctx.worktree.list({ projectID })
await ctx.worktree.refresh({ projectID })
await ctx.worktree.remove({ projectID, directory: created.directory, force: false })
```

Oluşturma işlemi, yapılandırmayı ve eklentileri projenin kaydedilmiş `canonical` dizininden yükler ve onların seçtiği
stratejiyi kullanır. İsteğe bağlı olarak üst dizin (`directory`), kaynak (`from`), başlangıç dalı (`branch`) ve ad
(`name`) kabul eder. Kaynak varsayılan olarak kanonik checkout'tur; `from` ile verilen bir kaynak o projeye ait olmalıdır.
Kaynak seçmek yapılandırma kökünü değiştirmez. Verilen başlangıç ref'i seçili strateji tarafından desteklenmelidir;
örneğin Rift'in yerel anlık görüntü işleminde ref seçme seçeneği yoktur.

Oluşturma ve yenileme, kanonik checkout'un eklentilerinin etkinleşmesini bekler. O checkout'un eklenti kurulumu sırasında
yapılan çağrılar o ana kadarki kayıtları görür ve kendi etkinleşmelerini beklemez.

Kaldırma işlemi kanonik yapılandırmayı yükleyip eklentilerini etkinleştirir, ardından o anda seçili varsayılan yerine
worktree'nin kayıtlı stratejisini kullanır. Kayıtlı sahip kullanılamıyorsa hata oluşur. Worktree'nin hedefi başka bir
yerde olabilir:

```ts
await ctx.worktree.remove({
  directory: "/worktrees/task",
  projectID,
  force: false,
})
```

Sahibi bulunamayan worktree'lerde kaldırma işlemi Git'e geri dönmek yerine başarısız olur. Bir strateji, Core veya Git
hatalarına bağımlı olmadan zorla kaldırma onayı istemek için `Worktree` öğesini `@opencode/plugin` paketinden içe aktarıp
`new Worktree.OperationError({
message: "Uncommitted changes", forceRequired: true })` fırlatabilir.

Yenileme işlemi kanonik yapılandırmayı yükler ve kullanılabilir tüm stratejilerden bilinen checkout kökleri genelinde
worktree'leri bulmalarını ister. Sonuçları birleştirir, kayıtlı sahipliği korur ve artık var olmayan dizinleri ayıklar.
Başarısız olan bir keşif kaynağı günlüğe kaydedilir, diğer kaynaklar devam eder. Var olan dizinler, kullanılabilir
hiçbir strateji onları bildirmese bile kayıtlı kalır. Değişen envanteri okumak için `worktree.updated` olayını izleyin ve
`list` işlemini yeniden çağırın.

```ts
await ctx.worktree.refresh({ projectID })
```

#### Başvuru

Uygulamalar, adlandırma ve çakışma yönetimi yapıldıktan sonra önerilen bir hedef alır. `create` işleminden gerçek dizini
döndürün; bir arka uç kendi dizin düzenini gerektiriyorsa bu dizin farklı olabilir. OpenCode döndürülen yolu çözümler ve
envanter, başlangıç komutları ve API sonucu için kullanır. Döndürülen dizin var olmalıdır.

Başka bir hedef seçen stratejiler, oradaki ad çakışmalarını kendileri ele alır. OpenCode yine de stratejiyi çağırmadan
önce önerilen üst dizini oluşturur. `list` yalnızca stratejinin sahip olduğu dizinleri ve varsa depo köklerini
bildirmelidir.

```ts
interface WorktreeDefinition {
  readonly id: string
  create(
    input: { sourceDirectory: string; directory: string; branch?: string },
    context: { signal: AbortSignal },
  ): Promise<{ directory: string }>
  remove(input: { directory: string; force: boolean }, context: { signal: AbortSignal }): Promise<void>
  list(
    sourceDirectory: string,
    context: { signal: AbortSignal },
  ): Promise<readonly { directory: string; type: "root" | "worktree" }[]>
}

interface WorktreeEditor {
  add(definition: WorktreeDefinition): void
}

interface WorktreeDomain extends WorktreeApi {
  transform(callback: (editor: WorktreeEditor) => void): Promise<Registration>
  reload(): Promise<void>
}
```

Promise geri çağırmaları `signal` ile yapılan iptale uyum sağlamalıdır. Effect geri çağırmaları ise Effect döndürür ve
bunun yerine Effect kesintisini (interruption) kullanır. Kayıtlar eklentinin çalışma zamanına göre kapsamlı kalır; proje
işlemleri kanonik checkout'un kayıt defterini kullanır. Core yapılandırma bağdaştırıcıları dizin ayarlarını bu kayıt
defterine aktarır.

```ts
await ctx.websearch.transform((editor) => editor.default.set(false))
```

Şemalar: [`WebSearch.Provider`](/api#schema-WebSearch.Provider), [`WebSearch.Result`](/api#schema-WebSearch.Result)

## Hook'lar

Hook'lar canlı işlemlere müdahale eder. Bir hook'u ilgili alana kaydedin ve artık gerekmediğinde döndürülen kaydı serbest
bırakın.

```ts
const registration = await ctx.session.hook("context", () => {})
await registration.dispose()
```

Birden fazla eklenti aynı hook'u kaydedebilir. OpenCode bunları eklenti sırasıyla çalıştırır; böylece sonraki hook'lar
önceki hook'ların yaptığı değişiklikleri görür.

### Oturumlar

Oturum hook'ları istem kabulüne, model çağrılarına, yerel HTTP'ye ve yeniden denemelere müdahale eder.

#### İstem kabulü

Gelen kullanıcı istemlerini; ek ve beceri çözümlemesinden ve kalıcı gelen kutusuna kabulden önce yakalayın:

```ts
await ctx.session.hook("prompt", (event) => {
  event.prompt.text = event.prompt.text.replaceAll("company-secret", "[redacted]")
  event.prompt.files ??= []
  event.prompt.files.push({ uri: "file:///project/policy.md" })
  event.metadata = { ...event.metadata, source: "company-policy" }
  event.delivery = "queue"
})
```

Hook, size ait ve değiştirilebilir bir taslak alır:

- `prompt`; `text`, `files`, `agents` içindeki ajan anmalarını ve seçili `skills` değerlerini içerir.
- `metadata`, uygulama tarafından tanımlanan kabul meta verilerini içerir.
- `delivery` varsayılan olarak `"steer"` olur ve `"queue"` olarak değiştirilebilir.
- Oturum ve mesaj ID'leri salt okunurdur; hook kabulü başka bir yere yönlendiremez.

Hook tarafından eklenen dosyalar ve beceriler normal çözümleme ve doğrulama yolunu izler. Metni yeniden yazarken artık
eşleşmeyen ek `mention` konumlarını güncelleyin veya kaldırın. Ajan anmaları oturumun etkin ajanını değiştirmez.

İstem hook'ları şu koşullarda çalışır:

- Hook'lar, oturumun konum eklentileri hazır olduktan sonra kayıt sırasıyla çalışır.
- `session.prompt` üzerinden gönderim yapan komutlar hook'u çalıştırır.
- Sentetik mesajlar, shell mesajları, sıkıştırma denetimleri ve taşıma denetimleri çalıştırmaz.
- Hook her model çağrısından önce değil, kabul sırasında bir kez çalışır.
- Model çözümlemesi kabulden sonra gerçekleştiği için sağlayıcıya göre kapsamlama kullanılamaz.

Düzenlemeler kalıcı olarak kaydedilen kanonik kullanıcı girdisi olur. Hazırlık başarısız olursa veya kesintiye uğrarsa
OpenCode istemi kabul etmez.

İstem hook'larını yeniden denemeye karşı güvenli tutun. Bunlar yan etkilerin tam olarak bir kez gerçekleşmesini garanti
eden bir sınır değildir:

- Zaten beklemede olan veya teslim edilmiş bir ID'yi yeniden denemek, hook'ları tekrar çalıştırmadan özgün kabulü
  döndürür.
- Eşzamanlı gönderimler hook'ları birden fazla kez çalıştırabilir, ancak yalnızca ilk başarılı kabul geçerli olur.
- İstem hook'ları girdiyi dönüştürür; türlendirilmiş bir reddetme API'si sunmaz.

#### Model istekleri

Model gönderiminden hemen önce derlenen sistem talimatlarını, mesajları, araçları veya istek seçeneklerini değiştirin.
Oturumun gönderdiği her istek türünün kendi hook'u vardır; böylece bir eklenti ajan döngüsünü ve yardımcı istekleri farklı
şekilde ele alabilir:

- `context`, araç kaynaklı devam adımları dahil ajan döngüsü için çalışır.
- `compaction`, kontrol noktası özetleri için çalışır. `messages` özetlenen konuşma dökümüdür; OpenCode, hook'lar
  çalıştıktan sonra kendi özet istemini ekler. Sıkıştırmayı kendiniz kaydedip model çağrısını atlamak için `result`
  ayarlayın; tamamlanmış bir sıkıştırma mesajıyla aynı alanları alır.
- `generate`, geçici `ctx.session.generate` çağrıları için çalışır.
- `title`, başlık üretimi için çalışır. `agent` veya `tools` içermez. Başlığı kendiniz sağlamak için `result` ayarlayın.

```ts
await ctx.session.hook("context", (event) => {
  event.system.push({ type: "text", text: "Keep the review focused on correctness." })
  delete event.tools.write
  event.options.temperature = 0.2
  event.options.maxTokens = 8_000
})

await ctx.session.hook("compaction", async (event) => {
  event.result = { summary: await summarize(event.messages) }
})
```

Değişiklikler kalıcı geçmişi veya yapılandırmayı değil, yalnızca giden model çağrısını etkiler. Her isteğe uygulanması
gereken bir hook, her tür için ayrı ayrı kaydedilmelidir.

İstek geçersiz kılmaları şu kurallara uyar:

- `options` her model çağrısında boş başlar; çözümlenmiş model ayarlarını içermez.
- Türü tanımlı anahtarlar üretim ayarlarıdır; diğer tüm anahtarlar seçili protokole sağlayıcı seçeneği olarak geçirilir.
- Hook'lar kayıt sırasıyla çalışır ve önceki hook'ların yaptığı geçersiz kılmaları görür.
- İstek geçersiz kılmaları model varsayılanlarından, model varsayılanları da rota varsayılanlarından önceliklidir.
- Sağlayıcı seçeneği nesneleri özyinelemeli olarak birleştirilir; diziler ve skaler değerler önceki değerlerin yerini
  alır.
- Bir geçersiz kılmayı silmek veya `undefined` yapmak, yapılandırılmış varsayılanları kaldırmaz; bunlara geri döner.
- Ham HTTP gövdesi katmanları, protokol dönüşümünden sonra uygulanır ve ortaya çıkan alanları geçersiz kılabilir.

#### Sağlayıcı seçenekleri

Sağlayıcı seçenekleri ham HTTP gövdesi alanlarını değil, seçili protokolün anlamsal seçenek adlarını kullanır.
Sağlayıcıya özgü ayarları eşleşen sağlayıcıyla sınırlayın. Örneğin OpenAI Responses `reasoningEffort` kullanır:

```ts
await ctx.session.hook(
  "context",
  (event) => {
    event.options.reasoningEffort = "high"
  },
  { providerID: "openai" },
)
```

Üretim seçenekleri seçili protokole ve modele bağlıdır:

- `maxTokens`, anlamsal çıktı token'ı sınırıdır.
- Gemini `topK` destekler; OpenAI Responses bu seçeneği sunmaz.

#### Model isteği

Model isteği ayarlarını değiştirin ve isteğe bağlı olarak hook'u tek bir sağlayıcıyla sınırlayın. Olay, aşağıdaki HTTP
hook'larıyla aynı `kind` değerini taşır.

```ts
await ctx.session.hook(
  "model.request",
  (event) => {
    event.headers["x-plugin"] = "review"
  },
  { providerID: "anthropic" },
)
```

#### Yerel HTTP

Yerel sağlayıcı isteklerini veya yanıtlarını değiştirin. Gövdeleri yalnızca bir kez okunabilen akışlardır; bir gövdeyi
okumadan önce klonlayın veya değiştirin.

İki hook da oturumun gönderdiği her istek için çalışır. `event.kind`, isteği hangi akışın gönderdiğini belirtir: ajan
döngüsü için `"primary"`, kontrol noktası özetleri için `"compaction"`, başlık üretimi için `"title"` ve geçici
`ctx.session.generate` çağrıları için `"generate"`. Yardımcı istekleri birbirinden ayırt etmek için ajan ID'si yerine bunu
kullanın.

```ts
await ctx.session.hook("http.request", (event) => {
  event.request.headers.set("x-session-id", event.sessionID)
  if (event.kind === "title") event.request.headers.set("x-priority", "background")
})

await ctx.session.hook("http.response", (event) => {
  event.response = new Response(event.response.body, {
    status: event.response.status,
    headers: { ...Object.fromEntries(event.response.headers), "x-plugin": "review" },
  })
})
```

#### Yerel WebSocket (deneysel)

WebSocket üzerinden akış yapan sağlayıcılar oturum başına bir bağlantı açar ve bunu istekler arasında yeniden kullanır;
bu nedenle `http.request` ve `http.response` bu trafiği hiçbir zaman görmez. `experimental.ws.handshake` hook'u, her model
çağrısında bağlantı seçilmeden önce bir kez çalışır. HTTP hook'larıyla aynı `sessionID`, `agent`, `model` ve `kind`
değerlerini, ayrıca bağlantının `url` ve `headers` değerlerini taşır. `url` veya `headers` değiştirildiğinde isteğin
kullandığı soket de değişir; bu nedenle yenilenen bir bearer token bağlantıyı yeniden açar.

HTTP hook'ları, bir WebSocket rotasının geri döndüğü istek dahil her HTTP isteği için çalışmaya devam eder.

```ts
await ctx.session.hook(
  "experimental.ws.handshake",
  async (event) => {
    event.headers.authorization = `Bearer ${await mintToken(event.url)}`
    delete event.headers["api-key"]
  },
  { providerID: "azure" },
)
```

`experimental.ws.send` ve `experimental.ws.receive`, çerçevelerin kendisini sunar; bu, bir HTTP isteği veya yanıt
gövdesini düzenlemenin WebSocket karşılığıdır. `send`, sağlayıcı sürücüsü giden bir çerçeve oluşturduktan sonra ve
çerçeve yazılmadan önce çalışır; `receive` ise gelen her çerçevede, sürücü çerçeveyi görmeden önce çalışır. İkisi de
çerçeveyi dize olarak taşır ve hook döndüğünde `frame` içinde ne varsa onu gönderir.

OpenCode yeniden yazılmış çerçeveleri doğrulamaz. Sürücü, durumu sağlayıcının yanıtlarından izler; bu nedenle protokol
anlamını değiştiren bir yeniden yazma, tıpkı yeniden yazılmış bir HTTP gövdesinde olduğu gibi eklentinin
sorumluluğundadır.

```ts
await ctx.session.hook(
  "experimental.ws.send",
  (event) => {
    const body = JSON.parse(event.frame)
    if (body.type === "response.create") body.metadata = { ...body.metadata, session: event.sessionID }
    event.frame = JSON.stringify(body)
  },
  { providerID: "openai" },
)

await ctx.session.hook("experimental.ws.receive", (event) => {
  if (event.frame.includes('"type":"error"')) console.error(event.frame)
})
```

Bu hook'lar deneyseldir; adları veya yapıları değişebilir.

#### Yeniden deneme politikası

Bir sağlayıcı hatası için yeniden deneme kararını geçersiz kılın veya bekleme süresini milisaniye cinsinden değiştirin.
Hook, OpenCode hatayı sınıflandırıp politikasını önerdikten sonra, ancak herhangi bir yeniden deneme zamanlanmadan önce
çalışır. OpenCode'un bir sonraki denemeyi dahili olarak nasıl gerçekleştirdiğini göstermez.

```ts
await ctx.session.hook("retry", (event) => {
  if (event.error.status === 429) {
    event.decision = { retry: true, delay: 10_000 }
    return
  }
  if (event.error.type === "provider.invalid-request" && event.attempt === 2) {
    event.decision = { retry: true, delay: 0 }
    return
  }
  if (event.attempt >= 3) event.decision = { retry: false }
})
```

Yeniden deneme hook'ları, yeniden denenmeyecek bir hatayı yeniden denenebilir hâle getirerek veya önerilen bir yeniden denemeyi
engelleyerek OpenCode'un ilk `decision` değerini değiştirebilir.

Yeniden deneme kararları şu kurallara uyar:

- Birden fazla hook kayıt sırasıyla çalışır; sonraki hook'lar geçerli kararı görür.
- Yerleşik en fazla deneme sayısı kesin bir sınır olarak kalır.
- `attempt`, değerlendirilen fiili denemedir. İlk istek `1` olduğundan ilk yeniden deneme `2` olur.
- `NaN`, sonsuz veya negatif değerler gibi geçersiz bekleme süreleri hesaplanan süreye geri döner.
- Bağlam taşması kurtarma işlemi ayrıdır; çünkü aynı isteği yeniden denemek yerine konuşmayı sıkıştırır.

### İzinler

İzin kararlarını, yapılandırılmış kurallar değerlendirildikten sonra ve bir eylem çalışmadan ya da onay istemi
yayımlanmadan önce gözden geçirin.

```ts
await ctx.permission.hook("evaluate", async (event) => {
  if (event.action === "read") return

  const messages = await ctx.session.context({ sessionID: event.sessionID })
  const review = await ctx.generate.text({
    model: { providerID: "anthropic", id: "claude-sonnet-4-6" },
    prompt: buildSafetyPrompt({ messages, action: event.action, resources: event.resources }),
  })
  const decision = parseDecision(review.text)

  event.effect = decision.effect
  event.message = decision.reason
})
```

İzin hook'ları şu kurallara uyar:

- Hook'lar `allow` ve `ask` kararları için çalışır.
- Açıkça yapılandırılmış bir `deny` kesindir ve hook'u çağırmaz.
- Hook, `effect` değerini `allow`, `ask` veya `deny` olarak değiştirebilir.
- `message`, kullanıcıya yükseltilen izin isteğinde görünür veya reddetme gerekçesi olur.

#### Başvuru

```ts
  readonly resources: readonly string[]
  readonly metadata?: Record<string, unknown>
  readonly source?: { type: "tool"; messageID: string; id: string }
```

## Yayımlama

Paket eklentisi, yerel eklentiyle aynı varsayılan dışa aktarımı kullanır. Minimal bir manifest şöyledir:

```json title="package.json"
{
  "name": "opencode-acme-plugin",
  "version": "1.0.0",
  "type": "module",
  "exports": {
    ".": "./src/index.ts",
    "./rpc": "./src/rpc.ts"
  },
  "dependencies": {
    "@opencode/plugin": "latest"
  }
}
```

`./rpc` dışa aktarımı isteğe bağlıdır. Diğer eklentilerin ve istemcilerin uygulamanızı yüklemeden içe aktarabileceği
paylaşılan bir [RPC sözleşmesi](/build/plugins/rpc) yayımlarken ekleyin.

Hedeflediğiniz OpenCode sürümüyle uyumlu sürümler kullanın ve yalnızca çalışma alanına bağlı bir kopyayı değil, kurulu
paketi test edin. Daha yeni bir API sözleşmesine geçtiğinizde uyumlu bir eklenti güncellemesi yayımlayın.

## V1 desteği

Bir eklenti, aynı paket giriş noktasından hem V1'i hem V2'yi destekleyebilir. V1 `server()` fonksiyonunu ve V2
`setup()` fonksiyonunu içeren tek bir nesneyi varsayılan olarak dışa aktarın:

```ts title="src/index.ts"
import { Plugin } from "@opencode/plugin"

export default {
  ...Plugin.define({
    id: "example",
    async setup(ctx) {
      await ctx.tool.hook("execute.before", () => {
        console.log("A tool is about to run")
      })
    },
  }),
  async server() {
    return {
      "tool.execute.before": async () => {
        console.log("A tool is about to run")
      },
    }
  },
}
```

- V1, `server()` fonksiyonunu çağırır ve döndürülen hook'ları kullanır.
- V2, `server()` fonksiyonunu yok sayarak varsayılan dışa aktarımın `id` değerini ve `setup()` fonksiyonunu (Effect
  eklentileri için `effect()`) okur.
- Her uygulamayı kendi API'sinde tutun; aynı dışa aktarımı paylaşmak V1 hook'larını V2 hook'larına dönüştürmez.
- V2 tanımının `server()` fonksiyonundan ayrı olarak tür denetiminden geçmesi için `Plugin.define(...)` sonucunu dışa
  aktarılan nesneye yayın (spread).

V1 nesne biçimi OpenCode `1.18.29` sürümünde desteklenir. Daha eski V1 sürümleri bunun yerine fonksiyon dışa aktarımı
bekleyebilir; kurulu paketi desteklemeyi planladığınız en eski V1 sürümüyle ve V2 ile test edin.
