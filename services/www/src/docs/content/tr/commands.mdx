Bir istemi `/review` komutuna dönüştürmek için `.opencode/commands/review.md` dosyasını oluşturun:

```md title=".opencode/commands/review.md"
Review $ARGUMENTS for bugs and missing tests.
```

Komutu TUI'den bir hedefle çalıştırın:

```text
/review src/auth.ts
```

OpenCode, `Review src/auth.ts for bugs and missing tests.` metnini kullanıcı istemi olarak gönderir.

## Markdown

Global komutları `~/.config/opencode/commands/` dizinine, proje komutlarını ise `.opencode/commands/` dizinine koyun.

```text
~/.config/opencode/commands/review.md
.opencode/commands/review.md
```

Yalnızca `.md` dosyaları bulunur. İç içe yollar, `/` ayırıcılarıyla komut adlarına dönüşür:

```md title=".opencode/commands/team/review.md"
Review $ARGUMENTS using the team's checklist.
```

İç içe komutu `/team/review src/auth.ts` olarak çalıştırın. Eski tekil `command/` dizinleri de taranır, ancak yeni
dosyalar için `commands/` dizinini kullanın.

Komutun meta veriye ihtiyacı varsa YAML frontmatter ekleyin. Kırpılmış Markdown gövdesi her zaman istem şablonudur.

```md title=".opencode/commands/review.md"
---
description: Review code for correctness
agent: plan
model: anthropic/claude-sonnet-4-5#high
---

Review $ARGUMENTS. Report bugs first.
```

## JSON

Komutları herhangi bir OpenCode JSON veya JSONC [yapılandırma dosyasında](/config) `commands` altında tanımlayın. Her
komut bir `template` gerektirir.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "commands": {
    "review": {
      "description": "Review code for correctness",
      "template": "Review $ARGUMENTS. Report bugs first.",
    },
  },
}
```

## Alanlar

Markdown frontmatter'ı ve JSON girdileri aynı alanları kabul eder; tek fark, Markdown'da `template` değerinin dosya
gövdesinden gelmesidir.

| Alan | Zorunlu | Davranış |
| --- | --- | --- |
| `template` | Yalnızca JSON | İstem şablonu. |
| `description` | Hayır | Komut listelerinde ve keşifte gösterilen metin. |
| `agent` | Hayır | Komut çalıştığında seçilen ajan. |
| `model` | Hayır | `provider/model` veya `provider/model#variant` biçiminde model geçersiz kılma. |
| `subagent` | Hayır | `true` arka planda bir alt oturumda çalıştırır; `false` geçerli oturumu zorunlu kılar. |
| `subtask` | Hayır | `subagent` için kullanımdan kaldırılmış takma ad. |

Örneğin bu JSON komutu, mevcut isteğe bağlı alanların tümünü ayarlar:

```jsonc title="opencode.jsonc"
{
  "commands": {
    "audit": {
      "template": "Audit $ARGUMENTS.",
      "description": "Audit a package",
      "agent": "general",
      "model": "anthropic/claude-sonnet-4-5#high",
      "subagent": true,
    },
  },
}
```

`template` alanını Markdown frontmatter'ına koymayın; bu değeri gövde sağlar.

## Argümanlar

Argüman dizesinin tamamını tam olarak girildiği şekliyle kullanmak için `$ARGUMENTS` yer tutucusunu kullanın.

```md title=".opencode/commands/component.md"
Create a typed React component named $ARGUMENTS.
```

`/component Account Settings` için yer tutucu `Account Settings` olur.

## Konumsal argümanlar

Ayrıştırılmış konumsal argümanlar için `$1`, `$2` ve daha büyük numaraları kullanın. Tek veya çift tırnaklar sözcükleri
gruplar ve kaldırılır.

```md title=".opencode/commands/check.md"
Check $1. Focus on $2.
```

`/check src/auth.ts "error handling"` için `$1` yer tutucusu `src/auth.ts`, `$2` ise `error handling` olur.

En yüksek numaralı yer tutucu kendi argümanını ve ondan sonraki her şeyi alır. Eksik konumlar boş dizeye dönüşür.

```md title=".opencode/commands/compare.md"
Compare $1 with $2.
```

`/compare api stable branch` için OpenCode `Compare api with stable branch.` metnini gönderir.

## Geri dönüş

Bir şablonda `$ARGUMENTS` veya konumsal yer tutucu yoksa OpenCode, boş olmayan argümanları boş bir satırdan sonra
ekler.

```md title=".opencode/commands/explain.md"
Explain this code clearly.
```

`/explain src/cache.ts` için istem şöyle olur:

```text
Explain this code clearly.

src/cache.ts
```

## Shell

Bir shell komutunun çıktısını istem gönderilmeden önce eklemek için komutu `!` işaretinin ardından ters tırnaklar içine
alın.

```md title=".opencode/commands/review-diff.md"
Review this diff:

!`git diff --stat && git diff`
```

OpenCode her bloğu yapılandırılmış shell ile etkin proje konumunda çalıştırır ve birleşik çıktısını ekler. Argüman yer
tutucuları önce genişletilir:

```md title=".opencode/commands/history.md"
Summarize these commits:

!`git log --oneline -$1`
```

`/history 5` için shell `git log --oneline -5` komutunu alır. Güvenilmeyen argümanları shell bloklarının içine
yerleştirmeyin.

<Callout type="warning">
  Shell blokları, OpenCode komutu değerlendirdiğinde ajanın araç izni akışının dışında çalışır. Yalnızca güvendiğiniz
  kaynaklardan gelen komutları kullanın.
</Callout>

## Ekler

Kayıtlı şablonlar `@path` ifadesini genişletmez; bu ifade sıradan istem metni olarak kalır.

```md title=".opencode/commands/readme.md"
Review @README.md.
```

Bir dosya eklemek için komutu çağırırken dosyayı istem giriş alanından ekleyin. OpenCode, genişletilmiş istemi
gönderirken giriş alanından eklenen bu ekleri korur.

## Yürütme

Komutlar, kalıcı bir kullanıcı istemi göndermeden önce argümanları ve shell bloklarını genişletir. Varsayılan olarak
geçerli oturumda çalışırlar.

```md title=".opencode/commands/plan.md"
---
agent: plan
---

Plan $ARGUMENTS.
```

`/plan migration` komutunu çalıştırmak, istemi göndermeden önce geçerli oturumu `plan` ajanına geçirir.

Model seçimi şu kurallara uyar:

1. Komutun `model` değeri diğer tüm modelleri geçersiz kılar.
2. Aksi hâlde, seçilen komut ajanının yapılandırılmış modeli, çağrı anında etkin olan modeli geçersiz kılar.
3. Aksi hâlde, geçerli oturum modeli etkin kalır.

Örneğin bu komut hem ajanını hem de açık bir modeli seçer:

```md title=".opencode/commands/design.md"
---
agent: plan
model: openai/gpt-5#high
---

Design $ARGUMENTS.
```

## Arka plan

Bir komutu arka planda bir alt oturumda çalıştırmak için `subagent: true` ayarlayın.

```md title=".opencode/commands/audit.md"
---
description: Audit changes
agent: general
subagent: true
---

Audit $ARGUMENTS for bugs and missing tests.
```

Üst oturum kullanılabilir kalır ve ajanını ve modelini korur. Alt oturum bittiğinde OpenCode, sonucunu veya hatasını üst
oturuma geri gönderir.

| Değer | Davranış |
| --- | --- |
| `true` | Seçilen ajan `mode: primary` olsa bile her zaman alt oturum kullanır. |
| `false` | Seçilen ajan `mode: subagent` olsa bile her zaman geçerli oturumu kullanır. |
| Belirtilmemiş | Yalnızca seçilen ajan `mode: subagent` olduğunda alt oturum kullanır. |

Alt oturum önce komut modelini, ardından seçilen ajanın modelini, en son da üst oturumun modelini kullanır. Eski
`subtask` alanı kabul edilmeye devam eder; iki alan birlikte varsa `subagent` geçerli olur.

```yaml
subagent: false
subtask: true
```

`subagent` öncelikli olduğu için bu örnek geçerli oturumda çalışır.

## Yükleme

Markdown ve JSON komutları tek bir kayıt defterini paylaşır. Sonraki kaynaklar, aynı adlı önceki komutların yerini alır.

```text
~/.config/opencode/commands/review.md   # Lower priority
.opencode/commands/review.md           # Replaces the global command
```

Proje kaynakları global kaynaklardan, daha yakın proje kaynakları da üst dizinlerdeki kaynaklardan önceliklidir. Özel bir
tanım, önceki bir yerleşik komutun da yerini alabilir. OpenCode komut dosyalarını ve yapılandırma değişikliklerini
otomatik olarak yeniden yükler.

```md title=".opencode/commands/review.md"
Review only the staged changes: !`git diff --cached`
```

Bu dosyayı kaydetmek, OpenCode'u yeniden başlatmadan `/review` komutunu günceller.
