---
title: "Modeller"
---

Geçerli oturum için `/models` komutuyla bir model seçin:

```text
/models
```

OpenCode; [models.dev](https://models.dev), sağlayıcı entegrasyonları ve yapılandırmanızdaki modelleri listeler. Seçici
yalnızca sağlayıcısı geçerli projede kullanılabilen etkin modelleri gösterir. Sağlayıcıları
[Sağlayıcılar](/providers) sayfasından bağlayın.

## Seçme

Sağlayıcı veya model ID'sini tahmin etmek yerine `/models` listesinden bir girdi seçin. Seçim geçerli oturuma uygulanır
ve yapılandırmanızı değiştirmez.

```text
anthropic/claude-sonnet-4-5
```

Kullanılabilirlik projeye özgüdür:

- Model etkin olmalıdır.
- Modelin sağlayıcısı geçerli projede kullanılabilir olmalıdır.
- Başka bir projedeki kimlik bilgileri ve yapılandırma otomatik olarak aktarılmaz.

## Çalıştırmalar

Yapılandırılmış varsayılanı değiştirmeden tek bir komut satırı çalıştırması için model seçmek üzere `--model` bayrağını
kullanın:

```bash
opencode run --model anthropic/claude-sonnet-4-5 "Refactor parseToken"
```

Ajanlar ve komutlar da kendi modellerini seçebilir. [Ajanlar](/agents) ve [Komutlar](/commands) sayfalarına bakın.

## Varsayılanlar

Yeni işler için varsayılanı seçmek üzere `opencode.json` veya `opencode.jsonc` dosyasında `model` anahtarını ayarlayın:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "anthropic/claude-sonnet-4-5",
}
```

Yapılandırılmış model etkinse ve sağlayıcısı kullanılabiliyorsa kataloğun varsayılanı olur. Aksi hâlde OpenCode,
kullanılabilir ve desteklenen en yeni modele geri döner.

- Bir oturum için önceden seçilmiş model, yapılandırılmış varsayılandan önceliklidir.
- Bir oturumun modelini değiştirmek yapılandırma dosyasını yeniden yazmaz.
- Kök düzeydeki `model` şu anda yalnızca varsayılan sağlayıcıyı ve modeli korur, varyantı korumaz.

Yapılandırma konumları ve öncelik sırası için [Yapılandırma](/config) sayfasına bakın.

## Varyantlar

Varyantlar, tek bir model için adlandırılmış seçeneklerdir ve genellikle akıl yürütme düzeyi (reasoning effort) veya
token bütçeleri için kullanılır. Bir çalıştırma, oturum, ajan veya komut için varyant seçerken `#variant` ekleyin:

```bash
opencode run --model openai/gpt-5.2#high "Review this migration plan"
```

Varyant adları, seçilen modelin güncel katalog meta verilerinden gelir. `low`, `high` ve `max` gibi adlar her model için
kullanılamaz; bilinmeyen bir varyant model çözümleme hatasına yol açar.

Modelin `variants` dizisinde yeni varyantlar tanımlayın veya aynı ID'ye sahip katalog varyantlarının yerine kendi
varyantlarınızı koyun:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "models": {
        "gpt-5.2": {
          "settings": {
            "reasoningEffort": "medium",
          },
          "variants": [
            {
              "id": "fast",
              "settings": {
                "reasoningEffort": "low",
              },
            },
            {
              "id": "deep",
              "settings": {
                "reasoningEffort": "high",
                "reasoningSummary": "auto",
              },
            },
          ],
        },
      },
    },
  },
}
```

Her varyant `settings`, `headers` ve `body` içerebilir. Varyant değerleri, sağlayıcı ve model değerlerinden sonra
uygulanır.

## Seçenekler

Sağlayıcı ve model girdileri, istekleri `settings`, `headers` ve `body` ile özelleştirebilir:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "openai": {
      "settings": {
        "baseURL": "https://api.example.com/v1",
      },
      "headers": {
        "X-Team": "platform",
      },
      "models": {
        "gpt-5.2": {
          "settings": {
            "reasoningEffort": "high",
          },
          "body": {
            "store": false,
          },
        },
      },
    },
  },
}
```

| Alan       | Amaç                                                                   |
| ---------- | ---------------------------------------------------------------------- |
| `settings` | `baseURL` veya `reasoningEffort` gibi sağlayıcı paketi seçenekleri.    |
| `headers`  | Ek HTTP istek başlıkları.                                              |
| `body`     | Sağlayıcıya özgü istek gövdesi alanları.                               |

OpenCode önce sağlayıcı değerlerini, ardından model değerlerini, en son da seçilen varyantı uygular.

- İç içe `settings` ve `body` nesneleri birleştirilir.
- Sonraki diziler ve skaler değerler öncekilerin yerini alır.
- Başlık adları büyük/küçük harf duyarsız olarak eşleştirilir.
- Seçenekler sağlayıcıya özgüdür; başka bir sağlayıcı paketi bunları yok sayabilir veya reddedebilir.

## Takma adlar

Bir API modeline daha kullanışlı bir katalog ID'si vermek için `modelID` alanını kullanın:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "openai/coding-default",
  "providers": {
    "openai": {
      "models": {
        "coding-default": {
          "modelID": "gpt-5.2",
          "name": "Coding default",
          "capabilities": {
            "tools": true,
            "input": ["text", "image"],
            "output": ["text"],
          },
          "limit": {
            "context": 200000,
            "output": 32000,
          },
        },
      },
    },
  },
}
```

Burada `openai/coding-default` seçilebilir referanstır, sağlayıcıya ise `gpt-5.2` gönderilir. Katalogda henüz bulunmayan
bir model için OpenCode şunları varsayar:

- Araç desteği, metin ve görsel girdisi, metin çıktısı.
- 200,000 token'lık bağlam sınırı ve 32,000 token'lık çıktı sınırı.
- Belirtilmemiş bir girdi sınırı.

Bunlar algılanmış yetenekler değil, yedek varsayımlardır. Biliniyorsa doğru `capabilities` ve `limit` değerlerini
ayarlayın; açıkça belirtilen değerler yedek değerlerin yerini alır. Bir modeli kullanılabilir katalogdan gizlemek için
`disabled: true` ekleyin:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "openai": {
      "models": {
        "legacy-model": {
          "disabled": true,
        },
      },
    },
  },
}
```

## Akıl yürütme

Akıl yürütme çıktısını özel bir asistan mesajı alanında akış olarak gönderen OpenAI uyumlu bir model için
`compatibility.reasoningField` ayarını yapın:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "local": {
      "models": {
        "reasoner": {
          "compatibility": {
            "reasoningField": "reasoning_content",
          },
        },
      },
    },
  },
}
```

OpenCode, `reasoning`, `reasoning_content` ve `reasoning_text` alanlarını tanır; sağlayıcıya özgü başka bir dizeyi de
kabul eder. Akış hâlinde gelen akıl yürütmeyi bu alandan okur ve önceki asistan mesajlarını modele geri gönderirken bu
alanı geri yükler.

## İstem önbelleği

OpenCode, Anthropic gibi önbellek kesme noktalarına ihtiyaç duyduğu bilinen yollarda istem önbelleği kesme noktalarını
otomatik olarak yerleştirir. Claude modelleri LiteLLM gibi OpenAI uyumlu bir proxy üzerinden sunulduğunda OpenCode, bu
modellerin Anthropic tarzı `cache_control` kesme noktalarına ihtiyaç duyduğunu anlayamaz. Bu Claude modellerinde
`compatibility.cacheFormat` ayarını yapın:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "litellm": {
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": { "baseURL": "https://litellm.example.com/v1" },
      "models": {
        "claude-sonnet-5": {
          "compatibility": { "cacheFormat": "anthropic" },
        },
        "claude-opus-5-5": {
          "compatibility": { "cacheFormat": "anthropic" },
        },
        // Other models on the same proxy cache automatically and need no setting.
        "gpt-6.1": {},
      },
    },
  },
}
```

Bu durumda OpenCode son araç tanımını, sistem istemini ve en son mesajı `cache_control: { "type": "ephemeral" }` ile
işaretler; bu, uç noktanın varsayılan beş dakikalık önbellek ömrünü kullanır. Aynı işaretleri kabul eden ancak araç
tanımlarında yok sayan Alibaba Model Studio modelleri için `"alibaba"` değerini kullanın. Sağlayıcının sunduğu tüm
modeller aynı biçimi kabul ediyorsa `compatibility.cacheFormat` ayarını bunun yerine sağlayıcı üzerinde yapın.

## Yerel

OpenCode, Ollama, LM Studio ve vLLM modellerini varsayılan yerel adreslerinde otomatik olarak bulur. Herhangi bir OpenAI
uyumlu sunucuyu elle de yapılandırabilirsiniz.

```text
ollama/gemma3:4b
lmstudio/google/gemma-4-26b-a4b
vllm/Qwen/Qwen3-Coder-30B-A3B-Instruct
```

### Ollama

Ollama `http://127.0.0.1:11434` adresinde dinliyorsa bulunan bir modeli `ollama` sağlayıcı ID'siyle seçin:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "ollama/gemma3:4b",
}
```

OpenCode model listesini arka planda yeniler ve bağlam, görüntü işleme ve araç kullanımı yeteneklerini Ollama'dan okur.
Yalnızca embedding üreten modeller hariç tutulur.

Farklı bir ana bilgisayar veya bağlantı noktası için Ollama'nın OpenAI uyumlu URL'sini ayarlayın. Model bulma yine aynı
yol önekindeki yerel Ollama API'sini kullanır:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "ollama": {
      "settings": {
        "baseURL": "http://127.0.0.1:5678/v1",
        "apiKey": "{env:OLLAMA_API_KEY}",
      },
    },
  },
}
```

- Uç nokta bearer kimlik doğrulaması gerektirmiyorsa `apiKey` alanını kaldırın.
- Model bulmayı `"plugins": ["-opencode.provider.ollama"]` ile devre dışı bırakın.

### LMStudio

Kimlik doğrulaması olmayan bir LM Studio sunucusu `http://127.0.0.1:1234` adresindeyse bulunan bir modeli `lmstudio`
sağlayıcı ID'siyle seçin:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "lmstudio/google/gemma-4-26b-a4b",
}
```

OpenCode model listesini arka planda yeniler ve bağlam, görüntü işleme ve araç kullanımı yeteneklerini LM Studio'dan
okur. Embedding modelleri hariç tutulur.

Farklı bir ana bilgisayar veya bağlantı noktası için OpenAI uyumlu URL'yi ayarlayın. Modeller yine otomatik olarak
bulunur:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "lmstudio": {
      "settings": {
        "baseURL": "http://127.0.0.1:5678/v1",
        "apiKey": "{env:LMSTUDIO_API_KEY}",
      },
    },
  },
}
```

- LM Studio kimlik doğrulaması devre dışıysa `apiKey` alanını kaldırın.
- Model bulmayı `"plugins": ["-opencode.provider.lmstudio"]` ile devre dışı bırakın.

### vLLM

vLLM `http://127.0.0.1:8000` adresinde dinliyorsa bulunan bir modeli `vllm` sağlayıcı ID'siyle seçin:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "vllm/Qwen/Qwen3-Coder-30B-A3B-Instruct",
}
```

OpenCode `/health` uç noktasını denetler, `/v1/models` listesini arka planda yeniler, bildirilen `max_model_len` değerini
bağlam sınırı olarak kullanır ve yalnızca sahibi `vllm` olan model kartlarını dahil eder.

Bulunan modeller metin girdisi ve çıktısı bildirir, ancak görüntü işleme veya araç desteği bildirmez. vLLM, araç
çağrısını `--enable-auto-tool-choice` ve `--tool-call-parser` gibi sunucu bayraklarıyla etkinleştirir; model bulma bu
bayrakları bildirmez.

Farklı bir uç nokta veya kimlik doğrulaması gerektiren bir sunucu için OpenAI uyumlu URL'sini ayarlayın:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "vllm": {
      "settings": {
        "baseURL": "http://127.0.0.1:9000/v1",
        "apiKey": "{env:VLLM_API_KEY}",
      },
    },
  },
}
```

- Kimlik doğrulaması devre dışıysa `apiKey` alanını kaldırın.
- Model bulmayı `"plugins": ["-opencode.provider.vllm"]` ile devre dışı bırakın.
- Yol önekli proxy'ler desteklenir. Örneğin `https://example.com/vllm/v1` için `/vllm/health` denetlenir ve modeller
  `/vllm/v1/models` adresinden bulunur.

### Uyumlu sunucular

Başka bir OpenAI uyumlu sunucu için sağlayıcı paketini, uç noktasını ve en az bir modeli tanımlayın:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "local/coder",
  "providers": {
    "local": {
      "name": "Local server",
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "http://127.0.0.1:1234/v1",
      },
      "models": {
        "coder": {
          "modelID": "model-name-on-server",
          "capabilities": {
            "tools": true,
            "input": ["text"],
            "output": ["text"],
          },
          "limit": {
            "context": 32768,
            "output": 8192,
          },
        },
      },
    },
  },
}
```

Sunucunun gerçek model adını, sınırlarını, girdi ve çıktı türlerini ve araç desteğini kullanın. OpenCode, özel model
için kullanılan yedek değerlerin doğru olup olmadığını algılayamaz. Uç nokta bir anahtar gerektiriyorsa `settings`
nesnesine `"apiKey": "{env:LOCAL_API_KEY}"` gibi bir ortam değişkeni ikamesiyle `apiKey` ekleyin; gizli bilgileri
depoya commit etmeyin.

## Referanslar

Model seçicileri, isteğe bağlı bir `#variant` ile birlikte `provider/model` biçimini kullanır:

```text
openai/gpt-5.2
openai/gpt-5.2#high
openrouter/anthropic/claude-sonnet-4.5#high
```

| Bölüm       | Kural                                                          |
| ----------- | -------------------------------------------------------------- |
| Sağlayıcı   | İlk `/` karakterinde biter; `/` veya `#` içeremez.             |
| Model       | Ek `/` karakterleri içerebilir; `#` içeremez.                  |
| Varyant     | Varsa `#` karakterinden sonra gelir.                           |
| Harf durumu | Sağlayıcı ve model ID'leri büyük/küçük harfe duyarlıdır.       |

Sağlayıcıların görünen adları yerine katalog ID'lerini kullanın. Kök, ajan ve komut `model` alanları yukarıdaki dize
biçimini veya genişletilmiş bir nesneyi kabul eder:

```jsonc
{
  "model": {
    "providerID": "openrouter",
    "model": "anthropic/claude-sonnet-4.5",
  },
}
```

Genişletilmiş biçim, otomatik oluşturulan veya programatik yapılandırmalar için kullanışlıdır.

## Dikkat edilecekler

Modelleri yapılandırırken şu kuralları göz önünde bulundurun:

```jsonc
{
  "model": "openai/gpt-5.2"
}
```

- Seçici nesnesi `model` alanını kullanır; sağlayıcı katalog girdisi ise sağlayıcıya gönderilen ID için `modelID`
  alanını kullanır.
- Kök düzeydeki seçim biçimi bir varyantı kabul etse de V2 katalog varsayılanı bu varyantı korumaz. Bunun yerine
  varyantları bir oturum, çalıştırma, ajan veya komut için seçin.
- Model seçenekleri sağlayıcıya özgüdür. Başka bir sağlayıcı paketi bunları yok sayabilir veya reddedebilir.
- Katalog verileri, kimlik bilgileri ve yapılandırma konuma özgüdür. Bir projede kullanılabilen bir model başka bir
  projede kullanılamayabilir.
- Yapılandırma dosyaları normalde otomatik olarak yeniden yüklenir. Devam eden bir model isteği, başladığı ayarları
  korur.
