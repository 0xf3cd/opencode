title: "主題"
---

OpenCode 內建許多適用於淺色和深色模式的主題。你可以在偏好設定中選擇主題，也可以自行搭配顏色。

## 選擇主題

按下 `Ctrl+P`，選擇 **Open settings**，然後開啟 **Theme**。預設主題是 `opencode`。

你也可以在全域的 [CLI 偏好設定](/cli/config)中設定主題：

```json title="~/.config/opencode/cli.json"
{
  "$schema": "https://opencode.ai/v2/cli.json",
  "theme": {
    "name": "tokyonight",
    "mode": "dark"
  }
}
```

執行 `/themes` 可以直接切換主題，不必開啟偏好設定。

## 系統色彩

當 OpenCode 能讀取你的終端機調色盤時，主題選擇器會包含 `system` 主題。這個主題會依據終端機的前景色、背景色和 ANSI 調色盤產生顏色。

主題名稱 `system` 代表使用從終端機取得的顏色；模式 `system` 則代表跟隨終端機的淺色或深色外觀。

## 模式

使用 `system` 跟隨終端機的外觀，或將主題固定為淺色或深色模式：

| 模式 | 行為 |
| --- | --- |
| `system` | 跟隨偵測到的終端機淺色或深色外觀。 |
| `dark` | 一律使用主題的深色配色。 |
| `light` | 一律使用主題的淺色配色。 |

這對應到 CLI 設定中 `theme` 底下的 `mode` 欄位。如果自訂主題只提供一種模式，在要求另一種模式時，OpenCode 會改用主題提供的那一種。

## 新增主題

若要新增下載的主題或他人分享的主題，請將它的 JSON 檔案複製到全域主題目錄：

```bash
cp theme.json ~/.config/opencode/themes/
```

你也可以將主題放在專案的 `.opencode/themes` 目錄中，讓它只在該專案中可用。

檔案名稱會成為主題名稱。例如，`my-theme.json` 會顯示為 `my-theme`。新增檔案後請重新啟動 OpenCode，再執行 `/themes` 選擇該主題。

OpenCode 只會讀取 `.json` 檔案。離目前目錄越近的主題，會取代全域或上層目錄中同名的主題。

## 在外掛中使用主題

[CLI 外掛](/build/plugins/cli)可以透過 `context.theme` 讀取解析後的顏色，並透過 `context.themeMode` 讀取目前的模式。請使用語意 token，讓外掛跟隨使用者選擇的主題：

```tsx title="Inside a CLI plugin component"
import { usePlugin } from "@opencode/plugin/tui"

function Status() {
  const context = usePlugin()
  return <text fg={context.theme.text.base}>Ready</text>
}
```

公開的 CLI 外掛 API 不提供主題註冊功能。請使用上述目錄中的 JSON 檔案加入自訂主題定義。

## 建立主題

使用我們的[主題工具](https://opencode.ai/theme/)建立或編輯主題。這個工具能幫助你輕鬆理解主題的結構、進行修改，並定義自訂顏色。以下說明僅供參考。

主題將共用的語意 token 與各模式專屬的調色盤分開：

| 區段 | 用途 |
| --- | --- |
| `base` | 所有模式共用的完整 token 樹。 |
| `light`、`dark` | 該模式的完整色相調色盤，以及選用的 token 覆寫。 |

每個主題都必須提供完整的 `base`，並至少定義 `light` 或 `dark` 其中之一。各模式繼承自該檔案的 `base`；不會繼承內建的 OpenCode 主題，模式之間也不會互相繼承。

以下範例只列出與各個概念相關的區段。請先使用主題編輯器產生完整的檔案，再進行自訂。

### 結構

將兩種模式都會用到的顏色放在 `base` 中，需要時再於 `light` 或 `dark` 中覆寫：

```json title="theme.json (excerpt)"
{
  "$schema": "https://opencode.ai/theme.json",
  "base": {
    "text": {
      "base": "$hue.neutral.200",
      "muted": "$hue.neutral.400"
    }
  },
  "light": {
    "hue": {}
  },
  "dark": {
    "hue": {},
    "text": {
      "muted": "$hue.neutral.300"
    }
  }
}
```

完整的 `base` 提供所有語意 token。每個模式都要提供所有必要的色相，並可覆寫 base token 樹的任何部分。

### 顏色與參照

顏色可以是十六進位色碼、`"transparent"`，或對其他主題顏色的參照：

```json title="Inside base or a mode"
{
  "text": {
    "base": "#eeeeee",
    "muted": "$hue.neutral.400"
  },
  "border": {
    "base": "$text.muted"
  }
}
```

### 色相

色相是九階的色彩刻度。每個模式都要定義八個基本色相和三個別名：

| 類型 | 值 |
| --- | --- |
| 基本 | `gray`, `red`, `orange`, `yellow`, `green`, `cyan`, `blue`, `purple` |
| 別名 | `accent`, `interactive`, `neutral` |
| 階 | `100`, `200`, `300`, `400`, `500`, `600`, `700`, `800`, `900` |

為基本色相定義全部九個階，或將某個色相設為另一個色相的別名：

```json title="Inside light or dark"
{
  "hue": {
    "purple": {
      "100": "#b38ff4",
      "200": "#9d7cd8",
      "300": "#8869bd",
      "400": "#7357a2",
      "500": "#5f4688",
      "600": "#4b356f",
      "700": "#392557",
      "800": "#271640",
      "900": "#17072b"
    },
    "accent": "$hue.purple"
  }
}
```

色相的階數依照模式的對比方向排列。淺色主題從 `100` 的深色排到 `900` 的淺色；深色主題則從 `100` 的淺色排到 `900` 的深色。

`base` 中的 `categorical` 陣列會設定一組有順序的色相，用來區分代理和其他重複出現的項目：

```json title="Inside base"
{
  "categorical": ["accent", "purple", "green", "blue"]
}
```

### 語意 token

語意 token 會將顏色指派給 UI 角色。元件使用這些角色，而不是直接選擇顏色。

| 群組 | 用途 |
| --- | --- |
| `text` | 基本、次要、動作、表單欄位、狀態和回饋文字。 |
| `background` | 基本、浮起表面、動作、表單欄位和回饋填色。 |
| `border`、`scrollbar` | 邊框和捲軸顏色。 |
| `diff` | 新增、移除、上下文、醒目提示和行號的顏色。 |
| `syntax` | 原始碼語法醒目提示。 |
| `markdown` | Markdown 元素。 |

例如，`text.muted` 控制次要文字，`background.raised` 則定義逐層浮起的表面：

```json title="Inside base"
{
  "text": {
    "base": "$hue.neutral.200",
    "muted": "$hue.neutral.400"
  },
  "background": {
    "base": "$hue.neutral.800",
    "raised": {
      "base": "$hue.neutral.700",
      "high": "$hue.neutral.600",
      "max": "$hue.neutral.500"
    }
  }
}
```

語法鍵包括 `comment`、`keyword`、`function`、`variable`、`string`、`number`、`type`、`operator` 和 `punctuation`。

Markdown 鍵包括 `text`、`heading`、`link`、`linkText`、`code`、`blockQuote`、`emphasis`、`strong`、`horizontalRule`、`listItem`、`listEnumeration`、`image`、`imageText` 和 `codeBlock`。

### 動作與狀態

動作有 `primary`、`secondary` 和 `destructive` 三種變體。動作和表單欄位使用 `base`，並可加上選用的互動狀態：

```json title="Inside base or a mode"
{
  "text": {
    "action": {
      "primary": {
        "base": "$hue.interactive.400",
        "$hovered": "$hue.interactive.300",
        "$disabled": "$hue.neutral.600"
      }
    }
  }
}
```

狀態鍵包括 `$hovered`、`$focused`、`$pressed`、`$selected` 和 `$disabled`。未指定的狀態會使用該動作或表單欄位的 `base` 顏色。

### 對話方塊表面

面板、對話方塊、選單和快顯通知會從 `background.raised` 選擇各自的層級。對話方塊還可以透過 `@dialog` 覆寫語意 token：

```json title="Inside base or a mode"
{
  "@dialog": {
    "background": {
      "base": "$background.raised.base",
      "action": {
        "primary": {
          "$hovered": "$background.raised.high"
        }
      }
    }
  }
}
```

TUI 在套用 `@dialog` 之後會重新解析參照，因此參照 `$background.base` 的 token 會跟著使用對話方塊的背景。情境動作的 `base` 會成為其未指定狀態的備援值；明確指定的狀態覆寫仍然優先。
