設定標準的代理伺服器環境變數，並排除回送位址。OpenCode 的 CLI 與背景服務之間使用本機 HTTP 連線，因此只要在 CLI 環境中設定了代理伺服器，就必須排除回送位址。

```bash
export HTTP_PROXY=http://proxy.example.com:8080
export HTTPS_PROXY=http://proxy.example.com:8080
export NO_PROXY=localhost,127.0.0.1,::1

opencode
```

`HTTP_PROXY` 處理 HTTP 目的地，`HTTPS_PROXY` 處理 HTTPS 目的地。兩個變數中的代理伺服器 URL 本身都可以使用 `http://`。`NO_PROXY` 是以逗號分隔的主機與位址清單，清單中的目標會直接連線。

## 背景服務

只有當背景服務是從 shell 啟動時，shell 中匯出的變數才會影響該服務。請將這些變數保存到受管理服務的設定中，讓之後每次啟動服務時都套用相同的網路設定。

```bash
opencode service set env HTTP_PROXY http://proxy.example.com:8080
opencode service set env HTTPS_PROXY http://proxy.example.com:8080
opencode service set env NO_PROXY localhost,127.0.0.1,::1
opencode service start
```

變更受管理的環境變數會停止正在執行的服務，`service start` 會以新的環境重新啟動它。如果 CLI 所在的 shell 也設定了代理伺服器，請在該 shell 中同樣保留 `NO_PROXY`，因為受管理的服務變數只套用於伺服器處理程序，不會套用於 CLI 處理程序。

使用 `service unset env` 移除已保存的變數：

```bash
opencode service unset env HTTPS_PROXY
```

## 身分驗證

如果代理伺服器接受 URL 中的認證資訊，請在每個需要驗證的代理伺服器 URL 中加入使用者名稱和密碼。使用者名稱或密碼中的 `@`、`:`、`/` 等字元必須經過百分比編碼。

```bash
export HTTPS_PROXY='http://user:p%40ssword@proxy.example.com:8080'
```

背景服務則需要保存完整的 URL。這個值會儲存在私有的服務設定中，且會顯示在 `opencode service get env` 的輸出裡，因此請勿分享該輸出。

```bash
opencode service set env HTTPS_PROXY 'http://user:p%40ssword@proxy.example.com:8080'
```

## 憑證

如果代理伺服器或目的地使用由私有憑證授權單位簽發的憑證，請將 `NODE_EXTRA_CA_CERTS` 設為 PEM 檔案的路徑。處理程序啟動時，這些額外的憑證授權單位會加入執行環境的信任存放區。

```bash
export NODE_EXTRA_CA_CERTS=/etc/company/ca.pem
opencode --standalone
```

為背景服務保存這個檔案路徑，然後重新啟動服務：

```bash
opencode service set env NODE_EXTRA_CA_CERTS /etc/company/ca.pem
opencode service start
```

## 前景處理程序

`--standalone` 和 `serve` 會使用各自處理程序的環境，`opencode service set env` 不會設定這些處理程序。

```bash
HTTP_PROXY=http://proxy.example.com:8080 \
HTTPS_PROXY=http://proxy.example.com:8080 \
NO_PROXY=localhost,127.0.0.1,::1 \
opencode --standalone
```

前景伺服器也套用相同的做法：

```bash
HTTPS_PROXY=http://proxy.example.com:8080 \
NO_PROXY=localhost,127.0.0.1,::1 \
opencode serve
```

## 驗證

套用設定後，檢查 CLI 是否能連線到背景服務：

```bash
opencode api get /api/info
```

收到成功的健康檢查回應，即表示本機用戶端與服務之間的連線正常。若要驗證服務對外連線時使用的代理伺服器和憑證路徑，請發出一次一般的供應商請求。
