OpenCode Go 讓你穩定存取熱門的開放式程式設計模型，提供兩種月費方案：

| 方案 | 價格 | 內含用量 |
| ----------- | ------------- | ------------------------------------------- |
| **Go** | **每月 $10** | 以較低成本使用下列模型 |
| **Go Plus** | **每月 $40** | 下列模型皆享有較高的用量上限 |

Go 在 OpenCode 中的運作方式和其他供應商一樣。訂閱 OpenCode Go 後即可取得 API 金鑰。它**完全是選用的**，不訂閱也能使用 OpenCode。

這項服務主要為國際使用者設計，提供穩定的全球存取。

## 運作方式

1. 登入 [OpenCode Console](https://opencode.ai/console)，訂閱 Go 或 Go Plus，加入帳單資訊，然後複製你的 API 金鑰。
2. 在 TUI 中執行 `/connect`，選擇 **OpenCode Go**，然後貼上你的 API 金鑰。

   ```text
   /connect
   ```

3. 執行 `/models`，選擇一個可透過 Go 使用的模型。

   ```text
   /models
   ```

<Callout>
  Go 和 Go Plus 適用於只有一位成員的工作區，例如註冊時建立的 **Personal** 工作區。已訂閱 Go 的工作區無法邀請成員。
</Callout>

## 可以在哪裡使用？

OpenCode Go 是為 [OpenCode](https://opencode.ai) 以及會產生類似請求的其他程式設計代理而設計。我們會監控流量，防止濫用行為影響其他使用者的體驗。

你的用戶端應該：

1. 傳送典型的程式設計代理流量。
2. 使用自己的 user agent 識別身分，例如 `my-coding-agent/1.0`，而不是通用的 SDK 或 HTTP 函式庫名稱。
3. 為每段對話在 `x-opencode-session` 中傳送固定的工作階段 ID，讓我們能夠最佳化路由和提示詞快取。

### 已驗證的用戶端

除了 OpenCode 之外，下列用戶端也已驗證可以正常搭配 OpenCode Go 使用，但我們不保證它們日後仍能持續正常運作。

| 用戶端 | 工作階段支援 |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Hermes** | 包含 [PR #101864](https://github.com/NousResearch/hermes-agent/pull/101864) 的版本，會在主要與輔助 OpenCode 請求中傳送此標頭。這項修正是在 v0.21.0 之後才合併，因此單獨使用該版本並不包含此修正。 |
| **Claude Code** | Go 可以辨識它原生的工作階段標頭，不需要另外包裝自訂標頭。 |
| **Codex** | Go 可以辨識它原生的工作階段標頭。部分版本和代理伺服器設定仍會省略此標頭；轉送請求時請保留工作階段標頭。 |
| **ZCode** | Go 可以辨識它原生的工作階段標頭。我們[請求支援 `x-opencode-session`](https://github.com/zai-org/feedback/issues/492) 的議題仍未關閉，但已經不需要傳送這個特定標頭。 |
| **Pi** | 目前的版本會為 OpenCode 傳送工作階段資訊。請更新較舊的安裝版本。 |
| **jcode** | 請更新至 **v0.81.6 或更新版本**，其中包含[工作階段標頭修正](https://github.com/1jehuang/jcode/issues/1167)。 |
| **Kilo Code CLI** | 包含 [PR #13752](https://github.com/Kilo-Org/kilocode/pull/13752) 的版本會恢復 OpenCode 工作階段標頭。這項修正適用於 CLI，不適用於 VS Code 擴充功能。請參閱 [issue #13723](https://github.com/Kilo-Org/kilocode/issues/13723)。 |

### 已知有問題的用戶端

在我們調查的版本中，這些用戶端缺少工作階段支援或支援不完整。連結中的回報會追蹤修正和因應方式。

| 用戶端 | 狀態與追蹤 |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **DeepSeek Harness** | 部分模型路徑會傳送工作階段資訊，其他路徑則沒有。我們可以辨識它原生的標頭，剩下的工作是讓所有轉接器都傳送此標頭。[Discussion #5495](https://github.com/deepseek-ai/deepseek-harness/discussions/5495)。 |
| **GitHub Copilot Chat** | 已在 [VS Code issue #334186](https://github.com/microsoft/vscode/issues/334186) 中請求自動支援工作階段標頭。 |
| **Kimi Code** | 已在 [issue #3506](https://github.com/MoonshotAI/kimi-code/issues/3506) 中請求自動支援工作階段標頭。 |
| **MiMo Code** | [Issue #2317](https://github.com/XiaomiMiMo/MiMo-Code/issues/2317) 已在 [PR #2327](https://github.com/XiaomiMiMo/MiMo-Code/pull/2327) 中提出修正，但尚未合併。 |

### 超出上限後的用量

如果你的 Console 餘額中也有額度，可以在 Console 中啟用 **Use balance** 選項。啟用後，達到用量上限時，Go 會改用你的[按用量計費餘額](/console/models#pricing)，而不是封鎖請求。

### 為什麼有些模型的用量較低

使用 Go 時，每月內含的用量會因模型而異。

大多數模型能做到這一點，是因為我們取得了大量採購折扣並預留了 GPU 容量，再把省下的費用以更高的每月用量回饋給你。

有些模型因為才剛推出，或公開價格本身已經有折扣，我們還沒有機會議定折扣，也無法以更低的成本託管。

對於這些模型，你得到的用量仍比直接向模型供應商付費略多一些，這也是它們每月內含用量較低的原因。

## 背景

開放式模型已經變得非常強大，在程式設計任務上的表現已接近專有模型。而且由於許多供應商都能以具競爭力的價格提供服務，它們通常便宜得多。

然而，要穩定且低延遲地存取這些模型並不容易。各家供應商的品質和可用性參差不齊。

<Callout type="tip">我們測試了一批與 OpenCode 搭配良好的精選模型和供應商。</Callout>

為了解決這個問題，我們做了幾件事：

1. 測試了一批精選的開放式模型，並與各模型團隊討論如何以最佳方式執行。
2. 與幾家供應商合作，確保這些模型以正確的方式提供服務。
3. 對模型與供應商的組合進行基準測試，整理出一份我們有信心推薦的清單。

Go 和 Go Plus 都能存取這些模型，請依照你的使用量選擇適合的方案。

## 目標

我們打造 OpenCode Go 的目的是：

1. 透過低價訂閱，讓更多人**負擔得起** AI 程式設計。
2. 提供**穩定**的存取，讓你使用最好的開放式程式設計模型。
3. 精選經過**測試與基準測試**、適合程式設計代理使用的模型。
4. **沒有綁定**，你也可以在 OpenCode 中使用其他任何供應商。
