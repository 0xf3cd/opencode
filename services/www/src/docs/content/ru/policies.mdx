Политики определяют, может ли OpenCode выполнить действие над именованным ресурсом. Они задаются в `policies`, а также
могут поступать из подключенного рабочего пространства [OpenCode Console](/console).

Политики отделены от [разрешений](/permissions). Разрешения — это правила для инструментов на уровне агента, которые
могут давать `allow`, `deny` или `ask`. Политики бинарны, никогда не вызывают запросов и могут только ужесточать то, что
иначе разрешили бы разрешения и провайдеры.

## Настройка

Чтобы запретить провайдера везде, добавьте правило в `opencode.jsonc`:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "policies": [{ "action": "provider.use", "resource": "openai", "effect": "deny" }],
}
```

Запрещенный провайдер исчезает из каталога и выбора моделей, даже если у него есть действительные учетные данные.

Более ранние версии читали политики из `experimental.policies`. Этот ключ по-прежнему работает и объединяется с
`policies`:

```jsonc
{
  "experimental": {
    "policies": [{ "action": "provider.use", "resource": "openai", "effect": "deny" }],
  },
}
```

## Правила

Каждое правило политики содержит три поля:

| Поле       | Значения                                      | Смысл                                                 |
| ---------- | --------------------------------------------- | ----------------------------------------------------- |
| `action`   | `provider.use`, `tool.use`, `integration.use` | Контролируемая операция                               |
| `resource` | строка или шаблон с подстановочными знаками   | К чему применяется правило; зависит от действия       |
| `effect`   | `allow`, `deny`                               | Решение, если правило совпало                         |

Правила, не прошедшие валидацию, отбрасываются с предупреждением в журнале сервера, а остальная часть списка
продолжает действовать. После редактирования `deny` проверьте журнал.

## Сопоставление

Ресурсы сопоставляются с теми же шаблонами для всего значения целиком, что и в разрешениях: `*` совпадает с нулем или
более символов, а `?` — ровно с одним.

```jsonc
{
  "policies": [{ "action": "provider.use", "resource": "company-*", "effect": "deny" }],
}
```

Это правило запрещает `company-us` и `company-eu`. Шаблон, оканчивающийся на ` *`, совпадает и со значением без
аргументов, поэтому `shell:git push *` охватывает и просто `git push`.

## Порядок

Если совпало несколько правил, действует последнее. Правила специфичности нет, поэтому сначала указывайте общие
правила, а после них — исключения. Если ничего не совпало, действие разрешено.

```jsonc
{
  "policies": [
    { "action": "provider.use", "resource": "*", "effect": "deny" },
    { "action": "provider.use", "resource": "anthropic", "effect": "allow" },
  ],
}
```

Доступным остается только Anthropic.

## Провайдеры

`provider.use` определяет, можно ли вообще использовать провайдера. Ресурс — это ID провайдера: `anthropic`, `openai`,
`opencode` или собственный ID из [`providers`](/providers).

```jsonc
{
  "providers": {
    "company-ai": {
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": { "baseURL": "https://ai.company.example/v1" },
    },
  },
  "policies": [
    { "action": "provider.use", "resource": "*", "effect": "deny" },
    { "action": "provider.use", "resource": "company-ai", "effect": "allow" },
  ],
}
```

Запись в `providers` настраивает эндпоинт, а правила делают этого провайдера единственным, которым будет пользоваться
OpenCode. Политика применяется независимо от того, откуда OpenCode узнал о провайдере: из данных каталога, переменных
окружения, сохраненных аккаунтов, встроенных плагинов или конфигурации.

Используйте `provider.use` вместо списков `enabled_providers` и `disabled_providers` из V1. Файлы V1 по-прежнему
загружаются; см. [Переход с V1](/migrate-v1#supported-fields-without-direct-native-equivalents).

## Инструменты

Правила `tool.use` жестко запрещают проверку [разрешения](/permissions). Ресурс имеет вид `<action>:<value>` и
сопоставляется с каждым ресурсом, который проверяет инструмент.

```jsonc
{
  "policies": [
    { "action": "tool.use", "resource": "shell:git push *", "effect": "deny" },
    { "action": "tool.use", "resource": "edit:*.env", "effect": "deny" },
    { "action": "tool.use", "resource": "webfetch:*", "effect": "deny" },
  ],
}
```

Запрещенная проверка завершается ошибкой `Blocked by configuration policy` вместо запроса. Политика применяется после
правил агента и сохраненных подтверждений, поэтому переопределяет как `ask`, так и подтверждение **Allow always**.

| Шаблон                       | Что блокирует                                         |
| ---------------------------- | ----------------------------------------------------- |
| `shell:*`                    | Все команды оболочки                                  |
| `read:*/.ssh/*`              | Чтение SSH-ключей и связанных файлов                  |
| `external_directory:*`       | Любой доступ за пределами расположения (Location) или worktree |
| `subagent:general`           | Запуск одного субагента                               |
| `github_delete_repository:*` | Один MCP-инструмент                                   |
| `*`                          | Все, что еще не запрещено                             |

Правило `tool.use` с `allow` никогда не дает доступ. Оно только снимает предшествующий более общий `deny`, после чего
решение принимают собственные правила агента.

```jsonc
{
  "policies": [
    { "action": "tool.use", "resource": "shell:*", "effect": "deny" },
    { "action": "tool.use", "resource": "shell:git status *", "effect": "allow" },
  ],
}
```

Для `git status` применяется правило `shell` агента; все остальные команды блокируются.

## Интеграции

`integration.use` определяет, загружается ли MCP-сервер, навык или плагин. Ресурс состоит из вида интеграции и ее ID:

| Ресурс            | К чему применяется                                                        |
| ----------------- | ------------------------------------------------------------------------- |
| `mcp:<server>`    | [MCP-сервер](/mcp-servers) по имени из конфигурации                       |
| `skill:<id>`      | [Навык](/skills) по его ID                                                |
| `plugin:<target>` | [Плагин](/plugins) по имени пакета без версии или по абсолютному пути     |

```jsonc
{
  "policies": [
    { "action": "integration.use", "resource": "mcp:*", "effect": "deny" },
    { "action": "integration.use", "resource": "mcp:github", "effect": "allow" },
    { "action": "integration.use", "resource": "plugin:opencode-acme-cli", "effect": "deny" },
  ],
}
```

Запрещенный MCP-сервер или навык удаляется, а запрещенный плагин не загружается, независимо от того, как он был
настроен.

## Приоритет

Для обычных настроек побеждает ближайшая конфигурация. У политик все наоборот: правила из более общей конфигурации
применяются позже и поэтому переопределяют более узкие. Последнее слово всегда остается за управляемой конфигурацией и
подключенной Console.

| Уровень      | Источник                                                                                                       |
| ------------ | -------------------------------------------------------------------------------------------------------------- |
| 1 (высший)   | Подключенное рабочее пространство OpenCode Console                                                             |
| 2            | Управляемые настройки macOS (`/Library/Managed Preferences/ai.opencode.managed.plist`)                         |
| 3            | Системный `opencode.json(c)` (`/Library/Application Support/opencode`, `/etc/opencode`, `%ProgramData%\opencode`) |
| 4            | Глобальный `~/.config/opencode/opencode.json(c)`                                                               |
| 5            | `opencode.json(c)` в каталоге; внешние каталоги главнее вложенных                                              |
| 6 (низший)   | `.opencode/opencode.json(c)`; внешние каталоги главнее вложенных                                               |

Репозиторий не может снова включить провайдера, которого вы запретили глобально:

```jsonc title="~/.config/opencode/opencode.jsonc"
{
  "policies": [{ "action": "provider.use", "resource": "openai", "effect": "deny" }],
}
```

```jsonc title="project/opencode.jsonc"
{
  "policies": [{ "action": "provider.use", "resource": "openai", "effect": "allow" }],
}
```

`openai` остается запрещенным. Внутри одного файла правила применяются в том порядке, в котором записаны.

## Console

Рабочее пространство в [OpenCode Console](/console) преобразует свои политики Providers и Tools в правила и возвращает
их вместе с конфигурацией рабочего пространства. OpenCode добавляет их после всех правил из конфигурации, поэтому
последнее слово остается за ними: `deny` организации нельзя снять с помощью `allow` в репозитории или у пользователя, а
`allow` организации снимает `deny` с более низким уровнем полномочий.

В сообщениях об отказе по этим правилам указывается рабочее пространство:

```text
Blocked by Acme's policy
```

Правила следуют за подключенным аккаунтом.

| Событие                              | Результат                                                   |
| ------------------------------------ | ----------------------------------------------------------- |
| Изменение политики в Console         | Применяется при следующем запросе, примерно раз в минуту    |
| Переключение на другое рабочее пространство | Правила заменяются правилами этого пространства      |
| Отключение                           | Правила удаляются                                           |
| Console недоступна                   | Продолжают действовать последние правила этого подключения  |

Плагин Console и плагин политик нельзя отключить через `plugins`; см. [управление плагинами](/plugins#control).

<Callout type="note">
  Политики не настраивают эндпоинты и учетные данные и не могут сделать непригодного провайдера пригодным. Они также не
  изолируют код плагинов: запрещенный провайдер блокируется на обычном пути использования провайдеров и моделей.
</Callout>
