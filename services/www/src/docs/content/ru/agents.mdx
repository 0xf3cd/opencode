title: "Агенты"
---

Чтобы добавить повторно используемого агента, создайте Markdown-файл. В этом примере добавляется ревьюер с доступом
только на чтение, которого основной агент может запускать для код-ревью:

```md title=".opencode/agents/reviewer.md"
---
description: Reviews changes for correctness and regressions
mode: subagent
model: anthropic/claude-sonnet-4-5#high
permissions:
  - action: edit
    resource: "*"
    effect: deny
  - action: shell
    resource: "*"
    effect: deny
---

Review the current changes. List findings in severity order with file and line references.
```

Попросите основного агента воспользоваться им:

```text
Use the reviewer subagent to review my current changes.
```

Агент объединяет системный промпт, предпочтительную модель, разрешения и параметры отображения в именованный профиль
ассистента.

## Расположение

Сохраняйте агентов в Markdown глобально, для всех проектов, или внутри проекта:

```text
~/.config/opencode/agents/<name>.md
.opencode/agents/<name>.md
```

OpenCode находит каталоги `.opencode` проекта от текущего каталога вверх до корня проекта. Вложенный путь становится
частью ID агента:

```text
.opencode/agents/team/reviewer.md  →  team/reviewer
```

## Форматы

### Markdown

Frontmatter принимает те же поля, что и запись в `agents` в конфигурации. Тело Markdown становится промптом `system`
агента:

```md title=".opencode/agents/explainer.md"
---
description: Explains code without changing it
mode: subagent
---

Explain the relevant code with short examples. Do not edit files.
```

### JSONC

Определяйте агентов в разделе `agents` любого [файла конфигурации OpenCode](/config):

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "agents": {
    "reviewer": {
      "description": "Reviews current changes",
      "mode": "subagent",
      "system": "Report findings in severity order.",
      "permissions": [
        { "action": "edit", "resource": "*", "effect": "deny" },
      ],
    },
  },
}
```

## Выбор агента

Задайте основного агента, который используется, если в сессии агент не выбран:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "default_agent": "writer",
  "agents": {
    "writer": { "mode": "primary" },
  },
}
```

Выбранный агент по умолчанию должен существовать, быть видимым и поддерживать работу в качестве основного. Иначе
OpenCode использует `build`, а если и он недоступен — первый видимый агент, который может быть основным. Изменение
этой настройки не заменяет агента, уже сохраненного в существующей сессии.

## Режимы

Задайте `mode` в зависимости от того, где должен работать агент:

```jsonc
{
  "agents": {
    "reviewer": { "mode": "subagent" },
  },
}
```

| Режим | Поведение |
| --- | --- |
| `primary` | Работает как основной агент сессии. Это значение по умолчанию для нового собственного агента. |
| `subagent` | Работает только в дочерней сессии через инструмент `subagent`. |
| `all` | Работает и как основной агент, и как субагент. |

Субагенты запускаются с чистым контекстом в дочерних сессиях на переднем плане или в фоне. Разрешения `subagent`
родительского агента определяют, каких агентов он может запускать; дочерний агент использует собственные настроенные
разрешения.

```jsonc
{
  "agents": {
    "orchestrator": {
      "permissions": [
        { "action": "subagent", "resource": "*", "effect": "deny" },
        { "action": "subagent", "resource": "reviewer", "effect": "allow" },
      ],
    },
  },
}
```

## Встроенные агенты

В OpenCode есть следующие видимые агенты:

| Агент | Режим | Назначение |
| --- | --- | --- |
| **Build** (`build`) | `primary` | Агент для программирования по умолчанию. Инструменты по умолчанию разрешены; чтение конфиденциальных файлов окружения и доступ за пределами рабочего пространства требуют подтверждения. |
| **Plan** (`plan`) | `primary` | Изучает код и планирует, не редактируя обычные файлы проекта. По запросу может записывать файлы планов OpenCode; команды оболочки по-прежнему контролируются разрешениями. |
| **General** (`general`) | `subagent` | Выполняет исследования и многошаговые задачи с широким доступом к инструментам, но не может запускать других субагентов. |
| **Explore** (`explore`) | `subagent` | Ищет и читает код или веб-источники, не редактируя файлы. |

Чтобы переопределить встроенного агента, используйте его ID:

```jsonc
{
  "agents": {
    "build": {
      "permissions": [
        { "action": "shell", "resource": "git push *", "effect": "ask" },
      ],
    },
  },
}
```

Скрытые агенты `compaction`, `title` и `summary` выполняют служебные задачи, и выбрать их напрямую нельзя. Встроенного
агента `scout` в V2 нет.

## Объединение

Определения агентов объединяются в порядке загрузки конфигурации. Более поздние скалярные значения заменяют более
ранние, объекты запросов объединяются по ключам, а правила разрешений добавляются в конец:

```jsonc
{
  "permissions": [
    { "action": "shell", "resource": "*", "effect": "ask" },
  ],
  "agents": {
    "build": {
      "permissions": [
        { "action": "shell", "resource": "git status", "effect": "allow" },
      ],
    },
  },
}
```

Глобальные `permissions` применяются раньше правил конкретного агента, поэтому правила агента могут их уточнять.

## Параметры

### Описание

`description` объясняет назначение агента. Добавляйте его субагентам: OpenCode показывает описание модели, когда она
выбирает, какого агента запустить.

```yaml
description: Reviews database migrations for safety
```

### Режим

`mode` принимает значения `primary`, `subagent` или `all`. Если параметр не задан для нового собственного агента,
используется `primary`:

```yaml
mode: all
```

### Модель

`model` задается в формате `provider/model` с необязательным `#variant`:

```yaml
model: anthropic/claude-sonnet-4-5#high
```

В JSON-конфигурации также можно использовать развернутую форму:

```jsonc
{
  "agents": {
    "reviewer": {
      "model": {
        "providerID": "anthropic",
        "model": "claude-sonnet-4-5",
        "variant": "high",
      },
    },
  },
}
```

- Субагент использует настроенную для него модель, а если она не задана — наследует модель родительской сессии.
- Сессия хранит выбранную модель отдельно. Выбор основного агента по ID эту модель не меняет.

### Системный промпт

`system` задает системный промпт агента. Непустое значение заменяет базовый промпт провайдера для этого агента:

```jsonc
{
  "agents": {
    "reviewer": { "system": "Review only. Do not modify files." },
  },
}
```

Инструкции проекта, навыки, внешние каталоги и другие источники инструкций по-прежнему добавляются. В агенте на
Markdown пишите этот текст в теле документа, а не в поле frontmatter `system`.

### Разрешения

`permissions` — упорядоченный список правил сопоставления:

```jsonc
{
  "agents": {
    "reviewer": {
      "permissions": [
        { "action": "*", "resource": "*", "effect": "deny" },
        { "action": "read", "resource": "src/**", "effect": "allow" },
      ],
    },
  },
}
```

| Поле | Значение |
| --- | --- |
| `action` | Инструмент или действие разрешения. Поддерживаются подстановочные знаки. |
| `resource` | Путь, команда, ID агента или другое значение, с которым сопоставляется действие. Поддерживаются подстановочные знаки. |
| `effect` | `allow`, `ask` или `deny`. |

Применяется последнее подходящее правило, поэтому общие правила ставьте перед исключениями. Часто используемые
действия:

| Действие | Что охватывает |
| --- | --- |
| `shell` | Команды оболочки |
| `edit` | Инструменты редактирования, записи и применения патчей |
| `subagent` | Дочерние агенты |
| `read`, `glob`, `grep` | Инструменты поиска по локальным файлам |
| `webfetch`, `websearch` | Веб-инструменты |
| `skill` | Загрузка навыков |

Для ресурсов `read`, `edit` и `external_directory` OpenCode раскрывает `~` и `$HOME`:

```jsonc
{ "action": "read", "resource": "~/notes/**", "effect": "allow" }
```

Ресурсы `shell` остаются исходным текстом команды, и эти значения в них не раскрываются.

### Шаги

`steps` задает максимальное число шагов модели (положительное):

```yaml
steps: 8
```

На последнем шаге OpenCode убирает инструменты и просит модель подвести итог текстом. Новый ввод пользователя
сбрасывает счетчик.

### Скрытие

`hidden` убирает агента из обычных списков, интерактивного поиска и каталога субагентов:

```yaml
hidden: true
```

Этот параметр управляет видимостью, а не безопасностью. Чтобы ограничить поведение агента, используйте разрешения.

### Цвет

`color` задает цвет агента в интерфейсе в виде шестизначного шестнадцатеричного значения:

```yaml
color: "#ff6b6b"
```

### Отключение

`disabled` удаляет встроенного или собственного агента на этом этапе загрузки конфигурации:

```jsonc
{
  "agents": {
    "plan": { "disabled": true },
  },
}
```

### Запрос

`request` позволяет для каждого агента дополнять заголовки и JSON-тело запроса:

```jsonc
{
  "agents": {
    "reviewer": {
      "request": {
        "headers": { "x-agent": "reviewer" },
        "body": { "temperature": 0.1 },
      },
    },
  },
}
```

<Callout type="warning">
  Механизм выполнения сессий V2 сохраняет эти значения, но пока не отправляет их в запросах к модели. Действующие
  параметры запросов задавайте на уровне провайдера, модели или варианта модели.
</Callout>

Не используйте в новой конфигурации агентов V2 устаревшие поля верхнего уровня, такие как `temperature`, `top_p`,
`prompt`, `permission`, `tools`, `disable` или `maxSteps`.
