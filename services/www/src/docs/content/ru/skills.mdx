---
title: "Навыки"
---

Навык (skill) дает агенту повторно используемые инструкции для определенной задачи. Создайте файл `SKILL.md` в
`.opencode/skills/<skill-id>` и опишите в `description`, когда его использовать.

```markdown title=".opencode/skills/git-release/SKILL.md"
---
name: Git Release
description: Prepare release notes, version bumps, and GitHub releases
---

## Workflow

1. Read `references/release-policy.md`.
2. Summarize merged changes since the previous tag.
3. Propose the version bump before changing files.
4. Run `scripts/changelog.ts` only after the user approves the version.
```

OpenCode сообщает модели об этом навыке, когда он актуален. Затем агент может загрузить его инструкции инструментом
`skill` — добавлять все навыки в каждый промпт не нужно.

## Создание

Храните связанные скрипты, справочные материалы и шаблоны рядом с `SKILL.md`:

```text
.opencode/skills/
└── git-release/
    ├── SKILL.md
    ├── scripts/
    │   └── changelog.ts
    └── references/
        └── release-policy.md
```

Пути внутри навыка указываются относительно каталога, в котором лежит `SKILL.md`. Рекомендуется форма с каталогом: у
вспомогательных файлов появляется собственный базовый каталог.

## Обнаружение

OpenCode автоматически ищет навыки в следующих расположениях:

| Область                  | Источники                              |
| ------------------------ | -------------------------------------- |
| Глобальные               | `~/.config/opencode/skills`            |
| Глобальные (совместимость) | `~/.claude/skills`, `~/.agents/skills` |
| Проект                   | `.opencode/skills`                     |
| Проект (совместимость)   | `.claude/skills`, `.agents/skills`     |

Для проектных источников OpenCode выполняет поиск от текущего каталога вверх до корня проекта и учитывает подходящие
каталоги на каждом уровне.

Каждый источник может содержать навыки в любой из двух форм:

```text
skills/
├── review.md
└── git-release/
    └── SKILL.md
```

- Markdown-файлы должны лежать в корне источника, например `skills/review.md`.
- Файлы с именем ровно `SKILL.md` могут находиться на любой глубине, например `skills/git-release/SKILL.md`.

## Источники

Дополнительные локальные каталоги или HTTP-каталоги навыков добавляются в массив `skills` в любом `opencode.json` или
`opencode.jsonc`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "skills": [
    "./team-skills",
    "~/shared/opencode-skills",
    "/opt/company-skills",
    "https://example.com/opencode/skills/",
  ],
}
```

| Значение | Разрешение |
| -------- | ---------- |
| Относительный путь | Относительно активного рабочего каталога OpenCode, а не файла конфигурации |
| Путь с `~/` | Относительно домашнего каталога текущего пользователя |
| Абсолютный путь | Используется как есть |
| URL `http://` или `https://` | Загружается как HTTP-каталог |

Записи добавляет каждый найденный файл конфигурации. Массивы `skills` объединяются, а не заменяют друг друга.

## HTTP-каталоги

HTTP-каталог — это базовый URL с файлом `index.json`:

```json title="index.json"
{
  "skills": [
    {
      "name": "git-release",
      "version": "3",
      "files": ["git-release.md", "references/release-policy.md"]
    }
  ]
}
```

Для этой записи OpenCode скачивает каждый файл по адресу `<base-url>/git-release/<file>`.

| Правило | Требование |
| ------- | ---------- |
| Пути | Должны быть безопасными, относительными и с того же источника (same-origin) |
| Основной файл | Включите `SKILL.md` или `<name>.md`, например `git-release.md` |
| Обновления | При изменении файлов увеличивайте `version`, чтобы OpenCode обновил кэш |

В HTTP-каталоге лучше использовать форму с именованным Markdown-файлом. Каждый скачанный каталог навыка становится
корнем источника, поэтому у `git-release.md` будет ID `git-release`. У `SKILL.md` в корне в V2 сейчас буквальный ID
`SKILL`.

## Frontmatter

Во frontmatter задаются имя навыка и то, где он будет показан:

```markdown title="SKILL.md"
---
name: Git Release
description: Prepare a repository release
metadata:
  opencode/autoinvoke: false
---

Prepare the changelog, version bump, tag, and release notes.
```

| Поле                           | Поведение                                                              |
| ------------------------------ | ---------------------------------------------------------------------- |
| `name`                         | Отображаемое имя; по умолчанию — ID, определенный по пути              |
| `description`                  | Краткое описание, по которому навык показывается модели                |
| `metadata.opencode/autoinvoke` | Значение `false` исключает навык из списка доступных модели            |
| `disable-model-invocation`     | Значение `true` действует так же, как `opencode/autoinvoke: false`     |

Во время выполнения все поля frontmatter необязательны. Если модель должна находить навык, добавьте понятное
`description`: навыки без описания модели не предлагаются.

`opencode/autoinvoke: false` только скрывает навык из списка, доступного модели. Навык остается зарегистрированным, и
его по-прежнему можно загрузить явно по ID. Если заданы и `disable-model-invocation`, и `opencode/autoinvoke`, приоритет
имеет `opencode/autoinvoke`. V2 принимает поля для переносимости, такие как `license` и `compatibility`, но не
интерпретирует их.

## ID

ID навыка определяется путем к файлу. Поле `name` во frontmatter — только отображаемая метка.

| Файл                              | ID            |
| --------------------------------- | ------------- |
| `<source>/git-release.md`         | `git-release` |
| `<source>/git-release/SKILL.md`   | `git-release` |
| `<source>/teams/release/SKILL.md` | `release`     |

ID сравниваются точно и с учетом регистра. Для переносимых навыков используйте уникальный ID в нижнем регистре в стиле
kebab-case длиной 1–64 символа и согласуйте его с именем каталога:

```text
^[a-z0-9]+(-[a-z0-9]+)*$
```

Сейчас V2 не проверяет ни этот шаблон, ни рекомендованную длину 1–64 символа, ни совпадение `name` с именем каталога,
ни максимальную длину описания.

## Приоритет

Навыки выбираются по ID. Если `git-release` определен в двух источниках, OpenCode загружает навык из источника,
зарегистрированного позже:

```text
~/.config/opencode/skills/git-release/SKILL.md  ← lower precedence
.opencode/skills/git-release/SKILL.md           ← loaded
```

Источники регистрируются от низшего приоритета к высшему:

1. Встроенные навыки
2. `.claude/skills`: сначала глобальный, затем от самого дальнего родительского каталога к текущему
3. `.agents/skills`: сначала глобальный, затем от самого дальнего родительского каталога к текущему
4. `~/.config/opencode/skills`
5. `.opencode/skills` проекта: от корня проекта к текущему каталогу
6. Явные записи `skills` в конфигурации: в порядке приоритета конфигурации и порядке элементов массива

Не используйте повторяющиеся ID, если только вы не хотите намеренно переопределить ранее объявленный навык.

## Загрузка

На каждом шаге модели OpenCode перечисляет разрешенные навыки, у которых есть описание и для которых
`opencode/autoinvoke` не равен `false`. Список содержит только ID, имя и описание, но не полное тело Markdown.

Модель загружает навык, вызывая инструмент `skill` с его точным ID:

```json title="skill tool input"
{
  "id": "git-release"
}
```

Затем OpenCode:

1. Выбирает текущее определение для этого ID.
2. Проверяет разрешение `skill` выбранного агента.
3. Добавляет в диалог тело Markdown без frontmatter.
4. Передает базовый каталог навыка и до десяти путей к вспомогательным файлам в качестве примера.

Чтобы загрузить навык самостоятельно, упомяните его в промпте как `@skill-id`.

Содержимое вспомогательных файлов автоматически не загружается: агент читает их, когда этого требует навык. Список
файлов доступен для навыков в форме каталога с `SKILL.md`; навыки в виде отдельных Markdown-файлов списка соседних
файлов не получают.

## Разрешения

Используйте действие `skill`, а в качестве ресурса — ID навыка. Правила проверяются по порядку, применяется последнее
подходящее:

```jsonc title="opencode.jsonc"
{
  "permissions": [
    { "action": "skill", "resource": "*", "effect": "allow" },
    { "action": "skill", "resource": "internal-*", "effect": "deny" },
    { "action": "skill", "resource": "experimental-*", "effect": "ask" },
  ],
}
```

| Эффект | Поведение |
| ------ | --------- |
| `allow` | Предлагает модели подходящие навыки и загружает их без подтверждения |
| `ask` | Предлагает подходящие навыки и запрашивает подтверждение перед загрузкой |
| `deny` | Скрывает подходящие навыки от модели и запрещает их загрузку |

Чтобы применить те же правила только к одному агенту, поместите их в `agents.<id>.permissions`.

## Устранение неполадок

Например, ID этого навыка — `release`, а не имя `Git Release` из frontmatter:

```text
.opencode/skills/release/SKILL.md
                      └─ ID: release
```

Если навык не находится или загружается не то содержимое:

1. Убедитесь, что файл — это либо `*.md` в корне источника, либо вложенный файл с именем ровно `SKILL.md`.
2. Проверяйте ID, определенный по пути и чувствительный к регистру, а не `name` из frontmatter.
3. Добавьте `description`, если модель должна находить навык.
4. Проверьте `opencode/autoinvoke` и разрешения `skill` выбранного агента.
5. Поищите источник, зарегистрированный позже и определяющий тот же ID.
6. Для HTTP-каталогов проверьте `index.json`, пути к файлам с того же источника и изменение `version`.
