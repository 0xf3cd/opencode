Создайте `.opencode/commands/review.md`, чтобы превратить промпт в команду `/review`:

```md title=".opencode/commands/review.md"
Review $ARGUMENTS for bugs and missing tests.
```

Запустите ее в TUI, указав цель:

```text
/review src/auth.ts
```

OpenCode отправит `Review src/auth.ts for bugs and missing tests.` как промпт пользователя.

## Markdown

Глобальные команды размещайте в `~/.config/opencode/commands/`, а команды проекта — в `.opencode/commands/`.

```text
~/.config/opencode/commands/review.md
.opencode/commands/review.md
```

Учитываются только файлы `.md`. Вложенные пути превращаются в имена команд с разделителем `/`:

```md title=".opencode/commands/team/review.md"
Review $ARGUMENTS using the team's checklist.
```

Вложенная команда запускается как `/team/review src/auth.ts`. Устаревшие каталоги с именем в единственном числе
`command/` тоже учитываются, но для новых файлов используйте `commands/`.

Если команде нужны метаданные, добавьте YAML-frontmatter. Тело Markdown (без начальных и конечных пробелов) всегда
служит шаблоном промпта.

```md title=".opencode/commands/review.md"
---
description: Review code for correctness
agent: plan
model: anthropic/claude-sonnet-4-5#high
---

Review $ARGUMENTS. Report bugs first.
```

## JSON

Определяйте команды в разделе `commands` любого [файла конфигурации](/config) OpenCode в формате JSON или JSONC. Для
каждой команды обязателен `template`.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "commands": {
    "review": {
      "description": "Review code for correctness",
      "template": "Review $ARGUMENTS. Report bugs first.",
    },
  },
}
```

## Поля

Frontmatter в Markdown и записи в JSON принимают одни и те же поля, только в Markdown `template` берется из тела файла.

| Поле | Обязательное | Поведение |
| --- | --- | --- |
| `template` | Только в JSON | Шаблон промпта. |
| `description` | Нет | Текст, который показывается в списках команд и при поиске. |
| `agent` | Нет | Агент, выбираемый при запуске команды. |
| `model` | Нет | Переопределение модели в формате `provider/model` или `provider/model#variant`. |
| `subagent` | Нет | `true` — выполнение в фоновой дочерней сессии; `false` — принудительно в текущей сессии. |
| `subtask` | Нет | Устаревший псевдоним `subagent`. |

Например, в этой JSON-команде заданы все актуальные необязательные поля:

```jsonc title="opencode.jsonc"
{
  "commands": {
    "audit": {
      "template": "Audit $ARGUMENTS.",
      "description": "Audit a package",
      "agent": "general",
      "model": "anthropic/claude-sonnet-4-5#high",
      "subagent": true,
    },
  },
}
```

Не указывайте `template` во frontmatter Markdown — его задает тело файла.

## Аргументы

`$ARGUMENTS` подставляет всю строку аргументов точно в том виде, в каком она введена.

```md title=".opencode/commands/component.md"
Create a typed React component named $ARGUMENTS.
```

Для `/component Account Settings` плейсхолдер заменяется на `Account Settings`.

## Позиционные аргументы

`$1`, `$2` и следующие номера подставляют разобранные позиционные аргументы. Одинарные или двойные кавычки группируют
слова и удаляются.

```md title=".opencode/commands/check.md"
Check $1. Focus on $2.
```

Для `/check src/auth.ts "error handling"` `$1` становится `src/auth.ts`, а `$2` — `error handling`.

Плейсхолдер с наибольшим номером забирает свой аргумент и все, что идет после него. Отсутствующие позиции заменяются
пустыми строками.

```md title=".opencode/commands/compare.md"
Compare $1 with $2.
```

Для `/compare api stable branch` OpenCode отправит `Compare api with stable branch.`

## Без плейсхолдеров

Если в шаблоне нет ни `$ARGUMENTS`, ни позиционных плейсхолдеров, OpenCode добавляет непустые аргументы в конец после
пустой строки.

```md title=".opencode/commands/explain.md"
Explain this code clearly.
```

Для `/explain src/cache.ts` промпт будет таким:

```text
Explain this code clearly.

src/cache.ts
```

## Команды оболочки

Чтобы перед отправкой промпта вставить вывод команды оболочки, заключите ее в обратные кавычки с `!` перед ними.

```md title=".opencode/commands/review-diff.md"
Review this diff:

!`git diff --stat && git diff`
```

OpenCode выполняет каждый такой блок в настроенной оболочке в текущем расположении проекта и вставляет его объединенный
вывод. Плейсхолдеры аргументов подставляются заранее:

```md title=".opencode/commands/history.md"
Summarize these commits:

!`git log --oneline -$1`
```

Для `/history 5` оболочка получит `git log --oneline -5`. Не подставляйте недоверенные аргументы в блоки оболочки.

<Callout type="warning">
  Блоки оболочки выполняются, когда OpenCode обрабатывает команду, — вне механизма разрешений для инструментов агента.
  Используйте команды только из источников, которым доверяете.
</Callout>

## Вложения

Сохраненные шаблоны не раскрывают `@path`: это остается обычным текстом промпта.

```md title=".opencode/commands/readme.md"
Review @README.md.
```

Чтобы прикрепить файл, добавьте его через поле ввода при вызове команды. OpenCode сохраняет такие вложения при отправке
раскрытого промпта.

## Выполнение

Перед отправкой промпта пользователя, который сохраняется в сессии, команды подставляют аргументы и выполняют блоки
оболочки. По умолчанию команды выполняются в текущей сессии.

```md title=".opencode/commands/plan.md"
---
agent: plan
---

Plan $ARGUMENTS.
```

`/plan migration` переключает текущую сессию на агента `plan`, а затем отправляет промпт.

Модель выбирается по следующим правилам:

1. `model` команды переопределяет любую другую модель.
2. Иначе модель, настроенная для выбранного командой агента, переопределяет модель, активную в момент вызова.
3. Иначе остается активной текущая модель сессии.

Например, эта команда выбирает и агента, и явно заданную модель:

```md title=".opencode/commands/design.md"
---
agent: plan
model: openai/gpt-5#high
---

Design $ARGUMENTS.
```

## Фоновое выполнение

Чтобы выполнить команду в фоновой дочерней сессии, задайте `subagent: true`.

```md title=".opencode/commands/audit.md"
---
description: Audit changes
agent: general
subagent: true
---

Audit $ARGUMENTS for bugs and missing tests.
```

Родительская сессия остается доступной и сохраняет своего агента и модель. Когда дочерняя сессия завершается, OpenCode
передает ее результат или ошибку в родительскую.

| Значение | Поведение |
| --- | --- |
| `true` | Всегда используется дочерняя сессия, даже если у выбранного агента `mode: primary`. |
| `false` | Всегда используется текущая сессия, даже если у выбранного агента `mode: subagent`. |
| Не задано | Дочерняя сессия используется, только если у выбранного агента `mode: subagent`. |

Дочерняя сессия использует модель команды, затем модель выбранного агента, затем модель родительской сессии. Устаревшее
поле `subtask` по-прежнему принимается; если заданы оба поля, приоритет имеет `subagent`.

```yaml
subagent: false
subtask: true
```

Этот пример выполняется в текущей сессии, потому что приоритет имеет `subagent`.

## Загрузка

Команды из Markdown и JSON хранятся в общем реестре. Более поздние источники заменяют ранее загруженные команды с тем же
именем.

```text
~/.config/opencode/commands/review.md   # Lower priority
.opencode/commands/review.md           # Replaces the global command
```

Проектные источники имеют приоритет над глобальными, а более близкие к текущему каталогу — над родительскими.
Собственное определение может заменить и встроенную команду. OpenCode автоматически перезагружает файлы команд и
изменения конфигурации.

```md title=".opencode/commands/review.md"
Review only the staged changes: !`git diff --cached`
```

После сохранения этого файла команда `/review` обновится без перезапуска OpenCode.
