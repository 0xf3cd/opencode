---
title: "Снимки"
---

Снимки позволяют отменить недавние изменения в переписке и в файлах одновременно. Используйте их, чтобы переделать
недавнюю работу, но для всего важного по-прежнему делайте коммиты Git или резервные копии.

## Порядок работы

Выполните `/undo` после ответа, который хотите переделать. OpenCode подготавливает откат, восстанавливает затронутые
файлы и возвращает удаленный промпт в поле ввода, чтобы его можно было отредактировать.

```text
/undo

# Edit the restored prompt, then submit it again.
Add validation without changing the public API.
```

Отправка отредактированного промпта фиксирует подготовленный откат. До отправки можно выполнить `/redo`, чтобы отменить
откат и вернуть переписку и файлы в состояние до `/undo`.

```text
/redo
```

В терминале также есть сочетания клавиш по умолчанию:

| Действие | Команда | Сочетание клавиш |
| --- | --- | --- |
| Подготовить откат предыдущего сообщения | `/undo` | `<leader>u` |
| Отменить подготовленный откат | `/redo` | `<leader>r` |

Можно также выбрать более раннее сообщение и нажать **Revert**, чтобы подготовить откат к этой точке.

## Создание снимков

На каждом шаге модели OpenCode пытается сделать снимок непосредственно перед вызовом модели и еще один — когда шаг
завершается зафиксированным успехом или ошибкой. В сообщении ассистента записывается, какие пути изменились между этими
снимками.

```text
before model step ── snapshot A
model edits src/api.ts
step finishes ────── snapshot B ── changed: src/api.ts
```

Создание снимков не гарантировано. Если какой-либо из двух снимков недоступен, переписка продолжается, но
изменения файлов на этом шаге, возможно, нельзя будет восстановить.

## Охват

Снимки охватывают активный каталог сессии внутри worktree Git. Например, сессия, открытая в `packages/app`, сохраняет
подходящие файлы внутри `packages/app`, но не изменения в других местах репозитория.

| Содержимое | Сохраняется | Пример |
| --- | --- | --- |
| Отслеживаемые файлы в активном каталоге | Да | `packages/app/src/app.tsx` |
| Неотслеживаемые и неигнорируемые файлы размером до 2 MiB каждый | Да | `packages/app/notes.txt` |
| Файлы, игнорируемые Git | Нет | `packages/app/dist/app.js` |
| Отдельные неотслеживаемые файлы больше 2 MiB | Нет | `packages/app/debug.log` |
| Файлы вне активного каталога | Нет | `packages/server/src/index.ts` |
| Метаданные Git и другие побочные эффекты | Нет | коммиты, ветки, базы данных или процессы |

Для снимков файловой системы нужен Git-репозиторий. Вне его `/undo` по-прежнему может откатить историю переписки, но не
может восстановить файлы.

## Восстановление

Откат восстанавливает только пути, изменения которых приписаны шагам ассистента после выбранной границы переписки.
Каждый путь возвращается в состояние до первого отмененного шага; файл, созданный на этих шагах, удаляется, если до них
его не существовало.

| Хронология | `src/api.ts` | `src/new.ts` |
| --- | --- | --- |
| Выбранная граница | версия A | отсутствует |
| Последующие шаги ассистента | версия B | создан |
| После отката | версия A | удален |

Пути, не приписанные этим шагам, не затрагиваются. Текущие правки затронутого пути могут быть перезаписаны, поэтому
перед тем как продолжить, просмотрите сводку восстановления и `git diff`.

```sh
git diff --stat
git diff
```

## Хранение

OpenCode хранит снимки локально в отдельной внутренней базе объектов Git в своем каталоге данных. При создании снимков
не создаются коммиты, не перемещаются ветки и намеренно не изменяется индекс вашего репозитория.

```sh
# Your repository remains an ordinary dirty worktree after capture.
git status --short
```

Объекты снимков могут содержать полное содержимое отслеживаемых и подходящих неотслеживаемых файлов. Относитесь к
каталогу данных OpenCode как к конфиденциальным локальным данным.

## Настройки

Снимки включены по умолчанию. Задайте `snapshots: false` в [конфигурации](/config#snapshots), чтобы прекратить
создавать снимки файловой системы.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "snapshots": false,
}
```

Отключение снимков не удаляет уже сохраненные снимки. Откат переписки по-прежнему доступен, но без сохраненного состояния
файловой системы связанные изменения файлов восстановить нельзя.

## Безопасность

Снимки — это удобство, а не транзакция и не резервная копия:

- Команды оболочки могут изменить сервисы, процессы, сетевые ресурсы, базы данных, состояние Git, игнорируемые
  артефакты или файлы вне активного каталога. Восстановление снимка эти изменения не отменяет.
- Прерванная или завершившаяся ошибкой работа может оставить изменения, если создать снимок не удалось или нет пригодной
  пары снимков.
- Восстановление затронутых путей перезаписывает их текущее содержимое. Отмена подготовленного отката тоже может
  перезаписать более поздние правки.
- OpenCode не выполняет откат, пока сессия работает, но внешние редакторы и команды все равно могут изменить worktree
  между созданием снимка и восстановлением.
- Фиксация отката убирает сообщения из видимой переписки, но не из сохраненной истории сессии и не из хранилища
  снимков. Это не безопасное удаление данных.

Прежде чем использовать `/undo` в worktree с незафиксированными изменениями, сделайте коммит или резервную копию важной
работы.
