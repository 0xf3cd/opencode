Задайте стандартные переменные окружения для прокси и исключите loopback-адреса. CLI и фоновый сервис OpenCode общаются
по локальному HTTP, поэтому, если в окружении CLI настроен прокси, loopback-адреса обязательно нужно исключить.

```bash
export HTTP_PROXY=http://proxy.example.com:8080
export HTTPS_PROXY=http://proxy.example.com:8080
export NO_PROXY=localhost,127.0.0.1,::1

opencode
```

`HTTP_PROXY` используется для HTTP-адресов назначения, а `HTTPS_PROXY` — для HTTPS. Сам URL прокси в обеих переменных
может начинаться с `http://`. `NO_PROXY` — это список хостов и адресов через запятую, к которым OpenCode подключается
напрямую.

## Фоновый сервис

Переменные, экспортированные в оболочке, действуют на фоновый сервис, только если он запускается из этой оболочки.
Сохраните переменные в конфигурации управляемого сервиса, чтобы при каждом следующем запуске сервис использовал те же
сетевые настройки.

```bash
opencode service set env HTTP_PROXY http://proxy.example.com:8080
opencode service set env HTTPS_PROXY http://proxy.example.com:8080
opencode service set env NO_PROXY localhost,127.0.0.1,::1
opencode service start
```

При изменении переменной окружения управляемого сервиса запущенный сервис останавливается. Команда `service start`
снова запускает его уже с новым окружением. Если в оболочке CLI тоже задан прокси, оставьте в ней и `NO_PROXY`: переменные
управляемого сервиса применяются к процессу сервера, а не к процессу CLI.

Чтобы удалить сохраненную переменную, используйте `service unset env`:

```bash
opencode service unset env HTTPS_PROXY
```

## Аутентификация

Если прокси принимает учетные данные в URL, укажите имя пользователя и пароль в каждом URL прокси, где требуется
аутентификация. Символы вроде `@`, `:` и `/` в имени пользователя или пароле нужно закодировать с помощью percent-encoding.

```bash
export HTTPS_PROXY='http://user:p%40ssword@proxy.example.com:8080'
```

Для фонового сервиса сохраните URL целиком. Значение хранится в закрытой конфигурации сервиса и выводится командой
`opencode service get env`, поэтому не публикуйте ее вывод.

```bash
opencode service set env HTTPS_PROXY 'http://user:p%40ssword@proxy.example.com:8080'
```

## Сертификаты

Если прокси или целевой сервер использует сертификат, подписанный частным центром сертификации, укажите в
`NODE_EXTRA_CA_CERTS` путь к PEM-файлу. Дополнительные центры сертификации добавляются в хранилище доверенных
сертификатов среды выполнения при запуске процесса.

```bash
export NODE_EXTRA_CA_CERTS=/etc/company/ca.pem
opencode --standalone
```

Сохраните путь к файлу для фонового сервиса и перезапустите его:

```bash
opencode service set env NODE_EXTRA_CA_CERTS /etc/company/ca.pem
opencode service start
```

## Процессы на переднем плане

`--standalone` и `serve` используют окружение собственного процесса. Команда `opencode service set env` эти процессы не
настраивает.

```bash
HTTP_PROXY=http://proxy.example.com:8080 \
HTTPS_PROXY=http://proxy.example.com:8080 \
NO_PROXY=localhost,127.0.0.1,::1 \
opencode --standalone
```

Так же настраивается и сервер, запущенный на переднем плане:

```bash
HTTPS_PROXY=http://proxy.example.com:8080 \
NO_PROXY=localhost,127.0.0.1,::1 \
opencode serve
```

## Проверка

Применив настройки, убедитесь, что CLI может подключиться к фоновому сервису:

```bash
opencode api get /api/info
```

Успешный ответ health-проверки подтверждает, что локальное соединение между клиентом и сервисом работает. Чтобы
проверить исходящий прокси и настройку сертификатов сервиса, выполните обычный запрос к провайдеру.
