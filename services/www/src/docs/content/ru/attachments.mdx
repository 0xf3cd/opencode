## Прикрепление

Прикрепите локальный файл и попросите OpenCode использовать его в промпте. В десктопном или веб-клиенте выберите
**Attach file**, вставьте файл или перетащите его в поле промпта.

```text
Summarize the attached README.md and list the required setup steps.
```

Файлы, выбранные в диалоге десктопного приложения, могут занимать в сумме до 20 MiB. В других интерфейсах ограничения на
стороне клиента могут быть ниже.

<Callout type="warning">
  Прежде чем прикреплять изображение, выберите модель, которая принимает изображения на вход. OpenCode может передать
  провайдеру поддерживаемые изображения, но провайдер и модель все равно применяют собственные ограничения на форматы,
  размеры в пикселях, количество и объем файлов. Модель, работающая только с текстом, может отклонить запрос.
</Callout>

## Синтаксис

Во входных данных промптов и команд V2 вложение описывается полем `uri` и необязательными `name` и `description`:

```json
{
  "uri": "file:///home/me/project/src/server.ts",
  "name": "server.ts",
  "description": "HTTP server entrypoint"
}
```

Для файла или каталога, доступного серверу, используйте абсолютный URL `file:`. Для текстовых файлов положительные
параметры `start` и `end` выбирают строки (нумерация с единицы).

```text
file:///home/me/project/src/server.ts?start=20&end=60
```

Чтобы передать содержимое напрямую, используйте URL `data:`:

```json
{
  "uri": "data:text/plain;base64,SGVsbG8sIE9wZW5Db2RlIQ==",
  "name": "greeting.txt"
}
```

URL вложений с HTTP и HTTPS не поддерживаются. Программная отправка промптов описана в сгенерированном
[справочнике по API](/api).

## Форматы

В текущих сессиях V2 модели доступны следующие типы вложений:

| Входные данные           | Что получает модель                                            | Пример             |
| ------------------------ | -------------------------------------------------------------- | ------------------ |
| Текстовый файл в UTF-8   | Имя файла и декодированный текст                               | `README.md`        |
| Каталог                  | Нерекурсивный список вложенных файлов и каталогов первого уровня | `file:///home/me/` |
| PNG, JPEG, GIF или WebP  | Изображение                                                    | `diagram.png`      |

SVG обрабатывается как текст. PDF, AVIF, BMP, аудио, видео и другие бинарные вложения в запрос к модели не включаются.
Сначала преобразуйте неподдерживаемый бинарный файл в текст или поддерживаемое изображение: например, экспортируйте
страницу PDF как `page-1.png` и прикрепите ее.

OpenCode читает каждое вложение до того, как принять промпт. Он отклоняет некорректные URL, недоступные для чтения пути,
пути, которые не являются файлами или каталогами, а также вложения больше 20 MiB после декодирования. Тип содержимого
определяется по байтам, поэтому изменение имени файла или типа в URL `data:` не сделает неподдерживаемый бинарный файл
видимым для модели.

## Изображения

Нормализация изображений настраивается в `opencode.json` или `opencode.jsonc`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "media": {
    "image": {
      "auto_resize": true,
      "max_width": 2000,
      "max_height": 2000,
      "max_base64_bytes": 5242880,
    },
  },
}
```

Все поля необязательны:

| Поле               | По умолчанию | Поведение                                                                   |
| ------------------ | ------------ | --------------------------------------------------------------------------- |
| `auto_resize`      | `true`       | Уменьшать изображение, превышающее заданный лимит; при `false` — отклонять его. |
| `max_width`        | `2000`       | Максимальная ширина в пикселях; положительное целое число.                  |
| `max_height`       | `2000`       | Максимальная высота в пикселях; положительное целое число.                  |
| `max_base64_bytes` | `5242880`    | Максимальный размер изображения в кодировке Base64 в байтах; положительное целое число. |

Например, такая настройка отклоняет изображения шире 1200 пикселей, а не уменьшает их:

```jsonc title="opencode.jsonc"
{
  "media": {
    "image": {
      "auto_resize": false,
      "max_width": 1200,
    },
  },
}
```

Эти настройки применяются как к поддерживаемым изображениям, прикрепленным к промптам, так и к изображениям, которые
возвращает встроенный инструмент `read`.

## Обработка

Инструмент `read` распознает PNG, JPEG, GIF и WebP по содержимому и читает до 20 MiB исходных данных изображения. Он
сверяет ширину, высоту и длину в Base64 с заданными лимитами.

При `auto_resize: true` OpenCode сохраняет соотношение сторон и уменьшает изображение до допустимых размеров. Затем он
пробует все более компактные варианты кодирования PNG и JPEG, пока не уложится в лимит Base64, поэтому тип выходного
изображения может измениться.

```text
Input:  4000 × 2000 WebP
Limits: 2000 × 2000
Output: 2000 × 1000 PNG or JPEG
```

Если ни один вариант не подходит, обработка завершается ошибкой. При `auto_resize: false` изображение, превышающее любой
лимит, отклоняется без изменений; изображение, которое не удается декодировать, тоже вызывает ошибку.

```text
Input:  2400 × 1600 JPEG
Limit:  max_width = 2000, auto_resize = false
Result: Image processing fails
```

Если модуль изменения размера недоступен, OpenCode передает исходное изображение без изменений. Поэтому настройки
изображений — это ограничения обработки, а не барьер для загрузки и не мера безопасности.

## Ограничения

| Ограничение                         | Значение или поведение                                          | Пример                                            |
| ----------------------------------- | --------------------------------------------------------------- | ------------------------------------------------- |
| Прямое вложение                     | 20 MiB на элемент после декодирования; клиенты могут ограничивать сильнее | Два файла по 12 MiB проходят лимит на элемент |
| Выбор файлов в десктопном приложении | 20 MiB в сумме                                                 | Два файла по 12 MiB превышают лимит выбора        |
| `max_base64_bytes`                  | Только закодированные данные Base64, без остальной части URL `data:` | `SGVsbG8=` считается как 8 байт              |
| Лимиты провайдера на изображения    | Применяются после обработки в OpenCode                          | Провайдер может отклонить принятое изображение    |
| Поддержка текстовых вложений моделью | Мультимодальная модель не требуется                            | `notes.txt` вставляется в промпт как текст        |
| Лимиты текста в `read`              | Действуют отдельные лимиты разбиения на страницы и усечения     | Большой лог читается по страницам                 |

То, что клиент принял файл, не гарантирует, что его содержимое дойдет до модели. Вложение должно быть в формате, видимом
модели, и укладываться в лимиты и OpenCode, и провайдера.
