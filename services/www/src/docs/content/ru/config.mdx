---
title: "Конфигурация"
---

Чтобы настроить OpenCode, создайте в проекте файл `opencode.jsonc`. Добавьте схему для проверки в редакторе и задайте
только нужные параметры.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "anthropic/claude-sonnet-4-5",
}
```

Можно также попросить OpenCode обновить этот файл за вас.

## Формат

OpenCode поддерживает JSON и JSONC. Используйте JSONC, если нужны комментарии или завершающие запятые.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  // Use this model by default.
  "model": "anthropic/claude-sonnet-4-5",
}
```

## Расположение

Управляемые настройки для всей машины размещайте в системном каталоге конфигурации:

| Платформа | Каталог                                 |
| --------- | --------------------------------------- |
| macOS     | `/Library/Application Support/opencode` |
| Linux     | `/etc/opencode`                         |
| Windows   | `%ProgramData%\opencode`                |

Системный каталог работает так же, как глобальный. Помимо `opencode.json(c)`, из него загружаются `agents/`,
`commands/`, `skills/` и `plugins/` для всех пользователей машины:

```text
/etc/opencode/
├── opencode.json
├── agents/review.md
├── commands/release.md
└── skills/deploy/SKILL.md
```

В macOS OpenCode также читает управляемые настройки, которые MDM-инструменты разворачивают для домена
`ai.opencode.managed`. Профиль конкретного пользователя заменяет профиль для всей машины:

```text
/Library/Managed Preferences/<user>/ai.opencode.managed.plist
/Library/Managed Preferences/ai.opencode.managed.plist
```

Управляемые настройки имеют наивысший приоритет: пользователи и проекты не могут переопределить заданные в них значения,
а управляемые настройки macOS переопределяют системный каталог. Одни лишь настройки не запрещают пользователям добавлять
провайдеры, MCP-серверы, агентов или плагины — для ограничений используйте [политики](/policies#precedence) в управляемой
конфигурации.

Пользовательские настройки для всех проектов размещайте в глобальной конфигурации:

```text
~/.config/opencode/opencode.json(c)
```

Настройки проекта размещайте в одном из этих файлов:

```text
/home/user/projects/my-app/opencode.json(c)
/home/user/projects/my-app/.opencode/opencode.json(c)
```

OpenCode ищет файлы от текущего каталога до корня файловой системы. Сначала он объединяет файлы `opencode.json(c)`,
лежащие непосредственно в каталогах, — от самого дальнего к ближайшему, затем в том же порядке объединяет файлы внутри
каталогов `.opencode`. Поэтому любая найденная конфигурация из `.opencode` переопределяет любую конфигурацию,
лежащую непосредственно в каталоге. Если такое поведение вам не нужно, используйте во всем дереве каталогов один вариант.

Например, запустим OpenCode из `/home/user/projects/acme/packages/web`:

```text
/etc/opencode/opencode.json
~/.config/opencode/opencode.json

/home/user/projects/acme/
├── opencode.json
└── packages/
    └── web/
        ├── opencode.json
        └── src/
```

OpenCode применяет эти файлы от низшего приоритета к высшему:

1. `~/.config/opencode/opencode.json`
2. `/home/user/projects/acme/opencode.json`
3. `/home/user/projects/acme/packages/web/opencode.json`
4. `/etc/opencode/opencode.json`

Конфигурация пакета переопределяет совпадающие настройки конфигурации репозитория, а та — глобальную конфигурацию.
Системная конфигурация переопределяет их все. Неконфликтующие настройки сохраняются. [Политики](/policies#precedence)
из глобальных и проектных файлов вычисляются в обратном порядке, а системные политики важнее всех остальных.

## Схема

Полная схема конфигурации OpenCode доступна по адресу [opencode.ai/config.json](https://opencode.ai/config.json).

Добавьте поле `$schema` в файл конфигурации, чтобы включить проверку и автодополнение в редакторах с поддержкой
JSON Schema:

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json"
}
```

Схема — основной источник информации о доступных полях, допустимых значениях и структуре вложенной конфигурации.

### Оболочка

Задает оболочку для терминала и инструментов оболочки.

```jsonc
{
  "shell": "/bin/zsh",
}
```

### Модель

Задает модель по умолчанию в формате `provider/model`. Корневое значение по умолчанию пока не сохраняет `#variant`;
выбрать вариант можно в ссылках на модель в агентах и командах.

```jsonc
{
  "model": "anthropic/claude-sonnet-4-5",
}
```

О выборе модели и локальных моделях читайте в [руководстве по моделям](/models).

### Агент

Выберите основного агента, который используется, если сессия не задает агента явно.

```jsonc
{
  "default_agent": "build",
}
```

О встроенных и собственных агентах читайте в [руководстве по агентам](/agents).

### Обновления

Проверка обновлений настраивается в глобальной конфигурации. Значение `"disable"` в `update` отключает проверку,
`"notify"` показывает доступные обновления перед установкой, а `"auto"` устанавливает обновления автоматически. Если
параметр не задан, `update` по умолчанию равен `"notify"`.

Автоматическая установка не перезапускает работающий сервер. Чтобы установленное обновление вступило в силу,
перезапустите его вручную. Значения на уровне проекта игнорируются.

```jsonc
{
  "update": "notify",
}
```

### Общий доступ

Задает политику общего доступа к сессиям. OpenCode принимает это поле, но общий доступ к сессиям пока не
поддерживается.

```jsonc
{
  "share": "manual",
}
```

Подробнее — в [руководстве по общему доступу](/sharing).

### Имя пользователя

Задает имя пользователя. OpenCode принимает это поле, но не показывает имя в диалогах.

```jsonc
{
  "username": "alice",
}
```

### Разрешения

Задайте упорядоченные правила, которые разрешают или запрещают агенту использовать инструмент для подходящего ресурса
либо требуют сначала спросить пользователя.

```jsonc
{
  "permissions": [
    {
      "action": "shell",
      "resource": "git push *",
      "effect": "ask",
    },
  ],
}
```

О сопоставлении правил и доступных действиях читайте в [руководстве по разрешениям](/permissions).

### Политики

Упорядоченные правила политик разрешают или запрещают использовать провайдер, безусловно запрещают действие при
проверке разрешений или блокируют MCP-сервер, навык или плагин. Конфигурация более широкого уровня может их
переопределить.

```jsonc
{
  "policies": [
    { "action": "provider.use", "resource": "*", "effect": "deny" },
    { "action": "provider.use", "resource": "anthropic", "effect": "allow" },
    { "action": "tool.use", "resource": "shell:git push *", "effect": "deny" },
  ],
}
```

О сопоставлении, приоритете между файлами конфигурации и политиках, управляемых через Console, читайте в
[руководстве по политикам](/policies).

### Агенты

Переопределяйте встроенных агентов или создавайте специализированных — со своей моделью, инструкциями, режимом и
разрешениями.

```jsonc
{
  "agents": {
    "reviewer": {
      "description": "Review changes without editing files",
      "mode": "subagent",
      "system": "Focus on correctness, security, and missing tests.",
      "permissions": [{ "action": "edit", "resource": "*", "effect": "deny" }],
    },
  },
}
```

Все параметры агентов и агенты в отдельных файлах описаны в [руководстве по агентам](/agents).

### Снимки

Включает или отключает снимки файловой системы, на которых основаны отмена и откат изменений.

```jsonc
{
  "snapshots": false,
}
```

Об отмене и повторе изменений читайте в [руководстве по снимкам](/snapshots).

### Отслеживание файлов

Укажите файлы и каталоги, изменения которых не должны вызывать обновления файловой системы.

```jsonc
{
  "watcher": {
    "ignore": ["dist/**", "coverage/**"],
  },
}
```

### Форматтер

Форматирует файлы после того, как их изменили инструменты `write`, `edit` или `patch`. Задайте `formatter` значение
`true`, чтобы включить доступные встроенные форматтеры.

```jsonc
{
  "formatter": true,
}
```

О встроенных и собственных форматтерах читайте в [руководстве по форматтерам](/formatters).

### Медиафайлы

Определяет, как слишком большие изображения, загруженные инструментом `read`, уменьшаются или отклоняются перед
отправкой модели.

```jsonc
{
  "media": {
    "image": {
      "auto_resize": true,
      "max_width": 2000,
      "max_height": 2000,
      "max_base64_bytes": 5242880,
    },
  },
}
```

Об обработке изображений и ограничениях читайте в [руководстве по вложениям](/attachments).

### Вывод

Задает максимальное число строк и байтов, сохраняемых из результата инструмента.

```jsonc
{
  "tool_output": {
    "max_lines": 2000,
    "max_bytes": 51200,
  },
}
```

### Поиск

Выберите, как OpenCode ищет в интернете. Значение `"random"` автоматически выбирает доступный провайдер.

```jsonc
{
  "websearch": {
    "provider": "random",
  },
}
```

О провайдерах, учетных данных, выборе провайдера, ограничениях частоты запросов и отключении поиска читайте в
[руководстве по веб-поиску](/websearch).

### MCP

Настройка локальных и удаленных серверов Model Context Protocol. Глобальные тайм-ауты можно переопределить для
отдельного сервера.

```jsonc
{
  "mcp": {
    "servers": {
      "playwright": {
        "type": "local",
        "command": ["bunx", "@playwright/mcp"],
      },
    },
  },
}
```

Об удаленных серверах, OAuth, переменных окружения и тайм-аутах читайте в [руководстве по MCP](/mcp-servers).

### Сжатие контекста

Управляет автоматическим сжатием контекста и объемом сохраняемого недавнего контекста.

```jsonc
{
  "compaction": {
    "auto": true,
    "keep": {
      "tokens": 15000,
    },
    "buffer": 20000,
  },
}
```

По умолчанию по-прежнему используются локальные сводки. Чтобы включить нативное сжатие на стороне провайдера и для
автоматических, и для ручных запросов, задайте политику провайдера или модели:

```jsonc
{
  "providers": {
    "openai": {
      "settings": { "compaction": { "type": "native" } },
      "models": {
        "gpt-4.1": { "settings": { "compaction": { "type": "summary" } } },
      },
    },
  },
}
```

Настройка модели переопределяет настройку провайдера. Автоматическое сжатие использует доступный бюджет входных
токенов выбранной модели. Контрольные точки провайдера сохраняют недавние сообщения пользователя в пределах того же
бюджета `compaction.keep.tokens`, который локальные сводки используют для сохраняемого «хвоста». Значение
`compaction.auto: false` на верхнем уровне отключает новое автоматическое сжатие, не удаляя уже установленные
контрольные точки. О бюджете и восстановлении при переполнении читайте в [руководстве по сжатию контекста](/compaction).

### Прогрев

Поддерживает недавно активные сессии модели «прогретыми» с помощью периодических временных запросов. По умолчанию
прогрев отключен; задайте значение `true`, чтобы использовать четырехминутный интервал простоя и 30-минутное окно
активности.

```jsonc
{
  "warming": {
    "prompt": "Do not perform any work. Reply with exactly: OK",
    "interval": "4 minutes",
    "duration": "30 minutes",
  },
}
```

О поведении запросов, настройке и затратах читайте в [руководстве по прогреву](/warming).

### Навыки

Добавьте каталоги или URL, в которых OpenCode должен искать навыки агентов.

```jsonc
{
  "skills": ["./team-skills", "https://example.com/.well-known/skills/"],
}
```

О структуре навыков и их автоматическом обнаружении в `.opencode/skills/` читайте в [руководстве по навыкам](/skills).

### Команды

Определяйте повторно используемые slash-команды как именованные шаблоны промптов.

```jsonc
{
  "commands": {
    "review": {
      "description": "Review the current changes",
      "template": "Review the current diff for correctness and missing tests.",
    },
  },
}
```

Об аргументах, моделях, агентах и командах в отдельных файлах читайте в [руководстве по командам](/commands).

### Инструкции

Объявляет дополнительные файлы инструкций, glob-шаблоны или URL. OpenCode принимает это поле, но не загружает
его элементы; для инструкций используйте `AGENTS.md`.

```jsonc
{
  "instructions": ["CONTRIBUTING.md", "docs/guidelines/*.md"],
}
```

Об инструкциях проекта и `AGENTS.md` читайте в [руководстве по инструкциям](/instructions).

### Внешние каталоги

Делает локальные каталоги или Git-репозитории доступными как именованный вспомогательный контекст.

```jsonc
{
  "references": {
    "docs": {
      "path": "../product-docs",
      "description": "Product behavior and terminology",
    },
    "effect": {
      "repository": "Effect-TS/effect",
      "branch": "main",
    },
  },
}
```

О сокращенной записи, видимости и разрешении путей читайте в [руководстве по внешним каталогам](/references).

### Worktree

Задает родительский каталог для новых локальных worktree. OpenCode добавляет к нему запрошенное или сгенерированное
имя worktree.

```jsonc
{
  "worktree": {
    "directory": "../worktrees",
  },
}
```

Относительные пути разрешаются относительно сохраненной канонической рабочей копии проекта. Это относится и к
глобальной, и к проектной конфигурации; абсолютные пути используются как есть, а `~/` разрешается относительно
домашнего каталога пользователя.

Например, такая глобальная конфигурация размещает новые worktree в собственном каталоге `.lane/trees/` каждого проекта:

```jsonc
{
  "worktree": {
    "directory": ".lane/trees",
  },
}
```

Без этой настройки worktree создаются в каталоге данных сервера по пути
`worktree/<first-six-project-ID-characters>` (первые шесть символов ID проекта). Создание и обновление worktree
загружают конфигурацию из сохраненной канонической рабочей копии проекта, в том числе когда ID проекта общий для
нескольких клонов. Изменение настройки не перемещает существующие worktree.

По умолчанию встроенной стратегией является Git. [Плагин](/build/plugins#worktrees), регистрирующий стратегию,
автоматически становится стратегией по умолчанию в своей среде выполнения. Операции с проектом используют среду
выполнения канонической рабочей копии. Параметры конкретной стратегии относятся к этому плагину, а не к объекту
конфигурации `worktree`.

### Плагины

Загружает плагины из пакетов или локальных каталогов плагинов. Если плагин принимает параметры, используйте форму
объекта.

```jsonc
{
  "plugins": [
    "opencode-example-plugin",
    {
      "package": "./plugins/local",
      "options": {
        "enabled": true,
      },
    },
  ],
}
```

О загрузке и настройке плагинов читайте в [руководстве по плагинам](/plugins).

### Провайдеры

Настраивайте провайдеры, добавляйте или переопределяйте их модели, параметры запросов, заголовки и варианты моделей.

```jsonc
{
  "providers": {
    "openai": {
      "models": {
        "gpt-5.2-custom": {
          "modelID": "gpt-5.2",
          "name": "GPT-5.2 Custom",
          "limit": {
            "context": 200000,
            "output": 32000,
          },
        },
      },
    },
  },
}
```

Параметр провайдера `settings.transport: "websocket"` включает WebSocket-соединение для сессий.

Об учетных данных, собственных эндпоинтах, пакетах провайдеров, транспорте WebSocket и настройке моделей читайте в
[руководстве по провайдерам](/providers).
