title: "Модели"
---

Выберите модель для текущей сессии командой `/models`:

```text
/models
```

OpenCode берет список моделей из [models.dev](https://models.dev), интеграций с провайдерами и вашей конфигурации. В
списке выбора показываются только включенные модели, провайдер которых доступен в текущем проекте. Подключить
провайдеры можно в разделе [Провайдеры](/providers).

## Выбор

Выбирайте модель из списка `/models`, а не угадывайте ID провайдера или модели. Выбор действует для текущей сессии и не
меняет конфигурацию.

```text
anthropic/claude-sonnet-4-5
```

Доступность моделей зависит от проекта:

- Модель должна быть включена.
- Ее провайдер должен быть доступен в текущем проекте.
- Учетные данные и конфигурация из другого проекта автоматически не переносятся.

## Запуски

Чтобы выбрать модель для одного запуска из командной строки, не меняя модель по умолчанию в конфигурации, используйте
`--model`:

```bash
opencode run --model anthropic/claude-sonnet-4-5 "Refactor parseToken"
```

Агенты и команды тоже могут выбирать собственную модель. См. разделы [Агенты](/agents) и [Команды](/commands).

## Модель по умолчанию

Чтобы задать модель по умолчанию для новой работы, укажите `model` в `opencode.json` или `opencode.jsonc`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "anthropic/claude-sonnet-4-5",
}
```

Заданная модель становится моделью по умолчанию в каталоге, если она включена и ее провайдер доступен. Иначе OpenCode
использует самую новую доступную поддерживаемую модель.

- Модель, уже выбранная для сессии, имеет приоритет над моделью по умолчанию из конфигурации.
- Смена модели в сессии не перезаписывает файл конфигурации.
- Корневой параметр `model` пока сохраняет только провайдер и модель по умолчанию, но не вариант.

О расположении файлов конфигурации и приоритете читайте в разделе [Конфигурация](/config).

## Варианты

Варианты — это именованные наборы параметров для одной модели; чаще всего они задают уровень рассуждений (reasoning
effort) или бюджет токенов. Чтобы выбрать вариант для запуска, сессии, агента или команды, добавьте `#variant`:

```bash
opencode run --model openai/gpt-5.2#high "Review this migration plan"
```

Имена вариантов берутся из текущих метаданных каталога для выбранной модели. Имена вроде `low`, `high` и `max` есть не
у всех моделей, а неизвестный вариант вызывает ошибку разрешения модели.

Новые варианты, а также замены вариантов из каталога с тем же ID, задаются в массиве `variants` модели:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "models": {
        "gpt-5.2": {
          "settings": {
            "reasoningEffort": "medium",
          },
          "variants": [
            {
              "id": "fast",
              "settings": {
                "reasoningEffort": "low",
              },
            },
            {
              "id": "deep",
              "settings": {
                "reasoningEffort": "high",
                "reasoningSummary": "auto",
              },
            },
          ],
        },
      },
    },
  },
}
```

Каждый вариант может содержать `settings`, `headers` и `body`. Его значения применяются после значений провайдера и
модели.

## Параметры

Записи провайдеров и моделей могут настраивать запросы с помощью `settings`, `headers` и `body`:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "openai": {
      "settings": {
        "baseURL": "https://api.example.com/v1",
      },
      "headers": {
        "X-Team": "platform",
      },
      "models": {
        "gpt-5.2": {
          "settings": {
            "reasoningEffort": "high",
          },
          "body": {
            "store": false,
          },
        },
      },
    },
  },
}
```

| Поле       | Назначение                                                            |
| ---------- | --------------------------------------------------------------------- |
| `settings` | Параметры пакета провайдера, например `baseURL` или `reasoningEffort`. |
| `headers`  | Дополнительные заголовки HTTP-запроса.                                |
| `body`     | Поля тела запроса, специфичные для провайдера.                        |

OpenCode применяет сначала значения провайдера, затем значения модели и в последнюю очередь — выбранный вариант.

- Вложенные объекты `settings` и `body` объединяются.
- Более поздние массивы и скалярные значения заменяют более ранние.
- Имена заголовков сравниваются без учета регистра.
- Параметры специфичны для провайдера: пакет другого провайдера может их проигнорировать или отклонить.

## Псевдонимы

С помощью `modelID` можно дать модели API более удобный ID в каталоге:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "openai/coding-default",
  "providers": {
    "openai": {
      "models": {
        "coding-default": {
          "modelID": "gpt-5.2",
          "name": "Coding default",
          "capabilities": {
            "tools": true,
            "input": ["text", "image"],
            "output": ["text"],
          },
          "limit": {
            "context": 200000,
            "output": 32000,
          },
        },
      },
    },
  },
}
```

Здесь `openai/coding-default` — это ссылка, которую можно выбрать, а провайдеру отправляется `gpt-5.2`. Для модели,
которой еще нет в каталоге, OpenCode предполагает:

- поддержку инструментов, ввод текста и изображений, вывод текста;
- лимит контекста 200,000 токенов и лимит вывода 32,000 токенов;
- неопределенный лимит ввода.

Это резервные предположения, а не обнаруженные возможности. Если точные значения `capabilities` и `limit` известны,
задайте их — явные значения заменяют резервные. Чтобы скрыть модель из каталога доступных, добавьте `disabled: true`:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "openai": {
      "models": {
        "legacy-model": {
          "disabled": true,
        },
      },
    },
  },
}
```

## Рассуждения

Если OpenAI-совместимая модель передает рассуждения в потоке в нестандартном поле сообщения ассистента, задайте
`compatibility.reasoningField`:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "local": {
      "models": {
        "reasoner": {
          "compatibility": {
            "reasoningField": "reasoning_content",
          },
        },
      },
    },
  },
}
```

OpenCode распознает `reasoning`, `reasoning_content` и `reasoning_text`, а также принимает любую другую строку,
специфичную для провайдера. Он читает потоковые рассуждения из этого поля и восстанавливает поле, когда отправляет
модели предыдущие сообщения ассистента.

## Кэширование промптов

OpenCode автоматически расставляет точки кэширования промпта на маршрутах, где они заведомо нужны, например для
Anthropic. Когда модели Claude обслуживаются через OpenAI-совместимый прокси, например LiteLLM, OpenCode не может
определить, что им нужны точки `cache_control` в стиле Anthropic. Задайте `compatibility.cacheFormat` для этих моделей
Claude:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "litellm": {
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": { "baseURL": "https://litellm.example.com/v1" },
      "models": {
        "claude-sonnet-5": {
          "compatibility": { "cacheFormat": "anthropic" },
        },
        "claude-opus-5-5": {
          "compatibility": { "cacheFormat": "anthropic" },
        },
        // Other models on the same proxy cache automatically and need no setting.
        "gpt-6.1": {},
      },
    },
  },
}
```

После этого OpenCode помечает последнее определение инструмента, системный промпт и последнее сообщение меткой
`cache_control: { "type": "ephemeral" }`, при которой используется стандартное для эндпоинта время жизни кэша — пять
минут. Для моделей Alibaba Model Studio используйте `"alibaba"`: они принимают те же метки, но игнорируют их в
определениях инструментов. Если все модели провайдера принимают один и тот же формат, задайте
`compatibility.cacheFormat` на уровне провайдера.

## Локальные модели

OpenCode автоматически находит модели Ollama, LM Studio и vLLM по их стандартным локальным адресам. Любой
OpenAI-совместимый сервер также можно настроить вручную.

```text
ollama/gemma3:4b
lmstudio/google/gemma-4-26b-a4b
vllm/Qwen/Qwen3-Coder-30B-A3B-Instruct
```

### Ollama

Если Ollama слушает `http://127.0.0.1:11434`, выберите найденную модель с ID провайдера `ollama`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "ollama/gemma3:4b",
}
```

OpenCode обновляет список моделей в фоне и получает от Ollama сведения о контексте, поддержке изображений и вызове
инструментов. Модели, предназначенные только для эмбеддингов, исключаются.

Для другого хоста или порта укажите OpenAI-совместимый URL Ollama. Для обнаружения по-прежнему используется нативный
API Ollama с тем же префиксом пути:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "ollama": {
      "settings": {
        "baseURL": "http://127.0.0.1:5678/v1",
        "apiKey": "{env:OLLAMA_API_KEY}",
      },
    },
  },
}
```

- Если эндпоинт не требует bearer-аутентификации, не указывайте `apiKey`.
- Отключить обнаружение можно с помощью `"plugins": ["-opencode.provider.ollama"]`.

### LM Studio

Если сервер LM Studio без аутентификации работает на `http://127.0.0.1:1234`, выберите найденную модель с ID провайдера
`lmstudio`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "lmstudio/google/gemma-4-26b-a4b",
}
```

OpenCode обновляет список моделей в фоне и получает от LM Studio сведения о контексте, поддержке изображений и вызове
инструментов. Модели эмбеддингов исключаются.

Для другого хоста или порта укажите OpenAI-совместимый URL. Модели по-прежнему обнаруживаются автоматически:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "lmstudio": {
      "settings": {
        "baseURL": "http://127.0.0.1:5678/v1",
        "apiKey": "{env:LMSTUDIO_API_KEY}",
      },
    },
  },
}
```

- Если аутентификация в LM Studio отключена, не указывайте `apiKey`.
- Отключить обнаружение можно с помощью `"plugins": ["-opencode.provider.lmstudio"]`.

### vLLM

Если vLLM слушает `http://127.0.0.1:8000`, выберите найденную модель с ID провайдера `vllm`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "vllm/Qwen/Qwen3-Coder-30B-A3B-Instruct",
}
```

OpenCode проверяет `/health`, обновляет `/v1/models` в фоне, использует указанный сервером `max_model_len` как лимит
контекста и учитывает только карточки моделей, владельцем которых указан `vllm`.

Найденные модели заявляют ввод и вывод текста, но не поддержку изображений и инструментов. Вызов инструментов в vLLM
включается флагами сервера, например `--enable-auto-tool-choice` и `--tool-call-parser`, а при обнаружении эти флаги
не сообщаются.

Для другого эндпоинта или сервера с аутентификацией укажите его OpenAI-совместимый URL:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "vllm": {
      "settings": {
        "baseURL": "http://127.0.0.1:9000/v1",
        "apiKey": "{env:VLLM_API_KEY}",
      },
    },
  },
}
```

- Если аутентификация отключена, не указывайте `apiKey`.
- Отключить обнаружение можно с помощью `"plugins": ["-opencode.provider.vllm"]`.
- Поддерживаются прокси с префиксом пути. Например, для `https://example.com/vllm/v1` проверяется `/vllm/health`, а
  модели запрашиваются из `/vllm/v1/models`.

### Совместимые серверы

Для другого OpenAI-совместимого сервера укажите пакет провайдера, эндпоинт и хотя бы одну модель:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "local/coder",
  "providers": {
    "local": {
      "name": "Local server",
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "http://127.0.0.1:1234/v1",
      },
      "models": {
        "coder": {
          "modelID": "model-name-on-server",
          "capabilities": {
            "tools": true,
            "input": ["text"],
            "output": ["text"],
          },
          "limit": {
            "context": 32768,
            "output": 8192,
          },
        },
      },
    },
  },
}
```

Указывайте реальное имя модели на сервере, лимиты, типы ввода и вывода и поддержку инструментов. OpenCode не может
проверить, верны ли резервные значения для собственной модели. Если эндпоинт требует ключ, добавьте `apiKey` в
`settings` с подстановкой переменной окружения, например `"apiKey": "{env:LOCAL_API_KEY}"`; не коммитьте секреты.

## Ссылки на модели

Селекторы моделей используют формат `provider/model` с необязательным `#variant`:

```text
openai/gpt-5.2
openai/gpt-5.2#high
openrouter/anthropic/claude-sonnet-4.5#high
```

| Часть      | Правило                                                          |
| ---------- | ---------------------------------------------------------------- |
| Провайдер  | Заканчивается на первом `/`; не может содержать `/` или `#`.     |
| Модель     | Может содержать дополнительные символы `/`; не может содержать `#`. |
| Вариант    | Следует после `#`, если указан.                                  |
| Регистр    | ID провайдера и модели чувствительны к регистру.                 |

Используйте ID из каталога, а не отображаемые имена провайдеров. Поля `model` в корне конфигурации, в агентах и
командах принимают строку в указанном формате или развернутый объект:

```jsonc
{
  "model": {
    "providerID": "openrouter",
    "model": "anthropic/claude-sonnet-4.5",
  },
}
```

Развернутая форма удобна для сгенерированной или программно создаваемой конфигурации.

## Особенности

При настройке моделей учитывайте следующие правила:

```jsonc
{
  "model": "openai/gpt-5.2"
}
```

- Объект селектора использует `model`, а запись в каталоге провайдера — `modelID` для ID, который отправляется
  провайдеру.
- Хотя корневой селектор принимает вариант, модель по умолчанию в каталоге V2 его не сохраняет. Выбирайте варианты для
  сессии, запуска, агента или команды.
- Параметры моделей специфичны для провайдера. Пакет другого провайдера может их проигнорировать или отклонить.
- Данные каталога, учетные данные и конфигурация привязаны к расположению. Модель, доступная в одном проекте, может быть
  недоступна в другом.
- Файлы конфигурации обычно перезагружаются автоматически. Запрос к модели, который уже выполняется, использует
  настройки, с которыми он был запущен.
