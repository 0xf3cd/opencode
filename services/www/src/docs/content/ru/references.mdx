---
title: "Внешние каталоги"
---

Внешние каталоги дают OpenCode именованный доступ к каталогам за пределами текущего проекта. Добавьте каталог в
`opencode.json` или `opencode.jsonc`, а затем, когда он понадобится, прикрепите его псевдоним в клиенте.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "references": {
    "docs": {
      "path": "../product-docs",
      "description": "Use for product behavior and terminology",
    },
  },
}
```

Прикрепив `docs`, попросите агента изучить нужный путь:

```text
Read the attached docs reference and summarize api/authentication.md.
```

Внешние каталоги удобны для документации, общих библиотек, примеров или исходного кода из другого репозитория.

## Локальные каталоги

Для локального каталога используйте `path`:

```jsonc
{
  "references": {
    "design-system": {
      "path": "../design-system",
      "description": "Use when working with components or design tokens",
    },
  },
}
```

Пути обрабатываются так:

- Относительные пути отсчитываются от каталога, в котором находится файл конфигурации.
- Поддерживаются абсолютные пути.
- Поддерживаются пути относительно домашнего каталога, например `~/docs`.

Если другие поля не нужны, используйте сокращенную запись строкой:

```jsonc
{
  "references": {
    "docs": "../docs",
    "shared": "~/work/shared",
  },
}
```

<Callout type="note">
  Строка в сокращенной записи считается локальным путем, только если начинается с `.`, `/` или `~`. Пишите `./docs`, а
  не `docs`: значение `docs` без префикса интерпретируется как Git-репозиторий.
</Callout>

## Git

Для удаленного Git-репозитория используйте `repository`:

```jsonc
{
  "references": {
    "effect": {
      "repository": "Effect-TS/effect",
      "branch": "main",
    },
    "internal-sdk": {
      "repository": "git@gitlab.example.com:platform/sdk.git",
      "branch": "release/v2",
    },
  },
}
```

Поддерживаются следующие формы адреса:

- сокращение GitHub `owner/repo`;
- Git URL;
- формы вида «хост/путь»;
- адреса в стиле SCP.

Локальные репозитории `file:` не поддерживаются.

Чтобы следить за веткой по умолчанию удаленного репозитория, используйте сокращенную запись строкой:

```jsonc
{
  "references": {
    "effect": "Effect-TS/effect",
    "sdk": "gitlab.com/platform/sdk",
  },
}
```

Без `branch` OpenCode получает и обновляет ветку по умолчанию удаленного репозитория. Имена веток могут содержать буквы,
цифры, `/`, `_`, `.` и `-`, но не могут начинаться с `-` или содержать `..`.

```jsonc
{
  "references": {
    "sdk": {
      "repository": "example/sdk",
      "branch": "release/v2.1",
    },
  },
}
```

## Хранение

OpenCode нормализует адрес каждого удаленного репозитория и хранит по одной рабочей копии на каждую пару «репозиторий —
ветка» в своем глобальном каталоге данных. Если ветка не указана явно, путь имеет такой вид:

```text
opencode/repos/<host>/<repository-path>
```

При типичной установке в Linux `Effect-TS/effect` хранится здесь:

```text
~/.local/share/opencode/repos/github.com/Effect-TS/effect
```

Явно указанная ветка добавляет закодированный суффикс `@<branch>`:

```text
~/.local/share/opencode/repos/github.com/Effect-TS/effect@main
```

## Обновление

Отсутствующие репозитории клонируются асинхронно. Существующие рабочие копии проверяются в фоне при загрузке или
перезагрузке внешних каталогов, а также после того, как в их расположении (Location) принят новый промпт пользователя.

```text
Prompt admitted → refresh check starts in background → agent continues
```

Рабочая копия подлежит обновлению, если последняя попытка обновления была не менее 24 часов назад или попыток еще не
было. При обновлении выполняется fetch и сброс к указанной ветке или к ветке по умолчанию удаленного репозитория.

```text
Last attempt: 25 hours ago → eligible
Last attempt: 2 hours ago  → skipped
```

Обновление работает по следующим правилам:

- Отметки времени сохраняются между перезапусками сервиса.
- Расположения, использующие одну рабочую копию, используют общую отметку времени.
- Неудачные попытки записываются в журнал, и на них тоже распространяется 24-часовой интервал.
- Пока расположение не используется, периодического опроса нет.
- Ошибки клонирования или обновления не мешают загрузке других внешних каталогов.

Промпты не ждут завершения клонирования или обновления. Вложение может содержать устаревшее содержимое, даже если
последующее чтение инструментом уже видит обновленную копию, а новый внешний каталог может появиться раньше, чем его
рабочая копия будет готова.

```text
Attachment created → cached content
Background refresh completes → later tool read sees newer content
```

<Callout type="warning">
  Кэшированные рабочие копии общие и могут обновиться, пока агент с ними работает. Не редактируйте их: обновление
  сбрасывает все изменения.
</Callout>

## Подсказки для агентов

`description` сообщает агентам, когда внешний каталог полезен. Каталоги с описанием попадают в инструкции агента вместе
с псевдонимом и полным путем.

```jsonc
{
  "references": {
    "docs": {
      "path": "../docs",
      "description": "Use for product behavior and terminology",
    },
  },
}
```

Каталоги без описания остаются доступны клиентам, но агентам автоматически не предлагаются.

```jsonc
{
  "references": {
    "archive": {
      "path": "../archive",
    },
  },
}
```

## Видимость

Задайте `hidden: true`, чтобы убрать внешний каталог из интерактивных списков выбора в клиентах:

```jsonc
{
  "references": {
    "internal": {
      "path": "../internal",
      "description": "Use for internal service behavior",
      "hidden": true,
    },
  },
}
```

`hidden` влияет только на видимость в интерактивном интерфейсе. Каталог остается в API внешних каталогов, а если у него
есть описание, — и в инструкциях агента.

## Использование

Клиенты прикрепляют внешний каталог по псевдониму корня. Вложение содержит нерекурсивный список файлов и каталогов,
находящихся непосредственно в корне.

```text
Attached alias: docs
Ask: Inspect docs/guides/deployment.md and explain the deployment steps.
```

Если нужно содержимое глубже корня, попросите агента изучить конкретный путь.

## Разрешения

Внешние каталоги не дают инструментам дополнительных разрешений. Доступ за пределами активного расположения по-прежнему
подчиняется обычным правилам инструментов и разрешению `external_directory`; для редактирования также нужно
соответствующее разрешение на редактирование.

```text
Read ../product-docs/api.md
```

Запрос выполнится, только если активные разрешения допускают такое чтение внешнего каталога.

## Поля

| Поле          | Локальный      | Git            | Описание                                      |
| ------------- | -------------- | -------------- | --------------------------------------------- |
| `path`        | Обязательно    | Нет            | Путь к локальному каталогу                    |
| `repository`  | Нет            | Обязательно    | Удаленный Git-репозиторий                     |
| `branch`      | Нет            | Необязательно  | Ветка для получения и checkout                |
| `description` | Необязательно  | Необязательно  | Подсказка, когда агентам стоит его использовать |
| `hidden`      | Необязательно  | Необязательно  | Скрыть из интерактивных списков выбора в клиентах |

Полная запись Git может использовать все поля, совместимые с Git:

```jsonc
{
  "references": {
    "sdk": {
      "repository": "example/sdk",
      "branch": "main",
      "description": "Use for SDK implementation details",
      "hidden": false,
    },
  },
}
```

## Псевдонимы

Псевдоним не может быть пустым или содержать `/`, `\`, пробельные символы, обратную кавычку или запятую.

```text
Valid:   docs
Invalid: product docs
Invalid: docs/api
```
