Подключите провайдера в TUI, а затем выберите одну из его моделей:

```text
/connect
/models
```

`/connect` показывает интеграции, доступные на текущем сервере и в текущем проекте. Выберите провайдера, укажите способ
аутентификации, если их несколько, и следуйте подсказкам.

## TUI

TUI поддерживает API-ключи, OAuth и команды аутентификации провайдеров. При OAuth открывается URL авторизации или
показывается код для ввода; нажмите `o`, чтобы открыть URL, или `c`, чтобы скопировать данные авторизации.

```text
/connect
# Select OpenAI, then Codex device code (legacy).
```

Чтобы добавить еще один аккаунт, снова выполните `/connect`. Если выбрать уже подключенного провайдера, откроется список
его аккаунтов: сохраненный аккаунт можно сделать активным, переименовать или удалить.

## CLI

Команда `auth login` предлагает те же способы аутентификации без запуска TUI. Если провайдер не указан, команда
открывает интерактивный выбор провайдера.

```bash
opencode auth login
```

Передайте ID или название интеграции, чтобы пропустить первый шаг выбора. Флаг `--method key` явно выбирает ввод
API-ключа.

```bash
opencode auth login anthropic --method key
```

ID способов зависят от провайдера. Чтобы увидеть доступные способы, если их несколько, выполните команду без `--method`.

```bash
opencode auth login openai
```

Для ввода API-ключа и заполнения форм провайдера нужен интерактивный терминал. Он также нужен для способов OAuth, при
которых требуется вставить код авторизации.

## Способы

OpenCode получает учетные данные провайдеров четырьмя способами интеграции:

| Способ | Поведение |
| --- | --- |
| API-ключ | Запрашивает секрет и сохраняет его как аккаунт провайдера. |
| OAuth | Предоставляет URL для браузера, код устройства или запрос кода авторизации, затем сохраняет токены и обновляет их, если это поддерживается. |
| Команда | Выполняет команду аутентификации, предоставленную провайдером, и сохраняет ее стандартный вывод как ключ. |
| Окружение | Читает поддерживаемую переменную из окружения процесса сервера, не сохраняя ее. |

Провайдеры могут добавлять к способам «API-ключ» и OAuth формы для обязательных данных, например имени ресурса Azure или
домена GitHub Enterprise. CLI и TUI показывают эти формы перед началом аутентификации.

## Окружение

Задайте поддерживаемую провайдером переменную окружения для процесса сервера, который выполняет запросы к модели. Для
разового приватного сервера передайте ее при запуске в автономном режиме.

```bash
ANTHROPIC_API_KEY=sk-ant-... opencode --standalone
```

Для общего фонового сервера добавьте переменную в его управляемое окружение. Запущенный сервис при этом остановится;
следующая команда OpenCode запустит его уже с новым значением.

```bash
opencode service set env ANTHROPIC_API_KEY sk-ant-...
opencode auth list
```

Подключения через окружение отображаются в `auth list` с типом `environment`. Это не аккаунты: `auth logout` не может
их удалить, поэтому для отключения удалите переменную. Сохраненный аккаунт имеет приоритет над подключением через
окружение для той же интеграции.

```bash
opencode auth list
opencode service unset env ANTHROPIC_API_KEY
```

Некоторые облачные провайдеры вместо переменной с API-ключом используют собственную цепочку учетных данных из
окружения:

- Amazon Bedrock поддерживает стандартную цепочку учетных данных AWS, включая профили, ключи доступа в переменных
  окружения, web identity и учетные данные контейнера. Также поддерживается `AWS_BEARER_TOKEN_BEDROCK`.
- Google Vertex использует Application Default Credentials и проект, который удается определить. Например,
  выполните аутентификацию командой `gcloud auth application-default login` и задайте `GOOGLE_CLOUD_PROJECT`.
- Azure предлагает способ подключения **Microsoft Entra ID (Azure CLI)**, если установлен `az`. Сначала выполните
  `az login`, затем выберите этот способ в `/connect` или в `auth login azure`.

```bash
gcloud auth application-default login
GOOGLE_CLOUD_PROJECT=my-project opencode
```

Настройка отдельных провайдеров и серверная настройка описаны в разделе [Провайдеры](/providers).

## Аккаунты

Каждый успешный вход через API-ключ, OAuth или команду создает сохраненный аккаунт. Активным становится самый новый
аккаунт; переключить активный аккаунт можно по его метке или ID учетных данных.

```bash
opencode auth list
opencode auth switch anthropic work
```

Удалить сохраненный аккаунт можно командой `auth logout`. Если аргументы не указаны, обе команды открывают меню выбора.

```bash
opencode auth logout anthropic work
```

В TUI команда `/connect` позволяет так же добавлять, активировать, переименовывать и удалять сохраненные аккаунты.

## Хранение

Сохраненные API-ключи и OAuth-токены хранятся в базе данных SQLite на сервере. Путь к базе данных локального сервера
можно вывести командой:

```bash
opencode debug paths db
```

Обычно для релизной версии это `~/.local/share/opencode/opencode.db`; путь может изменяться в зависимости от
`XDG_DATA_HOME`, канала релиза и `OPENCODE_DB`. Не редактируйте базу данных вручную, чтобы управлять учетными данными, —
используйте `/connect` или команды `auth`.

При миграции базы данных V2 импортирует поддерживаемые учетные данные из устаревшего файла `auth.json` в каталоге данных
OpenCode. Новые и обновленные учетные данные сохраняются в SQLite и обратно в этот файл не записываются.
