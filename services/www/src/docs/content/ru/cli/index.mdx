Чтобы открыть полноэкранный терминальный интерфейс, запустите CLI в каталоге проекта:

```bash
opencode
```

Чтобы работать с другим проектом, передайте путь к его каталогу:

```bash
opencode ~/code/my-project
```

Рекомендуемые терминалы:

- [Ghostty](https://ghostty.org)
- [WezTerm](https://wezterm.org)
- [Alacritty](https://alacritty.org)
- [Kitty](https://sw.kovidgoyal.net/kitty/)

С поддержкой truecolor темы отображаются с максимально точными цветами; в терминалах без нее цвета приближаются к
доступной палитре.

## Автоматизация

Команда `opencode run` отправляет промпт без запуска интерактивного интерфейса. Она предназначена для скриптов, CI-задач
и других сценариев, где ответ модели нужен прямо в терминале.

```bash
opencode run "Explain this repository"
```

## Mini

Команда `opencode mini` запускает минималистичный интерактивный интерфейс OpenCode вместо полноэкранного TUI.

```bash
opencode mini
```

Параметры сессии, модели, агента, промпта и воспроизведения можно посмотреть командой `opencode mini --help`.

## Фоновый сервис

По умолчанию OpenCode находит или запускает один общий фоновый сервер для вашей учетной записи пользователя. К нему
подключаются все локальные клиенты OpenCode, а сам сервер управляет сессиями, конфигурацией, интеграциями,
разрешениями и выполнением инструментов.

Флаг `--standalone` запускает OpenCode с отдельным приватным сервером, а `--server` подключает к серверу по указанному URL:

```bash
opencode --standalone
opencode --server http://localhost:4096
```

Чтобы команды CLI по умолчанию запускали приватный сервер, а не общий сервис, отключите общий сервис:

```bash
opencode service set disabled true
opencode
```

Эта команда останавливает запущенный фоновый сервис. Флаг `--server` по-прежнему подключает к явно указанному серверу, а
`opencode service start` по-прежнему может явно запустить общий сервис. Чтобы вернуть автоматическое использование
сервиса, выполните `opencode service unset disabled`. Сопряжение (pairing) работает только через общий сервис и
недоступно, пока он отключен.

Диагностика общего сервиса описана в разделе [Устранение неполадок](/troubleshooting), а эндпоинты сервера — в
[справочнике API](/api).

## Пути

Выведите нужный локальный путь, чтобы передать его другим инструментам:

```bash
opencode debug paths db
sqlite3 "$(opencode debug paths db)"
```

Необязательный селектор принимает значения `db`, `home`, `data`, `config`, `cache`, `state`, `tmp`, `bin`, `log` или
`repos`; команда выводит только путь и перевод строки. Путь к базе данных учитывает канал релиза и `OPENCODE_DB`:
относительные пути из переопределения разрешаются относительно каталога данных, а `:memory:` выводится как есть. Команда
не запускает сервер и не открывает базу данных.

Без селектора команда выводит все пути с подписями:

```bash
opencode debug paths
```

## Удаление

Посмотрите, какие файлы и установка будут удалены:

```bash
opencode uninstall --dry-run
```

Чтобы подтвердить удаление, выполните `opencode uninstall`. Перед удалением глобального каталога кеша, общего для всех
версий и каналов OpenCode, команда останавливает зарегистрированные фоновые сервисы и постоянные терминалы. Данные
сессий, конфигурация и состояние никогда не удаляются.

- `--force` (`-f`) пропускает подтверждение; используйте его для неинтерактивного удаления.
- Установки через пакетный менеджер удаляются найденным пакетным менеджером. Для установок через curl выводится
  итоговая команда, чтобы удалить исполняемый файл вручную.
