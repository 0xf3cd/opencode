---
title: "Сжатие контекста"
---

Сжатие контекста освобождает место в длинной сессии: старая часть переписки заменяется сводкой, и сессия может
продолжаться дальше лимита контекста модели.

## Как это работает

Когда сессия приближается к лимиту контекста модели, OpenCode составляет сводку всего, кроме самой свежей части
переписки (по умолчанию около 15 000 токенов). Готовая сводка помещается перед этой свежей частью, и сессия продолжается
с этого места.

```text
before   [ system prompt ][ older conversation ............ ][ recent 15k ][ pending work ]
after    [ system prompt ][ summary ][ recent 15k ][ pending work ]
```

Модель воспринимает сводку как прошлую часть переписки. При последующих сжатиях обновляется та же сводка, а не
создается новая.

## Запуск

Автоматическое сжатие включено по умолчанию:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "compaction": {
    "auto": true,
    "keep": { "tokens": 15000 },
  },
}
```

Сжатие происходит с потерями. Если важны точные недавние детали, увеличьте `keep.tokens` или запустите сжатие сами,
не дожидаясь автоматического.

## Ручной запуск

Запросить сжатие можно в любой момент, даже если история короткая:

```sh
opencode api post /api/session/ses_example/compact --data '{}'
```

Команда `api` сама находит фоновый сервис и проходит аутентификацию. Ответ подтверждает, что запрос принят, но не ждет
готовности сводки. Чтобы узнать о завершении, отслеживайте события `session.compaction.*`. Полное описание операции —
в [справочнике по API](/api).

| Правило | Поведение |
| --- | --- |
| Время | Выполняется в следующей безопасной точке, раньше промптов, которые еще ожидают в очереди. |
| Повторы | Запросы, отправленные, пока один уже ожидает выполнения, объединяются с ним. |
| Автоматизация | Работает, даже если `compaction.auto` равен `false`. |

Передайте `id`, чтобы точный повтор запроса был идемпотентным. Повторное использование того же ID для другого запроса
возвращает конфликт.

```sh
opencode api post /api/session/ses_example/compact --data '{"id":"msg_compact_once"}'
```

## Настройки

Добавьте `compaction` в любой [файл конфигурации OpenCode](/config):

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "compaction": {
    "auto": false,
    "keep": { "tokens": 24000 },
    "buffer": 16000,
  },
}
```

| Поле | По умолчанию | Поведение |
| --- | ---: | --- |
| `auto` | `true` | Автоматически сжимать контекст вблизи лимита и один раз восстанавливаться, если провайдер отклоняет запрос как слишком длинный. Ручное сжатие работает всегда. |
| `keep.tokens` | `15000` | Примерный объем свежей переписки, сохраняемой рядом со сводкой. Большие значения сохраняют больше деталей, но оставляют меньше места для новой работы. |
| `buffer` | 10% лимита | Количество токенов, которое нужно оставлять свободным ниже лимита модели. Чем больше значение, тем раньше запускается автоматическое сжатие. |

`keep.tokens` и `buffer` принимают неотрицательные целые числа.

## Провайдеры

По умолчанию OpenCode составляет сводку сам, используя модель сессии. Некоторые провайдеры могут сжимать переписку на
своей стороне. Это включается для провайдера или модели параметром `settings.compaction`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "settings": { "compaction": { "type": "native" } },
      "models": {
        "gpt-4.1": { "settings": { "compaction": { "type": "summary" } } },
      },
    },
  },
}
```

Настройка модели переопределяет настройку провайдера. `native` использует сжатие провайдера, `summary` — собственное
сжатие OpenCode.

При нативном сжатии OpenCode отправляет переписку на эндпоинт сжатия провайдера. Провайдер возвращает непрозрачный
зашифрованный элемент, который заменяет старую часть переписки. Рядом с ним сохраняются ваши недавние сообщения и
вложения в пределах `keep.tokens`:

```text
before   [ older conversation ........................ ][ recent user messages ]
after    [ encrypted checkpoint + recent user messages ]
```

| Тема | Поведение |
| --- | --- |
| Поддержка | Модели OpenAI Responses. Поддержка зависит от развертывания и модели. |
| Порог | Те же параметры `auto` и `buffer`, что и для сжатия через сводку. Ручные запросы тоже работают. |
| Переносимость | Зашифрованная контрольная точка работает только с тем же провайдером, моделью и эндпоинтом. Если сменить модель, сессия продолжится с исходной переписки. |
| Слишком длинный запрос | Если провайдер отклоняет сжатие как слишком длинное, OpenCode повторяет его с меньшим запросом. На сводку он не переключается. |

## Сводки

Сводка структурирована так, чтобы другой агент мог по ней продолжить работу:

```md
## Objective
Finish the authentication migration.

## Next Move
- Update the callback handler.
- Verify the login flow.
```

В ней описываются цель и требования, принятые решения, завершенная и текущая работа, блокеры и следующие шаги, а также
важные файлы. В сохраняемой рядом с ней свежей части переписки длинный вывод инструментов сокращается, а данные вложений
заменяются коротким описанием.

После сжатия текущие версии ваших файлов инструкций становятся базовыми для сессии; см. [Инструкции](/instructions).

## Ограничения

| Ограничение | Результат |
| --- | --- |
| Модель | Сжатие использует модель сессии. Отдельной модели для сжатия нет. |
| История | Для сжатия нужна старая часть переписки, которую можно заменить. Оно не освободит место, если запрос в основном состоит из неизменных инструкций и схем инструментов. |
| Размер | Если сжимаемая переписка сама слишком длинная, OpenCode отправляет сокращенную текстовую версию и может опустить самые старые обмены сообщениями. |
| Восстановление | Запрос, отклоненный как слишком длинный, сжимается и повторяется один раз. Повторный отказ возвращается как ошибка. |
| Хранение | Более ранние сообщения остаются сохраненными, даже если больше не отправляются модели. |

Например, здесь сжатие не поможет:

```text
128k context = 120k fixed instructions and tools + 8k conversation
```

## Миграция

В V1 использовались сохранение последних ходов (tail turns) и отсечение (pruning). В V2 используются сводки и
`compaction.keep.tokens`:

```jsonc
{
  "compaction": {
    "keep": { "tokens": 15000 }
  }
}
```

Настройки и поведение, описанные на этой странице, относятся к V2.
