---
title: "Разрешения"
---

Разрешения определяют, может ли агент выполнить действие над ресурсом.

## Настройка

Типичная настройка: спрашивать перед запуском команд оболочки, разрешать обычные команды просмотра Git и всегда
запрещать push. Добавьте эти правила в указанном порядке в `opencode.jsonc`:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "permissions": [
    { "action": "shell", "resource": "*", "effect": "ask" },
    { "action": "shell", "resource": "git status *", "effect": "allow" },
    { "action": "shell", "resource": "git diff *", "effect": "allow" },
    { "action": "shell", "resource": "git push *", "effect": "deny" },
  ],
}
```

Действует последнее совпавшее правило, поэтому конкретные исключения идут после общего правила.

<Callout type="warning">
  В V1 используются другие имена полей и действий. В V2 пишите `permissions`, `shell` и `subagent` вместо `permission`,
  `bash` и `task`.
</Callout>

## Правила

Каждое правило содержит три обязательных строковых поля:

| Поле       | Значение                                                                   |
| ---------- | -------------------------------------------------------------------------- |
| `action`   | Действие разрешения инструмента                                            |
| `resource` | Используемое значение: путь, команда, URL, запрос, ID навыка или ID агента |
| `effect`   | `allow`, `deny` или `ask`                                                  |

```jsonc
{
  "permissions": [
    { "action": "read", "resource": "*", "effect": "allow" },
    { "action": "read", "resource": "*.env", "effect": "deny" },
  ],
}
```

| Эффект  | Результат                           |
| ------- | ----------------------------------- |
| `allow` | Продолжить без запроса              |
| `deny`  | Заблокировать операцию              |
| `ask`   | Дождаться решения от клиента        |

Если ни одно правило не совпало, OpenCode использует `ask`.

## Сопоставление

Действия и ресурсы сопоставляются с простыми шаблонами, которые применяются ко всему значению целиком:

| Шаблон  | Совпадает с                                |
| ------- | ------------------------------------------ |
| `*`     | Ноль или более символов, включая `/`       |
| `?`     | Ровно один символ                          |
| Другое  | Сам этот символ                            |

```jsonc
{
  "permissions": [
    { "action": "edit", "resource": "packages/docs/*.mdx", "effect": "allow" },
  ],
}
```

Этот шаблон сопоставляется со всем нормализованным путем. Обратные слеши заменяются на прямые, а в Windows
сопоставление не учитывает регистр.

Шаблон для оболочки, оканчивающийся на ` *`, совпадает и с командой без аргументов:

```jsonc
{ "action": "shell", "resource": "git status *", "effect": "allow" }
```

Он совпадает и с `git status`, и с `git status --short`.

OpenCode объединяет правила по порядку и использует последнее совпадение. Сначала загружается конфигурация с более
низким приоритетом, затем добавляются глобальные правила, а в самом конце — правила агента.

```jsonc
{
  "permissions": [
    { "action": "read", "resource": "*", "effect": "allow" },
    { "action": "read", "resource": "secrets/*", "effect": "deny" },
  ],
}
```

Операция может проверять несколько ресурсов — например, патч, затрагивающий несколько файлов. Любой `deny` запрещает
операцию; иначе любой `ask` приводит к запросу; в остальных случаях операция разрешается.

## Действия

В V2 имена действий — это строки, поэтому плагины могут определять собственные действия. Встроенные инструменты сейчас
используют такие действия и ресурсы:

| Действие             | Ресурс                                                                      |
| -------------------- | --------------------------------------------------------------------------- |
| `read`               | Внутренний путь относительно расположения (Location) или канонический абсолютный внешний путь |
| `edit`               | Целевой путь для `edit`, `write` и `patch`                                  |
| `glob`               | Запрошенный glob-шаблон                                                     |
| `grep`               | Запрошенное регулярное выражение, а не путь поиска                          |
| `shell`              | Строка команды, выделенная сканером; составные команды могут дать несколько |
| `subagent`           | ID целевого агента                                                          |
| `skill`              | ID навыка                                                                   |
| `question`           | `*`                                                                         |
| `webfetch`           | Запрошенный URL                                                             |
| `websearch`          | Поисковый запрос                                                            |
| `external_directory` | Каноническая граница внешнего каталога, обычно оканчивается на `/*`         |
| `<server>_<tool>`    | `*` для MCP-инструмента; неподдерживаемые символы в обоих именах заменяются на `_` |
| `execute`            | `*`; определяет доступность Code Mode, а вложенные инструменты применяют свои правила |

Например, можно разрешить один навык и запретить все остальные:

```jsonc
{
  "permissions": [
    { "action": "skill", "resource": "*", "effect": "deny" },
    { "action": "skill", "resource": "effect", "effect": "allow" },
  ],
}
```

`doom_loop` и `lsp` не являются действиями разрешений в текущем V2 Core.

## Каталоги

Для пути за пределами и активного расположения, и некорневого worktree его проекта нужно подтверждение
`external_directory`, прежде чем будет проверено подтверждение `read` или `edit`.

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "permissions": [
    { "action": "external_directory", "resource": "~/projects/reference/*", "effect": "allow" },
    { "action": "read", "resource": "~/projects/reference/*", "effect": "allow" },
    { "action": "edit", "resource": "~/projects/reference/*", "effect": "deny" },
  ],
}
```

Это относится к внешним путям, которые используют `read`, `edit`, `write` и `patch`. Перед проверкой ресурсов `shell`
оболочка проверяет свой внешний рабочий каталог и каталоги, выведенные сканером.

Для `external_directory`, `read` и `edit` начальные `~`, `~/`, `$HOME` или `$HOME/` раскрываются при загрузке
конфигурации:

```jsonc
{ "action": "read", "resource": "$HOME/reference/*", "effect": "allow" }
```

Ресурсы `shell` остаются исходным текстом команды, и домашний каталог в них не раскрывается.

<Callout type="warning">
  `shell` работает с правами пользователя хоста на файловую систему, процессы и сеть. Каталоги определяются по тексту
  команды без гарантии точности, поэтому лучше использовать узкий список разрешенных команд, чем шаблоны,
  которые пытаются распознать каждую опасную команду.
</Callout>

Относительные пути, по которым вносятся изменения, могут выходить за пределы активного расположения, оставаясь внутри
worktree его проекта. Явно указанные внешние пути перед сопоставлением приводятся к каноническому виду, поэтому
разрешайте только доверенные границы каталогов.

## Сканер

Экспериментальный переносимый сканер команд оболочки включается так:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "experimental": {
    "portable_shell_scanner": true,
  },
}
```

Переносимый сканер заменяет сканер по умолчанию на основе tree-sitter; tree-sitter не используется ни как резервный
вариант, ни для повторной проверки. Если переносимый сканер не может разобрать команду, возвращается ошибка сканера, а
не отказ в разрешении.

Флаг меняет только выбор парсера. Существующие правила разрешений, сохраненные шаблоны подтверждений и определение
каталогов без гарантии точности продолжают действовать. Дополнительного режима подтверждения или общего запрета для
неизвестных каталогов нет.

## Значения по умолчанию

Каждый агент, включая пользовательских, начинает с такой упорядоченной базовой политики:

```jsonc
[
  { "action": "*", "resource": "*", "effect": "allow" },
  { "action": "external_directory", "resource": "*", "effect": "ask" },
  { "action": "read", "resource": "*.env", "effect": "ask" },
  { "action": "read", "resource": "*.env.*", "effect": "ask" },
  { "action": "read", "resource": "*.env.example", "effect": "allow" },
]
```

Встроенные агенты добавляют к ней свои правила:

| Агент        | Дополнительные правила                                                         |
| ------------ | ------------------------------------------------------------------------------ |
| `build`      | Разрешает вопросы                                                              |
| `plan`       | Разрешает вопросы; запрещает редактирование, кроме файлов в `~/.opencode/plan` |
| `general`    | Запрещает вопросы и запуск субагентов                                          |
| `explore`    | Запрещает все, кроме чтения, glob, grep, загрузки веб-страниц и веб-поиска; запрашивает подтверждение для внешних каталогов и чтения `.env` |
| `title`      | Запрещает все действия                                                         |
| `summary`    | Запрещает все действия                                                         |
| `compaction` | Сохраняет базовую политику                                                     |

OpenCode также разрешает `external_directory` для своих управляемых каталогов: вывода инструментов, вывода оболочки,
временных файлов и глобальной конфигурации. Для самого действия — `read`, `edit` или другого — по-прежнему
применяются его собственные правила. Последующие глобальные правила и правила агента могут переопределить эти значения
по умолчанию.

## Агенты

Общие правила задавайте на верхнем уровне, а более узкие — в `agents.<id>.permissions`:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "permissions": [
    { "action": "shell", "resource": "*", "effect": "ask" },
    { "action": "shell", "resource": "git status *", "effect": "allow" },
  ],
  "agents": {
    "reviewer": {
      "description": "Review code without changing it",
      "mode": "subagent",
      "permissions": [
        { "action": "edit", "resource": "*", "effect": "deny" },
      ],
    },
  },
}
```

Правила агента добавляются после глобальных и не заменяют глобальный массив. Пользовательский субагент использует
собственные разрешения, а не подмножество разрешений родительского агента.

## Подтверждения

Если правило дает `ask`, клиент может ответить так:

| Вариант      | Ответ      | Результат                                                            |
| ------------ | ---------- | -------------------------------------------------------------------- |
| Allow once   | `once`     | Подтвердить только текущий запрос                                    |
| Allow always | `always`   | Подтвердить и сохранить для проекта шаблоны, предложенные инструментом |
| Reject       | `reject`   | Отклонить этот и все остальные ожидающие запросы разрешений в сессии |

Например, если выбрать **Allow always** для `git status --short`, может сохраниться префикс команды, который охватит и
последующие команды `git status`:

```text
shell: git status * → allow
```

Сохраненные подтверждения — это постоянные правила `allow` на уровне проекта. Они никогда не переопределяют заданный в
конфигурации `deny`. Шаблон для сохранения предлагает инструмент: одни предлагают `*`, оболочка — префиксы команд, а
навыки и субагенты — свои ID. Проверяйте слишком широкие подтверждения и удаляйте ненужные.

При отклонении клиент может приложить отзыв. Неинтерактивные клиенты должны сами решать, как обрабатывать запросы
подтверждения; правила `deny` из конфигурации применяются всегда.

## Политики

[Политика](/policies) может жестко запретить проверку разрешения после того, как применены эти правила и сохраненные
подтверждения. Она превращает `allow` или `ask` в `deny` и никогда не дает доступ.

```jsonc
{
  "policies": [{ "action": "tool.use", "resource": "shell:sudo *", "effect": "deny" }],
}
```

Глобальные политики и политики, управляемые через Console, переопределяют конфигурацию проекта. Так организация может
заблокировать команду, которую разрешил бы репозиторий.
