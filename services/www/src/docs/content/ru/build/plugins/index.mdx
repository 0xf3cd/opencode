Плагины позволяют изменять поведение OpenCode и добавлять новые возможности. Чтобы изменить терминальный интерфейс,
создайте [CLI-плагин](/build/plugins/cli).

Переносите существующий плагин для OpenCode 1? Воспользуйтесь [руководством по миграции плагинов с
V1](/build/plugins/migrate-v1).

```ts title=".opencode/plugins/example/index.ts"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "example",
  async setup(ctx) {
    await ctx.storage.set("loaded", true)
  },
})
```

Плагины из `.opencode/plugins/` загружаются автоматически, как локальный пример выше. Чтобы загрузить опубликованные
пакеты или каталоги плагинов из других мест, добавьте их в `plugins` в `opencode.json(c)`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": [
    "opencode-acme-plugin",
    "opencode-acme-plugin@1.2.0",
    "@acme/opencode-plugin",
    "./plugins/local",
    "../shared/plugin",
    "/absolute/path/plugin",
    "file:///home/me/plugins/local",
    {
      "package": "@acme/opencode-plugin",
      "options": {
        "agent": "reviewer",
        "strict": true,
      },
    },
  ],
}
```

Другие способы загрузки и параметры конфигурации описаны в разделе [Настройка плагинов](/plugins).

## Жизненный цикл

`setup` выполняется при загрузке плагина. Он может вернуть функцию очистки, которая выполнится при выгрузке плагина.

```ts
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "example",
  setup(ctx) {
    console.log(`loaded in OpenCode ${ctx.app.version}`)
    return () => console.log("unloaded")
  },
})
```

### Контекст

По сути, контекст плагина — это [клиент сервера OpenCode](/build/client). Его методы чтения и действий принимают те же
входные данные и возвращают те же ответы, что и клиент. Кроме того, контекст добавляет методы, доступные только
плагинам: преобразования, хуки среды выполнения, перезагрузку, регистрации и параметры плагина.

```ts
setup(ctx) {
  console.log(ctx.app.version)
}
```

`ctx.location` описывает расположение, в котором загружен этот экземпляр плагина. Оно включает `directory`,
необязательный `workspaceID` и метаданные `project` (`id`, `directory` и `canonical`). Свойство доступно как в
Promise-плагинах, так и в плагинах на Effect. Это расположение экземпляра плагина, а не каждой сессии, к которой он
может обращаться, или каждого события, которое он получает.

```ts
setup(ctx) {
  console.log(ctx.location.directory)
  console.log(ctx.location.project.canonical)
}
```

### Параметры

Параметры плагина передаются в объектной форме записи в `opencode.json(c)`.

```jsonc title="opencode.jsonc"
{
  "plugins": [
    {
      "package": "./plugins/company",
      "options": {
        "strict": true,
      },
    },
  ],
}
```

Во время `setup` читайте эти значения из `ctx.options`.

```ts title="plugins/company/index.ts"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "company",
  setup(ctx) {
    const strict = ctx.options.strict === true
  },
})
```

## Преобразования

Преобразования — это синхронные правки состояния доменов OpenCode; каждое из них опирается на предыдущие регистрации
в своем домене. Чтение из реестра, например `ctx.model.list()`, учитывает все регистрации на текущий момент, в том числе
во время `setup` плагинов: пакетная обработка при запуске лишь объединяет уведомления об обновлениях и никогда не
задерживает результат чтения. API статуса ресурсов по-прежнему сообщают состояние запущенных ресурсов: зарегистрированное
определение не означает, что подключение или другая работа с ресурсом уже завершены.

Источники добавляют провайдеров и неизменяемые определения моделей через `ctx.provider.transform`.

```ts title="plugins/models/index.ts"
import { Model, Plugin, Provider } from "@opencode/plugin"

export default Plugin.define({
  id: "company.models",
  async setup(ctx) {
    const providerID = Provider.ID.make("acme")
    const models = [{ ...Model.Info.default(providerID, Model.ID.make("reasoner")), name: "Acme Reasoner" }]
    await ctx.provider.transform((editor) => {
      editor.add({
        info: {
          ...Provider.Info.empty(providerID),
          name: "Acme",
          activation: "enabled",
          package: "@opencode/ai/providers/openai-compatible",
          settings: { baseURL: "http://127.0.0.1:8000/v1" },
        },
        models,
      })
    })

    const available = await ctx.model.list()
  },
})
```

Любая регистрация, удаление или вызов `reload()` помечает реестр как измененный; при следующем чтении он пересобирается:
все активные преобразования заново применяются к новому значению в порядке регистрации. Преобразования должны быть
легковесными и повторяемыми. Уже прочитанное значение последующие пересборки не изменяют.

После того как преобразования провайдеров применены и доступность определена, OpenCode формирует модели активных
провайдеров и по порядку применяет все преобразования моделей. Политика моделей может анализировать весь набор
кандидатов, включая только что обновленные источники.

```ts title="plugins/model-budget/index.ts"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "company.model-budget",
  async setup(ctx) {
    await ctx.model.transform((editor) => {
      editor
        .list()
        .filter((model) => model.cost.some((tier) => tier.output > 20))
        .forEach((model) => {
          editor.remove(model.providerID, model.id)
        })
    })
  },
})
```

Захваченные входные данные не отслеживаются автоматически. Загрузите внешние данные до синхронного колбэка, а после
их изменения вызовите `reload()`. В этом примере `loadFromSource()` возвращает элементы вида
`{ info: Provider.Info, models: readonly Model.Info[] }`.

```ts title="plugins/models/index.ts"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "company.models",
  async setup(ctx) {
    const source = { providers: await loadFromSource() }

    await ctx.provider.transform((editor) => {
      source.providers.forEach((provider) => editor.add(provider))
    })

    const refresh = async () => {
      source.providers = await loadFromSource()
      await ctx.provider.reload()
    }

    const timer = setInterval(() => void refresh().catch(console.error), 60_000)
    return () => clearInterval(timer)
  },
})
```

Изменения провайдеров инвалидируют весь результат по активным моделям, поэтому политика по цене вывода по-прежнему
фильтрует обновленные модели. Если изменились только входные данные, захваченные преобразованием моделей, используйте
`ctx.model.reload()`.

## API

### Агенты

Получайте всех агентов или одного агента по ID.

```ts
const agents = await ctx.agent.list()
const build = await ctx.agent.get({ agentID: "build" })
```

Зарегистрируйте преобразование, чтобы просматривать, изменять и удалять агентов или выбрать агента по умолчанию.

```ts
await ctx.agent.transform((editor) => {
  const agents = editor.list()
  const build = editor.get("build")

  editor.default("build")
  editor.update("build", (agent) => {
    agent.description = "Builds features and fixes bugs"
  })
  editor.remove("legacy")
})
```

Если изменилось внешнее состояние, которое использует преобразование, перезагрузите агентов.

```ts
await ctx.agent.reload()
```

### Провайдеры

Получайте доступных провайдеров или метаданные одного провайдера по ID.

```ts
const providers = await ctx.provider.list()
const provider = await ctx.provider.get({ providerID: "anthropic" })
```

Преобразования провайдеров изменяют настройки провайдеров и исходные определения. Чтение в редакторе включает
неактивных провайдеров и возвращает неизменяемые определения; `models.update` изменяет собственную копию исходной
модели.

```ts
await ctx.provider.transform((editor) => {
  editor.update("anthropic", (provider) => {
    provider.headers = { ...provider.headers, "x-company": "engineering" }
  })
  editor.models.update("anthropic", "claude-sonnet-4-5", (model) => {
    model.name = "Team Sonnet"
  })
  editor.models.remove("anthropic", "legacy-model")
  editor.remove("legacy-provider")
})
```

Замените исходный набор моделей провайдера с помощью `models.set`, а после изменения захваченных определений выполните
перезагрузку.

```ts
const source = { models: await loadModels() }
await ctx.provider.transform((editor) => {
  editor.models.set("acme", source.models)
})

source.models = await loadModels()
await ctx.provider.reload()
```

Если набор моделей зависит от аккаунта, передайте в `sourceConnection` подключение, через которое он загружен. Пока
выбрано другое подключение, OpenCode исключает этого провайдера — до тех пор, пока плагин не опубликует обновленный
набор.

```ts
const connection = await ctx.integration.connection.active("acme")
if (!connection) return
const inventory = await loadInventory(connection)
await ctx.provider.transform((editor) => {
  editor.add({ info: inventory.provider, models: inventory.models, sourceConnection: connection })
})
```

### Модели

Получайте доступные модели и модель, выбранную по умолчанию.

```ts
const models = await ctx.model.list()
const selected = await ctx.model.default()
```

Преобразования моделей изменяют весь набор кандидатов от активных провайдеров. Отключенные кандидаты остаются
доступными для изменения, пока не завершатся все преобразования; `update` может добавить модель только к доступному
провайдеру.

```ts
await ctx.model.transform((editor) => {
  editor.list("anthropic").forEach((model) => {
    editor.update(model.providerID, model.id, (draft) => {
      draft.enabled = draft.capabilities.tools
    })
  })
  editor.default.set("anthropic", "claude-sonnet-4-5")
  editor.remove("anthropic", "legacy-model")
})
```

Колбэки изменяют необработанные переопределения моделей. Значения по умолчанию провайдера объединяются один раз, когда
OpenCode фиксирует результат; последующие чтения без изменений используют этот результат повторно. `editor.provider`
предоставляет неизменяемые исходные определения, включая неактивные шаблоны, а не результат преобразований моделей.

```ts
await ctx.model.transform((editor) => {
  const source = editor.provider.get("anthropic")?.models.get("claude-sonnet-4-5")
  if (!source) return
  editor.update("anthropic", source.id, (model) => {
    model.limit.context = Math.min(model.limit.context, source.limit.context)
  })
})

await ctx.model.reload()
```

### Интеграции

Получайте интеграции и проверяйте активные учетные данные.

```ts
const integrations = await ctx.integration.list()
const github = await ctx.integration.get({ integrationID: "github" })
const connection = await ctx.integration.connection.active("github")
const credential = connection ? await ctx.integration.connection.resolve(connection) : undefined
```

Подключайте интеграции с помощью API-ключа.

```ts
await ctx.integration.connect.key({
  integrationID: "github",
  key: process.env.GITHUB_TOKEN!,
})
```

Запускайте, проверяйте, завершайте или отменяйте попытку подключения через OAuth.

```ts
const attempt = await ctx.integration.oauth.connect({ integrationID: "github", methodID: "oauth" })
const status = await ctx.integration.oauth.status({ integrationID: "github", attemptID: attempt.data.attemptID })
await ctx.integration.oauth.complete({ integrationID: "github", attemptID: attempt.data.attemptID, code })
await ctx.integration.oauth.cancel({ integrationID: "github", attemptID: attempt.data.attemptID })
```

Для подключений через команду доступен тот же процесс: запуск, проверка статуса и отмена.

```ts
const attempt = await ctx.integration.command.connect({ integrationID: "acme", methodID: "cli" })
const status = await ctx.integration.command.status({ integrationID: "acme", attemptID: attempt.data.attemptID })
await ctx.integration.command.cancel({ integrationID: "acme", attemptID: attempt.data.attemptID })
```

Зарегистрируйте преобразование, чтобы просматривать интеграции и управлять их способами аутентификации.

```ts
await ctx.integration.transform((editor) => {
  const integrations = editor.list()
  const acme = editor.get("acme")

  editor.update("acme", (integration) => {
    integration.name = "Acme"
  })
  editor.method.update({
    integrationID: "acme",
    method: { id: "cli", type: "command", label: "Sign in with Acme CLI", command: ["acme", "login"] },
  })

  const methods = editor.method.list("acme")
  const legacy = methods.find((method) => method.type === "command" && method.id === "legacy")
  if (legacy) editor.method.remove("acme", legacy)
  editor.remove("legacy")
})
```

Если изменилось внешнее состояние, которое использует преобразование, перезагрузите интеграции.

```ts
await ctx.integration.reload()
```

### MCP

Получайте список MCP-серверов и их текущее состояние подключения.

```ts
const servers = await ctx.mcp.list()
```

Плагины управляют MCP-серверами только через преобразования. `editor.set` добавляет или заменяет сервер,
`editor.update` изменяет его конфигурацию, а `editor.remove` удаляет его. Просматривать конфигурацию можно с помощью
`editor.list` и `editor.get`.

```ts
await ctx.mcp.transform((editor) => {
  const servers = editor.list()
  const docs = editor.get("docs")
  editor.set("docs", { type: "remote", url: "https://mcp.example.com" })
  editor.update("docs", (server) => {
    server.disabled = false
  })
  editor.remove("legacy")
})
```

Задайте в преобразовании `disabled: true`, чтобы отключить сервер и разорвать соединение, или `disabled: false`, чтобы
включить его и разрешить OpenCode подключиться. OpenCode приводит жизненный цикл серверов в соответствие с
преобразованной конфигурацией.

Если изменилось внешнее состояние, которое использует преобразование, вызовите `reload()`: преобразования применятся
заново, и состояние серверов будет согласовано.

```ts
await ctx.mcp.reload()
```

### Инструменты

Получайте зарегистрированные на данный момент инструменты (с учетом всех преобразований) вне колбэка преобразования.
У каждого инструмента есть `id`, содержащий его итоговое имя.

```ts
const tools = await ctx.tool.list()
const read = tools.find((tool) => tool.id === "read")
```

Регистрируйте, изменяйте и удаляйте инструменты с помощью синхронного преобразования — в том числе в Promise-плагинах.
Загружайте внешние данные до регистрации или перезагрузки. Более поздняя корректная регистрация переопределяет
инструмент с тем же итоговым именем.

```ts
const registration = await ctx.tool.transform((editor) => {
  editor.namespace({
    name: "acme",
    description: "Customer account tools",
  })
  editor.add({
    name: "greeting",
    description: "Create a greeting",
    input: {
      type: "object",
      properties: { name: { type: "string" } },
      required: ["name"],
      additionalProperties: false,
    },
    options: { namespace: "acme", codemode: true },
    execute: async (input, context) => {
      await context.progress({ status: "greeting" })
      return { content: `Hello ${(input as { name: string }).name}!` }
    },
  })
})
```

Обработчики инструментов в Promise-плагинах получают `context.signal`. Передавайте его в отменяемые операции, например
в `fetch`, чтобы при остановке сессии останавливалась и сама операция.

```ts
execute: async ({ url }, context) => {
  const response = await fetch(url, { signal: context.signal })
  return { content: await response.text() }
}
```

После изменения исходных данных, захваченных колбэком, вызовите `reload()`. Перезагрузка заново применяет активные
преобразования, не меняя их порядок; `setup` плагина повторно не выполняется.

```ts
await ctx.tool.reload()
```

Чтобы просмотреть инструменты, которые сейчас находятся в редакторе, используйте `list()` и `get()`. У инструментов есть
`id`, содержащий их итоговое имя, а `get()` возвращает `undefined`, если такого ID нет. В `update` и `remove` указывайте
итоговое имя инструмента вместе с пространством имен (в примере выше — `acme_greeting`). Точки в пространствах имен и
недопустимые символы в именах инструментов заменяются на `_`. Отсутствующие имена игнорируются; чтобы создать
инструмент, вызовите `add` с полным определением. Изменения сохраняют имя и пространство имен. Чтобы заменить схемы или
параметры, присваивайте новые значения, а не изменяйте вложенные. Некорректные изменения записываются в лог, а прежнее
определение остается без изменений.

```ts
await ctx.tool.transform((editor) => {
  editor.update("acme_greeting", (tool) => {
    tool.description = "Greet the user by name"
  })
  editor.remove("acme_obsolete")
})
```

Изменения и удаления применяются по порядку вместе с добавлениями, в том числе после обновления каталога MCP. Если
освободить их регистрацию, эти изменения отменяются, и состояние пересобирается из оставшихся преобразований.

Освобождение регистрации удаляет ее преобразование и пересобирает состояние из оставшихся, так что снова становится
видно более раннее определение, которое оно переопределяло. Повторное освобождение безопасно, а при выгрузке плагина
все его регистрации освобождаются автоматически.

```ts
await registration.dispose()
```

Каждый запрос к модели фиксирует стабильный исполняемый снимок инструментов. Последующие преобразования, перезагрузки и
освобождение регистраций влияют на будущие снимки, но не на уже зафиксированные определения, описания пространств имен
Code Mode и обработчики. Обработчики, замыкающие изменяемые данные плагина, по-прежнему видят эти данные; если значение
должно оставаться привязанным к конкретному определению, захватите его внутри преобразования.

### Worktree

Зарегистрируйте локальную стратегию worktree в рамках обычного жизненного цикла плагина. В этом примере модуль
реализации отвечает за проверку параметров и операции бэкенда `create`, `remove` и `list`.

```ts title="plugins/worktrees/index.ts"
import { Plugin } from "@opencode/plugin"
import { makeStrategy } from "./strategy"

export default Plugin.define({
  id: "company.worktrees",
  async setup(ctx) {
    const strategy = makeStrategy(ctx.options)
    await ctx.worktree.transform((editor) => {
      editor.add(strategy)
    })
  },
})
```

Загрузите плагин через `plugins`, а общий целевой каталог настройте отдельно:

```jsonc title="opencode.jsonc"
{
  "worktree": { "directory": "../worktrees" },
  "plugins": [{ "package": "./plugins/worktrees", "options": {} }],
}
```

- Добавленная стратегия выбирается автоматически. Действует последняя активная регистрация; отдельная настройка выбора
  стратегии не нужна.
- Освобождение регистрации или выгрузка плагина восстанавливает предыдущую реализацию, а в конечном счете — встроенную
  стратегию Git.
- `reload()` заново применяет преобразования после изменения захваченных входных данных; `setup` плагина повторно не
  выполняется.
- При ошибке создания повторная попытка через Git не выполняется. Существующие worktree сохраняют записанного владельца,
  даже если стратегия по умолчанию меняется.
- Стратегии управляют локальными каталогами. Подготовка удаленных рабочих пространств в этот интерфейс не входит.

#### Операции

Контекст плагина предоставляет те же операции с worktree на уровне проекта, что и клиент. Каждой операции нужен
`projectID`. `list` читает только сохраненный список, включая известные рабочие копии того же проекта; он не загружает
конфигурацию, не запускает плагины и не обнаруживает изменения в файловой системе.

```ts
const projectID = ctx.location.project.id
const created = await ctx.worktree.create({ projectID, name: "task" })
const inventory = await ctx.worktree.list({ projectID })
await ctx.worktree.refresh({ projectID })
await ctx.worktree.remove({ projectID, directory: created.directory, force: false })
```

Создание загружает конфигурацию и плагины из сохраненного каталога `canonical` проекта и использует выбранную в них
стратегию. Можно передать необязательные родительский каталог `directory`, источник `from`, начальную ветку `branch` и
имя `name`. По умолчанию источником служит каноническая рабочая копия, а переданный `from` должен принадлежать тому же
проекту. Выбор источника не меняет корень конфигурации. Переданная начальная ссылка (ref) должна поддерживаться
выбранной стратегией: например, у нативной операции снимка в Rift нет параметра выбора ref.

Создание и обновление ждут активации плагинов канонической рабочей копии. Вызовы, сделанные во время `setup` плагинов
этой рабочей копии, видят уже выполненные регистрации и не ждут собственной активации.

Удаление загружает каноническую конфигурацию и активирует ее плагины, а затем использует стратегию, записанную для
worktree, а не текущую стратегию по умолчанию. Если записанный владелец недоступен, возникает ошибка. Целевой каталог
worktree может находиться в другом месте:

```ts
await ctx.worktree.remove({
  directory: "/worktrees/task",
  projectID,
  force: false,
})
```

Если владелец отсутствует, удаление завершается ошибкой, а не переключается на Git. Чтобы запросить подтверждение
принудительного удаления, не завися от ошибок Core или Git, стратегия может выбросить `new Worktree.OperationError({
message: "Uncommitted changes", forceRequired: true })`, импортировав `Worktree` из `@opencode/plugin`.

Обновление загружает каноническую конфигурацию и просит все доступные стратегии найти worktree во всех известных
корнях рабочих копий. Результаты объединяются, записанные владельцы сохраняются, а отсутствующие каталоги удаляются из
списка. Сбой одного источника обнаружения записывается в лог, остальные продолжают работу. Существующие каталоги
остаются сохраненными, даже если ни одна доступная стратегия о них не сообщает. Чтобы прочитать измененный список,
отслеживайте событие `worktree.updated` и снова вызывайте `list`.

```ts
await ctx.worktree.refresh({ projectID })
```

#### Справочник

Реализации получают предлагаемый целевой каталог уже после выбора имени и обработки конфликтов. Верните из `create`
фактический каталог: он может отличаться, если бэкенду нужна собственная структура. OpenCode разрешает возвращенный
путь и использует его для списка worktree, команд запуска и результата API. Возвращенный каталог должен существовать.

Стратегии, выбирающие другой целевой каталог, сами обрабатывают конфликты имен в нем. OpenCode все равно создает
предложенный родительский каталог перед вызовом стратегии. `list` должен сообщать только о каталогах, которыми владеет
стратегия, а также о корнях репозиториев.

```ts
interface WorktreeDefinition {
  readonly id: string
  create(
    input: { sourceDirectory: string; directory: string; branch?: string },
    context: { signal: AbortSignal },
  ): Promise<{ directory: string }>
  remove(input: { directory: string; force: boolean }, context: { signal: AbortSignal }): Promise<void>
  list(
    sourceDirectory: string,
    context: { signal: AbortSignal },
  ): Promise<readonly { directory: string; type: "root" | "worktree" }[]>
}

interface WorktreeEditor {
  add(definition: WorktreeDefinition): void
}

interface WorktreeDomain extends WorktreeApi {
  transform(callback: (editor: WorktreeEditor) => void): Promise<Registration>
  reload(): Promise<void>
}
```

Колбэки в Promise-плагинах должны учитывать отмену через `signal`. Колбэки на Effect возвращают Effect и вместо этого
используют прерывание Effect. Регистрации остаются привязанными к среде выполнения плагина; операции с проектом
используют реестр канонической рабочей копии. Адаптеры конфигурации Core передают в этот реестр настройки каталогов.

### Веб-поиск

await ctx.websearch.transform((editor) => {

## Хуки

Хуки перехватывают выполняемые операции. Зарегистрируйте хук в его домене и освободите возвращенную регистрацию, когда
она станет не нужна.

```ts
const registration = await ctx.session.hook("context", () => {})
await registration.dispose()
```

Один и тот же хук могут зарегистрировать несколько плагинов. OpenCode выполняет их в порядке плагинов, поэтому более
поздние хуки видят изменения, внесенные более ранними.

### Сессии

Хуки сессий перехватывают прием промптов, вызовы модели, нативный HTTP и повторные попытки.

#### Прием промпта

Перехватывайте входящие пользовательские промпты до разрешения вложений и навыков и до постоянного сохранения во
входящую очередь:

```ts
await ctx.session.hook("prompt", (event) => {
  event.prompt.text = event.prompt.text.replaceAll("company-secret", "[redacted]")
  event.prompt.files ??= []
  event.prompt.files.push({ uri: "file:///project/policy.md" })
  event.metadata = { ...event.metadata, source: "company-policy" }
  event.delivery = "queue"
})
```

Хук получает собственный изменяемый черновик:

- `prompt` содержит `text`, `files`, упоминания агентов в `agents` и выбранные навыки в `skills`.
- `metadata` содержит определяемые приложением метаданные приема.
- `delivery` по умолчанию равно `"steer"`, его можно изменить на `"queue"`.
- ID сессии и сообщения доступны только для чтения; хук не может перенаправить промпт.

Файлы и навыки, добавленные хуком, проходят обычное разрешение и проверку. Если вы переписываете текст, обновите или
удалите смещения `mention` у вложений, которые больше не совпадают. Упоминания агентов не переключают активного агента
сессии.

Хуки промпта выполняются при следующих условиях:

- Хуки выполняются в порядке регистрации после того, как плагины расположения сессии готовы.
- Команды, отправляющие промпт через `session.prompt`, запускают хук.
- Синтетические сообщения, сообщения оболочки, управляющие элементы сжатия и перемещения — не запускают.
- Хук выполняется один раз при приеме промпта, а не перед каждым вызовом модели.
- Ограничить хук провайдером нельзя, поскольку модель определяется уже после приема.

Внесенные правки становятся каноническим сохраненным пользовательским вводом. Если подготовка завершилась ошибкой или
была прервана, OpenCode не принимает промпт.

Хуки промпта должны быть безопасны для повторного выполнения. Они не гарантируют, что побочные эффекты произойдут ровно
один раз:

- Повторная отправка с ID, который уже ожидает обработки или доставлен, возвращает исходный результат приема без
  повторного запуска хуков.
- При одновременных отправках хуки могут выполниться несколько раз, но засчитывается только первый успешный прием.
- Хуки промпта преобразуют ввод и не предоставляют типизированного API для отклонения.

#### Запросы к модели

Изменяйте собранные системные инструкции, сообщения, инструменты или параметры запроса непосредственно перед отправкой
модели. У каждого вида запросов, которые отправляет сессия, свой хук, поэтому плагин может по-разному обрабатывать цикл
агента и вспомогательные запросы:

- `context` выполняется для цикла агента, включая продолжения после вызовов инструментов.
- `compaction` выполняется для контрольных сводок. `messages` — это сжимаемая переписка; промпт для сводки OpenCode
  добавляет после выполнения хуков. Задайте `result`, чтобы самостоятельно записать результат сжатия и пропустить вызов
  модели; он принимает те же поля, что и завершенное сообщение сжатия.
- `generate` выполняется для разовых вызовов `ctx.session.generate`.
- `title` выполняется для генерации заголовка. У него нет `agent` и `tools`. Задайте `result`, чтобы предоставить
  заголовок самостоятельно.

```ts
await ctx.session.hook("context", (event) => {
  event.system.push({ type: "text", text: "Keep the review focused on correctness." })
  delete event.tools.write
  event.options.temperature = 0.2
  event.options.maxTokens = 8_000
})

await ctx.session.hook("compaction", async (event) => {
  event.result = { summary: await summarize(event.messages) }
})
```

Изменения затрагивают только исходящий вызов модели, а не сохраненную историю или конфигурацию. Хук, который должен
применяться ко всем запросам, нужно зарегистрировать для каждого вида.

Переопределения запроса подчиняются следующим правилам:

- Для каждого вызова модели `options` изначально пуст; он не содержит итоговых настроек модели.
- Типизированные ключи — это настройки генерации; любой другой ключ передается выбранному протоколу как параметр
  провайдера.
- Хуки выполняются в порядке регистрации и видят переопределения, сделанные более ранними хуками.
- Переопределения запроса имеют приоритет над значениями модели по умолчанию, а те — над значениями маршрута по
  умолчанию.
- Объекты параметров провайдера объединяются рекурсивно; массивы и скалярные значения заменяют прежние.
- Удаление переопределения или присвоение ему `undefined` возвращает настроенные значения по умолчанию, а не удаляет их.
- Наложения на тело HTTP-запроса применяются после преобразования в формат протокола и могут переопределить
  получившиеся поля.

#### Параметры провайдера

Параметры провайдера используют семантические имена параметров выбранного протокола, а не поля тела HTTP-запроса.
Настройки, специфичные для провайдера, ограничивайте соответствующим провайдером. Например, OpenAI Responses использует
`reasoningEffort`:

```ts
await ctx.session.hook(
  "context",
  (event) => {
    event.options.reasoningEffort = "high"
  },
  { providerID: "openai" },
)
```

Параметры генерации зависят от выбранного протокола и модели:

- `maxTokens` — семантический лимит выходных токенов.
- Gemini поддерживает `topK`; OpenAI Responses этот параметр не предоставляет.

#### Запрос к модели

Изменяйте настройки запроса к модели и при необходимости ограничивайте хук одним провайдером. Событие содержит тот же
`kind`, что и HTTP-хуки ниже.

```ts
await ctx.session.hook(
  "model.request",
  (event) => {
    event.headers["x-plugin"] = "review"
  },
  { providerID: "anthropic" },
)
```

#### Нативный HTTP

Изменяйте нативные запросы к провайдеру или его ответы. Их тела — одноразовые потоки: прежде чем читать тело, клонируйте
или замените его.

Оба хука выполняются для каждого запроса, который отправляет сессия. `event.kind` указывает, какой процесс отправил
запрос: `"primary"` — цикл агента, `"compaction"` — контрольные сводки, `"title"` — генерация заголовка, `"generate"` —
разовые вызовы `ctx.session.generate`. Чтобы различать вспомогательные запросы, используйте его, а не ID агента.

```ts
await ctx.session.hook("http.request", (event) => {
  event.request.headers.set("x-session-id", event.sessionID)
  if (event.kind === "title") event.request.headers.set("x-priority", "background")
})

await ctx.session.hook("http.response", (event) => {
  event.response = new Response(event.response.body, {
    status: event.response.status,
    headers: { ...Object.fromEntries(event.response.headers), "x-plugin": "review" },
  })
})
```

#### Нативный WebSocket (экспериментально)

Провайдеры, передающие данные потоком через WebSocket, открывают одно соединение на сессию и используют его для всех
запросов, поэтому `http.request` и `http.response` этот трафик не видят. Хук `experimental.ws.handshake` выполняется
один раз на вызов модели до выбора соединения. Он содержит те же `sessionID`, `agent`, `model` и `kind`, что и
HTTP-хуки, а также `url` и `headers` соединения. Изменение `url` или `headers` меняет сокет, который использует запрос,
поэтому после смены bearer-токена соединение открывается заново.

HTTP-хуки по-прежнему выполняются для каждого HTTP-запроса, включая запрос, на который переключается маршрут WebSocket
в качестве резервного варианта.

```ts
await ctx.session.hook(
  "experimental.ws.handshake",
  async (event) => {
    event.headers.authorization = `Bearer ${await mintToken(event.url)}`
    delete event.headers["api-key"]
  },
  { providerID: "azure" },
)
```

`experimental.ws.send` и `experimental.ws.receive` дают доступ к самим кадрам — это аналог изменения тела
HTTP-запроса или ответа для WebSocket. `send` выполняется после того, как драйвер провайдера сформировал исходящий кадр,
и до его отправки; `receive` — для каждого входящего кадра до того, как его увидит драйвер. Оба хука получают кадр в
виде строки и отправляют то, что содержится в `frame` на момент завершения хука.

OpenCode не проверяет переписанные кадры. Драйвер отслеживает состояние по ответам провайдера, поэтому за правку,
меняющую смысл на уровне протокола, отвечает плагин — так же, как и за переписанное тело HTTP-запроса.

```ts
await ctx.session.hook(
  "experimental.ws.send",
  (event) => {
    const body = JSON.parse(event.frame)
    if (body.type === "response.create") body.metadata = { ...body.metadata, session: event.sessionID }
    event.frame = JSON.stringify(body)
  },
  { providerID: "openai" },
)

await ctx.session.hook("experimental.ws.receive", (event) => {
  if (event.frame.includes('"type":"error"')) console.error(event.frame)
})
```

Эти хуки экспериментальные: их имена и структура могут измениться.

#### Политика повторных попыток

Переопределяйте решение о повторной попытке при сбое провайдера или заменяйте задержку (в миллисекундах). Хук
выполняется после того, как OpenCode классифицировал сбой и предложил политику, но до планирования повторной попытки. То,
как OpenCode внутренне выполняет следующую попытку, хук не раскрывает.

```ts
await ctx.session.hook("retry", (event) => {
  if (event.error.status === 429) {
    event.decision = { retry: true, delay: 10_000 }
    return
  }
  if (event.error.type === "provider.invalid-request" && event.attempt === 2) {
    event.decision = { retry: true, delay: 0 }
    return
  }
  if (event.attempt >= 3) event.decision = { retry: false }
})
```

Хуки повторных попыток могут изменить исходное решение OpenCode в `decision`: сделать окончательный сбой повторяемым или
запретить предложенную повторную попытку.

Решения о повторных попытках подчиняются следующим правилам:

- Несколько хуков выполняются в порядке регистрации, и более поздние видят текущее решение.
- Встроенное максимальное число попыток остается жестким ограничением.
- `attempt` — номер рассматриваемой фактической попытки. Исходный запрос — это `1`, поэтому первая повторная попытка —
  `2`.
- Некорректные задержки, например `NaN`, бесконечность или отрицательные значения, заменяются вычисленной задержкой.
- Восстановление после переполнения контекста выполняется отдельно: вместо повтора того же запроса оно сжимает
  переписку.

### Разрешения

Проверяйте решения о разрешениях после применения настроенных правил — до выполнения действия или публикации запроса
разрешения.

```ts
await ctx.permission.hook("evaluate", async (event) => {
  if (event.action === "read") return

  const messages = await ctx.session.context({ sessionID: event.sessionID })
  const review = await ctx.generate.text({
    model: { providerID: "anthropic", id: "claude-sonnet-4-6" },
    prompt: buildSafetyPrompt({ messages, action: event.action, resources: event.resources }),
  })
  const decision = parseDecision(review.text)

  event.effect = decision.effect
  event.message = decision.reason
})
```

Хуки разрешений подчиняются следующим правилам:

- Хуки выполняются для решений `allow` и `ask`.
- Явно настроенное `deny` окончательно, и хук для него не вызывается.
- Хук может изменить `effect` на `allow`, `ask` или `deny`.
- `message` отображается в запросе разрешения, переданном пользователю, или становится причиной отказа.

## Публикация

Плагин из пакета использует тот же экспорт по умолчанию, что и локальный плагин. Минимальный манифест выглядит так:

```json title="package.json"
{
  "name": "opencode-acme-plugin",
  "version": "1.0.0",
  "type": "module",
  "exports": {
    ".": "./src/index.ts",
    "./rpc": "./src/rpc.ts"
  },
  "dependencies": {
    "@opencode/plugin": "latest"
  }
}
```

Экспорт `./rpc` необязателен; добавьте его, если публикуете общий [контракт RPC](/build/plugins/rpc), который другие
плагины и клиенты смогут импортировать, не загружая вашу реализацию.

Используйте версии, совместимые с целевым релизом OpenCode, и тестируйте установленный пакет, а не только копию,
подключенную через workspace. Переходя на более новый контракт API, публикуйте совместимое обновление плагина.

## Поддержка V1

Плагин может поддерживать V1 и V2 через одну и ту же точку входа пакета. Экспортируйте по умолчанию один объект с
функцией `server()` для V1 и функцией `setup()` для V2:

```ts title="src/index.ts"
import { Plugin } from "@opencode/plugin"

export default {
  ...Plugin.define({
    id: "example",
    async setup(ctx) {
      await ctx.tool.hook("execute.before", () => {
        console.log("A tool is about to run")
      })
    },
  }),
  async server() {
    return {
      "tool.execute.before": async () => {
        console.log("A tool is about to run")
      },
    }
  },
}
```

- V1 вызывает `server()` и использует возвращенные хуки.
- V2 читает из экспорта по умолчанию `id` и `setup()` (или `effect()` для плагинов на Effect) и игнорирует `server()`.
- Каждая реализация должна использовать свой API: общий экспорт не превращает хуки V1 в хуки V2.
- Разверните `Plugin.define(...)` в экспортируемый объект через spread, чтобы определение V2 проверялось типами
  отдельно от `server()`.

Объектная форма для V1 поддерживается в OpenCode `1.18.29`. Более старые релизы V1 могут ожидать экспорт функции;
тестируйте установленный пакет на самом старом релизе V1, который собираетесь поддерживать, а также на V2.
