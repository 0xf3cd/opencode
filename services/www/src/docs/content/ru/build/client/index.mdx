`@opencode/client` — TypeScript-клиент для HTTP API OpenCode. Используйте его, если ваше приложение подключается к
серверу OpenCode по сети. Нативные типы и методы клиента генерируются из того же контракта, что и
[справочник по API](/api). Типы RPC плагинов берутся из импортированных определений RPC.

## Установка

```sh
bun add @opencode/client
```

## Создание клиента

Создайте клиент, указав URL сервера, а затем вызывайте методы, сгруппированные по ресурсам API:

```ts
import { OpenCode } from "@opencode/client"

const client = OpenCode.make({
  baseUrl: "http://localhost:4096",
})

const session = await client.session.create({
  location: { directory: "/workspace" },
})

await client.session.prompt({
  sessionID: session.id,
  text: "Review the current changes",
})
```

## Заголовки и запросы

Заголовки аутентификации или приложения, которые нужно отправлять по умолчанию, передайте в `OpenCode.make` через
`headers`. Можно также указать собственную реализацию `fetch`. Последним аргументом каждая операция принимает параметры
запроса — `AbortSignal` или заголовки для конкретного запроса. Исключение составляют подписки на события: они
поддерживают только отмену на стороне подписчика и используют заголовки базового клиента.

```ts
const client = OpenCode.make({
  baseUrl: "https://opencode.example.com",
  headers: {
    authorization: `Bearer ${process.env.OPENCODE_TOKEN}`,
  },
})

await client.session.list(undefined, {
  signal: AbortSignal.timeout(10_000),
})
```

## Поток событий

Потоковые эндпоинты возвращают асинхронные итерируемые объекты:

```ts
for await (const event of client.event.subscribe()) {
  console.log(event.type)
}
```

Подписчики на нативные события и события RPC используют одно ленивое соединение на клиент. Создание клиента,
дескриптора или итерируемого объекта не открывает соединение для событий — оно открывается, когда начинается чтение.
Выход из цикла итерации или отмена подписчика завершает только этот итератор. Когда уходит последний подписчик,
соединение закрывается. Общий источник ждет, пока каждое событие примут все активные подписчики, поэтому перед
медленной обработкой потребителям стоит буферизовать события.

Подписки работают только в реальном времени: события не воспроизводятся повторно, а соединение не восстанавливается
автоматически. Сбой источника завершает текущие подписки; после восстановления подпишитесь заново. Подписчик на
нативные события, подключившийся позже, получает текущий маркер `server.connected`, но не прошлые бизнес-события.

## RPC плагинов

Импортируйте общий контракт плагина и передайте его в `client.rpc`:

```ts
import { OpenCode } from "@opencode/client"
import { Acme } from "opencode-acme-plugin/rpc"

const acme = client.rpc(Acme)
const result = await acme.search(
  { query: "hello" },
  { location: { directory: "/workspace" }, signal: AbortSignal.timeout(10_000) },
)

const unsubscribe = acme.events.on("updated", (event) => {
  console.log(event.type, event.location.directory, event.data.text)
})
```

Второй, необязательный аргумент метода содержит `location`, `signal` и `headers` отдельно от входных данных, которые
определяет плагин. Если `location` не указан, действуют те же значения по умолчанию, что и для нативных запросов:
сначала заголовки расположения из базового клиента, затем рабочий каталог сервера. При создании подклиента `location` не
выбирается.

Типы аргументов и результатов методов выводятся из определения. Разбор схем выполняется на границе контракта:
вызывающая сторона отправляет входные данные в принимаемом представлении, а обработчики получают уже разобранные
значения. Promise-клиент принимает определения в формате Standard Schema или обычной JSON Schema и не запускает
парсеры схем локально: сервер возвращает уже разобранный и преобразованный результат. Для определений на Effect Schema
нужен Effect-клиент.

Объявленные ошибки методов отклоняют Promise так же, как ошибки других эндпоинтов Promise-клиента, а перехваченные
ошибки остаются нетипизированными. Типизированный подклиент снимает общие обертки ошибок HTTP RPC. Зарезервированные
сбои фреймворка `rpc.*` остаются обычными сбоями RPC, а не связанные с ними ошибки аутентификации, транспорта и
протокола сохраняют свое обычное клиентское представление.

Подписки RPC используют локальные имена и получают события этого RPC из всех расположений (location). Чтобы
отфильтровать их, проверяйте обязательное поле `event.location`. `events.subscribe` повторяет нативный API асинхронных
итерируемых объектов:

```ts
for await (const event of acme.events.subscribe("updated")) {
  console.log(event.data.text)
}
```

`events.on` — удобная обертка над тем же источником. Она возвращает функцию отписки; асинхронные колбэки ожидаются
последовательно. Сбои колбэка или источника записываются в лог и завершают этот слушатель. Нативные и типизированные
подписки получают одинаковую обычную обертку `rpc.<rpcID>.<event>`, в которой данные события передаются напрямую в
виде объекта. Подписки в реальном времени не воспроизводят пропущенные события.

Плагин на сервере должен быть настроен и реализовывать RPC: импорт определения его не регистрирует. API определения и
регистрации описан в разделе [RPC плагинов](/build/plugins/rpc). Любой HTTP-клиент также может вызвать общий маршрут
`POST /api/rpc/{rpcID}/{method}` с телом `{ "input": ... }` и получить `{ "output": ... }`. Отсутствие поля input или
output означает отсутствие значения.

## Локальный фоновый сервис

Основные точки входа клиента совместимы с браузером и не включают управление локальными процессами. В приложении на
Node.js импортируйте нативный Promise API сервиса из `@opencode/client/service`.

- `Service.discover()` возвращает работающий зарегистрированный эндпоинт, не запуская процесс.
- `Service.ensure()` возвращает совместимый сервис и при необходимости запускает его.
- `Service.stop()` останавливает именно тот экземпляр сервиса, который зарегистрирован.
- `Service.headers(endpoint)` создает заголовки аутентификации для клиента.

```ts
import { OpenCode } from "@opencode/client"
import { Service } from "@opencode/client/service"

const endpoint = await Service.ensure()
const client = OpenCode.make({
  baseUrl: endpoint.url,
  headers: Service.headers(endpoint),
})

const info = await client.server.info()
```

`Service.ensure()` принимает необязательные файл регистрации, версию, команду запуска сервиса и колбэк `onStart`. В
`version` можно передать точное значение или предикат совместимости:

```ts
const endpoint = await Service.ensure({
  file: "/var/run/opencode/service.json",
  version: (version) => version.startsWith("2."),
  command: ["opencode", "serve", "--service"],
  onStart(reason, previousVersion) {
    console.log(reason, previousVersion)
  },
})
```

Если не указывать эти параметры, используются стандартный путь к файлу регистрации и команда
`opencode serve --service`.
