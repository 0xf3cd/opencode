---
title: "โมเดล"
---

เลือกโมเดลสำหรับเซสชันปัจจุบันด้วย `/models`:

```text
/models
```

OpenCode แสดงรายการโมเดลจาก [models.dev](https://models.dev) อินทิเกรชันของผู้ให้บริการ และการกำหนดค่าของคุณ ตัวเลือกจะแสดงเฉพาะโมเดลที่เปิดใช้งานและผู้ให้บริการพร้อมใช้งานในโปรเจกต์ปัจจุบันเท่านั้น เชื่อมต่อผู้ให้บริการได้ที่[ผู้ให้บริการ](/providers)

## การเลือกโมเดล

เลือกรายการจาก `/models` แทนการเดา ID ของผู้ให้บริการหรือโมเดล การเลือกนี้มีผลกับเซสชันปัจจุบันและไม่เปลี่ยนการกำหนดค่าของคุณ

```text
anthropic/claude-sonnet-4-5
```

ความพร้อมใช้งานขึ้นอยู่กับแต่ละโปรเจกต์:

- โมเดลต้องเปิดใช้งานอยู่
- ผู้ให้บริการของโมเดลต้องพร้อมใช้งานในโปรเจกต์ปัจจุบัน
- ข้อมูลรับรองและการกำหนดค่าจากโปรเจกต์อื่นจะไม่ส่งต่อมาโดยอัตโนมัติ

## การรันครั้งเดียว

ใช้ `--model` เพื่อเลือกโมเดลสำหรับการรันผ่านบรรทัดคำสั่งครั้งเดียว โดยไม่เปลี่ยนค่าเริ่มต้นที่กำหนดไว้:

```bash
opencode run --model anthropic/claude-sonnet-4-5 "Refactor parseToken"
```

เอเจนต์และคำสั่งก็เลือกโมเดลของตัวเองได้เช่นกัน ดู[เอเจนต์](/agents)และ[คำสั่ง](/commands)

## ค่าเริ่มต้น

ตั้งค่า `model` ใน `opencode.json` หรือ `opencode.jsonc` เพื่อเลือกโมเดลเริ่มต้นสำหรับงานใหม่:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "anthropic/claude-sonnet-4-5",
}
```

โมเดลที่กำหนดไว้จะเป็นค่าเริ่มต้นของแคตตาล็อกเมื่อโมเดลเปิดใช้งานอยู่และผู้ให้บริการพร้อมใช้งาน มิฉะนั้น OpenCode จะใช้โมเดลที่รองรับและพร้อมใช้งานล่าสุดเป็นค่าสำรอง

- โมเดลที่เลือกไว้แล้วสำหรับเซสชันมีลำดับความสำคัญสูงกว่าค่าเริ่มต้นที่กำหนดไว้
- การสลับโมเดลของเซสชันจะไม่เขียนทับไฟล์กำหนดค่า
- ปัจจุบัน `model` ระดับบนสุดเก็บไว้เฉพาะผู้ให้บริการและโมเดลเริ่มต้น ไม่เก็บ variant

ดูตำแหน่งไฟล์และลำดับความสำคัญของการกำหนดค่าได้ที่[การกำหนดค่า](/config)

## Variant

variant คือตัวเลือกที่มีชื่อสำหรับโมเดลหนึ่ง ๆ มักใช้กำหนดระดับการให้เหตุผล (reasoning effort) หรืองบประมาณโทเค็น เพิ่ม `#variant` เมื่อเลือก variant สำหรับการรัน เซสชัน เอเจนต์ หรือคำสั่ง:

```bash
opencode run --model openai/gpt-5.2#high "Review this migration plan"
```

ชื่อ variant มาจากข้อมูลเมตาในแคตตาล็อกปัจจุบันของโมเดลที่เลือก ชื่ออย่าง `low`, `high` และ `max` ไม่ได้มีในทุกโมเดล และ variant ที่ไม่รู้จักจะทำให้เกิดข้อผิดพลาดในการระบุโมเดล

กำหนด variant ใหม่ หรือแทนที่ variant ในแคตตาล็อกที่มี ID เดียวกัน ได้ในอาร์เรย์ `variants` ของโมเดล:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "models": {
        "gpt-5.2": {
          "settings": {
            "reasoningEffort": "medium",
          },
          "variants": [
            {
              "id": "fast",
              "settings": {
                "reasoningEffort": "low",
              },
            },
            {
              "id": "deep",
              "settings": {
                "reasoningEffort": "high",
                "reasoningSummary": "auto",
              },
            },
          ],
        },
      },
    },
  },
}
```

แต่ละ variant มี `settings`, `headers` และ `body` ได้ ค่าเหล่านี้จะใช้หลังจากค่าของผู้ให้บริการและโมเดล

## ตัวเลือก

รายการผู้ให้บริการและโมเดลปรับแต่งคำขอได้ด้วย `settings`, `headers` และ `body`:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "openai": {
      "settings": {
        "baseURL": "https://api.example.com/v1",
      },
      "headers": {
        "X-Team": "platform",
      },
      "models": {
        "gpt-5.2": {
          "settings": {
            "reasoningEffort": "high",
          },
          "body": {
            "store": false,
          },
        },
      },
    },
  },
}
```

| ฟิลด์ | วัตถุประสงค์ |
| ---------- | ------------------------------------------------------------------ |
| `settings` | ตัวเลือกของแพ็กเกจผู้ให้บริการ เช่น `baseURL` หรือ `reasoningEffort` |
| `headers`  | header เพิ่มเติมของคำขอ HTTP |
| `body`     | ฟิลด์ใน body ของคำขอเฉพาะผู้ให้บริการ |

OpenCode ใช้ค่าของผู้ให้บริการก่อน ตามด้วยค่าของโมเดล และใช้ variant ที่เลือกเป็นลำดับสุดท้าย

- ออบเจกต์ `settings` และ `body` ที่ซ้อนกันจะรวมเข้าด้วยกัน
- อาร์เรย์และค่าสเกลาร์ที่มาทีหลังจะแทนที่ค่าก่อนหน้า
- ชื่อ header จับคู่แบบไม่สนตัวพิมพ์เล็กใหญ่
- ตัวเลือกเป็นแบบเฉพาะผู้ให้บริการ แพ็กเกจผู้ให้บริการอื่นอาจละเว้นหรือปฏิเสธตัวเลือกเหล่านี้

## ชื่อแทน

ใช้ `modelID` เพื่อตั้ง ID ในแคตตาล็อกที่จำง่ายกว่าให้กับโมเดลของ API:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "openai/coding-default",
  "providers": {
    "openai": {
      "models": {
        "coding-default": {
          "modelID": "gpt-5.2",
          "name": "Coding default",
          "capabilities": {
            "tools": true,
            "input": ["text", "image"],
            "output": ["text"],
          },
          "limit": {
            "context": 200000,
            "output": 32000,
          },
        },
      },
    },
  },
}
```

ในตัวอย่างนี้ `openai/coding-default` คือการอ้างอิงที่เลือกใช้ได้ และ `gpt-5.2` คือค่าที่ส่งไปยังผู้ให้บริการ สำหรับโมเดลที่ยังไม่มีในแคตตาล็อก OpenCode จะสันนิษฐานว่า:

- รองรับเครื่องมือ รับอินพุตเป็นข้อความและรูปภาพ และให้เอาต์พุตเป็นข้อความ
- มีขีดจำกัดบริบท 200,000 โทเค็นและขีดจำกัดเอาต์พุต 32,000 โทเค็น
- ไม่ได้ระบุขีดจำกัดอินพุต

ค่าเหล่านี้เป็นข้อสันนิษฐานสำรอง ไม่ใช่ความสามารถที่ตรวจพบจริง ให้ตั้งค่า `capabilities` และ `limit` ให้ถูกต้องเมื่อทราบ ค่าที่ระบุชัดเจนจะแทนที่ค่าสำรอง เพิ่ม `disabled: true` เพื่อซ่อนโมเดลจากแคตตาล็อกที่พร้อมใช้งาน:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "openai": {
      "models": {
        "legacy-model": {
          "disabled": true,
        },
      },
    },
  },
}
```

## การให้เหตุผล

สำหรับโมเดลที่เข้ากันได้กับ OpenAI ซึ่งสตรีมการให้เหตุผล (reasoning) ในฟิลด์ของข้อความผู้ช่วยแบบกำหนดเอง ให้ตั้งค่า `compatibility.reasoningField`:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "local": {
      "models": {
        "reasoner": {
          "compatibility": {
            "reasoningField": "reasoning_content",
          },
        },
      },
    },
  },
}
```

OpenCode รู้จัก `reasoning`, `reasoning_content` และ `reasoning_text` และยังรับสตริงอื่นที่เฉพาะผู้ให้บริการได้ด้วย OpenCode จะอ่านการให้เหตุผลที่สตรีมมาจากฟิลด์นั้น และใส่ฟิลด์กลับคืนเมื่อส่งข้อความผู้ช่วยก่อนหน้ากลับไปยังโมเดล

## การแคชพรอมต์

OpenCode วางจุดแบ่งแคชพรอมต์ (breakpoint) ให้อัตโนมัติบนเส้นทางที่ทราบว่าจำเป็นต้องใช้ เช่น Anthropic เมื่อให้บริการโมเดล Claude ผ่านพร็อกซีที่เข้ากันได้กับ OpenAI อย่าง LiteLLM นั้น OpenCode ไม่สามารถรู้ได้ว่าโมเดลเหล่านั้นต้องใช้จุดแบ่ง `cache_control` แบบ Anthropic ให้ตั้งค่า `compatibility.cacheFormat` ให้กับโมเดล Claude เหล่านั้น:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "litellm": {
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": { "baseURL": "https://litellm.example.com/v1" },
      "models": {
        "claude-sonnet-5": {
          "compatibility": { "cacheFormat": "anthropic" },
        },
        "claude-opus-5-5": {
          "compatibility": { "cacheFormat": "anthropic" },
        },
        // Other models on the same proxy cache automatically and need no setting.
        "gpt-6.1": {},
      },
    },
  },
}
```

จากนั้น OpenCode จะทำเครื่องหมายนิยามเครื่องมือตัวสุดท้าย system prompt และข้อความล่าสุดด้วย `cache_control: { "type": "ephemeral" }` ซึ่งใช้อายุแคชเริ่มต้น 5 นาทีของ endpoint ใช้ `"alibaba"` สำหรับโมเดลของ Alibaba Model Studio ซึ่งรับเครื่องหมายแบบเดียวกันแต่ละเว้นเครื่องหมายบนนิยามเครื่องมือ หากทุกโมเดลที่ผู้ให้บริการนั้นให้บริการรับรูปแบบเดียวกัน ให้ตั้ง `compatibility.cacheFormat` ที่ผู้ให้บริการแทน

## โมเดลภายในเครื่อง

OpenCode ค้นพบโมเดลจาก Ollama, LM Studio และ vLLM ที่ที่อยู่ภายในเครื่องเริ่มต้นได้โดยอัตโนมัติ คุณยังกำหนดค่าเซิร์ฟเวอร์ใดก็ได้ที่เข้ากันได้กับ OpenAI ด้วยตนเองได้ด้วย

```text
ollama/gemma3:4b
lmstudio/google/gemma-4-26b-a4b
vllm/Qwen/Qwen3-Coder-30B-A3B-Instruct
```

### Ollama

เมื่อ Ollama รอรับการเชื่อมต่อที่ `http://127.0.0.1:11434` ให้เลือกโมเดลที่ค้นพบด้วย ID ผู้ให้บริการ `ollama`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "ollama/gemma3:4b",
}
```

OpenCode รีเฟรชรายการโมเดลในเบื้องหลัง และอ่านความสามารถด้านบริบท การมองเห็นภาพ (vision) และการใช้เครื่องมือจาก Ollama โมเดลที่ใช้สำหรับ embedding อย่างเดียวจะไม่รวมอยู่ด้วย

สำหรับโฮสต์หรือพอร์ตอื่น ให้ตั้งค่า URL ที่เข้ากันได้กับ OpenAI ของ Ollama การค้นพบยังคงใช้ API เนทีฟของ Ollama ที่ prefix ของพาธเดียวกัน:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "ollama": {
      "settings": {
        "baseURL": "http://127.0.0.1:5678/v1",
        "apiKey": "{env:OLLAMA_API_KEY}",
      },
    },
  },
}
```

- ไม่ต้องใส่ `apiKey` หาก endpoint ไม่ต้องใช้การยืนยันตัวตนแบบ bearer
- ปิดการค้นพบด้วย `"plugins": ["-opencode.provider.ollama"]`

### LMStudio

เมื่อเซิร์ฟเวอร์ LM Studio ที่ไม่ต้องยืนยันตัวตนทำงานอยู่ที่ `http://127.0.0.1:1234` ให้เลือกโมเดลที่ค้นพบด้วย ID ผู้ให้บริการ `lmstudio`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "lmstudio/google/gemma-4-26b-a4b",
}
```

OpenCode รีเฟรชรายการโมเดลในเบื้องหลัง และอ่านความสามารถด้านบริบท การมองเห็นภาพ และการใช้เครื่องมือจาก LM Studio โมเดล embedding จะไม่รวมอยู่ด้วย

สำหรับโฮสต์หรือพอร์ตอื่น ให้ตั้งค่า URL ที่เข้ากันได้กับ OpenAI โมเดลจะยังถูกค้นพบโดยอัตโนมัติ:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "lmstudio": {
      "settings": {
        "baseURL": "http://127.0.0.1:5678/v1",
        "apiKey": "{env:LMSTUDIO_API_KEY}",
      },
    },
  },
}
```

- ไม่ต้องใส่ `apiKey` หากปิดการยืนยันตัวตนของ LM Studio ไว้
- ปิดการค้นพบด้วย `"plugins": ["-opencode.provider.lmstudio"]`

### vLLM

เมื่อ vLLM รอรับการเชื่อมต่อที่ `http://127.0.0.1:8000` ให้เลือกโมเดลที่ค้นพบด้วย ID ผู้ให้บริการ `vllm`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "vllm/Qwen/Qwen3-Coder-30B-A3B-Instruct",
}
```

OpenCode ตรวจสอบ `/health` รีเฟรช `/v1/models` ในเบื้องหลัง ใช้ `max_model_len` ที่รายงานมาเป็นขีดจำกัดบริบท และรวมเฉพาะ model card ที่มี `vllm` เป็นเจ้าของ

โมเดลที่ค้นพบจะประกาศว่ารองรับอินพุตและเอาต์พุตแบบข้อความ แต่ไม่รองรับการมองเห็นภาพหรือเครื่องมือ vLLM เปิดใช้การเรียกใช้เครื่องมือ (tool call) ด้วยแฟล็กของเซิร์ฟเวอร์ เช่น `--enable-auto-tool-choice` และ `--tool-call-parser` ซึ่งการค้นพบไม่ได้รายงานไว้

สำหรับ endpoint อื่นหรือเซิร์ฟเวอร์ที่ต้องยืนยันตัวตน ให้ตั้งค่า URL ที่เข้ากันได้กับ OpenAI ของเซิร์ฟเวอร์นั้น:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "vllm": {
      "settings": {
        "baseURL": "http://127.0.0.1:9000/v1",
        "apiKey": "{env:VLLM_API_KEY}",
      },
    },
  },
}
```

- ไม่ต้องใส่ `apiKey` หากปิดการยืนยันตัวตนไว้
- ปิดการค้นพบด้วย `"plugins": ["-opencode.provider.vllm"]`
- รองรับพร็อกซีที่มี prefix ของพาธ ตัวอย่างเช่น `https://example.com/vllm/v1` จะตรวจสอบ `/vllm/health` และค้นพบโมเดลจาก `/vllm/v1/models`

### เซิร์ฟเวอร์ที่เข้ากันได้

สำหรับเซิร์ฟเวอร์อื่นที่เข้ากันได้กับ OpenAI ให้กำหนดแพ็กเกจผู้ให้บริการ endpoint และโมเดลอย่างน้อยหนึ่งตัว:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "local/coder",
  "providers": {
    "local": {
      "name": "Local server",
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "http://127.0.0.1:1234/v1",
      },
      "models": {
        "coder": {
          "modelID": "model-name-on-server",
          "capabilities": {
            "tools": true,
            "input": ["text"],
            "output": ["text"],
          },
          "limit": {
            "context": 32768,
            "output": 8192,
          },
        },
      },
    },
  },
}
```

ใช้ชื่อโมเดล ขีดจำกัด ประเภทอินพุตและเอาต์พุต และการรองรับเครื่องมือตามจริงของเซิร์ฟเวอร์ OpenCode ตรวจไม่ได้ว่าค่าสำรองของโมเดลแบบกำหนดเองถูกต้องหรือไม่ หาก endpoint ต้องใช้คีย์ ให้เพิ่ม `apiKey` ใน `settings` โดยใช้การแทนค่าจากตัวแปรสภาพแวดล้อม เช่น `"apiKey": "{env:LOCAL_API_KEY}"` และอย่า commit ข้อมูลลับ

## การอ้างอิงโมเดล

ตัวเลือกโมเดลใช้รูปแบบ `provider/model` และระบุ `#variant` ต่อท้ายได้:

```text
openai/gpt-5.2
openai/gpt-5.2#high
openrouter/anthropic/claude-sonnet-4.5#high
```

| ส่วน | กฎ |
| ---------- | ---------------------------------------------------------- |
| ผู้ให้บริการ | สิ้นสุดที่ `/` ตัวแรก มี `/` หรือ `#` ไม่ได้ |
| โมเดล | มีอักขระ `/` เพิ่มเติมได้ แต่มี `#` ไม่ได้ |
| Variant | อยู่หลัง `#` เมื่อมีการระบุ |
| ตัวพิมพ์ | ID ของผู้ให้บริการและโมเดลแยกตัวพิมพ์เล็กใหญ่ |

ใช้ ID ในแคตตาล็อกแทนชื่อที่แสดงของผู้ให้บริการ ฟิลด์ `model` ระดับบนสุด ของเอเจนต์ และของคำสั่ง รับได้ทั้งรูปแบบสตริงด้านบนหรือออบเจกต์แบบเต็ม:

```jsonc
{
  "model": {
    "providerID": "openrouter",
    "model": "anthropic/claude-sonnet-4.5",
  },
}
```

รูปแบบเต็มมีประโยชน์สำหรับการกำหนดค่าที่สร้างขึ้นอัตโนมัติหรือสร้างด้วยโปรแกรม

## ข้อควรระวัง

คำนึงถึงกฎเหล่านี้เมื่อกำหนดค่าโมเดล:

```jsonc
{
  "model": "openai/gpt-5.2"
}
```

- ออบเจกต์ตัวเลือกโมเดลใช้ `model` ส่วนรายการในแคตตาล็อกของผู้ให้บริการใช้ `modelID` สำหรับ ID ที่ส่งไปยังผู้ให้บริการ
- แม้รูปแบบการเลือกระดับบนสุดจะรับ variant ได้ แต่ค่าเริ่มต้นของแคตตาล็อกใน V2 จะไม่เก็บ variant ไว้ ให้เลือก variant สำหรับเซสชัน การรัน เอเจนต์ หรือคำสั่งแทน
- ตัวเลือกของโมเดลเป็นแบบเฉพาะผู้ให้บริการ แพ็กเกจผู้ให้บริการอื่นอาจละเว้นหรือปฏิเสธตัวเลือกเหล่านี้
- ข้อมูลแคตตาล็อก ข้อมูลรับรอง และการกำหนดค่ามีขอบเขตตามตำแหน่ง (location) โมเดลที่ใช้ได้ในโปรเจกต์หนึ่งอาจใช้ไม่ได้ในอีกโปรเจกต์หนึ่ง
- โดยปกติไฟล์กำหนดค่าจะโหลดใหม่โดยอัตโนมัติ คำขอไปยังโมเดลที่กำลังดำเนินการอยู่จะใช้การตั้งค่าที่มีอยู่ตอนเริ่มต้นต่อไป
