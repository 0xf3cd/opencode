---

การซิงค์ไดเรกทอรี (SCIM 2.0) จะเพิ่มผู้ใช้เข้าสู่ Workspace เมื่อคุณกำหนดผู้ใช้ในผู้ให้บริการข้อมูลประจำตัว (identity provider) และเพิกถอนสิทธิ์เข้าถึงเมื่อคุณยกเลิกการกำหนด ส่วนบทบาทยังคงจัดการใน Console

```text
https://opencode.ai/console/scim/v2
```

## ก่อนเริ่มต้น

- ตั้งค่า [SSO](/console/sso) สำหรับ Workspace
- [ยืนยัน](/console/sso#verify-email-domains)ทุกโดเมนอีเมลที่ผู้ใช้ใช้ลงชื่อเข้าใช้ การซิงค์ไดเรกทอรีจะเพิ่มเฉพาะผู้ใช้ในโดเมนที่ยืนยันแล้ว สำหรับคนอื่นให้เชิญจาก[สมาชิก](/console/members)

## สร้างโทเค็น

1. เปิด **Settings › Security** แล้วคลิก **Set up** ใต้ **Directory sync**
2. คัดลอก **SCIM base URL** และโทเค็น โทเค็นจะแสดงเพียงครั้งเดียว จึงควรเก็บไว้ในตัวจัดการข้อมูลลับ (secrets manager)

ผู้ให้บริการข้อมูลประจำตัวจะส่งโทเค็นนี้ไปกับทุกคำขอ

```text
Authorization: Bearer <token>
```

## เชื่อมต่อผู้ให้บริการข้อมูลประจำตัว

### Okta

1. เพิ่มแอป **SCIM 2.0 Test App (Header Auth)**
2. ตั้งค่า base URL และป้อน `Bearer ` ตามด้วยโทเค็นใน **API Token**
3. เปิด **Create Users**, **Update User Attributes** และ **Deactivate Users** ปล่อย **Import Groups** และการซิงค์รหัสผ่านไว้ให้ปิด

### Microsoft Entra ID

1. ในแอประดับองค์กร (enterprise app) ให้เปิด **Provisioning** แล้วตั้งโหมดเป็น **Automatic**
2. ป้อน base URL เป็น **Tenant URL** และโทเค็นเป็น **Secret Token**
3. กำหนดผู้ใช้และกลุ่ม แล้วเริ่ม provisioning

### ผู้ให้บริการอื่น

ใช้แอป SCIM 2.0 ที่ยืนยันตัวตนด้วยโทเค็นใน header และชี้ไปที่ base URL Console รองรับ endpoint `/Users` และ `/Groups`

กำหนดผู้ใช้ทดสอบหนึ่งคนก่อน **Directory sync** จะแสดง **Connected to your identity provider** หลังจากคำขอแรก

## สิ่งที่ซิงค์

| ในผู้ให้บริการข้อมูลประจำตัว | ใน Console                                                                        |
| ------------------------- | --------------------------------------------------------------------------------- |
| กำหนดผู้ใช้                  | เพิ่มในบทบาท **Member** สมาชิกที่มีอยู่แล้วคงบทบาทเดิม                               |
| อัปเดตชื่อ                   | อัปเดตโปรไฟล์                                                                       |
| ยกเลิกการกำหนดหรือปิดใช้งาน    | ระงับสิทธิ์เข้าถึงและแสดงเป็น **Deactivated** คีย์ API ที่ผู้ใช้สร้างไว้จะถูกเพิกถอน          |
| กำหนดใหม่อีกครั้ง              | คืนสิทธิ์เข้าถึง คีย์ที่ถูกเพิกถอนไปแล้วยังคงถูกเพิกถอน                                      |
| ลบ                         | นำออกจาก Workspace โดยไม่กระทบบัญชีของผู้ใช้และ Workspace อื่น                          |

- การซิงค์ไดเรกทอรีไม่เปลี่ยนบทบาทและอีเมล
- เจ้าของคนสุดท้ายจะถูกปิดใช้งานหรือลบไม่ได้
- Workspace ที่สมัครสมาชิก [Go](/console/go) ไว้จะเพิ่มสมาชิกผ่านการซิงค์ไดเรกทอรีไม่ได้

## กลุ่ม

พุชกลุ่มเพื่อติดแท็กให้สมาชิกในกลุ่ม เช่น ด้วย **Push Groups** ของ Okta หรือการกำหนดกลุ่มใน Entra ให้กำหนดผู้ใช้ก่อนพุชกลุ่มของผู้ใช้เหล่านั้น

```text
Platform Admins  →  platform-admins
```

แต่ละกลุ่มจะติดแท็กที่ตั้งชื่อตามกลุ่มให้สมาชิกในกลุ่ม ใน **Settings › Security › Group tags** คุณเปลี่ยนชื่อแท็ก ชี้หลายกลุ่มไปที่แท็กเดียว หรือหยุดติดแท็กให้กลุ่มได้ เมื่อออกจากกลุ่ม แท็กของกลุ่มนั้นจะถูกนำออก

## หมุนเวียนโทเค็น

1. คลิก **New token** แล้วติดตั้งโทเค็นในผู้ให้บริการข้อมูลประจำตัว
2. รอจนกว่าโทเค็นใหม่จะแสดงเวลาที่ใช้งานล่าสุด
3. เพิกถอนโทเค็นเดิม

การเพิกถอนโทเค็นจะหยุดการอัปเดตในอนาคต แต่ไม่เปลี่ยนแปลงสมาชิกที่มีอยู่ การลบการเชื่อมต่อ SSO จะเพิกถอนโทเค็นทั้งหมด

## SSO และการซิงค์ไดเรกทอรี

เมื่อ Workspace ออกโทเค็นแล้ว SSO จะไม่[เพิ่มสมาชิกโดยอัตโนมัติ](/console/sso#automatic-membership)อีกต่อไป ไดเรกทอรีจะเป็นตัวกำหนดว่าใครเป็นสมาชิก แม้ว่าโทเค็นจะถูกเพิกถอนในภายหลังก็ตาม
