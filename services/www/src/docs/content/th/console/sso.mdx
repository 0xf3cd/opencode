---

การลงชื่อเข้าใช้ครั้งเดียว (SSO) จะส่งสมาชิก Workspace ไปยังผู้ให้บริการข้อมูลประจำตัว (identity provider) ของบริษัทเมื่อลงชื่อเข้าใช้ เจ้าของและผู้ดูแลระบบตั้งค่าได้ใน **Settings › Security** และใช้ได้กับทุก Workspace

| โปรโตคอล       | ผู้ให้บริการ                                                                            |
| -------------- | -------------------------------------------------------------------------------------- |
| OpenID Connect | Google Workspace, Microsoft Entra ID, Okta, Auth0, Ping Identity หรือผู้ให้บริการ OIDC ใดก็ได้ |
| SAML 2.0       | Google Workspace, Microsoft Entra ID, Okta หรือผู้ให้บริการ SAML ใดก็ได้                       |

แต่ละ Workspace มีการเชื่อมต่อ SSO ได้หนึ่งรายการ

## ตั้งค่า OIDC

1. เปิด **Settings › Security** คลิก **Configure SSO** แล้วเลือก **OpenID Connect** และผู้ให้บริการของคุณ
2. สร้างแอปในผู้ให้บริการตามขั้นตอนที่แสดง โดยใช้ scope `openid`, `email` และ `profile`
3. ป้อน **Issuer URL** หรือ tenant หรือโดเมนของคุณ พร้อม **Client ID**, **Client Secret** และ **Display Name** แล้วคลิก **Save**
4. คัดลอก **Callback URL** จากการเชื่อมต่อไปใส่ใน redirect URI ที่อนุญาตของผู้ให้บริการ

```text
https://opencode.ai/console/auth/sso/ssoconn_.../callback
```

Console จะตรวจสอบว่าเข้าถึง issuer ได้เมื่อคุณบันทึก SSO จะเริ่มทำงานทันทีที่บันทึกการเชื่อมต่อ

## ตั้งค่า SAML

1. เปิด **Settings › Security** คลิก **Configure SSO** แล้วเลือก **SAML 2.0** และผู้ให้บริการของคุณ
2. คัดลอก **ACS URL** และ **SP Entity ID** ไปใส่ในผู้ให้บริการ สำหรับผู้ให้บริการแบบกำหนดเอง จะใช้ **SP Metadata URL** หรือดาวน์โหลด XML แทนก็ได้
3. เพิ่มเมทาดาทาของผู้ให้บริการด้วย URL อัปโหลด XML หรือวางเนื้อหา คุณยังป้อน **IdP Entity ID**, **IdP SSO URL** และ **IdP Certificate** ด้วยตนเองได้
4. ตรวจสอบรายละเอียดแล้วคลิก **Activate SSO**

```text
ACS URL:       https://opencode.ai/console/auth/sso/ssoconn_.../callback
SP Entity ID:  https://opencode.ai/console/auth/sso/ssoconn_.../metadata
```

ผู้ให้บริการต้องลงนาม response หรือ assertion และส่งอีเมลของผู้ใช้เป็นแอตทริบิวต์ `email` หรือเป็น NameID

## ยืนยันโดเมนอีเมล

ผู้ที่ลงชื่อเข้าใช้ [Console](https://opencode.ai/console) ด้วยอีเมลในโดเมนที่ยืนยันแล้วจะถูกส่งไปยังผู้ให้บริการข้อมูลประจำตัวของคุณ เมื่อ SSO ทำงานแล้ว ให้คลิก **Add domain** ใต้ **Email domains** ป้อนโดเมน แล้วเผยแพร่ระเบียน TXT ที่แสดง

```text
Name:   _opencode-console-challenge.example.com
Type:   TXT
Value:  oc-verify=...
```

คลิก **Verify Domain** เมื่อเผยแพร่ระเบียนแล้ว การเปลี่ยนแปลง DNS อาจใช้เวลาสักพักกว่าจะมีผล แต่ละโดเมนเป็นของ Workspace ได้เพียงแห่งเดียว

## การบังคับใช้ SSO

เมื่อ Workspace มี SSO แล้ว ผู้ดูแลระบบและสมาชิกต้องลงชื่อเข้าใช้ผ่าน SSO เพื่อเปิด Workspace และ Console จะเปลี่ยนเส้นทางให้โดยอัตโนมัติ การเชื่อมต่อ OpenCode ด้วย `/connect` ก็ใช้กฎเดียวกัน

เจ้าของยังลงชื่อเข้าใช้โดยไม่ผ่าน SSO ได้ ดังนั้นผู้ให้บริการที่กำหนดค่าผิดจะไม่ทำให้ Workspace ถูกล็อกออกจากการตั้งค่าของตนเอง

## การเป็นสมาชิกอัตโนมัติ

ผู้ใช้ในโดเมนที่ยืนยันแล้วจะเข้าร่วม Workspace ในบทบาท **Member** เมื่อลงชื่อเข้าใช้ผ่าน SSO ครั้งแรก แต่จะไม่ถูกเพิ่มโดยอัตโนมัติเมื่อ:

- มีคำเชิญที่รอดำเนินการอยู่ ระบบจะใช้คำเชิญนั้นแทน
- Workspace ใช้[การซิงค์ไดเรกทอรี](/console/scim) ซึ่งเป็นตัวกำหนดการเป็นสมาชิก
- Workspace สมัครสมาชิก [Go](/console/go) ไว้

คำเชิญเข้าสู่ Workspace ที่ใช้ SSO จะส่งผู้ได้รับเชิญไปยังผู้ให้บริการข้อมูลประจำตัวเมื่อเปิดลิงก์

## บัญชีที่มีอยู่แล้ว

หากผู้ใช้มีบัญชี Console ที่ใช้อีเมลเดียวกันอยู่แล้ว Console จะขอให้ลงชื่อเข้าใช้บัญชีนั้นหนึ่งครั้งเพื่อเชื่อมโยงกับ SSO ผู้ที่ได้รับเชิญและผู้ที่ถูกเพิ่มผ่านการซิงค์ไดเรกทอรีจะถูกเชื่อมโยงโดยอัตโนมัติ

## แก้ไขหรือลบ

คลิก **Edit** ที่การเชื่อมต่อเพื่อเปลี่ยนรายละเอียด เว้นช่อง secret หรือใบรับรองว่างไว้เพื่อใช้ค่าปัจจุบันต่อ หากต้องการสลับระหว่าง OIDC กับ SAML ให้ลบการเชื่อมต่อแล้วสร้างใหม่

ลบการเชื่อมต่อได้จาก **⋯ › Delete...** สมาชิกจะกลับไปใช้วิธีลงชื่อเข้าใช้อื่นของตน การซิงค์ไดเรกทอรีจะหยุดทำงานและโทเค็นจะถูกเพิกถอน ส่วนโดเมนอีเมลยังคงอยู่
