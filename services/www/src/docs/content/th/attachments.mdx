## แนบไฟล์

แนบไฟล์ในเครื่อง แล้วขอให้ OpenCode ใช้ไฟล์นั้นในพรอมต์ ในไคลเอนต์เดสก์ท็อปหรือเว็บ ให้เลือก **Attach file** วางไฟล์ หรือลากไฟล์มาวางในช่องพรอมต์

```text
Summarize the attached README.md and list the required setup steps.
```

ไฟล์ที่เลือกผ่านตัวเลือกไฟล์ของเดสก์ท็อปมีขนาดรวมได้สูงสุด 20 MiB อินเทอร์เฟซอื่นอาจกำหนดขีดจำกัดฝั่งไคลเอนต์ที่ต่ำกว่านี้

<Callout type="warning">
  เลือกโมเดลที่รับอินพุตเป็นรูปภาพได้ก่อนแนบรูปภาพ OpenCode ส่งรูปภาพที่รองรับไปยังผู้ให้บริการได้ แต่ผู้ให้บริการและโมเดลยังคงบังคับใช้ข้อกำหนดของตนเองเรื่องรูปแบบ ขนาดภาพ จำนวนไฟล์ และขนาดไฟล์ โมเดลที่รับเฉพาะข้อความอาจปฏิเสธคำขอ
</Callout>

## ไวยากรณ์

อินพุตของพรอมต์และคำสั่งใน V2 อธิบายไฟล์แนบด้วย `uri` และ `name` กับ `description` ซึ่งไม่บังคับ:

```json
{
  "uri": "file:///home/me/project/src/server.ts",
  "name": "server.ts",
  "description": "HTTP server entrypoint"
}
```

ใช้ URL แบบ `file:` ที่เป็นพาธสัมบูรณ์สำหรับไฟล์หรือไดเรกทอรีที่เซิร์ฟเวอร์เข้าถึงได้ สำหรับไฟล์ข้อความ พารามิเตอร์ `start` และ `end` ที่เป็นค่าบวกจะเลือกช่วงบรรทัด โดยเริ่มนับบรรทัดแรกเป็น 1

```text
file:///home/me/project/src/server.ts?start=20&end=60
```

ใช้ URL แบบ `data:` เพื่อส่งเนื้อหาแบบ inline:

```json
{
  "uri": "data:text/plain;base64,SGVsbG8sIE9wZW5Db2RlIQ==",
  "name": "greeting.txt"
}
```

ไม่รองรับ URL ไฟล์แนบแบบ HTTP และ HTTPS ดูการส่งพรอมต์ผ่านโปรแกรมได้ที่[เอกสารอ้างอิง API](/api) ที่สร้างขึ้นโดยอัตโนมัติ

## รูปแบบไฟล์

เซสชัน V2 ในปัจจุบันทำให้โมเดลมองเห็นไฟล์แนบประเภทต่อไปนี้:

| อินพุต | สิ่งที่โมเดลได้รับ | ตัวอย่าง |
| --- | --- | --- |
| ไฟล์ข้อความ UTF-8 | ชื่อไฟล์และข้อความที่ถอดรหัสแล้ว | `README.md` |
| ไดเรกทอรี | รายการไฟล์และไดเรกทอรีในระดับถัดไปเท่านั้น (ไม่ recursive) | `file:///home/me/` |
| PNG, JPEG, GIF หรือ WebP | สื่อรูปภาพ | `diagram.png` |

SVG จะถือเป็นข้อความ ส่วนไฟล์แนบในพรอมต์ที่เป็น PDF, AVIF, BMP, เสียง, วิดีโอ และไบนารีอื่น ๆ จะไม่ถูกรวมในคำขอไปยังโมเดล ให้แปลงไบนารีที่ไม่รองรับเป็นข้อความหรือรูปภาพที่รองรับก่อน เช่น export หน้า PDF เป็น `page-1.png` ก่อนแนบ

OpenCode จะอ่านไฟล์แนบแต่ละไฟล์ก่อนรับพรอมต์ และจะปฏิเสธ URL ที่ไม่ถูกต้อง พาธที่อ่านไม่ได้ พาธที่ไม่ใช่ไฟล์หรือไดเรกทอรี และไฟล์แนบที่มีขนาดหลังถอดรหัสเกิน 20 MiB ประเภทสื่อจะตรวจจากไบต์ของไฟล์ ดังนั้นการเปลี่ยนชื่อไฟล์หรือประเภทสื่อใน URL แบบ `data:` จะไม่ทำให้โมเดลมองเห็นไบนารีที่ไม่รองรับ

## รูปภาพ

กำหนดค่าการปรับรูปภาพให้เป็นมาตรฐานใน `opencode.json` หรือ `opencode.jsonc`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "media": {
    "image": {
      "auto_resize": true,
      "max_width": 2000,
      "max_height": 2000,
      "max_base64_bytes": 5242880,
    },
  },
}
```

ทุกฟิลด์ไม่บังคับ:

| ฟิลด์ | ค่าเริ่มต้น | พฤติกรรม |
| --- | --- | --- |
| `auto_resize` | `true` | ปรับขนาดรูปภาพที่เกินขีดจำกัดที่กำหนด หากเป็น `false` จะปฏิเสธรูปภาพนั้น |
| `max_width` | `2000` | ความกว้างสูงสุดเป็นพิกเซล ต้องเป็นจำนวนเต็มบวก |
| `max_height` | `2000` | ความสูงสูงสุดเป็นพิกเซล ต้องเป็นจำนวนเต็มบวก |
| `max_base64_bytes` | `5242880` | จำนวนไบต์สูงสุดของรูปภาพที่เข้ารหัสแบบ Base64 ต้องเป็นจำนวนเต็มบวก |

ตัวอย่างเช่น การกำหนดค่านี้จะปฏิเสธรูปภาพที่กว้างกว่า 1200 พิกเซลแทนการปรับขนาด:

```jsonc title="opencode.jsonc"
{
  "media": {
    "image": {
      "auto_resize": false,
      "max_width": 1200,
    },
  },
}
```

การตั้งค่าเหล่านี้ใช้กับทั้งรูปภาพที่รองรับซึ่งแนบมากับพรอมต์ และรูปภาพที่เครื่องมือ `read` ในตัวส่งกลับมา

## การประมวลผล

เครื่องมือ `read` จะจำแนก PNG, JPEG, GIF และ WebP จากเนื้อหาไฟล์ และอ่านข้อมูลรูปภาพต้นฉบับได้สูงสุด 20 MiB โดยจะตรวจความกว้าง ความสูง และความยาว Base64 เทียบกับขีดจำกัดรูปภาพที่กำหนดไว้

เมื่อตั้ง `auto_resize: true` OpenCode จะคงอัตราส่วนภาพไว้และย่อขนาดให้อยู่ในขีดจำกัดของขนาดภาพ จากนั้นจะลองเข้ารหัสเป็น PNG และ JPEG ที่เล็กลงเรื่อย ๆ จนกว่าจะอยู่ในขีดจำกัด Base64 ดังนั้นประเภทสื่อของเอาต์พุตอาจเปลี่ยนไป

```text
Input:  4000 × 2000 WebP
Limits: 2000 × 2000
Output: 2000 × 1000 PNG or JPEG
```

หากไม่มีการเข้ารหัสใดอยู่ในขีดจำกัด การประมวลผลจะล้มเหลว เมื่อตั้ง `auto_resize: false` รูปภาพที่เกินขีดจำกัดใดก็ตามจะล้มเหลวโดยไม่มีการแก้ไข และรูปภาพที่ถอดรหัสไม่ได้ก็จะล้มเหลวเช่นกัน

```text
Input:  2400 × 1600 JPEG
Limit:  max_width = 2000, auto_resize = false
Result: Image processing fails
```

หากตัวปรับขนาดรูปภาพไม่พร้อมใช้งาน OpenCode จะส่งรูปภาพต้นฉบับต่อไปโดยไม่เปลี่ยนแปลง การตั้งค่ารูปภาพจึงเป็นขีดจำกัดในการประมวลผล ไม่ใช่ขอบเขตด้านการอัปโหลดหรือความปลอดภัย

## ขีดจำกัด

| ขีดจำกัด | ค่าหรือพฤติกรรม | ตัวอย่าง |
| --- | --- | --- |
| ไฟล์แนบโดยตรง | 20 MiB ต่อรายการหลังถอดรหัส ไคลเอนต์อาจกำหนดขีดจำกัดที่ต่ำกว่า | ไฟล์ 12 MiB สองไฟล์ผ่านขีดจำกัดต่อรายการ |
| การเลือกผ่านตัวเลือกไฟล์ของเดสก์ท็อป | รวม 20 MiB | ไฟล์ 12 MiB สองไฟล์เกินขีดจำกัดของการเลือก |
| `max_base64_bytes` | นับเฉพาะ Base64 ที่เข้ารหัสแล้ว ไม่รวม URL แบบ `data:` ทั้งหมด | `SGVsbG8=` นับเป็น 8 ไบต์ |
| ขีดจำกัดรูปภาพของผู้ให้บริการ | มีผลหลังการประมวลผลของ OpenCode | ผู้ให้บริการอาจปฏิเสธรูปภาพที่ OpenCode ยอมรับแล้ว |
| การรองรับไฟล์แนบข้อความของโมเดล | ไม่ต้องใช้โมเดลแบบ multimodal | `notes.txt` จะถูกแทรกเป็นข้อความในพรอมต์ |
| ขีดจำกัดข้อความของ `read` | ใช้ขีดจำกัดการแบ่งหน้าและการตัดทอนแยกต่างหาก | อ่านล็อกขนาดใหญ่ทีละหน้า |

การที่ไคลเอนต์รับไฟล์ไว้ไม่ได้รับประกันว่าเนื้อหาจะไปถึงโมเดล ไฟล์แนบต้องอยู่ในรูปแบบที่โมเดลมองเห็นได้ และต้องเป็นไปตามขีดจำกัดของทั้ง OpenCode และผู้ให้บริการ
