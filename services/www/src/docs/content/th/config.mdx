title: "การกำหนดค่า"
---

สร้างไฟล์ `opencode.jsonc` ในโปรเจกต์เพื่อกำหนดค่า OpenCode เพิ่ม schema เพื่อให้เอดิเตอร์ตรวจสอบความถูกต้องได้ จากนั้นตั้งค่าเฉพาะตัวเลือกที่ต้องการ

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "anthropic/claude-sonnet-4-5",
}
```

คุณยังให้ OpenCode อัปเดตไฟล์นี้ให้ได้ด้วย

## รูปแบบไฟล์

OpenCode รองรับ JSON และ JSONC ใช้ JSONC เมื่อต้องการเขียนคอมเมนต์หรือใส่จุลภาคต่อท้าย (trailing comma)

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  // Use this model by default.
  "model": "anthropic/claude-sonnet-4-5",
}
```

## ตำแหน่งไฟล์

วางการตั้งค่าที่ผู้ดูแลระบบจัดการ (managed) ที่มีผลทั้งเครื่องไว้ในไดเรกทอรีกำหนดค่าของระบบ:

| แพลตฟอร์ม | ไดเรกทอรี |
| -------- | --------------------------------------- |
| macOS    | `/Library/Application Support/opencode` |
| Linux    | `/etc/opencode`                         |
| Windows  | `%ProgramData%\opencode`                |

ไดเรกทอรีของระบบทำงานเหมือนไดเรกทอรีส่วนกลาง (global) นอกจาก `opencode.json(c)` แล้ว ยังโหลด `agents/`, `commands/`, `skills/` และ `plugins/` ให้กับผู้ใช้ทุกคนบนเครื่อง:

```text
/etc/opencode/
├── opencode.json
├── agents/review.md
├── commands/release.md
└── skills/deploy/SKILL.md
```

บน macOS นั้น OpenCode ยังอ่าน managed preferences ที่เครื่องมือ MDM ติดตั้งไว้สำหรับโดเมน `ai.opencode.managed` ด้วย โดยโปรไฟล์เฉพาะผู้ใช้จะแทนที่โปรไฟล์ระดับเครื่อง:

```text
/Library/Managed Preferences/<user>/ai.opencode.managed.plist
/Library/Managed Preferences/ai.opencode.managed.plist
```

การตั้งค่าที่ผู้ดูแลระบบจัดการมีลำดับความสำคัญสูงสุด ผู้ใช้และโปรเจกต์จึงแทนที่ค่าเหล่านี้ไม่ได้ และ managed preferences จะแทนที่ไดเรกทอรีของระบบ อย่างไรก็ตาม การตั้งค่าเพียงอย่างเดียวไม่สามารถห้ามผู้ใช้เพิ่มผู้ให้บริการ เซิร์ฟเวอร์ MCP เอเจนต์ หรือปลั๊กอินได้ หากต้องการบังคับข้อจำกัด ให้ใช้[นโยบาย](/policies#precedence)ในการกำหนดค่าที่ผู้ดูแลระบบจัดการ

วางการตั้งค่าของผู้ใช้ที่ใช้กับทุกโปรเจกต์ไว้ในการกำหนดค่าส่วนกลาง:

```text
~/.config/opencode/opencode.json(c)
```

วางการตั้งค่าของโปรเจกต์ไว้ในไฟล์ใดไฟล์หนึ่งต่อไปนี้:

```text
/home/user/projects/my-app/opencode.json(c)
/home/user/projects/my-app/.opencode/opencode.json(c)
```

OpenCode ค้นหาตั้งแต่ไดเรกทอรีปัจจุบันขึ้นไปจนถึงรากของระบบไฟล์ โดยรวมไฟล์ `opencode.json(c)` ที่อยู่ในไดเรกทอรีโดยตรงก่อน เรียงจากไดเรกทอรีที่ไกลที่สุดไปใกล้ที่สุด จากนั้นจึงรวมไฟล์ภายในไดเรกทอรี `.opencode` ตามลำดับเดียวกัน หมายความว่าการกำหนดค่าใน `.opencode` ทุกไฟล์ที่พบจะแทนที่การกำหนดค่าที่อยู่ในไดเรกทอรีโดยตรงทุกไฟล์ ให้ใช้รูปแบบเดียวตลอดทั้งโครงสร้างไดเรกทอรี เว้นแต่ต้องการพฤติกรรมนี้

ตัวอย่างเช่น เริ่ม OpenCode จาก `/home/user/projects/acme/packages/web`:

```text
/etc/opencode/opencode.json
~/.config/opencode/opencode.json

/home/user/projects/acme/
├── opencode.json
└── packages/
    └── web/
        ├── opencode.json
        └── src/
```

OpenCode ใช้ไฟล์เหล่านี้เรียงจากลำดับความสำคัญต่ำสุดไปสูงสุด:

1. `~/.config/opencode/opencode.json`
2. `/home/user/projects/acme/opencode.json`
3. `/home/user/projects/acme/packages/web/opencode.json`
4. `/etc/opencode/opencode.json`

การกำหนดค่าของแพ็กเกจจะแทนที่การตั้งค่าที่ตรงกันในการกำหนดค่าของ repository ซึ่งแทนที่การกำหนดค่าส่วนกลางอีกที ส่วนการกำหนดค่าของระบบจะแทนที่ทั้งหมด การตั้งค่าที่ไม่ขัดแย้งกันจะคงไว้ทั้งหมด สำหรับ[นโยบาย](/policies#precedence)จากไฟล์ส่วนกลางและไฟล์โปรเจกต์ จะประเมินในลำดับย้อนกลับ และนโยบายของระบบมีลำดับสูงกว่าทั้งหมด

## Schema

schema การกำหนดค่าฉบับสมบูรณ์ของ OpenCode อยู่ที่ [opencode.ai/config.json](https://opencode.ai/config.json)

เพิ่มฟิลด์ `$schema` ลงในไฟล์กำหนดค่าเพื่อเปิดใช้การตรวจสอบความถูกต้องและการเติมข้อความอัตโนมัติในเอดิเตอร์ที่รองรับ JSON Schema:

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json"
}
```

ใช้ schema เป็นแหล่งอ้างอิงหลักสำหรับฟิลด์ที่มีให้ใช้ ค่าที่ยอมรับ และโครงสร้างการกำหนดค่าแบบซ้อน

### Shell

ตั้งค่า shell ที่เทอร์มินัลและเครื่องมือ shell ใช้

```jsonc
{
  "shell": "/bin/zsh",
}
```

### โมเดล

ตั้งค่าโมเดลเริ่มต้นในรูปแบบ `provider/model` ปัจจุบันค่าเริ่มต้นระดับบนสุดยังไม่เก็บ `#variant` ไว้ แต่การอ้างอิงโมเดลในเอเจนต์และคำสั่งเลือก variant ได้

```jsonc
{
  "model": "anthropic/claude-sonnet-4-5",
}
```

ดูการเลือกโมเดลและโมเดลภายในเครื่องได้ที่[คู่มือโมเดล](/models)

### เอเจนต์เริ่มต้น

เลือกเอเจนต์หลักที่จะใช้เมื่อเซสชันไม่ได้เลือกเอเจนต์ไว้อย่างชัดเจน

```jsonc
{
  "default_agent": "build",
}
```

ดูเอเจนต์ในตัวและเอเจนต์แบบกำหนดเองได้ที่[คู่มือเอเจนต์](/agents)

### การอัปเดต

ควบคุมการตรวจหาอัปเดตจากการกำหนดค่าส่วนกลาง ตั้ง `update` เป็น `"disable"` เพื่อข้ามการตรวจหา `"notify"` เพื่อแสดงอัปเดตที่มีก่อนติดตั้ง หรือ `"auto"` เพื่อติดตั้งอัปเดตโดยอัตโนมัติ หากไม่ระบุ `update` จะมีค่าเริ่มต้นเป็น `"notify"`

การติดตั้งอัตโนมัติจะไม่รีสตาร์ตเซิร์ฟเวอร์ที่กำลังทำงานอยู่ ให้รีสตาร์ตด้วยตนเองเพื่อเริ่มใช้อัปเดตที่ติดตั้งแล้ว ค่าที่ตั้งในระดับโปรเจกต์จะถูกละเว้น

```jsonc
{
  "update": "notify",
}
```

### การแชร์

ตั้งค่านโยบายการแชร์เซสชัน OpenCode ยอมรับฟิลด์นี้ แต่ยังไม่รองรับการแชร์เซสชัน

```jsonc
{
  "share": "manual",
}
```

ดูรายละเอียดเพิ่มเติมได้ที่[คู่มือการแชร์](/sharing)

### ชื่อผู้ใช้

ตั้งค่าชื่อผู้ใช้ OpenCode ยอมรับฟิลด์นี้ แต่ไม่แสดงชื่อนี้ในบทสนทนา

```jsonc
{
  "username": "alice",
}
```

### สิทธิ์

กำหนดกฎแบบเรียงลำดับเพื่ออนุญาต ปฏิเสธ หรือถามก่อนที่เอเจนต์จะใช้เครื่องมือกับทรัพยากรที่ตรงกัน

```jsonc
{
  "permissions": [
    {
      "action": "shell",
      "resource": "git push *",
      "effect": "ask",
    },
  ],
}
```

ดูการจับคู่กฎและ action ที่มีให้ใช้ได้ที่[คู่มือสิทธิ์](/permissions)

### นโยบาย

อนุญาตหรือปฏิเสธการใช้ผู้ให้บริการ ปฏิเสธการตรวจสอบสิทธิ์แบบเด็ดขาด หรือบล็อกเซิร์ฟเวอร์ MCP สกิล หรือปลั๊กอิน ด้วย statement แบบเรียงลำดับที่การกำหนดค่าในขอบเขตที่กว้างกว่าสามารถแทนที่ได้

```jsonc
{
  "policies": [
    { "action": "provider.use", "resource": "*", "effect": "deny" },
    { "action": "provider.use", "resource": "anthropic", "effect": "allow" },
    { "action": "tool.use", "resource": "shell:git push *", "effect": "deny" },
  ],
}
```

ดูการจับคู่ ลำดับความสำคัญระหว่างไฟล์กำหนดค่า และนโยบายที่จัดการผ่าน Console ได้ที่[คู่มือนโยบาย](/policies)

### เอเจนต์

แทนที่เอเจนต์ในตัว หรือกำหนดเอเจนต์เฉพาะทางที่มีโมเดล คำแนะนำ โหมด และสิทธิ์ของตัวเอง

```jsonc
{
  "agents": {
    "reviewer": {
      "description": "Review changes without editing files",
      "mode": "subagent",
      "system": "Focus on correctness, security, and missing tests.",
      "permissions": [{ "action": "edit", "resource": "*", "effect": "deny" }],
    },
  },
}
```

ดูตัวเลือกทั้งหมดของเอเจนต์และเอเจนต์แบบไฟล์ได้ที่[คู่มือเอเจนต์](/agents)

### สแนปช็อต

เปิดหรือปิดสแนปช็อตระบบไฟล์ที่ใช้สำหรับการเลิกทำ (undo) และการย้อนกลับ (revert)

```jsonc
{
  "snapshots": false,
}
```

ดูพฤติกรรมการเลิกทำและทำซ้ำ (redo) ได้ที่[คู่มือสแนปช็อต](/snapshots)

### Watcher

ละเว้นไฟล์และไดเรกทอรีที่ไม่ควรทำให้เกิดการอัปเดตระบบไฟล์

```jsonc
{
  "watcher": {
    "ignore": ["dist/**", "coverage/**"],
  },
}
```

### ตัวจัดรูปแบบโค้ด

จัดรูปแบบไฟล์หลังจากเครื่องมือ `write`, `edit` หรือ `patch` แก้ไขไฟล์ ตั้ง `formatter` เป็น `true` เพื่อเปิดใช้ตัวจัดรูปแบบในตัวที่มีอยู่

```jsonc
{
  "formatter": true,
}
```

ดูตัวจัดรูปแบบในตัวและแบบกำหนดเองได้ที่[คู่มือตัวจัดรูปแบบโค้ด](/formatters)

### สื่อ

ควบคุมวิธีปรับขนาดหรือปฏิเสธรูปภาพขนาดใหญ่เกินกำหนดที่เครื่องมือ `read` โหลดมา ก่อนส่งไปยังโมเดล

```jsonc
{
  "media": {
    "image": {
      "auto_resize": true,
      "max_width": 2000,
      "max_height": 2000,
      "max_base64_bytes": 5242880,
    },
  },
}
```

ดูการประมวลผลรูปภาพและขีดจำกัดได้ที่[คู่มือไฟล์แนบ](/attachments)

### เอาต์พุต

ตั้งค่าจำนวนบรรทัดและจำนวนไบต์สูงสุดที่เก็บไว้จากผลลัพธ์ของเครื่องมือ

```jsonc
{
  "tool_output": {
    "max_lines": 2000,
    "max_bytes": 51200,
  },
}
```

### การค้นหา

เลือกวิธีที่ OpenCode ค้นหาเว็บ ใช้ `"random"` เพื่อเลือกผู้ให้บริการที่ใช้งานได้โดยอัตโนมัติ

```jsonc
{
  "websearch": {
    "provider": "random",
  },
}
```

ดูผู้ให้บริการ ข้อมูลรับรอง การเลือก ขีดจำกัดอัตรา (rate limit) และการปิดการค้นหาได้ที่[คู่มือการค้นหาเว็บ](/websearch)

### MCP

กำหนดค่าเซิร์ฟเวอร์ Model Context Protocol ทั้งแบบภายในเครื่องและระยะไกล เซิร์ฟเวอร์แต่ละตัวสามารถแทนที่ค่าหมดเวลา (timeout) ส่วนกลางได้

```jsonc
{
  "mcp": {
    "servers": {
      "playwright": {
        "type": "local",
        "command": ["bunx", "@playwright/mcp"],
      },
    },
  },
}
```

ดูเซิร์ฟเวอร์ระยะไกล OAuth ตัวแปรสภาพแวดล้อม และค่าหมดเวลาได้ที่[คู่มือ MCP](/mcp-servers)

### การบีบอัดบริบท

ควบคุมการบีบอัดบริบทอัตโนมัติ และปริมาณบริบทล่าสุดที่จะคงไว้

```jsonc
{
  "compaction": {
    "auto": true,
    "keep": {
      "tokens": 15000,
    },
    "buffer": 20000,
  },
}
```

ค่าเริ่มต้นยังคงเป็นการสรุปภายในเครื่อง หากต้องการใช้การบีบอัดบริบทแบบเนทีฟของผู้ให้บริการทั้งกับคำขอแบบอัตโนมัติและแบบสั่งเอง ให้ตั้งนโยบายระดับผู้ให้บริการหรือระดับโมเดล:

```jsonc
{
  "providers": {
    "openai": {
      "settings": { "compaction": { "type": "native" } },
      "models": {
        "gpt-4.1": { "settings": { "compaction": { "type": "summary" } } },
      },
    },
  },
}
```

การตั้งค่าระดับโมเดลจะแทนที่การตั้งค่าระดับผู้ให้บริการ การบีบอัดบริบทอัตโนมัติใช้งบประมาณอินพุตที่ใช้ได้ของโมเดลที่เลือก checkpoint ของผู้ให้บริการจะเก็บข้อความล่าสุดของผู้ใช้ไว้ภายในงบประมาณ `compaction.keep.tokens` เดียวกับที่การสรุปภายในเครื่องใช้สำหรับส่วนท้ายที่คงไว้ การตั้ง `compaction.auto: false` ที่ระดับบนสุดจะปิดการบีบอัดบริบทอัตโนมัติครั้งใหม่ โดยไม่ทิ้ง checkpoint ที่ติดตั้งไว้แล้ว ดูการจัดงบประมาณและการกู้คืนเมื่อบริบทล้นได้ที่[คู่มือการบีบอัดบริบท](/compaction)

### การอุ่นเครื่องเซสชัน

อุ่นเครื่องเซสชันโมเดลที่เพิ่งใช้งานไว้ด้วยคำขอชั่วคราวเป็นระยะ การอุ่นเครื่องปิดอยู่โดยค่าเริ่มต้น ตั้งเป็น `true` เพื่อใช้ช่วงเวลาว่าง 4 นาทีและช่วงเวลาใช้งาน 30 นาที

```jsonc
{
  "warming": {
    "prompt": "Do not perform any work. Reply with exactly: OK",
    "interval": "4 minutes",
    "duration": "30 minutes",
  },
}
```

ดูพฤติกรรมของคำขอ การปรับแต่ง และข้อควรพิจารณาด้านค่าใช้จ่ายได้ที่[คู่มือการอุ่นเครื่องเซสชัน](/warming)

### สกิล

เพิ่มไดเรกทอรีหรือ URL ที่ OpenCode ควรค้นหาสกิลของเอเจนต์

```jsonc
{
  "skills": ["./team-skills", "https://example.com/.well-known/skills/"],
}
```

ดูโครงสร้างของสกิลและการค้นพบอัตโนมัติภายใต้ `.opencode/skills/` ได้ที่[คู่มือสกิล](/skills)

### คำสั่ง

กำหนดคำสั่งสแลช (slash command) ที่นำกลับมาใช้ซ้ำได้ในรูปแบบเทมเพลตพรอมต์ที่มีชื่อ

```jsonc
{
  "commands": {
    "review": {
      "description": "Review the current changes",
      "template": "Review the current diff for correctness and missing tests.",
    },
  },
}
```

ดูอาร์กิวเมนต์ โมเดล เอเจนต์ และคำสั่งแบบไฟล์ได้ที่[คู่มือคำสั่ง](/commands)

### คำแนะนำ

ประกาศไฟล์คำแนะนำ (instructions) เพิ่มเติม glob หรือ URL OpenCode ยอมรับฟิลด์นี้ แต่ไม่โหลดรายการในฟิลด์ ให้ใช้ `AGENTS.md` สำหรับคำแนะนำ

```jsonc
{
  "instructions": ["CONTRIBUTING.md", "docs/guidelines/*.md"],
}
```

ดูคำแนะนำของโปรเจกต์และ `AGENTS.md` ได้ที่[คู่มือคำแนะนำ](/instructions)

### ไดเรกทอรีอ้างอิง

ทำให้ไดเรกทอรีภายในเครื่องหรือ repository ของ Git ใช้งานได้ในฐานะบริบทเสริมที่มีชื่อ

```jsonc
{
  "references": {
    "docs": {
      "path": "../product-docs",
      "description": "Product behavior and terminology",
    },
    "effect": {
      "repository": "Effect-TS/effect",
      "branch": "main",
    },
  },
}
```

ดูรูปแบบย่อ การมองเห็น และการแปลงพาธได้ที่[คู่มือไดเรกทอรีอ้างอิง](/references)

### Worktree

ตั้งค่าไดเรกทอรีหลักสำหรับ worktree ภายในเครื่องที่สร้างใหม่ OpenCode จะต่อท้ายด้วยชื่อ worktree ที่ขอหรือที่สร้างขึ้น

```jsonc
{
  "worktree": {
    "directory": "../worktrees",
  },
}
```

พาธแบบสัมพัทธ์จะอ้างอิงจาก checkout หลัก (canonical checkout) ที่บันทึกไว้ของโปรเจกต์ ซึ่งใช้เหมือนกันทั้งการกำหนดค่าส่วนกลางและการกำหนดค่าโปรเจกต์ พาธแบบสัมบูรณ์จะใช้ตามที่ระบุ และ `~/` จะอ้างอิงจากโฮมไดเรกทอรีของผู้ใช้

ตัวอย่างเช่น การกำหนดค่าส่วนกลางนี้จะวาง worktree ใหม่ไว้ใต้ไดเรกทอรี `.lane/trees/` ของแต่ละโปรเจกต์:

```jsonc
{
  "worktree": {
    "directory": ".lane/trees",
  },
}
```

หากไม่ได้ตั้งค่านี้ การสร้าง worktree จะใช้ไดเรกทอรีข้อมูลของเซิร์ฟเวอร์ภายใต้ `worktree/<first-six-project-ID-characters>` การสร้างและรีเฟรช worktree จะโหลดการกำหนดค่าจาก checkout หลักที่บันทึกไว้ของโปรเจกต์ รวมถึงกรณีที่ clone อื่นใช้ ID โปรเจกต์เดียวกัน การเปลี่ยนค่านี้จะไม่ย้าย worktree ที่มีอยู่แล้ว

Git เป็นค่าเริ่มต้นในตัว [ปลั๊กอิน](/build/plugins#worktrees)ที่ลงทะเบียนกลยุทธ์ (strategy) จะกลายเป็นค่าเริ่มต้นในรันไทม์ของปลั๊กอินนั้นโดยอัตโนมัติ การดำเนินการระดับโปรเจกต์ใช้รันไทม์ของ checkout หลัก ตัวเลือกเฉพาะของแต่ละกลยุทธ์เป็นของปลั๊กอินนั้น ไม่ได้อยู่ในออบเจกต์การกำหนดค่า `worktree`

### ปลั๊กอิน

โหลดปลั๊กอินจากแพ็กเกจหรือไดเรกทอรีปลั๊กอินภายในเครื่อง ใช้รูปแบบออบเจกต์เมื่อปลั๊กอินรับตัวเลือก

```jsonc
{
  "plugins": [
    "opencode-example-plugin",
    {
      "package": "./plugins/local",
      "options": {
        "enabled": true,
      },
    },
  ],
}
```

ดูการโหลดและการกำหนดค่าปลั๊กอินได้ที่[คู่มือปลั๊กอิน](/plugins)

### ผู้ให้บริการ

กำหนดค่าผู้ให้บริการ และเพิ่มหรือแทนที่โมเดล การตั้งค่าคำขอ header และ variant ของโมเดล

```jsonc
{
  "providers": {
    "openai": {
      "models": {
        "gpt-5.2-custom": {
          "modelID": "gpt-5.2",
          "name": "GPT-5.2 Custom",
          "limit": {
            "context": 200000,
            "output": 32000,
          },
        },
      },
    },
  },
}
```

`settings.transport: "websocket"` ของผู้ให้บริการจะเลือกใช้ WebSocket ของเซสชันสำหรับผู้ให้บริการนั้น

ดูข้อมูลรับรอง endpoint แบบกำหนดเอง แพ็กเกจผู้ให้บริการ transport แบบ WebSocket และการกำหนดค่าโมเดลได้ที่[คู่มือผู้ให้บริการ](/providers)
