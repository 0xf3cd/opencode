---
title: "สแนปช็อต"
---

สแนปช็อตช่วยให้ย้อนการเปลี่ยนแปลงล่าสุดของทั้งบทสนทนาและไฟล์ไปพร้อมกันได้ ใช้สแนปช็อตเพื่อแก้ไขงานล่าสุด แต่สำหรับงานสำคัญให้ใช้ Git commit หรือสำรองข้อมูลไว้เสมอ

## ขั้นตอนการทำงาน

รัน `/undo` หลังการตอบกลับที่ต้องการแก้ไข OpenCode จะเตรียมการย้อนกลับ (rollback) คืนค่าไฟล์ที่ได้รับผลกระทบ และนำพรอมต์ที่ถูกนำออกกลับมาไว้ในช่องพิมพ์เพื่อให้คุณแก้ไขได้

```text
/undo

# Edit the restored prompt, then submit it again.
Add validation without changing the public API.
```

เมื่อส่งพรอมต์ที่แก้ไขแล้ว การย้อนกลับที่เตรียมไว้จะได้รับการยืนยัน ก่อนส่ง คุณรัน `/redo` เพื่อยกเลิกการย้อนกลับ และคืนบทสนทนาและไฟล์กลับไปเป็นสภาพก่อน `/undo` ได้

```text
/redo
```

เทอร์มินัลยังมีปุ่มลัดเริ่มต้นให้ด้วย:

| การทำงาน | คำสั่ง | ปุ่มลัด |
| --- | --- | --- |
| เตรียมย้อนกลับข้อความก่อนหน้า | `/undo` | `<leader>u` |
| ยกเลิกการย้อนกลับที่เตรียมไว้ | `/redo` | `<leader>r` |

นอกจากนี้ยังเลือกข้อความก่อนหน้าแล้วเลือก **Revert** เพื่อเตรียมย้อนกลับไปยังจุดนั้นได้

## การบันทึกสแนปช็อต

สำหรับแต่ละขั้นของโมเดล (model step) OpenCode จะพยายามสร้างสแนปช็อตทันทีก่อนเรียกโมเดล และอีกครั้งเมื่อขั้นนั้นบันทึกผลว่าสำเร็จหรือล้มเหลว ข้อความของผู้ช่วยจะบันทึกว่ามีพาธใดเปลี่ยนแปลงระหว่างสแนปช็อตทั้งสอง

```text
before model step ── snapshot A
model edits src/api.ts
step finishes ────── snapshot B ── changed: src/api.ts
```

การบันทึกสแนปช็อตเป็นแบบพยายามให้ดีที่สุด (best effort) หากสแนปช็อตใดสแนปช็อตหนึ่งไม่พร้อมใช้งาน บทสนทนาจะดำเนินต่อไป แต่ขั้นนั้นอาจไม่มีการเปลี่ยนแปลงไฟล์ให้คืนค่า

## ขอบเขต

สแนปช็อตครอบคลุมไดเรกทอรีที่ใช้งานอยู่ของเซสชันภายใน Git worktree เช่น เซสชันที่เปิดใน `packages/app` จะบันทึกไฟล์ที่เข้าเงื่อนไขภายใต้ `packages/app` เท่านั้น ไม่รวมการเปลี่ยนแปลงในส่วนอื่นของ repository

| เนื้อหา | บันทึก | ตัวอย่าง |
| --- | --- | --- |
| ไฟล์ที่ Git ติดตามในไดเรกทอรีที่ใช้งานอยู่ | ใช่ | `packages/app/src/app.tsx` |
| ไฟล์ที่ไม่ได้ติดตามและไม่ถูก ignore ขนาดไม่เกิน 2 MiB ต่อไฟล์ | ใช่ | `packages/app/notes.txt` |
| ไฟล์ที่ Git ignore | ไม่ | `packages/app/dist/app.js` |
| ไฟล์ที่ไม่ได้ติดตามแต่ละไฟล์ที่ใหญ่กว่า 2 MiB | ไม่ | `packages/app/debug.log` |
| ไฟล์นอกไดเรกทอรีที่ใช้งานอยู่ | ไม่ | `packages/server/src/index.ts` |
| เมตาดาตาของ Git และผลข้างเคียงอื่น ๆ | ไม่ | commit, branch, ฐานข้อมูล หรือโปรเซส |

สแนปช็อตของระบบไฟล์ต้องใช้ Git repository หากอยู่นอก repository คำสั่ง `/undo` ยังย้อนประวัติบทสนทนาได้ แต่คืนค่าไฟล์ไม่ได้

## การคืนค่า

การย้อนกลับจะคืนค่าเฉพาะพาธที่เป็นผลจากขั้นของผู้ช่วยหลังจุดในบทสนทนาที่เลือก แต่ละพาธจะกลับไปเป็นสภาพก่อนขั้นแรกที่ถูกย้อน ไฟล์ที่สร้างขึ้นในขั้นเหล่านั้นจะถูกลบหากไฟล์นั้นยังไม่มีอยู่ในตอนนั้น

| ลำดับเวลา | `src/api.ts` | `src/new.ts` |
| --- | --- | --- |
| จุดที่เลือก | เวอร์ชัน A | ไม่มี |
| ขั้นของผู้ช่วยหลังจากนั้น | เวอร์ชัน B | สร้างขึ้น |
| หลังย้อนกลับ | เวอร์ชัน A | ถูกลบ |

พาธที่ไม่ได้เป็นผลจากขั้นเหล่านั้นจะไม่ถูกแตะต้อง การแก้ไขปัจจุบันในพาธที่ได้รับผลกระทบอาจถูกเขียนทับ ดังนั้นให้ตรวจสอบสรุปการคืนค่าและ `git diff` ก่อนทำงานต่อ

```sh
git diff --stat
git diff
```

## พื้นที่จัดเก็บ

OpenCode เก็บสแนปช็อตไว้ในเครื่องในฐานข้อมูลอ็อบเจกต์ Git ภายในที่แยกต่างหากใต้ไดเรกทอรีข้อมูลของ OpenCode การบันทึกสแนปช็อตจะไม่สร้าง commit ไม่ย้าย branch และไม่ได้ตั้งใจเปลี่ยน index ของ repository ของคุณ

```sh
# Your repository remains an ordinary dirty worktree after capture.
git status --short
```

อ็อบเจกต์สแนปช็อตอาจมีเนื้อหาทั้งหมดของไฟล์ที่ติดตามและไฟล์ที่ไม่ได้ติดตามที่เข้าเงื่อนไข ให้ถือว่าไดเรกทอรีข้อมูลของ OpenCode เป็นข้อมูลในเครื่องที่ละเอียดอ่อน

## การตั้งค่า

สแนปช็อตเปิดใช้งานโดยค่าเริ่มต้น ตั้งค่า `snapshots` เป็น `false` ใน[การกำหนดค่า](/config#snapshots)เพื่อหยุดบันทึกสแนปช็อตของระบบไฟล์จากนี้ไป

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "snapshots": false,
}
```

การปิดสแนปช็อตจะไม่ลบสแนปช็อตที่จัดเก็บไว้แล้ว การย้อนบทสนทนายังใช้งานได้ แต่หากไม่มีสถานะระบบไฟล์ที่บันทึกไว้ ก็จะคืนค่าการเปลี่ยนแปลงไฟล์ที่เกี่ยวข้องไม่ได้

## ความปลอดภัย

สแนปช็อตเป็นเครื่องมืออำนวยความสะดวก ไม่ใช่ทรานแซกชันหรือการสำรองข้อมูล:

- คำสั่ง shell อาจเปลี่ยนแปลงบริการ โปรเซส ทรัพยากรเครือข่าย ฐานข้อมูล สถานะ Git เอาต์พุตที่ถูก ignore หรือไฟล์นอกไดเรกทอรีที่ใช้งานอยู่ การคืนค่าสแนปช็อตไม่ได้ย้อนผลเหล่านั้น
- งานที่ถูกขัดจังหวะหรือล้มเหลวอาจทิ้งการเปลี่ยนแปลงไว้ เมื่อการบันทึกล้มเหลวหรือไม่มีคู่สแนปช็อตที่ใช้ได้
- การคืนค่าพาธที่ได้รับผลกระทบจะเขียนทับเนื้อหาปัจจุบันของพาธนั้น การยกเลิกการย้อนกลับที่เตรียมไว้ก็อาจเขียนทับการแก้ไขที่ทำภายหลังได้เช่นกัน
- OpenCode ปฏิเสธการย้อนกลับขณะที่เซสชันกำลังทำงาน แต่เอดิเตอร์และคำสั่งภายนอกยังเปลี่ยนแปลง worktree ได้ในช่วงระหว่างการบันทึกและการคืนค่า
- การยืนยันการย้อนกลับจะนำข้อความออกจากมุมมองบทสนทนาที่ใช้งานอยู่เท่านั้น ไม่ได้ลบออกจากประวัติเซสชันที่บันทึกถาวรหรือพื้นที่จัดเก็บสแนปช็อตที่มีอยู่ จึงไม่ใช่การลบข้อมูลอย่างปลอดภัย

ให้ commit หรือสำรองงานสำคัญก่อนใช้ `/undo` กับ worktree ที่มีการเปลี่ยนแปลงค้างอยู่
