รัน CLI ในโปรเจกต์เพื่อเปิดอินเทอร์เฟซเต็มหน้าจอบนเทอร์มินัล:

```bash
opencode
```

ส่งพาธไดเรกทอรีเพื่อทำงานในโปรเจกต์อื่น:

```bash
opencode ~/code/my-project
```

เทอร์มินัลที่แนะนำ:

- [Ghostty](https://ghostty.org)
- [WezTerm](https://wezterm.org)
- [Alacritty](https://alacritty.org)
- [Kitty](https://sw.kovidgoyal.net/kitty/)

เทอร์มินัลที่รองรับ truecolor จะแสดงสีของธีมได้แม่นยำที่สุด ส่วนเทอร์มินัลที่ไม่รองรับจะใช้สีที่ใกล้เคียงที่สุดจากชุดสีที่มีอยู่

## การทำงานอัตโนมัติ

ใช้ `opencode run` เพื่อส่งพรอมต์โดยไม่ต้องเปิดอินเทอร์เฟซแบบโต้ตอบ คำสั่งนี้ออกแบบมาสำหรับสคริปต์ งาน CI และเวิร์กโฟลว์อื่น ๆ ที่ต้องการเอาต์พุตของโมเดลในเทอร์มินัลโดยตรง

```bash
opencode run "Explain this repository"
```

## Mini

ใช้ `opencode mini` เพื่อเริ่มอินเทอร์เฟซแบบโต้ตอบขนาดเล็กของ OpenCode แทน TUI แบบเต็มหน้าจอ

```bash
opencode mini
```

รัน `opencode mini --help` เพื่อดูตัวเลือกด้านเซสชัน โมเดล เอเจนต์ พรอมต์ และการเล่นซ้ำ (replay)

## บริการเบื้องหลัง

โดยค่าเริ่มต้น OpenCode จะค้นหาหรือเริ่มเซิร์ฟเวอร์เบื้องหลังที่ใช้ร่วมกันหนึ่งตัวสำหรับบัญชีผู้ใช้ของคุณ ไคลเอนต์ OpenCode ทุกตัวในเครื่องจะเชื่อมต่อกับเซิร์ฟเวอร์นี้ ซึ่งเป็นผู้ดูแลเซสชัน การกำหนดค่า การผสานรวม สิทธิ์ และการรันเครื่องมือ

ใช้ `--standalone` เพื่อรันด้วยเซิร์ฟเวอร์ส่วนตัว หรือใช้ `--server` เพื่อเชื่อมต่อกับ URL ของเซิร์ฟเวอร์ที่ระบุ:

```bash
opencode --standalone
opencode --server http://localhost:4096
```

หากต้องการให้คำสั่ง CLI ใช้เซิร์ฟเวอร์ส่วนตัวเป็นค่าเริ่มต้นแทนการเริ่มบริการที่ใช้ร่วมกัน ให้ปิดใช้งานบริการ:

```bash
opencode service set disabled true
opencode
```

คำสั่งนี้จะหยุดบริการเบื้องหลังที่กำลังทำงานอยู่ `--server` ยังคงเชื่อมต่อกับเซิร์ฟเวอร์ที่เลือกไว้อย่างชัดเจนได้ และ `opencode service start` ยังคงเริ่มบริการที่ใช้ร่วมกันได้เมื่อสั่งโดยตรง หากต้องการกลับไปใช้บริการโดยอัตโนมัติ ให้รัน `opencode service unset disabled` การจับคู่ (pairing) ต้องใช้บริการที่ใช้ร่วมกัน จึงใช้งานไม่ได้ขณะที่ปิดบริการอยู่

ดูวิธีวินิจฉัยบริการที่ใช้ร่วมกันได้ที่[การแก้ไขปัญหา](/troubleshooting) และดู endpoint ของเซิร์ฟเวอร์ได้ที่[เอกสารอ้างอิง API](/api)

## พาธ

พิมพ์พาธในเครื่องที่ต้องการเพื่อนำไปใช้กับเครื่องมืออื่น:

```bash
opencode debug paths db
sqlite3 "$(opencode debug paths db)"
```

ตัวเลือกพาธ (selector) ซึ่งไม่บังคับ รับค่า `db`, `home`, `data`, `config`, `cache`, `state`, `tmp`, `bin`, `log` หรือ `repos` และจะพิมพ์เฉพาะพาธตามด้วยการขึ้นบรรทัดใหม่ พาธฐานข้อมูลจะเป็นไปตามช่องทางรีลีส (release channel) และ `OPENCODE_DB` ค่าที่แทนที่พาธฐานข้อมูลแบบสัมพัทธ์จะอ้างอิงจากไดเรกทอรีข้อมูล ส่วน `:memory:` จะพิมพ์ออกมาตามเดิม คำสั่งนี้ไม่เริ่มเซิร์ฟเวอร์และไม่เปิดฐานข้อมูล

หากไม่ระบุ selector คำสั่งจะแสดงพาธทั้งหมดพร้อมป้ายกำกับ:

```bash
opencode debug paths
```

## ถอนการติดตั้ง

ดูตัวอย่างไฟล์และการติดตั้งที่จะถูกลบ:

```bash
opencode uninstall --dry-run
```

รัน `opencode uninstall` เพื่อยืนยันการลบ OpenCode จะหยุดบริการเบื้องหลังที่ลงทะเบียนไว้และเทอร์มินัลแบบถาวรก่อนลบไดเรกทอรีแคชส่วนกลาง ซึ่งใช้ร่วมกันระหว่างทุกเวอร์ชันและทุกช่องทางของ OpenCode ข้อมูลเซสชัน การกำหนดค่า และสถานะจะไม่ถูกลบเด็ดขาด

- `--force` (`-f`) ข้ามการยืนยัน ใช้สำหรับการลบแบบไม่โต้ตอบ
- การติดตั้งผ่านตัวจัดการแพ็กเกจจะใช้ตัวจัดการแพ็กเกจที่ตรวจพบ ส่วนการติดตั้งผ่าน curl จะพิมพ์คำสั่งสุดท้ายสำหรับลบไฟล์ปฏิบัติการด้วยตนเอง
