เชื่อมต่อผู้ให้บริการใน TUI แล้วเลือกโมเดลของผู้ให้บริการนั้น:

```text
/connect
/models
```

`/connect` แสดงรายการการผสานรวมที่ใช้ได้จากเซิร์ฟเวอร์และโปรเจกต์ปัจจุบัน เลือกผู้ให้บริการ เลือกวิธียืนยันตัวตนหากมีมากกว่าหนึ่งวิธี แล้วทำตามขั้นตอนที่แสดง

## TUI

TUI รองรับคีย์ API, OAuth และคำสั่งยืนยันตัวตนของผู้ให้บริการ OAuth จะเปิด URL สำหรับการอนุญาตหรือแสดงรหัสให้ป้อน กด `o` เพื่อเปิด URL และกด `c` เพื่อคัดลอกรายละเอียดการอนุญาต

```text
/connect
# Select OpenAI, then Codex device code (legacy).
```

รัน `/connect` อีกครั้งเพื่อเพิ่มบัญชีอื่น การเลือกผู้ให้บริการที่เชื่อมต่อไว้แล้วจะเปิดรายการบัญชีของผู้ให้บริการนั้น ซึ่งคุณสามารถเปิดใช้งาน เปลี่ยนชื่อ หรือลบบัญชีที่บันทึกไว้ได้

## CLI

ใช้ `auth login` เพื่อใช้วิธีเดียวกันของผู้ให้บริการโดยไม่ต้องเปิด TUI หากไม่ระบุอาร์กิวเมนต์ผู้ให้บริการ คำสั่งจะเปิดตัวเลือกผู้ให้บริการแบบโต้ตอบ

```bash
opencode auth login
```

ส่ง ID หรือชื่อของการผสานรวมเพื่อข้ามตัวเลือกแรก ใช้ `--method key` เพื่อเลือกการป้อนคีย์ API อย่างชัดเจน

```bash
opencode auth login anthropic --method key
```

ID ของวิธียืนยันตัวตนแตกต่างกันไปตามผู้ให้บริการ หากผู้ให้บริการมีมากกว่าหนึ่งวิธี ให้รันคำสั่งโดยไม่ใส่ `--method` เพื่อดูวิธีที่ใช้ได้

```bash
opencode auth login openai
```

การป้อนคีย์ API และฟอร์มของผู้ให้บริการต้องใช้เทอร์มินัลแบบโต้ตอบ วิธี OAuth ที่ให้วางรหัสการอนุญาตก็ต้องใช้เช่นกัน

## วิธียืนยันตัวตน

OpenCode รับข้อมูลรับรองของผู้ให้บริการผ่านวิธีการผสานรวมสี่แบบ:

| วิธี | การทำงาน |
| --- | --- |
| คีย์ API | ขอให้ป้อนค่าลับ แล้วบันทึกเป็นบัญชีผู้ให้บริการ |
| OAuth | ให้ URL สำหรับเบราว์เซอร์ รหัสอุปกรณ์ หรือช่องป้อนรหัสการอนุญาต จากนั้นบันทึกโทเค็นและรีเฟรชโทเค็นเมื่อรองรับ |
| คำสั่ง | รันคำสั่งยืนยันตัวตนที่ผู้ให้บริการกำหนด แล้วบันทึกเอาต์พุตมาตรฐานเป็นคีย์ |
| สภาพแวดล้อม | อ่านตัวแปรที่รองรับจากโปรเซสเซิร์ฟเวอร์โดยไม่บันทึกไว้ |

ผู้ให้บริการสามารถเพิ่มฟอร์มให้กับวิธีคีย์ API และ OAuth สำหรับข้อมูลที่จำเป็น เช่น ชื่อทรัพยากร Azure หรือโดเมน GitHub Enterprise โดย CLI และ TUI จะแสดงฟอร์มเหล่านั้นก่อนเริ่มยืนยันตัวตน

## สภาพแวดล้อม

ตั้งค่าตัวแปรสภาพแวดล้อมที่ผู้ให้บริการรองรับบนโปรเซสเซิร์ฟเวอร์ที่รันคำขอไปยังโมเดล สำหรับเซิร์ฟเวอร์ส่วนตัวที่ใช้ครั้งเดียว ให้ส่งตัวแปรตอนเริ่มโหมดสแตนด์อโลน

```bash
ANTHROPIC_API_KEY=sk-ant-... opencode --standalone
```

สำหรับเซิร์ฟเวอร์เบื้องหลังที่ใช้ร่วมกัน ให้เพิ่มตัวแปรลงในสภาพแวดล้อมที่ OpenCode จัดการ การทำเช่นนี้จะหยุดบริการที่กำลังทำงานอยู่ และคำสั่ง OpenCode ถัดไปจะเริ่มบริการด้วยค่าใหม่

```bash
opencode service set env ANTHROPIC_API_KEY sk-ant-...
opencode auth list
```

การเชื่อมต่อผ่านสภาพแวดล้อมจะแสดงใน `auth list` ด้วยประเภท `environment` การเชื่อมต่อเหล่านี้ไม่ใช่บัญชี `auth logout` จึงลบไม่ได้ ให้ยกเลิกการตั้งค่าตัวแปรเพื่อตัดการเชื่อมต่อ บัญชีที่บันทึกไว้มีลำดับความสำคัญสูงกว่าการเชื่อมต่อผ่านสภาพแวดล้อมของการผสานรวมเดียวกัน

```bash
opencode auth list
opencode service unset env ANTHROPIC_API_KEY
```

ผู้ให้บริการคลาวด์บางรายยังใช้ลำดับการค้นหาข้อมูลรับรองแบบเนทีฟจากสภาพแวดล้อม (ambient credential chain) แทนตัวแปรคีย์ API:

- Amazon Bedrock รองรับ AWS default credential chain ซึ่งรวมถึงโปรไฟล์ คีย์การเข้าถึงในสภาพแวดล้อม web identity และข้อมูลรับรองของคอนเทนเนอร์ และยังรองรับ `AWS_BEARER_TOKEN_BEDROCK` ด้วย
- Google Vertex ใช้ Application Default Credentials และโปรเจกต์ที่ระบุได้ เช่น ยืนยันตัวตนด้วย `gcloud auth application-default login` แล้วตั้งค่า `GOOGLE_CLOUD_PROJECT`
- Azure แสดง **Microsoft Entra ID (Azure CLI)** เป็นวิธีเชื่อมต่อเมื่อติดตั้ง `az` ไว้ ให้รัน `az login` ก่อน แล้วเลือกวิธีนั้นใน `/connect` หรือ `auth login azure`

```bash
gcloud auth application-default login
GOOGLE_CLOUD_PROJECT=my-project opencode
```

ดูการตั้งค่าเฉพาะผู้ให้บริการและฝั่งเซิร์ฟเวอร์ได้ที่[ผู้ให้บริการ](/providers)

## บัญชี

การเข้าสู่ระบบด้วยคีย์ API, OAuth หรือคำสั่งที่สำเร็จแต่ละครั้งจะสร้างบัญชีที่บันทึกไว้ บัญชีล่าสุดจะเป็นบัญชีที่ใช้งานอยู่ สลับบัญชีที่ใช้งานได้ด้วยป้ายกำกับหรือ ID ของข้อมูลรับรอง

```bash
opencode auth list
opencode auth switch anthropic work
```

ลบบัญชีที่บันทึกไว้ด้วย `auth logout` ทั้งสองคำสั่งจะเปิดตัวเลือกเมื่อไม่ได้ระบุอาร์กิวเมนต์

```bash
opencode auth logout anthropic work
```

ใน TUI คำสั่ง `/connect` มีการเพิ่ม เปิดใช้งาน เปลี่ยนชื่อ และลบบัญชีที่บันทึกไว้ได้เช่นเดียวกัน

## ที่จัดเก็บ

คีย์ API และโทเค็น OAuth ที่บันทึกไว้จะเก็บอยู่ในฐานข้อมูล SQLite ของเซิร์ฟเวอร์ สำหรับเซิร์ฟเวอร์ในเครื่อง พิมพ์พาธฐานข้อมูลได้ด้วย:

```bash
opencode debug paths db
```

พาธปกติของรีลีสคือ `~/.local/share/opencode/opencode.db` ซึ่ง `XDG_DATA_HOME` ช่องทางรีลีส และ `OPENCODE_DB` อาจเปลี่ยนพาธนี้ได้ โปรดอย่าแก้ไขฐานข้อมูลโดยตรงเพื่อจัดการข้อมูลรับรอง ให้ใช้ `/connect` หรือคำสั่ง `auth` แทน

V2 จะนำเข้าข้อมูลรับรองที่รองรับจาก `auth.json` เดิมในไดเรกทอรีข้อมูลของ OpenCode ระหว่างการย้ายฐานข้อมูล ข้อมูลรับรองที่สร้างใหม่หรืออัปเดตจะเก็บไว้ใน SQLite และจะไม่เขียนกลับไปยังไฟล์นั้น
