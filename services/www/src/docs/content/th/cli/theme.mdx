---
title: "ธีม"
---

OpenCode มาพร้อมธีมในตัวจำนวนมากทั้งสำหรับโหมดสว่างและโหมดมืด เลือกธีมได้ในการตั้งค่า หรือผสมสีในแบบของคุณเอง

## เลือกธีม

กด `Ctrl+P` เลือก **Open settings** แล้วเปิด **Theme** ธีมเริ่มต้นคือ `opencode`

หรือตั้งค่าธีมไว้ใน[การตั้งค่า CLI](/cli/config) ส่วนกลางก็ได้:

```json title="~/.config/opencode/cli.json"
{
  "$schema": "https://opencode.ai/v2/cli.json",
  "theme": {
    "name": "tokyonight",
    "mode": "dark"
  }
}
```

รัน `/themes` เพื่อเปลี่ยนธีมโดยไม่ต้องเปิดการตั้งค่า

## สีของระบบ

เมื่อ OpenCode อ่านชุดสีของเทอร์มินัลได้ ตัวเลือกธีมจะมีธีม `system` ให้เลือก ธีมนี้สร้างสีจากสีพื้นหน้า สีพื้นหลัง และชุดสี ANSI ของเทอร์มินัล

ชื่อธีม `system` หมายถึงการใช้สีที่สร้างจากเทอร์มินัล ส่วนโหมด `system` หมายถึงการใช้รูปลักษณ์สว่างหรือมืดตามเทอร์มินัล

## โหมด

ใช้ `system` เพื่อใช้รูปลักษณ์ตามเทอร์มินัล หรือล็อกธีมไว้ที่โหมดสว่างหรือโหมดมืด:

| โหมด | การทำงาน |
| --- | --- |
| `system` | ใช้รูปลักษณ์สว่างหรือมืดตามที่ตรวจพบจากเทอร์มินัล |
| `dark` | ใช้สีโหมดมืดของธีมเสมอ |
| `light` | ใช้สีโหมดสว่างของธีมเสมอ |

ค่านี้ตรงกับฟิลด์ `mode` ภายใน `theme` ในการกำหนดค่า CLI หากธีมที่กำหนดเองมีเพียงโหมดเดียว OpenCode จะใช้โหมดนั้นเมื่อมีการขอใช้อีกโหมดหนึ่ง

## การเพิ่มธีม

หากต้องการเพิ่มธีมที่ดาวน์โหลดมาหรือได้รับจากผู้อื่น ให้คัดลอกไฟล์ JSON ของธีมไปยังไดเรกทอรีธีมส่วนกลาง:

```bash
cp theme.json ~/.config/opencode/themes/
```

หรือวางธีมไว้ในไดเรกทอรี `.opencode/themes` ของโปรเจกต์เพื่อให้ใช้ได้เฉพาะในโปรเจกต์นั้น

ชื่อไฟล์จะกลายเป็นชื่อธีม เช่น `my-theme.json` จะแสดงเป็น `my-theme` รีสตาร์ต OpenCode หลังเพิ่มไฟล์ แล้วรัน `/themes` เพื่อเลือกธีม

OpenCode อ่านเฉพาะไฟล์ `.json` ธีมที่อยู่ใกล้ไดเรกทอรีปัจจุบันมากกว่าจะแทนที่ธีมส่วนกลางหรือธีมในไดเรกทอรีแม่ที่มีชื่อเดียวกัน

## การใช้ธีมในปลั๊กอิน

[ปลั๊กอิน CLI](/build/plugins/cli) อ่านสีที่ resolve แล้วผ่าน `context.theme` และอ่านโหมดที่ใช้งานอยู่ผ่าน `context.themeMode` ใช้โทเค็นเชิงความหมาย (semantic token) เพื่อให้ปลั๊กอินแสดงผลตามธีมที่เลือก:

```tsx title="Inside a CLI plugin component"
import { usePlugin } from "@opencode/plugin/tui"

function Status() {
  const context = usePlugin()
  return <text fg={context.theme.text.base}>Ready</text>
}
```

API ปลั๊กอิน CLI แบบสาธารณะไม่ได้ลงทะเบียนธีม ให้เพิ่มนิยามธีมที่กำหนดเองด้วยไฟล์ JSON ในไดเรกทอรีข้างต้น

## การสร้างธีม

ใช้ [Theme Tool](https://opencode.ai/theme/) เพื่อสร้างหรือแก้ไขธีม เครื่องมือนี้ช่วยให้เข้าใจโครงสร้าง ปรับแต่ง และกำหนดสีเองได้ง่าย คำอธิบายด้านล่างมีไว้เพื่อใช้อ้างอิง

ธีมแยกโทเค็นเชิงความหมายที่ใช้ร่วมกันออกจากชุดสีเฉพาะของแต่ละโหมด:

| ส่วน | วัตถุประสงค์ |
| --- | --- |
| `base` | โครงสร้างโทเค็นทั้งหมดที่ทุกโหมดใช้ร่วมกัน |
| `light`, `dark` | ชุดเฉดสีที่ครบถ้วนและการแทนที่โทเค็น (ไม่บังคับ) สำหรับโหมดนั้น |

ทุกธีมต้องมี `base` ที่ครบถ้วน และกำหนด `light` หรือ `dark` อย่างน้อยหนึ่งโหมด โหมดต่าง ๆ สืบทอดค่าจาก `base` ในไฟล์ โดยไม่สืบทอดจากธีม OpenCode ในตัวหรือจากโหมดอื่น

ตัวอย่างด้านล่างแสดงเฉพาะส่วนที่เกี่ยวข้องกับแต่ละแนวคิด ใช้ตัวแก้ไขธีมเพื่อสร้างไฟล์ที่ครบถ้วนก่อนปรับแต่ง

### โครงสร้าง

ใส่สีที่ใช้ทั้งสองโหมดไว้ใน `base` แล้วแทนที่ภายใน `light` หรือ `dark` เมื่อจำเป็น:

```json title="theme.json (excerpt)"
{
  "$schema": "https://opencode.ai/theme.json",
  "base": {
    "text": {
      "base": "$hue.neutral.200",
      "muted": "$hue.neutral.400"
    }
  },
  "light": {
    "hue": {}
  },
  "dark": {
    "hue": {},
    "text": {
      "muted": "$hue.neutral.300"
    }
  }
}
```

`base` ที่ครบถ้วนจะกำหนดโทเค็นเชิงความหมายทุกตัว แต่ละโหมดกำหนดเฉดสีที่จำเป็นทั้งหมด และแทนที่ส่วนใดของโครงสร้างโทเค็นใน base ก็ได้

### สีและการอ้างอิง

สีอาจเป็นค่า hex, `"transparent"` หรือการอ้างอิงไปยังสีอื่นในธีม:

```json title="Inside base or a mode"
{
  "text": {
    "base": "#eeeeee",
    "muted": "$hue.neutral.400"
  },
  "border": {
    "base": "$text.muted"
  }
}
```

### เฉดสี

เฉดสี (hue) คือสเกลสีเก้าระดับ ทุกโหมดต้องกำหนดเฉดสีพื้นฐานแปดเฉดและชื่อแทน (alias) สามชื่อ:

| ชนิด | ค่า |
| --- | --- |
| พื้นฐาน | `gray`, `red`, `orange`, `yellow`, `green`, `cyan`, `blue`, `purple` |
| ชื่อแทน | `accent`, `interactive`, `neutral` |
| ระดับ | `100`, `200`, `300`, `400`, `500`, `600`, `700`, `800`, `900` |

กำหนดให้ครบทั้งเก้าระดับสำหรับเฉดสีพื้นฐาน หรือกำหนดให้เฉดสีหนึ่งเป็นชื่อแทนของอีกเฉดสีหนึ่ง:

```json title="Inside light or dark"
{
  "hue": {
    "purple": {
      "100": "#b38ff4",
      "200": "#9d7cd8",
      "300": "#8869bd",
      "400": "#7357a2",
      "500": "#5f4688",
      "600": "#4b356f",
      "700": "#392557",
      "800": "#271640",
      "900": "#17072b"
    },
    "accent": "$hue.purple"
  }
}
```

ระดับของเฉดสีเป็นไปตามทิศทางคอนทราสต์ของโหมด ธีมสว่างเรียงจากเข้มที่ `100` ไปจนถึงอ่อนที่ `900` ส่วนธีมมืดเรียงจากอ่อนที่ `100` ไปจนถึงเข้มที่ `900`

อาร์เรย์ `categorical` ใน `base` กำหนดลำดับเฉดสีที่ใช้แยกแยะเอเจนต์และรายการอื่นที่ซ้ำกัน:

```json title="Inside base"
{
  "categorical": ["accent", "purple", "green", "blue"]
}
```

### โทเค็นเชิงความหมาย

โทเค็นเชิงความหมายกำหนดสีให้กับบทบาทต่าง ๆ ใน UI คอมโพเนนต์จะใช้บทบาทเหล่านี้แทนการเลือกสีโดยตรง

| กลุ่ม | วัตถุประสงค์ |
| --- | --- |
| `text` | ข้อความพื้นฐาน ข้อความรอง การกระทำ ฟิลด์ฟอร์ม สถานะ และข้อความแจ้งผล |
| `background` | พื้นหลังพื้นฐาน พื้นผิวที่ยกระดับ การกระทำ ฟิลด์ฟอร์ม และพื้นสีของการแจ้งผล |
| `border`, `scrollbar` | สีของเส้นขอบและแถบเลื่อน |
| `diff` | สีของส่วนที่เพิ่ม ส่วนที่ลบ บริบท ไฮไลต์ และหมายเลขบรรทัด |
| `syntax` | การไฮไลต์ซอร์สโค้ด |
| `markdown` | องค์ประกอบ Markdown |

ตัวอย่างเช่น `text.muted` ควบคุมข้อความรอง ส่วน `background.raised` กำหนดพื้นผิวที่ยกระดับขึ้นทีละขั้น:

```json title="Inside base"
{
  "text": {
    "base": "$hue.neutral.200",
    "muted": "$hue.neutral.400"
  },
  "background": {
    "base": "$hue.neutral.800",
    "raised": {
      "base": "$hue.neutral.700",
      "high": "$hue.neutral.600",
      "max": "$hue.neutral.500"
    }
  }
}
```

คีย์ของ syntax ได้แก่ `comment`, `keyword`, `function`, `variable`, `string`, `number`, `type`, `operator` และ `punctuation`

คีย์ของ Markdown ได้แก่ `text`, `heading`, `link`, `linkText`, `code`, `blockQuote`, `emphasis`, `strong`, `horizontalRule`, `listItem`, `listEnumeration`, `image`, `imageText` และ `codeBlock`

### การกระทำและสถานะ

การกระทำ (action) มี variant แบบ `primary`, `secondary` และ `destructive` การกระทำและฟิลด์ฟอร์มใช้ `base` และสถานะการโต้ตอบเพิ่มเติมที่ไม่บังคับ:

```json title="Inside base or a mode"
{
  "text": {
    "action": {
      "primary": {
        "base": "$hue.interactive.400",
        "$hovered": "$hue.interactive.300",
        "$disabled": "$hue.neutral.600"
      }
    }
  }
}
```

คีย์สถานะได้แก่ `$hovered`, `$focused`, `$pressed`, `$selected` และ `$disabled` สถานะที่ไม่ได้ระบุจะใช้สี `base` ของการกระทำหรือฟิลด์ฟอร์มนั้น

### พื้นผิวของกล่องโต้ตอบ

แผง กล่องโต้ตอบ เมนู และการแจ้งเตือนแบบ toast เลือกระดับความลึกจาก `background.raised` นอกจากนี้ กล่องโต้ตอบยังแทนที่โทเค็นเชิงความหมายเพิ่มเติมได้ด้วย `@dialog`:

```json title="Inside base or a mode"
{
  "@dialog": {
    "background": {
      "base": "$background.raised.base",
      "action": {
        "primary": {
          "$hovered": "$background.raised.high"
        }
      }
    }
  }
}
```

TUI จะ resolve การอ้างอิงอีกครั้งหลังใช้ `@dialog` โทเค็นที่อ้างอิง `$background.base` จึงเปลี่ยนตามพื้นหลังของกล่องโต้ตอบ `base` ของการกระทำในบริบทนั้นจะเป็นค่าสำรองของสถานะที่ไม่ได้ระบุ ส่วนสถานะที่แทนที่ไว้อย่างชัดเจนยังคงมีผลเหนือกว่า
