ตั้งค่าตัวแปรพร็อกซีมาตรฐาน และยกเว้นที่อยู่ loopback ไม่ให้ผ่านพร็อกซี OpenCode ใช้การเชื่อมต่อ HTTP ภายในเครื่องระหว่าง CLI กับบริการเบื้องหลัง ดังนั้นเมื่อกำหนดค่าพร็อกซีไว้ในสภาพแวดล้อมของ CLI จึงจำเป็นต้องยกเว้นที่อยู่ loopback ด้วย

```bash
export HTTP_PROXY=http://proxy.example.com:8080
export HTTPS_PROXY=http://proxy.example.com:8080
export NO_PROXY=localhost,127.0.0.1,::1

opencode
```

`HTTP_PROXY` ใช้กับปลายทางที่เป็น HTTP และ `HTTPS_PROXY` ใช้กับปลายทางที่เป็น HTTPS โดย URL ของพร็อกซีเองใช้ `http://` ได้กับทั้งสองตัวแปร ส่วน `NO_PROXY` คือรายการโฮสต์และที่อยู่ที่คั่นด้วยเครื่องหมายจุลภาค ซึ่งจะเชื่อมต่อโดยตรงโดยไม่ผ่านพร็อกซี

## บริการเบื้องหลัง

ค่าที่ export ไว้ใน shell จะมีผลกับบริการเบื้องหลังก็ต่อเมื่อบริการนั้นเริ่มทำงานจาก shell ดังกล่าวเท่านั้น ให้บันทึกตัวแปรเหล่านี้ไว้ในการกำหนดค่าของบริการที่ OpenCode จัดการ เพื่อให้การเริ่มบริการครั้งต่อ ๆ ไปใช้การตั้งค่าเครือข่ายเดียวกัน

```bash
opencode service set env HTTP_PROXY http://proxy.example.com:8080
opencode service set env HTTPS_PROXY http://proxy.example.com:8080
opencode service set env NO_PROXY localhost,127.0.0.1,::1
opencode service start
```

การเปลี่ยนตัวแปรสภาพแวดล้อมของบริการที่ OpenCode จัดการจะหยุดบริการที่กำลังทำงานอยู่ จากนั้น `service start` จะเริ่มบริการอีกครั้งด้วยสภาพแวดล้อมใหม่ หาก shell ของ CLI ตั้งค่าพร็อกซีไว้ ให้กำหนด `NO_PROXY` ใน shell นั้นด้วย เพราะตัวแปรของบริการมีผลกับโปรเซสเซิร์ฟเวอร์เท่านั้น ไม่มีผลกับโปรเซส CLI

ลบตัวแปรที่บันทึกไว้ด้วย `service unset env`:

```bash
opencode service unset env HTTPS_PROXY
```

## การยืนยันตัวตน

สำหรับพร็อกซีที่รับข้อมูลรับรองผ่าน URL ให้ใส่ชื่อผู้ใช้และรหัสผ่านไว้ในทุก URL ของพร็อกซีที่ต้องยืนยันตัวตน และหากชื่อผู้ใช้หรือรหัสผ่านมีอักขระอย่าง `@`, `:` และ `/` ให้เข้ารหัสอักขระเหล่านั้นแบบ percent-encoding

```bash
export HTTPS_PROXY='http://user:p%40ssword@proxy.example.com:8080'
```

สำหรับบริการเบื้องหลัง ให้บันทึก URL แบบเต็ม ค่านี้จะเก็บไว้ในการกำหนดค่าส่วนตัวของบริการ และจะแสดงออกมาเมื่อรัน `opencode service get env` จึงโปรดอย่าแชร์เอาต์พุตของคำสั่งนี้

```bash
opencode service set env HTTPS_PROXY 'http://user:p%40ssword@proxy.example.com:8080'
```

## ใบรับรอง

หากพร็อกซีหรือปลายทางใช้ใบรับรองที่ลงนามโดยผู้ออกใบรับรองส่วนตัว (private CA) ให้ตั้งค่า `NODE_EXTRA_CA_CERTS` เป็นไฟล์ PEM ผู้ออกใบรับรองเพิ่มเติมเหล่านี้จะถูกเพิ่มลงในที่เก็บใบรับรองที่เชื่อถือ (trust store) ของรันไทม์เมื่อโปรเซสเริ่มทำงาน

```bash
export NODE_EXTRA_CA_CERTS=/etc/company/ca.pem
opencode --standalone
```

บันทึกพาธไฟล์นี้สำหรับบริการเบื้องหลัง แล้วรีสตาร์ตบริการ:

```bash
opencode service set env NODE_EXTRA_CA_CERTS /etc/company/ca.pem
opencode service start
```

## โปรเซสเบื้องหน้า

`--standalone` และ `serve` ใช้สภาพแวดล้อมของโปรเซสตัวเอง ดังนั้น `opencode service set env` จึงไม่มีผลกับโปรเซสเหล่านี้

```bash
HTTP_PROXY=http://proxy.example.com:8080 \
HTTPS_PROXY=http://proxy.example.com:8080 \
NO_PROXY=localhost,127.0.0.1,::1 \
opencode --standalone
```

ใช้รูปแบบเดียวกันกับเซิร์ฟเวอร์ที่รันแบบเบื้องหน้า:

```bash
HTTPS_PROXY=http://proxy.example.com:8080 \
NO_PROXY=localhost,127.0.0.1,::1 \
opencode serve
```

## ตรวจสอบ

หลังจากตั้งค่าแล้ว ให้ตรวจสอบว่า CLI เชื่อมต่อกับบริการเบื้องหลังได้:

```bash
opencode api get /api/info
```

หาก health check ตอบกลับสำเร็จ แสดงว่าการเชื่อมต่อภายในเครื่องจากไคลเอนต์ไปยังบริการใช้งานได้ หากต้องการตรวจสอบพร็อกซีขาออกและพาธใบรับรองของบริการ ให้ส่งคำขอไปยังผู้ให้บริการตามปกติ
