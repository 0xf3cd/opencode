---
title: "สิทธิ์"
---

สิทธิ์ (permission) ควบคุมว่าเอเจนต์จะดำเนินการ (action) กับ resource ใดได้หรือไม่

## กำหนดค่า

การตั้งค่าที่ใช้กันทั่วไปคือ ให้ถามก่อนรันคำสั่ง shell อนุญาตการตรวจดู Git ที่ทำเป็นประจำ และบล็อกการ push เสมอ เพิ่มกฎตามลำดับต่อไปนี้ลงใน `opencode.jsonc`:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "permissions": [
    { "action": "shell", "resource": "*", "effect": "ask" },
    { "action": "shell", "resource": "git status *", "effect": "allow" },
    { "action": "shell", "resource": "git diff *", "effect": "allow" },
    { "action": "shell", "resource": "git push *", "effect": "deny" },
  ],
}
```

กฎสุดท้ายที่ตรงกันจะมีผล ดังนั้นข้อยกเว้นที่เฉพาะเจาะจงจึงต้องอยู่หลังกฎที่ครอบคลุมกว้าง

<Callout type="warning">
  V1 ใช้ชื่อฟิลด์และชื่อ action ที่ต่างออกไป ใน V2 ให้ใช้ `permissions`, `shell` และ `subagent` แทน `permission`, `bash` และ `task`
</Callout>

## กฎ

แต่ละกฎต้องมีฟิลด์สตริงสามฟิลด์:

| ฟิลด์ | ความหมาย |
| --- | --- |
| `action` | action สิทธิ์ของเครื่องมือ |
| `resource` | ค่าที่ใช้งาน เช่น พาธ คำสั่ง URL คำค้นหา ID ของสกิล หรือ ID ของเอเจนต์ |
| `effect` | `allow`, `deny` หรือ `ask` |

```jsonc
{
  "permissions": [
    { "action": "read", "resource": "*", "effect": "allow" },
    { "action": "read", "resource": "*.env", "effect": "deny" },
  ],
}
```

| Effect | ผลลัพธ์ |
| --- | --- |
| `allow` | ดำเนินการต่อโดยไม่ถาม |
| `deny` | บล็อกการดำเนินการ |
| `ask` | รอการตัดสินใจจากไคลเอนต์ |

หากไม่มีกฎใดตรงกัน OpenCode จะใช้ `ask`

## การจับคู่

action และ resource ใช้ wildcard แบบง่ายที่จับคู่กับค่าทั้งหมด:

| รูปแบบ | สิ่งที่ตรงกัน |
| --- | --- |
| `*` | อักขระศูนย์ตัวขึ้นไป รวมถึง `/` |
| `?` | อักขระหนึ่งตัวพอดี |
| อื่น ๆ | อักขระตัวนั้นตามตัวอักษร |

```jsonc
{
  "permissions": [
    { "action": "edit", "resource": "packages/docs/*.mdx", "effect": "allow" },
  ],
}
```

รูปแบบนี้จับคู่กับพาธที่ normalize แล้วทั้งพาธ เครื่องหมายแบ็กสแลชจะถูก normalize เป็นสแลช และบน Windows การจับคู่จะไม่แยกตัวพิมพ์เล็กและใหญ่

รูปแบบ shell ที่ลงท้ายด้วย ` *` จะตรงกับคำสั่งที่ไม่มีอาร์กิวเมนต์ด้วย:

```jsonc
{ "action": "shell", "resource": "git status *", "effect": "allow" }
```

รูปแบบนี้ตรงกับทั้ง `git status` และ `git status --short`

OpenCode รวมกฎตามลำดับและใช้กฎสุดท้ายที่ตรงกัน การกำหนดค่าที่มีลำดับความสำคัญต่ำกว่าจะโหลดก่อน จากนั้นจึงต่อท้ายด้วยกฎระดับ global และต่อท้ายด้วยกฎของเอเจนต์เป็นลำดับสุดท้าย

```jsonc
{
  "permissions": [
    { "action": "read", "resource": "*", "effect": "allow" },
    { "action": "read", "resource": "secrets/*", "effect": "deny" },
  ],
}
```

การดำเนินการหนึ่งอาจตรวจสอบหลาย resource เช่น แพตช์ที่แก้ไขหลายไฟล์ หากมี `deny` ใดก็ตาม การดำเนินการจะถูกปฏิเสธ หากไม่มีแต่มี `ask` ก็จะถาม หากไม่มีทั้งสองอย่าง การดำเนินการจะได้รับอนุญาต

## Action

ชื่อ action ใน V2 เป็นสตริง ปลั๊กอินจึงกำหนด action เพิ่มเติมได้ ปัจจุบันเครื่องมือในตัวใช้ action และ resource ต่อไปนี้:

| Action | Resource |
| --- | --- |
| `read` | พาธภายในที่สัมพัทธ์กับ Location หรือพาธภายนอกแบบสัมบูรณ์ที่เป็น canonical |
| `edit` | พาธเป้าหมายของ `edit`, `write` และ `patch` |
| `glob` | glob pattern ที่ร้องขอ |
| `grep` | regular expression ที่ร้องขอ ไม่ใช่พาธที่ค้นหา |
| `shell` | สตริงคำสั่งที่ตัวสแกนแยกออกมา คำสั่งแบบผสมอาจได้หลายรายการ |
| `subagent` | ID ของเอเจนต์เป้าหมาย |
| `skill` | ID ของสกิล |
| `question` | `*` |
| `webfetch` | URL ที่ร้องขอ |
| `websearch` | คำค้นหา |
| `external_directory` | ขอบเขตไดเรกทอรีภายนอกแบบ canonical ซึ่งปกติลงท้ายด้วย `/*` |
| `<server>_<tool>` | `*` สำหรับเครื่องมือ MCP อักขระที่ไม่รองรับในชื่อทั้งสองจะกลายเป็น `_` |
| `execute` | `*` ควบคุมว่าจะใช้ Code Mode ได้หรือไม่ ส่วนเครื่องมือที่ถูกเรียกซ้อนภายในจะบังคับใช้กฎของตนเอง |

ตัวอย่างเช่น อนุญาตสกิลเดียวและปฏิเสธสกิลอื่นทั้งหมด:

```jsonc
{
  "permissions": [
    { "action": "skill", "resource": "*", "effect": "deny" },
    { "action": "skill", "resource": "effect", "effect": "allow" },
  ],
}
```

`doom_loop` และ `lsp` ไม่ใช่ action สิทธิ์ของ V2 Core ในปัจจุบัน

## ไดเรกทอรี

พาธที่อยู่นอกทั้ง Location ที่ใช้งานอยู่และ worktree ของโปรเจกต์ (ที่ไม่ใช่ราก) ต้องได้รับการอนุมัติ `external_directory` ก่อนการอนุมัติ `read` หรือ `edit`

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "permissions": [
    { "action": "external_directory", "resource": "~/projects/reference/*", "effect": "allow" },
    { "action": "read", "resource": "~/projects/reference/*", "effect": "allow" },
    { "action": "edit", "resource": "~/projects/reference/*", "effect": "deny" },
  ],
}
```

กฎนี้ใช้กับพาธภายนอกที่ `read`, `edit`, `write` และ `patch` ใช้ ส่วน Shell จะตรวจสอบไดเรกทอรีทำงานภายนอกและไดเรกทอรีที่ตัวสแกนอนุมานได้ ก่อนตรวจสอบ resource ของ `shell`

สำหรับ `external_directory`, `read` และ `edit` ค่าที่ขึ้นต้นด้วย `~`, `~/`, `$HOME` หรือ `$HOME/` จะถูกขยายเมื่อโหลดการกำหนดค่า:

```jsonc
{ "action": "read", "resource": "$HOME/reference/*", "effect": "allow" }
```

resource ของ Shell ยังคงเป็นข้อความคำสั่งดิบ และจะไม่ถูกขยายโฮมไดเรกทอรี

<Callout type="warning">
  `shell` ทำงานด้วยสิทธิ์ด้านระบบไฟล์ โปรเซส และเครือข่ายเท่ากับผู้ใช้บนเครื่องโฮสต์ การอนุมานไดเรกทอรีจากข้อความคำสั่งเป็นแบบพยายามให้ดีที่สุด (best effort) จึงควรใช้ allowlist ของ shell ที่แคบ แทนรูปแบบที่พยายามจดจำคำสั่งอันตรายทุกคำสั่ง
</Callout>

พาธสัมพัทธ์ที่ใช้แก้ไขไฟล์อาจออกนอก Location ที่ใช้งานอยู่ได้ แต่ยังอยู่ภายใน worktree ของโปรเจกต์ ส่วนพาธภายนอกที่ระบุชัดเจนจะถูกแปลงเป็น canonical ก่อนจับคู่ ดังนั้นให้อนุญาตเฉพาะขอบเขตไดเรกทอรีที่เชื่อถือได้เท่านั้น

## ตัวสแกน

เปิดใช้งานตัวสแกน shell แบบพกพา (portable) ที่ยังเป็นรุ่นทดลองด้วย:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "experimental": {
    "portable_shell_scanner": true,
  },
}
```

ตัวสแกนแบบพกพาจะแทนที่ตัวสแกน tree-sitter ที่เป็นค่าเริ่มต้น โดย tree-sitter จะไม่ถูกใช้เป็นตัวสำรองหรือความเห็นที่สอง คำสั่งที่ตัวสแกนแบบพกพาวิเคราะห์ไม่ได้จะส่งคืนข้อผิดพลาดของตัวสแกน ไม่ใช่การปฏิเสธสิทธิ์

แฟล็กนี้เปลี่ยนเฉพาะตัวแยกวิเคราะห์ (parser) ที่ใช้ กฎสิทธิ์ที่มีอยู่ รูปแบบการอนุมัติที่บันทึกไว้ และการอนุมานไดเรกทอรีแบบ best effort ยังคงมีผลเช่นเดิม ไม่มีโหมดการอนุมัติเพิ่มเติมหรือการจำกัดแบบครอบคลุมสำหรับไดเรกทอรีที่ไม่รู้จัก

## ค่าเริ่มต้น

ทุกเอเจนต์ รวมถึงเอเจนต์แบบกำหนดเอง เริ่มต้นด้วยนโยบายพื้นฐานตามลำดับนี้:

```jsonc
[
  { "action": "*", "resource": "*", "effect": "allow" },
  { "action": "external_directory", "resource": "*", "effect": "ask" },
  { "action": "read", "resource": "*.env", "effect": "ask" },
  { "action": "read", "resource": "*.env.*", "effect": "ask" },
  { "action": "read", "resource": "*.env.example", "effect": "allow" },
]
```

เอเจนต์ที่มาพร้อม OpenCode จะต่อท้ายนโยบายเหล่านี้:

| เอเจนต์ | นโยบายเพิ่มเติม |
| --- | --- |
| `build` | อนุญาตให้ถามคำถาม |
| `plan` | อนุญาตให้ถามคำถาม ปฏิเสธการแก้ไข ยกเว้นไฟล์ใต้ `~/.opencode/plan` |
| `general` | ปฏิเสธการถามคำถามและการเริ่มเอเจนต์ย่อย |
| `explore` | ปฏิเสธทุกอย่างยกเว้นการอ่าน glob, grep, การดึงเว็บ และการค้นหาเว็บ ถามก่อนสำหรับไดเรกทอรีภายนอกและการอ่าน `.env` |
| `title` | ปฏิเสธทุก action |
| `summary` | ปฏิเสธทุก action |
| `compaction` | คงนโยบายพื้นฐานไว้ |

OpenCode ยังอนุญาตให้เข้าถึงไดเรกทอรีภายนอกที่ OpenCode จัดการเอง ได้แก่ ไดเรกทอรีเอาต์พุตของเครื่องมือ เอาต์พุตของ shell ไฟล์ชั่วคราว และการกำหนดค่าระดับ global แต่ action ที่อยู่เบื้องหลัง เช่น `read` หรือ `edit` ยังคงใช้กฎของตนเอง กฎระดับ global และกฎของเอเจนต์ที่มาทีหลังสามารถแทนที่ค่าเริ่มต้นเหล่านี้ได้

## เอเจนต์

วางกฎที่ใช้ร่วมกันไว้ที่ระดับบนสุด และวางกฎที่แคบกว่าไว้ใต้ `agents.<id>.permissions`:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "permissions": [
    { "action": "shell", "resource": "*", "effect": "ask" },
    { "action": "shell", "resource": "git status *", "effect": "allow" },
  ],
  "agents": {
    "reviewer": {
      "description": "Review code without changing it",
      "mode": "subagent",
      "permissions": [
        { "action": "edit", "resource": "*", "effect": "deny" },
      ],
    },
  },
}
```

กฎของเอเจนต์จะต่อท้ายหลังกฎระดับ global โดยไม่แทนที่อาร์เรย์ระดับ global เอเจนต์ย่อยแบบกำหนดเองใช้สิทธิ์ของตนเอง ไม่ใช่ส่วนย่อยของสิทธิ์ของเอเจนต์แม่

## การอนุมัติ

เมื่อกฎให้ผลเป็น `ask` ไคลเอนต์สามารถตอบกลับได้ดังนี้:

| ตัวเลือก | การตอบกลับ | ผลลัพธ์ |
| --- | --- | --- |
| Allow once | `once` | อนุมัติเฉพาะคำขอที่รออยู่ |
| Allow always | `always` | อนุมัติและบันทึกรูปแบบที่เครื่องมือเสนอไว้สำหรับโปรเจกต์ |
| Reject | `reject` | ปฏิเสธคำขอนี้และคำขอสิทธิ์อื่นทั้งหมดที่รออยู่ในเซสชันนั้น |

ตัวอย่างเช่น การเลือก **Allow always** สำหรับ `git status --short` อาจบันทึก prefix ของ shell ที่ครอบคลุมคำสั่ง `git status` ในภายหลัง:

```text
shell: git status * → allow
```

การอนุมัติที่บันทึกไว้คือกฎ `allow` ที่บันทึกถาวรในขอบเขตของโปรเจกต์ และจะไม่แทนที่ `deny` ที่กำหนดค่าไว้ เครื่องมือแต่ละตัวเป็นผู้เลือกรูปแบบที่เสนอให้บันทึก บางตัวเสนอ `*` ส่วน shell เสนอ prefix ของคำสั่ง และสกิลกับเอเจนต์ย่อยเสนอ ID ของตน ให้ตรวจสอบการอนุมัติที่ครอบคลุมกว้างและลบรายการที่ไม่จำเป็นแล้วออก

ไคลเอนต์อาจแนบความคิดเห็นเมื่อปฏิเสธได้ ไคลเอนต์ที่ไม่ใช่แบบโต้ตอบต้องตัดสินใจเองว่าจะจัดการคำขออนุมัติอย่างไร โดยกฎ `deny` ที่กำหนดค่าไว้จะยังคงถูกบังคับใช้เสมอ

## นโยบาย

[นโยบาย](/policies)สามารถปฏิเสธการตรวจสอบสิทธิ์แบบเด็ดขาดได้หลังจากกฎเหล่านี้และการอนุมัติที่บันทึกไว้ทำงานแล้ว โดยจะเปลี่ยน `allow` หรือ `ask` เป็น `deny` และไม่เคยให้สิทธิ์เข้าถึง

```jsonc
{
  "policies": [{ "action": "tool.use", "resource": "shell:sudo *", "effect": "deny" }],
}
```

นโยบายระดับ global และนโยบายที่จัดการผ่าน Console จะแทนที่การกำหนดค่าของโปรเจกต์ ซึ่งเป็นวิธีที่องค์กรใช้บล็อกคำสั่งที่ repository อนุญาตไว้
