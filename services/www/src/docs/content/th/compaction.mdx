---
title: "การบีบอัดบริบท"
---

การบีบอัดบริบท (compaction) ช่วยเพิ่มพื้นที่ในเซสชันที่ยาวโดยแทนที่บทสนทนาเก่าด้วยบทสรุป เพื่อให้เซสชันดำเนินต่อไปได้แม้จะเกินขีดจำกัดบริบทของโมเดล

## วิธีการทำงาน

เมื่อเซสชันใกล้ถึงขีดจำกัดบริบทของโมเดล OpenCode จะสรุปทุกอย่างยกเว้นบทสนทนาล่าสุด ซึ่งโดยค่าเริ่มต้นมีประมาณ 15,000 โทเค็น เมื่อบทสรุปพร้อมแล้ว บทสรุปจะถูกวางไว้หน้าบทสนทนาล่าสุดนั้น และเซสชันจะดำเนินต่อจากจุดนั้น

```text
before   [ system prompt ][ older conversation ............ ][ recent 15k ][ pending work ]
after    [ system prompt ][ summary ][ recent 15k ][ pending work ]
```

โมเดลจะมองบทสรุปเป็นบทสนทนาที่ผ่านมา การบีบอัดบริบทครั้งต่อ ๆ ไปจะอัปเดตบทสรุปเดิมแทนที่จะเริ่มใหม่

## เริ่มต้น

การบีบอัดบริบทอัตโนมัติเปิดใช้งานโดยค่าเริ่มต้น:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "compaction": {
    "auto": true,
    "keep": { "tokens": 15000 },
  },
}
```

การบีบอัดบริบททำให้รายละเอียดบางส่วนสูญหาย หากรายละเอียดล่าสุดที่แม่นยำมีความสำคัญ ให้เพิ่ม `keep.tokens` หรือสั่งบีบอัดบริบทเองก่อนที่การบีบอัดอัตโนมัติจะเกิดขึ้น

## สั่งเอง

สั่งบีบอัดบริบทได้ทุกเมื่อ แม้ประวัติจะยังสั้นอยู่:

```sh
opencode api post /api/session/ses_example/compact --data '{}'
```

คำสั่ง `api` จะค้นหาและยืนยันตัวตนกับบริการเบื้องหลังให้เอง การตอบกลับจะยืนยันว่ารับคำขอแล้ว แต่จะไม่รอให้บทสรุปเสร็จ ให้ติดตามอีเวนต์ `session.compaction.*` เพื่อดูว่าเสร็จเมื่อใด ดูรายละเอียดของ operation ทั้งหมดได้ที่[เอกสารอ้างอิง API](/api)

| กฎ | พฤติกรรม |
| --- | --- |
| จังหวะเวลา | ทำงานที่จุดปลอดภัยถัดไป ก่อนพรอมต์ที่ยังรออยู่ |
| การสั่งซ้ำ | คำขอที่ส่งมาระหว่างที่มีคำขอหนึ่งรออยู่จะถูกรวมเข้ากับคำขอนั้น |
| ระบบอัตโนมัติ | ใช้งานได้แม้ `compaction.auto` เป็น `false` |

ส่ง `id` เพื่อให้การลองใหม่ด้วยคำขอเดิมทุกประการเป็นแบบ idempotent การใช้ ID เดิมกับคำขอที่ต่างออกไปจะได้ผลลัพธ์เป็น conflict

```sh
opencode api post /api/session/ses_example/compact --data '{"id":"msg_compact_once"}'
```

## การตั้งค่า

เพิ่ม `compaction` ใน[ไฟล์กำหนดค่า OpenCode](/config) ไฟล์ใดก็ได้:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "compaction": {
    "auto": false,
    "keep": { "tokens": 24000 },
    "buffer": 16000,
  },
}
```

| ฟิลด์ | ค่าเริ่มต้น | พฤติกรรม |
| --- | ---: | --- |
| `auto` | `true` | บีบอัดบริบทอัตโนมัติเมื่อใกล้ถึงขีดจำกัดบริบท และกู้คืนหนึ่งครั้งเมื่อผู้ให้บริการปฏิเสธคำขอเพราะยาวเกินไป การบีบอัดบริบทแบบสั่งเองใช้งานได้เสมอ |
| `keep.tokens` | `15000` | ปริมาณโดยประมาณของบทสนทนาล่าสุดที่เก็บไว้คู่กับบทสรุป ค่าที่มากขึ้นจะคงรายละเอียดไว้ได้มากขึ้น แต่เหลือพื้นที่สำหรับงานใหม่น้อยลง |
| `buffer` | 10% ของขีดจำกัด | จำนวนโทเค็นที่เว้นว่างไว้ต่ำกว่าขีดจำกัดของโมเดล ค่าที่มากขึ้นจะทำให้การบีบอัดบริบทอัตโนมัติเริ่มเร็วขึ้น |

`keep.tokens` และ `buffer` รับค่าจำนวนเต็มที่ไม่ติดลบ

## ผู้ให้บริการ

โดยค่าเริ่มต้น OpenCode จะเขียนบทสรุปเองโดยใช้โมเดลของเซสชัน ผู้ให้บริการบางรายสามารถบีบอัดบทสนทนาฝั่งตนเองแทนได้ เปิดใช้งานรายผู้ให้บริการหรือรายโมเดลด้วย `settings.compaction`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "settings": { "compaction": { "type": "native" } },
      "models": {
        "gpt-4.1": { "settings": { "compaction": { "type": "summary" } } },
      },
    },
  },
}
```

การตั้งค่าระดับโมเดลจะแทนที่การตั้งค่าระดับผู้ให้บริการ `native` ใช้การบีบอัดบริบทของผู้ให้บริการ ส่วน `summary` ใช้การบีบอัดบริบทของ OpenCode เอง

เมื่อใช้การบีบอัดบริบทแบบ native OpenCode จะส่งบทสนทนาไปยัง endpoint สำหรับบีบอัดบริบทของผู้ให้บริการ ผู้ให้บริการจะส่งรายการที่เข้ารหัสและอ่านเนื้อหาไม่ได้กลับมาเพื่อใช้แทนบทสนทนาเก่า ข้อความและไฟล์แนบล่าสุดของคุณซึ่งมีขนาดไม่เกิน `keep.tokens` จะถูกเก็บไว้คู่กัน:

```text
before   [ older conversation ........................ ][ recent user messages ]
after    [ encrypted checkpoint + recent user messages ]
```

| หัวข้อ | พฤติกรรม |
| --- | --- |
| การรองรับ | โมเดล OpenAI Responses การรองรับแตกต่างกันไปตาม deployment และโมเดล |
| เกณฑ์ | ใช้การตั้งค่า `auto` และ `buffer` เดียวกับการบีบอัดบริบทแบบสรุป คำขอแบบสั่งเองก็ใช้งานได้เช่นกัน |
| การย้ายข้าม | checkpoint ที่เข้ารหัสใช้ได้กับผู้ให้บริการ โมเดล และ endpoint เดิมเท่านั้น หากเปลี่ยนโมเดล เซสชันจะดำเนินต่อจากบทสนทนาต้นฉบับแทน |
| ยาวเกินไป | หากผู้ให้บริการปฏิเสธการบีบอัดบริบทเพราะยาวเกินไป OpenCode จะลองใหม่ด้วยคำขอที่เล็กลง โดยไม่เปลี่ยนไปใช้บทสรุป |

## บทสรุป

บทสรุปมีโครงสร้างที่ทำให้เอเจนต์อื่นสามารถรับช่วงงานต่อได้:

```md
## Objective
Finish the authentication migration.

## Next Move
- Update the callback handler.
- Verify the login flow.
```

บทสรุปครอบคลุมเป้าหมายและข้อกำหนด การตัดสินใจ งานที่เสร็จแล้วและที่กำลังทำ อุปสรรคและขั้นตอนถัดไป รวมถึงไฟล์ที่เกี่ยวข้อง ในบทสนทนาล่าสุดที่เก็บไว้คู่กับบทสรุป เอาต์พุตของเครื่องมือที่ยาวจะถูกย่อให้สั้นลง และข้อมูลไฟล์แนบจะถูกแทนที่ด้วยคำอธิบายสั้น ๆ

หลังการบีบอัดบริบท ไฟล์คำแนะนำเวอร์ชันปัจจุบันจะกลายเป็นค่าตั้งต้น (baseline) ของเซสชัน ดู[คำแนะนำ](/instructions)

## ขีดจำกัด

| ขีดจำกัด | ผลลัพธ์ |
| --- | --- |
| โมเดล | การบีบอัดบริบทใช้โมเดลของเซสชัน ไม่มีโมเดลแยกสำหรับบีบอัดบริบท |
| ประวัติ | การบีบอัดบริบทต้องมีบทสนทนาเก่าให้แทนที่ หากคำขอส่วนใหญ่เป็นคำแนะนำคงที่และ schema ของเครื่องมือ ก็จะเพิ่มพื้นที่ไม่ได้ |
| ขนาด | หากบทสนทนาที่จะบีบอัดยาวเกินไปเอง OpenCode จะส่งข้อความฉบับย่อ และอาจตัดการโต้ตอบที่เก่าที่สุดออก |
| การกู้คืน | คำขอที่ถูกปฏิเสธเพราะยาวเกินไปจะถูกบีบอัดบริบทแล้วลองใหม่หนึ่งครั้ง หากถูกปฏิเสธอีกจะส่งกลับเป็นข้อผิดพลาด |
| พื้นที่จัดเก็บ | ข้อความก่อนหน้ายังคงถูกจัดเก็บไว้ แม้จะไม่ได้ส่งไปยังโมเดลแล้ว |

ตัวอย่างเช่น การบีบอัดบริบทช่วยไม่ได้ในกรณีนี้:

```text
128k context = 120k fixed instructions and tools + 8k conversation
```

## การย้าย

V1 ใช้พฤติกรรมแบบ tail-turn และ pruning ส่วน V2 ใช้บทสรุปและ `compaction.keep.tokens`:

```jsonc
{
  "compaction": {
    "keep": { "tokens": 15000 }
  }
}
```

การตั้งค่าและพฤติกรรมในหน้านี้ใช้กับ V2
