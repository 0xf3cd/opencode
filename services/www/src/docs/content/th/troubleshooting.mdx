<Callout type="tip">
  คุณให้ OpenCode ดีบักตัวเองได้ เพียงอธิบายปัญหาและขอให้ใช้หน้าการแก้ไขปัญหานี้ OpenCode จะอ่านขั้นตอนด้านล่าง ตรวจสอบบริการและล็อกของตัวเอง แล้วช่วยระบุสาเหตุของปัญหา
</Callout>

OpenCode ใช้สถาปัตยกรรมแบบไคลเอนต์-เซิร์ฟเวอร์ เซิร์ฟเวอร์เบื้องหลังเป็นผู้ดูแลเซสชัน ปลั๊กอิน สิทธิ์ และสถานะอื่น ๆ ของแอปพลิเคชัน เริ่มจากระบุว่าปัญหาอยู่ที่ไคลเอนต์ เซิร์ฟเวอร์ที่ใช้ร่วมกัน หรือโปรเจกต์ใดโปรเจกต์หนึ่ง

## ตรวจสอบบริการเบื้องหลัง

แสดงข้อมูลเซิร์ฟเวอร์ปัจจุบัน:

```bash
opencode service status
```

ตรวจสอบว่า API ทำงานปกติ:

```bash
opencode api get /api/info
```

หากบริการค้างหรือทำงานผิดปกติ ให้รีสตาร์ต:

```bash
opencode service restart
```

หรือจะหยุดแล้วเริ่มบริการเองก็ได้:

```bash
opencode service stop
opencode service start
```

<Callout type="note">
  โดยปกติ OpenCode จะค้นหาหรือเริ่มบริการเบื้องหลังที่ใช้ร่วมกันให้อัตโนมัติ คำสั่ง service จำเป็นเฉพาะเมื่อต้องการวินิจฉัยวงจรการทำงานของบริการเท่านั้น
</Callout>

## อนุญาต origin ของเบราว์เซอร์

หากไคลเอนต์บนเบราว์เซอร์ที่อยู่คนละ origin เชื่อมต่อไม่ได้เพราะ CORS ให้เพิ่ม origin ของไคลเอนต์นั้นลงในการกำหนดค่าบริการ:

```bash
opencode service set cors http://192.168.1.10:3001
opencode service get cors
```

ใช้ origin แบบ HTTP หรือ HTTPS ที่ตรงตัว รวมพอร์ตเมื่อจำเป็น โดยไม่มีพาธหรือเครื่องหมายทับต่อท้าย หากต้องการอนุญาตหลาย origin ให้ส่งรายการที่คั่นด้วยจุลภาคเป็นอาร์กิวเมนต์เดียว ช่องว่างรอบแต่ละ origin จะถูกตัดออก:

```bash
opencode service set cors "http://192.168.1.10:3001, https://app.example.com"
```

`service get cors` จะแสดงผลเป็นอาร์เรย์ JSON ลบรายการที่กำหนดไว้ด้วย:

```bash
opencode service unset cors
```

การตั้งค่าหรือยกเลิกการตั้งค่าของบริการจะหยุดบริการเบื้องหลัง การเริ่มครั้งถัดไปจะใช้การกำหนดค่าใหม่ ใช้ `opencode service start` เพื่อเริ่มบริการเอง

สำหรับเซิร์ฟเวอร์ที่รันแบบเบื้องหน้า ให้ใส่ `--cors` ซ้ำสำหรับแต่ละ origin ที่ต้องการอนุญาตเพิ่ม:

```bash
opencode serve --cors http://192.168.1.10:3001 --cors https://app.example.com
```

เมื่อใช้ `serve --service` แฟล็ก `--cors` ที่ระบุจะแทนที่รายการที่บันทึกไว้สำหรับโปรเซสนั้น หากไม่ระบุแฟล็กเหล่านี้ โหมดบริการจะใช้รายการที่บันทึกไว้ CORS ไม่ได้เปลี่ยนที่อยู่ที่รอรับการเชื่อมต่อ และไม่ได้ข้ามการยืนยันตัวตนของเซิร์ฟเวอร์

## ตรวจสอบ API

คำสั่ง `api` ใช้ขั้นตอนการค้นหาบริการภายในเครื่องและขั้นตอนการยืนยันตัวตนภายในเครื่อง รับได้ทั้งเมธอด HTTP กับพาธ หรือ operation ID ของ OpenAPI

ดู endpoint และ operation ID ทั้งหมดได้ที่[ข้อมูลอ้างอิง API](/api)

ส่ง body ของคำขอแบบ JSON ด้วย `--data` หรือ `-d` และเพิ่ม header ด้วย `--header` หรือ `-H`

<Callout type="warning">
  การรัน `opencode api` อาจเริ่มบริการเบื้องหลัง หากไม่มีบริการที่เข้ากันได้และทำงานปกติอยู่
</Callout>

## อ่านล็อก

บิลด์ที่ติดตั้งแล้วจะเขียนล็อกไว้ที่:

```text
~/.local/share/opencode/log/opencode.log
```

ติดตามล็อกระหว่างทำให้ปัญหาเกิดซ้ำ:

```bash
tail -f ~/.local/share/opencode/log/opencode.log
```

แต่ละบรรทัดมี `run` ID ของโปรเซสและฟิลด์ `role` ใช้ `role=server` เพื่อดูกิจกรรมของเซสชัน ผู้ให้บริการ ปลั๊กอิน สิทธิ์ และเครื่องมือ

```bash
grep 'role=server' ~/.local/share/opencode/log/opencode.log
grep 'run=8fc3b1d5' ~/.local/share/opencode/log/opencode.log
```

## เก็บโปรไฟล์ CPU และหน่วยความจำ

บน macOS และ Linux คุณส่งสัญญาณไปยังโปรเซส OpenCode ที่กำลังทำงานเพื่อเก็บข้อมูลวินิจฉัยได้ ดู PID ของเซิร์ฟเวอร์เบื้องหลังได้จาก endpoint health:

```bash
opencode api get /api/info
```

ใช้ `pid` จากการตอบกลับกับสัญญาณใดสัญญาณหนึ่งต่อไปนี้:

- `SIGPROF` เก็บโปรไฟล์ CPU เป็นเวลา 10 วินาที:

  ```bash
  kill -SIGPROF <pid>
  ```

  ผลลัพธ์จะเขียนไว้ในไดเรกทอรีล็อกเป็น `cpu-<pid>-<timestamp>.cpuprofile`

- `SIGUSR1` เก็บสแนปช็อตหน่วยความจำ (heap):

  ```bash
  kill -SIGUSR1 <pid>
  ```

  ผลลัพธ์จะเขียนไว้ในไดเรกทอรีล็อกเป็น `heap-<pid>-<timestamp>.heapsnapshot`

รอจนเห็น `CPU profile written` หรือ `heap snapshot written` ใน `opencode.log` ก่อนเปิดไฟล์ รายการล็อกนั้นจะมีพาธแบบเต็มของไฟล์ คุณเปิดดูไฟล์ทั้งสองประเภทได้ใน Chrome DevTools

<Callout type="note">
  การเก็บโปรไฟล์ด้วยสัญญาณใช้ไม่ได้บน Windows การเขียนสแนปช็อต heap อาจทำให้โปรเซสหยุดชั่วคราวและใช้หน่วยความจำเพิ่มขึ้นชั่วขณะ
</Callout>

## ไฟล์ของบริการ

เซิร์ฟเวอร์ที่ใช้ร่วมกันจะลงทะเบียนตัวเองไว้ที่:

```text
~/.local/state/opencode/service.json
```

การกำหนดค่าส่วนตัวของบริการเก็บแยกไว้ที่:

```text
~/.config/opencode/service.json
```

โดยปกติฐานข้อมูลอยู่ที่:

```text
~/.local/share/opencode/opencode.db
```

`OPENCODE_DB` ใช้แทนที่ตำแหน่งของฐานข้อมูลได้

<Callout type="warning">
  โปรดอย่าลบหรือแก้ไขไฟล์ของบริการหรือฐานข้อมูลระหว่างแก้ไขปัญหา ใช้คำสั่ง service เพื่อจัดการ daemon และสำรองข้อมูลก่อนตรวจสอบข้อมูลถาวรด้วยเครื่องมือภายนอก
</Callout>

## รายงานปัญหา

เมื่อรายงานปัญหาที่ทำให้เกิดซ้ำได้ ให้แนบข้อมูลต่อไปนี้:

- เอาต์พุตจาก `opencode --version`
- เอาต์พุตจาก `opencode service status`
- ลำดับขั้นตอนที่สั้นที่สุดที่ทำให้ปัญหาเกิดซ้ำ
- ปัญหาส่งผลต่อบริการที่ใช้ร่วมกัน ไคลเอนต์ใดไคลเอนต์หนึ่ง หรือโปรเจกต์เดียว
- บรรทัดล็อกที่เกี่ยวข้อง พร้อมฟิลด์ `run` และ `role`

ลบคีย์ API, header การยืนยันสิทธิ์ (authorization), พรอมต์ เนื้อหาไฟล์ และข้อมูลละเอียดอ่อนอื่น ๆ ออกก่อนแชร์ล็อก

แจ้งปัญหาที่ทำให้เกิดซ้ำได้ที่ [GitHub Issues](https://github.com/anomalyco/opencode/issues)
