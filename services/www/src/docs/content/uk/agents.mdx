---
title: "Агенти"
---

Щоб додати агента для повторного використання, створіть файл Markdown. Цей приклад додає рецензента лише для читання, якого основний агент може запускати для перевірки коду:

```md title=".opencode/agents/reviewer.md"
---
description: Reviews changes for correctness and regressions
mode: subagent
model: anthropic/claude-sonnet-4-5#high
permissions:
  - action: edit
    resource: "*"
    effect: deny
  - action: shell
    resource: "*"
    effect: deny
---

Review the current changes. List findings in severity order with file and line references.
```

Попросіть основного агента скористатися ним:

```text
Use the reviewer subagent to review my current changes.
```

Агент поєднує системний промпт, бажану модель, дозволи та параметри відображення в іменований профіль асистента.

## Розташування

Зберігайте агентів у Markdown глобально для всіх проєктів або в межах проєкту:

```text
~/.config/opencode/agents/<name>.md
.opencode/agents/<name>.md
```

OpenCode шукає каталоги `.opencode` проєкту від поточного каталогу до кореня проєкту. Вкладений шлях стає частиною ID агента:

```text
.opencode/agents/team/reviewer.md  →  team/reviewer
```

## Формати

### Markdown

Frontmatter приймає ті самі поля, що й запис у конфігурації `agents`. Тіло Markdown стає промптом `system` агента:

```md title=".opencode/agents/explainer.md"
---
description: Explains code without changing it
mode: subagent
---

Explain the relevant code with short examples. Do not edit files.
```

### JSONC

Визначайте агентів у полі `agents` будь-якого [файлу конфігурації OpenCode](/config):

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "agents": {
    "reviewer": {
      "description": "Reviews current changes",
      "mode": "subagent",
      "system": "Report findings in severity order.",
      "permissions": [
        { "action": "edit", "resource": "*", "effect": "deny" },
      ],
    },
  },
}
```

## Вибір агента

Задайте основного агента, який використовується, якщо сесія ще не вибрала агента:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "default_agent": "writer",
  "agents": {
    "writer": { "mode": "primary" },
  },
}
```

Вибраний агент за замовчуванням має існувати, бути видимим і підтримувати роль основного агента. Інакше OpenCode використовує `build`, а потім перший видимий агент, що може бути основним. Зміна цього налаштування не замінює агента, збереженого в наявній сесії.

## Режими

Задайте `mode` залежно від того, де має працювати агент:

```jsonc
{
  "agents": {
    "reviewer": { "mode": "subagent" },
  },
}
```

| Режим | Поведінка |
| --- | --- |
| `primary` | Працює як основний агент сесії. Це значення за замовчуванням для нового власного агента. |
| `subagent` | Працює лише в дочірній сесії через інструмент `subagent`. |
| `all` | Працює як основний агент або як субагент. |

Субагенти працюють зі свіжим контекстом у дочірніх сесіях на передньому плані або у фоні. Дозволи `subagent` батьківського агента визначають, яких агентів він може запускати; дочірній агент використовує власні налаштовані дозволи.

```jsonc
{
  "agents": {
    "orchestrator": {
      "permissions": [
        { "action": "subagent", "resource": "*", "effect": "deny" },
        { "action": "subagent", "resource": "reviewer", "effect": "allow" },
      ],
    },
  },
}
```

## Вбудовані агенти

OpenCode містить такі видимі агенти:

| Агент | Режим | Призначення |
| --- | --- | --- |
| **Build** (`build`) | `primary` | Агент для програмування за замовчуванням. Інструменти дозволено за замовчуванням; читання конфіденційних файлів середовища та доступ за межами робочого простору потребують підтвердження. |
| **Plan** (`plan`) | `primary` | Досліджує та планує, не редагуючи звичайні файли проєкту. На запит може записувати файли планів OpenCode, а команди оболонки й далі контролюються дозволами. |
| **General** (`general`) | `subagent` | Виконує дослідження та багатокрокову роботу з широким доступом до інструментів, але не може запускати інших субагентів. |
| **Explore** (`explore`) | `subagent` | Шукає та читає код або вебджерела, не редагуючи файлів. |

Щоб перевизначити вбудованого агента, використайте той самий ID:

```jsonc
{
  "agents": {
    "build": {
      "permissions": [
        { "action": "shell", "resource": "git push *", "effect": "ask" },
      ],
    },
  },
}
```

Приховані агенти `compaction`, `title` і `summary` виконують службові завдання, і вибрати їх напряму не можна. У V2 немає вбудованого агента `scout`.

## Об'єднання

Визначення агентів об'єднуються в порядку завантаження конфігурації. Пізніші скалярні значення замінюють попередні, мапи запитів об'єднуються за ключами, а правила дозволів додаються в кінець:

```jsonc
{
  "permissions": [
    { "action": "shell", "resource": "*", "effect": "ask" },
  ],
  "agents": {
    "build": {
      "permissions": [
        { "action": "shell", "resource": "git status", "effect": "allow" },
      ],
    },
  },
}
```

Глобальні `permissions` застосовуються перед правилами конкретного агента, тож пізніші правила агента можуть їх уточнювати.

## Параметри

### Опис

`description` пояснює призначення агента. Додавайте його до субагентів, бо OpenCode показує опис моделі, яка вибирає, якого агента запустити:

```yaml
description: Reviews database migrations for safety
```

### Режим

`mode` приймає `primary`, `subagent` або `all`. Якщо для нового власного агента параметр не задано, використовується `primary`:

```yaml
mode: all
```

### Модель

`model` задається у форматі `provider/model` з необов'язковим `#variant`:

```yaml
model: anthropic/claude-sonnet-4-5#high
```

JSON-конфігурація також приймає розгорнуту форму:

```jsonc
{
  "agents": {
    "reviewer": {
      "model": {
        "providerID": "anthropic",
        "model": "claude-sonnet-4-5",
        "variant": "high",
      },
    },
  },
}
```

- Субагент використовує налаштовану для нього модель, а якщо її не задано, успадковує модель батьківської сесії.
- Сесія зберігає вибрану модель окремо. Вибір основного агента за ID цю модель не змінює.

### Системний промпт

`system` задає системний промпт агента. Непорожнє значення замінює базовий промпт провайдера для цього агента:

```jsonc
{
  "agents": {
    "reviewer": { "system": "Review only. Do not modify files." },
  },
}
```

Інструкції проєкту, навички, посилання на каталоги та інші джерела інструкцій усе одно додаються. В агенті Markdown пишіть цей текст у тілі документа, а не в полі frontmatter `system`.

### Дозволи

`permissions` — це впорядкований список правил зіставлення:

```jsonc
{
  "agents": {
    "reviewer": {
      "permissions": [
        { "action": "*", "resource": "*", "effect": "deny" },
        { "action": "read", "resource": "src/**", "effect": "allow" },
      ],
    },
  },
}
```

| Поле | Значення |
| --- | --- |
| `action` | Інструмент або дія дозволу. Підтримуються шаблони підстановки. |
| `resource` | Шлях, команда, ID агента чи інше значення, з яким зіставляється дія. Підтримуються шаблони підстановки. |
| `effect` | `allow`, `ask` або `deny`. |

Перемагає останнє правило, що збіглося, тому ставте загальні правила перед винятками. Поширені дії:

| Дія | Що охоплює |
| --- | --- |
| `shell` | Команди оболонки |
| `edit` | Інструменти редагування, запису та застосування патчів |
| `subagent` | Дочірні агенти |
| `read`, `glob`, `grep` | Інструменти локального пошуку |
| `webfetch`, `websearch` | Вебінструменти |
| `skill` | Завантаження навичок |

Для ресурсів `read`, `edit` і `external_directory` OpenCode розгортає `~` і `$HOME`:

```jsonc
{ "action": "read", "resource": "~/notes/**", "effect": "allow" }
```

Ресурси оболонки залишаються сирим текстом команди, і ці значення в них не розгортаються.

### Кроки

`steps` задає максимальну кількість кроків моделі (додатне число):

```yaml
steps: 8
```

На останньому кроці OpenCode прибирає інструменти й просить модель підсумувати роботу текстом. Нове повідомлення користувача скидає ліміт.

### Приховування

`hidden` прибирає агента зі звичайних списків, інтерактивного пошуку та каталогу субагентів:

```yaml
hidden: true
```

Цей параметр керує видимістю, а не безпекою. Щоб обмежити поведінку, використовуйте дозволи.

### Колір

`color` задає колір агента в інтерфейсі шестизначним шістнадцятковим значенням:

```yaml
color: "#ff6b6b"
```

### Вимкнення

`disabled` видаляє вбудованого або власного агента на цьому етапі завантаження конфігурації:

```jsonc
{
  "agents": {
    "plan": { "disabled": true },
  },
}
```

### Запит

`request` приймає накладення заголовків і тіла JSON для конкретного агента:

```jsonc
{
  "agents": {
    "reviewer": {
      "request": {
        "headers": { "x-agent": "reviewer" },
        "body": { "temperature": 0.1 },
      },
    },
  },
}
```

<Callout type="warning">
  Виконавець сесій V2 зберігає ці значення, але поки що не надсилає їх у запитах до моделі. Активні параметри запитів
  натомість налаштовуйте для провайдера, моделі або варіанта моделі.
</Callout>

Не використовуйте в новій конфігурації агентів V2 застарілі поля верхнього рівня, як-от `temperature`, `top_p`, `prompt`, `permission`, `tools`, `disable` чи `maxSteps`.
