---
title: "Стиснення контексту"
---

Стиснення контексту звільняє місце в довгій сесії: старіша частина розмови замінюється підсумком, і сесія може
продовжуватися після досягнення ліміту контексту моделі.

## Як це працює

Коли сесія наближається до ліміту контексту моделі, OpenCode підсумовує все, крім найновішої частини розмови (за
замовчуванням приблизно 15 000 токенів). Коли підсумок готовий, його розміщують перед цією недавньою частиною, і сесія
продовжується з цього місця.

```text
before   [ system prompt ][ older conversation ............ ][ recent 15k ][ pending work ]
after    [ system prompt ][ summary ][ recent 15k ][ pending work ]
```

Модель сприймає підсумок як попередню розмову. Наступні стиснення оновлюють той самий підсумок, а не створюють його
заново.

## Початок роботи

Автоматичне стиснення ввімкнено за замовчуванням:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "compaction": {
    "auto": true,
    "keep": { "tokens": 15000 },
  },
}
```

Стиснення відбувається із втратою інформації. Якщо важливі точні недавні подробиці, збільште `keep.tokens` або запустіть
стиснення вручну раніше за автоматичне.

## Вручну

Запросити стиснення можна будь-коли, навіть для короткої історії:

```sh
opencode api post /api/session/ses_example/compact --data '{}'
```

Команда `api` знаходить фоновий сервіс і автентифікується в ньому. Її відповідь лише підтверджує, що запит прийнято, —
вона не чекає на підсумок. Щоб дізнатися, коли стиснення завершиться, відстежуйте події `session.compaction.*`. Повний
опис операції наведено в [довіднику API](/api).

| Правило | Поведінка |
| --- | --- |
| Час виконання | Запускається в наступній безпечній точці, перед промптами, які ще очікують. |
| Повтори | Запити, надіслані, поки один уже очікує, об'єднуються з ним. |
| Автоматизація | Працює, навіть коли `compaction.auto` має значення `false`. |

Передайте `id`, щоб точний повтор запиту був ідемпотентним. Повторне використання цього ID для іншого запиту повертає
конфлікт.

```sh
opencode api post /api/session/ses_example/compact --data '{"id":"msg_compact_once"}'
```

## Налаштування

Додайте `compaction` до будь-якого [файлу конфігурації OpenCode](/config):

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "compaction": {
    "auto": false,
    "keep": { "tokens": 24000 },
    "buffer": 16000,
  },
}
```

| Поле | За замовчуванням | Поведінка |
| --- | ---: | --- |
| `auto` | `true` | Автоматично стискає контекст поблизу ліміту й один раз відновлюється, коли провайдер відхиляє запит як задовгий. Ручне стиснення працює завжди. |
| `keep.tokens` | `15000` | Приблизний обсяг недавньої розмови, що зберігається поруч із підсумком. Більші значення зберігають більше подробиць, але залишають менше місця для нової роботи. |
| `buffer` | 10% ліміту | Кількість токенів, які залишаються вільними нижче ліміту моделі. Більші значення запускають автоматичне стиснення раніше. |

`keep.tokens` і `buffer` приймають невід'ємні цілі числа.

## Провайдери

За замовчуванням OpenCode сам пише підсумок за допомогою моделі сесії. Деякі провайдери можуть натомість стискати
розмову на своєму боці. Увімкніть це для провайдера або моделі через `settings.compaction`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "settings": { "compaction": { "type": "native" } },
      "models": {
        "gpt-4.1": { "settings": { "compaction": { "type": "summary" } } },
      },
    },
  },
}
```

Налаштування моделі перевизначає налаштування провайдера. `native` використовує стиснення провайдера, а `summary` —
власне стиснення OpenCode.

У разі нативного стиснення OpenCode надсилає розмову на ендпоінт стиснення провайдера. Провайдер повертає непрозорий
зашифрований елемент, який замінює старішу частину розмови. Ваші недавні повідомлення та вкладення в межах
`keep.tokens` зберігаються поруч із ним:

```text
before   [ older conversation ........................ ][ recent user messages ]
after    [ encrypted checkpoint + recent user messages ]
```

| Тема | Поведінка |
| --- | --- |
| Підтримка | Моделі OpenAI Responses. Підтримка залежить від розгортання та моделі. |
| Поріг | Ті самі налаштування `auto` і `buffer`, що й для стиснення через підсумок. Ручні запити також працюють. |
| Переносність | Зашифрована контрольна точка працює лише з тим самим провайдером, моделлю та ендпоінтом. Якщо змінити модель, сесія продовжиться з оригінальної розмови. |
| Задовгий запит | Якщо провайдер відхиляє стиснення як задовге, OpenCode повторює його з меншим запитом. На підсумок він не перемикається. |

## Підсумки

Підсумок має таку структуру, щоб інший агент міг продовжити з нього роботу:

```md
## Objective
Finish the authentication migration.

## Next Move
- Update the callback handler.
- Verify the login flow.
```

Він охоплює мету й вимоги, рішення, завершену та поточну роботу, блокери й наступні кроки, а також відповідні файли.
У недавній частині розмови, що зберігається поруч, довгий вивід інструментів скорочується, а дані вкладень замінюються
коротким описом.

Після стиснення поточні версії ваших файлів інструкцій стають базовими для сесії; див. [Інструкції](/instructions).

## Обмеження

| Обмеження | Результат |
| --- | --- |
| Модель | Стиснення використовує модель сесії. Окремої моделі для стиснення немає. |
| Історія | Для стиснення потрібна старіша частина розмови, яку можна замінити. Воно не звільнить місце, якщо запит здебільшого складається з фіксованих інструкцій і схем інструментів. |
| Розмір | Якщо розмова, яку потрібно стиснути, сама задовга, OpenCode надсилає її скорочену текстову версію й може пропустити найстаріші обміни повідомленнями. |
| Відновлення | Запит, відхилений як задовгий, стискається й повторюється один раз. Повторне відхилення повертається як помилка. |
| Зберігання | Попередні повідомлення залишаються збереженими, навіть коли їх більше не надсилають моделі. |

Наприклад, тут стиснення не допоможе:

```text
128k context = 120k fixed instructions and tools + 8k conversation
```

## Міграція

V1 зберігав останні ходи розмови й обрізав старіші. V2 використовує підсумки та `compaction.keep.tokens`:

```jsonc
{
  "compaction": {
    "keep": { "tokens": 15000 }
  }
}
```

Налаштування й поведінка, описані на цій сторінці, стосуються V2.
