---
title: "Посилання на каталоги"
---

Посилання на каталоги надають OpenCode іменований доступ до каталогів поза поточним проєктом. Додайте посилання в
`opencode.json` або `opencode.jsonc`, а потім за потреби вкладіть його псевдонім у клієнті.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "references": {
    "docs": {
      "path": "../product-docs",
      "description": "Use for product behavior and terminology",
    },
  },
}
```

Вклавши `docs`, попросіть агента переглянути потрібний шлях:

```text
Read the attached docs reference and summarize api/authentication.md.
```

Використовуйте посилання на каталоги для документації, спільних бібліотек, прикладів або коду з іншого репозиторію.

## Локальні каталоги

Для локального каталогу використовуйте `path`:

```jsonc
{
  "references": {
    "design-system": {
      "path": "../design-system",
      "description": "Use when working with components or design tokens",
    },
  },
}
```

Шляхи обробляються так:

- Відносні шляхи обчислюються від каталогу, що містить файл конфігурації.
- Абсолютні шляхи підтримуються.
- Шляхи відносно домашнього каталогу, як-от `~/docs`, підтримуються.

Якщо інші поля не потрібні, використовуйте скорочений рядковий запис:

```jsonc
{
  "references": {
    "docs": "../docs",
    "shared": "~/work/shared",
  },
}
```

<Callout type="note">
  Скорочений рядок вважається локальним шляхом, лише якщо починається з `.`, `/` або `~`. Пишіть `./docs`, а не `docs`:
  значення `docs` без префікса тлумачиться як репозиторій Git.
</Callout>

## Git

Для віддаленого репозиторію Git використовуйте `repository`:

```jsonc
{
  "references": {
    "effect": {
      "repository": "Effect-TS/effect",
      "branch": "main",
    },
    "internal-sdk": {
      "repository": "git@gitlab.example.com:platform/sdk.git",
      "branch": "release/v2",
    },
  },
}
```

Підтримувані форми віддалених адрес:

- скорочення GitHub `owner/repo`
- URL-адреси Git
- форми «хост/шлях»
- віддалені адреси у стилі SCP

Локальні репозиторії `file:` не підтримуються.

Щоб відстежувати гілку за замовчуванням віддаленого репозиторію, використовуйте скорочений рядковий запис:

```jsonc
{
  "references": {
    "effect": "Effect-TS/effect",
    "sdk": "gitlab.com/platform/sdk",
  },
}
```

Без `branch` OpenCode отримує й оновлює гілку за замовчуванням віддаленого репозиторію. Назви гілок можуть містити
літери, цифри, `/`, `_`, `.` і `-`, але не можуть починатися з `-` або містити `..`.

```jsonc
{
  "references": {
    "sdk": {
      "repository": "example/sdk",
      "branch": "release/v2.1",
    },
  },
}
```

## Зберігання

OpenCode нормалізує кожну віддалену адресу й зберігає одну робочу копію для кожної пари «репозиторій — гілка» у своєму
глобальному каталозі даних. Без явно вказаної гілки шлях має такий вигляд:

```text
opencode/repos/<host>/<repository-path>
```

У типовій інсталяції Linux `Effect-TS/effect` зберігається тут:

```text
~/.local/share/opencode/repos/github.com/Effect-TS/effect
```

Явно вказана гілка додає закодований суфікс `@<branch>`:

```text
~/.local/share/opencode/repos/github.com/Effect-TS/effect@main
```

## Оновлення

Відсутні репозиторії клонуються асинхронно. Наявні робочі копії перевіряються у фоновому режимі, коли посилання
завантажуються або перезавантажуються, а також після прийняття нового промпту користувача в їхньому розташуванні
(Location).

```text
Prompt admitted → refresh check starts in background → agent continues
```

Робоча копія підлягає оновленню, якщо остання спроба оновлення була щонайменше 24 години тому або жодної спроби ще не
зафіксовано. Оновлення виконує fetch і скидає копію до налаштованої гілки або гілки за замовчуванням віддаленого
репозиторію.

```text
Last attempt: 25 hours ago → eligible
Last attempt: 2 hours ago  → skipped
```

Оновлення працює за такими правилами:

- Позначки часу зберігаються після перезапуску сервісу.
- Розташування, що використовують ту саму робочу копію, мають спільну позначку часу.
- Невдалі спроби записуються в журнал, і на них теж поширюється 24-годинне обмеження.
- Поки розташування не використовується, періодичного опитування немає.
- Помилки клонування чи оновлення не заважають завантаженню інших посилань.

Промпти не чекають на клонування чи оновлення. Вкладення може містити старіший вміст, навіть якщо пізніше читання
інструментом бачить оновлену робочу копію, а нове посилання може з'явитися раніше, ніж його робоча копія буде готова.

```text
Attachment created → cached content
Background refresh completes → later tool read sees newer content
```

<Callout type="warning">
  Кешовані робочі копії спільні й можуть оновлюватися, поки агент їх використовує. Не редагуйте кешовані робочі копії:
  оновлення скидає їх.
</Callout>

## Вказівки для агентів

`description` повідомляє агентам, коли посилання доречне. Посилання з описом з'являються в інструкціях агента разом
із псевдонімом і обчисленим шляхом.

```jsonc
{
  "references": {
    "docs": {
      "path": "../docs",
      "description": "Use for product behavior and terminology",
    },
  },
}
```

Посилання без опису залишаються доступними клієнтам, але автоматично агентам не пропонуються.

```jsonc
{
  "references": {
    "archive": {
      "path": "../archive",
    },
  },
}
```

## Видимість

Задайте `hidden` значення `true`, щоб прибрати посилання з інтерактивних списків вибору в клієнтах:

```jsonc
{
  "references": {
    "internal": {
      "path": "../internal",
      "description": "Use for internal service behavior",
      "hidden": true,
    },
  },
}
```

`hidden` впливає лише на видимість в інтерактивних інтерфейсах. Посилання залишається в API посилань і, якщо має опис,
в інструкціях агента.

## Використання

Клієнти вкладають посилання за його кореневим псевдонімом. Вкладення містить нерекурсивний список файлів і каталогів
першого рівня в корені.

```text
Attached alias: docs
Ask: Inspect docs/guides/deployment.md and explain the deployment steps.
```

Якщо вам потрібен вміст глибше за корінь, попросіть агента переглянути конкретний шлях.

## Дозволи

Посилання на каталоги не надають додаткових дозволів для інструментів. Доступ поза активним розташуванням, як і раніше,
підпорядковується звичайним правилам інструментів і дозволу `external_directory`; для редагування також потрібен
відповідний дозвіл на редагування.

```text
Read ../product-docs/api.md
```

Запит буде успішним, лише якщо активні дозволи дають змогу прочитати цей зовнішній шлях.

## Поля

| Поле | Локальний | Git | Опис |
| --- | --- | --- | --- |
| `path` | Обов'язкове | Ні | Шлях до локального каталогу |
| `repository` | Ні | Обов'язкове | Віддалений репозиторій Git |
| `branch` | Ні | Необов'язкове | Гілка, яку потрібно отримати й переключити |
| `description` | Необов'язкове | Необов'язкове | Вказівка, коли агентам слід використовувати посилання |
| `hidden` | Необов'язкове | Необов'язкове | Приховує посилання з інтерактивних списків вибору в клієнтах |

Повний запис Git може використовувати всі поля, сумісні з Git:

```jsonc
{
  "references": {
    "sdk": {
      "repository": "example/sdk",
      "branch": "main",
      "description": "Use for SDK implementation details",
      "hidden": false,
    },
  },
}
```

## Псевдоніми

Псевдонім не може бути порожнім і не може містити `/`, `\`, пробільні символи, зворотний апостроф або кому.

```text
Valid:   docs
Invalid: product docs
Invalid: docs/api
```
