---
title: "Моделі"
---

Виберіть модель для поточної сесії командою `/models`:

```text
/models
```

OpenCode показує моделі з [models.dev](https://models.dev), інтеграцій провайдерів і вашої конфігурації. У списку
вибору є лише ввімкнені моделі, провайдер яких доступний у поточному проєкті. Підключіть провайдерів у розділі
[Провайдери](/providers).

## Вибір

Вибирайте запис у `/models`, а не вгадуйте ID провайдера чи моделі. Вибір застосовується до поточної сесії й не змінює
вашу конфігурацію.

```text
anthropic/claude-sonnet-4-5
```

Доступність залежить від проєкту:

- Модель має бути ввімкнена.
- Її провайдер має бути доступний у поточному проєкті.
- Облікові дані та конфігурація з іншого проєкту автоматично не переносяться.

## Запуски

Щоб вибрати модель для одного запуску з командного рядка, не змінюючи модель за замовчуванням, використайте `--model`:

```bash
opencode run --model anthropic/claude-sonnet-4-5 "Refactor parseToken"
```

Агенти й команди також можуть вибирати власну модель. Див. [Агенти](/agents) і [Команди](/commands).

## Значення за замовчуванням

Щоб вибрати модель за замовчуванням для нової роботи, задайте `model` у `opencode.json` або `opencode.jsonc`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "anthropic/claude-sonnet-4-5",
}
```

Налаштована модель стає моделлю каталогу за замовчуванням, якщо вона ввімкнена і її провайдер доступний. Інакше
OpenCode як резервний варіант використовує найновішу доступну підтримувану модель.

- Модель, уже вибрана для сесії, має пріоритет над налаштованою моделлю за замовчуванням.
- Перемикання моделі сесії не переписує файл конфігурації.
- Наразі кореневе поле `model` зберігає лише провайдера й модель за замовчуванням, але не варіант.

Про розташування конфігурації та пріоритет див. [Конфігурація](/config).

## Варіанти

Варіанти — це іменовані набори параметрів однієї моделі, які часто задають рівень міркування або бюджет токенів. Щоб
вибрати варіант для запуску, сесії, агента чи команди, додайте `#variant`:

```bash
opencode run --model openai/gpt-5.2#high "Review this migration plan"
```

Назви варіантів беруться з поточних метаданих каталогу для вибраної моделі. Назви на кшталт `low`, `high` і `max`
доступні не для кожної моделі, а невідомий варіант спричиняє помилку визначення моделі.

Визначайте нові варіанти або замінюйте варіанти з каталогу з тим самим ID у масиві `variants` моделі:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "models": {
        "gpt-5.2": {
          "settings": {
            "reasoningEffort": "medium",
          },
          "variants": [
            {
              "id": "fast",
              "settings": {
                "reasoningEffort": "low",
              },
            },
            {
              "id": "deep",
              "settings": {
                "reasoningEffort": "high",
                "reasoningSummary": "auto",
              },
            },
          ],
        },
      },
    },
  },
}
```

Кожен варіант може містити `settings`, `headers` і `body`. Його значення застосовуються після значень провайдера й
моделі.

## Параметри

Записи провайдерів і моделей можуть налаштовувати запити через `settings`, `headers` і `body`:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "openai": {
      "settings": {
        "baseURL": "https://api.example.com/v1",
      },
      "headers": {
        "X-Team": "platform",
      },
      "models": {
        "gpt-5.2": {
          "settings": {
            "reasoningEffort": "high",
          },
          "body": {
            "store": false,
          },
        },
      },
    },
  },
}
```

| Поле       | Призначення                                                        |
| ---------- | ------------------------------------------------------------------ |
| `settings` | Параметри пакета провайдера, як-от `baseURL` або `reasoningEffort`. |
| `headers`  | Додаткові заголовки HTTP-запиту.                                   |
| `body`     | Специфічні для провайдера поля тіла запиту.                        |

OpenCode застосовує спершу значення провайдера, потім значення моделі, а наостанок — вибраний варіант.

- Вкладені об'єкти `settings` і `body` об'єднуються.
- Пізніші масиви та скалярні значення замінюють попередні.
- Назви заголовків зіставляються без урахування регістру.
- Параметри специфічні для провайдера: інший пакет провайдера може їх ігнорувати або відхиляти.

## Псевдоніми

За допомогою `modelID` можна дати моделі API зручніший ID у каталозі:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "openai/coding-default",
  "providers": {
    "openai": {
      "models": {
        "coding-default": {
          "modelID": "gpt-5.2",
          "name": "Coding default",
          "capabilities": {
            "tools": true,
            "input": ["text", "image"],
            "output": ["text"],
          },
          "limit": {
            "context": 200000,
            "output": 32000,
          },
        },
      },
    },
  },
}
```

Тут `openai/coding-default` — це посилання, яке можна вибрати, а провайдеру надсилається `gpt-5.2`. Для моделі, якої
ще немає в каталозі, OpenCode припускає:

- підтримку інструментів, текстовий і графічний вхід та текстовий вихід;
- ліміт контексту 200 000 токенів і ліміт виводу 32 000 токенів;
- невизначений ліміт вхідних даних.

Це резервні припущення, а не виявлені можливості. Якщо точні значення `capabilities` і `limit` відомі, задайте їх;
явні значення замінюють резервні. Щоб приховати модель із каталогу доступних, додайте `disabled: true`:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "openai": {
      "models": {
        "legacy-model": {
          "disabled": true,
        },
      },
    },
  },
}
```

## Міркування

Для OpenAI-сумісної моделі, яка передає міркування потоком у нестандартному полі повідомлення асистента, задайте
`compatibility.reasoningField`:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "local": {
      "models": {
        "reasoner": {
          "compatibility": {
            "reasoningField": "reasoning_content",
          },
        },
      },
    },
  },
}
```

OpenCode розпізнає `reasoning`, `reasoning_content` і `reasoning_text`, а також приймає інший специфічний для
провайдера рядок. Він читає потокові міркування з цього поля й відновлює його, коли надсилає моделі попередні
повідомлення асистента.

## Кешування промптів

OpenCode автоматично розставляє точки кешування промптів на маршрутах, яким вони, як відомо, потрібні, наприклад для
Anthropic. Коли моделі Claude обслуговуються через OpenAI-сумісний проксі, як-от LiteLLM, OpenCode не може визначити,
що їм потрібні точки `cache_control` у стилі Anthropic. Задайте для цих моделей Claude `compatibility.cacheFormat`:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "litellm": {
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": { "baseURL": "https://litellm.example.com/v1" },
      "models": {
        "claude-sonnet-5": {
          "compatibility": { "cacheFormat": "anthropic" },
        },
        "claude-opus-5-5": {
          "compatibility": { "cacheFormat": "anthropic" },
        },
        // Other models on the same proxy cache automatically and need no setting.
        "gpt-6.1": {},
      },
    },
  },
}
```

Після цього OpenCode позначає останнє визначення інструмента, системний промпт і останнє повідомлення як
`cache_control: { "type": "ephemeral" }`, тобто використовує стандартний для ендпоінта п'ятихвилинний час життя кешу.
Для моделей Alibaba Model Studio використовуйте `"alibaba"`: вони приймають ті самі позначки, але ігнорують їх у
визначеннях інструментів. Якщо всі моделі провайдера приймають той самий формат, задайте `compatibility.cacheFormat`
для провайдера.

## Локальні моделі

OpenCode автоматично знаходить моделі з Ollama, LM Studio та vLLM за їхніми стандартними локальними адресами. Також
можна вручну налаштувати будь-який OpenAI-сумісний сервер.

```text
ollama/gemma3:4b
lmstudio/google/gemma-4-26b-a4b
vllm/Qwen/Qwen3-Coder-30B-A3B-Instruct
```

### Ollama

Якщо Ollama слухає на `http://127.0.0.1:11434`, виберіть знайдену модель з ID провайдера `ollama`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "ollama/gemma3:4b",
}
```

OpenCode оновлює список моделей у фоні й отримує з Ollama дані про контекст, підтримку зображень і використання
інструментів. Моделі, призначені лише для ембедингів, виключаються.

Для іншого хоста чи порту задайте OpenAI-сумісну URL-адресу Ollama. Виявлення й далі використовує нативний API Ollama
з тим самим префіксом шляху:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "ollama": {
      "settings": {
        "baseURL": "http://127.0.0.1:5678/v1",
        "apiKey": "{env:OLLAMA_API_KEY}",
      },
    },
  },
}
```

- Не вказуйте `apiKey`, якщо ендпоінт не вимагає bearer-автентифікації.
- Вимкнути виявлення можна через `"plugins": ["-opencode.provider.ollama"]`.

### LM Studio

Якщо сервер LM Studio без автентифікації працює на `http://127.0.0.1:1234`, виберіть знайдену модель з ID провайдера
`lmstudio`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "lmstudio/google/gemma-4-26b-a4b",
}
```

OpenCode оновлює список моделей у фоні й отримує з LM Studio дані про контекст, підтримку зображень і використання
інструментів. Моделі ембедингів виключаються.

Для іншого хоста чи порту задайте OpenAI-сумісну URL-адресу. Моделі й далі знаходяться автоматично:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "lmstudio": {
      "settings": {
        "baseURL": "http://127.0.0.1:5678/v1",
        "apiKey": "{env:LMSTUDIO_API_KEY}",
      },
    },
  },
}
```

- Не вказуйте `apiKey`, якщо автентифікацію в LM Studio вимкнено.
- Вимкнути виявлення можна через `"plugins": ["-opencode.provider.lmstudio"]`.

### vLLM

Якщо vLLM слухає на `http://127.0.0.1:8000`, виберіть знайдену модель з ID провайдера `vllm`:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "vllm/Qwen/Qwen3-Coder-30B-A3B-Instruct",
}
```

OpenCode перевіряє `/health`, оновлює `/v1/models` у фоні, використовує повідомлене значення `max_model_len` як ліміт
контексту й враховує лише картки моделей, власником яких є `vllm`.

Знайдені моделі заявляють текстовий вхід і вихід, але не підтримку зображень чи інструментів. У vLLM виклики
інструментів вмикаються прапорцями сервера, як-от `--enable-auto-tool-choice` і `--tool-call-parser`, про які
виявлення не повідомляє.

Для іншого ендпоінта або сервера з автентифікацією задайте його OpenAI-сумісну URL-адресу:

```jsonc title="opencode.jsonc"
{
  "providers": {
    "vllm": {
      "settings": {
        "baseURL": "http://127.0.0.1:9000/v1",
        "apiKey": "{env:VLLM_API_KEY}",
      },
    },
  },
}
```

- Не вказуйте `apiKey`, якщо автентифікацію вимкнено.
- Вимкнути виявлення можна через `"plugins": ["-opencode.provider.vllm"]`.
- Проксі з префіксом шляху підтримуються. Наприклад, для `https://example.com/vllm/v1` перевіряється `/vllm/health`,
  а моделі знаходяться в `/vllm/v1/models`.

### Сумісні сервери

Для іншого OpenAI-сумісного сервера визначте пакет провайдера, ендпоінт і щонайменше одну модель:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "local/coder",
  "providers": {
    "local": {
      "name": "Local server",
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "http://127.0.0.1:1234/v1",
      },
      "models": {
        "coder": {
          "modelID": "model-name-on-server",
          "capabilities": {
            "tools": true,
            "input": ["text"],
            "output": ["text"],
          },
          "limit": {
            "context": 32768,
            "output": 8192,
          },
        },
      },
    },
  },
}
```

Вказуйте справжню назву моделі на сервері, її ліміти, типи вхідних і вихідних даних та підтримку інструментів. OpenCode
не може перевірити, чи точні резервні значення для власної моделі. Якщо ендпоінт вимагає ключ, додайте `apiKey` до
`settings` з підстановкою змінної середовища, наприклад `"apiKey": "{env:LOCAL_API_KEY}"`; не комітьте секрети.

## Посилання на моделі

Селектори моделей мають формат `provider/model` з необов'язковим `#variant`:

```text
openai/gpt-5.2
openai/gpt-5.2#high
openrouter/anthropic/claude-sonnet-4.5#high
```

| Частина    | Правило                                                          |
| ---------- | ---------------------------------------------------------------- |
| Провайдер  | Закінчується на першому `/`; не може містити `/` або `#`.        |
| Модель     | Може містити додаткові символи `/`; не може містити `#`.         |
| Варіант    | Іде після `#`, якщо він є.                                       |
| Регістр    | ID провайдерів і моделей чутливі до регістру.                    |

Використовуйте ID з каталогу, а не відображувані назви провайдерів. Поля `model` на кореневому рівні, в агентах і
командах приймають наведену вище рядкову форму або розгорнутий об'єкт:

```jsonc
{
  "model": {
    "providerID": "openrouter",
    "model": "anthropic/claude-sonnet-4.5",
  },
}
```

Розгорнута форма зручна для згенерованої або програмно створеної конфігурації.

## Застереження

Налаштовуючи моделі, пам'ятайте про такі правила:

```jsonc
{
  "model": "openai/gpt-5.2"
}
```

- Об'єкт селектора використовує `model`; запис у каталозі провайдера використовує `modelID` для ID, який надсилається
  провайдеру.
- Хоча коренева форма вибору приймає варіант, значення за замовчуванням у каталозі V2 його не зберігає. Натомість
  вибирайте варіанти для сесії, запуску, агента чи команди.
- Параметри моделей специфічні для провайдера. Інший пакет провайдера може їх ігнорувати або відхиляти.
- Дані каталогу, облікові дані та конфігурація прив'язані до розташування. Модель, доступна в одному проєкті, може бути
  недоступна в іншому.
- Файли конфігурації зазвичай перезавантажуються автоматично. Запит до моделі, що вже виконується, зберігає
  налаштування, з якими його розпочато.
