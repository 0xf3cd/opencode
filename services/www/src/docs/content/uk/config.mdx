---
title: "Конфігурація"
---

Щоб налаштувати OpenCode, створіть у проєкті файл `opencode.jsonc`. Додайте схему для перевірки в редакторі, а потім задайте лише потрібні параметри.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "anthropic/claude-sonnet-4-5",
}
```

Також можна попросити OpenCode оновити цей файл за вас.

## Формат

OpenCode підтримує JSON і JSONC. Використовуйте JSONC, якщо потрібні коментарі або коми в кінці.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  // Use this model by default.
  "model": "anthropic/claude-sonnet-4-5",
}
```

## Розташування

Керовані налаштування для всієї машини розміщуйте в системному каталозі конфігурації:

| Платформа | Каталог                                 |
| --------- | --------------------------------------- |
| macOS     | `/Library/Application Support/opencode` |
| Linux     | `/etc/opencode`                         |
| Windows   | `%ProgramData%\opencode`                |

Системний каталог працює так само, як глобальний. Окрім `opencode.json(c)`, з нього завантажуються `agents/`,
`commands/`, `skills/` і `plugins/` для кожного користувача машини:

```text
/etc/opencode/
├── opencode.json
├── agents/review.md
├── commands/release.md
└── skills/deploy/SKILL.md
```

У macOS OpenCode також читає керовані параметри, які інструменти MDM розгортають для домену `ai.opencode.managed`.
Профіль конкретного користувача замінює профіль для всієї машини:

```text
/Library/Managed Preferences/<user>/ai.opencode.managed.plist
/Library/Managed Preferences/ai.opencode.managed.plist
```

Керовані налаштування мають найвищий пріоритет, тому користувачі та проєкти не можуть перевизначити задані в них
значення, а керовані параметри macOS перевизначають системний каталог. Самі лише налаштування не можуть заборонити
користувачам додавати провайдерів, сервери MCP, агентів чи плагіни; щоб запровадити обмеження, використовуйте
[політики](/policies#precedence) в керованій конфігурації.

Налаштування користувача для всіх проєктів розміщуйте в глобальній конфігурації:

```text
~/.config/opencode/opencode.json(c)
```

Налаштування проєкту розміщуйте в одному з цих файлів:

```text
/home/user/projects/my-app/opencode.json(c)
/home/user/projects/my-app/.opencode/opencode.json(c)
```

OpenCode шукає файли від поточного каталогу до кореня файлової системи. Спершу він об'єднує файли `opencode.json(c)`,
що лежать безпосередньо в каталогах, — від найвіддаленішого каталогу до найближчого, — а потім у тому самому порядку
об'єднує файли з каталогів `.opencode`. Отже, будь-яка знайдена конфігурація в `.opencode` перевизначає будь-яку
конфігурацію, що лежить безпосередньо в каталозі. Використовуйте одну форму в усьому дереві каталогів, якщо вам не
потрібна саме така поведінка.

Наприклад, запустіть OpenCode з `/home/user/projects/acme/packages/web`:

```text
/etc/opencode/opencode.json
~/.config/opencode/opencode.json

/home/user/projects/acme/
├── opencode.json
└── packages/
    └── web/
        ├── opencode.json
        └── src/
```

OpenCode застосовує ці файли від найнижчого пріоритету до найвищого:

1. `~/.config/opencode/opencode.json`
2. `/home/user/projects/acme/opencode.json`
3. `/home/user/projects/acme/packages/web/opencode.json`
4. `/etc/opencode/opencode.json`

Конфігурація пакета перевизначає відповідні налаштування з конфігурації репозиторію, а та, своєю чергою, — глобальну
конфігурацію. Системна конфігурація перевизначає їх усі. Налаштування, що не конфліктують, зберігаються.
[Політики](/policies#precedence) з глобальних і проєктних файлів обчислюються у зворотному порядку, а системні політики
мають пріоритет над усіма ними.

## Схема

Повна схема конфігурації OpenCode доступна за адресою
[opencode.ai/config.json](https://opencode.ai/config.json).

Додайте до файлу конфігурації поле `$schema`, щоб увімкнути перевірку й автодоповнення в редакторах, які підтримують
JSON Schema:

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json"
}
```

Вважайте схему джерелом істини щодо доступних полів, допустимих значень і структури вкладених налаштувань.

### Оболонка

Задайте оболонку, яку використовують термінал та інструменти оболонки.

```jsonc
{
  "shell": "/bin/zsh",
}
```

### Модель

Задайте модель за замовчуванням у форматі `provider/model`. Наразі кореневе значення за замовчуванням не зберігає
`#variant`; посилання на моделі в агентах і командах можуть його вибирати.

```jsonc
{
  "model": "anthropic/claude-sonnet-4-5",
}
```

Про вибір моделей і локальні моделі див. [посібник з моделей](/models).

### Агент

Виберіть основного агента, який використовується, якщо сесія не вибирає агента явно.

```jsonc
{
  "default_agent": "build",
}
```

Про вбудованих і власних агентів див. [посібник з агентів](/agents).

### Оновлення

Перевірками оновлень можна керувати в глобальній конфігурації. Задайте для `update` значення `"disable"`, щоб
пропускати їх, `"notify"`, щоб показувати доступні оновлення перед установленням, або `"auto"`, щоб установлювати
оновлення автоматично. Якщо параметр не задано, `update` має значення `"notify"`.

Автоматичне встановлення не перезапускає запущений сервер. Щоб активувати встановлене оновлення, перезапустіть його
вручну. Значення на рівні проєкту ігноруються.

```jsonc
{
  "update": "notify",
}
```

### Спільний доступ

Задайте політику спільного доступу до сесій. OpenCode приймає це поле, але спільний доступ до сесій поки що не
підтримується.

```jsonc
{
  "share": "manual",
}
```

Докладніше див. у [посібнику зі спільного доступу](/sharing).

### Ім'я користувача

Задайте ім'я користувача. OpenCode приймає це поле, але не показує його в розмовах.

```jsonc
{
  "username": "alice",
}
```

### Дозволи

Визначте впорядковані правила, які дозволяють, забороняють або вимагають підтвердження, перш ніж агент використає
інструмент для відповідного ресурсу.

```jsonc
{
  "permissions": [
    {
      "action": "shell",
      "resource": "git push *",
      "effect": "ask",
    },
  ],
}
```

Про зіставлення правил і доступні дії див. [посібник з дозволів](/permissions).

### Політики

Дозволяйте або забороняйте використання провайдера, безумовно забороняйте перевірку дозволу або блокуйте сервер MCP,
навичку чи плагін за допомогою впорядкованих інструкцій, які може перевизначити ширша конфігурація.

```jsonc
{
  "policies": [
    { "action": "provider.use", "resource": "*", "effect": "deny" },
    { "action": "provider.use", "resource": "anthropic", "effect": "allow" },
    { "action": "tool.use", "resource": "shell:git push *", "effect": "deny" },
  ],
}
```

Про зіставлення, пріоритет між файлами конфігурації та політику, керовану через OpenCode Console, див.
[посібник з політик](/policies).

### Агенти

Перевизначайте вбудованих агентів або визначайте спеціалізованих агентів із власною моделлю, інструкціями, режимом і
дозволами.

```jsonc
{
  "agents": {
    "reviewer": {
      "description": "Review changes without editing files",
      "mode": "subagent",
      "system": "Focus on correctness, security, and missing tests.",
      "permissions": [{ "action": "edit", "resource": "*", "effect": "deny" }],
    },
  },
}
```

Про всі параметри агентів і агентів у файлах див. [посібник з агентів](/agents).

### Знімки

Увімкніть або вимкніть знімки файлової системи, які використовуються для скасування та відкочування змін.

```jsonc
{
  "snapshots": false,
}
```

Про скасування та повторення змін див. [посібник зі знімків](/snapshots).

### Спостерігач

Ігноруйте файли й каталоги, зміни в яких не повинні запускати оновлення файлової системи.

```jsonc
{
  "watcher": {
    "ignore": ["dist/**", "coverage/**"],
  },
}
```

### Форматер

Форматуйте файли після того, як їх змінять інструменти `write`, `edit` або `patch`. Задайте для `formatter` значення
`true`, щоб увімкнути доступні вбудовані форматери.

```jsonc
{
  "formatter": true,
}
```

Про вбудовані та власні форматери див. [посібник з форматерів](/formatters).

### Медіа

Визначте, як зменшувати або відхиляти завеликі зображення, завантажені інструментом `read`, перш ніж надсилати їх
моделі.

```jsonc
{
  "media": {
    "image": {
      "auto_resize": true,
      "max_width": 2000,
      "max_height": 2000,
      "max_base64_bytes": 5242880,
    },
  },
}
```

Про обробку зображень і обмеження див. [посібник із вкладень](/attachments).

### Вивід

Задайте максимальну кількість рядків і байтів, що зберігаються з результату інструмента.

```jsonc
{
  "tool_output": {
    "max_lines": 2000,
    "max_bytes": 51200,
  },
}
```

### Пошук

Виберіть, як OpenCode шукатиме в інтернеті. Використайте `"random"`, щоб доступний провайдер вибирався автоматично.

```jsonc
{
  "websearch": {
    "provider": "random",
  },
}
```

Про провайдерів, облікові дані, вибір провайдера, обмеження частоти запитів і вимкнення пошуку див.
[посібник з вебпошуку](/websearch).

### MCP

Налаштуйте локальні та віддалені сервери Model Context Protocol. Окремий сервер може перевизначити глобальні тайм-аути.

```jsonc
{
  "mcp": {
    "servers": {
      "playwright": {
        "type": "local",
        "command": ["bunx", "@playwright/mcp"],
      },
    },
  },
}
```

Про віддалені сервери, OAuth, змінні середовища та тайм-аути див. [посібник з MCP](/mcp-servers).

### Стиснення контексту

Керуйте автоматичним стисненням контексту і тим, скільки нещодавнього контексту воно зберігає.

```jsonc
{
  "compaction": {
    "auto": true,
    "keep": {
      "tokens": 15000,
    },
    "buffer": 20000,
  },
}
```

За замовчуванням і далі використовуються локальні підсумки. Щоб увімкнути нативне стиснення на боці провайдера як для
автоматичних, так і для ручних запитів, задайте політику для провайдера або моделі:

```jsonc
{
  "providers": {
    "openai": {
      "settings": { "compaction": { "type": "native" } },
      "models": {
        "gpt-4.1": { "settings": { "compaction": { "type": "summary" } } },
      },
    },
  },
}
```

Налаштування моделі перевизначає налаштування провайдера. Автоматичне стиснення використовує доступний бюджет вхідних
даних вибраної моделі. Контрольні точки провайдера зберігають нещодавні повідомлення користувача в межах того самого
бюджету `compaction.keep.tokens`, який локальні підсумки використовують для збереженого «хвоста». Параметр верхнього
рівня `compaction.auto: false` вимикає нові автоматичні стиснення, не видаляючи вже встановлених контрольних точок.
Про бюджетування та відновлення після переповнення див. [посібник зі стиснення контексту](/compaction).

### Прогрівання

Підтримуйте нещодавно активні сесії моделей «теплими» за допомогою періодичних тимчасових запитів. Прогрівання
за замовчуванням вимкнено; задайте значення `true`, щоб використовувати інтервал простою чотири хвилини та активне вікно
30 хвилин.

```jsonc
{
  "warming": {
    "prompt": "Do not perform any work. Reply with exactly: OK",
    "interval": "4 minutes",
    "duration": "30 minutes",
  },
}
```

Про поведінку запитів, налаштування та витрати див. [посібник із прогрівання](/warming).

### Навички

Додайте каталоги або URL-адреси, у яких OpenCode шукатиме навички агентів.

```jsonc
{
  "skills": ["./team-skills", "https://example.com/.well-known/skills/"],
}
```

Про структуру навичок і автоматичне виявлення в `.opencode/skills/` див. [посібник з навичок](/skills).

### Команди

Визначайте багаторазові слеш-команди як іменовані шаблони промптів.

```jsonc
{
  "commands": {
    "review": {
      "description": "Review the current changes",
      "template": "Review the current diff for correctness and missing tests.",
    },
  },
}
```

Про аргументи, моделі, агентів і команди у файлах див. [посібник з команд](/commands).

### Інструкції

Оголосіть додаткові файли інструкцій, glob-шаблони або URL-адреси. OpenCode приймає це поле, але не завантажує його
елементи; для інструкцій використовуйте `AGENTS.md`.

```jsonc
{
  "instructions": ["CONTRIBUTING.md", "docs/guidelines/*.md"],
}
```

Про інструкції проєкту та `AGENTS.md` див. [посібник з інструкцій](/instructions).

### Посилання на каталоги

Зробіть локальні каталоги або репозиторії Git доступними як іменований допоміжний контекст.

```jsonc
{
  "references": {
    "docs": {
      "path": "../product-docs",
      "description": "Product behavior and terminology",
    },
    "effect": {
      "repository": "Effect-TS/effect",
      "branch": "main",
    },
  },
}
```

Про скорочений запис, видимість і розв'язання шляхів див. [посібник з посилань на каталоги](/references).

### Worktree

Задайте батьківський каталог для нових локальних worktree. OpenCode додає до нього запитану або згенеровану назву
worktree.

```jsonc
{
  "worktree": {
    "directory": "../worktrees",
  },
}
```

Відносні шляхи розв'язуються відносно збереженої канонічної копії проєкту. Це стосується як глобальної, так і проєктної
конфігурації; абсолютні шляхи використовуються як є, а `~/` розв'язується відносно домашнього каталогу користувача.

Наприклад, ця глобальна конфігурація розміщує нові worktree у власному каталозі `.lane/trees/` кожного проєкту:

```jsonc
{
  "worktree": {
    "directory": ".lane/trees",
  },
}
```

Без цього налаштування worktree створюються в каталозі даних сервера в `worktree/<first-six-project-ID-characters>`
(перші шість символів ID проєкту). Під час створення й оновлення worktree конфігурація завантажується зі збереженої
канонічної копії проєкту, зокрема коли інші клони мають той самий ID проєкту. Зміна налаштування не переміщує наявні
worktree.

Вбудованим варіантом за замовчуванням є Git. [Плагін](/build/plugins#worktrees), що реєструє стратегію, автоматично
стає варіантом за замовчуванням у середовищі виконання цього плагіна. Операції з проєктом використовують середовище
виконання канонічної копії. Параметри, специфічні для стратегії, належать плагіну, а не об'єкту конфігурації
`worktree`.

### Плагіни

Завантажуйте плагіни з пакетів або локальних каталогів плагінів. Якщо плагін приймає параметри, використовуйте
об'єктну форму.

```jsonc
{
  "plugins": [
    "opencode-example-plugin",
    {
      "package": "./plugins/local",
      "options": {
        "enabled": true,
      },
    },
  ],
}
```

Про завантаження та налаштування плагінів див. [посібник з плагінів](/plugins).

### Провайдери

Налаштуйте провайдерів і додайте або перевизначте їхні моделі, параметри запитів, заголовки та варіанти моделей.

```jsonc
{
  "providers": {
    "openai": {
      "models": {
        "gpt-5.2-custom": {
          "modelID": "gpt-5.2",
          "name": "GPT-5.2 Custom",
          "limit": {
            "context": 200000,
            "output": 32000,
          },
        },
      },
    },
  },
}
```

Параметр провайдера `settings.transport: "websocket"` вмикає для нього сесійне з'єднання WebSocket.

Про облікові дані, власні ендпоінти, пакети провайдерів, транспорт WebSocket і налаштування моделей див.
[посібник із провайдерів](/providers).
