Запустіть CLI у проєкті, щоб відкрити повноекранний термінальний інтерфейс:

```bash
opencode
```

Щоб працювати в іншому проєкті, передайте шлях до каталогу:

```bash
opencode ~/code/my-project
```

Рекомендовані термінали:

- [Ghostty](https://ghostty.org)
- [WezTerm](https://wezterm.org)
- [Alacritty](https://alacritty.org)
- [Kitty](https://sw.kovidgoyal.net/kitty/)

З підтримкою truecolor теми відображаються з найточнішими кольорами; у терміналах без неї кольори наближено
відтворюються доступною палітрою.

## Автоматизація

Використовуйте `opencode run`, щоб надіслати промпт без відкриття інтерактивного інтерфейсу. Ця команда призначена для
скриптів, завдань CI та інших сценаріїв, яким потрібен вивід моделі безпосередньо в терміналі.

```bash
opencode run "Explain this repository"
```

## Mini

Використовуйте `opencode mini`, щоб запустити мінімальний інтерактивний інтерфейс OpenCode замість повноекранного TUI.

```bash
opencode mini
```

Виконайте `opencode mini --help`, щоб переглянути параметри сесії, моделі, агента, промпту та відтворення історії.

## Фоновий сервіс

За замовчуванням OpenCode знаходить або запускає один спільний фоновий сервер для вашого облікового запису користувача.
Усі локальні клієнти OpenCode під'єднуються до цього сервера, який керує сесіями, конфігурацією, інтеграціями,
дозволами та виконанням інструментів.

Використовуйте `--standalone`, щоб працювати з приватним сервером, або `--server`, щоб під'єднатися до сервера за
конкретною URL-адресою:

```bash
opencode --standalone
opencode --server http://localhost:4096
```

Щоб команди CLI за замовчуванням використовували приватні сервери замість запуску спільного сервісу, вимкніть його:

```bash
opencode service set disabled true
opencode
```

Це зупиняє запущений фоновий сервіс. `--server` і далі під'єднується до явно вказаного сервера, а
`opencode service start` і далі може явно запустити спільний сервіс. Щоб повернутися до автоматичного використання
сервісу, виконайте `opencode service unset disabled`. Для створення пари (pairing) потрібен спільний сервіс, тому поки він
вимкнений, ця функція недоступна.

Діагностику спільного сервісу описано в розділі [Усунення проблем](/troubleshooting), а ендпоінти сервера — у
[довіднику API](/api).

## Шляхи

Виведіть конкретний локальний шлях, щоб використати його в інших інструментах:

```bash
opencode debug paths db
sqlite3 "$(opencode debug paths db)"
```

Необов'язковий селектор приймає `db`, `home`, `data`, `config`, `cache`, `state`, `tmp`, `bin`, `log` або `repos` і
виводить лише шлях із символом нового рядка. Шлях до бази даних враховує канал випуску та `OPENCODE_DB`; відносні
перевизначення шляху до бази даних обчислюються відносно каталогу даних, а `:memory:` виводиться як є. Ця команда не
запускає сервер і не відкриває базу даних.

Пропустіть селектор, щоб показати всі шляхи з підписами:

```bash
opencode debug paths
```

## Видалення

Перегляньте файли та встановлення, які буде видалено:

```bash
opencode uninstall --dry-run
```

Виконайте `opencode uninstall`, щоб підтвердити видалення. OpenCode зупиняє зареєстровані фонові сервіси та постійні
термінали, а потім видаляє глобальний каталог кешу, спільний для всіх версій і каналів OpenCode. Дані сесій,
конфігурація та стан ніколи не видаляються.

- `--force` (`-f`) пропускає підтвердження; використовуйте його для неінтерактивного видалення.
- Для встановлень через менеджер пакетів використовується виявлений менеджер пакетів. Для встановлень через curl
  виводиться остаточна команда, щоб видалити виконуваний файл вручну.
