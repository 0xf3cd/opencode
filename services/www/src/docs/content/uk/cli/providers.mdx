Підключіть провайдера в TUI, а потім виберіть одну з його моделей:

```text
/connect
/models
```

`/connect` показує список інтеграцій, доступних на поточному сервері та в поточному проєкті. Виберіть провайдера,
виберіть спосіб автентифікації, якщо їх кілька, і дотримуйтеся підказок.

## TUI

TUI підтримує ключі API, OAuth і команди автентифікації провайдера. OAuth відкриває URL-адресу авторизації або показує
код, який потрібно ввести; натисніть `o`, щоб відкрити URL-адресу, і `c`, щоб скопіювати дані авторизації.

```text
/connect
# Select OpenAI, then Codex device code (legacy).
```

Щоб додати ще один обліковий запис, знову виконайте `/connect`. Якщо вибрати вже підключеного провайдера, відкриється
список його облікових записів, де збережений обліковий запис можна активувати, перейменувати або видалити.

## CLI

Використовуйте `auth login`, щоб скористатися тими самими способами автентифікації без відкриття TUI. Без аргументу з
провайдером команда відкриває інтерактивний вибір провайдера.

```bash
opencode auth login
```

Передайте ID або назву інтеграції, щоб пропустити перший вибір. Використайте `--method key`, щоб явно вибрати введення
ключа API.

```bash
opencode auth login anthropic --method key
```

ID способів залежать від провайдера. Якщо провайдер пропонує кілька способів, виконайте команду без `--method`, щоб
побачити доступні.

```bash
opencode auth login openai
```

Для введення ключа API і заповнення форм провайдера потрібен інтерактивний термінал. Він потрібен і для способів OAuth,
які просять вставити код авторизації.

## Способи

OpenCode отримує облікові дані провайдерів чотирма способами інтеграції:

| Спосіб | Поведінка |
| --- | --- |
| Ключ API | Запитує секрет і зберігає його як обліковий запис провайдера. |
| OAuth | Надає URL-адресу для браузера, код пристрою або запит коду авторизації, а потім зберігає токени й оновлює їх, якщо це підтримується. |
| Команда | Виконує команду автентифікації, надану провайдером, і зберігає її стандартний вивід як ключ. |
| Середовище | Зчитує підтримувану змінну з процесу сервера, не зберігаючи її. |

Провайдери можуть додавати до способів із ключем API та OAuth форми для обов'язкових даних, наприклад назви ресурсу
Azure або домену GitHub Enterprise. CLI і TUI показують ці форми перед початком автентифікації.

## Середовище

Задайте підтримувану змінну середовища провайдера для процесу сервера, який виконує запити до моделей. Для одноразового
приватного сервера передайте її під час запуску в автономному режимі.

```bash
ANTHROPIC_API_KEY=sk-ant-... opencode --standalone
```

Для спільного фонового сервера додайте змінну до його керованого середовища. Це зупиняє запущений сервіс; наступна
команда OpenCode запустить його з новим значенням.

```bash
opencode service set env ANTHROPIC_API_KEY sk-ant-...
opencode auth list
```

Підключення через середовище відображаються в `auth list` з типом `environment`. Це не облікові записи: `auth logout`
не може їх видалити, тому щоб відключитися, видаліть змінну. Збережений обліковий запис має вищий пріоритет, ніж
підключення через середовище для тієї самої інтеграції.

```bash
opencode auth list
opencode service unset env ANTHROPIC_API_KEY
```

Деякі хмарні провайдери замість змінної з ключем API використовують власний ланцюжок облікових даних із середовища:

- Amazon Bedrock підтримує стандартний ланцюжок облікових даних AWS, зокрема профілі, ключі доступу в змінних
  середовища, web identity та облікові дані контейнера. Також підтримується `AWS_BEARER_TOKEN_BEDROCK`.
- Google Vertex використовує Application Default Credentials і проєкт, який вдається визначити. Наприклад, пройдіть
  автентифікацію командою `gcloud auth application-default login` і задайте `GOOGLE_CLOUD_PROJECT`.
- Azure пропонує спосіб підключення **Microsoft Entra ID (Azure CLI)**, якщо встановлено `az`. Спочатку виконайте
  `az login`, а потім виберіть цей спосіб у `/connect` або `auth login azure`.

```bash
gcloud auth application-default login
GOOGLE_CLOUD_PROJECT=my-project opencode
```

Налаштування для конкретних провайдерів і на боці сервера описано в розділі [Провайдери](/providers).

## Облікові записи

Кожен успішний вхід із ключем API, через OAuth або командою створює збережений обліковий запис. Найновіший обліковий
запис стає активним; перемкнути активний обліковий запис можна за його підписом або ID облікових даних.

```bash
opencode auth list
opencode auth switch anthropic work
```

Видаліть збережений обліковий запис командою `auth logout`. Якщо аргументи не вказано, обидві команди відкривають вибір.

```bash
opencode auth logout anthropic work
```

У TUI команда `/connect` надає ті самі операції для збережених облікових записів: додавання, активацію, перейменування
та видалення.

## Зберігання

Збережені ключі API і токени OAuth зберігаються в базі даних SQLite сервера. Для локального сервера шлях до бази даних
можна вивести командою:

```bash
opencode debug paths db
```

Зазвичай для випуску це `~/.local/share/opencode/opencode.db`; шлях можуть змінити `XDG_DATA_HOME`, канал випуску та
`OPENCODE_DB`. Не редагуйте базу даних, щоб керувати обліковими даними; використовуйте `/connect` або команди `auth`.

Під час міграції бази даних V2 імпортує підтримувані облікові дані із застарілого `auth.json` у каталозі даних OpenCode.
Нові та оновлені облікові дані зберігаються в SQLite і не записуються назад у цей файл.
