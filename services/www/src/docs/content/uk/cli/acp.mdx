---

`opencode acp` запускає OpenCode як агента [Agent Client Protocol](https://agentclientprotocol.com), тож ним можна
користуватися з клієнта ACP, наприклад Zed. Цей приклад додає OpenCode у Zed:

```json title="~/.config/zed/settings.json"
{
  "agent_servers": {
    "OpenCode": {
      "command": "opencode",
      "args": ["acp"]
    }
  }
}
```

Інші клієнти ACP використовують ту саму команду й аргумент `acp`, але їхній файл конфігурації та назви полів можуть
відрізнятися. Якщо графічний клієнт не знаходить `opencode`, задайте в `command` абсолютний шлях, який виводить
`which opencode`.

## Автентифікація

OpenCode використовує облікові дані провайдерів, які в нього вже є. Перш ніж запускати клієнт ACP, увійдіть у терміналі:

```bash
opencode auth login
```

OpenCode пропонує один спосіб автентифікації — `opencode-login`. За замовчуванням це спосіб автентифікації агентом.
Запит `authenticate` приймає лише цей спосіб і не збирає облікових даних. Якщо промпт не вдається виконати, бо провайдер
потребує автентифікації, OpenCode повертає помилку ACP `auth_required`.

Якщо клієнт задає `clientCapabilities.auth.terminal` значення `true`, це спосіб автентифікації через термінал:

```json
{
  "id": "opencode-login",
  "name": "Login with opencode",
  "description": "Run `opencode auth login` in the terminal",
  "type": "terminal",
  "args": ["--login"]
}
```

Клієнт не повинен надсилати цей спосіб у `authenticate`. Натомість він додає `--login` до команди, яка запускає
OpenCode, наприклад `opencode acp --login`, і виконує її в терміналі. OpenCode проходить процедуру
`opencode auth login` і завершує роботу. Код виходу 0 означає, що вхід виконано успішно. Після цього клієнт
перепідключається і знову надсилає `initialize`.

Якщо клієнт задає `clientCapabilities._meta["terminal-auth"]` значення `true`, спосіб автентифікації містить команду
входу:

```json
{
  "id": "opencode-login",
  "name": "Login with opencode",
  "description": "Run `opencode auth login` in the terminal",
  "_meta": { "terminal-auth": { "command": "opencode", "args": ["auth", "login"], "label": "OpenCode Login" } }
}
```

## Усунення несправностей

`opencode acp` чекає на повідомлення ACP у stdin, тому якщо запустити його безпосередньо в терміналі, здається, що він
завис. Запускайте його з клієнта ACP.

Якщо клієнт повідомляє, що процес завершився або вивів некоректні дані протоколу, додайте `--print-logs` перед `acp`
в аргументах клієнта. Тоді OpenCode записує журнали ACP і приватного сервера в stderr. У stdout передаються лише
повідомлення ACP.

```bash
opencode --print-logs acp
```

## Довідник протоколу

Цей розділ призначено для авторів клієнтів ACP. У ньому перелічено частини ACP, які підтримує OpenCode, і ключі
`_meta`, які додає OpenCode. Клієнти, що не розпізнають ці ключі, можуть їх ігнорувати. Повідомлення визначено в
[документації ACP](https://agentclientprotocol.com).

### Транспорт

Клієнт запускає `opencode acp` як дочірній процес. Вони обмінюються повідомленнями JSON-RPC, розділеними символом нового
рядка, через stdin і stdout, за протоколом ACP версії 1.

`opencode acp` запускає приватний сервер OpenCode для власних потреб. Він не під'єднується до спільного фонового
сервісу і не відкриває мережевий порт для ACP. Один процес може обслуговувати багато сесій ACP. Він завершує роботу,
коли клієнт закриває stdin.

### Можливості

Відповідь OpenCode на `initialize` містить такі можливості агента:

```json
{
  "loadSession": true,
  "mcpCapabilities": { "http": true, "sse": false },
  "promptCapabilities": { "embeddedContext": true, "image": true },
  "sessionCapabilities": {
    "additionalDirectories": {},
    "close": {},
    "delete": {},
    "fork": {},
    "list": {},
    "resume": {}
  }
}
```

OpenCode зчитує такі можливості клієнта:

| Можливість                             | Результат                                                               |
| -------------------------------------- | ----------------------------------------------------------------------- |
| `auth.terminal` зі значенням `true`    | Спосіб автентифікації — [автентифікація через термінал](#authentication). |
| `elicitation.form`                     | OpenCode ставить [запитання](#questions) у вигляді форм.                |
| `session.compaction`                   | OpenCode повідомляє про [стиснення контексту](#compaction) через оновлення ACP. |
| `_meta["terminal-auth"]` зі значенням `true` | Спосіб автентифікації містить [команду входу](#authentication).   |

### Сесії

Клієнт задає робочий каталог під час створення сесії. OpenCode використовує конфігурацію цього каталогу, зокрема його
моделі, агентів, команди, навички, інструкції, плагіни та сервери MCP.

- `cwd` має бути абсолютним шляхом. Відносний `cwd` OpenCode відхиляє з помилкою недійсних параметрів.
- `session/load` відтворює збережені повідомлення. `session/resume` і `session/fork` їх не відтворюють.
- Щоб завантажити, відновити або розгалузити сесію, клієнт має передати каталог цієї сесії як `cwd`. Інший `cwd`
  OpenCode відхиляє з помилкою недійсних параметрів.
- `session/list` повертає до 100 сесій на сторінку. Приймає фільтр `cwd` і `cursor`.
- `session/close` перериває активну роботу та від'єднує сесію від процесу ACP. Збережену сесію OpenCode залишає.
- `session/delete` завершує активний промпт так само, як `session/cancel`, а потім видаляє сесію. Видалення сесії, якої
  не існує, завершується успішно.
- Сесія виконує лише один промпт водночас. Якщо надіслати другий `session/prompt`, поки перший активний, OpenCode
  поверне помилку.

### Скасування

`session/cancel` завершує активний промпт зі `stopReason: "cancelled"`. `$/cancel_request` для запиту промпту робить те
саме. OpenCode відхиляє запити на дозвіл, що очікують відповіді. Виклики інструментів, які не завершилися після
скасування, OpenCode позначає як `failed`.

### Додаткові каталоги

Клієнт може передати `additionalDirectories` у `session/new`, `session/load`, `session/resume` і `session/fork`:

```json
{ "cwd": "/work/app", "additionalDirectories": ["/work/shared"], "mcpServers": [] }
```

- Кожен запис має бути абсолютним шляхом без `*` і `?`.
- OpenCode дозволяє доступ до зовнішніх каталогів у межах кожного кореневого каталогу. Правила дозволів на читання,
  редагування та виконання команд оболонки й далі діють.
- Список у кожному запиті замінює попередній список сесії, як визначено в
  [RFD щодо додаткових каталогів](https://agentclientprotocol.com/rfds/additional-directories).
- OpenCode зберігає ці дозволи в сесії, тому вони діють і тоді, коли сесію використовує інший клієнт OpenCode. Дочірні
  сесії копіюють дозволи під час створення.

`session/list` повертає збережений список кожної сесії в `additionalDirectories`.

### Параметри конфігурації

Нові сесії використовують модель і основного агента за замовчуванням для каталогу. Відповіді на `session/new`,
`session/load`, `session/resume` і `session/fork` містять такі параметри конфігурації:

| ID       | Категорія       | Значення                                                                      |
| -------- | --------------- | ----------------------------------------------------------------------------- |
| `model`  | `model`         | Увімкнені моделі у форматі `provider/model`. Суфікс `/variant` також задає рівень зусиль. |
| `effort` | `thought_level` | Варіанти моделі та `default`. Є лише для моделей із варіантами.               |
| `mode`   | `mode`          | Видимі основні агенти.                                                        |

`session/set_config_option` приймає рядкові значення:

```json
{ "sessionId": "ses_123", "configId": "model", "value": "anthropic/claude-sonnet-4" }
```

`session/set_mode` також задає агента. OpenCode надсилає `config_option_update`, коли змінюються доступні моделі або
агенти, а також коли інший клієнт змінює модель або агента сесії.

### Вміст промпту

Промпти можуть містити текст, зображення, вбудовані ресурси та посилання на ресурси. Аудіоблоки OpenCode ігнорує. Інші
блоки обробляються так:

| Блок                                                  | Що робить OpenCode                                                                     |
| ----------------------------------------------------- | -------------------------------------------------------------------------------------- |
| `text`                                                | Надсилає його моделі.                                                                  |
| `text` лише з аудиторією `assistant`                  | Надсилає його моделі як окремий контекст, поза повідомленням користувача.              |
| `text` лише з аудиторією `user`                       | Не включає його у вхідні дані моделі.                                                  |
| `image` з `data`                                      | Вкладає його в промпт.                                                                 |
| `image` лише з `uri`                                  | Обробляє його як посилання на ресурс.                                                  |
| `resource` з `text`                                   | Вставляє текст після шляху або URI ресурсу.                                            |
| `resource` з `blob`                                   | Вкладає його, якщо задано `mimeType`. Інакше відкидає.                                 |
| `resource_link` на URI `file://`                      | Вкладає файл. Якщо файлу немає або його не вдається прочитати, натомість надсилає посилання Markdown. |
| `resource_link` на URI `zed://` з параметром запиту `path` | Вкладає файл за шляхом `path`.                                                    |
| `resource_link` на інший URI                          | Надсилає посилання Markdown, наприклад `[spec](https://example.com/spec.md)`.          |

Аудиторія визначається з `annotations` блоку. Блок `image`, у якому немає ні `data`, ні `uri`, OpenCode відхиляє. Цей
блок є контекстом лише для моделі:

```json
{ "type": "text", "text": "Open file: src/app.ts", "annotations": { "audience": ["assistant"] } }
```

### Команди

Після `session/new`, `session/load`, `session/resume` або `session/fork` OpenCode надсилає `available_commands_update`
з командами каталогу та вбудованою командою `compact`. Коли команди змінюються, OpenCode надсилає ще одне оновлення.

```json
{
  "sessionUpdate": "available_commands_update",
  "availableCommands": [{ "name": "compact", "description": "Compact the session" }]
}
```

Якщо промпт починається з `/` і назви доступної команди, OpenCode виконує цю команду, передаючи решту тексту як
аргументи. Інший текст, що починається з `/`, OpenCode надсилає як звичайний промпт. `/compact` запускає
[стиснення контексту](/compaction).

### Сервери MCP

Клієнт може передати сервери MCP типу stdio та HTTP у `session/new`, `session/load`, `session/resume` і `session/fork`.
OpenCode додає їх до каталогу сесії на весь час роботи процесу `opencode acp`, тож інші сесії в цьому каталозі теж
можуть ними користуватися. OpenCode передає заголовки HTTP без змін і не використовує OAuth для цих серверів. Він не
оголошує підтримку MCP через SSE і не підтримує MCP через ACP.

```json
{ "type": "http", "name": "docs", "url": "https://mcp.example.com", "headers": [] }
```

### Дозволи

Запити на дозвіл пропонують три варіанти:

```json
[
  { "optionId": "once", "kind": "allow_once", "name": "Allow once" },
  { "optionId": "always", "kind": "allow_always", "name": "Always allow" },
  { "optionId": "reject", "kind": "reject_once", "name": "Reject" }
]
```

Якщо запит змінює файли, OpenCode додає вміст `diff`, коли може побудувати попередній перегляд змін.

### Запитання

Якщо клієнт оголошує `elicitation.form`, OpenCode ставить запитання через `elicitation/create` у режимі форми. Запит
містить `toolCallId`, якщо OpenCode надіслав цей виклик інструмента як `session/update` для цієї сесії.

```json
{
  "mode": "form",
  "sessionId": "ses_123",
  "toolCallId": "call_1",
  "message": "Which package manager?",
  "requestedSchema": {
    "type": "object",
    "properties": { "pm": { "type": "string", "oneOf": [{ "const": "bun", "title": "Bun" }] } },
    "required": ["pm"]
  }
}
```

- OpenCode ніколи не надсилає форми, які можуть збирати секрети.
- Якщо поле, крім варіантів, приймає введену відповідь, схема додає необов'язкову рядкову властивість `<key>_custom`.
  Для одиночного вибору непорожня власна відповідь замінює вибраний варіант. Для множинного вибору OpenCode додає її до
  вибраних варіантів.
- Якщо користувач відхиляє або скасовує форму, OpenCode скасовує запитання.

Якщо OpenCode не може показати запитання, він скасовує його і вказує моделі продовжити без відповіді.

### Стиснення контексту

Якщо клієнт оголошує `session.compaction`, OpenCode повідомляє про стиснення контексту оновленнями `compaction_update` і
`compaction_summary_chunk` з RFD ACP про [стиснення сесії](https://agentclientprotocol.com/rfds/session-compaction),
який має статус Preview. Коли клієнт завантажує сесію, OpenCode відтворює кожне завершене або невдале стиснення як одне
оновлення.

```json
{
  "sessionUpdate": "compaction_update",
  "compactionId": "msg_123",
  "status": "completed",
  "summary": [{ "type": "text", "text": "..." }]
}
```

Інші клієнти натомість отримують [маркер стиснення](#compaction-marker). Маркер також використовується для стиснення
в дочірніх сесіях.

### Використання

Відповідь на промпт містить `usage` з RFD про
[використання наприкінці ходу](https://agentclientprotocol.com/rfds/end-turn-token-usage), який має статус чернетки.
`usage` підсумовує виклики моделі для цього промпту в цій сесії. Дочірні сесії не враховуються.

```json
{ "stopReason": "end_turn", "usage": { "inputTokens": 1200, "outputTokens": 340, "totalTokens": 1540 }, "_meta": {} }
```

Перед відповіддю OpenCode надсилає `usage_update` з RFD про
[використання в сесії](https://agentclientprotocol.com/rfds/session-usage). Він надсилає його лише тоді, коли промпт
використав токени і OpenCode знає розмір контексту моделі. `cost` — загальна вартість сесії в USD.

```json
{ "sessionUpdate": "usage_update", "used": 1540, "size": 200000, "cost": { "amount": 0.012, "currency": "USD" } }
```

### Дочірні сесії

Поки виконується промпт, OpenCode надсилає оновлення від своїх дочірніх сесій як сповіщення `session/update` у сесії
промпту. Кожне оновлення містить `_meta["opencode/child-session"]`. OpenCode додає до ID викликів інструментів префікс
`<childSessionId>:`. До назв викликів інструментів він додає як префікс назву дочірньої сесії, якщо вона є.

```json
{
  "sessionUpdate": "tool_call",
  "toolCallId": "ses_child:call_1",
  "title": "Explore the codebase: src/app.ts",
  "_meta": {
    "opencode/child-session": { "id": "ses_child", "parentID": "ses_123", "depth": 1, "title": "Explore the codebase" }
  }
}
```

| Поле       | Тип      | Опис                                                                                   |
| ---------- | -------- | -------------------------------------------------------------------------------------- |
| `id`       | `string` | ID дочірньої сесії.                                                                    |
| `parentID` | `string` | ID батьківської сесії для дочірньої сесії.                                             |
| `depth`    | `number` | 1 для дочірньої сесії сесії промпту, 2 для дочірньої сесії цієї дочірньої сесії і так далі. |
| `title`    | `string` | Назва дочірньої сесії. Якщо назви немає, OpenCode пропускає це поле.                   |

Запити на дозвіл від дочірньої сесії містять той самий ключ у `toolCall._meta`. Після завершення промпту OpenCode
перестає надсилати оновлення дочірніх сесій. Запити на дозвіл і запитання від дочірніх сесій і далі надходять клієнту.

### Стан повторних спроб

Коли виклик моделі завершується помилкою і OpenCode планує повторну спробу, він надсилає `session_info_update` з
`_meta["opencode/retry"]`. Коли повторна спроба починається, OpenCode надсилає `"opencode/retry": null`. Коли надходить
відповідь на промпт, очистьте будь-який стан повторної спроби.

```json
{
  "sessionUpdate": "session_info_update",
  "_meta": {
    "opencode/retry": {
      "attempt": 1,
      "nextRetryAt": "2026-10-02T12:00:05.000Z",
      "error": { "type": "provider.rate-limit", "message": "Rate limit exceeded", "status": 429 }
    }
  }
}
```

| Поле          | Тип      | Опис                                                                                       |
| ------------- | -------- | ------------------------------------------------------------------------------------------ |
| `attempt`     | `number` | Номер повторної спроби.                                                                    |
| `nextRetryAt` | `string` | Час наступної спроби у форматі ISO 8601.                                                   |
| `error`       | `object` | Містить `type` і `message`. Також містить `status` і `response.body`, якщо їх надіслав провайдер. |

### Маркер стиснення

Якщо клієнт не оголошує `session.compaction`, OpenCode повідомляє про хід стиснення контексту через
`session_info_update` з `_meta["opencode/compaction"]`. Для стиснення в дочірніх сесіях OpenCode завжди використовує
маркер.

```json
{
  "sessionUpdate": "session_info_update",
  "_meta": { "opencode/compaction": { "status": "started", "messageId": "msg_123", "reason": "auto" } }
}
```

| Поле        | Тип      | Опис                                                                                 |
| ----------- | -------- | ------------------------------------------------------------------------------------ |
| `status`    | `string` | `started`, `completed` або `failed`. Скасоване стиснення має стан `failed`.          |
| `messageId` | `string` | Пов'язує початок стиснення з його завершенням. Вважайте його непрозорим ключем.      |
| `reason`    | `string` | `auto` або `manual`.                                                                 |
| `error`     | `object` | Є, коли `status` має значення `failed`. Має ту саму форму, що й `error` у [повторних спробах](#retry-status). |

Маркер не містить підсумку. Автоматичне стиснення може завершитися невдачею без маркера `started`. Коли клієнт
завантажує сесію, OpenCode відтворює кожне завершене або невдале стиснення як один маркер.
