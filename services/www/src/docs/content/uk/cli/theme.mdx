---
title: "Тема"
---

OpenCode містить багато вбудованих тем зі світлим і темним режимами. Виберіть одну з них у налаштуваннях або підберіть
власні кольори.

## Вибір теми

Натисніть `Ctrl+P`, виберіть **Open settings**, а потім відкрийте **Theme**. Тема за замовчуванням — `opencode`.

Тему також можна задати в глобальних [налаштуваннях CLI](/cli/config):

```json title="~/.config/opencode/cli.json"
{
  "$schema": "https://opencode.ai/v2/cli.json",
  "theme": {
    "name": "tokyonight",
    "mode": "dark"
  }
}
```

Щоб змінити тему, не відкриваючи налаштувань, виконайте `/themes`.

## Системні кольори

Якщо OpenCode може прочитати палітру вашого термінала, у виборі тем з'являється тема `system`. Вона бере кольори з
основного кольору, тла та палітри ANSI вашого термінала.

Назва теми `system` вибирає кольори, отримані з термінала. Режим `system` відповідає світлому або темному вигляду
термінала.

## Режим

Використовуйте `system`, щоб тема відповідала вигляду термінала, або зафіксуйте світлий чи темний режим:

| Режим | Поведінка |
| --- | --- |
| `system` | Відповідає виявленому світлому або темному вигляду термінала. |
| `dark` | Завжди використовує темні кольори теми. |
| `light` | Завжди використовує світлі кольори теми. |

Це відповідає полю `mode` всередині `theme` у конфігурації CLI. Якщо власна тема надає лише один режим, OpenCode
використовує його, навіть коли запитано інший.

## Додавання теми

Щоб додати тему, яку ви завантажили або отримали від когось, скопіюйте її JSON-файл у глобальний каталог тем:

```bash
cp theme.json ~/.config/opencode/themes/
```

Тему також можна покласти в каталог `.opencode/themes` проєкту, щоб вона була доступна лише в цьому проєкті.

Назва файлу стає назвою теми. Наприклад, `my-theme.json` відображається як `my-theme`. Після додавання файлу
перезапустіть OpenCode, а потім виконайте `/themes`, щоб вибрати тему.

OpenCode читає лише файли `.json`. Тема, розташована ближче до поточного каталогу, замінює глобальну або батьківську тему
з такою самою назвою.

## Використання тем у плагінах

[Плагіни CLI](/build/plugins/cli) отримують обчислені кольори через `context.theme`, а активний режим — через
`context.themeMode`. Використовуйте семантичні токени, щоб ваш плагін відповідав вибраній темі:

```tsx title="Inside a CLI plugin component"
import { usePlugin } from "@opencode/plugin/tui"

function Status() {
  const context = usePlugin()
  return <text fg={context.theme.text.base}>Ready</text>
}
```

Публічний API плагінів CLI не реєструє теми. Додавайте визначення власних тем JSON-файлами в зазначених вище каталогах.

## Створення теми

Створюйте та редагуйте теми за допомогою нашого [Theme Tool](https://opencode.ai/theme/). Цей інструмент допомагає
легко зрозуміти структуру, змінити її та визначити власні кольори. Наведене нижче пояснення — довідкове.

Тема відокремлює спільні семантичні токени від палітр для окремих режимів:

| Розділ | Призначення |
| --- | --- |
| `base` | Повне дерево токенів, спільне для всіх режимів. |
| `light`, `dark` | Повна палітра відтінків і необов'язкові перевизначення токенів для цього режиму. |

Кожна тема надає повний `base` і визначає принаймні один із режимів `light` або `dark`. Режими успадковують значення з
`base` цього файлу; вони не успадковують їх ні з вбудованої теми OpenCode, ні один від одного.

Наведені нижче приклади показують лише розділи, що стосуються відповідного поняття. Перш ніж налаштовувати тему,
згенеруйте повний файл у редакторі тем.

### Структура

Кольори, які використовують обидва режими, розмістіть у `base`, а за потреби перевизначте їх у `light` або `dark`:

```json title="theme.json (excerpt)"
{
  "$schema": "https://opencode.ai/theme.json",
  "base": {
    "text": {
      "base": "$hue.neutral.200",
      "muted": "$hue.neutral.400"
    }
  },
  "light": {
    "hue": {}
  },
  "dark": {
    "hue": {},
    "text": {
      "muted": "$hue.neutral.300"
    }
  }
}
```

Повний `base` задає всі семантичні токени. Кожен режим задає всі обов'язкові відтінки й може перевизначити будь-яку
частину базового дерева токенів.

### Кольори та посилання

Колір може бути шістнадцятковим значенням, `"transparent"` або посиланням на інший колір теми:

```json title="Inside base or a mode"
{
  "text": {
    "base": "#eeeeee",
    "muted": "$hue.neutral.400"
  },
  "border": {
    "base": "$text.muted"
  }
}
```

### Відтінки

Відтінки — це дев'ятиступеневі колірні шкали. Кожен режим визначає вісім базових відтінків і три псевдоніми:

| Тип | Значення |
| --- | --- |
| Базовий | `gray`, `red`, `orange`, `yellow`, `green`, `cyan`, `blue`, `purple` |
| Псевдонім | `accent`, `interactive`, `neutral` |
| Ступінь | `100`, `200`, `300`, `400`, `500`, `600`, `700`, `800`, `900` |

Визначте всі дев'ять ступенів для базового відтінку або зробіть один відтінок псевдонімом іншого:

```json title="Inside light or dark"
{
  "hue": {
    "purple": {
      "100": "#b38ff4",
      "200": "#9d7cd8",
      "300": "#8869bd",
      "400": "#7357a2",
      "500": "#5f4688",
      "600": "#4b356f",
      "700": "#392557",
      "800": "#271640",
      "900": "#17072b"
    },
    "accent": "$hue.purple"
  }
}
```

Ступені відтінків ідуть у напрямку контрасту режиму. У світлих темах вони змінюються від темного на `100` до світлого на
`900`; у темних темах — від світлого на `100` до темного на `900`.

Масив `categorical` у `base` задає впорядкований список відтінків, якими розрізняють агентів та інші повторювані
елементи:

```json title="Inside base"
{
  "categorical": ["accent", "purple", "green", "blue"]
}
```

### Семантичні токени

Семантичні токени призначають кольори ролям в інтерфейсі. Компоненти використовують ці ролі, а не вибирають кольори
напряму.

| Група | Призначення |
| --- | --- |
| `text` | Основний, приглушений текст, текст дій, полів форм, стану та зворотного зв'язку. |
| `background` | Основне тло, підняті поверхні, дії, поля форм і заливки для зворотного зв'язку. |
| `border`, `scrollbar` | Кольори рамок і смуг прокручування. |
| `diff` | Кольори доданих, видалених і контекстних рядків, виділення та номерів рядків. |
| `syntax` | Підсвічування вихідного коду. |
| `markdown` | Елементи Markdown. |

Наприклад, `text.muted` керує другорядним текстом, а `background.raised` визначає поверхні з поступово більшим
підняттям:

```json title="Inside base"
{
  "text": {
    "base": "$hue.neutral.200",
    "muted": "$hue.neutral.400"
  },
  "background": {
    "base": "$hue.neutral.800",
    "raised": {
      "base": "$hue.neutral.700",
      "high": "$hue.neutral.600",
      "max": "$hue.neutral.500"
    }
  }
}
```

Ключі синтаксису: `comment`, `keyword`, `function`, `variable`, `string`, `number`, `type`, `operator` і `punctuation`.

Ключі Markdown: `text`, `heading`, `link`, `linkText`, `code`, `blockQuote`, `emphasis`, `strong`, `horizontalRule`,
`listItem`, `listEnumeration`, `image`, `imageText` і `codeBlock`.

### Дії та стани

Дії мають варіанти `primary`, `secondary` і `destructive`. Дії та поля форм використовують `base` і необов'язкові
стани взаємодії:

```json title="Inside base or a mode"
{
  "text": {
    "action": {
      "primary": {
        "base": "$hue.interactive.400",
        "$hovered": "$hue.interactive.300",
        "$disabled": "$hue.neutral.600"
      }
    }
  }
}
```

Ключі станів: `$hovered`, `$focused`, `$pressed`, `$selected` і `$disabled`. Для незаданого стану використовується
колір `base` відповідної дії або поля форми.

### Поверхня діалогових вікон

Панелі, діалогові вікна, меню та спливні сповіщення вибирають рівень підняття з `background.raised`. Діалогові вікна
можуть додатково перевизначати семантичні токени через `@dialog`:

```json title="Inside base or a mode"
{
  "@dialog": {
    "background": {
      "base": "$background.raised.base",
      "action": {
        "primary": {
          "$hovered": "$background.raised.high"
        }
      }
    }
  }
}
```

Після застосування `@dialog` TUI знову обчислює посилання, тож токени, що посилаються на `$background.base`, відповідають
тлу діалогового вікна. Контекстний `base` дії стає резервним значенням для її незаданих станів; явно задані
перевизначення станів і далі мають пріоритет.
