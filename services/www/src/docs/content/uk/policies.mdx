Політики визначають, чи може OpenCode виконати дію з іменованим ресурсом. Їх задають у `policies`, а також їх може
надавати підключений робочий простір [OpenCode Console](/console).

Політики відокремлені від [дозволів](/permissions). Дозволи — це правила інструментів для окремих агентів, які можуть
мати значення `allow`, `deny` або `ask`. Політики бінарні, ніколи не запитують підтвердження й можуть лише звузити
те, що інакше було б дозволено дозволами та провайдерами.

## Налаштування

Щоб заборонити одного провайдера скрізь, додайте інструкцію в `opencode.jsonc`:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "policies": [{ "action": "provider.use", "resource": "openai", "effect": "deny" }],
}
```

Заборонений провайдер зникає з каталогу й вибору моделі, навіть якщо для нього є дійсні облікові дані.

Попередні випуски читали політики з `experimental.policies`. Цей ключ досі працює й об'єднується з `policies`:

```jsonc
{
  "experimental": {
    "policies": [{ "action": "provider.use", "resource": "openai", "effect": "deny" }],
  },
}
```

## Інструкції політики

Кожна інструкція має три поля:

| Поле | Значення | Призначення |
| --- | --- | --- |
| `action` | `provider.use`, `tool.use`, `integration.use` | Операція, яку контролюють |
| `resource` | рядок або шаблон із символами підстановки | До чого застосовується інструкція; залежить від дії |
| `effect` | `allow`, `deny` | Рішення, коли інструкція збігається |

Інструкції, що не пройшли валідацію, відкидаються з попередженням у журналі сервера, а решта списку продовжує діяти.
Після редагування `deny` перевірте журнал.

## Зіставлення

Ресурси підтримують ті самі шаблони для всього значення, що й дозволи: `*` збігається з нулем або більше символів, а
`?` — з одним символом.

```jsonc
{
  "policies": [{ "action": "provider.use", "resource": "company-*", "effect": "deny" }],
}
```

Це забороняє `company-us` і `company-eu`. Шаблон, що закінчується на ` *`, також збігається зі значенням без аргументів,
тож `shell:git push *` охоплює й саму команду `git push`.

## Порядок

Коли збігається кілька інструкцій, діє остання. Правила специфічності немає, тому спершу розміщуйте загальні
інструкції, а після них — винятки. Якщо нічого не збігається, дію дозволено.

```jsonc
{
  "policies": [
    { "action": "provider.use", "resource": "*", "effect": "deny" },
    { "action": "provider.use", "resource": "anthropic", "effect": "allow" },
  ],
}
```

Доступним залишається лише Anthropic.

## Провайдери

`provider.use` визначає, чи можна взагалі використовувати провайдера. Ресурсом є ID провайдера: `anthropic`, `openai`,
`opencode` або власний ID із [`providers`](/providers).

```jsonc
{
  "providers": {
    "company-ai": {
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": { "baseURL": "https://ai.company.example/v1" },
    },
  },
  "policies": [
    { "action": "provider.use", "resource": "*", "effect": "deny" },
    { "action": "provider.use", "resource": "company-ai", "effect": "allow" },
  ],
}
```

Запис у `providers` налаштовує ендпоінт, а інструкції роблять його єдиним провайдером, якого використовуватиме
OpenCode. Політика застосовується незалежно від того, звідки OpenCode дізнався про провайдера: з даних каталогу, змінних
середовища, збережених облікових записів, вбудованих плагінів чи конфігурації.

Використовуйте `provider.use` замість списків V1 `enabled_providers` і `disabled_providers`. Файли V1 і далі
завантажуються; див. [Перехід з V1](/migrate-v1#supported-fields-without-direct-native-equivalents).

## Інструменти

Інструкції `tool.use` остаточно забороняють перевірку [дозволу](/permissions). Ресурс має вигляд `<action>:<value>` і
зіставляється з кожним ресурсом, який перевіряє інструмент.

```jsonc
{
  "policies": [
    { "action": "tool.use", "resource": "shell:git push *", "effect": "deny" },
    { "action": "tool.use", "resource": "edit:*.env", "effect": "deny" },
    { "action": "tool.use", "resource": "webfetch:*", "effect": "deny" },
  ],
}
```

Заборонена перевірка завершується помилкою `Blocked by configuration policy` замість запиту на підтвердження. Вона
застосовується після правил агента та збережених підтверджень, тому перевизначає як `ask`, так і підтвердження
«Allow always».

| Шаблон | Що блокує |
| --- | --- |
| `shell:*` | Усі команди оболонки |
| `read:*/.ssh/*` | Читання SSH-ключів і пов'язаних файлів |
| `external_directory:*` | Будь-який доступ поза розташуванням (Location) або worktree |
| `subagent:general` | Запуск одного субагента |
| `github_delete_repository:*` | Один інструмент MCP |
| `*` | Усе, що ще не заборонено |

Інструкція `tool.use` з `allow` ніколи не надає доступу. Вона лише знімає попередню ширшу заборону `deny`, після чого
рішення ухвалюють власні правила агента.

```jsonc
{
  "policies": [
    { "action": "tool.use", "resource": "shell:*", "effect": "deny" },
    { "action": "tool.use", "resource": "shell:git status *", "effect": "allow" },
  ],
}
```

Для `git status` діє правило `shell` агента; усі інші команди заблоковано.

## Інтеграції

`integration.use` визначає, чи завантажується сервер MCP, навичка або плагін. Ресурсом є тип інтеграції та її ID:

| Ресурс | Застосовується до |
| --- | --- |
| `mcp:<server>` | [Сервера MCP](/mcp-servers) за його назвою в конфігурації |
| `skill:<id>` | [Навички](/skills) за її ID |
| `plugin:<target>` | [Плагіна](/plugins) за назвою пакета без версії або абсолютним шляхом |

```jsonc
{
  "policies": [
    { "action": "integration.use", "resource": "mcp:*", "effect": "deny" },
    { "action": "integration.use", "resource": "mcp:github", "effect": "allow" },
    { "action": "integration.use", "resource": "plugin:opencode-acme-cli", "effect": "deny" },
  ],
}
```

Заборонений сервер MCP чи навичка вилучаються, а заборонений плагін не завантажується — незалежно від того, як їх
налаштовано.

## Пріоритет

Для звичайних налаштувань перемагає найближча конфігурація. Для політик навпаки: інструкції із ширших конфігурацій
обчислюються пізніше, тому перевизначають вужчі. Остаточне слово завжди за керованою конфігурацією та підключеним
OpenCode Console.

| Пріоритет | Джерело |
| --- | --- |
| 1 (найвищий) | Підключений робочий простір OpenCode Console |
| 2 | Керовані налаштування macOS (`/Library/Managed Preferences/ai.opencode.managed.plist`) |
| 3 | Системний `opencode.json(c)` (`/Library/Application Support/opencode`, `/etc/opencode`, `%ProgramData%\opencode`) |
| 4 | Глобальний `~/.config/opencode/opencode.json(c)` |
| 5 | Безпосередньо `opencode.json(c)`; зовнішні каталоги мають перевагу над внутрішніми |
| 6 (найнижчий) | `.opencode/opencode.json(c)`; зовнішні каталоги мають перевагу над внутрішніми |

Репозиторій не може знову ввімкнути провайдера, якого ви заборонили глобально:

```jsonc title="~/.config/opencode/opencode.jsonc"
{
  "policies": [{ "action": "provider.use", "resource": "openai", "effect": "deny" }],
}
```

```jsonc title="project/opencode.jsonc"
{
  "policies": [{ "action": "provider.use", "resource": "openai", "effect": "allow" }],
}
```

`openai` залишається забороненим. У межах одного файлу інструкції зберігають порядок, у якому їх записано.

## Console

Робочий простір в [OpenCode Console](/console) компілює свої політики Providers і Tools в інструкції та повертає їх
разом із конфігурацією робочого простору. OpenCode додає їх після всіх інструкцій, заданих у файлах, тож остаточне
слово за ними: `deny` організації не можуть зняти `allow` репозиторію чи користувача, а `allow` організації знімає
`deny` з нижчим пріоритетом.

Заборони з цих інструкцій містять назву робочого простору:

```text
Blocked by Acme's policy
```

Інструкції прив'язані до підключеного облікового запису.

| Подія | Результат |
| --- | --- |
| Зміна політики в OpenCode Console | Застосовується під час наступного отримання, приблизно раз на хвилину |
| Перемикання на інший робочий простір | Інструкції замінюються інструкціями цього робочого простору |
| Відключення | Інструкції очищаються |
| OpenCode Console недоступний | Останні інструкції для цього підключення залишаються чинними |

Плагін Console і плагін політик не можна вимкнути через `plugins`; див.
[керування плагінами](/plugins#control).

<Callout type="note">
  Політики не налаштовують ендпоінти чи облікові дані й не можуть зробити непридатного до використання провайдера
  придатним. Вони також не ізолюють код плагінів: заборонений провайдер блокується на звичайному шляху використання
  провайдерів і моделей.
</Callout>
