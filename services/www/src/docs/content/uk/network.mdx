---
title: Мережа
description: Налаштування проксі та власних центрів сертифікації.
---

Задайте стандартні змінні проксі та виключіть loopback-адреси. OpenCode використовує локальні HTTP-з'єднання між CLI і
фоновим сервісом, тому якщо в середовищі CLI налаштовано проксі, виключення loopback-адрес обов'язкове.

```bash
export HTTP_PROXY=http://proxy.example.com:8080
export HTTPS_PROXY=http://proxy.example.com:8080
export NO_PROXY=localhost,127.0.0.1,::1

opencode
```

`HTTP_PROXY` застосовується до HTTP-адрес призначення, а `HTTPS_PROXY` — до HTTPS-адрес. Сама URL-адреса проксі може
використовувати `http://` в обох змінних. `NO_PROXY` — це список хостів і адрес через кому, до яких слід підключатися
напряму.

## Сервіс

Змінні, експортовані в оболонці, впливають на фоновий сервіс лише тоді, коли його запущено з цієї оболонки. Збережіть
змінні в конфігурації керованого сервісу, щоб під час наступних запусків він використовував ті самі мережеві
налаштування.

```bash
opencode service set env HTTP_PROXY http://proxy.example.com:8080
opencode service set env HTTPS_PROXY http://proxy.example.com:8080
opencode service set env NO_PROXY localhost,127.0.0.1,::1
opencode service start
```

Зміна керованої змінної середовища зупиняє запущений сервіс. Команда `service start` запускає його знову з новим
середовищем. Якщо оболонка CLI теж задає проксі, залиште `NO_PROXY` і в ній: змінні керованого сервісу застосовуються
до процесу сервера, а не до процесу CLI.

Щоб видалити збережену змінну, використайте `service unset env`:

```bash
opencode service unset env HTTPS_PROXY
```

## Автентифікація

Якщо проксі приймає облікові дані в URL-адресі, додайте ім'я користувача та пароль до кожної URL-адреси проксі, що
потребує автентифікації. Символи на кшталт `@`, `:` і `/` в імені користувача чи паролі потрібно закодувати
percent-кодуванням.

```bash
export HTTPS_PROXY='http://user:p%40ssword@proxy.example.com:8080'
```

Для фонового сервісу збережіть повну URL-адресу. Значення зберігається в приватній конфігурації сервісу і виводиться
командою `opencode service get env`, тому не поширюйте цей вивід.

```bash
opencode service set env HTTPS_PROXY 'http://user:p%40ssword@proxy.example.com:8080'
```

## Сертифікати

Якщо проксі або сервер призначення використовує сертифікат, підписаний приватним центром сертифікації, вкажіть
у `NODE_EXTRA_CA_CERTS` шлях до PEM-файлу. Додаткові центри сертифікації додаються до сховища довірених сертифікатів
середовища виконання під час запуску процесу.

```bash
export NODE_EXTRA_CA_CERTS=/etc/company/ca.pem
opencode --standalone
```

Збережіть шлях до файлу для фонового сервісу, а потім перезапустіть його:

```bash
opencode service set env NODE_EXTRA_CA_CERTS /etc/company/ca.pem
opencode service start
```

## Передній план

`--standalone` і `serve` використовують середовище власного процесу. Команда `opencode service set env` ці процеси
не налаштовує.

```bash
HTTP_PROXY=http://proxy.example.com:8080 \
HTTPS_PROXY=http://proxy.example.com:8080 \
NO_PROXY=localhost,127.0.0.1,::1 \
opencode --standalone
```

Так само налаштуйте сервер, запущений на передньому плані:

```bash
HTTPS_PROXY=http://proxy.example.com:8080 \
NO_PROXY=localhost,127.0.0.1,::1 \
opencode serve
```

## Перевірка

Після застосування налаштувань переконайтеся, що CLI може під'єднатися до фонового сервісу:

```bash
opencode api get /api/info
```

Успішна відповідь перевірки стану підтверджує локальне з'єднання між клієнтом і сервісом. Щоб перевірити вихідний
проксі та сертифікати сервісу, виконайте звичайний запит до провайдера.
