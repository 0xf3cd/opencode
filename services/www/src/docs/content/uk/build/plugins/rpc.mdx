---
title: "RPC"
---

Плагіни можуть надавати власні методи й події, які виконуються на сервері та доступні для виклику з інших плагінів або
клієнтів.

## Визначення

Перелічіть методи, помилки й події RPC за допомогою `Rpc.define`.

```ts title="src/rpc.ts"
import { Rpc } from "@opencode/plugin/rpc"

export const Acme = Rpc.define({
  id: "acme",
  methods: {
    search: {
      input: {
        type: "object",
        properties: { query: { type: "string" } },
        required: ["query"],
        additionalProperties: false,
      },
      output: {
        type: "object",
        properties: { text: { type: "string" } },
        required: ["text"],
        additionalProperties: false,
      },
      errors: {
        not_found: {
          type: "object",
          properties: { query: { type: "string" } },
          required: ["query"],
          additionalProperties: false,
        },
      },
    },
  },
  events: {
    updated: {
      schema: {
        type: "object",
        properties: {
          itemID: { type: "string" },
          text: { type: "string" },
        },
        required: ["itemID", "text"],
        additionalProperties: false,
      },
    },
  },
})
```

### Валідація

Визначення RPC описує структуру вхідних і вихідних даних методів, подій та помилок. Підтримуються два формати схем:

- JSON Schema — простий формат, що не потребує залежностей.
- Будь-який валідатор, сумісний зі Standard Schema:
  - Zod
  - Valibot
  - ArkType

### Вхідні й вихідні дані

Кожен метод може визначати схему `input` для свого аргументу та схему `output` для значення, що повертається. Пропустіть
будь-яку з них, якщо метод не приймає або не повертає значення.

```ts
search: {
  input: {
    type: "object",
    properties: { query: { type: "string" } },
    required: ["query"],
  },
  output: {
    type: "object",
    properties: { text: { type: "string" } },
    required: ["text"],
  },
}
```

Значення з JSON Schema в TypeScript мають тип `unknown`, тож звужуйте їхній тип перед використанням. Standard Schema
виводить типи вхідних і вихідних даних автоматично.

### Помилки

Додайте до методу мапу `errors` для очікуваних збоїв. Кожен ключ стає `type` помилки, а його схема визначає `data`
помилки.

```ts
errors: {
  not_found: {
    type: "object",
    properties: { query: { type: "string" } },
    required: ["query"],
    additionalProperties: false,
  },
}
```

Назви помилок, що починаються з `rpc.`, зарезервовані за OpenCode.

### Події

Додайте події до мапи `events` верхнього рівня. Кожна подія має схему даних, які надсилаються підписникам.

Дані події мають бути об'єктом. Якщо даних немає, використайте схему порожнього об'єкта:

```ts
events: {
  refreshed: {
    schema: { type: "object", additionalProperties: false },
  },
}
```

Скалярні значення, масиви, `null` і `undefined` не є допустимими даними події.

## Реалізація

Зареєструйте реалізацію всередині `setup`:

```ts title="src/index.ts"
import { Plugin } from "@opencode/plugin"
import { Acme } from "./rpc.js"

export default Plugin.define({
  id: "acme-plugin",
  async setup(ctx) {
    const registration = await ctx.rpc.register(Acme, {
      search: async (input, context) => {
        const { query } = input as { query: string }
        const text = await findText(query, { signal: context.signal })
        if (!text) return context.error("not_found", "Result not found", { query })
        return { text }
      },
    })

    const acme = ctx.rpc(Acme)
    const result = await acme.search({ query: "hello" })

    await registration.events.emit("updated", { itemID: "item-1", text: "ready" })
  },
})
```

Після реєстрації RPC той самий плагін може викликати його через `ctx.rpc(Acme)`.

Другий аргумент містить `signal` для скасування та `context.error(...)` для оголошених помилок. Помилку можна повернути
або викинути.

Один плагін може зареєструвати кілька RPC. Звільнення реєстрації видаляє відповідний RPC.

## Виклик

Зареєстрований RPC можна викликати через HTTP або з іншого плагіна.

### HTTP

Створіть клієнт OpenCode, а потім за допомогою `client.rpc` створіть субклієнт для RPC:

```ts
import { OpenCode } from "@opencode/client"
import { Acme } from "opencode-acme-plugin/rpc"

const client = OpenCode.make({
  baseUrl: "http://localhost:4096",
})

const acme = client.rpc(Acme)
const result = await acme.search({ query: "hello" })
```

### Плагін

Плагіни вже мають клієнт OpenCode. Наприклад, TUI-плагін може створити той самий субклієнт RPC з `context.client`:

```ts title="src/tui.ts"
import { Plugin } from "@opencode/plugin/tui"
import { Acme } from "opencode-acme-plugin/rpc"

export default Plugin.define({
  id: "acme-tui",
  async setup(context) {
    const acme = context.client.rpc(Acme)
    const result = await acme.search({ query: "hello" })
    console.log(result)
  },
})
```

### Підписка

Використовуйте `events.on`, щоб передати колбек, і скасуйте підписку, коли слухач більше не потрібен:

```ts
const unsubscribe = acme.events.on("updated", (event) => {
  console.log(event.type, event.location.directory, event.data.text)
})

unsubscribe()
```

Для асинхронного ітератора використовуйте `events.subscribe("updated")`:

```ts
for await (const event of acme.events.subscribe("updated")) {
  console.log(event.data.text)
}
```

Підписки на події працюють лише в реальному часі, тож від'єднані підписники пропускають події.

- Підписуйтеся за локальною назвою, наприклад `updated`.
- Отриманий тип має префікс, наприклад `rpc.acme.updated`.
- Кожна подія містить `data` і `location`.
- Вивантаження плагіна закриває його підписки.

Зовнішні клієнти отримують події з усіх розташувань, тож за потреби перевіряйте `event.location`. Серверний плагін при
цьому має бути налаштований і запущений.
