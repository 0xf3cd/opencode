`@opencode/client` — це клієнт TypeScript для HTTP API OpenCode. Використовуйте
його, коли ваш застосунок підключається до сервера OpenCode через мережу. Його
нативні типи й методи згенеровано з того самого контракту, що й
[довідник API](/api). Типи RPC плагінів беруться з імпортованих визначень RPC.

## Установлення

```sh
bun add @opencode/client
```

## Створення клієнта

Створіть клієнт з URL-адресою сервера, а потім викликайте методи, згруповані за ресурсами API:

```ts
import { OpenCode } from "@opencode/client"

const client = OpenCode.make({
  baseUrl: "http://localhost:4096",
})

const session = await client.session.create({
  location: { directory: "/workspace" },
})

await client.session.prompt({
  sessionID: session.id,
  text: "Review the current changes",
})
```

## Заголовки та запити

Передайте в `OpenCode.make` через `headers` заголовки автентифікації або
застосунку за замовчуванням. Також можна вказати власну реалізацію `fetch`.
Кожна операція приймає останнім аргументом параметри запиту — для `AbortSignal`
або заголовків окремого запиту. Виняток становлять підписки на події: вони
підтримують лише скасування на рівні підписника й використовують заголовки
базового клієнта.

```ts
const client = OpenCode.make({
  baseUrl: "https://opencode.example.com",
  headers: {
    authorization: `Bearer ${process.env.OPENCODE_TOKEN}`,
  },
})

await client.session.list(undefined, {
  signal: AbortSignal.timeout(10_000),
})
```

## Потік подій

Потокові ендпоінти повертають асинхронні ітеровані об'єкти:

```ts
for await (const event of client.event.subscribe()) {
  console.log(event.type)
}
```

Підписники на нативні та RPC-події спільно використовують одне ліниве з'єднання
на клієнт. Створення клієнта, дескриптора чи ітерованого об'єкта не відкриває
з'єднання для подій — його відкриває споживання. Вихід з ітерації або скасування
підписника завершує лише відповідний ітератор. Коли від'єднується останній
підписник, з'єднання закривається. Спільне джерело чекає, доки активні підписники
приймуть кожну подію, тому перед повільною обробкою споживачам варто буферизувати
події.

Підписки працюють лише в реальному часі, без повторного відтворення й
автоматичного перепідключення. Збій джерела завершує поточні підписки; після
відновлення підпишіться знову. Нативний підписник, що приєднався пізніше, отримує
поточний маркер `server.connected`, а не минулі бізнес-події.

## RPC плагінів

Імпортуйте спільний контракт плагіна й передайте його в `client.rpc`:

```ts
import { OpenCode } from "@opencode/client"
import { Acme } from "opencode-acme-plugin/rpc"

const acme = client.rpc(Acme)
const result = await acme.search(
  { query: "hello" },
  { location: { directory: "/workspace" }, signal: AbortSignal.timeout(10_000) },
)

const unsubscribe = acme.events.on("updated", (event) => {
  console.log(event.type, event.location.directory, event.data.text)
})
```

Другий необов'язковий аргумент методу містить `location`, `signal` і `headers`
окремо від вхідних даних, визначених плагіном. Якщо розташування не вказано,
діють ті самі правила за замовчуванням, що й для нативних запитів: спочатку
заголовки розташування базового клієнта, потім робочий каталог сервера.
Створення підклієнта розташування не вибирає.

Методи виводять типи аргументів і результатів із визначення. Розбір схем
відбувається на межі контракту: виклики надсилають прийнятне представлення
вхідних даних, а обробники отримують уже розібрані значення. Promise-клієнт
приймає визначення Standard Schema або звичайні визначення JSON Schema і не
запускає парсери схем локально: сервер повертає вже розібрані й перетворені
вихідні дані. Для визначень Effect Schema потрібен Effect-клієнт.

Оголошені помилки методів відхиляють Promise так само, як помилки інших
ендпоінтів Promise-клієнта, а перехоплені помилки залишаються нетипізованими.
Типізований підклієнт знімає загальні обгортки помилок HTTP RPC. Зарезервовані
збої фреймворку `rpc.*` залишаються звичайними збоями RPC, а не пов'язані з RPC
помилки автентифікації, транспорту та протоколу зберігають звичне для клієнта
представлення.

Підписки RPC використовують локальні назви подій і отримують події цього RPC з
усіх розташувань. Щоб відфільтрувати їх, перевіряйте обов'язкове поле
`event.location`. `events.subscribe` відповідає нативному API асинхронних
ітерованих об'єктів:

```ts
for await (const event of acme.events.subscribe("updated")) {
  console.log(event.data.text)
}
```

`events.on` — зручна обгортка над тим самим джерелом. Вона повертає функцію
відписки; асинхронні колбеки виконуються послідовно з очікуванням. Збої колбека
або джерела записуються в журнал і завершують цього слухача. Нативні й
типізовані підписки отримують однаковий звичайний конверт
`rpc.<rpcID>.<event>` з даними події у вигляді об'єкта. Підписки в реальному
часі не відтворюють пропущені події.

Серверний плагін має бути налаштований і реалізовувати RPC: імпорт визначення
не реєструє його. API визначення та реєстрації описано в розділі
[RPC плагінів](/build/plugins/rpc). Будь-який HTTP-клієнт також може викликати
загальний маршрут `POST /api/rpc/{rpcID}/{method}` з `{ "input": ... }` і
отримати `{ "output": ... }`. Відсутні поля input/output означають відсутність
значення.

## Локальний фоновий сервіс

Основні точки входу клієнта сумісні з браузером і не містять керування
локальними процесами. У застосунку Node імпортуйте нативний Promise API сервісу
з `@opencode/client/service`.

- `Service.discover()` повертає справний зареєстрований ендпоінт, не запускаючи
  процес.
- `Service.ensure()` повертає сумісний сервіс і за потреби запускає його.
- `Service.stop()` зупиняє саме той екземпляр сервісу, що зареєстрований.
- `Service.headers(endpoint)` створює заголовки автентифікації для клієнта.

```ts
import { OpenCode } from "@opencode/client"
import { Service } from "@opencode/client/service"

const endpoint = await Service.ensure()
const client = OpenCode.make({
  baseUrl: endpoint.url,
  headers: Service.headers(endpoint),
})

const info = await client.server.info()
```

`Service.ensure()` приймає необов'язкові файл реєстрації, версію, команду
сервісу та колбек `onStart`. `version` приймає точне значення або предикат
сумісності:

```ts
const endpoint = await Service.ensure({
  file: "/var/run/opencode/service.json",
  version: (version) => version.startsWith("2."),
  command: ["opencode", "serve", "--service"],
  onStart(reason, previousVersion) {
    console.log(reason, previousVersion)
  },
})
```

Якщо ці параметри не вказати, використовуються стандартний шлях реєстрації та
команда `opencode serve --service`.
