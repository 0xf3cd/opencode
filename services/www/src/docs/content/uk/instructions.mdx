title: "Інструкції"
---

Додайте файл `AGENTS.md`, щоб надати OpenCode постійні вказівки щодо проєкту. Опишіть у ньому команди збирання, нотатки
про архітектуру, домовленості щодо коду та вимоги до перевірки.

```md title="AGENTS.md"
# Project instructions

- Run `bun typecheck` after changing TypeScript.
- Keep database queries in `src/database`.
- Do not edit generated files directly.
```

Додайте файли інструкцій проєкту в репозиторій, щоб усі, хто з ним працює, отримували однакові вказівки.

## Область дії

Розмістіть `AGENTS.md` у каталозі, до якого мають застосовуватися його вказівки. OpenCode завантажує глобальний файл, а
потім кожен `AGENTS.md`, рухаючись від поточного каталогу робочого простору до домашнього каталогу. Для робочих
просторів поза домашнім каталогом пошук зупиняється на корені проєкту.

```text
~/.config/opencode/AGENTS.md
~/code/my-project/AGENTS.md
~/code/my-project/packages/AGENTS.md
~/code/my-project/packages/web/AGENTS.md  ← current workspace
```

У цьому прикладі завантажуються всі чотири файли. Їх об'єднують у такому порядку:

```text
~/.config/opencode/AGENTS.md
packages/web/AGENTS.md
packages/AGENTS.md
AGENTS.md
```

Вказівки, які стосуються всього, зберігайте в глобальному файлі. Вказівки для всього репозиторію розмістіть у корені
проєкту, а конкретніші — ближче до коду, якого вони стосуються. OpenCode об'єднує файли й не розв'язує конфлікти між
ними.

Якщо робочий простір розташований поза коренем проєкту, завантажується лише глобальний файл. Задайте
`OPENCODE_DISABLE_PROJECT_CONFIG=1`, щоб пропустити пошук `AGENTS.md` у проєкті, не вимикаючи глобальний файл.

<Callout type="note">
  OpenCode V2 розпізнає лише `AGENTS.md`. Файл `CLAUDE.md` як резервний варіант не використовується.
</Callout>

## Виявлення

Файли інструкцій нижче робочого простору виявляються в міру того, як агент досліджує проєкт. Читання файлу або перегляд
вмісту каталогу завантажує всі файли `AGENTS.md`, розташовані між цією ціллю та робочим простором.

```text
my-project/                         ← current workspace
├── AGENTS.md                       loaded initially
└── packages/
    └── web/
        ├── AGENTS.md               loaded when this area is read
        └── src/
            └── app.ts              read target
```

Вкладені файли завантажуються від найближчого й не дублюються, доки відповідний запис інструкцій лишається в історії,
видимій моделі. Повторне читання тієї самої частини проєкту зазвичай не додає їх знову. Якщо стиснення контексту або
відкат видаляє цей запис, наступне читання може завантажити файл повторно.

Зміни у вкладеному файлі після його завантаження автоматично не відстежуються. Якщо оновлений текст має застосуватися
одразу, почніть нову сесію.

## Порядок

Першим надсилається системний промпт вибраного агента або провайдера. Потім OpenCode збирає початкові інструкції в
такому порядку:

```text
1. Agent or provider system prompt
2. Built-in environment and date context
3. Code Mode tool guidance, when enabled
4. Global and project AGENTS.md files
5. Available skill, reference, and MCP guidance
6. Session-specific instruction entries supplied through the API
```

Ці джерела об'єднуються, а не перевизначають одне одного. Вкладені файли `AGENTS.md`, виявлені пізніше, додаються до
історії сесії в порядку виявлення.

## Оновлення

Щоб оновити вказівки запущеної сесії, відредагуйте глобальний `AGENTS.md` або файл, знайдений вище за деревом каталогів.

```bash
$ printf '\n- Run the integration suite before committing.\n' >> AGENTS.md
```

Перед наступним запитом до моделі OpenCode виявляє зміну й додає оновлення інструкцій, перш ніж передати введення, що
очікує:

```text
AGENTS.md changes
→ instruction update
→ next prompt
```

- Якщо видалити всі фонові файли `AGENTS.md`, сесія отримає повідомлення, що попередні фонові інструкції більше не діють.
- Тимчасова помилка читання зберігає останні відомі інструкції, а не вважає їх видаленими.
- Переміщена сесія зберігає стан інструкцій, тому вказівки в новому розташуванні додаються як оновлення.
- Підтвердження відкату сесії скидає стан інструкцій і перезавантажує їх перед наступним промптом.

Значення інструкцій залишаються привілейованими. Клієнти бачать, які джерела змінилися, але не бачать їхнього вмісту.

## Конфігурація

Схема конфігурації V2 приймає масив `instructions`, але наразі V2 не обробляє вказані в ньому файли, glob-шаблони чи
URL-адреси. Така конфігурація поки не додає інструкцій для моделі:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "instructions": ["CONTRIBUTING.md", "docs/guidelines/*.md", "https://example.com/instructions.md"],
}
```

Для інструкцій, що діють у V2, використовуйте `AGENTS.md`. Розташування конфігурації та пріоритет описано в розділі
[Конфігурація](/config).
