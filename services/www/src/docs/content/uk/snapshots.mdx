---
title: "Знімки"
---

Знімки дають змогу разом скасувати нещодавні зміни в розмові та файлах. Використовуйте їх, щоб переробити останню
роботу, але для всього важливого покладайтеся на коміти Git або резервні копії.

## Робочий процес

Виконайте `/undo` після відповіді, яку хочете переробити. OpenCode готує відкат, відновлює змінені файли й повертає
видалений промпт у поле введення, щоб ви могли його відредагувати.

```text
/undo

# Edit the restored prompt, then submit it again.
Add validation without changing the public API.
```

Надсилання відредагованого промпту підтверджує підготовлений відкат. Щоб скасувати його до надсилання, виконайте
`/redo` — розмову та файли буде відновлено до стану перед `/undo`.

```text
/redo
```

У терміналі також є сполучення клавіш за замовчуванням:

| Дія | Команда | Сполучення клавіш |
| --- | --- | --- |
| Підготувати відкат попереднього повідомлення | `/undo` | `<leader>u` |
| Скасувати підготовлений відкат | `/redo` | `<leader>r` |

Також можна вибрати попереднє повідомлення й натиснути **Revert**, щоб підготувати відкат до цієї точки.

## Створення знімків

Для кожного кроку моделі OpenCode намагається створити знімок безпосередньо перед викликом моделі та ще один, коли
крок завершується зафіксованим успіхом або помилкою. Повідомлення асистента зберігає, які шляхи змінилися між цими
знімками.

```text
before model step ── snapshot A
model edits src/api.ts
step finishes ────── snapshot B ── changed: src/api.ts
```

Знімки створюються за принципом «наскільки можливо». Якщо будь-який із двох знімків недоступний, розмова триває, але
файлові зміни цього кроку можуть бути недоступні для відновлення.

## Охоплення

Знімки охоплюють активний каталог сесії всередині Git worktree. Наприклад, сесія, відкрита в `packages/app`, фіксує
відповідні файли в `packages/app`, але не зміни в інших частинах репозиторію.

| Вміст | Фіксується | Приклад |
| --- | --- | --- |
| Відстежувані файли в активному каталозі | Так | `packages/app/src/app.tsx` |
| Невідстежувані файли, які не ігноруються, розміром до 2 MiB кожен | Так | `packages/app/notes.txt` |
| Файли, які ігнорує Git | Ні | `packages/app/dist/app.js` |
| Окремі невідстежувані файли, більші за 2 MiB | Ні | `packages/app/debug.log` |
| Файли поза активним каталогом | Ні | `packages/server/src/index.ts` |
| Метадані Git та інші побічні ефекти | Ні | коміти, гілки, бази даних або процеси |

Знімки файлової системи потребують репозиторію Git. Поза ним `/undo` усе одно може відкотити історію розмови, але не
відновить файли.

## Відновлення

Відкат відновлює лише шляхи, пов'язані з кроками асистента після вибраної межі розмови. Кожен шлях повертається до
стану перед першим скасованим кроком; файл, створений цими кроками, видаляється, якщо тоді його не існувало.

| Хронологія | `src/api.ts` | `src/new.ts` |
| --- | --- | --- |
| Вибрана межа | версія A | відсутній |
| Наступні кроки асистента | версія B | створено |
| Після відкату | версія A | видалено |

Шляхи, не пов'язані з цими кроками, лишаються без змін. Поточні правки у зачеплених шляхах можуть бути перезаписані,
тому перш ніж продовжувати, перегляньте підсумок відновлення та `git diff`.

```sh
git diff --stat
git diff
```

## Зберігання

OpenCode зберігає знімки локально в окремій внутрішній базі об'єктів Git у своєму каталозі даних. Створення знімків
не створює комітів, не переміщує гілки й навмисно не змінює індекс вашого репозиторію.

```sh
# Your repository remains an ordinary dirty worktree after capture.
git status --short
```

Об'єкти знімків можуть містити повний вміст відстежуваних і відповідних невідстежуваних файлів. Вважайте каталог даних
OpenCode конфіденційними локальними даними.

## Налаштування

Знімки ввімкнено за замовчуванням. Задайте `snapshots` значення `false` у [конфігурації](/config#snapshots), щоб
припинити подальше створення знімків файлової системи.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "snapshots": false,
}
```

Вимкнення знімків не видаляє вже збережені знімки. Відкат розмови залишається доступним, але без зафіксованого стану
файлової системи він не може відновити пов'язані зміни файлів.

## Безпека

Знімки — це зручність, а не транзакція чи резервна копія:

- Команди оболонки можуть змінювати сервіси, процеси, мережеві ресурси, бази даних, стан Git, ігнорований вивід або
  файли поза активним каталогом. Відновлення знімка не скасовує цих наслідків.
- Перервана або невдала робота може залишити зміни, якщо створити знімок не вдалося або немає придатної пари знімків.
- Відновлення зачеплених шляхів перезаписує їхній поточний вміст. Скасування підготовленого відкату також може
  перезаписати пізніші правки.
- OpenCode відхиляє операції відкату, поки сесія виконується, але зовнішні редактори й команди все одно можуть змінити
  worktree між створенням знімка та відновленням.
- Підтвердження відкату видаляє повідомлення з активного подання розмови, але не з постійної історії сесії чи наявного
  сховища знімків. Це не безпечне стирання даних.

Перш ніж використовувати `/undo` у worktree з незафіксованими змінами, зробіть коміт або резервну копію важливої роботи.
