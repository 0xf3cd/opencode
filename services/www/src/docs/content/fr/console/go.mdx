OpenCode Go vous donne un accès fiable aux modèles de code ouverts les plus populaires, avec deux forfaits mensuels :

| Forfait     | Prix          | Utilisation incluse                                      |
| ----------- | ------------- | -------------------------------------------------------- |
| **Go**      | **$10/mois**  | Accès à moindre coût aux modèles ci-dessous              |
| **Go Plus** | **$40/mois**  | Limites d'utilisation plus élevées sur les modèles ci-dessous |

Go fonctionne comme n'importe quel autre fournisseur dans OpenCode : vous vous abonnez à OpenCode Go et obtenez votre clé API. Il est **entièrement facultatif** et n'est pas nécessaire pour utiliser OpenCode.

Le service est conçu principalement pour les utilisateurs internationaux et offre un accès stable dans le monde entier.

## Fonctionnement

1. Connectez-vous à [OpenCode Console](https://opencode.ai/console), abonnez-vous à Go ou Go Plus, ajoutez vos informations de facturation et copiez votre clé API.
2. Exécutez `/connect` dans le TUI, sélectionnez **OpenCode Go** et collez votre clé API.

   ```text
   /connect
   ```

3. Exécutez `/models` pour sélectionner un modèle disponible avec Go.

   ```text
   /models
   ```

<Callout>
  Go et Go Plus sont destinés aux espaces de travail à un seul membre, comme l'espace de travail **Personal** créé lors de
  votre inscription. Un espace de travail abonné à Go ne peut pas inviter de membres.
</Callout>

## Où l'utiliser ?

OpenCode Go est conçu pour [OpenCode](https://opencode.ai) et les autres agents de code qui produisent des requêtes
similaires. Le trafic est surveillé afin de détecter les abus qui dégradent l'expérience des autres utilisateurs.

Votre client doit :

1. Envoyer un trafic typique d'agent de code.
2. S'identifier avec son propre user agent, par exemple `my-coding-agent/1.0`, plutôt qu'avec le nom générique d'un SDK
   ou d'une bibliothèque HTTP.
3. Envoyer un ID de session stable dans `x-opencode-session` pour chaque conversation, afin que nous puissions optimiser
   le routage et la mise en cache des prompts.

### Clients validés

Outre OpenCode, les clients suivants ont été validés comme fonctionnant correctement avec OpenCode Go. Nous ne
garantissons toutefois pas qu'ils continueront de fonctionner à l'avenir.

| Client            | Prise en charge des sessions |
| ----------------- | ---------------------------- |
| **Hermes**        | Les builds qui contiennent la [PR #101864](https://github.com/NousResearch/hermes-agent/pull/101864) envoient l'en-tête dans les requêtes OpenCode principales et auxiliaires. Le correctif a été fusionné après la v0.21.0 ; cette version seule ne l'inclut pas. |
| **Claude Code**   | Go reconnaît son en-tête de session natif. Aucun wrapper d'en-tête personnalisé n'est nécessaire. |
| **Codex**         | Go reconnaît son en-tête de session natif. Certaines versions et configurations de proxy l'omettent encore : conservez l'en-tête de session lorsque vous transférez des requêtes. |
| **ZCode**         | Go reconnaît son en-tête de session natif. Notre [demande concernant `x-opencode-session`](https://github.com/zai-org/feedback/issues/492) reste ouverte, mais il n'est plus nécessaire d'envoyer cet en-tête précis. |
| **Pi**            | Les builds actuels envoient les informations de session pour OpenCode. Mettez à jour les installations plus anciennes. |
| **jcode**         | Passez à la **v0.81.6 ou ultérieure**, qui inclut le [correctif de l'en-tête de session](https://github.com/1jehuang/jcode/issues/1167). |
| **Kilo Code CLI** | Les builds qui contiennent la [PR #13752](https://github.com/Kilo-Org/kilocode/pull/13752) rétablissent les en-têtes de session OpenCode. Ce correctif concerne le CLI, pas l'extension VS Code. Consultez l'[issue #13723](https://github.com/Kilo-Org/kilocode/issues/13723). |

### Clients problématiques connus

La prise en charge des sessions est absente ou incomplète dans les versions de ces clients que nous avons examinées. Les
signalements en lien suivent les correctifs et les solutions de contournement.

| Client                  | État et suivi |
| ----------------------- | ------------- |
| **DeepSeek Harness**    | Les informations de session arrivent sur certains chemins de modèles, mais pas sur d'autres. Nous reconnaissons son en-tête natif ; il reste à l'envoyer depuis tous les adaptateurs. [Discussion #5495](https://github.com/deepseek-ai/deepseek-harness/discussions/5495). |
| **GitHub Copilot Chat** | La prise en charge automatique de l'en-tête de session est demandée dans l'[issue VS Code #334186](https://github.com/microsoft/vscode/issues/334186). |
| **Kimi Code**           | La prise en charge automatique de l'en-tête de session est demandée dans l'[issue #3506](https://github.com/MoonshotAI/kimi-code/issues/3506). |
| **MiMo Code**           | L'[issue #2317](https://github.com/XiaomiMiMo/MiMo-Code/issues/2317) dispose d'un correctif proposé dans la [PR #2327](https://github.com/XiaomiMiMo/MiMo-Code/pull/2327), qui n'a pas encore été fusionnée. |

### Utilisation au-delà des limites

Si vous disposez aussi de crédits dans le solde de votre Console, vous pouvez activer l'option **Use balance** dans la
Console. Une fois vos limites d'utilisation atteintes, Go se rabat alors sur votre
[solde à l'usage](/console/models#pricing) au lieu de bloquer les requêtes.

### Pourquoi certains modèles ont une utilisation plus faible

Avec Go, l'utilisation mensuelle incluse varie selon le modèle.

Pour la plupart des modèles, nous y parvenons grâce à des remises sur volume et à de la capacité GPU réservée. Nous vous répercutons ensuite ces économies sous forme d'une utilisation mensuelle plus élevée.

Pour certains modèles, nous n'avons pas encore pu négocier de remise ni les héberger à moindre coût, soit parce que le modèle est récent, soit parce que son prix public est déjà réduit.

Pour ces modèles, vous obtenez tout de même un peu plus que si vous payiez directement les fournisseurs ; c'est pourquoi leur utilisation mensuelle incluse est plus faible.

## Contexte

Les modèles ouverts sont devenus vraiment bons. Ils atteignent désormais des performances proches de celles des modèles propriétaires pour les tâches de code. Comme de nombreux fournisseurs peuvent les servir à des prix compétitifs, ils sont généralement bien moins chers.

Il peut toutefois être difficile d'y accéder de façon fiable et avec une faible latence. Les fournisseurs varient en qualité et en disponibilité.

<Callout type="tip">Nous avons testé une sélection de modèles et de fournisseurs qui fonctionnent bien avec OpenCode.</Callout>

Pour y remédier, nous avons :

1. Testé une sélection de modèles ouverts et échangé avec leurs équipes sur la meilleure façon de les exécuter.
2. Travaillé avec quelques fournisseurs pour nous assurer que ces modèles étaient servis correctement.
3. Évalué chaque combinaison modèle/fournisseur pour établir une liste que nous recommandons en toute confiance.

Go et Go Plus donnent tous deux accès à ces modèles : choisissez le forfait adapté à votre niveau d'utilisation.

## Objectifs

Nous avons créé OpenCode Go pour :

1. Rendre le code assisté par IA **accessible** au plus grand nombre grâce à un abonnement peu coûteux.
2. Offrir un accès **fiable** aux meilleurs modèles de code ouverts.
3. Sélectionner des modèles **testés et évalués** pour une utilisation avec des agents de code.
4. N'imposer **aucun verrouillage** : vous pouvez aussi utiliser n'importe quel autre fournisseur avec OpenCode.
