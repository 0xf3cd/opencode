L'API de la Console permet aux intégrations de lire la configuration de l'espace de travail et de gérer les budgets. Les
chemins sont relatifs à l'URL de base de la Console.

```bash
export CONSOLE_URL="https://opencode.ai/console"
export SERVICE_API_KEY="oc_sk_..."

curl --fail-with-body "${CONSOLE_URL}/api/v2/config" \
  --header "Authorization: Bearer ${SERVICE_API_KEY}"
```

| API                                         | Points de terminaison                      |
| ------------------------------------------- | ------------------------------------------ |
| [Inférence](/console/api/inference)         | `https://opencode.ai/inference/...`        |
| [Fournisseurs](/console/api/providers)      | `https://opencode.ai/inference/custom/...` |
| [Budgets](/console/api/budgets)             | `/api/v1/budgets/members`                  |
| [Configuration](#workspace-config)          | `GET /api/v2/config`                       |

## Comptes de service

Les intégrations s'authentifient avec un compte de service : un membre non humain de l'espace de travail, doté de ses
propres clés API, de sa propre utilisation et de son propre [budget](/console/budgets#service-account-budgets). Les
propriétaires et les administrateurs les gèrent depuis **Keys**.

1. Ouvrez **Keys** et cliquez sur **Add Service Account**, puis nommez-le, par exemple `CI Pipeline`.
2. Ouvrez le compte de service et cliquez sur **Add API Key**.
3. Choisissez un **Key name**, des **Permissions** et éventuellement une **Expiry date**, puis cliquez sur
   **Create key**.
4. Copiez la clé. Elle n'est affichée qu'une seule fois.

```text
oc_sk_1a2b3c4d5e6f_...
```

Envoyez la clé comme bearer token. Elle est liée à un seul espace de travail : aucun en-tête d'espace de travail n'est
donc nécessaire.

```text
Authorization: Bearer oc_sk_...
```

### Permissions

| Permission     | Autorise                                                                                                                  |
| -------------- | ------------------------------------------------------------------------------------------------------------------------- |
| Inference only | Les requêtes [Inférence](/console/api/inference) et [Fournisseurs](/console/api/providers), ainsi que `GET /api/v2/config`. |
| All            | Tout ce qui précède, plus l'API de la Console avec un accès administrateur, à l'exception de la gestion des modèles.     |

Certaines actions nécessitent toujours une personne connectée à la Console, même avec une clé **All** : inviter des
membres, modifier des rôles, retirer des membres, et créer ou révoquer des clés.

### Révoquer des clés

Ouvrez le compte de service et révoquez une clé depuis **API Keys**. Supprimer le compte de service révoque toutes ses
clés. Les automatisations qui utilisent une clé révoquée ou expirée reçoivent immédiatement une erreur HTTP `401`.

## Tokens utilisateur

Les tokens utilisateur agissent au nom d'une personne connectée, avec son rôle dans l'espace de travail. Envoyez le
token avec un en-tête `x-org-id` qui désigne l'espace de travail.

```bash
curl --fail-with-body "${CONSOLE_URL}/api/v2/config" \
  --header "Authorization: Bearer ${USER_TOKEN}" \
  --header "x-org-id: org_..."
```

Les tokens issus du [flux d'appareil](#device-flow) sont liés à l'espace de travail choisi lors de la connexion et n'ont
pas besoin de cet en-tête. Un `x-org-id` différent renvoie `403`.

## Flux d'appareil

OpenCode se connecte avec l'autorisation d'appareil OAuth (device authorization grant, RFC 8628). D'autres CLI peuvent
utiliser le même flux.

1. Demandez un code d'appareil. Envoyez `supports_org_scope=true` pour lier le token à un espace de travail.

   ```bash
   curl --fail-with-body "${CONSOLE_URL}/auth/device/code" \
     --data "client_id=my-cli" \
     --data "supports_org_scope=true"
   ```

   La réponse contient `device_code`, `user_code`, `verification_uri_complete`, `expires_in` (600 secondes) et
   `interval` (5 secondes).

2. Ouvrez `verification_uri_complete` dans un navigateur. Il s'agit d'un chemin tel que `/console/device?user_code=...`,
   relatif à `https://opencode.ai`. La personne se connecte, choisit un espace de travail et approuve.

3. Interrogez le serveur pour obtenir le token toutes les `interval` secondes, avec le même `client_id`.

   ```bash
   curl --fail-with-body "${CONSOLE_URL}/auth/device/token" \
     --data "grant_type=urn:ietf:params:oauth:grant-type:device_code" \
     --data "device_code=..." \
     --data "client_id=my-cli"
   ```

   Tant que l'approbation n'a pas eu lieu, la réponse est `400` avec `authorization_pending`. En cas de succès, elle
   renvoie `access_token`, `refresh_token`, `expires_in` et `org_id`.

4. Actualisez le token avant l'expiration du token d'accès. Le lien avec l'espace de travail est conservé.

   ```bash
   curl --fail-with-body "${CONSOLE_URL}/auth/device/token" \
     --data "grant_type=refresh_token" \
     --data "refresh_token=..." \
     --data "client_id=my-cli"
   ```

Chaque refresh token ne peut être utilisé qu'une seule fois. Réutiliser un ancien refresh token révoque toute la
session.

## Configuration de l'espace de travail

`GET /api/v2/config` renvoie les fournisseurs et les modèles disponibles pour l'espace de travail, au format de
[configuration](/config) d'OpenCode V2. OpenCode la charge après `/connect`.

```bash
curl --fail-with-body "${CONSOLE_URL}/api/v2/config" \
  --header "Authorization: Bearer ${SERVICE_API_KEY}"
```

```json
{
  "providers": {
    "opencode": {
      "name": "OpenCode",
      "env": ["OPENCODE_CONSOLE_TOKEN"],
      "package": "aisdk:@ai-sdk/openai-compatible",
      "settings": {
        "baseURL": "https://opencode.ai/inference/openai/v1",
        "apiKey": "{env:OPENCODE_CONSOLE_TOKEN}"
      },
      "headers": { "x-opencode-org-id": "org_..." },
      "models": {
        "kimi-k2.6": { "name": "Kimi K2.6" }
      }
    }
  }
}
```

| Champ                   | Description                                                                                          |
| ----------------------- | ---------------------------------------------------------------------------------------------------- |
| `providers`             | La Console, Go et les fournisseurs connectés, chacun avec ses paramètres de passerelle et ses modèles. |
| `websearch`             | La [recherche web](/console/websearch) hébergée, pour les membres lorsqu'elle est activée.           |
| `mcp`                   | Le serveur MCP de la Console, pour les membres.                                                      |
| `experimental.policies` | Les instructions de [politique](/policies#console) de l'espace de travail.                           |

Tous les niveaux de permission des clés et tous les rôles de membre peuvent lire la configuration.

## Erreurs

Les erreurs renvoient du JSON avec un champ `_tag` qui nomme l'erreur.

```json
{ "_tag": "Forbidden" }
```

| Statut | Signification                                                                                                  |
| ------ | -------------------------------------------------------------------------------------------------------------- |
| `400`  | `OrgRequired` : un token utilisateur a été envoyé sans `x-org-id`.                                             |
| `401`  | Identifiants absents, invalides, expirés ou révoqués.                                                          |
| `403`  | Mauvais espace de travail, permission manquante ou clé **Inference only** utilisée sur un point de terminaison de la Console. |
| `404`  | L'espace de travail n'existe pas ou a été supprimé.                                                            |
