---
title: "Références"
---

Les références donnent à OpenCode un accès nommé à des répertoires situés hors du projet courant. Ajoutez-en une dans
`opencode.json` ou `opencode.jsonc`, puis joignez son alias dans votre client lorsque vous en avez besoin.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "references": {
    "docs": {
      "path": "../product-docs",
      "description": "Use for product behavior and terminology",
    },
  },
}
```

Après avoir joint `docs`, demandez à l'agent d'examiner le chemin concerné :

```text
Read the attached docs reference and summarize api/authentication.md.
```

Utilisez les références pour de la documentation, des bibliothèques partagées, des exemples ou du code source provenant
d'un autre dépôt.

## Répertoire local

Utilisez `path` pour un répertoire local :

```jsonc
{
  "references": {
    "design-system": {
      "path": "../design-system",
      "description": "Use when working with components or design tokens",
    },
  },
}
```

Les chemins se comportent ainsi :

- Les chemins relatifs sont résolus à partir du répertoire qui contient le fichier de configuration.
- Les chemins absolus sont pris en charge.
- Les chemins relatifs au répertoire personnel, comme `~/docs`, sont pris en charge.

Utilisez la forme abrégée en chaîne lorsqu'aucun autre champ n'est nécessaire :

```jsonc
{
  "references": {
    "docs": "../docs",
    "shared": "~/work/shared",
  },
}
```

<Callout type="note">
  Une chaîne abrégée n'est un chemin local que si elle commence par `.`, `/` ou `~`. Écrivez `./docs` et non `docs` : une
  valeur `docs` seule est interprétée comme un dépôt Git.
</Callout>

## Git

Utilisez `repository` pour un dépôt Git distant :

```jsonc
{
  "references": {
    "effect": {
      "repository": "Effect-TS/effect",
      "branch": "main",
    },
    "internal-sdk": {
      "repository": "git@gitlab.example.com:platform/sdk.git",
      "branch": "release/v2",
    },
  },
}
```

Les formes de dépôt distant prises en charge sont notamment :

- la forme abrégée GitHub `owner/repo` ;
- les URL Git ;
- les formes hôte/chemin ;
- les dépôts distants de style SCP.

Les dépôts locaux `file:` ne sont pas pris en charge.

Utilisez la forme abrégée en chaîne pour suivre la branche par défaut du dépôt distant :

```jsonc
{
  "references": {
    "effect": "Effect-TS/effect",
    "sdk": "gitlab.com/platform/sdk",
  },
}
```

Sans `branch`, OpenCode extrait et actualise la branche par défaut du dépôt distant. Les noms de branche peuvent contenir
des lettres, des chiffres, `/`, `_`, `.` et `-`, mais ne peuvent pas commencer par `-` ni contenir `..`.

```jsonc
{
  "references": {
    "sdk": {
      "repository": "example/sdk",
      "branch": "release/v2.1",
    },
  },
}
```

## Stockage

OpenCode normalise chaque dépôt distant et stocke une copie de travail par dépôt et par branche dans son répertoire de
données global. Sans branche explicite, le chemin a la forme suivante :

```text
opencode/repos/<host>/<repository-path>
```

Sur une installation Linux classique, `Effect-TS/effect` est stocké ici :

```text
~/.local/share/opencode/repos/github.com/Effect-TS/effect
```

Une branche explicite ajoute un suffixe encodé `@<branch>` :

```text
~/.local/share/opencode/repos/github.com/Effect-TS/effect@main
```

## Actualisation

Les dépôts manquants sont clonés de manière asynchrone. Les copies de travail existantes sont vérifiées en arrière-plan
lorsque les références sont chargées ou rechargées, et après l'admission d'un nouveau prompt utilisateur dans leur
Location.

```text
Prompt admitted → refresh check starts in background → agent continues
```

Une copie de travail est éligible lorsque sa dernière tentative d'actualisation remonte à au moins 24 heures, ou
lorsqu'aucune tentative n'a été enregistrée. Une actualisation récupère la branche configurée, ou la branche par défaut
du dépôt distant, et s'y réinitialise.

```text
Last attempt: 25 hours ago → eligible
Last attempt: 2 hours ago  → skipped
```

L'actualisation suit ces règles :

- Les horodatages sont conservés après un redémarrage du service.
- Les Locations qui utilisent la même copie de travail partagent son horodatage.
- Les tentatives en échec sont journalisées et restent soumises à la limite de 24 heures.
- Aucune interrogation périodique n'a lieu tant qu'une Location n'est pas utilisée.
- Les échecs de clonage ou d'actualisation n'empêchent pas le chargement des autres références.

Les prompts n'attendent pas la fin du clonage ou de l'actualisation. Une pièce jointe peut contenir un contenu plus
ancien alors qu'une lecture ultérieure par un outil voit la copie de travail mise à jour, et une nouvelle référence peut
apparaître avant que sa copie de travail soit prête.

```text
Attachment created → cached content
Background refresh completes → later tool read sees newer content
```

<Callout type="warning">
  Les copies de travail en cache sont partagées et peuvent être mises à jour pendant qu'un agent les utilise. Évitez de
  les modifier, car une actualisation les réinitialise.
</Callout>

## Consignes

`description` indique aux agents quand une référence est pertinente. Les références dotées d'une description
apparaissent dans les instructions des agents, avec leur alias et leur chemin résolu.

```jsonc
{
  "references": {
    "docs": {
      "path": "../docs",
      "description": "Use for product behavior and terminology",
    },
  },
}
```

Les références sans description restent disponibles pour les clients, mais ne sont pas signalées automatiquement.

```jsonc
{
  "references": {
    "archive": {
      "path": "../archive",
    },
  },
}
```

## Visibilité

Définissez `hidden` sur `true` pour retirer une référence des sélecteurs interactifs des clients :

```jsonc
{
  "references": {
    "internal": {
      "path": "../internal",
      "description": "Use for internal service behavior",
      "hidden": true,
    },
  },
}
```

`hidden` n'affecte que la visibilité interactive. La référence reste présente dans l'API des références et, si elle a
une description, dans les instructions des agents.

## Utilisation

Les clients joignent une référence par son alias racine. La pièce jointe contient une liste non récursive des fichiers
et répertoires situés directement à la racine.

```text
Attached alias: docs
Ask: Inspect docs/guides/deployment.md and explain the deployment steps.
```

Demandez à l'agent d'examiner un chemin précis lorsque vous avez besoin d'un contenu situé sous la racine.

## Permissions

Les références n'accordent aucune permission d'outil supplémentaire. L'accès hors de la Location active reste soumis aux
règles habituelles des outils et à la permission `external_directory` ; la modification nécessite en plus la permission
de modification applicable.

```text
Read ../product-docs/api.md
```

La requête n'aboutit que si les permissions actives autorisent cette lecture externe.

## Champs

| Champ | Local | Git | Description |
| --- | --- | --- | --- |
| `path` | Obligatoire | Non | Chemin du répertoire local |
| `repository` | Non | Obligatoire | Dépôt Git distant |
| `branch` | Non | Facultatif | Branche à récupérer et à extraire |
| `description` | Facultatif | Facultatif | Consigne indiquant quand les agents doivent l'utiliser |
| `hidden` | Facultatif | Facultatif | Masque la référence dans les sélecteurs interactifs des clients |

Une entrée Git complète peut utiliser tous les champs compatibles avec Git :

```jsonc
{
  "references": {
    "sdk": {
      "repository": "example/sdk",
      "branch": "main",
      "description": "Use for SDK implementation details",
      "hidden": false,
    },
  },
}
```

## Alias

Un alias ne peut pas être vide ni contenir `/`, `\`, d'espace, de backtick ou de virgule.

```text
Valid:   docs
Invalid: product docs
Invalid: docs/api
```
