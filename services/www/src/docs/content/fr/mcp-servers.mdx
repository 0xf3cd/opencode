---
title: "Serveurs MCP"
---

OpenCode se connecte à des serveurs [Model Context Protocol](https://modelcontextprotocol.io/) et expose leurs fonctionnalités : outils, prompts, ressources et instructions. Les outils MCP consomment du contexte du modèle : n'ajoutez donc que les serveurs dont vous avez besoin.

## Mise en place

Ajoutez un serveur distant depuis le projet qui doit l'utiliser, puis vérifiez sa connexion :

```sh
opencode mcp add context7 --url https://mcp.context7.com/mcp
opencode mcp list
```

La commande écrit le serveur dans la [configuration](/config) du projet. Ajoutez `--global` pour le rendre disponible dans tous les projets :

```sh
opencode mcp add context7 --global --url https://mcp.context7.com/mcp
```

Les serveurs distants utilisent OAuth par défaut. Si la liste affiche `needs authentication`, ouvrez OpenCode, exécutez `/mcps`, sélectionnez le serveur et connectez-vous. Un serveur connecté est prêt à être utilisé par un agent :

```text
✓ context7  connected
```

## Configuration

Pour configurer un serveur manuellement, donnez-lui un nom unique sous `mcp.servers`. Dans V2, les noms de serveurs ne se placent pas directement sous `mcp`.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "my-server": {
        "type": "local",
        "command": ["npx", "-y", "example-mcp-server"],
      },
    },
  },
}
```

Les serveurs se connectent automatiquement. Utilisez `disabled`, et non un champ `enabled`, pour conserver un serveur dans la configuration sans le connecter :

```jsonc
{
  "mcp": {
    "servers": {
      "my-server": {
        "type": "local",
        "command": ["npx", "-y", "example-mcp-server"],
        "disabled": true,
      },
    },
  },
}
```

Une configuration de projet de priorité supérieure remplace entièrement l'objet serveur de même nom. Utilisez des noms différents pour des connexions ou des comptes distincts ; sinon, répétez tous les champs obligatoires dans le remplacement :

```jsonc title="opencode.jsonc"
{
  "mcp": {
    "servers": {
      "my-server": {
        "type": "remote",
        "url": "https://mcp.example.com/mcp",
      },
    },
  },
}
```

## Serveurs locaux

Un serveur local est une commande qu'OpenCode démarre avec le transport stdio de MCP. Ajoutez-en un en indiquant la commande après `--` :

```sh
opencode mcp add everything -- npx -y @modelcontextprotocol/server-everything
```

Utilisez la configuration pour les options du processus, comme le répertoire de travail ou les variables d'environnement :

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "everything": {
        "type": "local",
        "command": ["npx", "-y", "@modelcontextprotocol/server-everything"],
        "cwd": ".",
        "environment": {
          "LOG_LEVEL": "info",
          "MCP_API_KEY": "{env:MCP_API_KEY}",
        },
      },
    },
  },
}
```

| Champ | Obligatoire | Description |
| --- | --- | --- |
| `type` | Oui | Doit valoir `"local"`. |
| `command` | Oui | Exécutable suivi de ses arguments. |
| `cwd` | Non | Répertoire du processus. Les chemins relatifs sont résolus à partir de l'espace de travail, qui est aussi la valeur par défaut. |
| `environment` | Non | Variables de type chaîne ajoutées à l'environnement de processus hérité d'OpenCode. |
| `disabled` | Non | Empêche la connexion lorsqu'il vaut `true`. Valeur par défaut : `false`. |
| `codemode` | Non | Définissez-le sur `false` pour exposer les outils directement plutôt que via Code Mode. Valeur par défaut : `true`. |
| `timeout` | Non | Délais d'expiration propres au serveur, qui remplacent les valeurs par défaut. |
| `protocol` | Non | `legacy` (par défaut), `auto` ou `2026-07-28`. Consultez [Version du protocole](#protocol-version). |

Utilisez `{env:NAME}` pour substituer une variable d'environnement. Les expressions shell comme `$NAME` ne sont pas développées dans les chaînes JSON :

```jsonc
{
  "environment": {
    "MCP_API_KEY": "{env:MCP_API_KEY}",
  },
}
```

## Serveurs distants

Un serveur distant utilise le transport Streamable HTTP de MCP et nécessite une URL absolue :

```sh
opencode mcp add context7 --url https://mcp.context7.com/mcp
```

Utilisez la configuration lorsque le serveur a besoin d'en-têtes ou d'autres options. Stockez les secrets dans des variables d'environnement plutôt que dans le fichier :

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "context7": {
        "type": "remote",
        "url": "https://mcp.context7.com/mcp",
        "oauth": false,
        "headers": {
          "CONTEXT7_API_KEY": "{env:CONTEXT7_API_KEY}",
        },
      },
    },
  },
}
```

| Champ | Obligatoire | Description |
| --- | --- | --- |
| `type` | Oui | Doit valoir `"remote"`. |
| `url` | Oui | Point de terminaison Streamable HTTP absolu. |
| `headers` | Non | En-têtes HTTP de type chaîne envoyés au point de terminaison. |
| `oauth` | Non | Paramètres OAuth, ou `false` pour désactiver OAuth. |
| `disabled` | Non | Empêche la connexion lorsqu'il vaut `true`. Valeur par défaut : `false`. |
| `codemode` | Non | Définissez-le sur `false` pour exposer les outils directement plutôt que via Code Mode. Valeur par défaut : `true`. |
| `timeout` | Non | Délais d'expiration propres au serveur, qui remplacent les valeurs par défaut. |
| `protocol` | Non | `legacy` (par défaut), `auto` ou `2026-07-28`. Consultez [Version du protocole](#protocol-version). |

N'utilisez `oauth: false` que si le serveur utilise exclusivement une clé API ou un autre identifiant transmis dans un en-tête :

```jsonc
{
  "type": "remote",
  "url": "https://mcp.example.com/mcp",
  "oauth": false,
  "headers": { "Authorization": "Bearer {env:MCP_API_KEY}" },
}
```

## OAuth

OAuth est activé pour les serveurs distants, sauf si `oauth` vaut `false`. OpenCode découvre le serveur d'autorisation, utilise PKCE, actualise les tokens et tente l'enregistrement dynamique du client lorsqu'il est pris en charge ; les identifiants restent en dehors de la configuration du projet.

Pour l'enregistrement dynamique, configurez uniquement l'URL du serveur :

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "sentry": {
        "type": "remote",
        "url": "https://mcp.sentry.dev/mcp",
      },
    },
  },
}
```

Si le serveur nécessite une authentification, exécutez `/mcps`, sélectionnez-le et terminez l'autorisation dans le navigateur. Le CLI peut lancer le même processus :

```sh
opencode mcp auth sentry
```

Lorsqu'un fournisseur vous remet des identifiants client, utilisez les champs OAuth en snake_case de V2 :

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "company-tools": {
        "type": "remote",
        "url": "https://mcp.example.com/mcp",
        "oauth": {
          "client_id": "{env:MCP_CLIENT_ID}",
          "client_secret": "{env:MCP_CLIENT_SECRET}",
          "scope": "tools:read tools:execute",
          "callback_port": 19876,
          "redirect_uri": "http://127.0.0.1:19876/callback",
        },
      },
    },
  },
}
```

| Champ | Description |
| --- | --- |
| `client_id` | ID de client préenregistré. Omettez-le pour tenter l'enregistrement dynamique. |
| `client_secret` | Secret d'un client préenregistré. |
| `scope` | Portées à demander, séparées par des espaces. |
| `callback_port` | Port de rappel local, de `1` à `65535`. Par défaut, un port éphémère disponible. |
| `redirect_uri` | URI de bouclage préenregistrée dont le chemin et le port atteignent l'écouteur de rappel local. |
| `auth_server_metadata_url` | URL du document de métadonnées OAuth ou OpenID Connect du serveur d'autorisation. Définissez-la lorsque le serveur MCP ne publie pas de métadonnées de ressource protégée indiquant son serveur d'autorisation. |

Supprimez les identifiants OAuth stockés lorsque vous devez vous reconnecter ou changer de compte :

```sh
opencode mcp logout sentry
```

## Délais d'expiration

Les délais d'expiration sont des entiers positifs exprimés en millisecondes. Définissez les valeurs par défaut sous `mcp.timeout` ; l'objet `timeout` d'un serveur remplace les valeurs par défaut correspondantes.

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "timeout": {
      "startup": 45000,
      "catalog": 30000,
      "execution": 600000,
    },
    "servers": {
      "slow-tools": {
        "type": "remote",
        "url": "https://mcp.example.com/mcp",
        "timeout": {
          "catalog": 60000,
        },
      },
    },
  },
}
```

| Délai | Valeur par défaut | S'applique à |
| --- | --- | --- |
| `startup` | 30 secondes | Connexion du transport et initialisation du serveur. |
| `catalog` | 30 secondes | Liste des outils, prompts, ressources et modèles de ressources. |
| `execution` | 12 heures | Appels d'outils, récupération des prompts et lecture des ressources. |

## Version du protocole

Par défaut, OpenCode ouvre chaque serveur avec la négociation MCP classique `initialize`. Définissez le `protocol` d'un serveur pour communiquer avec un serveur fondé sur la révision 2026-07-28 :

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "modern": {
        "type": "remote",
        "url": "https://mcp.example.com/mcp",
        "protocol": "auto",
      },
    },
  },
}
```

| Valeur | Comportement |
| --- | --- |
| `legacy` | Par défaut. Envoie `initialize` et prend en charge les révisions du protocole jusqu'à 2025-11-25. |
| `auto` | Sonde la révision 2026-07-28 avec `server/discover` et se rabat sur `legacy` lorsque le serveur ne la prend pas en charge. |
| `2026-07-28` | Exige la révision 2026-07-28. La connexion échoue avec les serveurs plus anciens. |

Sonder un serveur local `legacy` lance un processus supplémentaire de courte durée et peut attendre jusqu'à l'expiration du délai de démarrage si le serveur ignore les requêtes inconnues : réservez donc `auto` aux serveurs qui en ont besoin.

## Noms

OpenCode nomme un outil `<server>_<tool>`. Il remplace par `_` tous les caractères autres que les lettres, les chiffres, `_` et `-` :

```text
server: context 7
tool:   resolve.library/id
name:   context_7_resolve_library_id
```

Les prompts MCP deviennent des commandes nommées `<server>:<prompt>`, avec la même normalisation. Par exemple :

```text
/context_7:find_docs
```

Choisissez des noms de serveurs courts qui restent uniques après normalisation. Avec Code Mode, actif par défaut, les outils sont regroupés par nom de serveur normalisé :

```text
tools.context_7.resolve_library_id(...)
```

## Permissions

Code Mode est le mode par défaut. Définissez `codemode` sur `false` lorsque les outils d'un serveur doivent rester dans la liste d'outils native du fournisseur :

```jsonc
{
  "mcp": {
    "servers": {
      "context7": {
        "type": "remote",
        "url": "https://mcp.context7.com/mcp",
        "codemode": false,
      },
    },
  },
}
```

Utilisez les actions de permission pour masquer ou refuser des outils sans déconnecter leur serveur. Faites correspondre le nom normalisé `<server>_<tool>` :

```jsonc
{
  "permissions": [
    {
      "action": "context7_*",
      "resource": "*",
      "effect": "deny",
    },
  ],
}
```

## Contexte

Pour les appels effectués au nom d'une session, OpenCode envoie l'ID de session dans `CallToolRequest.params._meta["ai.opencode/sessionID"]`. Cela s'applique aux outils directs comme à Code Mode, en stdio comme en Streamable HTTP :

```json
{
  "method": "tools/call",
  "params": {
    "name": "lookup",
    "arguments": { "query": "example" },
    "_meta": { "ai.opencode/sessionID": "ses_..." }
  }
}
```

L'ID est une métadonnée de requête, pas un argument d'outil : il n'apparaît donc pas dans le schéma visible par le modèle. Traitez-le comme une valeur de corrélation opaque :

| Règle | Comportement |
| --- | --- |
| Identité | Il identifie la session OpenCode à l'origine de l'appel, et non la session de transport MCP. |
| Présence | Il peut être absent pour les appels sans contexte de session. |
| Sécurité | Ne l'utilisez pas seul pour l'authentification ou l'autorisation. |
| Confidentialité | Les serveurs distants reçoivent l'ID brut et peuvent le journaliser ou le conserver. |

## Gestion

Listez les serveurs et leur état de connexion actuel depuis n'importe quel projet :

```sh
opencode mcp list
```

Utilisez `/mcps` dans OpenCode pour afficher, connecter, déconnecter ou authentifier des serveurs. Utilisez le CLI pour ajouter des serveurs et gérer les identifiants OAuth :

```sh
opencode mcp add sentry --url https://mcp.sentry.dev/mcp
opencode mcp auth sentry
opencode mcp logout sentry
```

Pour supprimer un serveur, retirez son entrée de la configuration du projet ou de la configuration globale dans laquelle il a été ajouté :

```jsonc
{
  "mcp": {
    "servers": {},
  },
}
```

Modifiez directement la configuration pour les paramètres de client OAuth, les délais d'expiration, les répertoires de travail ou l'activation persistante :

```jsonc
{
  "mcp": {
    "servers": {
      "sentry": {
        "type": "remote",
        "url": "https://mcp.sentry.dev/mcp",
        "disabled": true,
      },
    },
  },
}
```
