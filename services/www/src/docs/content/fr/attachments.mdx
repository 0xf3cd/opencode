## Joindre un fichier

Joignez un fichier local, puis demandez à OpenCode de l'utiliser dans votre prompt. Dans le client de bureau ou web,
choisissez **Attach file**, collez un fichier ou faites-le glisser dans la zone de prompt.

```text
Summarize the attached README.md and list the required setup steps.
```

Les fichiers sélectionnés avec le sélecteur de l'application de bureau peuvent totaliser jusqu'à 20 MiB. D'autres
interfaces peuvent appliquer des limites plus basses côté client.

<Callout type="warning">
  Choisissez un modèle qui accepte les images en entrée avant de joindre une image. OpenCode peut transmettre les images
  prises en charge au fournisseur, mais le fournisseur et le modèle appliquent toujours leurs propres contraintes de
  format, de dimensions, de nombre de fichiers et de taille. Un modèle texte uniquement peut rejeter la requête.
</Callout>

## Syntaxe

Dans V2, les entrées de prompt et de commande décrivent une pièce jointe avec un `uri` et, en option, un `name` et une
`description` :

```json
{
  "uri": "file:///home/me/project/src/server.ts",
  "name": "server.ts",
  "description": "HTTP server entrypoint"
}
```

Utilisez une URL `file:` absolue pour un fichier ou un répertoire accessible au serveur. Pour les fichiers texte, des
paramètres `start` et `end` positifs sélectionnent des lignes, numérotées à partir de 1.

```text
file:///home/me/project/src/server.ts?start=20&end=60
```

Utilisez une URL `data:` pour envoyer le contenu directement :

```json
{
  "uri": "data:text/plain;base64,SGVsbG8sIE9wZW5Db2RlIQ==",
  "name": "greeting.txt"
}
```

Les URL de pièces jointes HTTP et HTTPS ne sont pas prises en charge. Consultez la [référence de l'API](/api) générée pour
envoyer des prompts par programmation.

## Formats

Les sessions V2 actuelles rendent ces types de pièces jointes visibles par le modèle :

| Entrée | Ce que reçoit le modèle | Exemple |
| --- | --- | --- |
| Fichier texte UTF-8 | Nom du fichier et texte décodé | `README.md` |
| Répertoire | Liste non récursive des fichiers et répertoires qu'il contient directement | `file:///home/me/` |
| PNG, JPEG, GIF ou WebP | Contenu de l'image | `diagram.png` |

Le SVG est traité comme du texte. Les pièces jointes PDF, AVIF, BMP, audio, vidéo et les autres fichiers binaires ne sont
pas incluses dans la requête envoyée au modèle. Convertissez d'abord un binaire non pris en charge en texte ou en image
prise en charge : par exemple, exportez une page PDF sous `page-1.png` avant de la joindre.

OpenCode lit chaque pièce jointe avant d'admettre le prompt. Il rejette les URL non valides, les chemins illisibles, les
chemins qui ne sont ni des fichiers ni des répertoires, et les pièces jointes de plus de 20 MiB une fois décodées. Le type
de média est détecté à partir des octets : modifier le nom du fichier ou le type de média d'une URL `data:` ne rend donc
pas visible un binaire non pris en charge.

## Images

Configurez la normalisation des images dans `opencode.json` ou `opencode.jsonc` :

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "media": {
    "image": {
      "auto_resize": true,
      "max_width": 2000,
      "max_height": 2000,
      "max_base64_bytes": 5242880,
    },
  },
}
```

Tous les champs sont facultatifs :

| Champ | Valeur par défaut | Comportement |
| --- | --- | --- |
| `auto_resize` | `true` | Redimensionne une image qui dépasse une limite configurée ; si `false`, rejette l'image. |
| `max_width` | `2000` | Largeur maximale en pixels ; doit être un entier positif. |
| `max_height` | `2000` | Hauteur maximale en pixels ; doit être un entier positif. |
| `max_base64_bytes` | `5242880` | Nombre maximal d'octets de l'image encodée en Base64 ; doit être un entier positif. |

Par exemple, cette configuration rejette une image de plus de 1200 pixels de large au lieu de la redimensionner :

```jsonc title="opencode.jsonc"
{
  "media": {
    "image": {
      "auto_resize": false,
      "max_width": 1200,
    },
  },
}
```

Ces paramètres s'appliquent à la fois aux images prises en charge jointes aux prompts et aux images renvoyées par l'outil
intégré `read`.

## Traitement

L'outil `read` reconnaît les formats PNG, JPEG, GIF et WebP d'après leur contenu et lit jusqu'à 20 MiB de données
d'image source. Il compare la largeur, la hauteur et la longueur Base64 aux limites d'image configurées.

Avec `auto_resize: true`, OpenCode conserve les proportions et réduit l'image jusqu'aux limites de dimensions. Il essaie
ensuite des encodages PNG et JPEG de plus en plus compacts jusqu'à respecter la limite Base64 : le type de média en sortie
peut donc changer.

```text
Input:  4000 × 2000 WebP
Limits: 2000 × 2000
Output: 2000 × 1000 PNG or JPEG
```

Si aucun encodage ne respecte la limite, le traitement échoue. Avec `auto_resize: false`, une image qui dépasse l'une des
limites échoue sans être modifiée ; une image impossible à décoder échoue également.

```text
Input:  2400 × 1600 JPEG
Limit:  max_width = 2000, auto_resize = false
Result: Image processing fails
```

Si le redimensionneur d'images n'est pas disponible, OpenCode transmet l'image d'origine sans la modifier. Les paramètres
d'image sont donc des limites de traitement, pas une barrière d'envoi ni de sécurité.

## Limites

| Limite | Valeur ou comportement | Exemple |
| --- | --- | --- |
| Pièce jointe directe | 20 MiB décodés par élément ; les clients peuvent imposer des limites plus basses | Deux fichiers de 12 MiB respectent la limite par élément |
| Sélection dans le sélecteur de l'application de bureau | 20 MiB au total | Deux fichiers de 12 MiB dépassent la limite de sélection |
| `max_base64_bytes` | Base64 encodé uniquement, sans l'URL `data:` complète | `SGVsbG8=` compte pour 8 octets |
| Limites d'image du fournisseur | S'appliquent après le traitement par OpenCode | Un fournisseur peut rejeter une image acceptée |
| Prise en charge des pièces jointes texte par le modèle | Ne nécessite pas de modèle multimodal | `notes.txt` est inséré comme texte du prompt |
| Limites de texte de `read` | Utilise des limites de pagination et de troncature distinctes | Lisez un long journal page par page |

Qu'un client accepte un fichier ne garantit pas que son contenu parvienne au modèle. La pièce jointe doit utiliser un
format visible par le modèle et respecter à la fois les limites d'OpenCode et celles du fournisseur.
